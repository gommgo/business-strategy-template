# ЧАСТЬ I. Ядро фреймворка

## Главная идея (3 перехода)

1. **Людям не нужны наши продукты.** Они хотят достигать целей и лучше себя чувствовать. *(Кейс Twiga: думали — учёт финансов, оказалось — «займы без геморроя на 2 года».)*
2. **Всё, что нужно для создания продукта, — в головах клиентов, а не в наших.** Изучай цели людей вместо придумывания фич.
3. **Разрыв шаблона:** Работа ⟂ Решение ⟂ Проблемы — три разные сущности, которые нельзя смешивать.

## Цепочка причинности

```
ПОТРЕБНОСТЬ (не осознаётся)
   ↓ мозг формирует под неё...
ЦЕЛЬ = РАБОТА (Job) — осознаётся
   ↓ человек «нанимает» (hire)...
РЕШЕНИЕ (Solution) — продукт ИЛИ собственные действия
   ↓ от конкретного решения возникают...
ПРОБЛЕМЫ / удовлетворённость / ценность / привычка / барьеры
```

- **Потребности** (~9 базовых, выделены из 7 моделей: SDT, Consistency, Alderfer, McClelland, Self-Efficacy, Maslow, SCARF): физиология, безопасность, социальные/контакт, уважение/**статус**, реализация/рост, автономия, компетентность, согласованность. **Не осознаются.**
- **Работа = цель, которую мозг формирует, чтобы удовлетворить потребность.** Осознаётся. Это и есть JTBD. Фреймворк ничего не выдумывает — он описывает то, как мозг уже работает.
- **Эмоции** — сигнальная система прогресса к цели.
- **Решение** мозг выбирает на внутреннем «аукционе» (огромную роль играет **привычка** — когнитивная простота).

## Разрыв шаблона: Работа ⟂ Решение ⟂ Проблемы

> **Проблема никогда не существует сама по себе — она всегда следствие конкретного решения, нанятого на работу.**

Поэтому, услышав «проблему», нельзя сразу принимать продуктовое решение: неизвестно, (а) платят ли эти люди, (б) важна ли им эта работа, (в) сильна ли проблема. *(Кейс CapCut: «плохо распознаёт русскую речь» — починка проблемы неважной работы у неплатящих не даст роста.)*

Разные решения на одну работу → разные низкоуровневые работы и проблемы (проводные наушники → «распутывать»; беспроводные → «проверять заряд»).

## Шаблон описания работы

**B2C:**
```
[Запоминающееся название]
КОГДА   [контекст + психологические особенности + прошлый опыт + ТРИГГЕР]
ХОЧУ    [понятный мне результат]
ЧТОБЫ   [работа выше уровнем + чувствовать себя по-другому]
РЕШЕНИЕ [доминирующее решение сегмента]
ПРОБЛЕМЫ [проблема 1, 2 … + сила эмоции 1–10]
метаданные: частотность · важность X/10 · удовлетворённость X/10
```

**B2B:** контекст = особенности компании + особенности сотрудника + прошлый опыт компании/сотрудника + триггер; «чтобы» = KPI/OKR (верхний уровень) → за ним личные работы сотрудника. Подробно → [B2B-специфика](konspekty/M1_03_B2B-специфика.md).

> ⚠️ «Понятный мне результат» — критичная формулировка: разные люди при похожей работе хотят разного (студент vs предприниматель про «добраться из A в B»). Это и есть основа сегментации по работам.

# ЧАСТЬ II. Граф работ

> JTBD без графа работ — деньги на ветер. Граф (раньше — «дерево») — структура связанных работ сегмента вокруг целевой работы.

**Навигация:**
- **Вверх (высокоуровневая работа):** «Зачем вам {результат}? Чтобы что?» Высокоуровневые работы **не меняются десятилетиями**. Здесь живут **неожиданные конкуренты**.
- **Вниз (низкоуровневые работы):** «Что вы делали, чтобы получить результат?» → к каждому действию «Какой результат хотели?». Низкоуровневые работы — следствие конкретного решения.
- Связь «хочу ↔ чтобы»: «чтобы» нижней работы = «хочу» верхней (похоже на «5 почему»).

**Насколько копать:** вверх — до уровня, где наше/конкурирующее решение может быть **доминирующим**; вниз — до реальных работ с заметными затратами времени/денег.

**Типы работ** (определяют продуктовую стратегию):

| Тип | Суть | Зачем важен |
|---|---|---|
| Разовые | один раз | — |
| Последовательные | цепочкой друг за другом | здесь люди отваливаются/переходят |
| Частотные | повторяются регулярно | двигатель возвращаемости и LTV |
| Виральные | для/вместе с другими людьми | рост: 2-й человек начнёт пользоваться, если 1-й выполнит работу с продуктом |
| Налоговые | вынужденные издержки | их можно «убить» и создать ценность |
| Ложные [85 lvl] | кажущиеся работы | нужен проверочный вопрос — не двигают к ценности |

# ЧАСТЬ III. Ценность

## Что такое ценность (операционально)

- **Фича** — часть продукта, которую **клиент** считает ценной («в глазах смотрящего»). Само слово не отвечает на вопрос «как создавать ценность».
- **Job/Solution Cost** — вся энергия, время и деньги на выполнение всех низкоуровневых работ с текущим решением.
- **Job/Solution Benefits** — все ресурсы, которые человек получает.
- **Job/Solution Value = Benefits / Cost.** Мозг — аллостатическая машина (Lisa Feldman Barrett): инвестирует энергию в ожидании возврата.

> ❌ **«Проклятый цикл» (фичефактори):** придумать фичу → защитить у стейкхолдеров → метрики → полгода пилить → крохотный сдвиг метрики. AJTBD заменяет это управляемым алгоритмом.

## 11 способов создания ценности

Ценность создаётся напрямую из графа работ:

1. **Растить Benefits внутри одной работы** — лучше звук/камера, больше памяти.
2. **Снижать Cost внутри одной работы, НЕ убивая работу** — скидка, легче телефон, дольше заряд.
3. **Вернуть работу, которая выполнялась, но перестала** — Zoom вернул «встречаться», когда офис закрыт.
4. **Починить проблемы текущего решения** — в т.ч. убить порождённые ими налоговые работы (влагозащита убивает «купить новые наушники»).
5. **Будить спящие работы** — работа есть, но не выполняется из-за адского Cost; резкое снижение Cost будит её (Uber, ChatGPT, AirPods «ходить по дому со звуком»).
6. **Забрать работу у другого решения** — наушники с кнопкой забрали «регулировку громкости/звонки» у телефона.
7. **Убить низкоуровневую работу** — кэш → карты → Apple Pay; «Перевести всё» в Сбере. *Удобство = всегда убийство работ.*
8. **Коммуницировать, что выполняем высокоуровневую работу** — Практикум продаёт не «профессию тестировщика», а «выход из тревоги за семью в стабильность».
9. **Начать выполнять следующую работу** на том уровне, где наняли продукт (механика продуктовой стратегии).
10. **Начать выполнять базовую психологическую потребность** — статус (белые AirPods как сигнал принадлежности); статус активен у всех.
11. **Выполнять высокоуровневые работы нескольких сегментов одним решением** — AirPods Pro + шумодав добавил сегмент «работа в тишине».

## Управляемый алгоритм создания ценности

```
0. Бизнес-задача
1. Выбрать целевой сегмент
2. Изучить дерево работ целевого сегмента
3. Разметить работы по типам
4. Сгенерировать гипотезы ценности по 11 механикам
5. Отранжировать по RICE → делать
```

> **B2B:** ценность = сумма Value для ЛПР + ЛВР + End User + ценность для самого продукта/компании. Подробно → [Принципы создания ценности](konspekty/M1_07_Принципы_создания_ценности.md).

# ЧАСТЬ IV. Конверсия и как люди меняют решения

## Конверсия = КПД продукта

```
                 кол-во людей, выполнивших работу с нашим продуктом
Конверсия = ───────────────────────────────────────────────────────
                 кол-во людей, которых мы подали в продукт
```
Всё, что ниже 100%, — конкретные пробелы по 5 шагам воронки.

## Воронка активации лида в ценность (5 шагов)

| # | Шаг | Чем закрывается |
|---|---|---|
| 1 | Привлекли лида с работой, которую решаем | JTBD для поиска сегмента + тюнинг маркетинга |
| 2 | Предложили ценность выше текущего решения | JTBD для поиска продукта + сравнение с конкурентами |
| 3 | Лид понял ценность | Решенческие интервью |
| 4 | У лида нет тревог и возражений (барьеров) | Решенческие интервью |
| 5 | Активировался и не отвалился из-за инвестиции | UX-тесты |

## Барьеры, драйверы, привычка, Motion

- **Барьеры** — страхи/тревоги/сомнения, что новое решение не выполнит работу. **Пожиратели ценности.** Достаются на решенческих интервью («было ли что-то, что вас останавливало?»).
- **Драйверы** — то, что тянет человека к выполнению работы.
- **Привычка** — физическое изменение мозга. Мозг не любит меняться (дорого), любит знакомое, переоценивает риски нового. → *не прививать новые привычки, переиспользовать существующие, выкатывать постепенно* (кейс PitchMe).
- **Motion** — баланс воспринимаемой пользы (**Perceived** Benefits) и ожидаемой инвестиции (Cost) на каждом шаге. Perceived Value ≫ Cost → идёт дальше; иначе отваливается (частый провал — экран оплаты, где «забыли» показать ценность).

## Итоговое соглашение продукта и клиента

> [обещаем выполнить работу] → [снижаем барьеры: «у нас всё классно»] → [используем драйверы: «представь, как будет круто»] → [требуем заплатить Cost] → [Benefits/Cost > 1] → **[у нас дельта ценности больше, чем у текущего и альтернативных решений]**

*Кейс Яндекс.Браузер vs Chrome:* 60+ JTBD+решенческих интервью (гипотезы работ и барьеров) → количественник (ранжирование). Барьер «минималистичности» оказался рационализацией барьера непривычности. Главный барьер — «не перенесутся пароли» (снимается коммуникацией «переносится в один клик»). Подробно → [Как люди меняют решения](konspekty/M2_01_Как_люди_меняют_решения.md).

# ЧАСТЬ V. Сегмент

> **Сегмент = люди, объединённые общей работой** (не демографией). Ценность, коммуникация и стратегия — всегда следствие выбранного сегмента.

**Главная ошибка:** галлюцинировать, что мы знаем сегменты. Поиск сегмента = поиск **known unknown**.

## Формула приоритизации

```
Score = важность × частотность × размер × (10 − удовлетворённость решением)
```
Чем хуже текущее решение и чем больше ценности мы можем принести — тем проще конкурировать.

> ⚠️ Ни тестирование MVP («тыкать палкой в темноте»), ни проблемные интервью не находят сегменты — проблемные интервью пропускают сегменты с высокой удовлетворённостью, для которых всё равно можно сделать значимо ценнее.

## Алгоритм поиска сегмента

```
Исследование итерациями по 6–8 интервью. В каждой итерации:
  1. Гипотеза работы (максимально высокоуровневая, широкая)
  2. Рекрут респондентов
  3. Кластеризация в сегменты, дифференциация между собой
  4. Отбраковка НЕ-сегментов (с фиксацией «почему»)
  5. Выбор, какие сегменты копать дальше
Полнота: когда два цикла подряд не принесли новых работ.
```

**Логика:** изучаем тех, кто выполняет работу максимально часто и **много платит**; единственный внешний сигнал о наличии работы — **затраты энергии и денег**. Изучаем дерево работ от целевой: наверх («зачем? чтобы что?») и в прошлое (предыдущие последовательные работы = маркетинговая воронка). Подробно → [Поиск сегмента](konspekty/M1_08_Поиск_изучение_сегмента.md).

# ЧАСТЬ VI. Поиск Product/Market Fit

## 4 критерия PMF (нужны одновременно)

1. Большой платёжеспособный сегмент с важной **underserved**-работой, для которой делаем **кратно** ценнее.
2. Клиенты **переходят** на наш продукт с текущего решения.
3. Целевая маржа на платящего (**AMPPU**).
4. Работают каналы привлечения с **предсказуемой юнит-экономикой**.

> Самый вероятный результат поиска PMF — **провал** (90% стартапов умирают; подтверждается 1 из 10–20 гипотез). Отсюда — весь алгоритм.

## RAT — Riskiest Assumption Test

```
Risk Score = Вероятность × Последствия / стоимость проверки
```
Наверх всплывают предположения с высокой вероятностью провала, дорогими последствиями и дешёвой проверкой. **Категории риска (порядок проверки):** рынок/тренды/регуляции → **сегмент** (самый опасный и относительно дешёвый — поэтому всё начинается с кастдева) → продукт → юнит-экономика → масштабирование привлечения.

> ⚠️ Выписывайте **кастомные** рискованные предположения вашего рынка/культуры. *Кейс: Яндекс.Такси потратил 3 месяца в Ереване из-за незамеченного культурного риска (голос навигатора, который не понимали сборщики).*

## Алгоритм поиска PMF с нормативами

```
Рынок/тренды        → кабинетное исследование (можно купить у Venture Analysts)
Сегмент             → JTBD: 30+ интервью (B2C) / 20+ (B2B) на навигацию
                       → 10–12 на сегмент (получить N сегментов по 10 респондентов)
                       → 8+ JTBD-интервью на продукт для выбранного сегмента
Продукт             → решенческие интервью итерациями по 10, пока 2–4 покупки
                       → UX-тест: 3 из 4 активируются в главную работу
                       → активация на проде 60%+
Юнит-экономика      → проверять параллельно
```

- **Пивот** — плановое «кручение ручек» внутри набора рискованных предположений (сегмент/продукт/бизнес-модель/всё). Не катастрофа, а механизм обучения (Airbnb поменяли всё разом).
- **Top-down** (от сегмента к продукту) — основной путь. **Bottom-up** («solution in search of a problem») оправдан только для спящих работ при очень дешёвом MVP.

Подробно → [Поиск PMF](konspekty/M2_02_Поиск_PMF.md).

# ЧАСТЬ VII. Развитие существующего продукта

## Local Optima vs Global Optima

| | Local Optima | Global Optima |
|---|---|---|
| Что меняем | тот же сегмент/продукт/бизнес-модель | новый сегмент И/ИЛИ продукт И/ИЛИ бизнес-модель |
| Риск / награда | низкий риск / ограниченный потолок | высокий риск / кратный рост |

Выбор между ними — **инвестиционное** решение: зависит от ROI на горизонте планирования, компетенций команды, ожиданий стейкхолдеров. Большие компании инвестируют в оба одновременно с разным соотношением.

## ABCD-сегментация (для Local Optima)

> «Не все клиенты одинаково полезны». A/B-клиенты дают ~80% маржи, но часто получают ~20% внимания (C/D громче кричат в саппорте). ABCD — не демография, а **призма ценности продукта** (одна аудитория в разных продуктах попадает в разные сегменты).

**Базовый алгоритм (любая Local Optima задача):**
```
ABCD-сегментация → 10–20+ JTBD-интервью с AB-клиентами:
  • целевые работы, на которые нанимают наш продукт + в чём ценность
    (вопрос «в лоб»: «продай мне продукт, как другу»; aha-moment: «когда понял ценность?»)
  • дерево работ ниже уровня: что выполняем мы, а что — НЕ мы
```
Далее шаблон модифицируется под задачу: чинить проблемы / растить ценность / эффективнее привлекать / **растить возвращаемость** (включая интервью с **отвалившимися** AB — из-за чего ушли и к ценности какого конкурента).

**Сегментация Шона Эллиса** — быстрый аналог для малого числа клиентов: доля **Very Disappointed** ≥ 40% = PMF (Superhuman: 22% → 58% за год работы с Very Disappointed). Подробно → [Развитие продукта](konspekty/M2_04_Развитие_продукта.md).

# ЧАСТЬ VIII. Методы исследования

## JTBD-интервью

**Принцип:** работа живёт в психике, напрямую не видна. Единственная зацепка — **действия** (затраты времени/денег/энергии), не мнения и не гипотетика.

**Поток вопросов (каждый опирается на предыдущий ответ, «monkey see — monkey do»):**
1. Изучаемое решение → «Расскажи, **как** ты это купил/сделал?»
2. **Ожидаемый результат:** «Какой результат хотел получить?»
3. **Контекст/триггер:** «В какой ситуации был, когда решил?»
4. **Работа выше уровнем:** «Зачем тебе это? Чтобы что?»
5. **Работы ниже уровнем:** «Что ты делал, чтобы получить результат?» → к каждому шагу «Какой результат хотел?»

**Правила глубинного интервью** (см. [Глубинные интервью](konspekty/M1_06_Глубинные_интервью.md)):
- ✅ Спрашивай только о **прошлом** (затраты энергии доказывают наличие работы).
- ✅ Эмоциональный контакт до сутевых вопросов; открытые вопросы; один вопрос за раз; не перебивай паузы; докапывайся до эмоций («что тяжёлого в том, что…?»); анализируй сразу после интервью.
- ❌ Не задавай гипотетику/будущее, не используй жаргон, не подсказывай ответ, не задавай по 4 вопроса сразу.
- **B2C:** нейтральный старт без называния продукта. **B2B:** наоборот — прозрачный контракт («вот продукт, вот что хочу узнать»), заземление работы в деньги, карта ролей сделки.

## Решенческие интервью
Проверяют конкретную гипотезу решения/ценности и **барьеры**. Итерациями по 10, пока не будет 2–4 покупок.

## UX-тесты
Быстрый дешёвый поиск ошибок в **любом медиуме** (лендинг, email, скрипт продаж, онбординг, интерфейс — посредник, через который взаимодействуем с клиентом).
- **Протокол (4 вопроса на каждом шаге):** что видишь / что думаешь / что чувствуешь / что хочешь сделать, чтобы {работа}. Не идём дальше, пока не отвечены все 4.
- Метод **RITE/RITE-итерации по 4:** 4 теста → починить всё → следующие 4.
- **Норматив:** из 4 респондентов 3 активируются в главную работу; на проде активация 60%+.
- Подробно → [UX-тесты](konspekty/M2_03_UX-тесты.md).

## Сводка нормативов по объёму исследований

| Задача | Объём |
|---|---|
| Навигация в сегменты | 30+ интервью (B2C) / 20+ (B2B) |
| На один сегмент | 10–12 интервью |
| JTBD для продукта на выбранный сегмент | 8+ интервью |
| Поиск сегмента (итерация) | 6–8 интервью |
| Решенческие интервью | итерациями по 10, до 2–4 покупок |
| UX-тест | 3 из 4 активируются; проде 60%+ |
| Норматив тренинга | 16 JTBD-интервью B2C / 10 B2B + 6 UX-тестов |

# ЧАСТЬ IX. Сборник алгоритмов «по задаче» (cookbook)

> Все алгоритмы выводятся из ядра фреймворка. Это не рецепты для заучивания, а следствия первых принципов.

### 🆕 Сделать продукт с нуля
RAT → кабинетное исследование рынка → JTBD для поиска сегмента (30+/20+ интервью) → выбрать сегмент по Score → 8+ JTBD на продукт → гипотезы ценности по 11 механикам → решенческие интервью (до 2–4 покупок/10) → UX-тесты (3/4) → проверка юнит-экономики. Top-down. Готовься к пивотам.

### 🔍 Найти сегмент для непродающегося продукта
Не чинить продукт «в лоб». Запустить поиск сегмента (итерации 6–8 интервью), искать тех, кто **много платит и часто выполняет работу**, у кого низкая удовлетворённость текущим решением. Пересобрать ценность и коммуникацию под найденный сегмент.

### 📈 Поднять конверсию в продажу
Разложить воронку на 5 шагов → найти, где теряем → закрыть инструментом шага: барьеры (решенческие интервью) → понимание ценности (коммуникация) → активация (UX-тесты) → следить за Motion (Perceived Value vs Cost), особенно на экране оплаты.

### 💎 Растить ценность продукта
Изучить дерево работ AB-сегмента → найти работы, которые выполняем НЕ мы / выполняем с проблемами → применить 11 механик (чинить, +1 работа, убить низкоуровневую, забрать у конкурента, будить спящие) → RICE.

### 🔁 Растить возвращаемость
Фокус на **частотных** работах. JTBD с AB → какие частотные работы дерева выполняет конкурент, а не мы → интервью с **отвалившимися** AB (почему ушли, к какой ценности) → чинить и добавлять частотные работы.

### ⚔️ Выйти из прямой конкуренции (не воевать бюджетами)
Найти высокоуровневую работу / соседний сегмент с underserved-работой → коммуницировать выполнение высокоуровневой работы (механика #8) → создать дельту ценности там, где конкурент слаб (низкая удовлетворённость).

### 🏗️ Развивать существующий продукт
ABCD-сегментация → решить Local vs Global optima (по ROI/компетенциям/стейкхолдерам) → для Local: базовый алгоритм с AB-клиентами под конкретную подзадачу.
