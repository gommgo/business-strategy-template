# Урок 2.1 — Как люди меняют решения и при чём тут конверсия

> **Модуль 2 «Конверсия и PMF» · ~2 ч 35 мин**
> Источники: видео `01.1` (транскрипт ~102 484 симв.), презентация воркшопа 4 (`M2_01.2`).
> Ключевой урок модуля: объясняет, почему люди не переходят на новые решения и что с этим делать.

---

## 🎯 Главное за 60 секунд

1. **Конверсия = КПД продукта.** Сколько людей из поданных в продукт выполнили работу с нашим решением — столько и есть наш КПД. Всё, что мешает 100%, — это наши пробелы.
2. **Пять звеньев воронки.** Провал в любом звене убивает конверсию: нет лидов с нужной работой → нет ценности выше конкурентов → лид не понял ценность → барьеры съедают ценность → лид технически не смог активироваться.
3. **Привычка — физическое изменение мозга.** Привычку нельзя недооценивать: не прививайте новую, переиспользуйте существующую, выкатывайте изменения постепенно.
4. **Барьеры — пожиратели ценности.** Страхи, тревоги, сомнения блокируют переход даже при высокой ценности. Их надо доставать на решенческих интервью и целенаправленно снижать.
5. **Motion — баланс воспринимаемой пользы и инвестиции.** На каждом шаге продукт просит Cost; если Perceived Benefits не превышают Cost — человек отваливается.
6. **Работать нужно с квалифицированными «отвалившимися».** Не разговаривайте со всеми, кто бросил — найдите тех, кто похож на тех, кто дошёл до конца, и ищите их на предыдущих шагах воронки.
7. **Итоговое соглашение продукта и клиента** — явное обещание работы + снижение барьеров + использование драйверов + требование оплатить Cost + дельта выше конкурентов.
8. **Инструментарий закрывает каждый шаг воронки:** JTBD-исследование → дерево работ → решенческие интервью → UX-тесты.

## 1. Что такое конверсия

```
                 Количество людей, выполнивших работу с нашим продуктом
Конверсия  =  ────────────────────────────────────────────────────────
                 Количество людей, которых мы подали в наш продукт
                              [предположительно с работой]
```

Конверсия измеряется в процентах. Нормы сильно варьируются: 0,3–2% для широких каналов, 10–20% для тёплых. Конверсия — это **КПД продукта**: чем выше, тем эффективнее система.

> ⚠️ «Выполнение работы» ≠ только «оплата». Для триала — это совершение ключевого действия (пример CleanMyMac: нажать «удалить» после сканирования = намерение = выполнение работы). Для B2B — подписать договор, отправить письмо руководителю, дать предоплату.

## 2. Пять шагов воронки активации лида в ценность

Это **условия**, которые должны выполниться одновременно. Провал в любом — потеря конверсии.

```
┌──────────────────────────────────────────────────────────────────────┐
│  ШАГ 1  │  Привлекли лида с работой, которую мы решаем             │
│         │  Инструмент: JTBD для поиска сегмента + тюнинг маркетинга │
├──────────────────────────────────────────────────────────────────────┤
│  ШАГ 2  │  Предложили ценность выше текущего решения/конкурентов    │
│         │  Инструмент: дерево работ → 11 механик создания ценности  │
├──────────────────────────────────────────────────────────────────────┤
│  ШАГ 3  │  Лид понял ценность продукта (aha-moment)                 │
│         │  Инструмент: решенческие интервью (лендинг/скрипт продаж) │
├──────────────────────────────────────────────────────────────────────┤
│  ШАГ 4  │  У лида нет тревог и возражений к нашему решению          │
│         │  Инструмент: решенческие интервью → работа с барьерами    │
├──────────────────────────────────────────────────────────────────────┤
│  ШАГ 5  │  Лид смог активироваться в ценность и не отвалился        │
│         │  из-за высокой инвестиции                                  │
│         │  Инструмент: UX-тесты                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### Что ломается на каждом шаге

| Шаг | Типичный сбой |
|-----|--------------|
| 1 | Делаем продукт, не зная сегмент; привлекаем «не тех» людей |
| 2 | Ценность создана «из головы», не из дерева работ |
| 3 | Ценность есть, но не загружена в голову клиента (лендинг, скрипт не работают) |
| 4 | Барьеры не выявлены и не закрыты |
| 5 | Технические ошибки, сложная форма, адовая регистрация |

## 3. Почему люди вообще меняют решения — три причины

1. **Изменились работы** — появилась новая работа, проснулась спящая, изменился контекст (переезд, новая роль, внешние события).
2. **Сильные проблемы с текущим решением** — раздражение копится, решение сломалось или деградировало, ценность упала.
3. **Узнали про более ценное решение** — друг рассказал, реклама, инфлюенсер. *Это реактивная реакция: «мне показали, я решил изучить».*

## 4. Четыре силы перехода (Switch Forces)

Модель из книги Intercom о JTBD. Возникает только в **уникальный момент** — когда человек пользуется текущим решением и **одновременно** изучает новое.

```
        ВПЕРЁД (к новому решению):
        ├── Ценность нового решения  ← в нашей зоне контроля
        └── Проблемы текущего решения  ← влиять сложнее

        НАЗАД (к старому решению):
        ├── Барьеры к новому решению  ← в нашей зоне контроля
        └── Привычка к текущему решению  ← влиять сложнее
```

> ⚠️ Важное ограничение: четыре силы действуют только когда человек **активно изучает** новое решение. Если он этого не делает — барьеров и ценности для него не существует.

**Стратегический вывод:** не бороться «со всеми» — искать **сегменты**, у которых пропорция сил уже в нашу пользу. Стартап-стратегия: найти сегмент с сильными проблемами, для которого первая версия «без проблем» уже лучше текущего.

## 5. Привычка — невероятная сила

### Что такое привычка

**Привычка = физическое изменение мозга.** Мозг взрослого человека — набор функциональных нейронных сетей. При регулярном использовании продукта мозг буквально перестраивается под него. Убрать это невозможно быстро.

Три механизма, почему привычка так сильна:
1. **Мозг не любит меняться** — это энергозатратно. «Давайте ездить по той дороге, что уже проложена».
2. **Мозг любит знакомое** — знакомым сущностям больше доверия, с ними ощущение безопасности.
3. **Мозг переоценивает потенциальные негативные последствия** — эволюционно новое часто было опасным; тревога при встрече с новым — базовый ответ.

Дополнительно: **люди сильно недооценивают силу своих привычек** — и мы, создатели продуктов, делаем то же самое.

> 📌 Кейс CityMobile: вбухали огромные деньги, давали 2000 ₽ на бесплатные поездки. Треть-половина аудитории попробовали, сервис был сравним по качеству с Яндекс.Такси. Итог: остались пользоваться — 3–4 человека из аудитории. Люди вернулись к привычке. Вывод: продукт «на уровне» не отвоёвывает рынок — нужна принципиально другая ценность.

### Три принципа работы с привычкой

1. **Не прививайте новые привычки** — это дорого и долго (30–40 повторений, ~3 месяца).
2. **Переиспользуйте существующие привычки** — встраивайтесь в то, что человек уже делает.
3. **Выкатывайте изменения в существующем продукте постепенно** — минимум когнитивного стресса.

> 📌 Кейс PitchMe: стартап — CRM для HR (рынок США/UK). Главный конкурент — древнее корявое решение типа Salesforce, к которому HR невероятно привыкли. PitchMe не стал бороться с привычкой — он **встроился в интерфейс текущего решения**, добавив надстройку с более точными данными о кандидатах. Продажи пошли, Product/Market Fit найден. Урок: не борись с привычкой — паразитируй на ней.

> 📌 Кейс Яндекс.Браузер (привычка): на решенческих интервью пользователи Chrome при переходе на Яндекс.Браузер говорили «зачем у вас поиск не по центру, открываю вкладку — другое поведение». Команда зафиксировала все «непривычные штуки» и стала повторять поведение Chrome — чтобы при переходе мозг пользователя встречал наименьшее количество незнакомого и не тратил когнитивные усилия.

## 6. Барьеры — пожиратели ценности

### Что такое барьеры

> **Барьер = страх, тревога, сомнение, что новое решение не оптимально выполнит мою работу.**

Барьеры бывают двух видов:
- **К нашему продукту** — «слышал, что CleanMyMac ворует данные», «боюсь, что не перенесутся пароли».
- **К выполнению работы в принципе** — «страшно идти к психотерапевту», «непонятно, нужен ли мне психолог».

Барьеры **пожирают ценность**: даже если ценность высокая, барьер может полностью заблокировать переход.

> ⚠️ Барьеры ≠ проблемы продукта. Проблема = то, с чем человек уже столкнулся (Glovo не привезло). Барьер = то, что останавливает ещё до/вне опыта использования («боюсь, что не привезут свежее»).

### Как доставать барьеры

**Если клиент уже рассматривал продукт:**
> «Было ли что-то, что останавливало вас от того, чтобы начать использовать это решение? Может, вас что-то тревожило, что решение не оптимально выполнит вашу работу?»

**Если клиент ещё не рассматривал продукт:**
Проводим **решенческое интервью** — предлагаем прямо сейчас купить/зарегистрироваться/поделиться. Получаем реальный ответ «да/нет», а не «классно/не классно». Если нет — спрашиваем: «Что останавливает?»

> ⚠️ На решенческом интервью важно получить **инвестицию**, а не оценку. Человек, который сказал «классно», ещё ничего не решил. Человек, который написал письмо руководителю — уже решил.

### Как снижать барьеры

Пример из кейса Яндекс.Браузера: основной барьер — «у меня там все авторизовано, пароли, закладки, всё не перенесётся». На самом деле всё переносится одним кликом. Гипотезы снижения: рассказать на лендинге → в рекламе → в скрипте инфлюенсера → при онбординге. За полгода барьер значительно снизился.

## 7. Работа с последовательными работами и «отвалившимися»

### Воронка последовательных работ (кейс: депрессия → психотерапевт)

Люди идут по последовательности работ, и на каждом шаге часть отваливается — это нормально.

```
100%                    20%                      4%                       <1%
важность: 7/10          важность: 4/10           важность: 6/10           важность: 8/10
«У меня депрессия,  →   «Понял: нужен       →   «Когда не страшно,   →   «Нужен терапевт,
хочу понять           психолог, страшно,       хочу понять,             хочу найти
что делать»           успокойте меня»          нужен ли МНЕ»            подходящего»

Отвалились: 70% → «прошло само / да не особо болит»
            14% → «прошло само, страшно, ну и нафиг»
            3%  → «прошло само, ой, сложна...»
```

Аналогичная воронка у Ultimate Guitar (научиться играть на гитаре → криво лабать любимую → хорошо играть → криво играть популярные → лабать на вечеринке).

### Как правильно работать с отвалившимися

**Не** разговаривать со всеми подряд — высокий риск попасть на ложные работы, неважные работы или людей, которые в принципе никогда не заплатят.

**Правильная последовательность:**
1. Найти квалифицирующие факторы, которые объединяют тех, кто **дошёл до конца**.
2. На предыдущих шагах воронки искать отвалившихся, которые **похожи** на тех, кто дошёл.
3. Разговаривать именно с ними.

> 📌 Кейс книгоиздание (2019): исследовал предпринимателей. Два сегмента — кто написали книгу и кто давно хотят. Второй сегмент находится в «хочу» уже годами — ложная/неважная работа? Анализ тех, кто написали, дал 5 квалифицирующих факторов: (1) гордятся своим бизнесом, (2) считают контент уникальным, (3) регулярно рефлексируют/перерабатывают материал, (4) книга — не первый канал (есть блог/YouTube/выступления), (5) много черновиков. → Искать таких людей на этапах ДО написания книги.

> 📌 Кейс Ultimate Guitar: смотрим, что объединяет тех, кто уже хорошо играет → ищем таких же среди бросивших на ранних этапах → разговариваем только с ними.

**Бонус:** интервью с теми, кто дошёл до конца, позволяет узнать **все предыдущие работы** за одно интервью.

## 8. Драйверы к выполнению работы

На пути по последовательным работам человека тянут вперёд **два типа сил**:
- **Ценность продукта** — прямой рычаг, мы управляем.
- **Драйверы** — внутренние факторы и события, не связанные напрямую с нашим продуктом.

Человека останавливают:
- **Проблемы продукта** — то, с чем уже столкнулся.
- **Барьеры к выполнению работы** — тревоги и сомнения.

> 📌 Кейс refeel (матча): AB-сегмент — девушки, у которых были ритуалы с кофе, но организм перестал переносить кофе (ЖКТ, нервная система). Ритуалы остались, а напитка нет. Драйверы первой покупки: бренд коммуницирует о здоровье (мне близко), мне рекомендовали, нравятся креативы, ищу замену кофе. Барьеры первой покупки: дорого (20 порций = 2420 ₽), нет физических точек продаж, нет пробников, страх — «заплачу много, не понравится». Драйверы повторных покупок: дешевле кафе, программа лояльности, принадлежность сообществу, удобная упаковка, вижу влияние на здоровье, нравится вкус и ритуалы.

## 9. Motion — баланс воспринимаемой ценности и инвестиции

> **Пройдёт ли человек дальше в вашем продукте — следствие баланса воспринимаемой субъективной пользы и ожидаемой инвестиции.**

```
Job/Solution Perceived Benefits    vs    Job/Solution Cost

Если Perceived Value >> Cost    → человек скорее пройдёт дальше
Если ценность не видна, а Cost требуется → человек отвалится
Если ценность понятна, но Cost огромен   → продукт убивает адовой инвестицией
```

### Три сценария провала Motion

| Ситуация | Эффект |
|----------|--------|
| Просите Cost, но забыли рассказать ценность | Человек не понимает, за что платит |
| Ценность есть, но просите огромную инвестицию (адовая форма) | Человек отваливается даже при интересе |
| Ценность и Cost примерно равны | Человек колеблется — конвертируется плохо |

> 📌 Кейс приложения Motion (AI-календарь): на лендинге — «теперь в году 13 месяцев», обещают больше времени, сфокусированность, сон. На каждом экране параллельно просят: оставить контакт → авторизоваться Google → выбрать тариф → ввести карту. Самый большой отвал — на экране оплаты, потому что именно здесь Cost (деньги реальные) впервые превышает воспринимаемую ценность.

> 📌 Личный кейс (кинотеатр на Бали): огромная мотивация посмотреть нового Тора. Сайт: зарегистрируйся → подтверди СМС → подтверди email → пополни кошелёк → подожди СМС → заплати из кошелька. Пример, когда Cost убивает даже очень сильный драйвер. Автор прошёл только из-за гиперважности работы.

## 10. Итоговое соглашение продукта и клиента

Успешный продукт подписывает с клиентом неявное соглашение из пяти пунктов:

```
[1] Обещаем выполнить работу
    «Мы, мамой клянёмся, выполним важную для тебя работу»
    (для B2B — работу ЛПР, ЛВР и End User)

[2] Снижаем барьеры
    «Если кажется, что мы плохо выполним работу — нет, смотри, у нас всё классно»
    (отзывы, гарантии, демо, кейсы, снятие конкретных тревог)

[3] Используем драйверы к выполнению работы
    «Представь как будет круто — ты же этого хочешь»
    (встраиваемся в мотивацию человека, усиливаем её)

[4] Требуем заплатить Job/Solution Cost
    «От тебя потребуется инвестиция времени, энергии и денег»
    (честно, без скрытых затрат)

[5] Дельта ценности выше, чем у конкурентов
    «Итоговая польза будет выше инвестиций, и дельта лучше, чем у текущего решения»
```

## 11. Кейс: Яндекс.Браузер vs Google Chrome

### Контекст

Год назад (2022) команда Яндекс.Браузера пришла с задачей: Chrome — 41% рынка, Яндекс.Браузер — 35%. Текущий продуктовый подход не отъедает клиентов. Нужно понять, куда инвестировать.

### Последовательность решения задачи

**Шаг 1. Качественный этап (60+ JTBD + решенческих интервью)**

Что изучали:
- Работы, которые пользователи Chrome выполняют в браузере (собрали 60–80 работ).
- Барьеры пользователей Chrome к Яндекс.Браузеру.
- Как люди пришли к установке Chrome.

**Ключевые находки качественного этапа:**
- Подавляющее большинство установили Chrome **по совету более знающего человека** (друг, коллега-разработчик, админ) → решение: сделали 20 интервью с инфлюенсерами (YouTube-блогеры + микроинфлюенсеры-эксперты), узнали по каким принципам они рекомендуют → сформировали отдельный большой трек работы с инфлюенсерами.
- Собрали набор барьеров → отправили на ранжирование в количественник.
- Барьер «минималистичность» (пользователи Chrome: «у вас пёстро, много всего, у Chrome чисто») — казался крупнейшим на качественном этапе.

**Шаг 2. Количественный этап (1500+ респондентов)**

Инструмент: анкета на Толоке. По каждой работе — «выполняешь / нет, как часто» (4 варианта от «несколько раз в день» до «несколько раз в год»).

**Находки количественного этапа:**
1. Отранжировали группы работ → попилили стримы разработки, наняли людей (январь–июль 2023).
2. **Барьеры переранжировались** — качественный этап дал неверное ранжирование. Барьер «минималистичность» упал почти в ноль → перестали инвестировать.
3. **Главный барьер (сюрприз-сюрприз)**: «у меня там всё авторизовано, все пароли, закладки — я не смогу это перенести». На самом деле Яндекс.Браузер переносит всё одним кликом → команда начала коммуницировать это на всех точках касания.
4. Дополнительные барьеры: «плохо работают сервисы Google», «хуже работают рабочие сайты» → команды генерируют гипотезы снижения.
5. Сегментация по работам не дала кластеров — 1500 человек показали однородное облако → отказались от кластеризации, перешли к **смысловым группам работ**.

**Топ группа работ пользователей Chrome:**
«Когда у меня есть задача, которую нужно сделать со вкладкой — держу её на виду, чтобы помнить; не закрываю, пока не сделаю» (вкладка как тудушка/напоминалка).

Под эту группу работ — отдельный стрим: умные уведомления, ответ прямо из уведомления (snooze, архив, удалить, спам), добавление сервисов как приложения и т.д.

### Итог и уроки кейса

| Урок | Суть |
|------|------|
| Качественный этап — для поиска гипотез, не для ранжирования | Ранжировать только количественно |
| Инфлюенсеры — отдельный стратегический трек | Подавляющее большинство установок по рекомендации |
| Барьер «минималистичности» = рационализация барьера непривычности | Не тратить ресурсы на рационализацию |
| Главный барьер — отсутствие ценностей для перехода | Ценность создаётся под конкретные работы сегмента |

## 12. Инструменты для каждого шага воронки (сводная таблица)

| Шаг воронки | Инструмент |
|-------------|-----------|
| Привлечь лидов с нужной работой | JTBD-исследование (Switch-интервью) + настройка каналов |
| Создать ценность выше конкурентов | Дерево работ + 11 механик создания ценности |
| Загрузить ценность в голову лида | Решенческие интервью (лендинг, скрипт продаж, имейл) |
| Снизить барьеры и тревоги | Решенческие интервью → гипотезы снижения барьеров |
| Помочь активироваться в ценность | UX-тесты (лендинг, онбординг, интерфейс) |

**Эффективное совмещение:** если респондент согласился на 1,5 часа — в одном сеансе можно: JTBD-интервью + решенческий блок + UX-тест. За одно интервью: дерево работ + проверка ценности + барьеры + UX.

## 13. Switch-интервью

Отдельный вид интервью (из публичного знания о JTBD), фокусируется на **процессе смены решения**:

- Какое решение использовал раньше, почему, какая ценность, какие проблемы.
- Почему захотел сменить, какие факторы внешние и внутренние.
- Что гуглил, с кем советовался, что слышал от инфлюенсеров, на что реагировал.
- Как сравнивал, что в итоге выбрал.

Знание этого процесса → точные **креативы и маркетинговые кампании** (реклама = коммуникация ценности в нужный момент, словами нужных людей).

## ⚠️ Важные ограничения и антипаттерны

- **Антипаттерн:** разговаривать со всеми отвалившимися подряд → тратите время на ложные работы и незаинтересованных.
- **Антипаттерн:** ранжировать барьеры и работы только по качественному этапу → ошибочные приоритеты (кейс Яндекс.Браузера с «минималистичностью»).
- **Антипаттерн:** привязываться к оценке «классно/не классно» на решенческом интервью → нужна реальная инвестиция человека (деньги, подписание, шаринг).
- **Антипаттерн:** недооценивать силу привычки и выкатывать большие изменения разом → отток пользователей.
- **Антипаттерн:** просить большой Cost, не показав ценность перед этим → самый высокий отвал именно на экране оплаты.

## 📝 Практика урока

1. **Барьеры своего продукта:** написать 5–10 барьеров, которые могут останавливать ваших потенциальных клиентов от перехода. Для каждого — гипотезу, как снизить.
2. **Воронка активации:** нарисовать 5-шаговую воронку для своего продукта. Для каждого шага — какой инструмент закроет этот шаг? Где сейчас самый большой отвал?
3. **Motion-анализ:** взять любой экран своего продукта (лендинг, онбординг). Что обещаем? Что просим? Положительная ли дельта?
4. **Switch-интервью:** провести 2–3 интервью с людьми, которые переходили с решения на решение в вашей нише. Зафиксировать: триггер, что изучали, на что реагировали, какие барьеры.
5. **Квалифицирующие факторы:** если есть пользователи, которые дошли до «активации» — провести интервью, выписать 3–5 факторов, которые их объединяют. Использовать как фильтр для отбора отвалившихся.
