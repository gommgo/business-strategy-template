# Ф8 — ключ посеянных дефектов (сценарий «пакет» проверки §6)

Пишет оркестратор до запуска C13 (`../PLAN.md` §2 «C13», §6). Фикстуру с этими дефектами строит C13 в
`scripts/tests/fixtures/` (бриф `../briefs/C13.md`, та же таблица); агент проверки шага 11 этот файл не читает — он
проходит сценарий «пакет» по `SKILL.md`, указателю утилит и `--help`, а оркестратор сверяет его ответы с ключом.

Готово: `design_audit` на фикстуре с дефектами находит все 14 — ровно этими правилами и с путём к месту дефекта;
лишних `error` нет (лишние `warning` и `hint` — с объяснением в отчёте C13).

а не одной парой «правило + путь» (Р204). Дефект 9 даёт три находки R-FRESH-001 — по одной на производное (CSS,
передняя часть `DESIGN.md`, `tokens.json` артефакта); это один дефект.
