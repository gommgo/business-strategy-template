## 3. Отступления от плана и спецификации

- **GT-11: `budgets.page` и `fonts_kb` снимаются вместе с читателями — у C14.** Пороги ворот эффектов читают
  `budgets.page.*` и `budgets.effects.fonts_kb` по `threshold_ref` (EG-PERF-04…06, EG-WEIGHT-07…09 в
  `effect-gates.yaml`), а самопроверка `motion_check.py` — порог T-02 (`budgets.page.first_screen_mb`, L1 телефон 2,0) и
  «`threshold_ref` разрешается для L0–L2». Оба файла — C14, трогать их бриф запрещает; снятие ключей сейчас уронило бы
  смоук `motion_check.py --selftest`. Сделано ближайшее без поломки: `budgets.page_ref` на профиль site; `page` —
  зеркало с пометкой «для threshold_ref ворот эффектов»; `scroll_fps_min` живёт в `budgets.effects` (якорь YAML), путь
  страницы — ссылка YAML на него (одно значение); `fonts_kb` — зеркало с пометкой. Предложение: C14 на шаге 7 переводит
  перечисленные `threshold_ref` на `budgets.yaml` (со `scale` МБ → КБ, с → мс) и `budgets.effects.scroll_fps_min`,
  правит T-02 и снимает из `ambition-levels.yaml` блоки `levels[].budgets.page` и `budgets.effects.fonts_kb` (файл
  нужно вписать в бриф C14). Решает оркестратор.
- **GT-08: у L2 кадр в покое — 30 / 60, «мир» при прокрутке — 50 / 100.** Строка `draw_calls_max` L2 держала 30 / 100
  (100 — «мир»). По решению узла (`draw_calls_max` — кадр в покое; L2 десктоп 100 — кадр сцены-«мира», при прокрутке
  ≤ 50 / 100 — blender 11/05 §11) число 100 переехало в `draw_calls_scroll_max`, а десктоп кадра в покое L2 стал 60 по
  канону blender (WEB-05). Читателей в коде нет.
- **Схема `treatment`: потолки петель по уровню сняты из `allOf`.** Они повторяли числа уровней (1 / 2 / 3); теперь их
  проверяет `spec_check.py` (TR-21) по YAML — иначе смена числа в YAML расходилась бы со схемой. Изменение совместимое
  (схема стала мягче); `site_validate.py` зовёт `spec_check.py plan` (TR-25, C7). Ограничение `chrome` — 0 петель —
  осталось в схеме (правило роли, не число уровня).
- **`$defs/reference`: `source` — три значения** (`customer`, `claude`, `creative-library`), как у `site-brief`: запись
  библиотеки заказчика (`ref:<id>`) — третий источник; спецификация C6 называет два. Форма для C7 — §4.
- **Длительности K2 — роли `motion.marketing` и эталонные токены ui**, а не список пресета профиля
  (`marketing-profile.yaml#preset.durations`): `marketing_audit.py` подменяет `P["durations"]` после `load_profile`.
  Значения 80, 160, 240, 250, 350, 450, 480, 700 мс теперь вне шкалы (полировка D) — по NU-26 это и есть норма. Строку
  `preset.durations` профиля (файл C2) код не читает — снять её может оркестратор или Ф10.
- **MKT-C2 стал находкой** (FAIL, серьёзно) при доле полосы выше порога записи или арт-дирекции и без бренда в полосе
  или `--allow cliche:purple-neon-band` — по VI-34 полоса без бренда — примета на любой поверхности; прежде было
  «информативно».
- **Надзаголовки: число владельца пока читается из `pass_when` COPY-C-18** («не чаще 1 на 3 секции»): отдельного
  числового поля у text нет. Код сначала ищет поле `per_sections` анализатора `an-eyebrow-rate` (предложение C15, §4).
- **`registry_check.py` в смоуке — только `--selftest`:** прогон по реестру базы даёт код 1 (9 расхождений, реестр правит
  Ф10). Самопроверка проверяет и то, что у реестра базы 0 ошибок структуры, и печатает расхождения.

  `--json`.

## 4. Для следующих зон

### Контракт `x-canvas-map` (первый писатель — C4; C7, C8 следуют, C11 читает)

Один ключ верхнего уровня у схемы-владельца (у YAML-данных — у файла). Форма:

```text
x-canvas-map:
  source: <id документа-источника>        # обязательно; от его корня считаются указатели from
  stages: [<этап>, …]                      # обязательно; directions | wireframe | mockup | motion — где проекция нужна
  base: {<указатель схемы>: <указатель источника>}   # по желанию: где лежат экземпляры схемы в чужом документе
  files:                                   # обязательно
    <файл входа>:                          # путь внутри <surface>/input/ по протоколу: brief.yaml, refs.md,
                                           # pages/<page-id>/page.yaml, pages/<page-id>/motion.md, contract.md, …
      <поле холста>:                       # YAML/JSON входа — путь через точку, элемент списка — «[]»
                                           # (decisions.motion.level, sections[].treatment.level); md входа — заголовок
                                           # раздела или колонки протокола дословно (роль, брать, не брать, значения, снято)
        rule: copy | map | derive | drop | claude_fills
        from: [<указатель>, …]             # JSON Pointer (RFC 6901) от корня source; «*» — любой элемент списка или ключ;
                                           # поле другого документа — «<id>#<указатель>»; у claude_fills — []
        note: <строка>                     # обязательна у map, derive, drop, claude_fills; у copy — по желанию
        stages: [<этап>, …]                # по желанию — подмножество stages
        values: {<значение источника>: <значение холста>}   # по желанию, только у map — словарь перевода
  drop:                                    # поля источника, которые во вход не идут ни в каком файле
    - {from: [<указатель>, …], note: <причина>}
  <имя блока>: …                           # другие ключи — именованные блоки владельца (у text: publish_filter, facts_md,
                                           # missing_md, never_claim_md, copy_md); сборщик читает их по имени
```

- **Покрытие (правило сборщика C11):** каждое заполненное поле документа-источника покрыто указателем `from` любого
  правила или `drop` — самим указателем или предком (`*` совпадает с любым элементом). Поле источника без правила —
  ошибка сборщика с именем поля и схемы. Карты с одним `source` покрывают документ вместе: у `page-plan` (C7) поддерево
