## 3. Отступления от плана и спецификации

1. **id приметы: в `tells.yaml#checks` нет ключей `ui_audit`.** Раздел `checks` держит только проверки `mockup_checks.py`
   (K3-*, F-*, M-*, V-*, E-*). Сделано ближайшее к решению оркестратора: `ui_audit` берёт id приметы только из
   `checks`, ключом `ui_audit:<id проверки>`, в код id не зашиты; пока ключей нет, поле `tell` пустое, раздел «Приметы»
   не выводится. Механизм проверен самопроверкой на подставленном реестре. Предлагаемые строки — §4 (оркестратору);
   `tells.yaml` я только читал.
2. **VI-22, D4: в `glass-panel.limits` чисел свечения нет.** D3 профиля берёт все четыре лимита записи `glass-panel`.
   Для D4 число — `glow_max: 1` в данных профиля по решению узла («свечение — только `shadow.cta-glow` у одной кнопки
   по решению арт-дирекции», creative 04/03 §4.3); счёт — элементы со свечением, а не строки тени. Таблица профиля в
   каноне (creative 09/03 §4.2) пишет «≤ 2» — её выровнять (§8).
3. **Профиль `marketing` в `ui_audit` — API, а не ключ CLI.** Профиль один на скилл (GT-40): его применяет
   `marketing_audit.py`. `ui_audit` даёт `load_profile` (пресет + таблица из данных, лимиты стекла из каталога),
   `apply_profile` (keep, retune, severity, info) и сам считает D3, D4, L4 при пресете профиля (ключи `glass_*`,
   `glow_max`, `purple_band` есть только у него); остальные строки `recompute` (A1, A2, B1, B2, H1, H2, H4, H10, J6,
   J8, L5, J3) по-прежнему считает `marketing_audit.py` — C4 переводит его на данные (§4). Значения пресета страницы
   перенесены из `PRESET_MARKETING` без изменения чисел, кроме строк по действиям: D3 (VI-22), D4 (VI-22), F1 — тач 44
   (NU-09), H8 — в знаках (NU-18), K2 — без потолка пресета (потолок страницы — уровень амбиций, `motion_check.py`);
   `para_max_width` из профиля убран (H8 в знаках).
4. **Токены без ключа у consumer.** Бриф: без `--tokens` — эталонные токены ui. Эталон — токены пресета A («плотная
   админка»); у B эталона нет, а шкалы A на экране B дали бы ложные находки (радиус 10, контрол 40). Сделано: без ключа
   admin берёт эталонные токены, consumer — шкалы пресета; источник шкал записан в отчёте проверки и JSON (`tokens`).
5. **F1 на таче.** Раньше тач-прогон поднимал порог F1 до 44 с исключением «зазор 2.5.8» (блокер). Теперь F1 — 24×24
   или зазор везде (блокер), на тач-прогоне ещё F3 — зона ≥ 44×44 у каждой цели, серьёзно (UX-A11-14 — S; 44 —
   AAA, NU-09). `ctx["target_min"]` вызывающей утилиты больше не читается: `marketing_audit.py` передаёт его на тач-прогоне
   consumer — теперь там 24 плюс F3, что и требует NU-09 для страницы.
6. **H8 до правки не срабатывал никогда**: текст узла в `COLLECT_JS` обрезан до 120 знаков, а условие было «> 120».
   Длина текста теперь собирается отдельно (`tlen` у p, li, dd, blockquote) — на реальных страницах H8 начнёт
   находить длинные строки. Для строк без `tlen` (синтетика вызывающих утилит) остался прежний порог в px.
7. **Скрытое вне F.** Бриф называет I1 и H; визуально скрытое исключено и из целей нажатия: sr-only ссылка «к
   содержимому» и скрытый нативный чекбокс — не цели на экране, иначе F1 давал ложный блокер.
8. **`master-checklist.yaml`: строка `generated_at` заменена `source_sha256_16`.** С временем запуска `--check` не может
   сверять байт в байт. Остальной дифф — только из md (§5).
9. **ux 06/01 §8.1:** кроме перечня, в том же блоке исправлена строка приоритета (S23 между S16 и S13) — иначе файл
   спорил бы сам с собой.
10. **`build_reference_tokens.py`:** вывод CSS и Tailwind оставлен байт в байт прежним — `kb/ui/14-recipes/examples/tokens.css`
    не моя зона и совпадает с выводом; поэтому строки шапки CSS («Эталонный набор токенов ui-research…»,
    «99-raw/tools/…») и `$description` JSON — прежние (§8).
11. **`measure_ui.py --selftest`** — новый: у утилиты не было самопроверки, а изменённое поведение (порог шапки) надо
    проверять без браузера.
12. **`components.yaml`:** кроме `screen_states`, у типа Chart в `app_css` добавлены классы новой серии графика
    (`.bar-pair`, `.bar--2`) — словарь перечисляет классы эталонного слоя.
