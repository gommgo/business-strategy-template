## 3. Отступления от плана и спецификации

1. **`kind` находок — `design-system`**, а не `system` из примера брифа: так называется вид записи ДС в каноне
   (`_template/design/README.md § Файлы`, таблица kind: «токены, проза, карта решений, артефакт — одна запись»). `ref` —
   `system#/components/<Тип>`, `system#/extensions/<i>/…`, `tokens#<JSON Pointer>`, `tokens-css`, `design-md#front-matter`,
   `artifact#tokens.json`, `artifact#README.md`, `artifact#components/<Компонент>`. Варианты: (а) оставить; (б) `system`.
   Рекомендация — (а).
2. **Команды сверх `build`/`check`:** у всех трёх — `show` (как `tree show`); у `ds_coverage` нет `build` (утилита только
   проверяет), есть `--stage ds-components|mockup`; у `ds_sync` — обязательный `--live FILE` и `--write`.
3. **NU-15 — значение выводится сборкой, поля в DTCG нет:** узкая ширина `type.body` = max(кегль, 16 px) ниже первой
   границы `breakpoint.*`; в `system.tokens.css` — блок `@media (width < …)`, в передней части — `x-narrow`. «Мобильная
   поверхность» прочитана как узкая ширина продукта (веб ниже первой границы и приложение `type: mobile`). Развилка: как
   мобильное приложение берёт это значение — README mobile говорит «тема из `system.tokens.json`»; сейчас значение есть в
   `x-narrow` передней части `DESIGN.md` и в CSS. Варианты: (а) приложение читает `x-narrow` (тексты — C17); (б) режим
   `narrow` в `$extensions["org.ui-research.modes"]` токена `type.body` (новое имя режима — решение базы ui, Ф10);
   (в) отдельная проверка у `/mobile-audit`. Рекомендация — (а) до пилота SaaS с приложением.
4. **Имена CSS-переменных 1:1 с путями (Р42) против таблицы переименований ui 09/04 §6.3** (`--fg-*`, `--corner-*`,
   `--palette-*`, `--scale-*`, `--bp-*` — чтобы не занять пространства имён Tailwind). Сборка следует Р42 и примеру cd
   (`--color-bg`, `--radius-sm`); мост к Tailwind `@theme inline` код-репо строит сам и не пишет самоссылок вида
   `--radius-sm: var(--radius-sm)`. Решает оркестратор; мост — Ф9 (пилот SaaS) или шаблон `<org>/frontend`.
5. **Что не идёт в `tokens.json` артефакта:** примитивы `primitive.*` и движение (группы `motion*`, типы duration,
   cubicBezier, transition — у формата артефакта нет семейства движения, cd 05/01 §3.2; длительности и кривые пишутся в
   `…/_design-system/project/components/bundle.css` руками). В CSS и передней части они есть. Поля артефакта, которых нет в DTCG (семейство токена
   без префикса группы, группа и образец стиля текста, имя системы, заметки семейств), — новое расширение
   `$extensions["org.design-deep-dive.artifact"]`; `usage` = `$description`.
6. **Передняя часть `DESIGN.md`** — ключи формата Google Labs (`version: alpha`, `name`, `description`, `colors`,
   `typography`, `rounded`, `spacing`) и три своих: `x-tokens` (прочие токены), `x-modes` (темы, плотность, сокращённое
   движение — транзитивно), `x-narrow`. Необязательный `npx @google/design.md lint` предупредит об этих ключах
   (`unknown-key`). Имя системы — поле `name` расширения артефакта, иначе заголовок прозы, иначе имя бренда, иначе slug.
7. **Правка на странице артефакта поднимается литералом в путь имени** (алиас роли рвётся); предложение называет прежний
   алиас и соседей на нём — правку примитива выбирает владелец. Автоматического «правка у всех ролей → примитив» нет.
8. **Фикстура:** артефакт — слой примера cd целиком (остаются `design-system.json` «Спицы», `bundle.css`, `Cover`,
   `ServiceCard`, `Steps` — не сопоставлены типам, покрытию не мешают), свои компоненты перекрывают `Button` и `Field`;
   производные лежат собранными (фикстура свежая сразу, как `map.md` у `cabinet`). В блок `request-details` правкой
   `replace` добавлен `ui:AddressMap` — расширение, названное в stable-экране; файлы `cabinet` не правились.
9. **`kb/common/README.md`:** кроме трёх строк таблицы — одна фраза вступления (что лежит в папке), чтобы вступление не
   отставало от таблицы.
10. **Схема `app-brief` ссылается на схемы-владельцы** (`meaning#/properties/legal_category`,
    `site-brief#/$defs/reference/properties/role`): одно место перечня; валидатору нужен реестр со схемами meaning и
    site-brief (`ds_coverage.registry()`).
11. **Объём** — ≈ 3,1 тыс. строк кода (оценка плана 1,2–1,8 тыс.): самопроверки ≈ 0,6 тыс., встроенная схема DTCG и
    правка JSON по месту без переформатирования.
