## Зона
Замыкающие утилиты `project/`: манифест готовности поверхности для репозитория кода (`design/<surface>/ready.yaml`,
T4 G1) и структурный прогон правил `/design-audit` (`design-audit/references/rules.md` — 64 правила R-SURF … R-VIS,
это твоя спецификация). Аудит детерминированные правила проверяет сам или вызовом валидаторов баз и утилит `project/`,
правила «чтением» перечисляет для скилла; суждений модели в коде нет (Р183 п. 7). Выход аудита — находки JSON (контракт
C3) и сводка; `last-report.md` в `audit-state/` пишет скилл, не утилита.

## Что сделать
- **`ready.py`** (H10-ready, F7-Z6-4 — R-FRESH-006, F7-Z5b-1 — часть C13): по форме `ready.yaml` — род и потребитель из
  реестра `surface.md`; источники со статусами и sha256; единицы (страницы сайта или экраны кабинета) — композиция,
  тексты, макет по вердикту `review/REVIEW.md` с совпавшим отпечатком (отпечаток единицы — по её артбордам из колонки
  «артборды» таблицы одобрения, форма C11), `budget_profile`, `gate_exceptions` из плана, `after_build` из
  `input/ACCEPTANCE.md`, `open` (заглушки и демо-факты); `perf` по роду (сайт — профили планов, кабинет — p75, RUM и
  лабораторные AC, G5); `frontend_design` (G6); `blockers`; `status` из единиц. `build` пишет файл, `check` сверяет
  без записи.
- **`design_audit.py`** (H10-design_audit, F7-Z6-1, T1-rules, T2a-rules, T2b-rules, VI-04 — сводка R-VIS в единице
  домена, F7-Z1-2 — R-COV-007 автоматической сверкой каналов голоса с родами поверхностей, по Р169 вариант (а)):
  категории R-SURF, R-STRUCT, R-REF, R-COV, R-PROJ, R-FRESH, R-MAT, R-SEM, R-DEBT — проверки, у которых в `rules.md`
  детерминированный способ; вызовы — `site_validate.py`, `vocab_lint.py`, `copydeck.py validate`, `claims_check.py`,
  `validate_*.py`, `spec_check.py`, `ad_check.py`, `plan_to_assets.py --check`, `vlm_to_dna.py validate`, утилиты
  `project/` (`tree`, `states`, `screen_map`, `ds_coverage`, `ds_build check`, `canvas_input check`, `ready check`) —
  через их CLI или функции, как удобнее; находку вызванной утилиты переводи в правило `rules.md`, которое её называет.
  R-VIS — только перечень для визуального прогона (он идёт по просьбе заказчика с копиями и судьёй). Тяжесть — по
  этапу из статусов файлов (правило в `rules.md` и `design-audit/SKILL.md § Уровни тяжести`). Правила «чтением» —
  списком id с тем, что прочитать, в выходе.
- **Фикстура с посеянными дефектами** (ENV-6 — часть C13): ровно дефекты таблицы, каждый — в своём месте, без
  побочных находок; это вход проверки Ф8 (сценарий «пакет», §6), ключ лежит в журнале у оркестратора.

  | № | дефект | правило |

  | 2 | папка `site/<surface>/` у slug, которого нет в `surface.md` | R-SURF-001 |
  | 3 | ссылка `{…}` в DTCG на несуществующий токен | R-STRUCT-006 |
  | 4 | `brand.ref` брифа ведёт в несуществующий файл | R-REF-001 |
  | 5 | слот copy deck, которого нет в плане страницы | R-REF-003 |
  | 6 | текстовый слот плана без текста в copy deck (план `approved`) | R-COV-002 |
  | 7 | слот данных плана без факта в `facts.yaml` | R-COV-003 |
  | 8 | тип `ui:` stable-экрана без компонента в `system.yaml` | R-COV-005 |
  | 9 | значение токена в DTCG изменено без пересборки производных | R-FRESH-001 |

  | 12 | файл ассета лежит при плане ассетов в `draft` | R-MAT-008 |
  | 13 | канал голоса `product-ui` при поверхности рода `app` без профиля голоса продукта | R-COV-007 |
  | 14 | демо-факт `example: true` в закрытом copy deck | R-DEBT-002 |
