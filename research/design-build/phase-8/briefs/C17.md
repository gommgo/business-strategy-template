## Правило «проверки — сигнализация, а не цель» (Р203, решение заказчика)
Впиши его, по одному месту на мысль, со ссылками вместо повторов: `design-deep-dive/SKILL.md` (раздел о проверках),
`references/phases.md § Принципы всех этапов`, `references/workflow-patterns.md` (как вести сессию), `design-audit/SKILL.md`
(отчёт). Смысл:
- проверки гоняются на переходе этапа, а не в процессе работы; цель агента — бриф, выбранное направление и решение
  заказчика; прохождение проверок — не приёмка;
- порог, который мешает хорошему решению, агент выносит заказчику вопросом, а не подгоняет результат под порог;
- обход проверки (исключение ворот, «не применимо: причина», снятие приметы) — только с записанной причиной; отчёт
  аудита перечисляет обходы отдельным списком;
- жёстко останавливают работу пять гейтов: генерация — только по утверждённому плану ассетов; чистовой макет — только
  на утверждённых текстах и подтверждённых фактах; в публикацию не уходят демо-факты, заглушки и утверждения без
  источника; пакет для кода — только принятый макет с совпавшим отпечатком; ворота после сборки блокируют только B.
  Остальные находки — доклад заказчику, решение за ним.
