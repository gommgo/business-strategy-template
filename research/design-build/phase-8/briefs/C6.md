## Зона
Два модуля, которые кормят вход холста кабинета (его собирает C11): производный демо-набор данных `example: true` и
контракт генерации экранов — 10 разделов ux 11/04 §7.3 с разделом на экран. Демо-набор — производный: авторского файла
фикстур нет, иначе он стал бы вторым источником данных продукта (T3 F9, Р69). У каждого раздела контракта — источник
(путь файла проекта), чтобы массовый провал на макете вёл в слой проекта (T3 F8, «Обратная связь»).

| файл | что |
|---|---|
| `scripts/project/demo_data.py` (новый) | демо-набор из глоссария объектов, объёмов коллекций и крайних случаев; каждая запись `example: true`; детерминированно |
| `scripts/project/contract.py` (новый) | контракт генерации: 10 разделов ux 11/04 §7.3, раздел на экран; обязательные состояния — S-id из `states.py` (ST-02); источник у раздела |
| слой фикстуры кабинета в `scripts/tests/fixtures/` (свой слой поверх фикстуры C3) | то, чего контракту и демо-набору не хватает: `examples` и атрибуты объектов, `volume` блоков, приёмка сценария, конвенции `map.md` |
| `scripts/tests/smoke/project-demo.tsv` | строки двух модулей |

Оба модуля — функции для сборщика входа холста (C11 пишет `input/` сам) и CLI: `build <slug> <surface> [--out …]
[--json]` печатает или пишет результат вне репозитория (`--out`, иначе stdout), `check` — проверка источников
(чего не хватает для раздела — находки контракта C3), `--selftest`. В репозиторий модули не пишут: `input/` — зона C11.

## Что сделать
- **`demo_data.py`** (H10-demo_contract — часть, T3-scripts — часть C6, F7-Z2-1 — часть): из `object.md` (атрибуты,
  типы, длины, перечни статусов, `aliases`, `examples`), объёмов коллекций (`volume` блока: сколько записей типично,
  минимум, максимум — форма `_template/screens/_template/block.md`) и крайних случаев ux 06/01 §6.1–§6.2 и ux 13/04 §12
  (0, 1, 20, 500, 5 000 записей; самое длинное и короткое имя, диакритика; пусто, `null`, 0, отрицательное, очень
  большое; дата в прошлом и будущем, другой часовой пояс; объект без связей и с 50 связями; самая длинная строка
  локализации) — набор на коллекцию с тремя количествами (ux 06/01 §6.1) и крайними случаями; значения — из
  `examples` и перечней объекта, недостающее — генерацией по типу поля с зерном (одинаковый вход — одинаковый выход).
  Каждая запись и набор целиком — `example: true`. Чисел в строках интерфейса нет: число — из данных (TX-12).
- **`contract.py`** (H10-demo_contract — часть, S6-ST-02, F7-Z2-1 — часть): разделы по таблице T3 F8 — «Контекст
  продукта», «Объектная модель», «Карта экранов», «Дизайн-система», «Обязательные состояния», «Данные», «Тексты»,
  «Запреты», «Примеры», «Критерии приёмки»; раздел на экран — тип, объект, главная задача, главное действие, блоки и
  компоненты (`tree.py`), обязательные состояния — список S-id: ключи `states` экрана ∪ обязательный набор `states.py`,
  «не применимо» — с причиной; «Данные» — ссылка на демо-набор; «Тексты» — строки `texts.md` нужного этапу статуса
  (вайрфрейм — черновые, макет — утверждённые; статус — вход), `aliases` и `banned`; «Дизайн-система» — ссылка на ДС и
  карту «тип → компонент» (файлы C5, если есть; нет — пометка пробела); у каждого раздела — источник (путь и раздел
  файла проекта). Формат — md по форме протокола (`references/claude-design.md § 6. Вход холста`, кабинет: `contract.md`);
  назови в отчёте §4 точную форму и функции для C11.
- **Слой фикстуры** — поверх фикстуры кабинета C3 (её файлы не правь; недостающее — своим слоем), иллюстрация,
  `example: true`.

## Ожидаемый результат (проверит оркестратор)
- Фикстура кабинета (C3 + твой слой): `contract build` — 10 разделов в порядке §7.3; на каждый экран поверхности —
  раздел; список S-id раздела «Обязательные состояния» совпадает с набором `states.py` плюс ключи `states` экрана; у
  каждого раздела — источник, путь существует.
- `demo_data build` — на каждую коллекцию три количества (0, мало, типично) и максимум из `volume`, крайние случаи
  перечня; каждая запись `example: true`; повторный запуск — тот же вывод байт в байт.
- Снятый `volume` у блока коллекции или пустой `object.md#examples` → `check` называет пробел находкой с путём.
- `--selftest` двух модулей — зелёные без сети; `smoke.py --only scripts/project` — 0 FAIL.

## Уроки и стыки прежних шагов
- Контракт находок — `scripts/project/findings.py` (отчёт C3 §4): строки JSON `{rule, severity, surface, kind, ref,
  path, message, fix}`, `F.Report().add(...)`, `F.print_findings(items, as_json=…)`, `F.exit_code(items)` (0/1/2),
  `F.severity_for(status, draft=…, stable=…)`; `kind` — слово-slug своей записи (`system`, `demo`, `contract` …),
  `ref` — `<slug>` или `<slug>#<место>`, `path` — `docpaths.rel(файл, repo)`. Разбор файлов проекта — `layer.py`
  (`L.Layer(slug, surface, repo)`: экраны, блоки, каркасы, `map`, `texts`, `interface`, `product`, `design`,
  `components`), разбор вызова — `docpaths.parser`/`parse`.
- Фикстура кабинета — `cabinet` (проект `otves-office`, поверхность `office`, все экраны stable, строки `texts.md` —
  `checked`); свою фикстуру строй поверх — `extends: [cabinet]`, файлы `cabinet` не правь.
- Имя своей фикстуры — `cabinet-demo` (параллельная зона пишет `cabinet-ds` (C5)): папки не пересекаются.
- Наборы состояний — `S.screen_set(lay, slug)` → `items` (`key`, `id`, `reasons`, `covered`), `S.dump(lay)` — все наборы
  с `priority`; раздел контракта «Обязательные состояния» — ключи `states` экрана ∪ `required` набора (S-id — из
  YAML словаря). Деревья и компоненты экрана — `T.composition(trees, screen)`; свод — `M.derive(lay)`, `M.render(lay)`.
