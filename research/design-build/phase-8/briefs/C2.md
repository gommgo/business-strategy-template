## Решения оркестратора для зоны
- **S23 и S24 в источнике.** Канон словаря — ux 06/01 §2 с 24 состояниями (Р125), а в файле пока строки S01–S22;
  производный YAML собирается из источника, поэтому строки S23 `not-found` (группа «доступ и правила») и S24
  `generating` (группа «процесс») вносятся в таблицы §2 сейчас, по форме соседних строк: смысл — README экранов
  (`docs/projects/_template/screens/README.md § Состояния экрана`) и `research/design-build/phase-4/nodes/05-ST.md` §1.1;
  нормы — ux 05/04 §4.1 и ux 13/03 §6 (адресом, не пересказом). Заголовок §2 и перечень §8.1 — S01–S24; место S23 в
  таблице приоритета §2.5 — по приоритету README экранов (S18 > S16 > S23 > S13 > S07 > S02 > S01). Прочие упоминания
  «S01–S22» в сжатом слое (выжимка, чек-лист) не трогай — список мест в отчёт, выравнивание — Ф10.
- **id приметы** в находке `ui_audit` берётся из `kb/common/tells.yaml` (раздел `checks`: ключ проверки → id приметы),
  в код не зашивается: на шаге 10 оркестратор переименует id в данных (`K3-*` → `LOOK-*`), и код меняться не должен.
  `tells.yaml` ты только читаешь.
- **Токены ДС проекта** — вход `ui_audit` ключом (путь к `system.tokens.json` DTCG или `system.tokens.css`); без ключа —
  эталонные токены ui (`kb/ui/14-recipes/examples/tokens.css`) с пометкой в отчёте проверки. Разбор DTCG — минимальный
  (значения `$value` по путям), своего формата токенов не заводи: производные ДС пишет C5.
- Число каждой нормы — у владельца: ширины — `kb/common/acceptance-widths.yaml`; тач 44 и минимумы — строки NU (Р52,
  Р126); `glass-panel.limits` — `kb/creative/06-effects-catalog/effects.yaml` (читаешь, не правишь); потолок движения —
  пресет ДС. В `scripts/ui/data/` живут только величины, у которых нет другого владельца (таблица профиля, порог кеглей
  проверок), — с адресом нормы в комментарии.
