## Зона
Основа для всех зон кода: пути к файлам проекта, окружение с установкой, смоук по спискам и сборщик демо-проектов.
Утилиты `scripts/project/` (зоны C3, C5, C6, C11, C13) строятся на твоих `docpaths` и сборщике фикстур; ворота (C14)
и все утилиты — на `kbpaths` и `install.sh`.

| файл | что |
|---|---|
| `scripts/lib/kbpaths.py` | домен `project` в `DOMAINS`; корень репозитория с переменной окружения; справка без Р-номеров |

| `scripts/tests/smoke.py`, `scripts/tests/smoke/*.tsv` (новые) | смоук читает все списки папки; `smoke-list.tsv` разложен по папкам |

## Что сделать
- **`docpaths.py`** (H10-docpaths). Корень данных проекта: `--repo DIR` → переменная окружения (имя выбери и запиши;
  ориентир — `DDD_REPO`) → репозиторий, в котором лежит скилл (`kbpaths.repo()`). Канон форм `_template/` берётся из
  репозитория скилла, даже когда данные — во временной копии: сборщик фикстур кладёт только проект. Функции (имена —
  твои, запиши в отчёт): список проектов (без `_template`, `infrastructure` и файлов-реестров), папка проекта, реестр
  поверхностей из `surface.md` (slug, `type`, `web-kind`), папки слоёв по поверхности (`site/<surface>/`,
  `interface/<surface>/`, `screens/<surface>/`, `fsd/<surface>/`, `mobile/<surface>/`, `telegram-bot-flow/<surface>/`,
  `design/` и `design/<surface>/` с `input/`, `canvas/`, `review/`, `assets/`, `ready.yaml`), файлы уровня продукта
  (`facts*.yaml`, `voice*.yaml`, `voc.yaml`, md продукта), статус файла (frontmatter или поле `status`); общий разбор
  аргументов `<команда> <slug> [<surface>] [--repo] [--out] [--json]` (контракт §4) — чтобы все утилиты `project/`
  разбирали вызов одинаково. Формат находок — у C3, в `docpaths` его не заводи. Раскладку бери из канона, а не из
  памяти: `docs/projects/README.md`; `_template/project/README.md` (§ Файлы уровня продукта, реестр поверхностей и
  `web-kind` — форма `_template/project/surface.md`); `_template/site/README.md` и `_template/design/README.md` (разделы
  о файлах и раскладке); `_template/screens/README.md` (состав слоя); остальные слои — по README их `_template/`.
  `--selftest` — на фикстуре своего сборщика, без сети.
- **`kbpaths.py`** (GT-03 — часть, T4-G4). Домен `project` (утилиты `scripts/project/`, `kbpaths.use("project")`);
  корень репозитория учитывает ту же переменную окружения, что `docpaths`, или явно остаётся корнем скилла — реши и
  запиши, кто из двух модулей её читает (одно место). Проверка «соседнего чекаута»: копия скилла во временной папке как
  `<tmp>/strategy/.claude/skills/design-deep-dive/` (копируй только нужное — не весь репозиторий), рабочая папка
  `<tmp>/site/`, запуск `python3 ../strategy/.claude/skills/design-deep-dive/scripts/lib/kbpaths.py` и одной утилиты
  базы (например, `scripts/site/page_gates.py --help`) — пути ведут в копию, а не в рабочую папку. Эту проверку оформи
  частью самопроверки `kbpaths --selftest` или отдельной строкой смоука. Справка модуля — без Р-номеров (BL-7).
- **`install.sh` и требования.** ENV-1: закрепления требуют Python ≥ 3.12 — шапка `requirements.txt` и сообщение
  `install.sh` называют 3.12–3.13; без `--python` установка сама выбирает `python3.13`, `python3.12` или `python3` не ниже
  3.12 и отказывает с понятной причиной на 3.11. ENV-2 (Р183 п. 5): ключ установки ставит в venv версию Playwright под
  браузеры `PLAYWRIGHT_BROWSERS_PATH`, когда там лежит Chromium не той ревизии, что ждут закрепления (облако: ревизия 1194
  → `playwright==1.56.0`; таблица «ревизия → версия» — данными в скрипте, с источником); без переменной — закрепление
  как есть. ENV-3: ffmpeg и ffprobe — системные, если есть; иначе ключ ставит статическую сборку в `$DDD_HOME/bin` с
  sha256 (адрес и sha256 проверь здесь, сеть открыта; `kbpaths.ffmpeg()` находит её). ENV-7: адреса архивов libjxl
  0.12.0 и libwebp 1.6.0 отвечали 404 — найди рабочие адреса того же релиза и sha256 или оставь строку «вручную, `--from`»
  с причиной; остальные адреса таблицы — проверь запросом `HEAD` и запиши итог. BL-5: `--from` и `--models-from` берут
  старые папки с другой раскладкой — на этой машине они лежат в `~/Документы/app-design/` (пути — README-plan-notes
  §3a): `blender-research/99-raw/tools/bin`, `ai-media-research/99-raw/tools/bin`, `ai-media-research/99-raw/tools/models`,
  `ai-media-research/03-image-models/models`, `ai-media-research/04-video-models/models`; ключ принимает несколько папок
  (повтор ключа или список), находит файл по имени из таблицы и сверяет sha256. Проверь `--dry-run` и `--check` на этих
  папках (что нашлось, что нет, где sha256 не сошёлся). Полную установку `--all` с `--from` делает оркестратор на шаге
  МЗ; ставить в `$DDD_HOME` ради проверки можно. CN-115: Blender Lab MCP — по желанию отдельным ключом (или только
  справкой, если установка вне скрипта), mcp-for-blender не ставится и не упоминается как вариант (три неисправленные
  уязвимости). BL-6: `DDD_BRAVE` — `kbpaths.brave()` его уже читает; `install.sh` и `--check` показывают, какой Brave
  найден, справка называет переменную. T2a-designmd (Р183 п. 3): линтеров формата (`@google/design.md`,
  `@terrazzo/cli`) в `package.json` не добавляем — формат DTCG проверит схема в `ds_build --check` (C5); запиши решение
  в отчёт. npm: скрипт установки `esbuild` блокируется настройкой `allowScripts` npm (шаг 0, CHAIN) — разберись, нужен ли
  он утилитам и эталонам (`esbuild` — эталонные сборки blender), и сделай так, чтобы установка давала рабочий `esbuild`
  или честно называла шаг. Справка `install.sh` — без Р-номеров и дат (BL-7).
- **Смоук** (ENV-5, H10-smoke). `smoke-list.tsv` раскладывается на списки `scripts/tests/smoke/<папка>.tsv` — по папке
  `scripts/` (`ai-media`, `blender`, `claude-design`, `creative`, `lib`, `maint`, `site`, `text`, `ui`, `ux`, `tests`),
  строки корня `scripts/` и примеров `kb/` — своими списками (имена выбери); у `project/` — по зонам:
  `project-screens`, `project-ds`, `project-demo`, `project-canvas`, `project-package` — пустые, с шапкой. Колонки и виды
  проверок те же; `smoke.py` читает все списки папки по порядку, `--only` и `--tsv` работают как прежде, дубли пути и
  вида проверки между списками — ошибка; по желанию — ключ, который перечисляет утилиты `scripts/` без строки смоука.
  Старый `smoke-list.tsv` не удаляй — `smoke.py` его больше не читает, оркестратор снимет его из git. Строки своих новых
  утилит (`docpaths`, `fixture_project`) — в своих списках. Справка `smoke.py` — о списках папки.
- **Сборщик фикстур** (ENV-6, часть C1; H10 — фикстуры в скилле, Р183 п. 4). `scripts/tests/fixture_project.py`: по
  манифесту `scripts/tests/fixtures/<имя>/manifest.yaml` собирает во временную папку дерево `docs/projects/<slug>/…` из
  слоёв — файлы примеров баз (`kb/…`, по пути, без копии в фикстуре) и свои файлы фикстуры (`scripts/tests/fixtures/<имя>/…`);
  слои накладываются по порядку, поздний перекрывает ранний; путь назначения — от папки проекта. Вызов:
  `build <имя> [--out DIR] [--json]` (печатает корень), `list`, `--selftest`; для самопроверок других утилит —
  функция-контекст, которая собирает фикстуру и убирает её после. Одна своя минимальная фикстура для самопроверки
  (например, `minimal`: `surface.md` с двумя поверхностями разного рода, `vision.md` с пометкой иллюстрации, один слой из
  примера базы). Фикстуры зон — кабинет (C3), ДС (C5), демо (C6), лендинг и многостраничник (C11), посеянные дефекты
  (C13) — они добавят сами своими манифестами: опиши формат манифеста в докстринге и в отчёте §4.
