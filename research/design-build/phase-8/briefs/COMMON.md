## Правила кода и причины
- **Пути.** Базу, соседние утилиты, данные, выходы, кэши, блокировки и бинарники код находит только через
  `lib/kbpaths.py`; файлы проекта `docs/projects/<slug>/…` — только через `lib/docpaths.py` (его пишет зона C1; корень —
  репозиторий скилла, `--repo` или переменная окружения — другой чекаут). Путей от рабочей папки, домашних папок
  источника, `99-raw/tools`, `<база>-research` нет: код-репо запускает утилиты из соседнего чекаута
  `../strategy/.claude/skills/design-deep-dive/scripts/…` со своей рабочей папкой, и такой путь сломался бы.
- **Выходы.** `$DDD_HOME/out/<домен>/` или `--out`. В репозиторий утилита пишет только свои производные файлы проекта по
  форме (`input/`, статичные копии и `kit.json`, `ready.yaml`, производные ДС, генерируемые разделы `map.md`) и только
  командой `build`; `--check` ничего не пишет; нормализатор без явного `--write` показывает дифф. Генератор данных kb
  (производный YAML) пишет свой файл и умеет `--check` — сверку байт в байт без записи.
- **Модель — только Opus** (Р5, Р47, Р55). Оценку, анализ и тексты делает Claude Opus 5.5 в сессии Claude Code (агент
  `design-judge`); код готовит пакеты заданий и разбирает ответы, моделей сам не вызывает; идентификаторов моделей
  других вендоров как умолчаний оценки в коде нет. Генерация картинок и видео — модели ai-media через polza, RouterAI,
  Gen-API, только по утверждённому плану ассетов и только `--live`: в Ф8 — только сухой прогон, 0 ₽.
- **Ключи** — вне репозитория (Р53): только переменные окружения владельца через `kbpaths.key()`; в коде, тестах,
  фикстурах, логах и отчётах ключей нет. Ф8 ключей не требует; платных вызовов и `--live` не делай.
- **Контракты между зонами** (`PLAN.md` §4) меняются только через оркестратора: `x-canvas-map` (форму пишет C4), `copy.md`
  (синтаксис фиксирует C8), находки утилит `project/` — строки JSON `{rule, severity, surface, kind, ref, path, message,
  fix}`, тяжесть `error | warning | hint`, код выхода 0 — ошибок нет, 1 — есть, 2 — вызов или окружение (первой пишет
  C3), вызов утилит `project/` — `<команда> <slug> [<surface>] [--repo DIR] [--stage …] [--out …] [--json]`, команды
  `build` и `check`, `--selftest` на встроенной фикстуре; JSON ворот — внутри C14; пакет судьи — C12. Первый писатель
  контракта фиксирует его точную форму в отчёте (§4 «Для следующих зон»), читатели следуют.
- **Тесты.** У новой утилиты — `--selftest` без сети и строка смоука; у изменённой — самопроверка покрывает новое
  поведение; производные файлы генераторов пересобираются байт в байт (`--check`).
- **Фикстуры** — `scripts/tests/fixtures/`: демо-проекты, которые сборщик `scripts/tests/fixture_project.py` (C1)
  раскладывает во временную папку из слоёв — примеры баз по манифесту (без копий) и свои файлы там, где примеров нет.
  Свои файлы — иллюстрация: в машинных файлах `example: true`, в md — пометка. В `docs/projects/` данных нет, папок
  проектов не заводи.
- **Forward-only в коде** (`.claude/rules/forward-only.md`). Докстринг, `--help`, комментарии и сообщения — о текущем
  поведении: без волн, агентов, дат, имени снятого исполнителя макета, «было / стало», Р- и Ф-номеров, путей в журнал
  `research/`; данные с датой (снимки прайсов) — данные. Зона чистит справку своих файлов (BL-7); полная уборка базы —
  Ф10. Следов прежнего исполнителя макета (kimi, K3, `watch` потока `kimi -p`) в коде зоны — 0, кроме данных; id примет
  `K3-*`/`F-*` переименует оркестратор на шаге 10 — их не трогай.
- **Схемы и данные kb.** Правка схемы — добавления и совместимые изменения, кроме снятий, которые называют действия
  (`x-kimi-*`, `handoff.kimi`, `executor_block`, `site_slot`); метасхема Draft 2020-12; примеры базы проходят новую схему
  (правит зона-владелец в том же шаге). Числа норм меняются только по действию: пороги — у владельцев величин.
- **Правь по месту: не переформатируй файлы** — переформатирование раздувает дифф и прячет потери. Стиль, отступы и
  ширина строк — как в файле; новый код — в стиле соседнего кода той же папки; комментарии — на языке окружающего кода
  (`CLAUDE.md` §8). Тексты md (README доменов, справка в kb) — по стандарту `research/design-build/phase-3/SKILL-MAP.md`
  §7: контекст и причина, без капса и давления, каждая информация в одном месте.
- **Не трогать:** `assets/calibration/` (утверждён заказчиком); `CLAUDE.md`; описания `SKILL.md`; чужие файлы;
  `research/design-build/phase-4/inputs/in-drafts/` (не читать); git — коммитит оркестратор. Удалять файлы не нужно:
  файл, который план заменяет новым, опиши в отчёте — оркестратор снимет его из git.
- **Чтение.** Большие файлы (больше ≈ 1 500 строк или ≈ 60 КБ) целиком не читай: найди `def`, `class`, `add_parser`
  или заголовки (`Grep` с номерами строк) и читай нужные места через `Read` с `offset` и `limit`. Спецификации и узлы —
  разделами и строками из брифа зоны. Код, который правишь, прочитай в месте правки и в местах вызова (поиск вызывающих
  до снятия ветки или ключа — иначе сломаются соседние утилиты).
- Субагентов не запускай: выводы опираются на прочитанное тобой. Бюджет контекста ≈ 700 тыс. токенов.

- JSON и YAML твоих файлов парсятся; схемы проходят метасхему Draft 2020-12
  (`$DDD_HOME/venv/bin/python -c "import json,sys,jsonschema; jsonschema.Draft202012Validator.check_schema(json.load(open(sys.argv[1])))" <схема>`;
  YAML-схема — через `yaml.safe_load`); примеры базы проходят свои схемы.
- `python3 research/design-build/tools/refcheck.py --strict <каждый новый и правленый .md>` — 0 битых ссылок, 0 следов
  журнала в тронутых строках; находка в строке, которой ты не касался, — в отчёт, не правь.
- Код зоны: `grep -rniE 'kimi|\bK3\b|gemini|qwen|gpt-|\bР[0-9]+\b|\bФ[0-9]+\b'` по своим файлам — только данные и
  объяснённые места; ключей нет; сеть и траты — только явными ключами.
