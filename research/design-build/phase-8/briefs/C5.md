## Зона
Дизайн-система проекта в репозитории — три файла (`design/system.tokens.json` DTCG, `design/DESIGN.md`,
`design/system.yaml` — карта «тип → компонент ДС», расширения словаря, «роль текста → стиль», конвенции); артефакт
Design System на claude.ai собирается из них в одну сторону, правки токенов с холста поднимаются обратно в DTCG
(T2a C4, C5). Утилиты: покрытие компонентов (Р29), сборка производных, обратная синхронизация; схемы форм уровня
продукта.

## Что сделать
- **Схемы форм** (H10-schemas-design, T2a-brand — часть C5): `brand` — из `site-brief $defs` (бренд для обоих брифов:
  сайта и кабинета), `system` — карта решений (`components`, `extensions`, роли текста, конвенции), `app-brief` — бриф
  на вид кабинета с `surfaces.<surface>`; источник полей — формы `_template/design/_template/{brand,system,app-brief}.yaml`
  (форма главнее: схема описывает её поля, не придумывает новых). Метасхема Draft 2020-12; формы с заполненными
  плейсхолдерами и фикстура проходят схемы. Ссылку `brand.ref` из `site-brief` пишет C7 в шаге 4 — назови в отчёте §4
  путь схемы и `$id`.
- **`ds_coverage.py`** (CM-01, CM-04, CM-06, CM-15, H10-ds_coverage, F7-Z6-2 — правило `design-audit` R-COV-005): типы
  `ui:` из деревьев stable-экранов (через `tree.py` C3) и слотов действий и форм планов страниц сайта (`site/<surface>/`
  план — если есть) → `system.yaml` `components` / `extensions` → компоненты артефакта ДС; у компонента —
  `states.required` типа и объявленные `states.optional` (`kb/common/components.yaml`); у расширения — `keyboard` и
  `text_roles`. Серьёзность по этапу — как в R-COV-005. Находки — контракт C3.
- **`ds_build.py`** (H10-ds_build_sync — часть, T2a-ds — часть, NU-15, F7-Z6-5 — R-FRESH-001, F7-Z6-10 — R-STRUCT-006
  по Р183 п. 3): `build` пишет производные (`system.tokens.css`, передняя часть `DESIGN.md` между метками, `tokens.json`
  и README артефакта — в раскладке `_template/design/README.md § Производные`), `check` — свежесть байт в байт без
  записи и формат DTCG (`$type`, `$value`, ссылки `{…}` разрешаются, группы) схемой — внешних линтеров нет. Имена
  CSS-переменных совпадают с путями DTCG 1:1 (Р42). Мобильная поверхность — `type.body` для узкой ширины (NU-15; минимум
  — норма NU, адресом).
- **`ds_sync.py`** (H10-ds_build_sync — часть, T2a-ds — часть; протокол `references/claude-design.md § 5`, «Правки
  токенов»): обратное сопоставление «имя ДС → путь DTCG», сверка живого `tokens.json` (прочитанного с claude.ai и
  сохранённого файлом) с собранным: что изменил заказчик, в каком пути DTCG это править; `--check` — код 1 при
  расхождении; запись в DTCG — только явным ключом.
- **Фикстура ДС** (ENV-6 — часть C5): слой из примера cd (`tokens.json` артефакта, компоненты, `README.md`), свой
  `system.tokens.json` DTCG и `DESIGN.md`, `system.yaml` с картой типов фикстуры кабинета (C3) и одним расширением.

## Ожидаемый результат (проверит оркестратор)
- Фикстура (кабинет C3 + слой ДС): `ds_build build` → производные; повторный `ds_build check` — 0 (байт в байт);
  правка значения токена в DTCG без `build` → `check` даёт R-FRESH-001; битый `$value` или ссылка `{…}` в пустоту →
  R-STRUCT-006.
- Круг «туда и обратно»: `ds_sync` по `tokens.json` примера cd восстанавливает пути DTCG; `ds_build` из них собирает
  `tokens.json` с теми же именами и значениями, что у примера (расхождения — только известные, перечислены в отчёте).
- `ds_coverage check` на фикстуре, где каждый тип `ui:` stable-экранов сопоставлен, — 0 `error`; снятое сопоставление
  одного типа → R-COV-005 с именем типа и экранами; компонент без обязательного состояния типа → находка; расширение
  без `keyboard` или `text_roles` → находка.
- Схемы `brand`, `system`, `app-brief` проходят метасхему; инстансы фикстуры — схемы; строки `kb/common/README.md` есть.
- `--selftest` трёх утилит — зелёные без сети; `smoke.py --only scripts/project` — 0 FAIL.

## Уроки и стыки прежних шагов
- Контракт находок — `scripts/project/findings.py` (отчёт C3 §4): строки JSON `{rule, severity, surface, kind, ref,
  path, message, fix}`, `F.Report().add(...)`, `F.print_findings(items, as_json=…)`, `F.exit_code(items)` (0/1/2),
  `F.severity_for(status, draft=…, stable=…)`; `kind` — слово-slug своей записи (`system`, `demo`, `contract` …),
  `ref` — `<slug>` или `<slug>#<место>`, `path` — `docpaths.rel(файл, repo)`. Разбор файлов проекта — `layer.py`
  (`L.Layer(slug, surface, repo)`: экраны, блоки, каркасы, `map`, `texts`, `interface`, `product`, `design`,
  `components`), разбор вызова — `docpaths.parser`/`parse`.
- Фикстура кабинета — `cabinet` (проект `otves-office`, поверхность `office`, все экраны stable, строки `texts.md` —
  `checked`); свою фикстуру строй поверх — `extends: [cabinet]`, файлы `cabinet` не правь.
- Имя своей фикстуры — `cabinet-ds` (параллельная зона пишет `cabinet-demo` (C6)): папки не пересекаются.
- Типы `ui:` stable-экранов фикстуры — `T.ui_types(trees, stable_only=True)` (`trees = T.parse_layer(lay)`): Alert,
  Banner, Button, DescriptionList, EmptyState, Field, KpiTile, Link, Pagination, Progress, SearchInput, Select, Sidebar,
  Skeleton, Table, TextInput, TopBar. Если фикстура ДС кладёт `design/system.tokens.json`, в нём нужны токены `md` и
  `sm` группы `space` — их называют деревья (иначе `tree check` даст R-SEM-014).
