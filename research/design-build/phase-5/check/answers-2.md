### 14. Что зафиксировать в паспорте визуала до первой генерации?

### 22. Как работать с холстом Claude Design, чтобы не затереть правки из редактора?
Ответ: Исходники холста лежат в репозитории проектирования, claude.ai — живой редактор. Перед каждой публикацией:
`read` живой версии + `list scope=files` → слить правки заказчика, сохранив чужие ключи и `createdOnFiles` → `publish` с
`root`. Правки из редактора забирают в репозиторий чтением (дифф → коммит «iter-NN customer») до своей правки, а свою
правку перед `publish` снова сливают с живой версией. Редактор сам сохраняет версии при открытии, поэтому сервер
отклоняет публикацию поверх непрочитанного. При отказе — прочитать весь артефакт и `list scope=files`, слить ещё раз;
`force` — только по прямой просьбе заказчика. Вне git живут загрузки `/_blob/<id>`, комментарии, совместная правка и
база; адреса и версии держат в `ARTIFACTS.md`. Мелкие числовые правки дешевле отдать заказчику (мышь, твики). Момент
стопа источники называют по-разному: cd 05/01 §6 — «ещё один отказ», cd 06/03 §1 и §5 — «третий отказ».
Канон: `claude-design/05-design-artifacts/01-design-system-and-canvas-in-session.md §6` (выжимка п. 13, 16); раунд со
слиянием — `claude-design/06-design-process/03-edit-loop-and-stop.md §1`, жёсткий стоп — там же §5.

### 23. Как устроить оценку двух вариантов макета судьёй?

### 24. Какие ворота скорости у страницы с 3D-героем и где их проверяют?
Ответ: Ворот три яруса, порядок: страница → эффекты → ассеты. Величину ставит один владелец, у соседей она — зеркало D.
3D-героя дают уровни L1 и L2; на L0 WebGL запрещён.
- **Страница** (site, профиль `<page_type>@L1|L2`). LCP в лаборатории: S выше цели (L1 — 2 500 мс на обоих устройствах;
  L2 — 3 000 на телефоне, 2 500 на десктопе), B выше 4 000. CLS: S > 0,1, B > 0,25. INP по сценарию: S > 200, B > 500.
  TBT: S выше цели (L1 — 300 / 200 мс, L2 — 600 / 300). Вес первого экрана (L1 — 2,0 / 3,5 МБ, L2 — 2,5 / 4,0) и
  сессии — S. LCP-элемент canvas или LCP-картинка с lazy — B (SG-PERF-06).
- **Эффекты** (creative, `effect-gates.yaml`). Длинные кадры при прокрутке ≤ 2 % на десктопе и ≤ 10 % на телефоне; JS 3D
  и число контекстов WebGL — по уровню; всё это S.
- **3D** (blender 09/05 §7.2, 11 порогов `site_probe.py` + `gate_check`). 3D-ассеты ≤ 820 / 1 536 КБ: B для ассета, на
  странице — D (SG-WEIGHT-08). Вклад 3D в TBT ≤ 300 / 150 мс, с KTX2 — 200 (позиция GT-06). Вызовов ≤ 30 / 60, DPR
  ≤ 1,5, первый кадр модели ≤ 5 / 2 с, при reduce — 0 вызовов в покое, 0 ошибок консоли. LCP ≤ 1 000 мс и вес 3 / 7 МБ
  из §7.2 и `gate_check.py` — копии, не пороги страницы (GT-04, GT-05).

3D первого экрана грузят после LCP и load, ниже первого экрана — по намерению (GT-09). Где проверяют (позиция GT-03):
