## Бриф и стратегия

### 1. Какие поля обязательны в брифе лендинга и кто владелец каждого поля?

из класса landing. С `proposed` (показ заказчику) добавляются `traffic`, `offer`, `proof`, `pages`, `ambition`, `search`,
`analytics`, `decision_context` и `meaning` (или `meaning_ref`) плюс минимум доказательств по типу: `company` у всех
коммерческих; лидогенерация услуг — ещё `price` или `offer-terms`, `business.geography` и `conversion.channels` с каналом
заявки; SaaS — `demo`; товар — `property` + `price` + `demo`. При `approved` — подпись `project.approval` и ни одного

### 2. Какой уровень амбиций ставить лендингу услуг с горячим мобильным трафиком?

## Структура и тексты

### 4. Какие секции и в каком порядке у лендинга услуг для холодного трафика?
Ответ: Порядок выводят из вопросов посетителя, а не из шаблона: тип → осведомлённость → макроструктура → роли. Температура
трафика — не ось порядка: холодный трафик (соцсети, медийка) переводят в уровень осведомлённости, обычно `problem-aware`
(`unaware` на посадочную почти не попадает — это кампания или статья). База `landing-lead-services` (для `solution-aware`):
`hero` (услуга + город + цена «от» или условие + микродоказательство) → `services`/`offer` → `pricing` → `lead-form`
(квиз, калькулятор, форма) → `how-it-works` → `case-studies`/`portfolio` → `testimonials` → `team`/`guarantee`/
`awards-press` → `faq` → `final-cta` + `contacts`. Для холодного `problem-aware` — отклонение: вставить `problem` →
`solution` перед ценой; дорогая услуга с высоким риском — `objections` до формы и `guarantee` рядом с ценой. Дерево
выбора типа даёт холодному трафику макроструктуру `sales-longread`. Роль без факта не ставится; промежуточный призыв в
середине — норма; блокирующее возражение — до главного призыва, FAQ — в нижней трети; нельзя цену только в FAQ и SEO-текст
между ценой и формой; хвост выводят из возражений страницы, а не из шаблона.
Канон: site 03/01 §3 (§3.1 вывод порядка, §3.2 таблица ЛУ и отклонения) — TR-49; макроструктура — site 03/01 §4.3,

### 6. Как проверить тексты страницы до макета и в каком порядке?
Ответ: Один порядок, дешёвое и объективное — раньше: (0) смысл против фактов до текста —
`chain_inputs.py meaning-claims`, факты — `claims_check.py lint-facts`; (1) факты и право — `claims_check.py` с
`--facts`, `--jurisdiction`, `--legal-category` (COPY-C-01…03); (2) стиль — `copy_lint.py` (COPY-C-05, 06, 10–18); (3)
длины, мета, GEO — `copydeck.py validate` с `copy-slots.yaml`, `meta-rules.yaml`, `geo-rules.yaml` (длина — сигнал);
(4) рубрика и судья COPY-R-01…09 — только после сверки с фактами (без неё рубрика поощряет выдумку); (5) человек — голос,
естественность, выбор, юридический риск, подтверждение фактов; (6) люди из аудитории. Шаги 1–3 разом —
`copydeck.py check` (claims → lint → validate), `--update --promote` переводит `draft → checked` при 0 error. Статус
меняют только ворота и человек, судья — сигнал; `checked → approved` решают заказчик, редактор, юрист. Правка по находкам
— кластерами, ≤ 3 проходов, после каждого — перезапуск сверки и линтера; перед публикацией 0 `[PLACEHOLDER]`
(`copy_lint.py --final`).

### 7. Что писать, если у клиента нет факта (цены, числа клиентов)?
Ответ: Нет факта — нет блока; выдумка хуже пустоты, пустой инвентарь — законное состояние. Пробел записывают в
`facts.yaml` → `missing[]` с `fallback`: `placeholder` — в тексте дословно `[PLACEHOLDER: …]` из `missing[].placeholder`
(с `--final` — error, опубликовать нельзя); `rewrite-without` — текст без этого утверждения; `omit-block` — слот или
секция сняты. Обязательный по типу факт (у лидогенерации услуг — цена или условия) — пробел с `blocking: true`, страница
не публикуется до ответа. На странице — честные замены: нет чисел о компании → конкретика предложения (срок, состав,
формат, цена); нет клиентов и логотипов → живое демо, настоящие скриншоты, «первые клиенты» на объявленных условиях (факт
`promo` с `valid.until`); нет отзывов → шаги работы, договор, гарантия из договора, основатель с подписью; нет рейтинга,
наград, прессы — не показывать. Нет точной цены — «от N ₽» только с реальной конфигурацией за N или 3–5 типовых случаев с
ценой; «цена по запросу» подрывает доверие; малые числа не показывать. Факты собирают анкетой text `proof-intake.md`.
Канон: site 05/02 §1.5 (честные замены), text 10/01 §1.3 (пробелы и `fallback`); формат пробела — `facts.schema.yaml`
(TR-21); цена «от» — site 05/02 §2.2.
Открыто (4 файла): `site/05-conversion-funnels/02-proof-pricing-risk.md` — поиск заголовков, выжимка (стр. 11–73), §1.5

### 8. Можно ли подписать кнопку «Подробнее»?
Ответ: Нет — как единственная подпись кнопки «Подробнее» запрещена. Кнопка называет ближайшее следствие нажатия или
повторяет ценность заголовка; по-русски — инфинитив совершенного вида + объект («Вызвать замерщика», «Посмотреть пример
сметы»), 1–4 слова, ≤ 25 знаков. «Подробнее», «Узнать больше», «Отправить», «Learn more» — слабая кнопка, правило линтера
COPY-M-MKT-07 (глагол + результат; для кнопок — warning). Как текст ссылки «Подробнее» тоже запрещена в одиночку
(«не различается», для скринридера бессмысленна) — ссылка называет, что откроется. Допустимо лишь как вторичная ссылка
рядом с осмысленным названием: у лидеров это частая вторичная ссылка, но вторичная кнопка всё равно называет, что
откроется. Имя главного действия одно на всю страницу.
Канон: text 04/01 §6.2 (TX-17), §6.3; для сайта — text 06/01 §11 (поправки к ux 07/06, правило MKT-07; позиция);
интерфейс — ux 07/06 (строка «Подробнее как единственный текст ссылки — запрет»), ux 07/02 §1.4.

## Подача

### 9. Сколько направлений показывать и чем они должны различаться?
Ответ: Страница сайта — 3–5 направлений: 4 по умолчанию, 3 — если бренд задан строго, 5 — только если одно из них канон
категории; больше пяти — вкусовщина. Каждые два различаются минимум по двум осям из четырёх: бумага (`dark`/`mid`/`light`),
стиль заголовков, тон акцента, макроструктура (id словаря site, лучше из разных семейств); тёплая бумага или антиква — не
больше чем у одного направления, если бренд не требует. У направления восемь частей: тезис, территория, оси, палитра hex
(контраст ≥ 4,5:1), гарнитуры с кириллицей, главный приём, первый экран, риск (+ цена и уровень). Рекомендация одна, с
причиной и риском; канон показывают, но не рекомендуют; показывают словами и числами; выбирает заказчик, смешение —
явно (`merged_from`). Приложение — иначе: 2–3 карточки стиля (выбранный стиль, сосед, третья — заведомо смелее) по семи

### 10. Как собрать мудборд и сколько референсов брать?

### 12. Героя страницы генерировать нейросетью, делать кодом или в Blender?
Ответ: Решают по порядку. (1) Слот фильтрует уместность ИИ: в hero нейросеть уместна только для атмосферы, сцены без
людей, фона под интерфейс; сам товар, люди-«клиенты» и скриншот не генерируют. (2) Лестница дешевизны: текст → SVG → CSS
или шейдер → картинка → видео → реалтайм-3D — берут первую ступень, которая решает задачу; «код раньше модели»
(геометрия, палитра, паттерн, абстрактный фон — кодом, 0 ₽). (3) Нужен ли 3D: оправдан, когда снимает неопределённость о
товаре (форма, механизм, материал) или сам является сообщением бренда; «для красоты» на странице конверсии — вред; для
бренда или SaaS без физического товара — шейдер-фон, для товара — предрендер или GLB (дерево blender 01/02 §7). (4) Если
3D: отвечает на ввод — код (или гибрид); фиксированный сюжет без ввода — секвенции Cycles на прокрутке; неподвижный
премиальный кадр (постер) — Blender; уникальная форма, точный бренд, 360°, правки — Blender; модели нет, предмет
параметрический — код. Правило одной фразой: страница целиком — гибрид (живое кодом на модели и материале Blender),
постер — Cycles, услуге — сюжетный кадр Blender, оживлённый светом; нейросеть — только ради скорости (4 ничьи из 4 с
Blender за 0 ₽). 3D-генераторы моделей не используются. LCP — H1 или постер, 3D грузится после LCP.

### 15. Где источник правды токенов и как они попадают в Claude Design?

### 22. Как работать с холстом Claude Design, чтобы не затереть правки из редактора?
Ответ: Исходники ДС и холста — файлы в репозитории проектирования (`docs/projects/<проект>/design/`), claude.ai — живой
редактор. Редакторы сами сохраняют версию при открытии (холст пишет `canvas.json`, страница ДС — свою версию), поэтому
сервер отклоняет публикацию поверх непрочитанной живой версии. Перед каждой публикацией: `Artifact read` + `list
scope=files` → слить, сохранив чужие ключи и `createdOnFiles` → `publish` с `root` → коммит. Итерация начинается с забора
правок заказчика: чтение живой версии → слияние → коммит «iter-NN customer» → свои правки → `diffshots` (0 «НЕОЖИДАННО») и
дифф `.dc.html` в git (изменены только названные элементы) → снова чтение → слияние → публикация → коммит «iter-NN». Отказ
после слияния — прочитать весь артефакт и список файлов, слить ещё раз; третий отказ — стоп и сообщение заказчику.
`force` стирает правки заказчика — только по его прямой просьбе. Мелкие числовые правки заказчик делает мышью и твиками,
Claude забирает их чтением; значения на артбордах — литералы из токенов ДС (их правит панель свойств), дырки `{{…}}` —
только для твиков и состояния. Регресс вне пунктов — откатить свои правки итерации, правки заказчика сохранить.
Загрузки, комментарии, `room` и `db` живут вне git — адреса и id держат в `ARTIFACTS.md`. Самопроверку тип запрещает без
просьбы: проверка — шаг, который заказывает заказчик.
Канон: cd 05/01 — выжимка п. 13, 16 и §6 (связка с репозиторием, конфликты); раунд целиком — cd 06/03 §1.

### 23. Как устроить оценку двух вариантов макета судьёй?
Ответ: Порядок: ворота и автопроверки → сверка с фактами → судья → человек; вариант с непройденными блокирующими воротами
судье не отдают. Судья — отдельная сессия Opus без контекста работы (новый субагент), каждый вызов — своя сессия. Входы:
кадры обоих вариантов — подмножество ширин приёмки по рубрике, PNG без потерь, одного размера и кодировки; рубрика
владельца (для макета — ui 13/02: 10 измерений 0–5 с весами, и гейты лендинга; аудит свежим контекстом — cd 06/04
§6–§7); одна строка задачи; без объяснений замысла, без метрик и баллов ворот. Слепота: нейтральные буквы, ключ вне
входов, узнаваемые бренды маскируют. Попарно: не больше двух изображений на вызов; ответ по критерию — A, B, ничья или
«оба не годятся», с причиной и местом; каждая пара — в обоих порядках разными вызовами, вердикт засчитывают только при
совпадении, иначе ничья; три прогона — большинство, иначе «неразличимы»; один прогон — лишь подсказка. Штраф за
избыточность: «богаче, темнее, длиннее, эффектнее» — не преимущество, добавленное без брифа — дефект. Доверие — по
согласию с голосами заказчика (`asset_audit.py agree`): меньше 20 пар — «мало данных», только отсев брака; согласие ≥ 0,7
— предфильтр; ≥ 0,8 и нижняя граница Уилсона — сортировать; перекос позиции A ≤ 0,15, согласованность перестановок ≥ 0,8
(пороги — позиции). Последнее слово — заказчик вслепую попарно на странице стенда (`stand_page.py`); вердикт судьи
показывают после его голоса. Правило решения: X лучше, если нижняя граница Уилсона 95 % > 0,5 и X выиграл большинство
видов в ≥ 75 % пар, иначе «неразличимы → умолчание» (более простой или дешёвый в доводке); автоматика не противоречит
(у «лучшего» W и приёмка не хуже). Запись: версии рубрики и промта, модель, прогоны и порядки, ответы с доказательствами,
вердикт; ключ слепоты — отдельно.
Канон: `common/judge.md` §1–§7; макет — cd 06/06 §6–§8; пороги доверия — `ai-media/11-evaluation-qa/thresholds.yaml`,
группа `judge`.

### 24. Какие ворота скорости у страницы с 3D-героем и где их проверяют?
Ответ: Три слоя по порядку «страница → эффекты → ассеты → проверки исполнителя»; величину ставит один владелец, у

блокеры B — LCP > 4 с, CLS > 0,25, INP-сценарий > 500 мс, нет LCP, LCP-картинка lazy, поле p75 «плохо»; S — выше цели:
LCP лаборатории телефон 2 500 (L2 — 3 000), десктоп L0 2 000, L1–L2 2 500 мс; CLS 0,1; INP 200; TBT телефон / десктоп L1
300 / 200, L2 600 / 300; вес первого экрана (L1 2 000 / 3 500 КБ, L2 2 500 / 4 000), JS, сессия — S, не блок. LCP-элемент —
H1 или постер из HTML, не canvas; 3D грузится после LCP и load. (2) 3D (blender, доля 3D): LCP-элемент не canvas и место
под canvas зарезервировано — блокер blender; 3D-ассеты первого экрана (GLB, текстуры, .bin) ≤ 820 / 1 536 КБ телефон /
