# Ф5 — карта знаний и навигатор: план

Рабочий документ журнала. Общий план — `../PLAN.md` (Ф5), решения — `../DECISIONS.md`. Опирается на итог сверки
`../phase-4/REPORT.md` и общие нормы `.claude/skills/design-deep-dive/kb/common/`.

## Цель и готовность
Агент, который проектирует продукт, видит карту всех знаний и смешивает нормы разных баз в одну идею (Р17, Р18). Карта —
`kb/INDEX.md`, навигатор — `SKILL.md`.
Готово, когда свежий агент по одной карте находит канонические места норм для типовых вопросов этапов (список ниже):
- не меньше 22 правильных ответов из 24;
- медиана — не больше 4 открытых файлов на вопрос;
- ни одного большого файла, прочитанного целиком.

## Что в карте
1. **Как пользоваться.** Порядок чтения: карта → `kb/common/` для межбазовых норм → README базы → «Выжимка для агента» → раздел. Старшинство (Р115). Что не норма (`99-raw/`, `PLAN.md` баз).
2. **Общие нормы `kb/common/`** — по строке на файл: что в нём и когда открывать.
3. **Базы.** Для каждой:
   - вопрос, на который она отвечает, и темы, которыми владеет (контракт тройки, `canon.tsv`);
   - входы — README и 5–10 ключевых файлов по ролям;
   - машинные файлы (схемы, YAML) и утилиты (`scripts/<база>/`).
4. **Межбазовые связи.** Контракты между базами: id, токены, паспорт визуала, план ассетов, ворота, уровни, словари, состояния, компоненты, бриф, направления, приметы, судья. У каждого — каноническое место и кто читает. Основа — SYNTHESIS §2.2 после сверки.
5. **Маршруты «этап → нормы → проверка»** по черновому порядку этапов (Р100–Р102, `../WORKFLOW-INPUTS.md` §5). Контракты этапов (вход, выход, кто утверждает) пишет `references/phases.md` в Ф7 (Р118), карта даёт знаниевую сторону. После blueprint маршруты сверяются с ним.
6. **Предметный указатель «вопрос → место»** для частых вопросов.

Объём карты — такой, чтобы читалась за один присест (ориентир ≤ 20 тыс. токенов). Подробности — в README баз, карта на них ссылается.

## Агенты
Работают по одному. Три группы независимы, поэтому допускается по два параллельно (Р78).
1. **Три агента по группам баз** — каждый пишет черновик разделов 3–6 для своих баз в `phase-5/drafts/<группа>.md`:
   - интерфейс — ux, ui;
   - маркетинг — site, text, creative;
   - ассеты и инструменты — ai-media, blender, claude-design.
   Входы: README баз, «Выжимки для агента» ключевых файлов, `kb/common/`, реестр Ф4.
2. **Сборка** — оркестратор или агент. `kb/INDEX.md` из черновиков, разделы 1–2 и 4 — общие; текст по стандарту `../phase-3/SKILL-MAP.md` §7 и forward-only.
3. **Проверка** — свежий агент без контекста сборки:
   - отвечает на 24 вопроса ниже только по карте с прогрессивной загрузкой и пишет, какие файлы открыл;
   - ключ ответов — `kb/common/canon.tsv` и строки реестра Ф4;
   - оценивает отдельный агент, не тот, что отвечал.
   Промахи — правка карты и повтор проверки.
4. **Навигатор `SKILL.md`** — оркестратор, по карте; остаётся скрытым от автовызова до Ф7.
