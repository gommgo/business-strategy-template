## Сквозные правила работы
1. В шаблоне ничего не меняем до утверждённого проекта системы (Ф3); дальше — в отдельной ветке.
2. Главная сессия — дирижёр: тяжёлое чтение делают субагенты на Opus 5.5, отчёты — в файлы, в контекст — резюме.
3. Каждая сессия начинает с `STATE.md` + `DECISIONS.md` и заканчивает их обновлением.
4. Механика — скриптами (перенос, ссылки, подсчёт, проверки): повторяемо, без токенов, проверяемо.
5. Каждый шаг измеряем (токены — `tools/count_tokens.py` с калибровкой Opus 5.5, размер, покрытие правил), а не оцениваем на глаз.

## Риски
- База ещё менялась 25.09 → заморозка + манифест.
- Размер репозитория: ≈ 40 МБ текста + ≈ 40 МБ бинарников в тематике → решение по архиву и крупным файлам в Ф2–Ф3.
- Правила базы не проверены практикой → пилоты.
- Окружение утилит: Playwright, headless-браузер, ffmpeg, Python-пакеты, ключи API, Blender → описание окружения + смоук-тесты.
- Глобальный CLAUDE.md заказчика грузится в каждого субагента → у консультанта по базе отключить.
- Claude Design — бета с серверными флагами: формат типов может смениться → снимок версий + проверка дрейфа; типов нет в среде → `kit`.
- Тип Design запрещает самопроверку без просьбы заказчика → аудит этапа макета — по его команде или на HTML-копиях через `kit`.
- Headless-браузер `kit` падает по памяти при ~2 ГБ свободной → порог `--min-free-gb 2` обязателен.
- Всегда в контексте шаблона ≈ 22 тыс. токенов (замер 26.09: `CLAUDE.md` ≈ 6, rules ≈ 1,7, шапки 29 скиллов ≈ 13,9 при бюджете
  листинга ≈ 10) → дизайн-систему в `CLAUDE.md` не класть; описания скиллов сокращать, иначе новые не попадут в листинг.
- Craft запрещён каноном (`CLAUDE.md` §3) → без правки канона дизайн-слой нелегален (решение заказчика).
