# Бриф: спецификация переноса — код (агент B)

Исполнитель — один агент на Claude Opus 5.5. До тебя агент A сделал часть «содержимое» (`SPEC.md`, `manifest-rules.yaml`,
`rules_eval.py`, `expected-content.tsv`); после тебя агент C напишет `migrate.py`, который соберёт перенос из ваших файлов.
Твоя часть — весь исполняемый код: что берём, куда кладём, какие механические правки нужны, чтобы утилиты заработали в новой
раскладке, и чем это проверить.

## Контекст
База знаний (8 ресерчей в `/home/mm/Документы/app-design/<база>-research/`) заморожена и переезжает в репозиторий-шаблон
`/home/mm/git/stit-core/business-strategy-template` внутрь скилла `.claude/skills/design-deep-dive/`. Раскладка согласована с
заказчиком — `_skill-build/phase-3/SKILL-MAP.md` (источник правды): код — в `scripts/<база>/` (имена папок = имена баз без
`-research`), общие модули — `scripts/lib/`, обслуживание базы — `scripts/maint/`, смоук — `scripts/tests/`, `kit` —
`scripts/claude-design/kit/`, данные, которые читает только код, — `scripts/<база>/data/`; окружение — вне репозитория, в
`~/.cache/design-deep-dive/` (переопределяется `DDD_HOME`). Все пути `_skill-build/…` — от `/home/mm/Документы/app-design/`.

Цель переноса по коду (SKILL-MAP §2.2): каждая взятая утилита импортируется и отвечает на `--help` (или самопроверку) в новой
раскладке. Правки при переносе — только механические: корни и пути, импорты соседей, абсолютные пути `/home/mm/…`, блокировки
браузера, каталоги выходов и кэшей, поиск бинарников и ключей. Логику, CLI, форматы вывода, Kimi-ветки, судью и схемы не трогаем —
смысловая адаптация будет позже внутри шаблона.

## Прочитать

- `_skill-build/phase-3/migration/SPEC.md` — особенно раздел «Передача агенту B»; `manifest-rules.yaml` и `expected-content.tsv` —
  чтобы знать, куда уезжают данные и файлы, на которые ссылается код.
- `_skill-build/phase-2/SYNTHESIS.md`: §4 (строки 310–410: сводная таблица утилит с каноном и вердиктом, «не брать», окружение),
  §6.9 (577–586).
- Свежий инвентарь `_skill-build/freeze/inventory/<база>.md` — разделы «Код и утилиты», «Дубли утилит (md5)»; построчно —
  `files.tsv` (классы `tool`, `code`) — только скриптами.
- Выжимки `_skill-build/phase-2/light/<база>-research.md` — точечно, разделы про код и утилиты (grep).
- Сам код — сканами (AST: импорты, argparse, `__file__`, `parents[...]`, `sys.path`, строки с `/home/mm`, `.locks`, `99-raw`,
  вызовы `node`, `blender`, бинарников, переменные окружения ключей), и глазами — там, где скан не решает.

## Что сделать (всё — в `_skill-build/phase-3/migration/`)
1. **`tools-map.tsv`** — по строке на каждый исполняемый файл-кандидат (включая дубли и не взятые): `source` (путь от корня
   app-design), `md5`, `canonical` (`yes` | `dup-of:<source>`), `verdict` (`take` | `adapt` | `skip`), `why` (Р-номер или раздел
   SYNTHESIS), `dest` (путь от корня шаблона), `kind` (`utility` | `module` | `step` | `kit` | `maint` | `test` | `data`),
   `deps_py`, `deps_node`, `deps_bin`, `patches` (коды механических правок), `smoke` (команда, `import-only` или `selftest`), `notes`.
   Охват: `99-raw/tools/` всех баз, принятые исключениями модули и шаги `99-raw/experiments/` (Р33, Р37, Р54, Р57, Р62, Р66), `kit`,
   копии утилит в тематике (`06-design-process/stand/` и др.), инструменты обслуживания `_skill-build/tools/` для `scripts/maint/`
   (check_links — одна общая версия из баз, orch_check, count_tokens + `calibration.json`, calibrate, layers).
2. **Механические правки** — `patches/` + `apply_patches.py`: детерминированно, к нетронутой копии файла; правка, которая не
   применилась или применилась не то число раз, — ошибка, а не молчание. Формат выбери сам (замены с ожидаемым числом совпадений
   или unified diff) и опиши.
3. **Overlay кода** — в `overlay/.claude/skills/design-deep-dive/scripts/`:
   - `lib/kbpaths.py` — только stdlib, без абсолютных путей: корень скилла от своего файла; `kb(база)`, `scripts(домен)`,
     `data(домен)`, домашний каталог окружения (`DDD_HOME` или `$XDG_CACHE_HOME/design-deep-dive`), выходы и кэши утилит,
     блокировки (замена `app-design/.locks/browser.lock`, с ожиданием), Python окружения, окружение Node и Playwright, поиск Blender и
     бинарников (переменная окружения или PATH), ключи — только из переменных окружения; способ подключить модули соседнего домена.
   - `requirements.txt` — версии, совместимые с уже поставленным окружением (`~/.cache/design-deep-dive/venv-freeze.txt`), плюс то,
     что найдёшь в импортах.
   - `package.json` — npm-зависимости утилит с версиями (SYNTHESIS §4.3).
   - `install.sh` — идемпотентный: venv и pip, npm в кэш, бинарники и модели ONNX с версиями и sha256 (Р55, Р59); режим
     `--dry-run` показывает, что будет сделано. Бинарники, модели и npm сейчас не скачивать.
   - `tests/smoke.py` — прогоняет каждую взятую утилиту (`smoke` из tools-map) с таймаутом и печатает таблицу.
   - `README.md` — указатель: утилита → назначение → входы → выходы → зависимости (собери скриптом из tools-map).
4. **Проверка на временной раскладке** `phase-3/migration/.staging-code/`: `scripts/` по tools-map с правками + `kb/<база>` —
   симлинки на базы источника (только для этой проверки). Смоук — Python из `~/.cache/design-deep-dive/venv`. Недостающие чистые
   Python-пакеты можно доставить в этот venv (заказчик разрешил окружение), список — в SPEC-code. Браузер не запускать: для
   `--help` он не нужен; если утилита поднимает браузер или сеть уже при импорте — отметь. Результат — `code-smoke.tsv`; правь
   правки, пока взятые утилиты не пройдут; остальное — исключения с причиной.
5. **`SPEC-code.md`** — итог в цифрах (утилит взято, дублей, не взято, по базам), API `kbpaths`, способ правок, зависимости и что
   поставлено в venv, результаты смоука, исключения, раздел «Передача агенту C» (как `migrate.py` должен применить tools-map,
   правки и overlay), раздел «На решение» — с твоей рекомендацией.

## Файлы — рабочие артефакты заказчика
Всё перечисленное — заказанные заказчиком рабочие артефакты сборки; их запись — сама задача, а не отчёт о работе. Если среда всё
же не даст записать какой-то файл, верни его полный текст в ответе — оркестратор сохранит.

## Границы
- Базы, шаблон и файлы агента A — только чтение. Писать — только в `_skill-build/phase-3/migration/` (кроме файлов агента A) и
  в venv `~/.cache/design-deep-dive/venv` (только чистые Python-пакеты). Ничего не удалять; свой файл — перезаписать.
- Решения не пересматривать; противоречия — в «На решение».
- Память: браузерные процессы не запускать; при `free -g` < 3 ГБ доступной — не запускать ничего тяжёлого.
- Итог в ответе — не длиннее 15 строк.
