## 1. О чём ресерч
Как пользоваться возможностями Claude Design (Anthropic Labs) из чата сессии Claude Code без веб-интерфейса claude.ai/design:
что Claude Design умеет, что из этого есть в Claude Code, что делаем сами, как выстроить конвейер «бриф → вайрфрейм → макет →
прототип → код», как это соотносится с Kimi K3. Завершён; сам Claude Design не запускался — всё о его качестве `[не проверено]`.
Небольшой: 18 md (≈ 3,7 тыс. строк) + прототип `04-claude-code-native/kit/` (5 файлов, 1,7 тыс. строк кода + пример «Спица»).

## 3. Ядро
1. **Исполнитель макета — сама сессия Claude Code (Opus 5.5)** в формате процесса Claude Design. Серверного агента Claude Design не
   вызывает ни один путь (API нет); у заказчика `/design` — только consent. Флаги не обходить, claude.ai браузером не автоматизировать
   (п. 3.7 Consumer Terms), сторонние мосты (CDP, cookies, чужие токены) не брать.
2. **Рабочий цикл**: 0 сессия (Opus 5.5; effort xhigh на ДС и первый hi-fi; git) → 1 бриф (`brief.yaml` kimi 07 + ≤ 7 вопросов одним
   сообщением) → 2 ДС (`DESIGN.md` + `tokens.css` → артборд-образец → «Keep») → 3 направления (2–4 low-fi по названным осям: фон hex /
   акцент hex / гарнитура + мотивация и компромисс) → 4 вайрфрейм (серые блоки) → 5 hi-fi (артборды 1440 и 390 + тёмная тема; frontend-design
   + нормы ui/ux/site/text) → 6 правки (`#N` по меткам → эхо → правка → `diffshots` 0 неожиданных → «было → стало» → Keep) → 7 ревью
   (`ui_audit.py` + 34 маркера ui 11/04 + приметы дом-стиля Claude + рубрика ui 13/02 + аудит свежим контекстом) → 8 экспорт (PDF, PNG 2×,
   `standalone.html`, zip) → 9 код той же сессией.
3. **Холст — папка `design/`**: `canvas.json` + HTML-артборды только на `var(--…)` из `tokens.css`; итерация = коммит + `review/iter-NN/`.
4. **Правки**: адрес — номер из `marks.json` снимка, который видел заказчик; номер один на всех ширинах и темах и живёт между итерациями;
   пакет ≤ 7 пунктов; ≤ 3 раундов на экран без решения заказчика; в эхе — уровень правки (элемент → компонент → токен); без `diffshots`
   правку не принимать; проверять и глазами, и числами.
5. **ДС до экранов**; системную ошибку чинить в токенах. Эстетику согласовывать направлениями, не выбирать молча.
6. **Дом-стиль Claude — бан-лист поимённо** (кремовый/off-white фон, серифный display, курсивные акценты, терракота, «01/02/03»,
   моноширинные подписи, кнопки-пилюли, капс над заголовком, «X, not Y», тикер, карточки везде) + конкретная альтернатива (5 hex,
   гарнитуры, радиус).
7. **Реальные данные и тексты — во вход**; нет — видимые заглушки `[ЦЕНА]`.
8. **Картинки, иконки, логотипы — не в Claude Design**: ассеты из ai-media и blender.
9. **Счёт**: из 35 функций Claude Design 26 работают в чате сейчас, 3 — с оговоркой, 2 — после включения `/design`, 4 — невозможны без
   интерфейса (экспорт в Google Slides, живая совместная правка, панель ДС, цикл «request tweaks»).
10. Лимит общий с Claude Code; модель и effort — явно; для данных клиента — выключить «Help Improve our AI models»; публикация
    артефакта — только по явному разрешению.
11. Гипотеза «Opus 5.5 лучше и управляемее K3» правдоподобна, не доказана (управляемость правок: Opus 5 High 11,04 % против 1,99 % у K3).
