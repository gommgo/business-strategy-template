# ux-research — дайджест корневого README

## 1. О чём ресерч
База знаний «для агента-проектировщика интерфейсов» по UX-слою: от ИА и сценариев до состояний, текстов, доступности, мобайла, дефектов ИИ-генерации и оценки; плейбуки — админка, клиентский сервис, ИИ-функции. Визуальный слой отдан `../ui-research/`. Отвечает, как спроектировать, проверить и починить интерфейс, включая сгенерированный; адресат — ИИ-агент. Статус: волны 1–4 завершены 22.09.2026; 57 файлов + 13 README папок (~54,4 тыс. строк), 79 дайджестов видео, 590 источников.

## 3. Ядро: ключевые выводы
1. **До экранов:** постура каждой роли (суверенная или транзитная) → глоссарий объектов и действий → сценарии (happy path → ветвления → ошибки → пустые) → ИА → навигация. Ревью после генерации сценарий не чинит (+0,03…0,12 из 5).
2. **Состояния — закрытым списком S01–S22:** идеальное, пустое, загрузка, частичное, ошибка; «пусто» только после загрузки, с причиной и одним действием (это онбординг, не тур); «нет прав», «лимит» — отдельные состояния.
3. **Каркас:** ИА ≤3 уровней (сайдбар ≤2); навигация слева, на десктопе видима (скрытая: 27 % против 48 % использования); шапка: назад, заголовок, статус, действия; одна primary на экран; одно и то же в одном месте.
4. **Контейнеры и защита:** панель → раскрытие строки → страница → модалка последней; предотвращение → отмена → подтверждение; кнопки называют результат («Удалить проект»); тост не для ошибок, 4–10 с.
5. **Формы — слабейшее место генерации** (FullFront ≤0,60; правила: 78 % против 42 % безошибочных отправок): одна колонка, подпись над полем, валидация по отправке со сводкой, кнопку не блокировать, ошибка над полем.
6. **Таблицы и дашборды:** страница 20 строк; >8 колонок — липкие шапка и первая колонка; >50 объектов — пагинация и фильтр; «дашборд по умолчанию» — дефект генерации; 3–6 показателей (не измерено), без круговых.
7. **Отклик:** 0,1/1/10 с; скелетон для страницы, спиннер для модуля; LCP ≤2,5 с, INP ≤200 мс, CLS ≤0,1; анимация 100–400 мс, `prefers-reduced-motion`; запрещены дефолты нейросетей: появление секций при прокрутке, hover на каждой карточке.
8. **Тексты:** читают ~20 %; кнопка = глагол + объект (инфинитив СВ, 1–3 слова); без «OK», «неверно», канцелярита; русский длиннее английского на 10–30 %; текст — до макета.
9. **Доступность и мобайл:** WCAG 2.2 AA для процесса целиком; цель ≥24×24 CSS px (тач 44×44); нативный элемент вместо ARIA; автоматика ловит ~57 % дефектов, но ~32 % критериев; на телефоне паритет функций, не интерфейса, и возобновление коротких сессий (72 с).
10. **Генерация:** вид ≠ работоспособность (WebGen-Bench: 52 % по дизайну против 17,1 % по функции); детальность входного контракта — единственный фактор, улучшающий всё; best-of-k надёжнее починки (IR 0,40 → 0,14 против 0,32); если ни один из k не прошёл ворота, чинить контракт.
11. **Оценка:** один прогон судьи-LLM — шум (13,6 % переворотов; 11 прогонов); эксперт находит 42 % крупных проблем → 3–5 проходов линзами; автопроверки — ворота, не оценка UX; метрика — успешность задачи, не клики.

## 5. Как README предлагает этим пользоваться
- Раздел «Как пользоваться (для агента)» адресован ИИ-агенту.
- Спуск: README папки (10 строк) → файл → «Выжимка для агента» (15–60 правил с метками доказательности) → тело → «Частые ошибки» → «Чек-лист» → источники.
- Повторяющееся правило живёт в файле-каноне; строка реестра противоречий сильнее любого файла.
- Маршруты: **с нуля** — `13/04` → плейбук → объекты, сценарии, ИА, экраны, компоненты, состояния, тексты, доступность, телефон, контракт → `12/02`; **проверка** — `12/01` → `12/02` → `12/03` → a11y и устройства → классификация по `11/01`; **починка** — классификация → чинить или перегенерировать → файл темы → регресс всех маршрутов → ворота `12/03 §10`.

## 7. Релевантность двум целям
**(а) Проектирование UX в бизнес-стратегии — выс.**
- Скелет: процедура `13/04` и плейбук по классу продукта.
- Артефакты до экранов: постуры ролей, глоссарий объектов, матрица «роль × объект × действие», спецификации сценариев, мобильные сценарии, вопросы ролей вместо дашборда, карта тона.
- Метрики по классу: успешность задачи; для экспертов время до первого успеха; для сервиса доля задач без поддержки.
- Право: 152-ФЗ, DSA, FTC, «отказ не дороже согласия».

**(б) Макеты во фронтенд-шаблоне SSR — выс** (поведение; визуал из ui-research).
- Контракт `11/04 §1`: реестр маршрутов (проверка по `href`), S01–S22 поимённо, реальные данные с краями (без lorem), один источник компонентов, стартер; порядок «каркас → данные → экраны → компоненты → тексты → состояния → проверки» (гипотеза).
- Ворота: `master-checklist.yaml` + `AC-*`, best-of-k, визуальный регресс всех маршрутов.
- (вывод) Под SSR ложатся: состояние списка в URL, пагинация, незаблокированная кнопка отправки, `<title>` на маршрут, серверная валидация, CWV.

- **Несостыковки:** 17,1 % WebGen-Bench отнесено то к формам (правило 27), то к функции в целом (55), сверить (вывод).

- **Устаревающее:** Digital Fairness Act (IV кв. 2026), 152-ФЗ с 01.09.2025, Deque 2021, Microsoft 2019.
- **Дубли:** контраст и размеры целей — в обеих базах, должны совпадать; (вывод) VLM-рубрики ui-research пересекаются с `11`/`12`.
