# site-research — дайджест корневого README

## 1. О чём ресерч
Логика маркетинговых сайтов (лендинги и многостраничники): какой сайт и какие страницы нужны, как собрать страницу из секций и блоков, как она ведёт к действию без обмана; плюс SEO/GEO, скорость, аналитика, право, приёмка. Читатель — ИИ-агент (Claude: бриф → карта → план → пакет → приёмка; Kimi K3 верстает по пакету) и заказчик. На 25.09.2026 волны 1–4 завершены, живая фаза не начата. Объём: 30 содержательных и 70 машиночитаемых файлов, 3 примера, 27 утилит. Право по умолчанию — РФ.

## 3. Ядро: ключевые выводы
Серьёзность: **B** — блокер (не публиковать), **S** — исправить или `x-gate-exception`, **D** — улучшение.

1. **Нет факта в `facts.yaml` — нет блока**: числа, отзывы, логотипы, цены, люди — только через слот `data` ↔ `fact:`; обязательный вид — факт или `missing[].blocking`, иначе страница не публикуется.
2. **Одно macro-действие, много мест призыва** (шапка, hero, после цены, финал, липкий на телефоне); второй путь — иным стилем; подпись называет результат нажатия.
3. **Порядок секций — из вопросов посетителя** (тип → осведомлённость → источник → макроструктура); «hero → фичи → отзывы → тарифы → CTA» без причины — дефект; у лидогенерации длина — ориентир 8–12 секций.
4. **Первый экран**: что это, для кого, что сделать + признак продолжения; ядро ≤ 40 слов; проверять с cookie-баннером на 390×844; липкие слои ≤ 20 % высоты.
5. **Блоки — только из `blocks.yaml` v1**; один словесный H1; `<header>` — только шапка, секции — `<section>` в `<main>`.
6. **Многостраничник**: главная — маршрутизатор; карта раньше планов; шапка и подвал — один раз в `site-map.chrome`; на каждую страницу ≥ 1 `<a href>`; адреса ≤ 3 сегментов; меню только за гамбургером на десктопе — нет.
7. **Формы**: заявка — 2 поля (в hero ≤ 3), антиспам без капчи, скрытые UTM; конверсия — только серверный успех; квиз — если ответы меняют предложение; калькулятор ≤ 3 параметров.
8. **Цена** — полной стоимостью; у лидогенерации — во 2–4-й секции; у B2B — не «по запросу».
9. **SSR/SSG**: H1, текст, цены, CTA, ссылки, canonical, JSON-LD — в HTML ответа (ИИ-боты JS не исполняют); один сигнал на URL; FAQPage ради сниппета и `llms.txt` — нет; поисковых ИИ-ботов не закрывать.
10. **Блокируют исходы, а не вес**: LCP > 4 с, CLS > 0,25, INP > 500 мс — B; вес — S по профилю `<page_type>@L<n>`; LCP — H1 или постер из HTML без lazy.
11. **Честность и право**: таймер — только до реальной даты; ИИ-люди в роли клиентов — никогда; РФ: отдельная неотмеченная галочка согласия на ПД (152-ФЗ); WCAG 2.2 AA — при открытом баннере; контраст — самое массовое нарушение.
12. **Приёмка**: SITE-PRE до сборки; ворота — своими замерами; UX-чек-лист только через маркетинговый профиль (иначе 87 % ложных); судья — последним, другого семейства; A/B — при выполнимой выборке (300 визитов/день, база 3 %, +20 % → ≈ 14 недель).

## 5. Как README предлагает этим пользоваться
- «Как пользоваться (для агента)»: папка → `README.md` → «Выжимка для агента» файла (15–40 правил с `→ §`) → нужный раздел через `grep -n '^#'`.
- Сценарии: **собрать** (бриф → факты → тип → карта → планы → сёстры → контроль → пакет → ворота); **проверить** (SITE-PRE → ворота → маркеры и факты → эксперт → судья → люди; ноль находок — неудачная проверка); **исправить** (дефект → правка в артефакте шага, где он родился; ≤ 7 за итерацию).
- Роутинг «шаг → файлы» — в сценарии 1; расхождения решает реестр В-01…В-36; сила правила — по меткам (`[стандарт]` обязательно, `[практика]` умолчание, `[спорно]` не выше S).

## 6. Связи с другими ресерчами
- **text, creative** — «тройка» по контракту `99-raw/notes/triad-contract-2026-09-24.md`: site — логика, text — тексты и `facts.yaml`, creative — подача (`treatment:1`, уровни амбиций).
- **ux** — каноны форм, тёмных паттернов, доступности; на сайте — с поправками, через маркетинговый профиль.
- **ui** — одна поправка (акцентная кнопка).
- **ai-media** — план ассетов из слотов, правило людей.
- **blender** — 3D по секциям: не в тарифах и формах.
- **kimi** — исполнитель вёрстки по проекции брифа; часть предложений ждёт kimi.
