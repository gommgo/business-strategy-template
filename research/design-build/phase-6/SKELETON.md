## 1. Маршруты — черновик верха страницы

- **Лендинг** (род `landing`): проект — vision-минимум и поверхность → слой страницы: бриф с уровнем → смысл и факты →
  воронка → план страницы → тексты по слотам и аудит → слой дизайна: мудборд и направления → арт-дирекция и паспорт
  визуала → ключевые ассеты → ДС по ассетам → вайрфрейм с реальными текстами → макет 1440 и 390 → движение, 3D, видео →
  проверки по просьбе → пакет для `<org>/site`.
- **Многостраничник** (род `site`): как лендинг; до планов — карта сайта и шаблоны страниц, план и тексты — на шаблон,
  главная — маршрутизатор.
- **SaaS и кабинет** (род `app`, тип `admin`): vision → роли и постуры → поверхности → capability → объекты и действия →
  сценарии → interface → экраны (карта, состояния, `ui:`, тексты «допущением») → FSD; дизайн рядом: бриф на вид →
  2–3 карточки стиля → ДС → иконки и иллюстрации по токенам → макет экранов по контракту генерации → проверки → пакет для
  `<org>/frontend`.
- **Смешанный продукт:** у каждой поверхности свой маршрут; ДС, факты и голос — общие; лендинг продукта и кабинет — два
  брифа на одной ДС.
- **Вход с любого места:** с первого этапа, у которого готов вход; пропуск — `_phase-jump.md` (A7).

## 2. Решения

### A. Маршруты

- **A1. Род поверхности — значения** (развилка; место решено, Р76 п. 2). (а) колонка только у `type: web`: `landing` ·
  `site` · `app`; `admin`, `mobile`, `bot` рода не требуют — маршрут задаёт тип; (б) колонка у всех поверхностей;
  (в) новые значения `type`. → (а): `type` — часть handoff-контракта с код-репо, колонка каскадит меньше всего
  (Ф1 05 §3). [T3]
- **A2. Лендинг: что нужно выше слоя страницы** (развилка). (а) vision-минимум (имя и род, проблема, для кого, успех)
  и поверхность; AJTBD, SWOT, карта гипотез — по желанию, пропуск — `_phase-jump.md` с долгом в state; есть карта
  гипотез — метрика воронки берётся из неё; (б) обязательны сегмент AJTBD и гипотеза. → (а): «просто сайт» не упирается
  в стратегию (Р76 п. 4). Нормы маршрута — процедура site 10/01, призыв — у site, проверки экрана — профиль `UX-*`
  (TR-30, TR-35, GT-41). [T1]
- **A3. Многостраничник** (развилка). (а) одна поверхность `site` на сайт: карта сайта и шаблоны — до планов, план и
  copy deck — на шаблон, особая страница — свой план; (б) поверхность на раздел сайта. → (а): карта сайта и единство
  визуальной системы — свойства одного сайта (site 10/01 §5, creative 04/03 §6). [T1]
- **A4. SaaS: когда начинается дизайн** (развилка). По ux 13/04 шаги 1–13 (vision, роли, объекты, сценарии) идут до
  экранов, 14–24 — экраны, 25–26 — бриф на вид и контракт генерации. (а) бриф на вид, карточки стиля и ДС — после
  шага 13, параллельно с экранами; макет — после stable-экранов; (б) весь дизайн — после stable-экранов. → (а): экраны
  структурны и ДС не ждут, а ДС нужна им для плотности и сопоставления компонентов; макет без stable-экранов
  переделывается. [T3]
- **A5. Смешанный продукт** (фиксация, карта §5): поверхность — свой маршрут; ДС одна на продукт, бриф — на
  поверхность (уровни — C1). [T2]
- **A6. Бот и мобильное в этой сборке** (развилка, вопрос 4). (а) только стыки: мобильное берёт ДС проекта и голос
  продукта; бот — голос, тексты жанра «интерфейс» и путь к человеку (ST-19); макет мобильных экранов и визуал бота —
  после пилотов, тем же входом холста; (б) полный маршрут макета мобильного уже сейчас. → (а): Р150 называет сайт,
  лендинг и SaaS, мобильного пилота нет. [T3]
- **A7. Вход с любого места, «просто сайт → сразу в дизайн»** (развилка). (а) скилл по артефактам проекта находит первый
  этап с готовым входом; быстрый путь — проект, поверхность с родом и бриф; пропущенное — `_phase-jump.md` с долгом;
  (б) дизайн без проекта — папка вне `docs/projects/`. → (а): ворота проходятся минимально, а не обходятся
  (Ф1 05 §4.1). [T1; `entrypoint` — T4]
- **A8. Где выбирается маршрут** (развилка). (а) `entrypoint` — по роду поверхности: «сайт, лендинг, страница» → слой
  страницы, «кабинет, сервис» → interface → screens, «макет, стиль, референсы, мудборд, ассеты» → дизайн; таблица
  маршрутов одна — в начале `phases.md`; (б) маршрут решает только дизайн-скилл. → (а): роутер слоёв — работа
  `entrypoint`. [T4]
- **A9. Лендинг без бэкенда** (развилка). (а) норма: поверхность `landing` без сервиса, формы — во внешние системы через
  `integration`; `/cross-audit` не считает это ошибкой (сейчас `surface-service` — error, `service-audit` — норма);
  размещение сайта решает периметр, здесь — явное «бэкенда нет»; (б) лендинг всегда с сервисом. → (а). [T1;
  `cross-audit` — T4]

- **B3. Форма файлов слоёв страницы и дизайна** (развилка). (а) машинные файлы по схемам баз — источник правды
