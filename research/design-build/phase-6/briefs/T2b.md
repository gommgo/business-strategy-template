## На что ответить в спецификации
1. **Вход холста (E1).** Производный `input/` против ручного: правила проекции «copy / map / derive / drop /
   claude_fills» (TR-22, SYNTHESIS §8.4) — поле за полем: бриф → проекция; «Нельзя утверждать» — из фактов (TR-46);
   тексты — литералы утверждённого copy deck; голос — проекция профиля (TR-50); числа — из токенов, роли display — из
   creative (NU-19, NU-22); движение — `motion-spec`, стек уровня, лист и кадры видео-референса (NU-36, NU-37, GT-27,
   CN-68); `build.perf` — из профиля страницы (GT-14); у SaaS — девять блоков контракта генерации экранов (передача T3).
   Где лежит вход, кто его собирает (скрипт — Ф8) и чем проверяется до публикации (cd 06/02 §6). Сверь с cd 06/02 §1–§6.
2. **Приёмка `ACCEPTANCE.md` (E2).** На поверхность, по роду и уровню: группы A–H (cd 06/02 §4); у сайта — блоки I–L:
   SEO и мета, право, формы, события (GT-42), A2 — действие из плана (TR-47), A3 — по политике плана (TR-45); у
   приложения — состояния по набору и «как проверить» (ST-05), кадры по классу экрана (NU-02); ширины —
   `kb/common/acceptance-widths.yaml` (NU-01); среда — тема, reduced-motion, зум 200 % (ST-27). Кто пишет и когда.
3. **Раунд правок и стоп (E3).** Пакет до 7 пунктов — ориентир, формат пункта (cd 06/03 §2), ≤ 3 раундов на экран;
   стоп после отказа публикации — «ещё один» (cd 05/01 §6) против «третий» (cd 06/03 §1, §5). Рекомендация каркаса —
   третий отказ подряд с полным чтением перед каждой попыткой; проверь по обоим файлам и по уроку синхронизации
   (`STATE.md` «Демо Claude Design 26.09»).
4. **Постоянная просьба о проверке (E4, Р64)** — где записана, как отзывается, что она разрешает.
5. **Судья (E5, JU-01)** — какие этапы зовут судью, по какому протоколу (`kb/common/judge.md`), что решает человек;
   находка `phase-5/check/grade.md` §5: `common/judge.md §7` называет только cd 06/06 §6 — нужен ли §8.
6. **Показ (E6, CN-117, Р76 п. 13)** — приватные артефакты по ходу работы, публичная ссылка — с разрешения; `kit` —
   проверки и запасной путь.
7. **Задание Claude Design (E7)** — бан-лист (`kb/common/tells.yaml`, cd 06/05 §2, блок §6), вопросы до макета одним
   блоком ≤ 7 с умолчаниями, о подаче сайта — не больше двух (VI-47).
8. **Контракты этапов холста:** вход холста → вайрфрейм с реальными текстами → макет (основные артборды 1440 и 390,
   остальные ширины — HTML-копиями) → раунд правок → проверки по постоянной просьбе → приёмка; у SaaS — макет экранов по
   контракту генерации. Для каждого — вход, выход, проверка, кто утверждает, нормы, вход с середины.
9. **Протокол `references/claude-design.md`** — оглавление и что в каждом разделе: публикация холста и ДС, синхронизация,
   раунд, стоп, показ, запасной путь `kit`; что из cd 06 (процессная часть) пишется заново, а что остаётся нормой в kb
   (Р118). Правило: правила типа артефакта в скилл не копируются, есть снимок версий и проверка дрейфа (Р15).
