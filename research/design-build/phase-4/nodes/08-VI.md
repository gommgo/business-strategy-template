## Как решалось

- **Место реестра.** Бриф давал два места: cd 06/05, если реестр — бан-лист дом-стиля Claude (Р61), и `kb/common/`, если
  он охватывает чужие для cd домены. Охватывает: text держит 93 маркера текста и лексикон на 336 правил, ai-media — 25 IMG-M
  и 18 VID-M, blender — клише 3D и пункты мастер-чек-листа, site — 52 маркера структуры и честности. cd 06/05 из них видит
  только проекцию на макет. Отсюда `kb/common/tells.yaml` (Р115: нормы без владельца — в `kb/common/`), а cd 06/05 —
  бан-лист для задания, который берёт приметы из реестра и пороги у владельцев.
- **Правило владельца.** Норма приметы живёт у владельца домена: визуал страницы — creative, визуал экрана приложения —
  ui, структура и честность страницы — site, тексты сайта — text, тексты интерфейса — ux, картинки и видео — ai-media,
  3D-ассеты — blender. Где пороги экрана и страницы разные (появление, стекло, градиенты, свечение), у приметы два места —
  по поверхности, и это одна норма с условием, а не две конкурирующих.
- **Числа не пересказываются.** Реестр называет владельца, а не порог: правка порога остаётся правкой одного места. Строки
  узла решают, какое число у владельца верное, и называют копии к правке.
- **T12 и C10 не перерешались.** Порог капс-надзаголовков — TR-14 (COPY-C-18), AIL-52 — TR-15 (калибровка). Строки VI-10 и
  VI-11 сходятся на них и добавляют связь с реестром: ui m30, cd 06/05 и `K3-EYEBROW` берут число у COPY-C-18; AIL-52 —
  кластер из пяти примет реестра.
- **Чтение** — слоями, как требует PLAN: README и выжимки, затем нужные разделы; реестр клише creative и маркеры site —
  целиком через разбор YAML скриптом (записи, `neighbors`, `crosswalk_external`, пороги), ui 11/04 и cd 06/05 — целиком.
  Все ссылки `tells.yaml` проверены скриптом: 293 ссылки на файлы, разделы и id — 0 ошибок; id проверок и 19 ключей
  `ALLOW_KEYS` совпадают с кодом утилиты.
