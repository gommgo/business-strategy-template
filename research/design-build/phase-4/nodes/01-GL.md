# 01. GL — единый глоссарий: отчёт узла

Рабочий документ журнала Ф4. Строки узла — `01-GL.tsv` (47), выход в базу — `kb/common/glossary.md`. Пути баз — от
`.claude/skills/design-deep-dive/kb/`, короткие адреса `ux 03/01 §2` — как в базах; слой проекта — `docs/projects/_template/`.

## Итог

- **`kb/common/glossary.md`** — 41 статья в 7 разделах (интерфейс и страница · облик и ДС · страница сайта · проверка и
  оценка · ширины, заглушки, доступность · тексты и доверие · служебные метки), 212 строк-переводов «где → что значит →
  скилл пишет» и 6 правил. Все 123 коротких адреса статей разрешаются в существующие файлы и разделы (скрипт по
  заголовкам); пути слоя проекта существуют; forward-only: без дат, истории, Р-номеров, ссылок на `research/` и без
  упоминания Kimi (Р80).
- **Строки** — 47: `term` 42, `new-norm` 1, `id-sync` 1, `duplicate` 2, `gap` 1; `закрыто` 45, `позиция` 2 (GL-07 сценарий,
  GL-09 компонент). Покрыты все 9 строк карты узла.
- **Главные решения по словам** (подробно — ниже и в статьях):
  - «зона (zone)» — только зона interface; ux «зона» → «область экрана», «тип области»; ui → «регион каркаса»;
    creative → «видимая область»;
  - «блок» голым не пишется: «блок (block)» — interface и screens, «блок каталога» (`block:<id>`) — site, text, creative;
  - голое «слот» — слот блока каталога (словарь site; у text и ai-media то же место); screens → «слот каркаса»;
  - «поток (flow)» — screens, «сценарий (flow)» — mobile, ux «сценарий» → «пользовательский сценарий», ux «поток» →
    «вовлечённость»;
  - «состояние» только с уточнением: «состояние экрана» (ST) и «состояние элемента» (CM); зрелость записи — «статус»;
  - «компонент» — тип закрытого словаря `components.yaml`, в screens — `ui:<Name>`; «интерфейсный примитив» screens =
    компонент;
  - «тема» — светлая и тёмная; набор бренда ui — «бренд»; «облик» — craft слоя проекта, «ремесло» — craft рубрики
    creative; «ложное дно» вместо кальки «ложный пол»;
  - «только с уточнением»: уровень, профиль, паспорт, ворота, шаблон, пресет, роль, виджет, фича, действие, бюджет.

## Как решалось

1. Глоссарий — словарь перевода: термины внутри баз не переименовываются (Р114, ловушка брифа GL), действия Ф10 —
   только там, где текст базы устарел или нужна отсылка.
2. Идентификаторы не трогаются: kind и поля слоя проекта — handoff-контракт (`CLAUDE.md` §8); id баз заморожены (Р49,
   Р62, Р86).
3. Сущность слоя проекта пишется словом и slug в скобках — это конвенция самого слоя (README interface и project:
   «перевод строгого термина + slug в скобках»); поэтому «зона (zone)», «блок (block)», «поток (flow)» не спорят с
   голыми словами баз.
4. Голое слово получает один смысл, если у него есть сущность слоя проекта или если три-четыре базы страницы совпадают
   и у словаря есть владелец (site); при трёх и более смыслах без главного — «только с уточнением» (прецедент — site
   глоссарий, выжимка п. 5: «"Уровень", "профиль", "шаблон" — только с уточнением»).
5. Числа, перечни и порядок (состояния, ширины, пороги, уровни, реестр примет) — не в глоссарии: статья отсылает к
   владельцу через `canon.tsv`, решают CM, ST, NU, GT, VI, JU, TX, TR.
6. Текст `kb/common/` — по стандарту `phase-3/SKILL-MAP.md` §7: причина у каждого ограничения, без давления, примеры —
   в строках таблиц.

- **TR:** голое «слот» = слот блока каталога site; «блок каталога» ≠ «блок (block)»; `section_role` — только словарь site;
