- Правила — `PLAN.md` фазы: Р-решения выше баз; реестр базы выше её сжатого слоя; канон — владелец темы по контракту §2,

  «закрыто». Статусы строк handoff site C1–C9 взяты по ответу W4 от 25.09 (примечания карты входов, site `PLAN.md` «Статус»).
- Большие файлы данных целиком не читались. Скрипт `tools/tr_vocab.py` (PyYAML из venv скилла) печатает сводку:
  A — пространства словаря site и статусы; B — временный словарь text против словаря site; C — `copy-slots.yaml` (слоты без
  правил, роли, `site_slot`); D — `crosswalk.tsv` (строки по базам, отношения, неизвестные id, `hero-core`, проекции);
  E — поле `block` в примерах copy deck; F — уровни creative по типам; G — префиксные ссылки сестёр на id site. Запуск —
  `~/.cache/design-deep-dive/venv/bin/python tools/tr_vocab.py [--section A,B,…]`; он же подходит для проверки после Ф8.
- `kb/common/` не пополнялся: владение темами — контракт тройки (владелец — site), словари — site, факты и copy deck — text,
  подача — creative, вход холста — claude-design. Кандидат без владельца — общий реестр примет и маркеров тройки (контракт §5,
  S2) — решает узел VI.

## 2. Словари страниц, секций и слотов

**TR-04 — утилиты text проверяют по временному словарю.** `copydeck.py validate` пишет error «page_type … нет во временном

Закрыто, действие Ф8.

## 5. Контракт полей: что читают соседи

Код тройки, читающий чужие файлы (по `scripts/`), и поля, которые нельзя менять без правки читателей в той же фазе (Ф8). URN схем
вида `urn:app-design:<база>-research:<формат>:<версия>` не меняются (Р86).

| читатель | что читает | на какие поля опирается |
|---|---|---|
| site `site_validate.py` | creative `ambition-levels.yaml`, `treatment.schema.json`; text `facts.schema.yaml`, `meaning.schema.yaml` | уровни L0–L2; `$id` `treatment:1`, `facts:1`, `meaning:1`; поля фактов и смысла по `$ref` |
| site `plan_to_assets.py` | site `crosswalk.tsv` (строки ai-media) | колонки `source_base`, `source_term`, `namespace`, `our_id`, `relation` |
| creative `spec_check.py` | site `blocks.yaml`, `page-plan.schema.json`, `site-map.schema.json` | `blocks` (id → анатомия, варианты), структура плана и карты |
| creative `recipe_check.py` | site `blocks.yaml`, `vocabulary.yaml` | ключи `blocks`; `namespaces.<пространство>.values[].id` |
| creative `ad_check.py` | ai-media `visual-dna.schema.json`; site `vocabulary.yaml`; свой `treatment` v0 | подсхемы паспорта визуала; `namespaces`; `x-effect-ids-v0` |
| creative `validate_stack.py` | свой `treatment` v0 | `x-effect-ids-v0` |

Правило: чтение соседа — через `kbpaths.kb('<база>', …)`; поле из этой таблицы переименовывается только вместе с читателями;
