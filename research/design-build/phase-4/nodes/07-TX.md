# 07. TX — тексты ux ↔ text: отчёт узла

Рабочий документ журнала Ф4. Узел сводит нормы текстов интерфейса (ux `07/*`) и маркетинговых текстов (text `04–08`) так,
чтобы оба вида текста проверялись одними инструментами без противоречий: словарь запретов, линтер, роли текста, жанр
«интерфейс», длины, типографика, голос бренда и продукта. Строки — `07-TX.tsv` (45). Пути баз — от
`.claude/skills/design-deep-dive/kb/`, пути слоя проекта и кода — от корня репозитория. Цитаты — не длиннее 15 слов, с
путём.

Правки существующих файлов делают следующие фазы (Р114): тексты баз — Ф10, код и производный YAML — Ф8, слой проекта —
Ф7, blueprint и слой дизайна — Ф6, калибровка — Ф9. Существующие файлы `kb/`, `scripts/` и `docs/` не правились. Утилиты
запускались только на чтение: `ux_dict_to_yaml.py --check` и `copy_lint.py` на пробных строках в папке сессии.

## Как решалось

- Правила — `PLAN.md` фазы: Р-решения выше баз; реестр противоречий базы выше её сжатого слоя (Р48); канон — у
  владельца темы; числа — в одном машиночитаемом месте. Опора: Р25 (тексты интерфейса — черновик «допущением», роли,
  реестр текстов, проверка словарём), Р31 (линтер text для текстов интерфейса, роль напрямую), Р49 (канон словаря — ux
  07/06, копия — сборкой), Р69 (демо-факты — меткой), Р70 (жанр «интерфейс», длины по ролям, межстрочные проверки), Р74
  (нормы 152-ФЗ — содержание базы, не правило работы системы).
- Переданное узлами принято как данность: GL — «роль текста» ≠ «стиль текста», граница голосов — здесь; TR — голос —
  профиль text, у холста проекция (TR-50), словарь id — site, свойства слота — `copy-slots.yaml` (TR-04); CM — роли
  частей компонентов здесь, `error` ≠ `invalid`; ST — словарь состояний S01–S24, тексты состояний и `fallback` бота —
  здесь; NU — тексты кнопки паузы, подпись hero-CTA.
- **Спорное решалось по механизму, а не по тексту.** Где база записала норму, а код ведёт себя иначе, решение проверено
  прогоном: `copy_lint.py` 0.9.3 на пробных строках со своим словарём ролей (`--vocab`) показал, что роль `body` и
  интерфейсные роли работают, если их передать, и что поправки сайта снижают уровни ux в любом жанре.
- **Жанровая развилка — не противоречие.** Большая часть «поправок к соседу» text (свод-01…11, ux-01…19) — законное
  различие жанров: ux пишет правила интерфейса, text — сайта. Такие строки закрыты как `duplicate` с одним каноном,
  который называет обе стороны; спор остаётся там, где одна норма действует на оба жанра (знак диапазона, пробел
  разряда, голос, «Подробнее»).
- **Почему без файла в `kb/common/`.** Роли и словарь — ux; линтер, профили, голос, типографика — text; вид текста — ui.
  Соответствие частей компонентов ролям ложится ключом в уже созданный `components.yaml` (CN или Ф10), соответствие
  полей слоя проекта ролям — вход Ф7, как сопоставление состояний у ST.

### TX-04 · Роль текста — прямой вход линтера (conflict, закрыто)

- **Стороны.** text 06/02 §3.1: «Тип слота (`slot_type`) — из временного словаря оркестратора». §6.12 п. 3: «Прямого
  ввода роли в линтер нет» (light/text) против ключей `--slot-type`, `--vocab` (text «Поправки»). Код `copy_lint.py`:
  `role_for(slot_type, vocab, fallback="marketing")` — неизвестный тип слота получает роль `marketing`.
- **Проверено прогоном.** Через словарь по умолчанию достижимы 17 ролей из 31 (так же через `copy-slots.yaml`: 69 типов,
  те же 17). Недостижимы `label`, `placeholder`, `tab`, `status`, `toast`, `banner`, `error`, `empty`, `confirm-title`,

  «Произошла ошибка» с несуществующим `--slot-type` — 0 находок (роль ушла в `marketing`); со своим `--vocab`, где тип
  ведёт к роли `error`, — две находки error (`ux-3-3-02`, `ux-3-3-11`).
- **Решение.** Верны обе стороны §6.12 п. 3: прямого ввода нет, обход через свой словарь есть. Роль становится входом
  наравне с типом слота: ключ `--role` и поле `role` у строки реестра текстов; значения — закрытый список ux 07/06 §7.2
  (TX-07) и внутренняя `meta` (TX-10). Неизвестная роль или тип — ошибка запуска. Для слотов сайта роль даёт
  `copy-slots.yaml` (TR-04).
- **Канон:** text 06/02 §3.1. **Ф8:** `copy_lint.py` — `--role`, поле `role`, вход «реестр текстов» (TX-45), отказ на
  неизвестном. **Ф10:** 06/02 §3.1 — «роль — из типа слота или напрямую».

### TX-05 · Жанр «интерфейс» (gap, закрыто)

- **Стороны.** `copy_lint.py`: жанры `landing`, `site-page`, `article`, `meta`, `geo`, `email-form`; текст без жанра
  разбирается как `landing`. Правила text о заголовках и кнопках (`ru-pun-title-case`, `ru-pun-caps-text`,
  `ru-pun-exclamation-heading`, `ru-pun-emoji-heading`, `ru-pun-arrow-cta`) выбирают место по `slot_types` сайта — у строк
  интерфейса их нет. Проза считается по `prose_slot_types`. ux 07/06 §7.4 — порядок проверок интерфейса.
- **Решение.** Жанр `interface` — поверхности голоса продукта (TX-30): интерфейс за входом, мобильное приложение, бот,
  транзакционные письма, СМС, push. Состав: правила ux — с уровнями 07/06 без поправок сайта, порядок §7.4; из правил
  text — артефакты, данные и типографика H; анализаторы прозы — только роли `body`, `help`, `email`; правила со
  `slot_types` заголовков и кнопок получают выбор по ролям (TX-23); длины по ролям (TX-18); межстрочные анализаторы
  (TX-21). Словари стиля сайта (LEX, SYN, MKT, STR, TON) в жанр не входят: они написаны для маркетинговой прозы, а
  строки интерфейса проверяет словарь ux.
- **Канон:** `text/06-anti-slop/profiles.yaml` (профиль `interface`). **Ф8:** жанр и профиль; **Ф10:** 06/02 §4 — строка
  профиля; **Ф6:** жанр строки — по поверхности.

### TX-07 · Роль `body` и закрытый список ролей (id-sync, закрыто)

- **Стороны.** ux 07/06 §7.2: «Закрытый список ролей, согласованный с ключами строк» (`05` §3.1) — 31 роль, `body` нет.

  `body`, `error`, `empty`, `status`, `tooltip`, `aria`. Правила 07/06 для `body`: §2.3 (пассив), §4.1 («There
  is»), §6.4 (знаки в прозе), пример §7.1. Конвертер: «в copy_lint не срабатывает, пока роль не уточнит ux» — 6 правил.
  §1 называет роль `confirm`, которой в списке нет (конвертер читает её как `confirm-title` и `confirm-body`).
- **Решение.** Два списка разной зернистости: 07/05 §3.1 — общие роли внутри ключа `{раздел}.{экран}.{компонент}.{роль}`,
  07/06 §7.2 — роль узла, в которую уже вошёл компонент (`confirm.body` → `confirm-body`, `toast.body` → `toast`). В
  07/06 §7.2 добавляется `body` (32 роли): связный текст интерфейса без своей роли — абзац на экране, пояснение
  онбординга, описание раздела. Берётся самая узкая роль: `confirm-body`, `banner`, `setting-description`, `empty`,
  `help` раньше `body`. Это расширение списка, не переименование: Р49 не затронут.
- **Ловушка.** Слот сайта `body` (тело блока) и роль `body` — разные пространства id: слот `body` даёт роль `marketing`.
- **Канон:** ux 07/06 §7.2. **Ф10:** §7.2 — `body` и правило самой узкой роли; §1 — `confirm-title`, `confirm-body`;
  07/05 §3.1 — таблица «роль ключа → роль 07/06»; глоссарий «Роль» — 32 роли (CN или Ф10). **Ф8:** `UX_ROLES` + `body`,
  пометку конвертера снять.

### TX-08 · Регулярки словаря переносимы (conflict, закрыто)

- **Стороны.** text ux-12 (handoff) и 06/01 §11: «В JS `\w` не матчит кириллицу даже с флагом u»; цепочки родительных
  §2.4 в JS не работают; `производ[иия]\w*` ловит «производитель»; `\b\(s\)he\b` не ловит «(s)he»; классы из заглавных
  с флагом `i` ловят строчные; «Ё» вне `А-Я` (`^[A-ZА-Я]{2,}\s—\s` не ловит «ОТЧЁТ — …»). ux 07/06, шапка: «синтаксис
  ECMAScript с флагами `giu`» и «`\b` в JS не работает с кириллицей»; частая ошибка 6 — то же.
- **Состояние.** Конвертер снимает `i` у классов из одних заглавных (`ux-5-3-03`, `ux-6-4-11` — флаги пустые); в
  Python `\w` юникодный, поэтому в линтере §2.4 работает; «производ» чинит заплатка `ux-2-1-04` в `marketing-role.yaml`.
  Не исправлены «(s)he», «Ё» в классе заглавных, `\w` и `\b` у кириллицы в §2.3, §3.6, §6.4 — они ломаются в JS.

  «—» без пробелов — вариант, который выбирает ДС продукта (канон Контура). Ошибка в любом жанре — дефис и тире с
  пробелами между числами. Линтер не ловит ни один из двух знаков, смешение знаков в продукте — межстрочная проверка
  форматов.
- **Почему так.** Написание чисел — общее ядро голоса бренда и голоса продукта (text 05/01 §2.2): два знака на сайте и
  в кабинете одного продукта — разнобой. У «–» больше сторон (Лебедев, ui, text, Microsoft), у «—» — Контур, который сам
  называет выбор стилем. Для оркестратора: если держать умолчанием «—», меняется только умолчание, правило «один знак
  на продукт» остаётся.
- **Канон:** text 08/02 §1.3. **Ф10:** ux 07/03 §6.3 и выжимка п. 10, 07/06 §9 п. 18, AC-TXT-13 — «тире в тексте —
  длинное; диапазон — знак продукта»; text 08/02 §1.3 — «один вариант на продукт». **Ф6:** ДС фиксирует знак.

### TX-27 · Пробел в разрядах (conflict, закрыто)

  действие, объект, группа (меню, статусы), статус «допущение» → «утверждено» (Р25). Жанр — `interface`.

| слой | поле | роль |
|---|---|---|
| screens | текстовый узел дерева: заголовок экрана, секции, абзац, подпись | `title`, `section-title`, `body`, `caption`; части компонентов — по TX-42 |
| screens | состояние экрана | по TX-43 |
| mobile | `rationale` разрешения | `body` (заголовок экрана разрешения — `title`) |
| mobile | `phrases` системного действия | слова пользователя: стиль не проверяется (`user-content`), термины — по глоссарию |
| mobile | `response` системного действия | `toast` |
| mobile | тексты виджета системы (`placeholder`, `empty`, `stale`) | `status`, `empty` |
| бот | `message` окна | `body`; первая строка уведомления — `push` |
| бот | подпись кнопки, `url`, пункт выбора | `action`, `link`, `label` |
| бот | `fallback` ключа getter'а | пусто — `empty`, отказ источника — `error` (ST-24) |
| бот | `errors` окна | `error` |
| бот | исходящее сообщение (`notification.md`) | `push` |

- **Почему позиция:** форма реестра и поля в слоях — Ф7, этап и порядок — Ф6; здесь — состав полей и роли.
- **Канон:** ux 07/05 §3.
