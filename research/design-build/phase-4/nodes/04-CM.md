# 04. CM — словарь компонентов и состояния элемента: отчёт узла

Рабочий документ журнала Ф4. Узел строит закрытый словарь типов компонентов (Р29, Р45, Р79), сводит состояния элемента
баз в один набор и закрывает ожидания ux от ui из handoff. Строки — `04-CM.tsv` (30); новый файл —
`.claude/skills/design-deep-dive/kb/common/components.yaml`. Пути баз — от `.claude/skills/design-deep-dive/kb/`.

Правки существующих файлов делают следующие фазы (Р114): тексты баз — Ф10, код и производный YAML — Ф8, слой проекта — Ф7,
слой дизайна и состав ДС — Ф6.

## Итог

- **Строк 30**, все 26 строк карты узла покрыты (`registry.py coverage --node CM`: 0 непокрытых). По видам: `duplicate` 13,
  `conflict` 4, `term` 4, `new-norm` 3, `id-sync` 3, `gap` 3. По статусам: закрыто 24, позиция 5, открыто 1, заказчику 0.
- **Словарь — `kb/common/components.yaml`**: 65 типов в семи группах (действия 7, ввод и выбор 19, навигация 8, оверлеи 5,
  обратная связь 7, данные 16, структура 3). У типа: имя, группа, потребность, ссылки на поведение ux и вид ui, клавиатура,
  тексты, обязательные и необязательные состояния элемента, части для `ui:<Тип>.<Часть>`, метки `usage` токенов, классы
  эталона `app.css`, строка матрицы состояний экрана, имена в других системах (`aka`), частые подмены (`use_instead`).
- **Состояния элемента — один набор из 18 id** (CM-02): rest, hover, focus-visible, active, selected, checked,
  indeterminate, expanded, disabled, readonly, invalid, warning, valid, loading, skeleton, dragged, drop-target, visited.
  11 / 9 / 8 у ux — срезы одного списка, 14 у ui — его уровень CSS и ARIA. У каждого типа — `states.required` (ДС рисует
  всегда) и `states.optional` (когда продукт использует режим).
- **Закрытость без внешней библиотеки** (CM-05): спор §6.12 п. 25 снят — словарь не возвращает снятый контракт с манифестом
  пакета, он нейтрален к коду и без props и вариантов; компоненты даёт ДС проекта сопоставлением «тип → компонент».
  Недостающий тип проект заводит расширением (CM-06, позиция до Ф6).
- **Что не входит в словарь** (CM-08 … CM-12): композиции и паттерны страниц (каркас, шапка страницы, master-detail, форма,
  дашборд …), раскладка, иконки, текст, облик, состояния экрана, блоки каталога сайта, виджеты окна бота и виджеты системы
  mobile. «Карточка дашборда» — тип Card или KpiTile, блоки дашборда — блоки (block). `shared-ui` FSD — код, который
  реализует тип.
- **Нормы типов**: тост — по умолчанию 5–6 с, ошибки и предупреждения не тостом (CM-16, канон ux 04/08 §3.2); форма в
  модальном окне — не больше пяти полей (CM-17); фокус — ui 06/07 §5, требования стандарта — ux 08/02 §7.1 (CM-18); UI1 —
  повтор призыва на сайте совместим с «одной главной на экран или секцию» (CM-19).
- **Ожидания ux от ui** (CM-22 … CM-30): выполнены все, кроме чисел — шкала отступов 8/4, длина строки, основной кегль на
  телефоне и цели по зонам уходят узлу NU (CM-29 открыто, CM-25 позиция).

## Как решалось

- Правила — `PLAN.md` фазы: Р-решения выше баз, реестр базы выше её сжатого слоя, канон — у владельца темы. Р45 делит
  словарь так: поведение и типы — ux 04, вид и матрица «компонент × состояние» — ui 06/07. У словаря как перечня владельца
  среди баз нет, поэтому он живёт в `kb/common/` (Р115), а нормы поведения и вида остаются у ux и ui и в файл не
  пересказываются — только ссылки.
- **Какой тип входит в словарь.** Три условия: (1) у компонента есть норма поведения ux или визуальная спецификация ui
  (для SkipLink и Carousel — нормы доступности ux 08); (2) он закрывает одну потребность и не является композицией —
  тест на разделение ux 10/02 §3.1; (3) экраны ставят его узлом `ui:`. Кандидаты — ux 04/*, ui 06/01–06, глоссарий ui 06 §2
  (33 типа), грань «Слот» словаря меток (40), классы `app.css`, имена в формах screens, каталог ux 10/01 §3.2.
- **Имена типов** — по ux 10/01 §3.2: «Имя компонента берётся отсюда, не выдумывается» (`ux/10-…/01-….md` §3.2). Где
  каталожное имя двусмысленно (Toggle — переключатель и кнопка-переключатель, Stepper — числовой степпер и шаги,
  Header — шапка приложения и часть модального окна), выбрано однозначное, каталожное — в `aka`.
- **Набор состояний** — объединение ux 06/01 §7.2, ui 06/07 §1 и глоссария ui 06 §4 после склейки синонимов. Id выбраны
  по ui и ARIA там, где имя ux сталкивается с другим словарём: `error` — состояние экрана (S13, S14) и роль текста ux 07/06,
  поэтому `invalid`; `default` — режим плотности и вариант кнопки, поэтому `rest`; `success` — состояние экрана S12,
  поэтому `valid`.
- **Обязательные состояния типа** — по строке матрицы ui 06/07 §2, сводке состояний поля ui 06/02 §3.1, таблице загрузки
  ui 06/07 §8 и контракту ux 04/06 §15.1; ui 06/07 чек-лист даёт ядро нажимаемых: rest, hover, active, focus-visible,
  disabled.
- Снятый контракт §6.12 п. 25 прочитан по истории (`git show 1dd3a93^:…/ui-inventory.md`, только чтение): его приёмы —
  семейства, `aka`, части `<Имя>.<Часть>`, «раскладка — не компонент» — взяты, внешний манифест и props — нет.
- Проверка файла — скрипт узла: YAML читается `yaml.safe_load`, все 356 ссылок в тексте файла (с комментариями) ведут на
  существующие файлы и разделы, состояния типов — из набора, `use_instead` и `crosswalk` ведут на типы, метки `usage` — из
  граней 1 и 4 словаря ui 14/08 §4, классы есть в `app.css`, `aka` не совпадают с типами и не повторяются.

## 1. Словарь типов (CM-01, CM-05, CM-06, CM-07)

**CM-01. Одно место словаря.** ux задаёт выбор типа и инвентарь «один примитив на потребность» до генерации
(`ux/13-app-types/04-master-procedure-brief-to-screens.md` §18); ui — визуальные спецификации 06/01–06; screens пишут
`ui:<Name>`, но «словаря примитивов и их атрибутов у слоя нет» (`docs/projects/_template/screens/README.md`). Решение —
`components.yaml`, раздел `types`:

| группа | типы |
|---|---|
| действия (7) | Button, IconButton, SplitButton, Link, Menu, CommandPalette, Toolbar |
| ввод и выбор (19) | Field, TextInput, Textarea, SearchInput, NumberInput, Select, Combobox, Listbox, Checkbox, RadioGroup, Switch, SegmentedControl, Slider, DatePicker, FileUpload, TagInput, ColorPicker, RichTextEditor, Chip |
| навигация (8) | Sidebar, TopBar, BottomNav, Breadcrumbs, Tabs, Pagination, Steps, SkipLink |
| оверлеи (5) | Modal, ConfirmModal, Drawer, Popover, Tooltip |
| обратная связь (7) | Toast, Banner, Alert, Progress, Spinner, Skeleton, EmptyState |
| данные (16) | Table, ComparisonTable, List, DescriptionList, Card, KpiTile, Chart, TreeView, Avatar, Badge, Tag, Code, Kbd, Image, Carousel, Rating |
| структура (3) | Accordion, Separator, ScrollArea |

Раздел «Проверка покрытия» в шапке файла — контракт скрипта Ф8: узлы `ui:` ∈ словарь или расширение проекта, части ∈
`parts`, каждый названный тип сопоставлен компоненту ДС (один компонент ДС может закрывать несколько типов, два на один
тип — дефект), у компонента нарисованы `states.required`, `hover` не требуется на поверхности `mobile`, значения — из
токенов ДС. Копии к правке (Ф7): screens README «Naming узлов», `screen-deep-dive/references/tree-notation.md` (имя
`ui:<Name>` «скилл выводит сам» → берётся из словаря), правило screen-audit «`ui:` вне словаря — error». Закрыто. GL-09
(«словаря компонентов нет») закрыт этой строкой.

**CM-05. Спор §6.12 п. 25.** Снятый коммитом 1dd3a93 контракт: «имя `ui:<Name>` валидно ⇔ `<Name>` есть в словаре
`components` манифеста» внешнего пакета, вместе с его props. Р29 и Р79 возвращают закрытость, но в другой форме: словарь
живёт в скилле, код и библиотеку не знает (Р7), props и вариантов не держит (облик — слой дизайна, Р76 п. 1); компонент
даёт ДС проекта. Вопрос ux-низ §8 п. 3 закрыт Р29 и Р79. Закрыто.

**CM-06. Расширение проектом.** Р79 говорит о словаре «на уровне проекта», ux 10/02 §3.1 — «на каждую потребность в продукте
ровно один компонент» и предупреждает, что отдача от новых компонентов убывает. Словарь проекта = типы `components.yaml` +
расширения проекта; у расширения — id, имя, потребность, ближайший тип и почему не подходит, поведение, состояния из общего
набора, части (раздел `project_extension`). Тип, понадобившийся второму проекту, переносят в словарь. Позиция: место записи
в слое дизайна — Ф6.

**CM-07. Имена.** ux 10/01 §3.4 даёт синонимы каталогов («Modal — Dialog, Popup», «Toast — Snackbar») и правило «в одном
продукте живёт одно имя». В формах screens `ui:Navbar` и `ui:Search` — это TopBar и SearchInput (Ф7). `aka` в экранах не
принимается: по нему проверка подсказывает тип, а слой дизайна сопоставляет компонент ДС с чужим именем. Закрыто.

## 2. Что не входит в словарь (CM-08 … CM-12)

**CM-08. Паттерны и композиции.** ux 10/01 §3.3: в каталогах «нет ни одной композиции уровня страницы» — page header, app
shell, master-detail, settings page. Они — каркас (shell) и блоки (block) экранов из типов словаря; нормы остаются в ux 04/*
и ux 13/04 §18 (инвентарь композиций). Классы `app.css` `.shell`, `.page-header`, `.settings`, `.object`, `.timeline` —
композиции. Немодальная боковая панель — слот `detail` каркаса, модальная — тип Drawer. Закрыто.

**CM-09. «Карточка дашборда».** ux глоссарий: «виджет» — карточка дашборда или секция экрана объекта; ux 04/03 §3.3 —
«Десять типов блоков — чек-лист состава». Плитка одного показателя — тип KpiTile (шаблон ux 04/03 §4.3, вид ui 06/06 §7),
прочий контейнер — Card; типы блоков дашборда — блоки (block). Закрыто.

**CM-10. `ui:` — ДС — `shared-ui`.** Screens: «в коде его реализуют проектные компоненты, у фронтовой поверхности это слайс
`shared-ui`»; FSD: `shared-ui` поднимается при реальном переиспользовании. Цепочка: тип (экраны) → компонент ДС
(сопоставление в слое дизайна) → код; слайс `shared-ui` называет тип, который реализует, тип может обойтись без слайса.
Позиция: колонка `ui-type` в `fsd/_template/shared-ui.md` — Ф7, сопоставление — Ф6.

**CM-11. Бот и mobile.** Виджет-язык окна бота закрыт в своём слое и читается кодом бота (`CLAUDE.md` §8); облик рисует
клиент Telegram. Виджеты mobile — виджеты системы. В словарь не входят; для перевода смысла — `crosswalk.bot_widgets`
(button → Button, url → Link, select → RadioGroup или Select, multiselect → Checkbox или Listbox, text-input → TextInput,
calendar → DatePicker). Закрыто.

**CM-12. Облик.** В формах screens `variant=accent`, `size=md` — «свободные семантические пометки автора»; ux-низ §6 в.3:
облик — в слое дизайна. В словаре нет вариантов и размеров; уровень действия (главное, второстепенное, в меню) — смысл по
матрице действий ux 04/10 §1.1, он остаётся в экранах. Размеры намерения `layout:` — канон screens. Позиция: имя
атрибута уровня действия и судьба `size` у `ui:` — Ф7.

| focus-visible | focus-visible | focus, focus-visible | focus |
| active | active, pressed | active, pressed | active |
| selected | selected | selected, current | selected |
| checked | = selected | checked, pressed (toggle) | selected |
| indeterminate | mixed (04/06 §4.2) | indeterminate | — |
| expanded | «открытое состояние» | expanded | — |
| disabled | disabled | disabled | disabled |
| readonly | read-only | readonly | readonly |
| invalid | error | invalid | invalid |
| warning | warning | warning | — |
| valid | «индикация успеха» (04/05 §4.7) | success (06/02 §3.1) | — |
| loading | loading | loading, busy | loading |
| skeleton | skeleton | — (приём загрузки) | — |

Не состояния элемента (раздел `not_element_states`): `focus` без кольца, `filled`, `focus-within`, открытость оверлея,
статус шага, тон статуса бейджа, комбинации вроде selected + hover (рисуются по ui 06/07 §10). Копии к правке (Ф10): ux 06/01
§7.2 и §8.1, 11/04 §1.4 и §7.3, 04/06 §15.1 и выжимка п. 26, 10/02 §3.4, UX-STA-14 (текст, id прежний; Ф8 пересобирает
YAML), ui 06/07 §1, глоссарий ui 06 §4. Закрыто.

**CM-03. Имена id.** `invalid`, `rest`, `valid` выбраны, чтобы не столкнуться с состоянием экрана, ролью текста и режимом
плотности; `focus-visible` — потому что фокус без кольца своего вида не имеет (ui 06/07, «Частые ошибки» п. 20: «`focus:`
вместо `focus-visible:` — кольцо при клике мышью»). Метки токенов не переименовываются: соответствие — в `synonyms.usage`.
Закрыто.

**CM-04. Состояния по типу.** Ядро нажимаемых — rest, hover, focus-visible, active, disabled («Обязательный минимум
состояний интерактивного элемента» — ui 06/07 выжимка п. 1); у полей ввода — rest, hover, focus-visible, disabled, readonly,
invalid (ui 06/02 §3.1); у контейнеров без собственного отклика (Modal, Toast, Badge …) — rest, отклик несут их части.
`hover` рисуется только при указателе (ui 06/07 §4.5, ux 09/02 §5.7). Варианты данных коллекций и плиток — состояния
экрана, ключ `screen_states` ведёт к строке ux 06/01 §3. Закрыто.

## 4. Связи словаря: usage, app.css, пакет ДС (CM-13 … CM-15)

**CM-13. `usage`: 84 или 94.** ui 14/08 §4: «84 метки в шести фасетах», грань «Слот» — «30 меток». По списку: грань 1 — 40,
всего 94 (40 + 18 + 10 + 10 + 9 + 7). Канон — сам список; счёт к правке (Ф10). У 53 типов есть метки грани «Слот»;
`page`, `surface`, `panel`, `page-header` — области каркаса и композиций. Закрыто.

**CM-14. `app.css`.** Классы эталона есть у 25 типов; выбранная строка и текущий пункт размечены `aria-selected` и
`aria-current` — состояние `selected`. Закрыто.

**CM-15. Блок «Дизайн-система».** ux ждёт формат, в котором токены попадают в блок «Дизайн-система» контракта генерации
(handoff §5 п. 2); ux 13/04 §26: блок = «Шаг 18 + токены из ui + правило заземления»; ui 12/04 §2.6 — пакет `design-system/`
(DESIGN.md, `tokens.json` DTCG, `guidelines/components/{overview,button,input,table,navigation,feedback,modal}.md`, starter,
checks). Решение: блок = типы продукта из словаря (потребность, подмены, состояния) + сопоставление «тип → компонент ДС» +
токены DTCG + правило заземления. Сопоставления в пакете ui нет — его добавляет слой дизайна; группы словаря ложатся на
`guidelines/components/` (действия → button, ввод → input, данные → table, навигация, обратная связь, оверлеи → modal).
Позиция: состав ДС проекта (артефакт Design System и DTCG в репозитории, Р14, Р42) — Ф6.

## 5. Нормы отдельных типов (CM-16 … CM-21)

**CM-16. Тост.** ux реестр № 11: «4–10 с (по умолчанию 5–6, не короче времени чтения)»; ux 04/08 §3.2: «по умолчанию около

Копии к правке: ui 06/05 §3.4 и выжимка п. 10, README ui 06 п. 8, глоссарии ui 06 и 00, 06/08, 14/06, ux 03/04 §8 п. 5.
Закрыто.

**CM-17. Форма в модальном окне.** ux 04/07 §1.2: «до ~5 полей, один экран без прокрутки»; реестр № 7 и правило 23 — ≤ 5;
