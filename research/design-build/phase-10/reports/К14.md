## Отступления

1. **`qa_pipeline.py --strict`: review — код 3, fail — код 1.** Прежние коды (0 pass / 1 review / 2 fail / 3 ошибка
   запуска) с порядком «0 / 1 / 2 / особые от 3» не совмещаются: 2 занят ошибкой вызова. Выбрано: fail (есть ERROR) — 1,
   review (только WARN) — особый исход 3, ошибка вызова — 2. Вариант «review — 0» отброшен: обёртка со `--strict`
   перестала бы отличать review от pass. У `gate_check.py --strict` особого кода нет: провал S кода не менял и раньше.
2. **`qa_pipeline.py`: стадия без результата — код 2 и без `--strict`.** Blender не вернул отчёт (`scene`) или зонд не
   дал файла (`page`) — это не выполненный замер; признак — поле `error` результата (у `page` поле и `codes`
   добавлены). Отказ отдельной проверки внутри `glb` (валидатор, three) остаётся находкой ERROR в отчёте: код 0, со
   `--strict` — 1.
3. **`qa_pipeline.py --help` — код 0** (был 3), вызов без режима, с чужим режимом, без входа или с несуществующим GLB —
   код 2 и строка в stderr (был 3 или трассировка). Отсюда строка в «Для смоука».
4. **`run_recipes.py`:** вызов без рецептов — код 2 (раньше печатал сводку сохранённого результата и возвращал 0);
   утилиты и блоки `# run: system` идут Python окружения скилла (`kbpaths.python()`), а не `python3` из PATH; шапка
   собираемых `build.py` и `post.py` — «Сгенерировано run_recipes.py из …». Образец рецепта (`build.py`, GLB, числа,
   `web/`) прогон по-прежнему пишет в `examples/<slug>/` базы — так устроен `rk.out_dir()` (чужой файл);
   в `$DDD_HOME/out/blender/run_recipes/` — только `result.json`.
5. **`run_doc_blocks.py`:** ключ `--dry-run` добавлен, потому что проверка пункта («разбор блоков без Blender») без
   него невозможна; блоки Blender исполняются с рабочей папкой `kb/blender` (раньше — папка вызова; у bash и
   `# run: system` корень базы был и до правки) — чтобы строка пути в блоке md могла быть относительной
   (`../../scripts/blender`), см. «Для текстов», п. 4. Проверено одним фоновым запуском Blender без рендера (0,7 с).
6. **Копии — не побайтные.** Побайтно совпадают три (`model_a.js`, `main_3d.js`, `page.js`); у `zstudio.py` добавлены
