### Договорённости между зонами (в задание каждой названной зоны)

Форму пишет первая названная зона и фиксирует её в отчёте («Для следующих зон»), остальные читают. Все новые поля схем —
необязательные: утверждённые файлы проектов проходят схемы без правки.

- **Д1 — мессенджер как цель и готовое сообщение (F9-005, F9-011).** Цель призыва шапки и action-слота —
  `messenger:<fact-id>`; готовое сообщение — текстовый слот типа `messenger-prefill`, на него ссылается `target.prefill`.
  `К1а` — схемы и проверки, `К1б` — тип слота и элементы блоков, `К4а` — правило слота и каркас, `К3б` — проекция во вход.
- **Д2 — локальная навигация (F9-023).** `page.navigation.local_nav {kind, sticky}`: `К1а` — схема, PL-N02, правило
  карты входа; `К1б` — вариант блока; `К3б` — проекция в `page.yaml`.
- **Д3 — таблица соответствий.** `source_base` в `crosswalk.tsv` — имя базы без суффикса исследования; данные и литерал
  чтения в `plan_to_assets.py` правит одна зона `К6в`; `К1б` файл не трогает.
- **Д4 — снятие ложной M-NAV (OE4-03).** `К8б` — ключ `allow` в `tells.yaml`; `К11` — `--allow` помечает находку
  `allowed` с причиной; `К2` — `visual_summary` не поднимает такую находку в R-VIS-001.
- **Д5 — один профиль голоса (OE5-18).** `К4б` — схема голоса допускает профиль продукта без профиля бренда; `К2` —
  R-COV-007 принимает один профиль.
- **Д6 — проекции `app-brief` (OE5-19).** Вход читает источник напрямую (`К3б`); копия необязательна, отставшая копия —
  `warning` (`К2`).
- **Д7 — источник по варианту (F9-068).** `variants[].source` с перечнем значений `source` слота; без поля — источник
  слота. `К6в` — схема и проверка плана, `К2` — R-MAT-008.
- **Д8 — поля арт-дирекции (F9-053, F9-117, F9-047).** `directions[].bans[]`, `directions[].notes`, поле вариантов
  подачи — форму пишет `К8а`; `К3б` читает после приёмки `К8а`.
- **Д9 — ширины проекта (OE1-22).** Строка «Условий холста» «Ширины приёмки: …» переопределяет набор базы: `К3б` —
  вход и манифест, `К11` — kit. `page_accept.py` (код-репо) строку проекта не читает.
- **Д10 — порядок кодов выхода (OE1-15).** Целевой порядок: 0 — `error` нет; 1 — есть `error`; 2 — ошибка вызова или
  окружения; особые исходы — от 3. Новый код зон волн 1–2 пишется сразу так; существующие коды меняет только `К10`.
- **Д11 — сверки арт-дирекции (F9-093).** Скрим — `vlm_to_dna.py validate --art-direction` (`К6а`); трекинг против
  каталога гарнитур — `ad_check.py` (`К8а`); роли и иконки ДС — `К9`.
- **Д12 — замеры возвращают 0 (OE3-19).** `page_accept.py` (`К5`), `gate_check.py`, `qa_pipeline.py` (`К14`): код 0
  при успешном замере, `--strict` — выход по находкам; вердикт — `page_gates.py`.
- **Д13 — свойства приёма.** Машинное поле списка свойств у приёма `effects.yaml` вносит `К8б`; сверку «свойства приёма
  на минимальном уровне разрешены уровнем или исключением» — `К8а` (`spec_check.py levels --check`).
- **Д14 — модель интерлиньяжа.** Один прогон браузером делает `К11` и отдаёт три числа; `К9` правит эталон только по
  подтверждённому итогу.
