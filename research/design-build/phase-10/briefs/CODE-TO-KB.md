# Ф10 — строки зон кода в базу знаний (общий бриф зоны «Т-код-<база>»)

Зоны кода поменяли поведение утилит, ключи схем, находки и коды. Статьи базы `kb/<база>/**/*.md`, которые это поведение
описывают, должны говорить то же, что код: по ним работает агент скилла на проекте заказчика. Готовые строки лежат в
разделах «Для текстов» отчётов зон кода. Ты вносишь их в файлы своей базы. Пиши по-русски. Пути `scripts/…`, `kb/…` —
от `.claude/skills/design-deep-dive/`; корень репозитория называет задание.

Следы исследования в статьях — буквы исполнителей, «волны», пути сырья, даты — не твоя работа: их убирает отдельная
уборка. Не трогай их, кроме случаев, названных ниже и в задании.

## Что читать
1. Этот бриф и задание зоны (срок, список отчётов).
2. Строки первой волны кода — `research/design-build/phase-10/text-zones-v2/_code-<база>.md` (если файл есть).
3. Строки следующих волн — разделы «Для текстов» отчётов, названных в задании: только строки о файлах `kb/<база>/**`.
   Раздел находишь поиском заголовка и читаешь до следующего заголовка `## `.
В остальной журнал `research/` не ходи.

## Как вносить
- Строка называет файл, место и готовый текст. Найди место — раздел, таблицу, абзац — поиском по файлу; большой файл
  целиком не читай.
- **Сверь с кодом.** Утилита, подкоманда, ключ, код находки существуют сейчас: `--help` утилиты, поиск по `scripts/`,
  значение в машинном файле. Строка отчёта разошлась с кодом — пиши по коду и назови расхождение в отчёте.
- **По месту и о текущем.** Соседние формулировки статьи не переписываются. Текст — о текущем поведении, без «теперь»,
  «раньше», «было / стало», без имён зон и номеров находок.
- **Норм не сочиняешь.** Числа, порога или правила нет ни в строке, ни в машинном файле — «не внесено: причина».
- Статья уже говорит то же — «уже так». Строка относится к файлу, которого нет, — «нет файла».
- **Замок браузера.** Команда статьи, которая оборачивает утилиту скилла во внешний `flock … browser.lock`, — обёртка
  снимается: утилиты берут замок сами, внешний замок на тот же файл вешает прогон. Объяснение рядом — одной фразой:
  утилита берёт замок браузера сама.
- **Машинный файл базы** правишь, только когда его называет строка, и только названное поле; ключи, id, числа и
  порядок записей не трогаешь. `scripts/`, `references/`, `docs/` и чужие базы не правишь: нужную там правку — в отчёт.
- Git — только чтение (`status`, `diff`, `log`, `show`). Сети, браузера, платных вызовов и субагентов нет. Временные
  файлы — в своей папке `~/.cache/design-deep-dive/out/f10/<зона>/`.

## Проверка перед сдачей
- `scripts/maint/normcheck.py --base HEAD --list-lost <изменённые md>` — числа, id, пути и метки, которых строки не
  меняли, на месте: каждая находка `НОРМА` либо исправлена, либо названа в отчёте как ожидаемая замена;
- `scripts/maint/refcheck.py <изменённые md>` — в изменённых строках новых битых ссылок нет;
- `scripts/maint/canon_check.py` и `scripts/maint/mapcheck.py kb/INDEX.md` — код 0;
- `scripts/maint/sync_check.py` — FAIL 0: статья-источник генератора изменилась — назови генератор и расхождение,
  производное руками не правь;
- изменённые машинные файлы разбираются; их читатели (поиск имени файла по `scripts/`) — самопроверки зелёные;
- `scripts/maint/accept.py --base HEAD --mask '.claude/skills/design-deep-dive/kb/<база>/*'` — следов в изменённых
  строках 0 (следы в нетронутых строках — не твои).

## Файл передачи и отчёт
С первого шага — `~/.cache/design-deep-dive/out/f10/<зона>/HANDOFF.md`: какие строки внесены, на какой остановился,
спорные места. Отчёт — `research/design-build/phase-10/reports/<зона>.md`: таблица «источник (отчёт, пункт) → файл и
место → итог (внесено / уже так / по коду иначе / не внесено: причина)»; расхождения строк с кодом; что отдать в общие
файлы; вопросы. Инструмент не дал записать отчёт — верни его текст в ответе. Ответ оркестратору — до 12 строк.
