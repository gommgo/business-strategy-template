## 3. Отступления от спецификации

1. **Объём выше ориентира.** `rules.md` — 606 строк (≈ 400–550), `SKILL.md` — 213 (≈ 150–200); правил 64 против ≈ 48
   в T4. Правила T1 4.3, T2a 4.4 и T2b 4.4 разложены по одной проверке на правило (так их проще звать id в отчёте и
   реализовать в `design_audit`), плюс списки H3 (R-REF, R-COV, R-VIS). Совпадающие проверки слиты (журнал в машинных
   файлах — одно правило, `mockup: skipped` — в R-FRESH-006, схемы text и copy deck — одно). Формат сжат: серьёзность —
   в заголовке, способ проверки — хвостом «Проверки». Решает оркестратор.
2. **«Литерал ∈ токенов» — в R-VIS (R-VIS-004), а не среди структурных правил холста** (T2b 4.4 п. 9). Так велит T4
   H3 (список `R-VIS` называет «литерал ∈ токенов»): сверка литералов артбордов — проверка результата на холсте, а её
   тип разрешает только по просьбе (cd 05/01 §7). Варианты: (а) как сделано; (б) структурно, без просьбы, как в T2b.
3. **`app-brief.yaml` «тогда и только тогда» (T2a 4.4 п. 2) разделено:** файл без поверхности кабинета — `error`
   (R-SURF-006); поверхность кабинета без брифа на вид — `hint` (R-SURF-007): на этапах `vision` … `scenarios` брифа по
   маршруту ещё нет, и `error` срабатывал бы на каждом раннем прогоне.
4. **Серьёзность покрытия по этапу.** T2a 4.4 п. 6 («план ассетов … — error при `approved` плане страницы») — `error`
   с закрытой арт-дирекции поверхности (вход `asset-plan` готов) или при входе холста страницы, до того — `hint`
   (R-COV-004); подлинность и постер 3D-слота — `error` всегда. T1 4.3 п. 5 без серьёзности: страница без плана —
   `error`, когда у страницы уже есть copy deck или файлы дизайна, иначе `hint` (R-COV-001); слот без текста — `error`,
   когда страница передана в дизайн или copy deck закрыт, иначе `warning` (R-COV-002); покрытие компонентов — `error` с
   входа `mockup` кабинета, до того `warning` (R-COV-005). Причина — в маршруте эти файлы появляются позже, чем
   закрывается их источник.
5. **R-MAT-006 — результаты проверок без строки просьбы.** T2b 4.4 п. 7 — `error`; разовая просьба заказчика законна
   (`design/README.md § Холст`, форма `ARTIFACTS.md`: «дальше — только разовые просьбы») и следа в файлах не оставляет.
   Сделано: `error`, если человек в сессии не подтвердил разовую просьбу, — аудит спрашивает одним вопросом
   (`SKILL.md` § Что делать при запуске, п. 4). Вариант: `warning` без вопроса.
6. **R-STRUCT-007 (NU-07):** `size.panel.*` обязательны у продукта с поверхностью кабинета и тогда — в одном файле с
   `breakpoint.*`; у ДС только сайта панелей нет (README дизайна: кабинет расширяет ДС `size.panel.*`). T2a 4.4 п. 7
   требует «оба в файле» без оговорки.
7. **R-COV-007 — каналы голоса против родов поверхностей** (решение оркестратора по зоне 1, вариант (а)). Сопоставление
   написано по `site/README.md § Уровень продукта` и схеме голоса: род `landing`, `site` — канал `marketing-site` с
   голосом `brand`; интерфейс (`web` рода `app`; `admin`, `desktop`, `embed`, `mobile`, `bot`) — `product-ui` с голосом
   `product` и профиль `…/voice.product.yaml` по `scope.product_voice_ref`; юридические страницы — `legal`
   (`neutral-legal`), подсказкой. Серьёзность — `warning` (T1 её не назвала). Решает оркестратор.
8. **Утилиты, которых нет в том виде, как их называет T4:** `ad_check.py FILE` — утилита проверяет примеры базы и файла
   проекта не принимает, поэтому арт-дирекция проекта — чтением по схеме (R-STRUCT-004); `tz check` — внешняя утилита
   формата DTCG (ui 14/08), в `scripts/` её нет (R-STRUCT-006); `literal_tokens`, `dc_to_html`, `copies_compare` в
   указателе `scripts/README.md` не описаны — правила их не называют и сверяют чтением (R-VIS-004, R-FRESH-005).
   `ds_build` добавлен к перечню утилит `project` аудита (он описан в указателе), чтобы назвать сборщик производных ДС
   (R-FRESH-001).
9. **Формат ответа «рубрика» у судьи.** T4 H4 — «да / нет / не уверен / не применимо»; рубрика ui 13/02 держит десять
   измерений 0–5 с якорями (cd 06/04 §6). В агенте: «формат ответа задаёт рубрика владельца», по умолчанию — ответы на
   вопросы с доказательством, балл и профиль считает код того, кто позвал (`judge.md` §2–§3).
10. **Описание `design-audit`** — черновик T4 §4.2 плюс «по разрешению» и «без `<project-slug>` — пикер по проектам»
    (как у соседних аудитов): 523 знака. Описания агентов — черновики T4 дословно (258 и 257).
11. **Frontmatter агентов сверен с документацией** (https://code.claude.com/docs/en/sub-agents, раздел «Frontmatter
    reference»; https://code.claude.com/docs/en/tools-reference, «Glob tool behavior»), все ключи T4 подтвердились: `name`, `description` обязательны; `tools` —
    строка через запятую; `model` — полный id `claude-opus-5-5` (алиас `opus` разрешается в модель основной сессии того
    же семейства — полный id явнее, как требует решение «модель явно»); `omitClaudeMd: true` — запуск без `CLAUDE.md`,
    нужен Claude Code v2.1.271 или новее (старая версия молча пропускает неизвестный ключ — судья получил бы
    `CLAUDE.md`); `Glob` и `Grep` на Linux и macOS по умолчанию выключены, но возвращаются субагенту, который называет их
    в `tools` без `Bash`. Замен ключей не понадобилось; `effort` не задан (T4).

## 4. Для следующих зон

- **Z7b (`screen-audit`, `screen-deep-dive`).** Проверка метафоры пустого состояния по списку паспорта — здесь
  (R-REF-007, R-SEM-004); `screen-audit` проверяет форму атрибута `illustration` у `ui:EmptyState`, а не список
  паспорта. Аудит читает деревья `ui:` stable-экранов (R-COV-005), роли строк `texts.md` (R-COV-006) и статусы
  экранов и свода `map.md` (R-MAT-011) — только чтением; находки ведут к `/screen-deep-dive`.
- **Z8 (`entrypoint`, `/cross-audit`, клиентский оркестратор).** Строки «Выбор аудита» `routing.md`:
  `/design-audit <slug>` — структура, `/design-audit <slug> --visual` — макет по разрешению заказчика. Отчёт аудита —
  `.claude/skills/design-audit/audit-state/<project-slug>/last-report.md`, вне дерева state. Аудит читает заметки
  пропусков `<state>/site/<surface>/_phase-jump.md`, `<state>/design/_phase-jump.md`,
  `<state>/design/<surface>/_phase-jump.md` и `**blocker**` веток `site/`, `design/` — `state-model.md` держит эти
  имена. «Границы» `/cross-audit`: покрытие слотов текстами, фактами и ассетами и структура фактов
  (`claims_check.py lint-facts`) — в `/design-audit`; угол `surface-design` читает тот же признак принятого макета
  (`accepted`, `accepted_with_notes` с совпавшим отпечатком — R-MAT-004, R-FRESH-006).
- **Z9 (описания).** `design-audit` — 523 знака; описания агентов в листинг скиллов не входят (у агентов свой предел
  описаний).
- **Оркестратор.** Папка `.claude/agents/` новая: по документации Claude Code наблюдение за папкой агентов охватывает
  только папки, которые были при старте сессии, — в текущей сессии агентов подхватит перезапуск, новые сессии видят их
  сразу.

  `canvas_input` (проверка) — R-FRESH-002 … 004; `ready --check` — R-FRESH-006; `ds_build` — R-FRESH-001; режим
