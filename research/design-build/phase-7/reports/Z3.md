## 3. Отступления от спецификации

1. **Потребитель FSD-карты — только `<org>/frontend`.** Спецификация просила строку «не для рода `landing`, `site`»; абзац
   README «Потребители слоя — `<org>/frontend` и `<org>/site`» после B8 стал бы ложным в том же файле — переписан: код
   сайта FSD-карту не читает. Строки с путями соседнего репозитория (`docs/stack/service.md`) оставлены как были.
2. **Числа норм.** `root` ↔ ux 02/02 §1.6 — названы строки таблицы выбора («Нижняя панель», «Drawer», «Навигационный
   хаб») и критерии выбора, без «3–5» и «6 и больше» из T3 (правило COMMON «числа — адресом», как у Z2). Порог
   `escalate` — «после трёх неудачных попыток» — записан один раз, в README бота § Путь к человеку, с адресом нормы: это
   определение поля контракта, которое читает код, а машинного файла у нормы нет; форма окна ссылается на README.
   Варианты: (а) так; (б) и порог — только адресом (ux 13/03 §16.2).
3. **ST-14 без новой колонки.** «Где видны статусы отложенных правок при `full`» — строка-заготовка «Отложенные правки:
   …» под таблицей § Offline и критерий 3, а не колонка таблицы: колонки форм mobile — контракт с `<org>/mobile`, и по
   аналогии с ST-07 новую колонку я не заводил. Вариант (б) — колонка в таблице Offline по договорённости с
   `<org>/mobile`.
4. **S17 `timeout` у бота** — исходом use-case бота, как S19–S21 (T3 его не называет, 05-ST §1.2 — «ключа нет»).
5. **Сценарии данных mobile.** `error` приложения — имя контракта, у веба — `error-load`; фраза «имена едины с код-репо
   и web-поверхностью» заменена явным соответствием. Новые сценарии mobile (`loading-initial`, `partial-few`,
   `overflow-many`, `no-permission`) названы ключами словаря, как у FSD, хотя ключ состояния экрана mobile для S18 —
   `permission-denied`.
6. **Роли, которых спецификация не называла.** mobile: `rationale` — `body`; `response` системного действия — `toast`
   (ответ ассистента) или `push`; оверлеи — `banner` и `title` + `body` + `action`; тексты состояний — по правилу
   README экранов. Бот: подписи виджетов — через `components.yaml` (`crosswalk.bot_widgets` → `text_roles`): `button` —
   `action`, `url` — `link`, `select` — `label`, `multiselect` — `checkbox-label`.
7. **Смысл `fallback` у бота сужен, ключ не переименован.** `fallback` ключа-коллекции описывал и пустоту; пустоту
   теперь несёт `empty`, `fallback` — только отказ источника (ST-24). Код `<org>/<bot>` должен знать оба ключа.
8. **Исход «передано человеку»** — словами в `### Outputs` и строкой `### Errors`, а не новым канон-ключом исхода: новые
   ключи бота по T3 §6 — только `empty` и `escalate`.
9. **Серьёзность `empty` у mobile** — error, как у соседнего правила «экран с сетью без `loading` и `error`»; у экранов
   веба непокрытое обязательное — warning, error у `stable`. Решает Z7b в `mobile-audit`.
10. **Проход шире «craft»** в `mobile/_template/widgets.md`: «компонент дизайн-системы код-репо» → «компонент ДС
    продукта; его код — в код-репо».
11. **Объём** — +448 / −83 строк против плана ≈ 115–200: таблицы соответствия (ключи экрана и виджета mobile, поля окна
    бота — по 24 id), таблицы «поле → роль», таблица типов экрана mobile.
