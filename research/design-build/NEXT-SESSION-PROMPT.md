Продолжаем развитие шаблона business-strategy-template после версии 0.1.0. Журнал сборки скилла design-deep-dive
вынесен из основной ветки; его архив — тег `archive/design-build-journal`. Этот файл лежит в архиве: его читают, когда
берутся за уборку текстов базы — первый пункт `ROADMAP.md`.

Первой строкой — ветка и модель (нужна Claude Opus 5.5).

Слова заказчика, которые действуют: решения по ходу работы отданы оркестратору (Р245), заказчику — коротко, что
сделано и куда идём, по канону `.claude/rules/guiding.md`; агенты читают базу знаний на всём протяжении этапа (Р256),
счётчиков чтения базы не делать; упавшего агента возобновлять тем же агентом; `claude -p` не использовать; `origin`
(git.stit.tech) — только по строке подтверждения заказчика; данных клиентов в журнале и шаблоне нет; `--no-verify` не
использовать.

Как начать уборку текстов базы:
1. В основной ветке: `git worktree add ../design-build-journal archive/design-build-journal` — архив журнала рядом,
   только для чтения.
2. Из архива прочитать: `STATE.md` (шапка «Как продолжать после версии»), `DECISIONS.md` Р244–Р262,
   `phase-10/TEXT-PLAN.md`, `phase-10/text-zones-v2/_zones.tsv`, брифы `phase-10/briefs/TEXTS-F10.md` и
   `TEXT-ZONE-TASK.md`, отчёт пробы `phase-10/reports/T-cd-1.md`.
3. Списки зон пересобрать на текущей основной ветке (`phase-10/tools/recut_text_zones.py`, счётчик `tools/kbscan.py`):
   после версии статьи уже правились — строки зон кода и часть следов внесены.
4. Вместе с уборкой — снятие `99-raw`, `PLAN.md` баз, журнала испытания витрины, версий v0; копии в
   `kb/common/canon.tsv` правятся в самой таблице (`scripts/maint/canon_check.py`); раздел «Состояние базы» скилла
   снимается последним.
5. Приёмка — `scripts/maint/accept.py`, `normcheck.py`, `canon_check.py`, `mapcheck.py`, полный смоук; новая версия —
   файл `.claude/skills/design-deep-dive/VERSION` и тег.
