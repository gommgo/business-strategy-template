## 3. Отступления от плана и спецификации

- **Реестр — цепочкой на картинку, а не «либо колонка, либо таблица».** К3 говорит «из колонки, а без неё — из
  „Загрузок“». У пилота колонка «id загрузки» есть, но заполнена у части строк, поэтому таблица читается и при
  колонке: id не нашёлся в списке — ищется в `ARTIFACTS.md`.
- **Ключ `--uploads` и поиск файла.** Без ключа `ARTIFACTS.md` ищется в папках выше списка `--assets` (до шести
  уровней): прежняя командная строка этапа проверок работает без правки текстов. Путь использованного реестра — в
  отчёте, `inputs.uploads`.
- **Тяжести новых исходов — мой выбор.** Загрузка вне реестра и загрузка не из списка страницы — `major` (как прежнее
  «картинки нет в списке ассетов»); реестра нет вовсе — одна `minor` на прогон (ошибка вызова, а не дефект макета);
  общий ассет продукта — `info`. Решает оркестратор.
- **Прочерк в ячейке — «сверять не с чем».** Раньше строка таблицы с «—» в колонке alt сравнивалась бы с прочерком
  буквально; на деле до правки строки для загрузок не находились, так что случай стал достижим только сейчас. alt на
  артборде при пустом alt в списке находкой не считается — так же ведёт себя ветка YAML. Строже («alt, которого нет в
  списке, — выдумка») — отдельное правило, в окне не делал.
- **LOOK-THREE-CARDS: ряд с заглушкой не мерится целиком.** Вариант «мерить вариацию по тексту без заглушек» отклонил:
  у демо-карточек остаток — пара одинаковых слов, и примета срабатывала бы снова.
- **`[data-wf]` исключён из всех проверок страницы**, а не только из сверки текстов: ярлыки давали ещё и числа
  (пропорции «4:5»), мета-строки «·» и наложение на текст.
- **`h1_count` у части ≥ 2 — «ровно ноль», а не пропуск.** H1 во второй части — второй H1 страницы.
- **`shot.py` импортирует правило имени части из `mockup_checks.py`** (`kbpaths.use('claude-design')`), чтобы правило
  жило в одном месте. Цена — `kit/shot.py` и `kit/export.py` теперь зависят от соседнего модуля.
- **У `shot.py` появилась `--selftest`** (её не было): без неё правки шрифтов, частей и манифеста проверялись бы
  только браузером. Строка смоука — раздел «Для смоука».
- **Hero: сначала блок верхнего уровня, секция — только сквозь обёртку.** Правило «ближайшая секция с H1» уменьшило
  бы hero у собранной страницы с вложенными секциями (H1 во внутренней `section`) и спрятало бы настоящую примету;
  поэтому прежний результат сохранён везде, где блок верхнего уровня сам секция, а спуск к секции идёт только из
  обёртки. Страница, целиком завёрнутая в `<section>`, ведёт себя как раньше.
- **LOOK-HERO-CENTER на `Home-1440` пилота остался** (`minor`, одиночная примета): hero там — `section#hero` 900 px
  при окне 900, текст по центру, продолжения не видно. Это настоящая примета, и прежняя версия называла тот же
  элемент: у копий макета есть `<main>`. Ложный случай — копия без `<main>` — показан на `Dir-D-1440` и синтетике.

## 4. Для следующих зон

- **Часть артборда (текст протокола — Z8, совпадает).** Имя — `<Имя>-<ширина>-<N>`, `N` с единицы, `<ширина>` равна ширине
  рамки (`Home-390-1`, `Home-390-2`). Код читает имя исходника из строки происхождения копии (`mockup_checks`) или
  поле `artboard` манифеста `kit.json` (`shot.py`). Шапка с навигацией и H1 — в первой части. Число в имени
  страницы номером части не считается (`Flat-204-1440` при рамке 1440 — артборд целиком).
- **Ярлык вайрфрейма (К4).** Код читает наличие атрибута `data-wf` у элемента; значение не разбирается. Исключается
  элемент вместе с поддеревом: в `mockup_checks` — из всех проверок страницы, в `dc_texts` — из единиц текста.
  Ярлык внутри текстового элемента (`<p>…<span data-wf>`) `dc_texts` вырезает; `mockup_checks` в сверке блоков с copy
  deck его не вырезает (блок берётся целиком) — ярлык ставить отдельным элементом.
- **Реестр загрузок.** `assets.md`: колонки «файл» (значение — первые обратные кавычки ячейки), «слот» (то же), «id
  загрузки» (один или несколько id); строка «placeholder · TODO» — пустой слот. `ARTIFACTS.md`: таблица с колонками
  `id` и «файл…», «слот», «артефакт» читаются по именам, порядок и лишние колонки не важны. Правки Z1 (строка на
  вариант, демо, общие ассеты `_assets/…`) разбор читает без изменений — проверено чтением её текущего кода.
- **Отчёт `page --json`:** новые поля `artboard`, `part`, `inputs.uploads`; у находки HON-CAPTION о загрузке —
  `evidence.upload` `{file, slot, artifact}`. `design_audit visual` правок не требует (самопроверка проходит).
