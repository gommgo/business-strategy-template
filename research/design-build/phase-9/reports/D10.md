## 3. Отступления от плана и спецификации
- **`dc_to_html check`: HTML без строки происхождения в `canvas/html/` — R-FRESH-005 `warning`.** Раньше такой файл считался
  адаптивной копией и находкой не был. Адаптивной копии больше нет: в папке копий такой файл — остаток (прежняя
  адаптивная копия) или чужой файл; доклад с советом «убрать; нужная ширина или состояние — артбордом на холсте», этап
  не держит. Вариант — молча пропускать; выбрал доклад (урок Ф8 о тихих пропусках). В `design_audit` доходит только
  при строке «Проверки макета: разрешены». Текстовая зона уже описала его в указателе.
- **Форма `kit.json` упрощена сильнее, чем «без адаптивных кадров».** Кадр несёт `artboard` и `stage` (раньше — в
  отдельном `copies.static`); поля, нужные только адаптивной копии (`themes`, `breakpoints`, `first_breakpoint`,
  `by_viewport`, `overflow_only`, `artboard_widths`, `kind`, `check`), сняты; `widths` — ширины артбордов (ряды холста).
  Манифест больше не читает токены ДС: правка токенов не делает `kit.json` устаревшим. Потребителей снятых полей в
  коде нет (поиск по `scripts/`). «× темы» брифа — тема каждой копии по её твикам: у статичной копии тема запечена.
- **`kit/shot.py` — снят режим `--widths acceptance` и `--first-bp`.** Режим раскладывал копию по всем ширинам приёмки и
  вылету — это имело смысл только для адаптивной страницы; статичная копия фиксированной ширины на чужой ширине даёт
  ложный вылет. Собранную страницу по ширинам снимают ворота после сборки (`ui_audit.py --acceptance`,
  `page_accept.py --acceptance`).
- **`canvas_input`: новый пункт D5** (вылет 0 на 320, «после сборки», общий для сайта и кабинета; у кабинета — экраны
  классов mobile и any, источник — `acceptance-widths.yaml#overflow_only; ux 08/01 §3.2; ui_audit.py --acceptance`). Бриф
  перечисляет «вылет на 320» среди пунктов адаптивной копии, но отдельного пункта не было: вылет на 320 сидел в D1
  сайта вместе с вылетом на артбордах. D1 разделён: вылет на артбордах всех ширин — «макет» (этап `wireframe`), 320 —
  D5 «после сборки». Вариант — перенести весь D1 «после сборки» (тогда вылет артбордов не проверялся бы на холсте).
  V1 получил приписку «на холсте тёмная тема — твиком», когда тёмная тема есть в ДС; шапка «Где» — «макет» проверяется
  на холсте, способ «скрипт» — на статичных копиях артбордов по просьбе заказчика.
- **`ready`: `canvas.json` в источники пакета не входит.** «Исходники холста и принятые артборды» прочитаны как `.dc.html`
  артбордов строк «Приёмка» с принятым вердиктом (все ширины единицы) и их статичные копии, если собраны; `canvas.json`
  меняется от любой перестановки на холсте и делал бы манифест устаревшим (R-FRESH-006 `error`) без правки принятых
  артбордов. Имя артборда из `REVIEW.md` — только имя файла `*.dc.html` (путь с каталогами пропускается). Вариант —
  добавить `canvas.json` (решает оркестратор).
- **`mockup_checks resize`: окна по умолчанию — из данных, а не `artboards[0]`/`artboards[-1]`.** При шести артбордах
  последний — 360, а норма H5 — «1440 → 390 → 1440»: `resize_windows()` берёт самую широкую ширину приёмки и самую
  широкую ниже первого брейкпоинта эталона ui (640) — 1440x900 и 390x844, как было.
- `acceptance-widths.yaml`: к комментарию `by_viewport` добавлено «артборды экрана — ширины его класса, вылет на 320 — на
  сборке» (вход холста строит таблицу артбордов по классу).
