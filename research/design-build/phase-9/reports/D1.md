## 3. Отступления от плана и спецификации

1. **«Токенов ДС нет» — проверка новая.** Таблица плана §4 пишет её в «остаётся `error`», но в коде такой проверки не
   было (у сайта — только «ДС не утверждена (нет design/system.yaml)»). Сделано: `ds_gate` на макете — `R-MAT-012
   error`, если нет ни `system.tokens.css`, ни `system.tokens.json`, ни `tokens.json` артефакта ДС. Следствие: у
   `input-site` (в фикстуре ДС нет совсем) на макете 17 `error`, а не ≈ 16, с `--page home` — 3, а не 2 (разбор — §5).
   Варианты: (а) так; (б) без этой проверки — у сайта без ДС на макете только `warning`. Решает оркестратор;
   предлагаю (а).
2. **Форма карты решений и расширения (`map_checks`) — `error` только когда кабинет продукта на макете**, иначе
   `warning` (было — `error` всегда, так пишет и реестр R-COV-005). Основание — план: «`error` только у поверхности
   кабинета на макете… формы и расширения», «у сайта — `warning` всегда». Тяжесть считается по всем поверхностям
   продукта, а не по охвату вызова: `design_audit` зовёт `coverage` по поверхности, и одна находка карты решений с
   разной тяжестью схлопнулась бы в `Report` по первой. Альтернатива — оставить форму и расширения `error` всегда.
3. **Этап `directions`** — партия из первой страницы (по умолчанию главной): источники входа — её план (раньше — планы
   всех страниц), `ACCEPTANCE.md` — по ней. Файлы входа те же.
4. **Кабинет без ключа:** `brief.yaml#product.screens` — экраны партии (все экраны поверхности), раньше — только stable;
   на фикстурах (все экраны stable) вывод тот же. Экран draft теперь во входе — с R-MAT-011 `warning`.
5. **Вне зоны осталась одна `error` PRE:** `demo_data.py` (файл не в зонах ДФ9) держит R-MAT-011 PRE-14 `error` в своём
   `demo_data check` и в поле `gaps` документа `demo-data.json`; контракт и вход понижают её до `warning`. Правка —
   тяжесть в двух вызовах `rep.add` функции `demo_data.gaps` и её самопроверка; решает оркестратор (или Ф10).
6. **`R-STRUCT-006` `ds_build` внутри проверки входа кабинета не тронут** (`error` — токены не разбираются: целостность
   входа); понижен только R-FRESH-001, как в таблице.
7. **Строка «вне партии»** перечисляет все единицы вне партии, без хвоста «и ещё N» — исполнителю нужны точные id.
   Подсказка R-COV-001 «страница без плана» остаётся при любой партии (это не единица входа); «план вне карты» —
   только у страниц партии.
8. **`--page`/`--screen` без поверхности** — ошибка вызова (код 2), в том числе у `check`.

## 4. Для следующих зон

### Партия входа холста (D2, D8, D9)

- Вызов: `canvas_input build <slug> <surface> --stage … [--page ID[,ID…] | --screen SLUG[,…]]`,
  `canvas_input check <slug> <surface> [--page … | --screen …] [--stage …]`. Код 2 (сообщение с перечнем единиц): ключ
  без поверхности, оба ключа сразу, `--page` у кабинета или `--screen` у сайта, пустой список, id вне единиц
  поверхности.
- Единицы: у сайта — страницы с планом (`page.id` плана) в порядке входа (лендинг — список брифа, главная первой; род
  `site` — `build_order` карты; планы вне списка — в конце); у кабинета — все экраны `screens/<surface>/screens/*`
  (любой статус), по slug. Партия идёт в порядке единиц, а не ключа. Этап `directions` — первая единица партии.
- Без ключа: `build` — все единицы; `check` — `units` передней части действующего `INPUT.md` (нет поля или входа —
  все единицы); id прежней партии, которых нет среди единиц, — пробел «единиц партии входа нет среди единиц
  поверхности: … — вход устарел» (и R-FRESH-002 по пропавшему источнику); у сайта, если из партии не осталось ни
  одной страницы, — R-MAT-012 `error` «страниц партии нет среди страниц с планом» с советом собрать вход `--page`.
- `INPUT.md`: передняя часть — ключи по порядку `stage, project, surface, route, units, built_by, check, files,
  manifest`; `units` — список строк (id единиц партии). Тело: после первого абзаца — «Партия входа: a, b (все единицы
  поверхности).» или «Партия входа: a — остальные единицы в «Пробелах».»; первая строка «Пробелов» —
  «вне партии: id[ (статус)], … — во входе этих страниц|экранов нет; их вход — build --page|--screen <id>» (статус — у
  экрана не stable); строка вызова и советы свежести (`R-FRESH-002/003/004`) — с ` --page a,b` / ` --screen a,b`, когда
  партия — часть единиц.
- Сайт: `pages/<id>/` — только страницы партии; `build` в репозиторий снимает папки остальных, `--out` — нет.
- Кабинет: `contract.md` — разделы экранов партии и строка «Экраны партии: …; вне партии — …» (без партии — прежний
  текст); раздел «Тексты», находка статуса строк (R-MAT-003 → R-MAT-012 на макете) и `copy.md` — ключи
  `contract.batch_scope(lay, trees, screens)["keys"]` (экран, блоки состава с вложенными, каркас экрана); `demo-data.json`
  — `contract.demo_part` (коллекции экранов партии, объекты экранов и коллекций с целями `ref:`; `gaps`, `sources` — их);
  `ACCEPTANCE.md` — ST-пункты и таблица кадров по классу — экраны партии; `brief.yaml#product.screens` — экраны партии;
  `ds_coverage` — типы stable-экранов партии. Без партии (все экраны) контракт, `copy.md` и демо-набор — прежние: весь
  реестр текстов и весь набор.
- `ACCEPTANCE.md`: строка «Партия входа (страницы|экраны): a, b.» после шапки.
- Python: `assemble(slug, surf, repo, stage, maps, today=None, units=None, strict=False)` → сборка (`files`, `rep`,
  `units`, `outside`, `batch_arg()`); `check_surface(slug, surf, repo, stage, maps, today=None, units=None, strict=False)`
  → (находки, сборка); `design_audit.fresh_input` зовёт как раньше (`units=None` → партия из `INPUT.md`).
- Для R-COV-002 (D2): партия текущего входа — `read_manifest(<input>/INPUT.md)[0].get("units")` (список) или папки
  `pages/<id>/`.

### Источники единицы и отпечаток одобрения (D2)

- `canvas_input.unit_sources(slug, surface, unit, repo=None)` → список `{"id", "path", "fingerprint"}`, отсортирован по
  `(id, path)`; `None` — единицы нет (у сайта нет плана с `page.id == unit`, у кабинета нет папки экрана). `surface` —
  slug поверхности, `repo` — корень данных (как `--repo`; `None` — `$DDD_REPO` или репозиторий скилла); нет проекта или
  поверхности — `docpaths.DocPathError`; поверхность не сайт и не кабинет — `None`. `path` — от корня данных
  (`docs/projects/<slug>/…`). Отпечаток — `sha256:<hex>` файла, если не сказано иное; `—` — названного источника нет на
  месте. Карт `x-canvas-map` функция не грузит; ~0,02–0,1 с на вызов.
- Страница сайта: `page-plan` (файл плана); `copy-deck` — `text_hash:` только этой страницы
  (`deck_text_hash(data, page=unit)`: `lang`, статус и `cta_primary` страницы, по слотам — секция, слот, тип, `asset_ref`,
  статус и текст выбранного варианта; записи проверок и заметки не входят; нет страницы в copy deck — строки нет);
  `asset-plan` (план ассетов: `refs.asset_plan` плана или `design/<s>/assets/plans/<id>.yaml`); `asset · <slot>` — файл
