## 3. Отступления от плана и спецификации

- **Запреты направления — расширение `x-direction-bans`, а не поле направления.** У `$defs/direction` схемы
  арт-дирекции `additionalProperties: false` и поля запретов нет, а зоне отдан только ключ `x-canvas-map`. Источник —
  расширение верхнего уровня документа (схема его пропускает), читает его обработчик, карта называет его в `note`.
  Вариант — поле `bans` в `$defs/direction`: правка схемы вне зоны. Решает оркестратор.
- **`x-demo` — тоже расширение.** Схема плана ассетов (ai-media) вне зоны; у слота плана `^x-` разрешён. Канон описан
  в README § Ассеты, читает его вход. Поля в схеме и проверки в `plan_to_assets check` нет.
- **Формат на холст — порядок в коде** (`FORMAT_ORDER`: svg, webp, png, jpg, avif, gif, mp4, webm; у роликов — H.264).
  К1 называет «`status: accepted` → `variant` → `format`», порядок форматов не задан. Взят тот, каким на пилоте шли
  загрузки. Несколько файлов одного варианта и формата идут все (светлый и тёмный знак).
- **Строка манифеста без `status` — не принята.** На холст идёт только `accepted`: строка без статуса даёт заглушку.
- **Строка без `page` — общая для страниц без своих строк** (так же прочитала зона Z2): у страницы со своими строками
  общие не берутся.
- **id загрузки — строка холста поверхности.** Файл, загруженный и в артефакт ДС, и в холст, имеет два id; вход берёт
  строку `canvas:<surface>`, строку ДС — когда другой нет, холст другой поверхности не читает. Без этого порядок строк
  таблицы решал, какой id попадёт во вход.
- **R-REF-008 — одна находка на файл**, а не на страницу: общий файл страниц иначе давал бы находку у каждой.
- **Кабинет.** `app_assets_md()` перешёл на то же правило выбора (принятое, вариант, формат): `asset_manifest` стал
  списком строк. Вход кабинета на фикстурах байт в байт прежний.

## 4. Для следующих зон (стыки)

- **К1 — манифест ассетов поверхности.** Вход читает `slot`, `page` (необязательное, id страницы плана ассетов), `file`
  (путь от папки манифеста), `status`, `variant` (id варианта плана; `desktop+mobile` — файл на оба), `format` (без
  поля — расширение файла), `codec`, `license`, `origin` или `provenance`. Выбор — `slot_files(rows, slot, page)`.
- **К2 — «Загрузки».** Колонки по именам: `id`, `файл`, `sha256`, `слот`, `артефакт`. Вход читает `id`, `файл`,
  `артефакт`; `sha256` не читает (сверка — R-FRESH-007 зоны Z2).
- **К3 — `assets.md` страницы.** Колонки и их имена прежние. Ячейка «файл»: `` `<путь>` `` — файл слота от папки
  ассетов поверхности, `` `_assets/<путь>` `` — общий ассет продукта, путь вне git — демо; «placeholder · TODO» —
  пустой слот. «слот» у общего ассета — `` `<слот>` (общий ассет продукта) ``. «источник и лицензия» у демо начинается
  с «демо · файл вне git, в публикацию не идёт». «id загрузки» — один id или «—».
- **Источники единицы.** `unit_sources` и `unit_fingerprint` — сигнатуры прежние; состав строк `asset · <слот>` — в
  разделе «Для пилота».
- **Новый источник входа макета** — `product-assets` (`design/_assets/manifest.yaml`), строкой в «Источниках»
  `INPUT.md`, когда файл есть.
