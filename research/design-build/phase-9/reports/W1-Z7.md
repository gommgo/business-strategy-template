## 3. Отступления от плана и находок

1. **F9-054 — `edit-real` при `real-only` каркас пишет как `real`, а не как «отдельный способ без `forbidden`».** Предложение
   находки — оставить `edit-real` и снять `forbidden`. Сделано иначе, потому что `real-only` — норма подлинности
   (site 08/02 §2.1, ai-media 12/04 §2, строки 9, 10, 14): модель не трогает то, что обязано остаться настоящим, а
   доводку без генерации (кадрирование, цвет, апскейл) схема плана сегодня выражает только как `real`. Так же записаны
   эти слоты в утверждённых планах пилота — они проходят проверку без изменений. Вариант «`edit-real` + `conditional`
   при `real-only`» ослабил бы умолчание каркаса и потребовал бы править правило R-COV-004 и описание схемы; он
   естественно приходит вместе с полем `local_edit` — в Ф10. Решает оркестратор.
2. **F9-058 — условие «арт-дирекция утверждена» из тяжести снято.** По находке и заданию `error` — только у страниц
   партии входа; раньше `error` давала и утверждённая арт-дирекция без входа. Теперь до входа холста — `hint`.
   Текст правила в `rules.md` описывает прежнюю тяжесть — строка в «Для текстов».
3. **F9-129 — сверх двух пунктов разбора.** (а) `find_by_id` пропускает запись операции с id исходника — тот же дефект
   через `download` и `status`; (б) копия исходника с именем операции снимается — файл 720p с именем `…upscale_1080p…`
   сошёл бы за результат; (в) `ledger --ops` — сверка записей без сети: без неё «разбор сохранённого ответа без
   `--live`» из колонки проверки и сверка журнала пилота делались бы разовым скриптом; команда ничего не пишет;
   (г) подкоманда `selftest` — у `polza.py` самопроверки не было. Сверка цены ответа с ценой исходника — эвристика:
   живого ответа синхронной операции с ценой нет (запрет трат), формы ответа взяты из сохранённого паспорта и базы.
4. **F9-130 — проверка обязательных файлов строже прежней.** Раньше ответ с ошибкой HTTP сохранялся как файл снимка;
   теперь у двух обязательных файлов это отказ снимка, у вспомогательных (`…catalog.*.json`, `openapi.json`) — как
   раньше: файл и статус в метаданных. Порог возраста не введён: строка печатается всегда, отметка — по норме «снимок
   за сегодня», которая уже записана в базе.
5. **F9-076 — паспорт отказа пишется при любом коде 4 клиента**, не только у пустого ответа RouterAI: причина та же.
6. **Тест `scripts/ai-media/tests/test_prompt_compile.py`** правлен, хотя в списке файлов зоны его нет: это тесты
   компилятора (строки смоука `--only prompt_compile`), у `prompt_compile.py` своей самопроверки нет.
7. **Живой путь `snapshot` не прогонялся** — сеть в задании запрещена; логика проверена подменой `get` в самопроверке.
   Оркестратору на приёмке: `polza_catalog.py snapshot --root <временная папка>` (бесплатный GET без ключа).

## 4. Для следующих зон

- **Запись невыполненной операции в журнале трат**: `{"event": "failed", "uid", "id", "cost_rub": 0.0,
  "estimate_rub", "error": {"code": "OPERATION_NOT_APPLIED", "message"}, "passport", "base_url"}`. Сводки `polza.py` и
  `mp_client.py` считают её в 0 ₽ без правок (`failed` → `cost_rub`).
- **Паспорт операции** (`polza-passport/1`): новые поля `response_operation`, `outcome` (`applied`, `own_record`,
  `code`, `cost_rub`, `same_as`, `removed_copies`); `cost.usage_cost_rub` — цена операции (0.0 — не выполнена, `null`
  — цены в ответе нет).
- **Паспорт отказа канала** (`mp-passport/1`): `status`, `error`, `response` (`http_status`, `headers`, `bytes`,
  `sha256`, `body`), `files: []`; читатели паспортов (`asset_audit.py`, `stand_run.py`, `provenance_check.py`) идут по
  `files[]` — пустой список им не мешает.
- **`plan_to_assets.py check <slug> [<surface>] [--page ID …]`** — контракт находок и вызов без `--page` прежние
  (`design_audit.py` зовёт без ключа). Тяжесть «нет плана ассетов»: `error` — страница в партии входа, иначе `hint`.
- **`polza_catalog.age_note(name, fetched_at, complete, refresh, now)` и `snapshot_note(snap, now)`** → (строка,
  отметка) — для любой утилиты, которая считает цену по снимку.
- **`ROUTERAI_CATALOG`** — снимок каталога RouterAI для компилятора (имя папки или путь), по образцу `POLZA_CATALOG`.

## Для пилота

**Журнал трат.** Руками журнал не править: он только дописывается, сводка берёт последнее событие задания.

1. Состояние сейчас: у записи операции апскейла последним стоит событие координатора `completed` с `cost_rub: 0.0` —
   сводка считает операцию в 0 ₽, фантомных 45 ₽ в сумме нет. Проверка утилитой, без сети и записи:
   `polza.py ledger --ops --ledger ~/.cache/design-deep-dive/out/ai-media/_ledger-P2.jsonl` — строка «не выполнена —
   канал вернул исходник (тот же id и тот же файл); в журнале 0,00 ₽», код 0.
2. Сверка с балансом (бесплатные GET, ключ исполнителя): `polza.py balance --live` → `available`;
   `polza.py ledger --sum --ledger <тот же журнал>` → «потрачено» по `https://polza.ai/api`. Баланс на старте пилота
   плюс пополнения минус `available` должен равняться сумме журнала по этой базе (в неё входят и задания `mp_client.py`
   каналов polza-chat и polza-images). Сошлось — править нечего.
3. Не сошлось ровно на цену генерации-исходника — значит, сводка считает операцию оплаченной: `ledger --ops` покажет
   её строкой «✗ … за невыполненную операцию должно быть 0 ₽» и кодом 1. Поправка — одно дописанное событие той же
   формы, какую теперь пишет сам `ops` (§4, первая строка), с `uid` этой операции. На журнале пилота это не нужно.
4. Файл `…-upscale_1080p__….mp4` рядом с исходником в выходах генерации — копия ролика 720p (тот же sha256), а не
   1080p: в ассеты он идти не должен. Новая версия такую копию снимает сама; старую исполнитель удаляет после сверки
   `ffprobe` (это кэш, не проект).
5. Апскейл этого ролика — заново, после слияния: `ops` теперь сам скажет, выполнена ли операция, и не запишет чужую
   цену; запасной путь маршрута `VID-UPSCALE` — в `routing.yaml`.
