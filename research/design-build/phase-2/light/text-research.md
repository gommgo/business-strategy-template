### 3.4. `measurements.tsv`: что это и нужен ли

- **Что.** Длинный формат `page_id, group, lang, genre, page_type, scope, metric, value`: 30 045 строк данных, шапка и строка-комментарий
  с версиями `copy_metrics 0.3.2`, `copy_lint 0.9.2 / 0.9.3`, «правил 336». 2,27 МБ, ≈ 1,19 млн ток. — 39 % переносимого text.
  - Группы: ru-mid 6 122, en-lead 5 349, ru-lead 4 995, en-mid 3 546, ai-self 2 975, ai-sulat 2 920, ai-k3 2 158, ru-mid-2021 1 083,
    ai-guided 582, en-mid-2021 315.
  - `scope`: page, hero, prose, structure, claims, meta, cta и 44 значения `slot:*`.
- **«K3».** 3 282 строки = группа `ai-k3` (2 158; «витрина K3») + страницы `as-k3-*` группы `ai-sulat` (1 124). Это метки групп сравнения
  «живой ИИ EN», а не интеграция с Kimi.
- **Кто пишет и читает.** Пишет `copy_metrics.py` (`--out measurements.tsv`). Читают только скрипты опытов: `D/03-measure/{analyze.py, write_thresholds.py,
  cta_pairs.py, run_final.sh}`, `D/05-why-markers/prose_vs_page.py`, `E/03-page-type-profile/profile.py`, `G/02-articles-geo/run.py`
  (grep `*.py`, `*.sh` по всему app-design). `write_thresholds.py` берёт из неё версии (первую строку).
  - Цепочка: `measurements.tsv` → `analyze.py` → `thresholds_draft.json` → `write_thresholds.py` → `thresholds.yaml`.
  - Рабочие утилиты читают `thresholds.yaml`, не замер: `copy_lint.py` — `THRESHOLDS_PATH`; `build_copy_slots.py` — через `E/01 lengths-final.json`.
- **Ссылки из содержимого:** README, README папки 03, `03/01–03`, `04/03`, `07/03`, шапка и поле `source` в `thresholds.yaml`. Это описание происхождения
  чисел.
- **Нужен ли (вывод):**
  - для работы достаточно `thresholds.yaml` и длин в `copy-slots.yaml`;
  - замер нужен, только чтобы пересчитать пороги по другому правилу без повторного обхода страниц;
  - перезамер новой версией линтера всё равно требует страниц корпуса `99-raw/cache/corpus-D/` — это копии чужих текстов, по п. 17 «только в cache»;
  - «частью» (только лидеры, ≈ 10,3 тыс. строк) не работает: error выводится из p98 людей (лидеры + средний рынок) и нижнего дециля ИИ, то есть нужны все группы.

**Жанры.**
- Жанров шесть — `landing`, `site-page`, `article`, `meta`, `geo`, `email-form`. Они зашиты в код: `GENRES` в `copy_lint.py:63` и

- Уровень находки уточняется по цепочке:
  1. `level` правила;
  2. `levels[жанр]`;
  3. `slot_levels[slot_type]`;
  4. `level_overrides`;
  5. `groups` (`06/02` §4).
- `--final` поднимает `[PLACEHOLDER]` до error.

**Вердикты и коды.**
- Вердикт выбирается по старшинству: `overcorrected` → `fail` → `rewrite` (≥ 6 warning из ≥ 2 семей) → `review` → `clean`.
- Коды выхода: 0 — нет error; 2 — есть error; 1 — ошибка входа.

**Проходы правки** (`06/02` §9, P6, `10/01` §5):
1. Проход 1 — все error; число без факта заменяется на `fact_ids` или `[PLACEHOLDER]`, другое число не подставляется.
2. Проходы 2–3 — warning кластерами: ≤ 5 на 300 слов прозы, у короткого слота — одна правка.
3. Правка идёт по порядку: удалить → заменить фактом → сказать проще.
4. После каждого прохода — `check` целиком.
5. Четвёртого прохода нет: остаток уходит человеку.

Ложные находки:
- находку линтера снимают через `lint_allow {rule, reason}`; артефакты (ART) и данные (CNT) так не снимаются;
- находки `COPY-F`, `COPY-L` и `COPY-D` снимаются только правкой текста или `facts.yaml`.

Известные ложные находки (К1–К31, X-audit §7) не внесены.

**Аудит готового текста** (README, сценарий 2):
- Без `facts.yaml` модуль права работает как аудит: правила с условием факта становятся вопросами.
- `claims_check.py` принимает deck, `copy.md` kimi, Markdown, HTML и текст.
- Линтер на целой странице без copy deck строже, чем по слотам: у лидеров корпуса `rewrite` — 16 из 24 EN и 11 из 14 RU (калибровка К5).
  (вывод) Это касается и проверки HTML-копий макета.

**Чего аудит не ловит** (`06/02` §12, `09/02` §1.6, `04/03`):
- утверждения без чисел — их ловит только судья, вопрос COPY-R-03 q1;
- медианный текст;
- сюжет заголовков;
- самопохвалу без числа («звоните в любое время», «Simple, transparent pricing» — предложения C);
- дискриминацию в вакансиях — правило `COPY-L-JOB-01` предложено, но не написано;
- единое имя главного действия. `COPY-D-CTA` проверяет только ссылку `cta_primary` (стр. 1131–1133); сравнение подписей кнопок есть
  только при `import-kimi` (стр. 2904–2909).
