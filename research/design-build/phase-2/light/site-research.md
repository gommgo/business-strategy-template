### 1.1. Авторская карта скиллов `99-raw/skills-map.md` (S2, 25.09 00:42): что предлагается

**Пять скиллов** вместо первоначальной гипотезы из семи:
- `site-brief` — шаги 1–3: бриф, вопросы, факты, тип сайта, уровень;
- `site-plan` — шаги 4–8: карта, планы страниц, конверсия, пакет исполнителя;
- `site-seo-geo` — head, robots, JSON-LD, политика ИИ-ботов, аудит;
- `site-check` — порядок проверки «SITE-PRE → ворота → маркеры и факты → эксперт → судья → люди», правка ≤ 7 пунктов;
- `site-measure` — события, цели, UTM → CRM, A/B.

Право и «скорость + ворота» отдельными скиллами не становятся: их YAML и утилиты вызываются из брифа, плана и проверки. Конверсия — часть плана.

**Принципы:**
- Одна копия правил: YAML и схемы остаются в базе, скилл вызывает утилиты по абсолютному пути
  `SR=/home/mm/Документы/app-design/site-research`.
- `SKILL.md` — 150–250 строк: шаги с командами, что читать, 15–25 правил, точки человека, `[не проверено]`.
- `references/` — «Выжимки для агента» дословно с датой снимка, чек-листы, таблицы.
- `templates/` — примеры из 10 с пометкой ДЕМО.
- Скоропортящееся — только через YAML с датой.

**Порядок сборки:** первым `site-check` (код уже работает), затем `site-brief`, `site-plan`, `site-seo-geo`; последним `site-measure` — ему нужен трафик.

**В скиллы не идут:** замер рынка, реестр противоречий, отчёты, заметки, кэш, дайджесты.

**Стык с Kimi:** образец раскладки — скилл kimi `kimi-design-director`; выход `site-plan` — пакет kimi.

**Расхождения с решениями заказчика** (вывод):
- пять скиллов против одного `design-deep-dive`;
- вызов базы по абсолютному пути против переезда базы внутрь скилла;
- стык с Kimi против Claude Design.

**Что полезно независимо от этого:** группировка шагов (бриф / план / SEO-GEO / проверка / измерение), разделение «порядок действий — в SKILL.md, нормы — в YAML», правило «скоропортящееся — через датированный YAML».
