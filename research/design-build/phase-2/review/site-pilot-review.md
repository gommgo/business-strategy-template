## 4. Вердикт и правки брифа

### 4.1. Вердикт

**Лёгкой глубины хватает** (вывод), если README-слой прочитан целиком. Её достаточно для:
- семантической карты;
- решений по умолчанию для крупных групп: дубли v0, Kimi, примеры-эталоны, копии утилит;
- главных рисков.

У пилота это условие выполнено: все числа семантической карты сходятся с README, 9 из 15 проверенных утверждений верны полностью, у остальных 6 верны числа.

**Не хватает в трёх местах:**
1. Категоричные выводы о коде сделаны по обрезанным докстрингам и `--help` (№10, №12).
2. Межбазовые связи: обратные зависимости (№3, п. 3.1.7) и уже готовые таблицы расхождений (п. 3.1.1–3.1.2). Для переезда в один скилл это главное.
3. Содержимое вне README: `PLAN.md`, 09/02 §8. Его находишь, только если знаешь, что искать.

**Насколько доверять таким выжимкам:**
- числам и карте — можно;
- решениям «не переносить» — только после проверки обратных зависимостей;
- выводам со словами «единственный», «не работает без», «никто не читает», «не видит» — только с доказательством из кода.

Ни одна лёгкая выжимка не должна быть единственным основанием для удаления файла.

**Бюджет.** README-слой site по оценке среза — ≈ 57 тыс. токенов, фактически ушло ≈ 78 тыс. (коэффициент ≈ 1,35: номера строк и рассуждения). У остальных ресерчей оценка README-слоя по `files.tsv`:
- ux — 94 тыс. (корневой README — 872 строки);
- ui — 67 тыс.;
- text — 53 тыс.;
- creative — 49 тыс.;
- ai-media — 78 тыс.;
- blender — 141 тыс. (корневой README — 1020 строк).

У blender один README-слой фактически займёт ≈ 190 тыс., поэтому единый лимит 150 тыс. не подходит (вывод).

### 4.2. Правки брифа для ux, ui, text, creative, ai-media и blender

1. **Отчёт о покрытии — первым разделом выжимки.**
   - Таблица «файл | `wc -l` | прочитанные диапазоны | доля». Для корневого README и README папок — 100 %, иначе выжимка не принимается.
   - Корневой README читать через Read кусками не больше 250 строк, с явными `offset` и `limit`.
   - Назвать последний заголовок README и номер его строки — это контрольная точка.
   - Для докстрингов и `--help` писать «целиком» или «первые N строк».
   - Оркестратор проверяет так же, как я: разбирает журнал и сверяет диапазоны Read с `wc -l` (скрипт — в приложении).
2. **Правило категоричных утверждений.** Слова «единственный», «не работает без», «никто не читает», «не нужен», «не видит» допустимы только с доказательством:
   - grep по всему `app-design` — и по содержимому, и по коду соседей;
   - полный докстринг (`ast.get_docstring`);
   - чтение ветки кода по нужному флагу.

   Иначе пометка «(вывод, не проверено)».
3. **Обязательные поиски** — по 1–2 вызова на каждый:
   - (а) таблицы «где базы расходятся», нормализации и поправок к соседям, реестры противоречий: grep по заголовкам со словами «расход», «нормализац», «поправк», «противореч». Перечислить их как содержимое и как кандидатов в общий файл скилла;
   - (б) схемы конвейера и таблицы владения форматами — в PLAN и в контрактах;
   - (в) обратные зависимости: для каждого решения «не переносить» — кто из соседей ссылается на файл (`links.tsv`, где `research` — другая база) или читает его кодом;
   - (г) границы покрытия («Что не покрыто», «вне рамок») — отдельной строкой в карте;
   - (д) решения заказчика, на которые ссылается содержимое: grep по всему содержимому, а не по выборке.
4. **Бюджет и лимиты.**
   - README-слой читать целиком, без лимита.
   - Точечные проверки — до 60 тыс. токенов и не больше 40 вызовов.
   - Срез не пересчитывать: не больше 3 фильтраций, и только для примеров.
   - Утилиты «только для ресерча» — одной строкой.
   - Авторские карты скиллов и планы — не больше 5 строк: только то, что полезно независимо от формата.
5. **Дубли утилит.** Одной командой `md5sum` сравнить одноимённые файлы во всех `*/99-raw/tools/`. Результат — таблица «утилита → совпадает с … / отличается от …; какая версия — надмножество». На site это показало: `page_accept.py` в site отличается от ai-media (ai-media — надмножество), а `check_links.py` разный во всех 7 базах, где он есть.
6. **Поправки к счёту среза.**
   - Счёт Kimi проверять выборкой: `\bK3\b` ловит агентов-продолжателей, а пути `kimi-research/99-raw/cache/repos/` — это внешние проекты, а не Kimi.
   - Лицензии внешних источников смотреть в `*/99-raw/cache/repos/*/LICENSE`, а не оставлять вопросом.
7. **По отдельным базам.**
   - **ux** — лёгкая выжимка только как первый проход: по решению от 26.09 для UX-слоя нужны 1–2 вдумчивых агента. README-слой у ux крупнее (≈ 94 тыс.).
   - **text и creative** — стык тройки с site: `facts.yaml`, `treatment`, `copy-deck`, раздел 0 глоссария («ложный пол» у site = «ложное дно» у text) и незавершённая сверка S2 (README site, строки 466–474).
   - **ai-media и blender** — сначала калибровочный набор и дубли утилит, потом конфликт ворот веса и 3D с site (handoff M6, B2). Для blender — отдельный лимит: корневой README на 1020 строк.
   - **ui** — есть ли маркетинговый профиль для `ui_audit.py`: на лендинге он даёт ложные J2, J8, H1–H2, A1, B2, L5 (README site, строка 327).

### Приложение: проверка покрытия по журналу агента

Запуск: `python3 coverage.py <журнал.jsonl> <абсолютный путь файла> <wc -l>`. На журнале пилота для `site-research/README.md` скрипт выдаёт «647/647 строк = 100 %». Чтение через `cat` или `sed -n` в Bash этот разбор не видит, поэтому бриф должен требовать Read для корневого README.

```python
import json, sys
log, target, total = sys.argv[1], sys.argv[2], int(sys.argv[3])   # журнал .jsonl, путь файла, wc -l
covered = set()
for line in open(log, encoding="utf-8"):
    if not line.strip():
        continue
    o = json.loads(line)
    if o.get("type") != "assistant":
        continue
    for b in o.get("message", {}).get("content") or []:
        if isinstance(b, dict) and b.get("type") == "tool_use" and b.get("name") == "Read":
            i = b["input"]
            if i.get("file_path") == target:
                start = i.get("offset") or 1
                covered.update(range(start, min(start + (i.get("limit") or 2000), total + 1)))
print(f"{len(covered)}/{total} строк = {100 * len(covered) / total:.0f} %")
```
