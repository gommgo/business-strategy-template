# Forward-only (никакой археологии)

Все артефакты — документация, артефакты аналитики, state скиллов, комментарии,
описания PR и коммитов — пишутся в режиме «что есть сейчас и куда идём».
**Без журналов прошлого**: без changelog'ов внутри prose, без следов миграций,
без ссылок на отменённые решения, без дат в комментариях, без «было X —
стало Y», без имён переходных фаз.

Когда эволюция вынесла факт — упоминание **удаляется**, а не сопровождается
пометкой «устарело». История живёт в `git log`, не в тексте файлов.

Правка forward-only-чиста, если:

- читатель, впервые открывший файл, понимает текущее состояние без словаря
  прошлых решений;
- нет ссылок на упразднённые сущности, прошлые имена, прошлые версии;
- нет относительных формулировок, которые сравнивают с прошлым текстом
  («теперь», «больше не», «по-прежнему», «как и раньше»);
- комментарии объясняют только неочевидное «почему», не «когда добавили»;
- описания контракта говорят про актуальное состояние, не про путь к нему.

Это важнее, чем «не сломать кросс-ссылку»: ссылка на упразднённую сущность
удаляется вместе с упоминанием.

## Исключение — журнал сборки

`research/design-build/` — журнал сборки скилла `design-deep-dive`: даты, решения и ход работы в нём —
по назначению, правило к нему не применяется. Журнал убирается при финальной уборке сборки.
