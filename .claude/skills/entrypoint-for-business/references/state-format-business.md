# Формат заметок клиентского оркестратора

State оркестратора — **срез «где мы»** по темам + **открытые темы-нити** +
заметки по блокам, которые оркестратор ведёт **сам** (SWOT/Карта гипотез).
Детальную память по бизнесу/клиентам/продукту ведут под-скиллы в своём
state — оркестратор её не дублирует, только ссылается.

## Расположение

```
.claude/skills/entrypoint-for-business/state/
├── index.md                    (срез «где мы» по темам, бизнес-язык)
├── threads/<slug>.md           (открытая тема-нить)
├── swot-hm/<slug>.md           (заметки по блокам SWOT/Карты гипотез)
└── _session-log/<UTC-ts>.md    (буфер вопросов-ответов → transcript при --share)
```

Создаётся по требованию; forward-only — закрытое удаляется. Не хранить
персональные данные клиента (кроме прямо относящихся к артефакту).

## `index.md` — срез по темам

Singleton-карта «где мы» в бизнес-формулировках, с маркером «закрыто / в
работе / не трогали». Ссылается на детальные заметки под-скиллов, не
дублирует их.

```markdown
# Где мы

## Про ваш бизнес
- в работе · детально: `../../business-deep-dive-for-business/state/`

## Про ваших клиентов
- одна группа разобрана, есть ещё · детально:
  `../../segment-deep-dive-for-business/state/`,
  `../../job-graph-deep-dive-for-business/state/`

## Сильные/слабые стороны, идеи, цель, число (ведём сами)
- задача «возврат клиентов»: стороны разобрали, цель в работе
- детально: `swot-hm/`

## Про продукт
- не трогали
```

## `threads/<slug>.md` — открытая тема-нить

Незавершённый разбор рассказа или тема через несколько направлений: что
обсуждаем и что **ждёт**. Закрытое — убирается; нить без открытого —
удаляется.

```markdown
---
slug: vozvrat-klientov
opened-from: рассказ клиента про задачу «возврат платных», 2026-06-06
---

## О чём (ждёт разбора)
- к чему стремимся (цель) — в работе
- по какому числу поймём — ждёт (метрика — возможно к аналитику)

## Что я имел в виду
- «отток» — про платных пациентов, не всех

## Что дальше
- закрыть цель словами, потом число
```

## `swot-hm/<slug>.md` — заметка по блоку (ведём сами)

По блокам SWOT/Карты гипотез, которые оркестратор ведёт сам. Несёт внутри
привязку к задаче; клиенту слово не показывается.

```markdown
---
блок: metric
slug: paid-churn
задача: возврат платных клиентов
---

## Открытые вопросы
- (**жду аналитика**) Как доказать, что отток упал из-за нас, а не из-за
  сезона — нужен аналитик.

## Что я имел в виду
- Когда сказал «отток», имел в виду платных пациентов, не всех.

## Что копать дальше
- Спросить в клинике точную цифру оттока за прошлый год.
```

## Секции

- **`## Открытые вопросы`** — как в аналитическом state, плюс маркер
  `**жду аналитика**` (при `--share` всё с ним → в summary). `**blocker**`
  используется редко.
- **`## Что я имел в виду`** — переформулировки клиента «когда сказал X,
  имел в виду Y». Ценный авторский контекст без интерпретации скилла.
- **`## Что копать дальше`** — как в аналитическом, реже.

## `_session-log/<UTC-ts>.md`

Накопительный буфер сессии. Блоки `## Вопрос (тема: <бизнес-название>)` →
`### Опции` → `### Ответ`. Служебный, не редактируется руками. При
`--share` уезжает в `client-handoff/transcripts/` и удаляется.

## Единый контекст (read-only)

Чтобы картина была единой, оркестратор read-only подтягивает соседние
`state/`:

- **клиентские слои** — `../business-deep-dive-for-business/state/`,
  `../segment-deep-dive-for-business/state/`,
  `../job-graph-deep-dive-for-business/state/`,
  `../project-deep-dive-for-business/state/<slug>/` (что клиент рассказал
  про бизнес, клиентов, продукт);
- **аналитические слои** — аналитический оркестратор
  `../entrypoint/state/`, и кухня исполнителей (`../business-deep-dive/state/`,
  `../segment-deep-dive/state/`, `../job-graph-deep-dive/state/`,
  `../swot-deep-dive/state/`, `../hypothesis-map-deep-dive/state/`,
  `../project-deep-dive/state/<slug>/`).

Проектный слой — только по текущему продукту (изоляция продуктов). В чужой
state **не пишет**.

**Anti-leak (клиент-режим).** Прочитанное из кухни аналитика — **тихий
контекст**: сырые открытые вопросы, черновые гипотезы, доменные решения,
`slug/draft/stable` клиенту **не зачитываются**, только переводятся в
бизнес-язык. Клиенту по-прежнему видно лишь «закрыто / в работе».

## Жизненный цикл

Создаётся при наличии содержимого; перезаписывается свободно;
заметка/нить удаляется при пустых секциях/каскаде; `_session-log` — при
`--share`. Forward-only, без истории.
