Шаблон для агента, который собирает редполитику сайта клиента: что заполнить, откуда взять, чем проверить. Почему
редполитика устроена так — `02-editorial-policy.md` §1; голос — `01-brand-voice.md`; истории и конкретика —
`03-storytelling-and-concreteness.md`.

## Выжимка для агента

1. **Редполитика — три части**: методичка для генератора (≤ 12 строк и 6–10 образцов строк), полная версия для проверки,
   журнал повторяющихся ошибок. `[практика]` `02` §1.3 все → §2.0, §2.9
2. **Пиши из текстов клиента, а не до них**: первая версия — разбор 3–5 его страниц, писем и отзывов плюс решения таблицы
   стиля; остальное — ссылками на базу. `[практика]` `02` §1.4 все → §1
3. **Чужую редполитику не копируй**: у клиента другие ошибки и другие решения таблицы стиля. `[мнение]` `02` §1.3 все → §1
4. **У каждого правила — id `rp-<раздел>-NN`, пара «нет / да» и способ проверки** (id правила линтера или сверки, критерий
   рубрики I, «человек»); правило без проверки — пожелание, в редполитику не входит. `[практика]` `02` §1.2 все → §2
5. **Машиночитаемое живёт в YAML, редполитика на него ссылается**: голос и таблица стиля — `voice.yaml`, обещания и запреты —
   `facts.yaml`; копия в Markdown расходится с YAML после первой правки. `[практика]` все → §1
6. **Не принятое заказчиком решение — умолчание базы с пометкой** «Going with: …» и вопрос в `open_questions` профиля;
   раздел не пропускать. `[практика]` `01` §3.2 все → §1
7. **Заполняй по порядку проходов**: зачем пишем → голос → обещания → таблица стиля → словарь → компания → жанры → проходы
   → журнал; методичку (§2.0) — последней, из готовых разделов. `[практика]` все → §2
8. **Пары «нет / да» — из текстов клиента**; своих текстов нет — пример `ai-self` с пометкой и прогоном `claims_check.py` →
   `copy_lint.py`. `[проверено]` все → §2
9. **Журнал: 3 повтора или 1 ошибка фактов и права → правило**; изменение — с доказательством, разбор раз в месяц, версия +1.
   `[практика]` `02` §1.4 все → §2.9
10. **Готовность проверяется кодом**: `validate_voice.py` — 0 ошибок, образцы и пары — 0 error в сверке и линтере, методичка
    ≤ 12 строк. `[проверено]` все → Чек-лист

## 1. Как пользоваться шаблоном

- **Куда класть.** Копия раздела 2 — файл `redpolicy.md` в папке проекта клиента рядом с `meaning.yaml` (B1), `voice.yaml` (F),
  `facts.yaml` (B2) и copy deck (J). Заполняется всё в угловых скобках `<…>`; строки-цитаты «> Пример („Отвес“)» — образец,
  в копию клиента не переносятся.
- **Откуда правила.** Разбор 3–5 текстов клиента (страницы, письма, отзывы) через `claims_check.py` → `copy_lint.py` с
  профилем голоса: каждая повторяющаяся находка — кандидат в правило; решения таблицы стиля — вопросом заказчику с умолчанием
  базы. Общие места (инфостиль, канцелярит, набор) — ссылкой на базу, не пересказом.
- **Кто утверждает.** Заказчик или его редактор утверждает версию (`status: approved`) и ведёт журнал; агент предлагает
  правила и изменения с доказательством.

### 2.0. Методичка для генератора

Не больше 12 строк: голос одной фразой, 3–5 решений таблицы стиля, которые модель нарушает чаще всего, «говорим / не
говорим» по 5–10 слов, запреты утверждений одной строкой, 1–3 свежие ошибки журнала; ниже — id 6–10 образцов строк из
`voice.yaml → samples`. Источник текста — `projections.prompt_brief`; полная редполитика в промт не идёт (`02` §1.3).

```text
// <модель> · <дата> · [не проверено]
<≤ 12 строк>
Образцы строк: <id из samples>
```

> Пример («Отвес»):
>
> ```text
> // методичка «Отвеса» для генератора · 2026-09-24 · [не проверено] — ai-self, пример заполнения
> Голос «Отвеса»: хороший прораб говорит с хозяином квартиры. На «вы», «вы» со строчной, о себе — «мы».
> Каждое обещание — с фактом из FACTS: срок в рабочих днях, цена «от» и «без материалов», гарантия 3 года по п. 7.2 договора.
> Числа — цифрами и только из FACTS; нет факта — [PLACEHOLDER: что нужно]. «Ё» — везде. Цена — «₽».
> «Бесплатно» — только с условием в той же строке: «в черте города».
> Людей — по именам из FACTS (Сергей Лапин, Анна К.); отзыв не правим и его слова не повторяем голосом компании.
> Говорим: «двушка», «хозяин квартиры», «рабочие дни», «по договору», «замерщик».
> Не говорим: «любой сложности», «команда профессионалов», «индивидуальный подход», «качественно», «лучший», «ремонт мечты».
> Не обещаем: «лучший ремонт в городе», «смета никогда не меняется».
> Эмодзи нет; «!» — не больше одного на страницу и не в заголовке, цене и гарантии. Не шутим о цене, сроках и гарантии.
> Свежая ошибка журнала: «Смета бесплатно» без «в черте города» (rp-3-01).
> Образцы строк: ru-headline, ru-subheadline, ru-hero-proof, ru-cta-label, ru-cta-note, ru-card-body.
> ```

## Частые ошибки

1. **Редполитика до работы**: разделы из прилагательных («пишем понятно и дружелюбно») без пар из текстов клиента и без
   проверки.
2. **Копия чужой редполитики** с заменой названия: чужие ошибки и чужие решения таблицы стиля.
3. **Дубли YAML в Markdown**: словарь и таблица стиля переписаны в редполитику и через неделю расходятся с `voice.yaml`.
4. **Вся редполитика в промте** или только прилагательные без образцов строк — медианный текст.
5. **Пропущенное решение**: раздел «Таблица стиля» пуст, потому что заказчик не ответил; нужно умолчание с пометкой.
6. **Журнал без решений**: находки копятся, правила не появляются, версия не растёт.
7. **Только русский словарь** при английской версии сайта: английскую выдумку и штампы не видит ни одна проверка.
8. **Ошибки нейросети при заполнении**: выдуманные решения клиента («заказчик предпочитает „Вы“ с заглавной»), пары «нет /
   да», написанные без прогона проверок, общие места базы вместо решений клиента.

## Открытые вопросы и противоречия

1. **Порог журнала «3 повтора»** — мнение базы (`02` §1.4); сколько находок становятся правилами и снижают ли они число
   правок, покажет живая фаза.
2. **Методичка против полной редполитики в промте** на генерации не сравнивалась (платных вызовов нет) — `[не проверено]`,
   план — отчёт F §5.
3. **Валюта в двух режимах** (А101: «рублей» в прозе, «₽» в таблицах) не выражается одним полем `style_sheet.currency` —
   предложение для версии 2 схемы (`currency_tables`, `02` §3.1).
4. **Ключ `--voice` в линтере** (предложение C): пока правила профиля и таблицы стиля собирают два конвертера F, команда
   прохода 4 длиннее, чем могла бы быть.
5. **Английский словарь профиля** в примерах базы не заполнен: поле `lang` у `vocabulary.avoid` есть, конвертер его
   учитывает, с тремя записями на профиль линтер ловит 3 из 3 английских наивных текстов (проба F3,
   `99-raw/experiments/F/05-style-sheet-pairs/en_avoid_probe.py`); дополнить профили-примеры — решение F или J.
