## Цель

Убедиться, что обе схемы — корректная JSON Schema draft 2020-12, что шесть примеров их проходят, что смысловые
правила (которые схемой не выразить) проверяются скриптом, и что типовые ошибки ловятся.

## Что проверяется

1. Метасхема 2020-12 для `02-strategy-messaging/meaning.schema.yaml` и `message-hierarchy.schema.yaml`.
2. Схема для каждого `examples/meaning-*.yaml` и `examples/hierarchy-*.yaml`.
3. Смысл `meaning`: уникальность id; разрешение всех внутренних ссылок (альтернативы, свойства, боли, выгоды, работы,
   возражения, снятие риска, сегменты); у каждого допущения есть вопрос; `fact:` и `missing:` сверяются с facts.yaml из
   `proof_ref` (missing вне инвентаря допустим только из `x-missing-proposals` — это предложение B2); ядро ценностного
   предложения, предмет и темы ценности не задевают `never_claim` с `lift: never` (урок «Кварца»); вопросов приоритета 1
   не больше 7.
4. Смысл `hierarchy`: первая секция — hero и несёт `core`; порядок без повторов; каждая опора несётся хотя бы одной
   секцией; ценности и возражения разрешаются в `meaning_ref`; возражения-блокеры основного сегмента закрыты до
   `final-cta`; тип hero соответствует уровню осведомлённости (иначе — предупреждение); never_claim в главном
   сообщении, опорах и сообщениях секций.
5. Отрицательные случаи в памяти (14): два основных сегмента; допущение без вопроса; ссылка на несуществующую
   альтернативу; возражение «answered» без доказательства и снятия риска; дата без кавычек; свойство has-proof без
   proof_ids; 11 вопросов; обещание про глаза в ядре «Кварца»; две опоры; первая секция не hero; опора без секции;
   неизвестное возражение в секции; section_role вне словаря; блокеры не закрыты до финального призыва.

## Результат (24.09.2026)

- Метасхема — OK для обеих схем.
- 3 meaning + 3 hierarchy — 0 ошибок схемы, 0 смысловых ошибок. Предупреждения: у «Отвеса» 6 `missing` вне инвентаря B2
  (все в `x-missing-proposals`); у «Лесной обжарки» facts.yaml нет (ожидаемо).
- Отрицательные случаи: пойманы 14 из 14.

## Вывод и ограничения

Схемы и валидатор готовы для site (включение `$ref`), J (copy-deck берёт `sections[].message` и `proof_ids`) и I
(цепочка генерации проверяет смысл до текста). Не проверяется: правдивость выводов (inferred), качество формулировок,
соответствие id словарю site после S0 (сейчас — временный словарь; enum в схемах придётся обновить), ссылки `voc:` —
формат записи голоса клиента B2 ещё не выпущен.
