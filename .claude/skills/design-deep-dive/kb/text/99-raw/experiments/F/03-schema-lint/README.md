# F/03 — схема профиля голоса и подключение профиля к линтеру C

- **Цель:** (1) `05-voice-editorial/voice.schema.yaml` — валидная JSON Schema 2020-12; три примера `examples/voice-*.yaml`
  проходят; типовые ошибки профиля ловятся; (2) проверить, читает ли `copy_lint.py` профиль как словарь бренда, и если
  нет — сделать точку подключения без правки кода C.
- **Команды:**
  - `99-raw/tools/venv-F/bin/python ../../scripts/text/validate_voice.py` — метасхема, примеры, 22 мутации;
  - `python3 99-raw/experiments/F/03-schema-lint/voice_to_lint.py --selftest` — конвертер «профиль → правила» (14 случаев);
  - `python3 …/voice_to_lint.py 05-voice-editorial/examples/voice-grafa-b2b.yaml --out …/out` → `rules-grafa-b2b.yaml`,
    `profiles-grafa-b2b.yaml`; затем `99-raw/tools/venv-C/bin/python ../../scripts/text/copy_lint.py naive-grafa-ai-self.md
    --genre landing --json --rules out/rules-grafa-b2b.yaml --profiles out/profiles-grafa-b2b.yaml --profile landing-grafa-b2b`.
- **Версии:** venv-F — Python 3.12.13, jsonschema 4.26.0, PyYAML 6.0.3 (uv 0.11.19); copy_lint.py 0.9.2 (C) из venv-C
  (pymorphy3); 2026-09-24.

**Точка подключения к линтеру.** `copy_lint.py` 0.9.2 не читает `voice.yaml`, но берёт внешний файл правил (`--rules`) и
чужой файл профилей (`--profiles` + `--profile`). Конвертер `voice_to_lint.py` делает оба файла: `vocabulary.avoid` →
правила `kind: words` (маскировка цитат, отзывы исключены), `spellings` → правила написания, `address` → «формы на ты»
и «Вы» с заглавной, `punctuation` → эмодзи и «!», `lint.level_overrides` → профиль `<жанр>-<voice_id>` в копии
`profiles.yaml`. Предложение C — ключ `--voice voice.yaml`, делающий то же внутри линтера.

**Опыт на «наивном» тексте** (`naive-grafa-ai-self.md`, 53 слова, ai-self: так пишет модель без правил):

| Прогон | error / warning / info | маркеров на 100 слов | находок словаря бренда |
|---|---|---|---|
| профиль `landing` без голоса | 1 / 5 / 3 | 9,43 | 0 |
| профиль `landing-grafa-b2b` + правила бренда | 1 / 15 / 2 | 15,09 | 13 |

Словарь бренда добавил 8 находок, которых нет у общего линтера: «осуществляет», «полный спектр», «Закажи» (обращение не
по профилю), «Уважаемый клиент», «Вам» с заглавной, «1C» латиницей, эмодзи, «!». Там, где место совпало с общим правилом
(«команда профессионалов» — `ru-mkt-self-praise`), побеждает сообщение бренда с заменой из профиля.

**Ошибки, найденные по дороге (исправлены в своих скриптах):**
1. Конвертер отбрасывал `flags: ""` как пустое значение → правила регистра («Вы», «1С») стали нечувствительны к регистру и
   ложно срабатывали на «вашей», «1С». Исправлено; в селфтест добавлены два случая.
2. В первой версии правила словаря бренда стояли с `count_as_marker: false` и `priority: 70`: они выигрывали место у общих
   правил и **снижали плотность маркеров** (9,43 → 5,66). Теперь `vocabulary.avoid` считается маркером (15,09).
3. Регулярка словаря в `validate_voice.py` портила класс «продолжения основы», заменяя «ё» после вставки класса; мутация
   «слово из avoid в образце» проходила незамеченной. Исправлено (сначала «ё», потом класс).

## Вывод

Схема держит структуру голоса (принцип без исполнения, пустая пара «мы / мы не», юмор в праве, тон вне шкалы — ошибки
схемы), а смысловые проверки ловят то, что схема не видит (обращение, эмодзи, словарь в образцах, ссылки на факты).
Линтер C читает профиль через файл правил и файл профилей — работает сегодня, без правки кода; ключ `--voice` уберёт
промежуточный шаг. Принципы, пары и точки осей линтер не проверяет — это судья (I) и человек (`01-brand-voice.md` §4).
