## 2. Формат правила

### 2.1. Поля

Наследует ux 07/06 §7.1 (`id, level, lang, pattern, flags, appliesTo, excludes, message, replacement, examples,
source`) [S1] и добавляет поля жанра, слота и порога. Поля вне списка при загрузке отбрасываются.

| Поле | Откуда | Значение | По умолчанию |
|---|---|---|---|
| `id` | ux §7.1 | латиницей в kebab-case: `ru-lex-copula`, `en-mkt-banned-openers`, `art-ai-utm`, `mkt-role-…`, `an-…`, `ux-<§>-<nn>`; повтор id — ошибка загрузки | обязательно |
| `level` | ux §7.1 | `error`, `warning`, `info`, `"off"` (норма жанра; в YAML — в кавычках, иначе это `false`) | обязательно |
| `lang` | ux §7.1 | `ru`, `en`, `any` | `any` |
| `pattern`, `flags` | ux §7.1 | регулярное выражение Python `re` с макросами §2.2; флаги `i m s x` | `i` |
| `words` | база | список слов и фраз вместо `pattern`: `*` — продолжение основы, `ё` = `[её]`, границы ставятся сами | — |
| `kind` | база | `regex`, `words`, `analyzer` (объявление анализатора §5), `manual` (ручная проверка из ux) | `regex` |
| `appliesTo`, `excludes` | ux §7.1 | роли ux 07/06 §7.2 | все роли |
| `message`, `replacement`, `examples` | ux §7.1 | что не так, как править (иерархия §9), пара `{bad, good}`; `skip_bad`, `skip_good` — не проверять пример | `message` обязательно |
| `source` | ux §7.1 | источник; без него правило не добавляется (S1 §7.5) | обязательно |
| `genres` | база | в каких из шести жанров действует | все |
| `levels`, `slot_levels` | база | уровень по жанру `{article: info}` и по типу слота `{headline: error}` | — |
| `slot_types`, `exclude_slot_types` | база | типы слотов временного словаря, шаблоны `fnmatch` | — |
| `marker_id` | база | маркер каталога `COPY-M-<группа>-<nn>` или `ux:07-06#<§>` | — |
| `group` | база | семья: `ART CNT LEX SYN PUN STR TON MKT UX EXT` — плотность, порядок отчёта | `LEX` |
| `threshold_ref` | база | порог D: `03-corpus-measured/thresholds.yaml#genres.<жанр>.analyzers.<имя>` | — |
| `count_as_marker` | база | входит ли находка в плотность маркеров | `true` |
| `min_count`, `scope` | база | сколько совпадений нужно в блоке (`unit`) или во всём документе (`doc`) | `1`, `unit` |
| `unless` | база | регулярка: найдена в том же предложении — правило молчит (`'\d'`: «быстро» с числом законно) | — |
| `requires_no_fact` | база | срабатывает, только если у слота нет `fact_ids` | `false` |
| `mask_quotes` | база | не искать внутри «…», “…”, „…“, "…", `…` | `true` для LEX SYN PUN STR TON MKT |
| `priority` | база | при совпадении места у двух правил остаётся приоритетное, затем более строгое | `50` |
| `evidence`, `date`, `note` | база | метка доказательности, дата правила, пояснение (попадает в находку) | — |

Заголовок файла: `date`, `version`, `owner`, `defaults` (сливаются в каждое правило файла), `rules`, `overrides`.

### 2.2. Регулярные выражения

- Движок — Python `re`. Макросы: `%B%` и `%E%` — левая и правая граница слова (`(?<![A-Za-zА-Яа-яЁё0-9_])`,
  `(?![A-Za-zА-Яа-яЁё0-9_])`), `%W%` — продолжение основы (`[A-Za-zА-Яа-яЁё0-9_]*`); явные классы переносимы.
- Правила ux написаны для ECMAScript. В JS `\w` не совпадает с кириллицей даже с флагом `u`: `мощн\w*` находит только
  основу, `(\w+(ния|…)\s+){3,}` (ux §2.4) не срабатывает вовсе; реализация на JS должна раскрывать макросы.
- Класс только из заглавных (`[A-ZА-Я]`) с флагом `i` ловит и строчные — конвертер снимает флаг (находка B1:
  «заглавная после двоеточия» срабатывала на «в Сормове: ремонт»); «Ё» вне диапазона `А-Я`, класс — `[А-ЯЁ]`.

### 2.3. Пример

```yaml
- id: ru-syn-not-only-but-also     # group SYN, lang ru, genres, date — из defaults файла ru-syn.yaml
  marker_id: COPY-M-SYN-01
  level: warning
  slot_levels: {headline: error, subheadline: error, meta-title: error, meta-description: error}
  pattern: '%B%не\s+только%E%[^.!?\n]{1,80}?(?:,\s*|\s+|\s*[—–-]\s*)(?:но|а)\s+(?:и\s+)?[а-яёa-z0-9«"]'
  message: "«Не только X, но и Y» — самая узнаваемая фигура сгенерированного текста."
  replacement: "два простых предложения; «как X, так и Y» — та же фигура"
  examples: {bad: "Сервис не только экономит время, но и снижает затраты.",
             good: "Отчёт включает не только штатных сотрудников."}
  source: "гайд Б2, §E п.8; humanizer-ru п.13 и lint.py; WP:AISIGNS «Not only… but»"
  evidence: "[консенсус]"
```

### 2.4. Поправки к чужим правилам и нормы жанра

- `overrides: [{target, set, note}]`: `target` — шаблон `fnmatch` по id (`ux-5-2-0[1235]`), `set` — заменяемые поля,
  `note` — причина (приписывается к находке). Применяются после загрузки всех файлов. Сейчас 10 поправок — все в
  `marketing-role.yaml`, по таблице поправок PLAN к ux 07/06 (каталог §11).
- Норма жанра — правило с `level: "off"` и пояснением: `mkt-role-category-words` («платформа», «решение» как
  категория), `mkt-role-headline-verb` (глагол в заголовке оффера), `ux-2-4-01` (дубль цепочки родительных). Агент,
  который перенесёт правило из чужого гайда, увидит, что его выключили намеренно.

### 2.5. Наследование ux 07/06

- `../../scripts/text/ux_dict_to_yaml.py` читает таблицы §1–§6 с колонкой «Regex» из
  `../ux/07-ux-writing/06-banned-words-and-patterns.md` и пишет `lexicon/ux-07-06.yaml` (руками не править):
  id `ux-<§>-<nn>`, `marker_id` `ux:07-06#<§>`, группа `UX`, `count_as_marker: false` (качество интерфейса, а не слоп).
- Уровень — из колонки «Уровень», из ячейки («уровень `предупреждение`») или из строки раздела «Уровень — запрет во
  всех строках»; роли — из «в узлах роли `link`», «кроме `email`», «вне узлов роли `placeholder`»; «подсчёт…» —
  `min_count: 2`; строки без регулярного выражения — `kind: manual` (7 правил, линтером не исполняются).
- В заголовке YAML — sha256 источника; `ux_dict_to_yaml.py --check` возвращает 3, если ux изменился. После обновления:
  конвертер → `copy_lint.py --selftest` → `99-raw/experiments/C/01-evals-ux-pairs/run.py` (полнота 122 / 122, ложных
  на чистых текстах ≤ 1) → нужны ли новые поправки. Правило ux на месте своего правила в отчёт не выходит.

### 2.6. Внешние правила G и H

- Формат — как у `lexicon/*.yaml`. Пути — `profiles.yaml → external_rules`: `07-seo-geo-copy/meta-rules.yaml`,
  `geo-rules.yaml` (G), `08-russian-legal-typography/typography-rules.yaml`, `claims-rules.yaml` (H). Файла нет —
  строка в `notes`; разовое подключение — `--rules <файл или папка>` (ключ повторяется). Группа вне списка — `EXT`;
  префиксы id — `meta-`, `geo-`, `typo-`, `law-`; для типографики и права `count_as_marker: false`.

## 3. Роли и типы слотов

### 3.1. Откуда роль

Тип слота (`slot_type`) — из временного словаря оркестратора `99-raw/notes/temp-vocabulary-v0.yaml` (63 типа, у каждого
роль ux 07/06 §7.2 и жанры; E закрепит его в `copy-slots.yaml`). Роль нужна правилам ux и защите отзывов.

| Роль ux | Типы слотов |
|---|---|
| `marketing` (23) | eyebrow, hero-proof, section-lead, body, list-item, card-body, step-body, stat-value, logos-caption, case-summary, case-result, pricing-plan-summary, pricing-price, pricing-feature, guarantee-text, objection-answer, form-lead, footer-tagline, article-lead, article-summary, article-paragraph, geo-answer, definition |
| `section-title` (7) | section-title, card-title, step-title, case-title, pricing-plan-name, faq-q, article-heading |
| `title`, `subtitle` | headline, form-title, article-title; subheadline |
| `action`, `link` | cta-label, email-cta-label; cta-secondary-label |
| `hint`, `caption` | cta-note, pricing-price-note, form-next-steps; stat-label, testimonial-attribution, footer-legal, article-author |
| `email` (5) | email-subject, email-preheader, email-heading, email-body, email-footer |
| прочие | image-alt, og-image-alt (`alt`); badge (`badge`); comparison-row (`column-header`); faq-a (`help`); form-consent (`checkbox-label`); form-success (`inline-message`); nav-label (`nav`); testimonial-quote (`user-content`) |
| без роли ux | meta-title, meta-description, og-title, og-description — внутренняя роль `meta`; in-image-text — `marketing` (текст в картинках — ai-media) |

Id вне словаря: псевдослот `hr` (разделитель `---` в Markdown, правило `ru-pun-hr`) и роль `meta` — внутренние
значения парсера, в словарь не предлагаются (строка в отчёте C).

### 3.2. Как правило выбирает слот

- Правила ux — по ролям (`appliesTo`, `excludes`): почти все исключают `marketing`, `help`, `user-content` и работают
  на кнопках, подписях, согласиях и сообщениях форм сайта.
- Свои правила — по жанру и типу слота: штамп вступления — warning в теле, error в headline, subheadline, meta-*, og-*,
  article-lead, email-subject, email-preheader.
- Роль `user-content` (отзыв): правила стиля (LEX, SYN, PUN, STR, TON, MKT) не применяются, если роль не названа в
  `appliesTo`; артефакты и данные проверяются. Внутри кавычек и бэктиков правила стиля молчат в любом слоте.
- Жанр слота — из `page_type` copy deck (словарь → `genre`); мета страницы проверяется профилем `meta` и внутри лендинга.

### 3.3. Разбор входа

| Вход | Как делится на блоки |
|---|---|
| copy deck YAML | `copy_deck.pages[].sections[].slots[]`: `slot_type`, `variants[].text` или `text`, `fact_ids`, `lint_allow`; мета страницы `meta.title/description/og_*`; короткая форма — `slots: [{slot_type, text}]`; `--chosen-only` — только выбранный вариант |
| Markdown, текст | `#` → headline (в статье article-title), `##` → section-title (article-heading), `###` и ниже → card-title; заголовок с «?» → faq-q; `- ` и `1.` → list-item; `>` → testimonial-quote; строка капсом ≤ 9 слов перед заголовком → eyebrow; `---` → hr; абзац → body (статья — article-paragraph, GEO — geo-answer, письмо — email-body, мета — meta-description) |
| HTML | `<title>` → meta-title; `meta description`, `og:*` → мета; h1–h6, p, li, `button` и `a.btn` → cta-label, blockquote → testimonial-quote, figcaption → stat-label или body, `label` согласия → form-consent, `img alt` → image-alt; script, style, svg пропускаются |
| `--slot-type X` | весь текст — один слот типа X |

### 3.4. Проза

Ритм, абзацы, тире, конкретика, повтор глагола и сверхкоррекция — только по блокам от 4 слов типов body, section-lead,
article-paragraph, article-lead, article-summary, geo-answer, definition, faq-a, email-body, case-summary,
guarantee-text, objection-answer, pricing-plan-summary (`prose_slot_types`); плотность маркеров и частоты — по всему.

## 4. Профили жанров

Профиль = `defaults` ⊕ `profiles.<имя>` из `06-anti-slop/profiles.yaml` ⊕ `genres.<жанр>.analyzers` из
`03-corpus-measured/thresholds.yaml` (глубокое слияние, позднее сильнее). Имя профиля по умолчанию равно жанру;
`--profile` выбирает другой, `--profiles` — другой файл.

Уровень находки считается так: `level` правила → `levels[жанр]` → `slot_levels[slot_type]` → `level_overrides`
профиля (шаблоны по id) → `groups[группа]`: `enabled: false` выключает семью, `max_level` — потолок, `min_level` —
пол. Ключ `--final` поднимает `art-placeholder-marker` (`[PLACEHOLDER]`) до error — проверка перед публикацией.

| Профиль | Жанр и слоты | Уровни (отличия от правил) | Анализаторы (отличия от `defaults`, §5) |
|---|---|---|---|
| `landing` | лендинг и его блоки, тексты вокруг форм на странице | STR не выше warning; продающий вопрос «Хотите…?» — info; рубленый драматизм — warning | «все списки по три» выкл. (три карточки — норма); вопросы — порог 1,5 |
| `site-page` | главная, услуги, о компании, кейсы, тарифы, контакты | STR не выше warning | «все списки по три» выкл.; вопросы — 1,5 |

### 5.1. Тире: обязательное или пунктуационное

Спор «тире по грамматике против порога» (находка B1: дословные факты «Смета и выезд замерщика — бесплатно» дали 6,5
тире на 100 слов и warning). Решение заказчика: тире — по грамматике, плотность в прозе — по порогам корпуса (PLAN,
решения п. 16). Линтер делит тире на два класса и штрафует только второй.

| Класс | Когда (гайд заказчика §C [S2]) | Пример | Чем заменить |
|---|---|---|---|
| Обязательное | подлежащее и сказуемое — существительные в именительном, инфинитивы, числа, без связки | «Смета — часть договора», «Наша задача — вернуть вам 4 часа», «Гарантия — 3 года» | ничем: перестроить фразу с глаголом |
| Обязательное | перед «это», «вот», «значит» (слева нет сказуемого) | «Консультация — это 40 минут разговора с юристом» | ничем |
| Обязательное | на месте пропущенного члена; «поле — значение» в карточке | «Доставка по Москве — за 30 минут», «Сборка — Казань» | ничем |
| Обязательное | перед обобщающим словом после перечня; прямая речь в начале строки | «Лампы, розетки, провода — всё проверяем» | ничем |
| Пунктуационное | пара тире вокруг вставки | «Сервис — и это важно — работает без выходных» | запятые, скобки |
| Пунктуационное | бессоюзное сложное: следствие, условие, противопоставление | «Звоните — приедем в течение часа» | союз или точка |
| Пунктуационное | пояснение или «эффектная пауза» после сказуемого, тире перед союзом | «Отправляем в день обжарки — без месяцев на складе»; «— и наслаждайтесь результатом» | запятая, двоеточие, точка (гайд §C, приёмы 1–10) |
| Пунктуационное | перед прилагательным-сказуемым (по норме тире не нужно) | «Доставка — бесплатна для заказов от 3000 ₽» | убрать тире |

Алгоритм `copy_lint.dash_classes` (без синтаксического разбора):
1. Тире — «—» или «–» с пробелами либо «—» между буквами; диапазон цифр («3–5 дней») не считается. Тире в начале
   строки (прямая речь) — обязательное.
2. Часть предложения — отрезок между `, ; : . ! ?`, переводом строки и скобкой. Два тире в одной части — оба
   пунктуационные (вставка); английский текст — все пунктуационные.
3. Справа союз («и», «а», «но», «поэтому», «чтобы», «если»…) — пунктуационное. Справа «это», «вот», «значит», «всё»,
   «никто», а слева нет сказуемого — обязательное.
4. Слева 1–7 слов, справа 1–9 слов, ни с одной стороны нет сказуемого — обязательное; иначе — пунктуационное.
   Сказуемое без морфологии — личная форма глагола по окончанию («-ем» только после гласной, «-им» после в т д с з б п
   л м р, повелительное «-ите/-ьте/-йте», «-ём», «-ёт») минус 288 слов с «глагольными» окончаниями и их формы
   («результат», «минут», «материал», «цели», «бюджете», «если», «Михаил»); слово с заглавной в середине части — имя.
   С pymorphy3 — глагол, краткое прилагательное или причастие, если этот разбор весомее прочих; незнакомые словарю
   слова и части через дефис — по окончаниям.

Точность на 124 размеченных тире (C/05): эвристика 0.9.1 — 0,734, 0.9.2 без морфологии — 0,960, с pymorphy3 — 0,976
[проверено: C/05; набор не слепой]. Остаются ошибки: длинное подлежащее с придаточным («Первый шаг для любой кофейни,
которая хочет продавать зерно онлайн, — сфотографировать упаковку») уходит в пунктуационное, прилагательное-сказуемое
(«Наша студия — лучшая в городе») — в обязательное. Спорное отдаётся автору: лучше пропустить лишнее тире, чем
оштрафовать правильное. На copy deck B1 из 19 тире 17 обязательных, предупреждения больше нет.

Метрики: `dash_count`, `dash_per_100w` (все), `dash_obligatory`, `dash_punct`, `dash_punct_per_100w` (порог — по ним).
Порог по жанрам — D; типографика тире (неразрывный пробел, «–» в диапазонах) — H; запрет тире kimi 05/03 — неверен.

### 5.2. Сверхкоррекция

Сигналы (`metrics.overcorrection_signals`): доля предложений прозы ≤ 3 слов ≥ 0,3; доля предложений со связками («но»,
«потому что», «который», «если»… — 48 RU, 30 EN) ≤ 0,25; рубленые фразы в ≥ 80 % абзацев (при ≥ 3 абзацах);
разговорные вставки («короче», «ну», «честно»; «honestly», «basically») ≥ 1,5 на 100 слов; средняя разница длин
соседних предложений ≥ 12. Нужно 3 из 5. C/04: пойманы 5 из 5 своих «очеловеченных» текстов, ложных 0 из 8 контролей,
все 32 сочетания порогов без ошибок [проверено: C/04]. Вердикт `overcorrected` ставится поверх любых error.

## 7. Порядок проверок

Совпадает с ux 07/06 §7.4 [S1], дополнен для сайта; в этом же порядке идут находки в отчёте.
1. **Артефакты** (ART): метки чат-ботов, `utm_source=chatgpt.com`, реплики ассистента, шаблоны `[Название]`, PUA и
   невидимые символы, пометки вымысла — ищутся и внутри цитат.
2. **Выдуманные данные** (CNT): числа и соцдоказательства без `fact_ids`, «идеальные» числа, дефицит без данных,
   выгода без факта; сверка с фактами — `claims_check.py` (B2).
3. **Словари ux и внешние правила** (UX, EXT): строки форм и кнопок, правила G и H.
4. **Лексика, синтаксис, пунктуация, маркетинг, тон** по жанру и слоту; с морфологией четыре правила — разбором (§10).
5. **Структура** (STR): склейки, концовки, ярлыки секций, надзаголовки. 6. **Анализаторы** (§5).
7. **Сверхкоррекция** — последней: она оценивает результат правки, а не исходный слоп.

Одно место — одна находка: остаётся более приоритетное правило, затем более строгое, затем своё раньше ux; второе
пишется в `note` («то же место: …»). `scope: doc` решает `min_count` по документу. `lint_allow` снимается до плотности.

## 8. Отчёт, коды выхода, запуск

JSON (`--json`), один элемент `results` на файл:

```text
{"tool": "copy_lint", "version": "0.9.2", "date": "2026-09-24", "results": [{
  "input":      {path, format, units, lang, genre, profile, morphology},
  "thresholds": {thresholds: "<источник порогов>", provisional, error?},
  "summary":    {error, warning, info, verdict, severity, gate, suppressed},
  "metrics":    {all, prose, prose_slot_types, markers: {count, hits, per_100w, distinct_rules, families, by_group},
                 overcorrection_signals?, eyebrows?, list_sizes?},
  "findings":   [{id, marker_id, level, group, message, fragment, context, position: {unit, start, end, line, col},
                  replacement, example, source, evidence, slot: {slot_type, role, page_id, section_id, slot_id, variant},
                  counts_as_marker, note?}],
  "notes"?: [...], "units"?: [...]}]}
```

- `verdict`: `overcorrected` (есть `an-overcorrection`) → `fail` (есть error) → `rewrite` (≥ 6 warning из ≥ 2 семей)
  → `review` (есть warning) → `clean`; `gate` — `fail` при любом error; `severity` — сумма по правилам min(4, вес),
  вес error 3, warning 1 («сколько разных видов слопа», а не длина текста — по образцу Gesso [S6]).
- `metrics.all` — весь текст, `metrics.prose` — прозаические слоты (`null` без прозы); ключи — §5 и «Для D» в
  `99-raw/notes/wave1/C-notes.md`. `position.line/col` — для Markdown и текста, для copy deck место — `slot`.
- Коды выхода: 0 — нет error; 2 — есть error; 1 — ошибка запуска, входа, словаря, неизвестный жанр. `--selftest`:
  0 — OK, 1 — FAIL. `--md` — таблица «уровень · правило · маркер · где · фрагмент · что не так · правка» и метрики.

Ключи: `--genre`, `--lang auto|ru|en`, `--profile`, `--profiles`, `--thresholds`, `--vocab`, `--slot-type`,
`--format md|txt|html|yaml`, `--json`, `--md`, `--metrics-only`, `--units`, `--rules` (повторяемый), `--final`,
`--chosen-only`, `--morph auto|on|off`, `--selftest`, `--version`; `-` — stdin. API (`sys.path` → `99-raw/tools`):
`lint_text(text, genre, lang, slot_type, profile, fmt, metrics_only)`, `text_metrics(text, lang, paragraphs, morph)`,
`dash_classes(text, dashes, lang, morph)`; ниже — `load_rules`, `read_document`, `lint_document`. JSON и API меняются
только добавлением ключей; изменения — в «Для D».

## 9. Протокол правки для агента

1. **Запуск.** Copy deck с `slot_type` и `fact_ids`, жанр из `page_type` или `--genre`; сначала `claims_check.py`
   (B2), затем `copy_lint.py --json`.
2. **Проход 1 — все error.** Артефакты удалить; число без факта — `fact_ids` на запись `facts.yaml` или
   `[PLACEHOLDER]` и вопрос заказчику, **не придумывать**; error в заголовке, мета, теме письма — переписать слот.
3. **Проходы 2–3 — warning кластерами.** Сгруппировать находки по слоту и предложению, начать с семьи, где их больше;
   за проход — не больше 5 кластеров на 300 слов прозы и одна правка на короткий слот; каждая правка — по иерархии
   удалить → факт → проще. Синоним из того же списка, «как X, так и Y» вместо «не только», «:» вместо каждого «—» —
   не правка [S2 §C, S3 «запрещённые замены»].
4. **Info** — только в одном предложении с warning или выше порога анализатора; одиночное «очень» не трогать.
5. **Сохранить:** функцию текста (CTA, оффер, срок, цена, условие), голос бренда (F), цитаты, отзывы, названия, длину
   слота по `copy-slots.yaml` (E).
6. **После прохода — перезапуск** линтера и `claims_check.py`: error = 0; плотность ниже прежней; нет новых семей;
   вердикт не `overcorrected`; `fact_ids` на месте. Стало хуже — откатить правку.
7. **Стоп:** `clean` или `review` с плотностью ниже порога и без warning в headline, subheadline, CTA, мета; иначе
   после 3 проходов — остаток находок человеку или судье (I): четвёртый проход ведёт к сверхкоррекции [S3: «лучше
   пропустить машинный текст, чем оболгать живой»].
8. **Законный случай** (слоган из брифа, термин отрасли, «платформа» как категория) — в слот copy deck
   `lint_allow: [{rule: <id>, reason: "<почему>"}]`: находка уходит в `notes` с причиной, счётчик —
   `summary.suppressed`; артефакты (ART) и данные (CNT) не подавляются. Поле — предложение J к схеме copy deck (по
   образцу видимого опт-аута Gesso `data-slop-allow` [S6] и ux 07/06 §7.5 [S1]).

Числа 5 кластеров и 3 прохода — `[мнение]` по опытам C/01 и C/04, на генерации не проверены (живая фаза, отчёт C).

## 10. Морфология и скорость

- Интерпретатор `99-raw/tools/venv-C/bin/python` включает pymorphy3 (`--morph auto`; `on` — ошибка без пакета; `off`
  — выключить); в отчёте `input.morphology: true`. Лицензии — [S10] и `../../scripts/text/README.md`.
- Морфология заменяет `ru-syn-gerund-tail`, `ru-syn-genitive-chain`, `ru-syn-passive`, `ru-syn-passive-agent` (полнота
  1,0 против 0,57–0,75 у регулярок при той же точности, C/03), уточняет повтор глагола и деление тире (C/05). Висячие
  деепричастия не решает (точность ≤ 0,8) — остаются регуляркой уровня warning и судьёй.
- Время на 10 000 слов: без морфологии 0,5 с, с морфологией 1,0–1,1 с.

| Строчная после двоеточия «в Сормове: ремонт» | `ux-6-4-11` | флаг `i` снят (конвертер и override) |
| «производитель» в FAQ | `ux-2-1-04` | шаблон переопределён на формы глагола «производить» |
| «подчёркивают», «демонстрируют» в прямом значении в статье | `ru-lex-empty-verbs` | article — info |
| «Не просто…, а» у живого автора (приём) | `ru-syn-not-just` | остаётся warning: решают кластер и человек |
| Цитаты плохих отзывов в статье без кавычек | вся лексика | оформлять «ёлочками» или цитатой — маскируются |
| Серия коротких вопросов в колонке | `an-rhythm-monotone` | монотонность — только при средней длине ≥ 9 слов |
| «Как быстро решат мою проблему?», «быстрее, чем» | `mkt-role-easy-fast` | молчит в вопросах и рядом с числом; «быстрее» убрано |
| «Скоро» на странице листа ожидания; «Нам доверяют» над настоящими логотипами | `ux-5-1-06`, `ux-5-2-02` | warning вместо error; info и только без `fact_ids` |
| Эхо-повтор «Клиент платил… Платил молча.»; «P. P. S.» | `an-verb-repeat`, `ru-syn-chopped` | короткое второе предложение не проверяется; фрагмент от двух букв |
| Вкладки и статусы веб-приложения как «проза» | анализаторы прозы | проза — блоки от 4 слов |
| delve, crucial у живого автора; дефис вместо тире | `en-lex-kobak-2024`, `ru-pun-hyphen-as-dash` | info от 4 слов; warning набора; оба не в плотности |
| Реальная акция «Только сегодня скидка 30 %» | `ru-mkt-false-urgency` | молчит при `fact_ids` в copy deck |
| Отзыв клиента со штампом «команда профессионалов» | правила стиля | роль `user-content` стилем не проверяется |

Остаются: длинное подлежащее и прилагательное-сказуемое (§5.1); висячее деепричастие; тройка в перечне фактов (info);
текст о слопе (каталог, отчёт): упоминание примера не отличить от употребления, «→ §N» считается стрелкой в прозе.

## 12. Чего линтер не ловит

Ограничения ux 07/06 §8 [S1] (синтаксис элемента, тон, заголовок против содержимого, бессмысленная правильность,
выбор из пары, мягкие тёмные приёмы, соответствие поведению) действуют и здесь; маркетинговые — ниже.

| Не ловится | Почему | Чем проверять |
|---|---|---|
| Медианный текст без позиции, «очевидный ответ» | лексически чист | судья и человек; голос и позиционирование (F, B1) |
| Выдуманная конкретика без чисел («сборка в Казани») и число из `facts.yaml` не в том смысле | нет примет в словах | `claims_check.py`, `never_claim` (B2), человек |
| Сюжет заголовков лендинга (инвертированный outline-тест) | нужен смысл последовательности | судья (I), чек-лист E |
| Уместность тона и один регистр на страницу | зависит от голоса и ситуации | карта голоса F, судья |
| Правовой риск («гарантированный результат», медицина) | нужна норма и контекст | H: `claims-rules.yaml`, правовой модуль `claims_check.py` |
| Шаблон страницы и срочность как механика | уровень страницы | site (`page-plan`, `blocks.yaml`) |
| Длина слота относительно раскладки | нужен лимит слота | E (`copy-slots.yaml`) по замерам D |
| Согласованность названий и CTA по странице | нужен обход узлов | частично SYN-13; ux 07/06 §7.3 «имя действия по потоку» |
| Новые слова моделей; калька EN ↔ RU вне списка | словарь буквальный | пересмотр по корпусу D раз в полгода; человек, судья |

## 13. Тесты и сопровождение

- `copy_lint.py --selftest`: загрузка словарей и внешних файлов; «плохо» каждого правила ловится, «хорошо» — нет (160
  пар); 12 сценариев; ритм; сверхкоррекция; деление тире (включая прямую речь); copy deck (число без факта, стрелка в
  кнопке); отзыв без проверки стиля; `lint_allow`. Регрессия — C/01 (122 / 122, ложных на чистых ≤ 1), C/02, C/04
  (5 / 5, 0 / 8), C/05 — после каждой правки словарей.
- Новое правило: id по схеме §2.1, `marker_id` из каталога (новый маркер — сначала строка каталога), `source`,
  `evidence`, пара `examples`, уровни по жанрам; затем `--selftest` и C/01.

## Частые ошибки

1. **Править по баллу, а не по находкам:** снижать плотность заменой слов на синонимы из того же списка.
2. **Считать тире «по гайду эссе»:** порог 2–3 на 1500 слов и запрет тире ломают русский набор (§5.1).
3. **Гонять ритм по карточкам и пунктам:** одинаковая длина — норма раскладки; ритм — только проза.
4. **Выключать правило вместо `lint_allow` с причиной** — исключение становится невидимым.
5. **Лечить число без факта выдуманным фактом** — провал «Кварца»; только `facts.yaml` или `[PLACEHOLDER]`.
6. **Бесконечные проходы:** четвёртый проход даёт сверхкоррекцию; после трёх — человек или судья.

## Чек-лист

1. Вход — copy deck со `slot_type` и `fact_ids` или текст с верным `--genre`?
2. `claims_check.py` пройден до линтера?
3. Error = 0, а исключения оформлены `lint_allow` с причиной?
4. Плотность маркеров ниже порога жанра, находки не из одной семьи?
5. Пунктуационных тире в прозе не больше порога; дефиса вместо тире нет?
6. Вердикт не `overcorrected`, связки на месте?
7. Проходов правки не больше трёх, остаток отдан человеку или судье?
8. В отчёте видно, чьими порогами проверяли, и нужные внешние правила подключены?

## Открытые вопросы и противоречия

1. **Пороги** стартовые: зазор «человек 0–1,5 / ИИ 6,7–10,5 маркера на 100 слов» получен на 21 фрагменте почти без
   человеческих лендингов RU (C/02). Итог — D2: `thresholds.yaml` v2 (§5); на живых страницах зазор не держится —
   плотность не детектор ИИ (D `03/02` п. 9–10; реестр X22).
2. **Тире:** ux 07/06 §6.2 и kimi 05/03 против русской нормы; порог — D, типографика — H; деление без синтаксиса
   ошибается в 2,4–4 % случаев (C/05, набор не слепой).
3. **`lint_allow`** — поле copy deck, которого нет в схеме v0 (PLAN): решение за J.
4. **Правила ux на JS:** `\w` без кириллицы и классы с флагом `i` ломают §2.4 и часть §1 (предложение соседу — отчёт C).
5. **Числа протокола правки** (5 кластеров, 3 прохода) не проверены на генерации — живая фаза.
6. **Роль `body`** в правилах ux §2.3 и §4.1 отсутствует в закрытом списке §7.2 — такие правила не срабатывают.
