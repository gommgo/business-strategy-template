## Как пользоваться (для агента)

Единица базы: папка → `README.md` (файлы и выжимка на 10 строк) → файл → «Выжимка для агента» (15–40 правил с меткой,
жанрами и `→ §`) → разделы → «Частые ошибки» → «Чек-лист» → «Открытые вопросы и противоречия» → «Источники».
Обозначения: `02/03 §5.1` — папка 02, файл 03, раздел 5.1; `X12` — пункт `CONTRADICTIONS.md`; `LT-01` — тест живой фазы
(`09-ai-generation-evaluation/live-test-plan.md`); `[V:<id> mm:ss]` — дайджест `91-videos/digests/<id>.md`;
`[проверено: B2/02]` — опыт `99-raw/experiments/B2/02-…`. Префиксы находок: `COPY-F-` сверка фактов, `COPY-L-` право,
`COPY-M-` маркеры слопа, `COPY-T-` набор, `COPY-D-` формат copy deck, `COPY-GEO-` GEO, `COPY-R-` рубрика, `COPY-C-`
чек-лист. Жанры — `landing`, `site-page`, `article`, `meta`, `geo`, `email-form`; интерфейс — `ux 07/06` по ролям. Id
типов страниц, ролей секций и слотов — временный словарь `99-raw/notes/temp-vocabulary-v0.yaml` (site `vocabulary.yaml`
ещё не выпустил). Два места базы расходятся — действует `CONTRADICTIONS.md`; одна норма в нескольких файлах — канон по
таблице дублей (`99-raw/reports/wave4-X-audit.md` §6). Утилиты запускаются из корня базы системным `python3` с PyYAML;
jsonschema — venv `99-raw/tools/venv-{B1,B2,F,J}`; сеть и модели не нужны.

### Сценарий 1. Написать тексты новой страницы

1. **Бриф → вопросы.** Промт `09-ai-generation-evaluation/prompts/p1-brief-intake.md`: факты с дословной цитатой, пробелы,
   ≤ 7 вопросов с умолчаниями; проверка — `python3 ../../scripts/text/check_intake.py intake.yaml
   --brief brief.txt`. Что спросить первым — `02/01` §5.3.
2. **Факты.** Анкета `02-strategy-messaging/proof-intake.md` → `facts.yaml` по `02/facts.schema.yaml` (образцы —
   `02/examples/facts-*.yaml`); `python3 ../../scripts/text/claims_check.py lint-facts facts.yaml` — 0 error. Правила — `02/03`
   §2, §4; голос клиента — `02/04` и `02/voc.schema.yaml`.
3. **Смысл.** `prompts/p2-meaning.md` → `meaning.yaml` по `02/meaning.schema.yaml`; читать `02/01` (позиционирование).
4. **Иерархия под трафик.** `prompts/p3-hierarchy.md` → одна иерархия на уровень осведомлённости
   (`02/message-hierarchy.schema.yaml`, `02/02` §1–§4). Проверка: `99-raw/tools/venv-B1/bin/python
   ../../scripts/text/validate_any.py meaning.yaml hierarchy.yaml`; сверка с фактами до текста —
   `python3 ../../scripts/text/chain_inputs.py meaning-claims --meaning meaning.yaml --hierarchy
   hierarchy.yaml -o mc.yaml` → `python3 ../../scripts/text/copydeck.py claims mc.yaml --facts facts.yaml`.
5. **Голос.** `voice.yaml` по `05/voice.schema.yaml` (образцы `05/examples/voice-*.yaml`, вывод голоса — `05/01` §3);
   `99-raw/tools/venv-F/bin/python ../../scripts/text/validate_voice.py voice.yaml`; редполитика —
   `05/redpolicy-template.md`.
6. **Тексты по слотам.** `prompts/p4-section-copy.md` (секция за вызов) по правилам `04/copy-slots.yaml` и `04/01–02`;
   тип страницы — `04/03`; письма вокруг формы — `04/04`; истории — `05/03`; мета, OG и FAQ — `prompts/p5-meta-geo.md`,
   `07/02` §4, `07/meta-rules.yaml`; GEO-слой — `07/03`, `07/geo-checklist.yaml`; право — `08/01` (отрасль →
   `legal_category`); набор — `08/02`. Формат — `10/copy-deck.schema.json`, образцы — `10/examples/*.yaml`.
7. **Проверки, выбор, утверждение, выгрузка** (`10/01` §1–§4, §7; ключи команд — `10/README.md`):

```bash
T=../../scripts/text/copydeck.py
python3 $T check deck.yaml --facts facts.yaml                           # claims → lint → validate; error → сценарий 3
python3 $T check deck.yaml --all-variants --update out/d.var.yaml         # каждый живой вариант «как выбранный» → variant.checks
python3 $T export-variants out/d.var.yaml -o out/sheet.md --key out/key.yaml --seed 1   # слепой лист A/B/C для человека
# выбор человека — правкой YAML: chosen + selection {method, by, at, compared, tally, ref} (команды apply-selection нет)
python3 $T check out/d.var.yaml --update out/d.checked.yaml --promote    # draft → checked при 0 error, text_hash
python3 $T approve out/d.checked.yaml --page PAGE --by "заказчик" -o out/d.approved.yaml   # только человек
python3 $T validate out/d.approved.yaml --final                          # 0 заглушек, мета заполнена, approved
python3 $T export-kimi out/d.approved.yaml --page PAGE --strict --out out/pkg --merge-into brief.yaml
python3 $T export-assets out/d.approved.yaml --page PAGE -o out/assets-plan.yaml   # alt, подписи, строки в картинке
```

   Пакет kimi дальше — `build_package.py build` и `check` в копии шаблонов kimi (`10/01` §7; Kimi не запускается).
   Собранную страницу с copy deck сверяют глазами: команды `verify-page` нет (спецификация — `10/01` §9).
8. **Второй язык** — отдельный copy deck `adaptation` со своим `facts.yaml` на языке страницы (`10/01` §6, `10/03`).

### Сценарий 2. Проверить готовые тексты

Порядок — факты и право → стиль → формат → рубрика и судья → человек (X1).
1. Нет `facts.yaml` — собрать минимальный из материалов заказчика (`02/03` §4). Без него `claims_check.py` работает в
   режиме аудита права: правила с условием факта становятся вопросами.
2. `python3 ../../scripts/text/claims_check.py check page.md --facts facts.yaml --legal-category general --md out/claims.md`
   (отрасль — `medical`, `finance`, `dietary-supplements`, `alcohol`, `education`, `real-estate`; профиль ЕС или США —
   `--jurisdiction eu|us`). Error — блокер. `copy.md` kimi — сначала `python3 ../../scripts/text/copydeck.py import-kimi copy.md
   -o deck.yaml --brief brief.yaml`.
3. `python3 ../../scripts/text/copy_lint.py page.md --genre landing --md` (жанр — один из шести; у copy deck — из `page_type`;
   морфология — интерпретатором `99-raw/tools/venv-C/bin/python`). **Вердикт на целой странице без copy deck строже,
   чем по слотам**: пороги D сняты по слотам (у лидеров корпуса `rewrite` — 16 из 24 EN и 11 из 14 RU); аудит страницы
   — сигнал, а не приговор (калибровка К5 аудита X).
4. Copy deck — всё сразу: `python3 ../../scripts/text/copydeck.py check deck.yaml` (+ `--all-variants`); прямые прогоны п. 2–3
   — контроль (прямой линтер не читает `meta.fact_ids`, `10/01` §2.2).
5. Рубрика и судья — только после 0 error: `09/copy-rubric.yaml` (12 критериев `COPY-R-…`), промт
   `prompts/p7-judge.md`, балл — `chain_inputs.py judge-score`; чек-лист — `09/copy-checklist.yaml` (32 пункта `COPY-C-…`).
   Судья — сигнал: статус меняют ворота и человек.
6. Человек — голос, естественность, «интересно», выбор вариантов вслепую; флаги права высокого риска — юрист (COPY-C-34).

Читать: `09/03` (карта оценки: ворота, сигналы, только человек), `06/01` (93 маркера по жанрам), `08/01` §12.

### Сценарий 3. Исправить сгенерированный текст

1. Находки — из `copydeck.py check` (или п. 2–3 сценария 2): сверка и право (`COPY-F-…`, `COPY-L-…`) → слоп
   (`COPY-M-…` и id словарей) → набор (`typo-…`, `COPY-T-…`) → формат (`COPY-D-…`).
2. Правка по протоколу `prompts/p6-edit-findings.md` (C `06/02` §9, I `09/02` §4): проход 1 — все error до нуля (число
   без факта → `fact_ids` или `[PLACEHOLDER]` + вопрос заказчику, другое число не подставлять); проходы 2–3 — warning
   кластерами; порядок — удалить → заменить фактом → сказать проще; после каждого прохода — `copydeck.py check` целиком;
   четвёртого прохода нет — остаток человеку.
3. Правка — новый вариант слота, старый — `rejected` с `reason`, запись `edit_log` (`10/01` §5.1).
4. Ложная находка линтера — `lint_allow: [{rule, reason}]` в слоте; находки сверки, права и формата так не снимаются —
   только правкой текста или `facts.yaml` (`10/01` §5.2). `COPY-F-USE` на мета, FAQ, статье — ограничение формата фактов
   B2: читать, текстом не лечить (X11).
5. Вердикт `overcorrected` — вернуть связки, а не добавлять приёмы (`06/01` §13).
6. Страницу целиком не перегенерировать: новая генерация приносит новые выдумки; секцию — только при error в половине
   слотов (`prompts/p4-section-copy.md`, `[мнение]`).

Пары «наивно → по правилам»: `10/before-after.tsv` (540 пар с колонкой `evidence`), таблица сбоев `09/02`, пример
«модель → как надо» у каждого маркера `06/01`.

## Выжимка: 59 правил по этапам конвейера «бриф → смысл → copy deck → проверка»

Метки — раздел «Метки и что ненадёжно». В основном блоке метки не слабее `[консенсус]`, `[проверено]`, `[стандарт]`,
`[документация]` (у составного правила — метка каждой части); числа `[кейс]` — только как механизм; `{…}` — жанры (нет
скобок — все); `→` — файл и раздел. Практика и мнение — отдельный блок в конце.

**Бриф: факты и вопросы**

1. **Любое число, имя, дата, цитата, логотип, рейтинг, цена, гарантия — запись `facts.yaml`** с источником вне модели и
   `source.quote`; нет записи — `[PLACEHOLDER: что именно]` + `missing`; вывод агента — вопрос, не факт («сборка в Казани»
   из «стартап из Казани»). `[стандарт: 38-ФЗ ст. 5 ч. 3]` `[проверено: B2/02]` → `02/03` §4, §7
2. **Главное сообщение — только после фактов**: бриф даёт 6–24 % утверждений смысла, анкета — ещё 27–31 %, без неё смысл
   на 55 % из допущений; допущение → вопрос (≤ 7 в сообщении, у каждого умолчание — `[практика]`), не обещание.
   `[проверено: B1/01, B1/03, I/04]` → `02/01` §5.2–5.3; `prompts/p1-brief-intake.md`
3. **Доказательства — анкетой до текстов** (виды по типу страницы, разрешения, срок годности); пробел — `missing` с
   `fallback`: `placeholder` — заглушка, `rewrite-without` — текст без утверждения, `omit-block` — слот снят.
   `[практика]` `[проверено: I/04, J/07]` → `02/03` §2; `10/01` §1.3
4. **`never_claim` запрещает непроверенное, а не весь слой доказательств**; здоровье, лечебный эффект и доход запрещены
   по умолчанию — снимаются документом и юристом, у немедицинского товара — никогда. `[стандарт: 38-ФЗ ст. 5 ч. 5 п. 6]`
   `[практика]` → `02/03` §3, §4.6
5. **Смысл и иерархию сверяют с фактами до текста** (`chain_inputs.py meaning-claims` → сверка): в I/04 — 6 верных error
   до первого слова страницы («12 лет» ×4 из «с 2014 года», отзыв без разрешения, «бесплатно» без условия).
   `[проверено: I/04]` → `09/02` §1.3

**Смысл: осведомлённость, иерархия, голос**

6. **Уровень осведомлённости трафика задаёт тип первого экрана, порядок доказательств и длину аргумента** (most-aware —
   сделка, …, unaware — узнавание себя; при высоком уровне сторонние доказательства — первыми); **одна иерархия — один
   уровень**. `[практика]` (Шварц) `[проверено: B1/02]` {landing, site-page} → `02/02` §1.2–1.4, §2.5
7. **Блокеры закрываются до главного призыва** — секцией или строкой у кнопки («[утверждение], даже если [возражение]»),
   а не в FAQ в конце. `[проверено: B1/03]` {landing, site-page} → `02/02` §4.3; `04/01` §7
8. **Снятие риска — только действующие условия из фактов**, рядом и по оферте; щедрой гарантии малоизвестного бренда при
   высокой цене без подкрепления не верят. `[исследование]` `[стандарт]` {landing, site-page, email-form} → `02/02` §4.4
9. **Голос выводят, а не придумывают**: назначение → аудитория и цена ошибки → знакомость бренда → нормы категории →
   голос клиента; принцип = имя + ≥ 2 проверяемых правила + «каким не бывает». `[практика]` `[проверено: F/03]` →
   `05/01` §3
10. **Незнакомому бренду — тон формальнее середины**: неформальный стиль поднимает доверие к знакомому бренду (6,01 против
    5,47 из 7) и снижает к незнакомому (5,05 против 5,70); юмора нет в цене, условиях, гарантии, праве, согласиях.
    `[исследование]` {landing, site-page, email-form} → `05/01` §3.2, §5
11. **Голос не меняет факты и оговорки, но меняет длины**: три голоса сохранили 13 из 13 чисел и 5 из 5 оговорок, а
    дерзкий удлинил заголовки выгод на 41–87 % — длины перепроверяй. `[проверено: F/01]` → `05/01` §4.3

**Copy deck: первый экран и кнопка**

12. **Первый экран словами отвечает**: что это, для кого, какой результат, чем отличается, что сделать; при «мало текста и
    большая картинка» посетитель не понимает, туда ли попал (NN/g 2020). `[исследование]` `[практика]` {landing,
    site-page} → `01/01` §2.2; `02/02` §2.3; `04/01` §1
13. **Ядро первого экрана ≤ 40 слов** (заголовок + подзаголовок + кнопка + строка у кнопки + микродоказательство): так у
    100 % лидеров RU (p90 34) и 88–92 % EN; превышение — warning; у страницы кейса без `hero` правило молчит (X44).
    `[проверено: D/03]` {landing} → `03/02` §2.5; `04/copy-slots.yaml` (`composites.hero-core`)

    `[проверено: D/03, E/01]` {landing, site-page} → `03/02` §2.1; `04/01` §2.4
15. **Суть — в первых двух словах** заголовка, пункта, подписи ссылки: по 11 знакам назначение не угадали у 35 % ссылок, а

16. **Кнопка называет ближайшее следствие нажатия**: 1–4 слова в строку (RU ≤ 25 знаков, EN ≤ 22), одно имя главного

17. **Надзаголовок — только с информацией, не чаще чем у каждой третьей секции** (p90 лидеров 0,28; EN-ИИ — 0,86); капс

18. **Заголовки секций подряд пересказывают страницу** (outline-тест на лендинге инвертирован); заголовок секции — ответ
    на её вопрос, не ярлык «Наши преимущества». `[исследование]` `[практика]` {landing, site-page, article} → `01/01`

**Copy deck: доказательства, отзывы, истории**

19. **Текст не сильнее факта**: не больше («1 200+» при 1 146), не точнее, не о другом объекте, не шире по смыслу;
    округление — в безопасную сторону («больше 1 100»); точное или круглое убеждает сильнее — открыто (X16).

## Живая фаза

План — `09-ai-generation-evaluation/live-test-plan.md`: 83 гипотезы из строк «Что проверить» всех отчётов, пакеты LT-01…
LT-09. Первый заход — LT-01 (модели на русском), LT-02 (факты до текста и русская ИИ-сторона корпуса), LT-03 (правка по
протоколу), LT-04 (судья и рубрика), LT-05 (первый экран на людях); LT-06 (K3 и пакет) — если у заказчика сессия kimi.
Оценка первого захода с фазой 2 (`live-test-plan.md` §4.1): ≈ 4–7 тыс. ₽ на генерацию и судей, ≈ 10–11 млн токенов, 0–10 тыс. ₽ на панель
людей, 2,5–3,5 часа заказчика (цены polza и Анкетолога на 2026-09-24). Правила: одна переменная на тест, входы и промты
заморожены версией, сравнения слепые, трата — после сухого прогона (0 ₽) и согласия заказчика, решения — по заранее
записанным правилам (`live-test-plan.md` §6). K3 запускает только заказчик; платные сервисы (Главред, «Тургенев», Wordstat API) — только с
его ключами.

## Как обновлять

Новый источник, файл, дайджест, правило линтера или сверки, перезамер порогов, метки, библиография и пары «до / после» —
процедуры в `PLAN.md`, раздел «Как расширять базу». Коротко: правила — в YAML (`06/lexicon/`, `07/*-rules.yaml`,
`08/claims-rules.yaml`, `08/typography-rules.yaml`) с парой примеров и `source`, после — `copy_lint.py --selftest` и
`claims_check.py --selftest`; пороги — перезамером D (`99-raw/experiments/D/03-measure/run_final.sh`), не руками;
`04/copy-slots.yaml` и `10/before-after.tsv` — только скриптами; приёмка — `python3 ../../scripts/maint/orch_check.py all
--selftest-tools` и `../../scripts/maint/check_links.py`; скоропортящееся — с датой рядом.
