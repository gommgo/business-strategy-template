## 1. Принципы

- **Слепо и попарно.** Заказчик выбирает из пар вариантов одного слота, не зная модели и условия (`03-evaluation.md` §7).
- **Факты общие.** Все модели получают одинаковые `facts.yaml`, `meaning.yaml`, иерархию и правила; без фактов — только
  в тестах, где проверяется выдумка (LT-02).
- **Проверки по порядку базы** после каждой генерации: `claims_check.py` → `copy_lint.py` → рубрика; числа ошибок —
  часть результата, а не повод переписать до показа (кроме пакетов, где правка и есть переменная).
- **Журнал.** У каждого варианта — `source: model` и `generated` (модель, канал, версия промта, параметры, прогон), у
  слота — `selection` (метод, сравнённые варианты, голоса, ссылка на подсчёт); схема J `copy-deck.schema.json`.
- **Стоп.** Пакет останавливается, если после 20 пар интервалы всех вариантов пересекаются и доля «оба не годятся»
  ≥ 30 % — менять подход (смысл, факты), а не добирать голоса.

## 5. Процедура

1. **Подготовка (база, бесплатно):** брифы «Отвес», «Кварц» — готовы (B1, B2); SaaS-бриф с фактами собрать с заказчиком по
   `02-strategy-messaging/proof-intake.md`; промты шагов и судьи — фаза 2 (`prompts/`), версия в первой строке.
2. **Задания:** файлы заданий `polza-chat` для `../../../scripts/ai-media/mp_client.py` (сухой прогон по
   умолчанию); `mp_client.py estimate` — 0 ₽; смета заказчику; лимит ключа — вдвое выше сметы; бюджеты каналов по
   умолчанию 0 (ai-media 07 §4).
3. **Запуск:** только оркестратор по согласию заказчика, `mp_client.py batch … --live`; K3 — заказчик через kimi.
4. **Сбор:** ответы → варианты copy deck с `generated`; сразу `copydeck.py check` (claims → lint → validate; числа — в
   результат); лист слепого выбора без имён моделей — `copydeck.py export-variants` (J).
5. **Страница выбора:** варианты одного слота — одинаковые карточки или первые экраны сборки 1440 и 390 px; ключ вне
   страницы; 10 % повторов со сменой сторон, контрольная пара (испорченный вариант), одинаковая пара (адаптер kimi G/05 и
   `stand_run.py page` ai-media работают с картинками — текст отрисовать карточкой или адаптировать `build_page`).
6. **Голосование:** сессии заказчика по 10–15 минут, 1–2 вопроса («лучше решает задачу слота», «звучит как этот бренд»).
7. **Подсчёт:** `tally` — доли побед с Уилсоном, Брэдли — Терри, согласованность повторов, контрольные пары.
8. **Судья:** задания на те же пары (оба порядка, 3 повтора, два вендора); согласие — по образцу `asset_audit.py agree`.
9. **Решения:** по §6; запись — в отчёт живой фазы и в файлы базы (модели, рубрика, протокол) с датой.

## Частые ошибки

1. **Входы и промты не заморожены версией** — результат нельзя повторить; правка промта посреди пакета — новый тест.
2. **Разные входы у моделей** (одной — факты, другой — нет): сравнивается вход, а не модель.
3. **Имена моделей или разная длина вариантов на странице выбора** — выбирают бренд и длину.
4. **Голоса вместо задач:** 40 голосов по двум парам ничего не говорят о модели; нужно 20–40 разных пар.
5. **Судья из семейства генератора, один порядок, один прогон** — самопредпочтение, позиция и случайность вместо оценки.
6. **Калибровка на текстах, которые оценщик уже видел, с видимыми брендами** — набор D2 угадан 10 из 10 (I/03).
7. **Трата без сухого прогона и сметы;** лимит ключа выше бюджета заказчика.
8. **Решение по впечатлению** вместо правила из §6, записанного до запуска.
9. **Панель без отбора по аудитории** для B2B — ответы не тех людей.

## Чек-лист

1. Входы и промты заморожены версией, у каждого варианта есть `generated`?
2. В тесте меняется одна переменная?
3. Сухой прогон `mp_client.py estimate` сделан, смета согласована с заказчиком, лимит ключа выставлен?
4. Страница выбора без имён моделей, с 10 % повторов, контрольной и одинаковой парами?
5. Варианты слота одной длины?
6. Судья другого вендора, оба порядка, 3 повтора, версии рубрики и промта записаны?
7. Набор для калибровки новый, бренды и мета скрыты?
8. Решающие правила §6 записаны до запуска?
9. Итоги записаны в copy deck (`selection`, `checks`) и в отчёт живой фазы с датой?

## Открытые вопросы

1. SaaS-бриф для LT-01 — собрать новый с заказчиком или взять демо «Смена» (kimi G/05) и дописать факты.
2. Панель: Анкетолог достаточен для B2C-лендингов; для B2B (SaaS) узкая аудитория может не набраться — своя база
