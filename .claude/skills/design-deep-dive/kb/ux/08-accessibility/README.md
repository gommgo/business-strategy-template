# 08 · Доступность как правила поведения интерфейса

Волна 2 · Агент F2 · 22 сентября 2026. Прочитано целиком 42 источника (полный текст WCAG 2.2, девять документов
Understanding, практики и 28 паттернов ARIA Authoring Practices Guide, 15 страниц туториалов W3C, COGA,
два отчёта WebAIM, отчёт Deque о покрытии автопроверок, состав правил axe-core 4.13, GOV.UK, Sara Soueidan,
Adrian Roselli, Heydon Pickering, NN/g, MDN) плюс один видеодайджест.

Папка переводит доступность с языка стандарта на язык правил для того, кто строит интерфейс: что должно быть у
каждого компонента и экрана, чтобы им могли пользоваться с клавиатуры, со скринридером, при увеличении, при
ограничениях движения, зрения, внимания и слуха, — и как это проверить.

**Границы.** Числовые таблицы контраста, палитры для тёмной темы, шкалы размеров и высоты контролов — в соседней
базе `../../ui/` (`01-color/`, `03-spacing-sizing/`, `04-shape-elevation/`, `08-motion/`). Здесь даются
только пороги стандарта, условия их применения и ссылка.

## Выжимка папки

1. **Целевой уровень — WCAG 2.2 AA: 55 критериев (31 A + 24 AA).** AAA как политика продукта не берётся: стандарт
   прямо это не рекомендует. Соответствие считается **для страницы целиком, для процесса целиком и для каждой
   вариации страницы на каждом брейкпоинте**. `[стандарт]`
2. **Шесть новых критериев 2.2 перестали быть «на будущее»**: с 2 сентября 2026 они входят в EN 301 549 v4.1.1,
   европейский стандарт под European Accessibility Act. Дешевле всего они закрываются в дизайн-системе: размеры
   целей, альтернативы перетаскиванию, видимость фокуса, единое место помощи, сохранение введённого, экран входа
   без капчи и с разрешённой вставкой. `[исследование]`
3. **Автоматика закрывает около 57 % дефектов по объёму, но лишь около 32 % критериев**, и по четырнадцати критериям
   A/AA даёт ровно ноль: порядок фокуса, видимость фокуса, нетекстовый контраст, порядок чтения, reflow, назначение
   ссылок, заголовки и подписи, всплывающий контент, пауза движения, ловушка фокуса, медиа. axe-core 4.13 знает
   **одно** правило для WCAG 2.2. Ручной протокол обязателен. `[исследование]`
4. **Доступность не возникает сама и не чинится в конце.** У фронтирных моделей разброс Inaccessibility Rate 0,13–0,45
   при одинаково «нормальном» виде; починка отчётом аудитора снижает IR 0,40 → 0,32, но вносит новые нарушения, а
   отбор лучшего из восьми вариантов по метрике даёт 0,40 → 0,14. Порядок: требования на входе → k вариантов →
   автопроверка → отбор → ручной проход. `[исследование]`
5. **Сначала нативный элемент, потом ARIA.** Роль — это обещание клавиатурного поведения. На страницах с ARIA в
   среднем 59,1 обнаруженной ошибки против 42 без неё; 22 % ARIA-меню создают барьеры. В режиме высокой
   контрастности системные цвета выбираются по нативной семантике, а не по ARIA: `<div role="button">` не станет
   выглядеть кнопкой. `[исследование]`
6. **Tab между компонентами, стрелки внутри компонента.** Один tab stop на весь тулбар, меню, радиогруппу, вкладки,
   грид, дерево. `tabindex` больше нуля запрещён; порядок меняется перестановкой в DOM. Фокус всегда где-то есть:
   удалили строку — перевести на соседнюю, закрыли диалог — вернуть на триггер, сменили маршрут в SPA — сменить
   `<title>` и увести фокус на `h1`. `[APG]`
7. **Видимый индикатор фокуса задаётся глобально, один раз, до написания компонентов.** Дефолт браузера формально
   проходит критерий, но измеренный контраст доходит до 1,4:1 на цветных кнопках. Рабочий рецепт:
   `:focus-visible { outline: 3px solid black; box-shadow: 0 0 0 6px white; }` — чёрное держит светлый фон, белое
   тёмный, `outline` переживает forced-colors и не двигает раскладку. `[консенсус]`
8. **Заголовки важнее лендмарков**: 71,6 % пользователей скринридеров ищут информацию по заголовкам и только 3,7 % —
   по лендмаркам. При этом 41,8 % страниц в вебе пропускают уровни, а `<main>` есть меньше чем на половине.
   Нужны и заголовки, и лендмарки, но бюджет внимания тратится на заголовки. `[исследование]`
9. **Живая область — последнее средство.** Сначала состояние ARIA (`aria-expanded`, `aria-pressed`), затем
   предупреждающая подсказка заранее («изменение фильтров меняет список»), затем перевод фокуса, и только потом
   `aria-live`. Живая область не передаёт разметку и не достижима фокусом, поэтому уведомление с кнопкой — это
   диалог, а не тост. На странице держат ровно две области: одну assertive, одну polite. `[консенсус]`
10. **Соответствие — не определение удобного продукта.** «Accessibility is a necessary, but not nearly sufficient,
    objective»; 67 % пользователей скринридеров никогда или редко сообщают о встреченном барьере, поэтому отсутствие
    жалоб ничего не значит. Дешёвая проверка: час с четырьмя-пятью сотрудниками с инвалидностью **на их собственных**
    вспомогательных технологиях. `[мнение]` + `[исследование]`
