# 10 · Дизайн-системы и консистентность

Волна 3 · Агент H · 22 сентября 2026. Проверено собственными запросами: каталог из 95 дизайн-систем
(component.gallery), индексы паттернов GOV.UK / Carbon / Primer, наличие `llms.txt` у 17 доменов, лицензии и
статус архивации 14 репозиториев (GitHub API). Плюс три статьи NN/g, прочитанные целиком, шесть
видеодайджестов и материалы по документации систем из файлов агентов D1, D2, F2.

Папка отвечает на два вопроса: **откуда брать правила** и **как не дать интерфейсу расползтись**. Числовые
значения дизайн-систем (цвет, типографика, отступы, радиусы, тени, брейкпоинты, размеры компонентов) — в
соседней базе `../../ui/10-design-systems-atlas/` и `09-design-tokens/`; здесь только UX-содержание.

## Выжимка папки

1. **«Дизайн-система» по умолчанию означает библиотеку компонентов, а не руководство по UX**: из 95 систем
   каталога только 55 документируют применение, 27 — доступность, 20 — тон, и лишь 2 приводят исследования.
   `[данные]` → 01 §3.1
2. **Композиций уровня страницы нет ни в одном каталоге** — page header, app shell, split view, inspector,
   master-detail, settings page. Их состав агент задаёт сам, в брифе. `[данные]` → 01 §3.3
3. **Админочные экраны — белое пятно всех систем**: настройки, матрица прав, аудит-лог, имперсонация,
   переключение организаций, командная палитра не описаны нигде; правила берутся из документации продуктов и
   помечаются `[система]`. `[данные]` → 01 §5.3
4. **Ранжируй источники и проверяй, жив ли источник**: репозиторий > пакет > реальное приложение > сайт >
   файлы; на 22.09.2026 репозитории Salesforce Lightning и Polaris React архивированы, у Atlassian публичного
   репозитория нет. `[данные]` → 01 §2
5. **Разным темам — разные источники**: формы и типы страниц — GOV.UK (30 паттернов); данные и универсальные
   паттерны — Carbon (14); деградированные состояния и сохранение — Primer (10); адаптив — Material 3;
   клавиатура и ARIA — Radix/React Aria и W3C APG. `[данные]` → 01 §5.1
6. **Представление объекта определяется один раз** и переиспользуется в списке, карточке, поиске, селекте,
   уведомлении, крошке и ссылке; порядок первых трёх атрибутов не переставляется нигде, а разные типы
   различимы «с расфокусированным взглядом». `[мнение]` → 02 §2
7. **Один примитив на потребность; одно действие — одно имя; одно и то же — в одном и том же месте.** Это три
   правила, из которых выводится почти всё остальное. `[консенсус]` → 02 §3
8. **Консистентность не равна одинаковости.** Отличаться намеренно нужно в четырёх случаях: деструктивное
   действие, критичное предупреждение, смена режима, смена контекста. `[консенсус]` → 02 §5
9. **Проверенный стартер — главный механизм консистентности между генерациями**: первый экран и первый
   компонент задают палитру, типографику, кнопки и отступы для всего остального; инвентарь составляется до
   генерации, а не выводится из неё. `[система]` → 02 §8
10. **Валидность по системе не равна качеству**: экран, целиком собранный из компонентов системы, может быть
    плохим экраном. Проверка соответствия запускается **после** поиска решения, а не вместо него.
    `[практика]` → 02 §10.1
