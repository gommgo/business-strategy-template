## 1. Зачем этот документ

База `ux` не задаёт визуальных величин: там, где правило требует числа (контраст, кегль, отступ, высота контрола,
брейкпоинт, длительность анимации), файл даёт **минимум или порог** и ссылается на папку `../ui/`. Здесь собрано,
**какие значения от `ui` ждут** и где в `ux` они применяются, чтобы соседняя база могла проверить,
что эти значения у неё есть и не противоречат нашим минимумам. Плюс — дайджесты и транскрипты, которые по содержанию
относятся к визуальному слою и должны жить (или дублироваться) у соседей.

## 3. Сводная таблица размеров целей (позиция `ux`, `08/01 §12.4`)

| Источник | Значение | Контекст |
|---|---|---|
| WCAG 2.2, 2.5.8 (AA) | **24×24 CSS px** или зазор (круги Ø24 не пересекаются) | минимум стандарта для любого указателя |
| WCAG 2.2, 2.5.5 (AAA) | **44×44 CSS px** | повышенный уровень |
| Apple HIG | **44×44 pt по умолчанию, 28×28 pt минимум** (iOS, iPadOS, watchOS); macOS 28/20, tvOS 66/56, visionOS 60/28; зазор ≈ 12 pt вокруг элементов с рамкой, ≈ 24 pt — без рамки | `09-mobile/04-platform-conventions-and-browser-quirks.md` §2.8 |
| Material 3 | **48×48 dp** | тач как основной ввод |
| Hoober; NN/g | **7 мм** в центре экрана, **12 мм** в углах; NN/g — 1 см × 1 см | физические величины, `09-mobile/02-mobile-navigation-and-actions.md` §2.4 |
| Российская практика (Альфа-Банк, W12) | 44×44 pt «как самая допустимая норма» | [V:p0oiYcrbplw 1:28:02] |

Правило выбора остаётся в `ux` (24 с зазором — плотная админка под мышь; ≥ 32 — панели инструментов; ≥ 44 — тач,
основные и деструктивные действия). От `ui/03-spacing-sizing/` ждём **полные таблицы высот контролов и зазоров по
дизайн-системам**, согласованные с этими минимумами (ни одна высота интерактивного элемента в клиентском сервисе < 44 CSS px,
в плотной админке < 24 px с зазором ≥ 4 px).

## 4. Какие значения ждём — по папкам `ui`

Упоминаний по папкам-целям: `(корень)` — 32; `03-spacing-sizing` — 21; `01-color` — 12; `05-layout-grid` — 11; `02-typography` — 8; `06-components-visual` — 8; `12-ai-generated-ui` — 6; `09-design-tokens` — 5; `08-motion` — 5; `10-design-systems-atlas` — 3; `03-spacing-sizing, 06-components-visual` — 2; `04-shape-elevation` — 2; `13-evaluation-checklists` — 2; `03-spacing-sizing, 05-layout-grid` — 1; `01-color, 02-typography` — 1; `01-color, 06-components-visual` — 1; `01-color, 03-spacing-sizing, 05-layout-grid` — 1; `01-color, 03-spacing-sizing` — 1; `01-color, 03-spacing-sizing, 08-motion` — 1; `05-layout-grid, 03-spacing-sizing` — 1; `02-typography, 03-spacing-sizing` — 1; `12-ai-generated-ui, 11-styles-trends` — 1; `09-design-tokens, 01-color` — 1; `11-styles-trends` — 1; `09-design-tokens, 99-raw` — 1; `14-recipes` — 1.

### `01-color`
Наши пороги: контраст текста 4.5:1 (AA) и 3:1 для крупного текста и графики (`08/01 §5`), статус APCA/WCAG 3 — только ориентир
(`08/01 §14`); ошибка ≠ предупреждение по цвету и не только цветом (`05/04 §2.2`); красный — только на финальном подтверждении
(`05/03 §4.3`); цвет статусов и состояний (`06/01`); контраст линий и заливок графиков (`04/03 §7.5, §10`); матрица контраста
всех пар в тёмной теме (`08/04 §4.2`, дефект F9.5 в `11/01`). **Ждём:** палитры с рассчитанными парами «фон — текст» по токенам,
матрицу тёмной темы, палитры графиков с контрастом ≥ 3:1 для линий и заливок, статус APCA; утилиту расчёта `99-raw/tools/color.py`
(на неё ссылается `12/03 §3.3`).

### `02-typography`
Наши пороги: кегль основного текста на телефоне **≥ 16 px** (порог зума iOS, `09/03 §3.4, §7.1`); длина строки **45–75 знаков**
(цель 60–70) на широком экране и **40–60** на узких (`03/02 §4`, `09/01`); табличные цифры для больших чисел (`06/01 §6.2`);
системный стек SF / Roboto в вебе задаётся продуктом (`09/04 §1.2`); типографические шкалы как инструмент иерархии (`03/03 §2.1`);
поза (posture) → кегль и плотность (`09/01 §6`). **Ждём:** шкалы кеглей и интерлиньяжа по системам, правила табличных цифр,
системные стеки, привязку шкалы к плотности.

### `03-spacing-sizing`
Наши пороги: одна шкала отступов **8/4** (`03/02 §1.4, §7.3`); расстояние между группами заметно больше, чем внутри (`01/01 §9`,
`04/05 §2.4`); плотность — режим на продукт и функция доступности (`03/02 §5.1`, `04/01 §4.1`, `08/04 §3.2`); высоты полей Carbon
32 / 40 / 48 px как ориентир (`04/06 §2.4`); ширины полей по длине ожидаемого ввода (`04/05 §2.3`), `maxlen` считается от ширины
компонента (`07/05 §4.6`); размеры целей — раздел 3; закон Фиттса без чисел (`01/01 §4.2`, `01/02 §12`). **Ждём:** полные таблицы
высот контролов, отступов и зазоров по системам, пресеты плотности (compact / default / comfortable) с числами, ширины полей по типам.

### `04-shape-elevation`
Наши требования: кольцо фокуса видимо всегда (толщина, цвет, смещение — у соседей; `08/02`); слои состояний hover/pressed/selected
(`06/01 §7.2`); скругления — правила Бирмана (раздел 2). **Ждём:** значения индикатора фокуса, проходящие 2.4.11/2.4.13, state
layers, шкалу радиусов с правилом вложенности.

### `05-layout-grid`
Наши пороги: брейкпоинты — именованные диапазоны как словарь правил перестроения, проверка на произвольных ширинах (`09/01 §4.1`
`[спорно]`, `10/02 §4.3`); регионы каркаса и ширина боковой панели ~400 dp (`02/02 §1.1`); высоты «хрома» страницы (`03/03 §7.2`);
ширины страницы и master-detail (M3: medium 50/50, expanded 360 dp, large/XL 412 dp — `03/01`). **Ждём:** числовые таблицы
брейкпоинтов, сеток, полей и промежутков по системам; высоты шапок и панелей.

### `06-components-visual`
Наши требования: ширины колонок таблиц и высоты строк (`04/01 §3.5, §4.1`), ширины полей (`04/05 §2.3`), кнопки — размер и цвет
(`05/03 §4.3`, `05/03` шапка), визуальные состояния и скелетон как графика (`06/01`), переключатели и радиусы контролов (`04/06`),
оверлеи для веб-админок (`04/07` ov). **Ждём:** спецификации компонентов с числами, согласованные с контрактом состояний
`06/01 §7.2` (11 состояний).

### `07-iconography-imagery`
Иконки действий и символы — визуальный слой консистентности (`10/02 §1.3` → `03/03`). **Ждём:** правила размера и подписи иконок,
согласованные с запретом иконок без подписи в навигации (`13/02` чек-лист 2).

### `08-motion`
Наши пороги: длительности 100–300 мс как ориентир, `prefers-reduced-motion` обязателен, ничего не мигает > 3 раз/с, автодвижение
> 5 с — с паузой (`06/03 §3.1, §7`, `08/04 §3.4`); пружинные параметры не разобраны (`06/03` ov). **Ждём:** таблицы токенов
движения (длительность, кривые, пружины) и правило деградации при reduced-motion.

### `09-design-tokens`, `10-design-systems-atlas`
Токены — контракт, произвольные значения запрещены и проверяются линтером (`10/02 §8.3`, `11/04 §1.3`, `12/02` UX-BLD-10, `12/03 §3.3`);
числа по системам — у соседей (`10/01 §1, §5.1`). **Ждём:** набор токенов и шкал, который возвращается в контракт генерации
(`13/04` шаг 25 → шаг 26), и атлас значений по системам (Material 3, Apple HIG, Carbon, Primer, Polaris, Atlassian, Spectrum, Ant).

### `11-styles-trends`, `12-ai-generated-ui`, `13-evaluation-checklists`, `14-recipes`
Визуальная часть «слоп-эстетики» (`11/01 §15, §17`, F2.5, F9.5; `13/03`; `12/02` UX-AIG: карточки с одним радиусом и тенью,
ALL-CAPS eyebrow, градиенты как декор); визуальные рубрики (`12/01 §7.8`); пресеты плотности по типу приложения и постуре
(`13/04` шаг 3–4 → `14-recipes`). **Ждём:** чек-лист визуальных дефектов генерации, согласованный с блоком AIG, и рецепты
плотности по постурам.

## 5. Что вернуть в `ux`

1. Подтверждение или поправку минимумов из разделов 3–4 (размеры целей, 16 px, длина строки, шкала 8/4, 24/44/48).
2. Список токенов и шкал для брифа на визуальный слой (`13/04` шаг 25): формат, в котором они попадают в блок «Дизайн-система»
   контракта генерации (шаг 26).
3. Решение по дайджестам раздела 2: кто пишет дайджесты четырёх русских транскриптов; ссылки на них из `10-design-systems-consistency/`.
4. Сверку `CONTRADICTIONS.md` соседней базы с реестром противоречий в `README.md` `ux` по темам: размеры целей,
   брейкпоинты, длина строки, плотность, порядок кнопок (визуальная часть).
