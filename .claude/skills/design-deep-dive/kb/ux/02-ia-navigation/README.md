## Выжимка папки

1. **Сначала IA, потом навигация.** Каркас «верхняя панель + левый рельс» вмещает не более 4 уровней; выбирать
   его до описания структуры — значит потом резать структуру под него. `[консенсус]`
2. **«7±2» к навигации не применяется.** NN/g прямо: больше 7–9 пунктов верхнего уровня — нормально, 13 пунктов
   в вертикальном меню работают. `[исследование]`
3. **Плоская иерархия лучше глубокой при прочих равных**; длинный список группируют визуально внутри уровня, а
   не дробят на подуровни. Три уровня — рабочий потолок приложения. `[исследование]`
4. **Разделы — существительные во множественном числе, действия — глаголы**; понятное слово выигрывает у
   умного, категории не должны пересекаться, «Разное» — симптом незаконченной IA. `[исследование]`
5. **Для веб-приложения главная навигация по умолчанию слева**: таблица ожидаемых мест NN/g — «Applications:
   Left side of the screen». `[консенсус]`
6. **Скрытая навигация на десктопе стоит дорого**: использование 27% против 48%, находимость −20%, время задачи
   +39%, субъективная сложность +21%. `[исследование]`
7. **Один путь к разделу.** Дублирование пунктов в двух панелях «не нужно и потенциально запутывает»; если два
   дубля видны одновременно — избыточности слишком много. `[исследование]`
8. **Ориентирование (wayfinding) держится на трёх элементах**: активное состояние пункта, хлебные крошки,
   заголовок страницы. Неуказание текущего места — самая частая ошибка меню. `[консенсус]`
9. **Крошки не нужны при иерархии в 1–2 уровня**, показывают иерархию, а не историю, и не соседствуют с
   кнопкой «Назад». **Вкладки** — один ряд, 2–7 штук, подписи 1–2 слова, над панелью, не для шагов и не для
   сравнения. `[консенсус]`
10. **Каркас приложения (app shell) = полосы + рейки + панели**; правая рейка — панель-инспектор со свойствами
    выбранного объекта. В Material 3 «window size classes» с мая 2026 называются **breakpoints**:
    compact <600, medium 600–839, expanded 840–1199, large 1200–1599, extra-large ≥1600 dp. `[система]`
