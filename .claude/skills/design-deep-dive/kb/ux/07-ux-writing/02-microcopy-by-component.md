# Микрокопи по компонентам: формулы, примеры, ограничения

Волна 3 · Агент G · 22 сентября 2026.

Справочник формулировок. Для каждого компонента: формула, ограничение длины, примеры «делай / не делай» по-русски и
по-английски, что запрещено. Механика компонентов (где показывать, когда валидировать, какой контейнер выбрать) —
в `../04-components-patterns/`, `../05-flows-journeys/`, `../06-feedback-states-motion/`; здесь только тексты.
Принципы, из которых выведены формулы, — `01-principles-voice-and-tone.md`. Русская грамматика и типографика —
`03-russian-interface-text.md`. Английские конвенции — `04-english-interface-text.md`. Запреты — `06`.

## Выжимка для агента

1. **Кнопка = глагол + объект.** Исключения — общеизвестные односложные действия в контексте («Отмена», «Готово»,
   «Закрыть») и кнопка в модалке, где объект назван в заголовке. `[консенсус]` → §1.1
2. **У кнопки ровно три законные функции**: команда, навигация (название того, что откроется), назначение статуса
   объекту. Подпись вне трёх категорий — сигнал ошибки. `[мнение]` → §1.2
3. **«OK» запрещено как подтверждение действия**: «OK is an exclamation, not an action». Допустимо только в чисто
   информационном сообщении, и лучше «Понятно» / «Закрыть». `[консенсус]` → §1.4
4. **Русская кнопка — инфинитив совершенного вида** («Что сделать?»): «Сохранить», не «Сохраните» и не
   «Сохранение». `[система]` → §1.3
5. **Деструктивная кнопка называет действие с объектом**: «Удалить проект», не «Подтвердить», не «Да».
   `[консенсус]` → §1.5, §6
6. **Ссылка называет назначение и не бывает «здесь», «тут», «подробнее», «click here»**; скринридер выводит список
   ссылок отдельно от текста. Длина 2–3 слова. `[консенсус]` → §2
7. **Подпись поля — 1–3 слова, существительное, без двоеточия и без призыва**: «Фамилия», не «Введите фамилию».
   `[консенсус]` → §3.1
8. **Плейсхолдер — только пример значения**, дублированный снаружи поля; без глаголов «введите», «укажите»; не
   дублирует подпись. `[консенсус]` → §3.2
9. **Подсказка под полем — одно предложение без точки**, отвечает на вопрос «где это взять» или «в каком формате».
   Ссылок внутри подсказки нет. `[система]` → §3.3
10. **Заголовок экрана — группа существительного**, глагол живёт на кнопке. Разные состояния одной формы различаются
    кнопкой, а не заголовком. `[мнение]` → §4
11. **Пустое состояние: заголовок утвердительно + что здесь появится + одно действие.** «Здесь пусто» и «Нет данных»
    без продолжения запрещены. Четыре причины пустоты — четыре разных текста. `[консенсус]` → §5
12. **Ошибка: что случилось + почему + что сделать.** Без кода, без «неверно», без «что-то пошло не так», без точки
    в конце, без восклицательных знаков, без капса. Шаблоны по типу нарушения. `[консенсус]` → §6
13. **Подтверждение: заголовок — вопрос с именем объекта; тело — одна строка с последствием; кнопки — результат
    каждого варианта.** «Вы уверены?» запрещено. `[консенсус]` → §7
14. **Тост — одна строка результата, без точки, с «Отменить», если действие обратимо.** Тост не годится для
    ошибок и для текста, который нужно успеть прочитать. `[система]` → §8
15. **Тултип — 1–2 предложения; критичного в тултипе нет.** Требования к паролю в тултипе — дефект.
    `[консенсус]` → §9
16. **Описание настройки объясняет, что произойдёт при включении**; про выключенное состояние писать не нужно.
    `[система]` → §10
17. **Название статуса отвечает на вопрос «какой?» и снимает вопрос, а не создаёт его**: «В обработке банком», не
    «В обработке». Все статусы одного объекта согласованы между собой. `[практика]` → §11
18. **Все пункты одного меню отвечают на один и тот же вопрос.** Раздел — существительное во множественном числе.
    `[практика]` → §12
19. **Заголовок колонки — существительное 1–3 слова**, единица измерения в заголовке, а не в каждой ячейке.
    `[практика]` → §13
20. **Текст ожидания называет этап, а не извиняется**; обратный отсчёт только при точно известном сроке.
    `[исследование]` → §14
21. **403 / 404 / 500 внутри приложения — разные тексты**: одна страница на все ошибки запрещена. При 404 без
    автоматического редиректа, при 403 — ссылка на смену учётной записи, при 500 — извинение.
    `[система]` → §15
22. **Письмо начинается с дела**; метрика письма — совершённое действие, а не открытие. Push — до двух строк,
    действие в первых словах. `[практика]` → §16
23. **Обрезка: «показать ещё» называет, чего ещё**, и не прячет критичное; многоточие ставится системой, а не
    руками. `[практика]` → §17
24. **ИИ-функции: сгенерированное помечено, уверенность названа, источник показан, действие обратимо.**
    `[консенсус]` → §18
25. **Доступное имя иконочной кнопки = действие + объект**, alt-текст описывает содержание, а не «изображение».
    `[консенсус]` → §19
26. **Имя действия одно на весь поток** — кнопка, заголовок диалога, сообщение, статус (F7.3). `[система]` → §1.6

## 1. Кнопки

### 1.1. Формула

`{глагол} + {объект}` — Polaris [S1], Apple HIG [S2], Carbon, Primer, Контур [S5].

Polaris прямо: «use the {verb} + {noun} content formula on buttons except in the case of common actions like "Done",
"Close", "Cancel", or "OK"».

| Контекст | Формула | RU | EN |
|---|---|---|---|
| Кнопка на странице, объект не назван рядом | глагол + объект | «Сохранить черновик», «Добавить сотрудника» | «Save draft», «Add employee» |
| Кнопка в модалке, объект назван в заголовке | глагол | «Сохранить», «Удалить» | «Save», «Delete» |
| Кнопка в контекстной панели сохранения, статус рядом | глагол | «Сохранить» (статус слева: «Несохранённая скидка») | «Save» + «Unsaved discount» |
| Кнопка внизу длинной формы, контекста нет | глагол + объект | «Сохранить скидку» | «Save discount» |
| Общеизвестное действие | одно слово | «Отмена», «Готово», «Закрыть», «Далее», «Назад» | «Cancel», «Done», «Close», «Next», «Back» |

Длина: **1–3 слова**, Apple — «2–4 слова без артиклей» [S2], Atlassian в диалоге — 1–2 слова. **Кнопка не пишется в
две строки**: делать шире или менять название; сокращать название нельзя [S5].

**Правило Уолтер**: текст кнопки отвечает на вопрос «что произойдёт, если нажать». «Find my Panama» → «Search»;
«Keep me in the loop» → «Send me text alerts». Кнопка — не место для образных выражений: их не разберёт человек с
когнитивными нарушениями [V:2juq00vrvl0 19:33].

### 1.2. Три законные функции кнопки

`[мнение]` Бирман [V:6Vh49gMvirE 36:00] — готовый валидатор подписи:

| Функция | Что называет | Примеры |
|---|---|---|
| **Команда** | действие, которое произойдёт | «Купить», «Отправить», «Закрыть», «Опубликовать» |
| **Навигация** | то, что откроется | «Настройки», «Шрифты», «Участники» |
| **Назначение статуса объекту** | статус, который присвоится | «Спам», «В архив», «Избранное» |

Подпись, не попадающая ни в одну категорию, — сигнал ошибки. Пример допустимого исключения: кнопка как реплика
пользователя («Я согласен с условиями», «Я крут в PHP») — осознанное отступление, а не норма.

**Кнопка не может быть частью предложения.** «С правилами поведения на борту можно ознакомиться [Здесь]» — кнопка
«Здесь» бессмысленна [V:6Vh49gMvirE 28:49]. **Команда оформляется кнопкой, а не ссылкой и не жирным текстом**:
инструкция Pinterest, где «Download HTML verification file» выделено только жирным, читается как обращение, а не как
команда [V:6Vh49gMvirE 15:32, 29:51].

### 1.3. Форма глагола

`[система]` Контур [S5]: «Называйте кнопку инфинитивом в совершенной форме — название отвечает на вопрос „Что
сделать?“. Пользователь даёт команду компьютеру, ориентированную на результат, а не процесс.»

| Верно | Неверно | Почему |
|---|---|---|
| Сохранить | Сохраните | Повелительное наклонение — это система обращается к человеку, а кнопка — реплика человека [V:6Vh49gMvirE 13:26] |
| Сохранить | Сохранение | Существительное называет процесс, а не результат |
| Отправить отчёт | Отправка отчёта | То же |
| Посмотреть | Предпросмотр | Соседние кнопки согласуются по форме: «Предпросмотр» рядом с «Сохранить» — рассогласование [V:6Vh49gMvirE 49:24] |

Подробнее о выборе вида и о случаях, где несовершенный вид оправдан, — `03-russian-interface-text.md` §2.

Название кнопки пишется с заглавной буквы (первое слово), остальные строчные, если это не имя собственное.

### 1.4. Запрещённые подписи

| Запрещено | Почему | Чем заменить |
|---|---|---|
| **OK** | «OK is an exclamation, not an action» [S1]; «по привычке люди выберут её, не прочитав окружающий текст» (Apple, через D2) | «Понятно» (закрыть сообщение), «Закрыть», конкретный глагол |
| **Да / Нет** в подтверждении действия | Не называют результат; нужно прочитать весь текст | Глаголы обоих вариантов (см. §7.3 про спор) |
| **Submit / Отправить** без объекта | Системный язык; не говорит, что произойдёт | «Сохранить изменения», «Отправить заявку» |
| **Подтвердить** | Не называет действие | «Удалить проект», «Опубликовать» |
| **Подробнее** как единственная подпись | Неинформативно; кейс: замена на «Схема» позволила человеку не нажимать и сэкономить время [V:hDqJzydcHMc 15:26] | Называть, что откроется: «Схема этажа», «Условия тарифа» |
| **Здесь / Тут / Click here** | Кнопка не часть предложения; в списке ссылок скринридера бессмысленно [V:2juq00vrvl0 20:35] | Назвать назначение |
| **Нажмите …** | «Кнопка уже сама собой говорит „нажмите“» [V:6Vh49gMvirE 58:40] | Убрать слово |
| **Готово** для немедленного сохранения | «Done» зарезервировано за отложенным сохранением [S1] | «Сохранить» |
| **Сохранить** для отложенного применения | Вводит в заблуждение: изменения ещё не в базе [S1] | «Готово» |
| Милые и выдуманные названия | «Человеку не должно приходиться гуглить название команды» (Apple, через D2) | Обычное слово |
| **→** в конце подписи | Шаблонная обвязка генерации (F13.1, кластер 5) | Убрать |

### 1.5. Деструктивная кнопка

`[консенсус]`. Подпись называет само действие и объект: **«Удалить проект»**, не «Подтвердить», не «Да», не
«Продолжить». Безопасная альтернатива тоже называет результат: «Оставить файл», «Продолжить редактирование».

Polaris [S1] для удалений даёт пару `[Отмена] [Удалить]` и запрещает «Remove», «Erase», «Discard» в роли удаления —
одно слово на одно действие. Для отказа от изменений — `[Продолжить редактирование] [Отменить изменения]`, для ухода
со страницы — `[Остаться] [Уйти со страницы]`.

**Слово-замедлитель** вместо Yes/No, когда причина отказа неочевидна (позиция базы, синтез из E1
`../05-flows-journeys/03-destructive-actions-undo-confirmation.md` §4.6):
«Удалить всё равно», «Опубликовать без проверки», «Отправить без вложения».

### 1.6. Имя действия одно на весь поток

`[система]` — правило Anthropic, закрывает дефект F7.3. Таблица форм для генератора:

| Действие | Кнопка | Заголовок диалога | Кнопка диалога | Результат | Статус | Обратное |
|---|---|---|---|---|---|---|
| Публикация | Опубликовать | Опубликовать статью? | Опубликовать | Опубликовано | Опубликован | Снять с публикации |
| Удаление | Удалить | Удалить проект «Альфа»? | Удалить | Проект удалён | — | Восстановить |
| Отправка | Отправить | Отправить отчёт? | Отправить | Отчёт отправлен | Отправлен | Отозвать |
| Архивация | В архив | — (обратимо) | — | Перенесено в архив | В архиве | Вернуть из архива |
| Приглашение | Пригласить | — | Пригласить | Приглашение отправлено | Приглашён | Отозвать приглашение |

Carbon добавляет проверяемое правило (через D2, `../04-components-patterns/10-actions-menus-bulk-shortcuts.md`
§1.4): **заголовок модалки совпадает с подписью кнопки, которая её открыла** — «Создать группу доступа» открывает
окно «Создать группу доступа», а не «Создать группу».

### 1.7. Пары глаголов: словарь различений

`[система]` Polaris [S1] — самый полный найденный словарь. Русские эквиваленты — решение базы.

| Различение | Когда первое | Когда второе | RU |
|---|---|---|---|
| Save / Done | сохранение сразу в базу | отложенное применение (модалка вносит несохранённые изменения на страницу) | «Сохранить» / «Готово» |
| Close / Accept | подтвердить прочтение | юридическое согласие | «Закрыть» / «Принять» |
| Close / Cancel | режим только чтения | есть изменения, которые отменяются | «Закрыть» / «Отмена» |
| Select / Choose | выбор из ограниченного набора однородных, очевидное решение | субъективное, стратегическое решение (тема, тариф) | «Выбрать» / «Подобрать», либо оба «Выбрать» с разным контекстом |
| Edit / Manage | изменить содержимое поля | несколько действий или настройки раздела | «Изменить» / «Настроить» |
| Change / Switch | заменить вариант без правки его свойств | переключение между пользователями, аккаунтами, локациями (предыдущее выключается) | «Заменить» / «Переключиться на …» |
| Create / Add | создать с нуля | внести существующее | «Создать» / «Добавить» |
| View / See | в кнопке, CTA, ссылке | в разговорном описании | «Посмотреть» / «увидите» |
| Export / Download | с конвертацией формата | копия того же формата | «Экспортировать» / «Скачать» |
| Import / Upload | с конвертацией формата | файл того же формата | «Импортировать» / «Загрузить» |
| Need / Must | всегда | никогда | «нужно» / не «обязаны» |

Дополнение из D2 (`../04-components-patterns/10-actions-menus-bulk-shortcuts.md` §6): «Дублировать» создаёт копию
сразу, «Создать на основе» открывает форму с предзаполненными полями; «Архивировать» и «Отключить» не путать с
«Удалить».

**Главное правило словаря**: внутри продукта выбирается одно слово на действие. «Изменить» или «Редактировать», но
не оба.

### 1.8. Заблокированная кнопка

`[практика]` Фридман [V:AVKz9ZYoxgo 1:08:31, 1:16:36]:

- Заблокированная кнопка без объяснения — **полная ошибка**: часть людей не восстановится.
- **Не объяснять блокировку текстом внутри кнопки**: меняющийся текст создаёт шум для скринридера и «прыгает».
  Сообщение ставится рядом с кнопкой.
- Формулировка объяснения: называет недостающее условие и даёт путь. «Нельзя продолжить: сначала выберите тариф» +
  ссылка на блок. Не «Заполните все поля».
- Во время выполнения: подпись не меняется, спиннер ставится рядом или заменяет иконку; ширина кнопки не меняется
  [S5].

## 2. Ссылки

### 2.1. Формула

Ссылка называет то, куда ведёт или что запустит, и понятна **без прочтения окружающего предложения** [S5].

| Правило | Источник | Пример |
|---|---|---|
| Длина 2–3 слова | Контур [S5] | «Условия тарифа» |
| Вне предложения — {глагол + объект}, без пунктуации, кроме вопросительного знака | Polaris [S1] | «Посмотреть счета», «Забыли пароль?» |
| В предложении линкуется **только фрагмент, называющий назначение** | Polaris [S1] | «Избегайте расходов на чарджбэки с [Shopify Protect]» |
| Ссылка не ведёт на страницу, на которой находится | Контур [S5] | — |
| Кавычки включаются в ссылку, знаки препинания — нет | Контур [S5] | [«Альфа»], а не [«Альфа».] |
| Предлог включается, только если не меняет смысл | Контур [S5] | «перейти в [предыдущий пост]» |
| Два подряд идущих ссылочных фрагмента запрещены | Контур [S5] | — |
| В списке ссылкой делается вся строка | Контур [S5] | — |

**Причина правила «линковать фрагмент, а не фразу»** — интернационализация: «word order might change, which would
break the link into two parts» [S1]. Для русского это критичнее, чем для английского (`05-localization-and-i18n.md`
§4.3).

### 2.2. Запреты

| Запрещено | Почему |
|---|---|
| «Здесь», «тут», «по ссылке», «click here», «here» | Скринридер выводит список всех ссылок страницы: он превращается в «click here, click here, click here» [V:2juq00vrvl0 20:35] |
| «Подробнее» как единственный текст ссылки | Не различается среди других «Подробнее» на странице; Atlassian: «Ссылки описывают назначение: „О правах пользователей“, а не „Подробнее“» (через D2) |
| «Читать далее» | То же |
| Отдельное предложение «Подробнее о …» после текста, где уже можно залинковать ключевые слова | Повтор и трата места [S1] |
| Ссылка вместо кнопки для основного действия окна | Форма противоречит роли [S5], [V:6Vh49gMvirE 29:51] |
| Пунктирное подчёркивание | Пользователи не различают типы подчёркивания [S5] |

Исключение Polaris: отдельное «Подробнее о …» допустимо, **только если текст затрагивает больше одного понятия** и
надо выбрать одно для ссылки [S1].

### 2.3. Ссылка, открывающая новое окно

Открывать в новом окне — когда страница относится к побочному сценарию и важно не потерять текущую (справка, внешний
сайт) [S5]. Текст обязан предупреждать: «(откроется в новой вкладке)» — либо визуально, либо для вспомогательных
технологий. Правило доступности — `../08-accessibility/02-keyboard-focus-semantics.md`.

## 3. Поля формы

Механика (где подпись, когда валидировать, как помечать обязательность) — `../04-components-patterns/05-forms-and-validation.md`.
Здесь формулировки.

### 3.1. Подпись поля

| Правило | Пример «делай» | Пример «не делай» |
|---|---|---|
| Существительное или именная группа, 1–3 слова | «Фамилия», «Дата рождения», «Юридический адрес» | «Введите вашу фамилию» |
| Без призыва: «поле само по себе уже говорит, что с ним делать» [V:hDqJzydcHMc 26:43] | «Фамилия, имя, отчество» | «Введите фамилию, имя, отчество» |
| Без двоеточия | «Электронная почта» | «Электронная почта:» |
| Формулировка допускает ровно один тип ответа [V:hDqJzydcHMc 17:27] | «Вид деятельности» | «Для чего будет использоваться касса» (получает ответ «чтобы брать деньги с покупателей») |
| Слово из языка пользователя, не из базы данных | «Телефон» | «Мобильное устройство», «Контактный номер абонента» |
| Пометка обязательности словом, а не только звёздочкой | «Отчество (необязательно)» | «Отчество*» без легенды |

Для группы полей — заголовок группы отвечает на тот же вопрос, что и подписи внутри.

### 3.2. Плейсхолдер

`[консенсус]`: плейсхолдер **не заменяет подпись** и **не хранит ничего, что понадобится после начала ввода**.
Остаётся ровно одна функция — **пример значения или способа ввода**, продублированный снаружи, если он важен.

| Правило | «Делай» | «Не делай» |
|---|---|---|
| Пример значения без глагола [S4] | «ivanov@example.com» | «Введите адрес почты» |
| Не дублирует подпись [S4] | подпись «Дата», плейсхолдер «дд.мм.гггг» | подпись «Дата», плейсхолдер «Дата» |
| Не содержит инструкцию [S4] | «ИНН или название» | «Введите ИНН из 10 или 12 цифр либо полное наименование организации без кавычек» |
| Не содержит требований, которые нужны при вводе | требования к паролю — в подсказке под полем | требования к паролю в плейсхолдере |
| Примеры анонимизированы (Carbon, через D2) | «ivanov@example.com» | реальный адрес сотрудника |

Контур формулирует назначение точнее всех [S4]: подсказка-плейсхолдер отвечает на вопросы «какими способами можно
ввести данные», «по каким реквизитам работает поиск», «как отформатировать данные, если поле не делает это
автоматически», «где найти нужные данные». И: **«Подсказка не нуждается в глаголах „введите“, „укажите“,
„заполните“, так как ввод следует из контекста»**.

### 3.3. Подсказка под полем (hint, helper text)

`[система]` GOV.UK, Carbon, Контур:

- **Одно короткое предложение, без точки в конце.**
- Видна всегда, в том числе при фокусе и после ввода.
- Отвечает на вопрос «где это взять», «в каком формате», «как это будет использовано».
- **Ссылок внутри подсказки нет**: скринридер прочитает текст ссылки, но не скажет, что это ссылка (GOV.UK, через
  D2).
- Одна подсказка на одно правило; не повторять одинаковую подсказку под каждым полем.
- Если объяснение не помещается в предложение — это не подсказка: выносить отдельным блоком текста или под ссылку
  [S4].

Разграничение слоёв помощи [V:hDqJzydcHMc 27:43]: **то, что непонятно всем, — в описание поля; частное и
ситуативное — в подсказку по требованию**.

| Слой | Виден | Содержимое | Пример |
|---|---|---|---|
| Подпись | всегда | что вводить | «Система налогообложения» |
| Подсказка под полем | всегда | где взять, в каком формате, зачем | «Указана в уведомлении из налоговой» |
| Плейсхолдер | до ввода | пример | «УСН доходы» |
| Тултип по «i» | по требованию | дополнительное объяснение | «Как сменить систему налогообложения» |

### 3.4. Мотивировка необязательного поля

`[практика]` [V:hDqJzydcHMc 27:43]. Необязательное поле, которого требует бизнес, сопровождается выгодой, а не только
пометкой: «Не обязательно, но с этой информацией мы проверим данные и откроем счёт быстрее».

Личный или чувствительный вопрос сопровождается объяснением, зачем он задан [V:vxGrL3YSBvw 09:33]: «Доход нужен,
чтобы подобрать лимит», а не голое поле «Годовой доход».

### 3.5. Запрет указания направления

`[система]` Polaris [S1]: «avoid using directional language such as "above/below" or "right/left"».

Три причины: скринридер читает линейно; в RTL стороны меняются; на мобильном раскладка другая. Плюс диагностическая:
«Directional language often indicates a lack of visual or content hierarchy».

| Не делай | Делай |
|---|---|
| «Нажмите кнопку справа вверху» | Поставить кнопку рядом с текстом или назвать её: «Нажмите „Создать“» |
| «Подробности ниже» | Убрать; поставить подробности туда, где они нужны |
| «Выберите вариант слева» | Назвать сам вариант |

**Исключение, оговорённое E2** (`../06-feedback-states-motion/01-state-matrix.md` §4.4): в пустом состоянии
указание на элемент интерфейса допустимо и полезно — «Нажмите „Создать“ в правом верхнем углу» учит, где живут
действия. Правило разрешается так: **называть элемент по имени обязательно, называть его положение — только когда
элемент точно виден на том же экране и его расположение не меняется на мобильном**.

## 4. Заголовки экранов и секций

### 4.1. Заголовок экрана

`[мнение]` Бирман [V:6Vh49gMvirE 48:23]: «в заголовке глаголу не место». Заголовок — группа существительного,
отвечающая на вопрос «что сейчас перед нами»; глагол живёт на кнопке.

| Ситуация | Заголовок | Кнопка |
|---|---|---|
| Создание нового объекта | «Новое предложение подряда» | «Сохранить черновик» |
| Редактирование черновика | «Предложение подряда» | «Сохранить черновик» |
| Редактирование опубликованного | «Предложение подряда» | «Опубликовать изменения» |

Смысл: «Опубликовать» на уже опубликованном объекте создаёт впечатление, что публикуется черновик. **Состояния
формы различаются кнопкой, а не заголовком.**

Дублирование «Регистрация» + «Зарегистрироваться» ошибкой не считается [V:6Vh49gMvirE 55:30].

Заголовок списка — имя типа объекта во множественном числе («Проекты», «Сотрудники»), правило агента B
(`../03-layout-placement/01-page-anatomy-templates.md`).

### 4.2. Заголовок секции

- Sentence case, **без точки, запятой и точки с запятой**, одно предложение [S1].
- Информативный и описательный: «Витрина интернет-магазина», не «Это ваша витрина интернет-магазина».
- **Разные секции формулируются по-разному** и не начинаются одинаково (правило bypassing, §3.4 файла 01).

### 4.3. Артикли и служебные слова

Polaris различает два регистра [S1]:

- **Разговорные места** (карточки на главной, пустые состояния, онбординг) — артикли и полные фразы: «Secure your
  account with two-step authentication».
- **Микрокопи** (подписи, заголовки, кнопки) — без артиклей: «Create collection».

Русский аналог — служебные слова и указательные местоимения: в разговорных местах «Защитите свой аккаунт
двухфакторной проверкой», в микрокопи «Двухфакторная проверка».

### 4.4. Заголовок в русском: утвердительно или отрицательно

Открытый вопрос, переданный E1 и E2, решается здесь один раз — см. §5.2.

## 5. Пустые состояния

Матрица причин и анатомия — `../06-feedback-states-motion/01-state-matrix.md` §4. Здесь тексты.

### 5.1. Формула по причинам

Четыре причины — четыре разных текста и четыре разных тона.

| Причина | Заголовок | Пояснение | Действие | Тон |
|---|---|---|---|---|
| **Ещё ничего не создано** | «Здесь появятся проекты» / «Начните с первого проекта» | что здесь будет и зачем, 1 предложение | primary-кнопка или указание на кнопку шапки | приглашающий |
| **Ничего не найдено** | «По запросу «отчёт за май» ничего не нашлось» | что изменить: другие слова, меньше слов, снять фильтр | «Сбросить фильтры», ссылка на полный список | нейтральный, деловой |
| **Всё сделано** | «Все задачи закрыты» | не нужно | нет | положительный, завершающий |
| **Данные есть, но не отдаются** (нет прав, ошибка, лимит) | «Нет доступа к разделу «Отчёты»» | почему и что сделать, 1 предложение | «Запросить доступ» / «Повторить» | прямой, без извинений |

Правило Carbon для четвёртого случая (через E2): не маскировать отказ под «нет данных». Пример: настроены
оповещения, но ничего не сработало — это **не** «оповещения не настроены», а «нет того, что требует внимания», и
дополнительный текст здесь не нужен.

### 5.2. Форма заголовка по-русски: решение

Открытый вопрос E1 и E2: «Пока нет проектов» против «Проекты появятся здесь» против «Создайте первый проект».
Решение `[практика]`, исходя из трёх правил, которые уже приняты в базе (утвердительная форма предпочтительнее —
Carbon/Atlassian; заголовок — группа существительного или утверждение, не команда — Бирман; заголовок несёт то, что
человек должен понять — Контур):

| Причина пустоты | Заголовок | Почему именно так |
|---|---|---|
| Ещё ничего не создано, действие доступно | **«Здесь появятся проекты»** | Утвердительно, отвечает на вопрос «что это за область»; команда переносится на кнопку под ним («Создать проект») |
| Ещё ничего не создано, это первый экран онбординга | **«Создайте первый проект»** | Здесь заголовок и есть призыв, потому что другого содержания на экране нет |
| Ничего не найдено | **«Ничего не нашлось»** + повтор запроса строкой ниже | Отрицательная форма здесь точнее: человек ждал результат, и подмена факта утверждением («Попробуйте другой запрос») скрывает результат поиска |
| Всё сделано | **«Все задачи закрыты»** | Утверждение о состоянии |
| Нет прав | **«Нет доступа к разделу „Отчёты“»** | Прямо и без смягчения |

**«Пока нет проектов» — допустимый, но более слабый вариант**: он сообщает факт и ничего не обещает. Использовать,
когда действие недоступно этому пользователю (нет прав на создание), — тогда обещать «появятся» нельзя, а звать
создавать бессмысленно.

**Запрещено во всех случаях**: «Здесь пусто», «Нет данных», «Ничего нет», «Nothing to see here» без продолжения —
«бессмысленная трата времени пользователя и экрана» [V:hDqJzydcHMc 26:43].

### 5.3. «Ничего не найдено»

`[исследование]` NN/g (через E2). Пять путей вперёд, из которых нужны минимум два:

1. Повторить исходный запрос текстом («По запросу «отчёт за май» ничего не нашлось»).
2. Поле поиска **с сохранённым запросом** для правки.
3. Похожие запросы, которые дают результаты.
4. Исправление опечатки («Возможно, вы имели в виду «отчёт за май 2026»?»).
5. Совет, как изменить запрос: другие слова, меньше слов, снять фильтр.

Текст перечисляет применённые фильтры: «Ничего не нашлось по запросу «Иванов» среди активных договоров за 2026 год».
Иначе человек не знает, что именно сузило выдачу.

**Не шутить** и **не обвинять**. Антипример NN/g: Disneyworld заменяет отсутствие результатов каламбурами.

Контур добавляет оформительское правило [S6]: **при нулевом результате поиска показывать короткое текстовое
сообщение без иконки** — «заглушка с иконкой в этом случае избыточна, она отвлекает от сценария поиска».

### 5.4. Что не писать

| Антипаттерн | Источник |
|---|---|
| Иллюстрация без действия и без объяснения | Carbon, NN/g (через E2) |
| Шутка или маскот в момент неудачи пользователя | NN/g, Carbon |
| Несколько вариантов действий в одном пустом состоянии | Carbon: «pick the most important» |
| Продуктовые термины, которых новичок ещё не знает | Carbon |
| Рассказ о других разделах приложения | Carbon: «be contextual» |
| Тупик без единого выхода | Carbon |
| Критичная информация, которая исчезнет при появлении данных | Apple HIG [S2]: «empty states are usually temporary» |

## 6. Сообщения об ошибках

Механика (где показывать, когда, как объявлять) — `../05-flows-journeys/04-errors-and-recovery.md` и
`../04-components-patterns/05-forms-and-validation.md`. Здесь формулировки.

### 6.1. Формула

`{что случилось} + {почему} + {что сделать}` [V:hDqJzydcHMc 24:37], [V:jh8ClG3Tl8M 33:37] — совпадение двух
независимых русских источников; то же у NN/g [S8] в виде «concisely describe the issue + offer constructive advice».

Контур добавляет четвёртый элемент для повторяемых ошибок [S4]: **что делать или чего не делать в будущем**, — нужен,
когда появление ошибки зависит от действий пользователя.

| Позиция | Что несёт | Пример |
|---|---|---|
| Заголовок | что остановилось | «Не удалось сохранить отчёт» |
| Первое предложение тела | почему | «Сервис отчётности не отвечает» |
| Второе предложение тела | что сделать | «Попробуйте через минуту. Черновик сохранён» |
| Кнопка | исправляющее действие | «Повторить» |

### 6.2. Шаблоны по типу нарушения

`[практика]` Фридман [V:AVKz9ZYoxgo 1:05:28], адаптировано к русскому:

| Нарушение | RU | EN |
|---|---|---|
| Поле пустое | «Укажите фамилию» | «Enter your last name» |
| Слишком коротко | «Не меньше 8 символов» | «Must be at least 8 characters» |
| Слишком длинно | «Не больше 100 символов» | «Must be 100 characters or fewer» |
| Недопустимые символы | «Только буквы и дефис» | «Use letters and hyphens only» |
| Не тот тип | «Введите число» | «Must be a number» |
| Не тот формат | «Формат: дд.мм.гггг, например 14.03.2026» | «Use the format mm/dd/yyyy, for example 03/14/2026» |
| Не выбрано | «Выберите вариант» / «Выберите хотя бы один вариант» | «Select an option» / «Select all that apply» |
| Значение вне диапазона | «Сумма от 100 до 500 000 ₽» | «Enter an amount between $100 and $500,000» |
| Не совпадает | «Адреса не совпадают» | «Email addresses don't match» |

letters for your name» лучше, чем «Don't use numbers or symbols»; «Choose a password with at least 8 characters»
лучше, чем «That password is too short».

### 6.3. Системная ошибка

| Ситуация | RU | Что запрещено |
|---|---|---|
| Сбой на стороне сервиса | «Не удалось загрузить список. Сервис недоступен, мы уже чиним. Попробуйте через несколько минут» | «Что-то пошло не так» |
| Потеря связи | «Нет соединения с интернетом. Изменения сохранятся, когда связь восстановится» | «Ошибка сети» |
| Таймаут | «Ответ не пришёл за 30 секунд. Операция могла выполниться — проверьте список перед повтором» | «Timeout» |
| Истекла сессия | «Сессия закончилась. Войдите заново — черновик сохранён» | «Session expired» |
| Лимит | «Достигнут лимит в 50 проектов. Удалите ненужные или перейдите на другой тариф» | «Превышен лимит» без числа |
| Частичный отказ массовой операции | «Обновлено 47 из 50 записей. Три не обновились: нет прав» + «Повторить для трёх» | «Операция завершена с ошибками» |

**Код ошибки** не показывается пользователю как сообщение [V:hDqJzydcHMc 34:57]: «цифра не даёт клиенту ничего;
максимум он напишет в поддержку „я вижу цифру 500 на странице“». Но Контур [S6] требует показывать код **рядом с
заголовком на странице ошибки**, потому что это ускоряет работу поддержки. Разрешение: код **есть на экране, но
визуально минимизирован и сообщением не служит**; в инлайн-ошибках формы кода нет вовсе. Это же формулирует NN/g:
«Hide or minimize the use of obscure error codes… show them for technical diagnostic purposes only» [S8].

### 6.4. Извинения

`[система]` Контур [S6] — самая операциональная формулировка из найденных:

> «Извиняться нужно, если проблема произошла по нашей вине. Если проблема возникла не по нашей вине, извиняться
> нельзя.»

| Ситуация | Извинение |
|---|---|
| 500, сервис не работает | да: «Извините, сервис недоступен. Мы знаем о проблеме и уже занимаемся ей» |
| Ошибка в данных, которые ввёл человек | нет |
| 404 по устаревшей ссылке или опечатке | нет: «Возможно, вы ошиблись, набирая адрес, или страница удалена» |
| Отказ в доступе по правилам системы | нет |
| Потеря введённых данных по вине сервиса | да, и обязательно — что сделано для восстановления |

### 6.5. Запреты в формулировках ошибок

Свод [S8], [S9], [V:AVKz9ZYoxgo 1:04:28], Apple [S2] `[консенсус]`:

- без общих фраз («Произошла ошибка», «Что-то пошло не так»);
- **без точки в конце**;
- без жаргона реализации («syntax error», «invalid», «null», «исключение»);
- без «запрещено», «не разрешено», «недопустимо»;
- без обвинения («вы забыли», «вы ввели неверно», «вы не заполнили»);
- без негативной рамки — переписывать в положительную («не поддерживается» → «поддерживаются JPG и PNG»)
  [V:0Cf80XFusHg 40:53];
- **без капса и восклицательных знаков**;
- **без «Oops!», «Упс», «Ой»** — «typically unnecessary and can sound insincere» [S2];
- без юмора (§8 файла 01);
- без тупика: всегда есть действие или путь;
- **для скринридера сообщение начинается со слова «Ошибка»** [V:AVKz9ZYoxgo 1:04:28]; в визуальном тексте это слово
  не нужно, оно передаётся визуально-скрытым префиксом или иконкой с доступным именем.

**Враждебные формулировки** — отдельный класс, разобранный NN/g [S11]. Два правила, относящиеся к тексту:

1. **Сообщение не появляется до того, как ошибка совершена.** Антипримеры из статьи: «Invalid email address» после
   первой буквы; «Please enter a valid date» до окончания ввода; «Please enter a last name» по клику в поле;
   «Amount cannot be blank» до любого взаимодействия. «Displaying error messages while the user types feels like an
   unwarranted scolding.»
2. **Оформление ошибки резервируется за ошибками.** «There are no attachments to display» в жёлтой плашке с
   восклицательным знаком заставляет человека остановиться и решить, должен ли там быть файл, хотя вложение
   необязательно. Нейтральный факт оформляется нейтрально; жёлтое и красное — только для сбоя и риска.

**Недопустимых имён не бывает** [V:AVKz9ZYoxgo 1:13:34]: ограничения длины и набора символов в поле имени
заставляют человека вводить неправду. Даже когда безопасность запрещает называть причину (неверный логин или
пароль), сообщение обязано помогать: как найти нужный адрес почты в прошлых письмах, как восстановить пароль.

### 6.6. Тон по типу ошибки

Двухосевая карта Фридмана [V:AVKz9ZYoxgo 57:16, 59:20]:

| Ось 1: чья вина | Ось 2: цена для человека | Тон |
|---|---|---|
| система | раздражает | нейтральный, короткий, с повтором |
| система | бесит (потеряно время) | признание + конкретный срок или обходной путь |
| система | катастрофа (потеряны данные) | прямое признание, что именно потеряно и что делается |
| пользователь | раздражает | инструктирующий, без упоминания вины |
| пользователь | бесит (блокирует) | инструктирующий + путь в обход (поддержка, альтернативный способ) |

## 7. Подтверждения

Когда подтверждение вообще нужно и какие ступени защиты бывают — `../05-flows-journeys/03-destructive-actions-undo-confirmation.md`.
Здесь только формулировки.

### 7.1. Формула

| Элемент | Формула | Пример RU | Пример EN |
|---|---|---|---|
| Заголовок | вопрос {глагол} + {объект с именем}? | «Удалить проект «Альфа»?» | «Delete Alpha project?» |
| Тело | одна строка: последствие | «Вместе с проектом удалятся 12 задач. Восстановить нельзя» | «This will also delete 12 tasks. This can't be undone» |
| Кнопка действия | глагол (объект назван в заголовке) | «Удалить» | «Delete» |
| Кнопка отказа | «Отмена» | «Отмена» | «Cancel» |

Polaris [S1]: заголовок — одно предложение, без пунктуации кроме вопросительного знака, без артиклей, sentence case.
Тело — одна строка, **не начинать с «Are you sure?»**.

### 7.2. Запрещённые заголовки

| Запрещено | Почему | Замена |
|---|---|---|
| «Вы уверены?» | Не называет ни действие, ни объект | «Удалить проект «Альфа»?» |
| «Вы уверены, что хотите удалить проект «Альфа»?» | Служебная рамка вопроса не несёт смысла | «Удалить проект «Альфа»?» |
| «Подтвердите действие» | То же | Назвать действие |
| «Внимание!» | Для этого есть значок [Microsoft, через E1] | Назвать, что произойдёт |
| «Отказаться от изменений?» | Отрицательная формулировка: на неё нельзя ответить «да/нет» [V:6Vh49gMvirE 25:45] | «Отменить изменения?» с кнопками «Продолжить редактирование» / «Отменить изменения» |
| «Удалить?» без объекта | Не видно, что именно удаляется | Имя объекта обязательно |

### 7.3. Кнопки: спор и решение

`[спорно]` — источники расходятся, и это надо знать.

| Источник | Позиция |
|---|---|
| NN/g | Кнопки называют результат: «Удалить файл» / «Оставить файл»; Yes/No запрещены |
| Apple | Глагол, называющий результат; «OK» — только для чисто информационных алертов |
| Atlassian | Императивный глагол, 1–2 слова, не «Done» |
| Microsoft | Yes/No допустимы, **когда причина отказа неочевидна**; «Never use OK and Cancel for confirmations» |
| Кочеткова [V:hDqJzydcHMc 23:37] | «Самый простой вариант — назвать кнопки „Да“ и „Нет“» |

**Решение базы** (совпадает с позицией E1, `../05-flows-journeys/03-destructive-actions-undo-confirmation.md` §4.6):

1. **По умолчанию — кнопки-глаголы, называющие результат обоих вариантов.** Три источника из пяти, плюс лучше для
   доступности: кнопка озвучивается вне контекста заголовка.
2. **Когда причина отказа неочевидна**, приём Microsoft применяется не через Yes/No, а через **слово-замедлитель** в
   подписи: «Удалить всё равно», «Опубликовать без проверки», «Отправить без вложения».
3. **OK / Отмена в подтверждении не использовать никогда** — здесь источники не расходятся.
4. **«Да» / «Нет» допустимы в единственном случае**: вопрос задан положительно, однозначно и не имеет побочных
   эффектов («Получить чек?» на банкомате [V:6Vh49gMvirE 23:40]). Это разрешает кейс Кочетковой: её пример
   («Отменить / Отказаться» при отказе от овердрафта) — именно та ситуация, где вопрос неоднозначен, и правильный
   ответ — переформулировать вопрос, а не спасать пару кнопок.
5. **«Отмена» всегда называется «Отмена»** — не «Назад», не «Закрыть», не «Отказаться» (D2,
   `../04-components-patterns/07-overlays-modals-drawers-popovers.md` §6.4).

### 7.4. Перечень последствий

`[практика]`, самая часто отсутствующая часть (E1 §4.3). Подтверждение отвечает на вопрос «что именно исчезнет»:

- число и тип объектов: «Будут удалены 3 проекта и 12 задач в них»;
- зависимые объекты: «Роль назначена 37 сотрудникам, они потеряют доступ к разделу «Отчёты»»;
- внешние эффекты: кому уйдёт уведомление, что перестанет работать;
- что **не** будет удалено: «Файлы в общем хранилище останутся»;
- срок хранения при мягком удалении: «Проект можно вернуть в течение 30 дней».

Приём Контура [S4]: **показывать конкретный список в мире пользователя**, а не число. «Удалить доверенности: ООО
„Ромашка“, ИП Петров, ООО „Вектор“» работает лучше, чем «Удалить 3 доверенности», потому что список может оказаться
заметно длиннее или короче ожидаемого и заставляет вникнуть.

Длинные перечни — через раскрытие («Показать все 37»), и **«Show details» не использовать, если деталей на самом
деле нет**.

### 7.5. Подтверждение вводом имени

Текст поля: «Введите название проекта, чтобы подтвердить» + показ имени рядом. **Просить напечатать имя объекта, а
не слово «УДАЛИТЬ»**: имя заставляет проверить, что удаляется именно это (E1 §4.4).

## 8. Тосты, баннеры, инлайн-сообщения

Выбор формы по событию — `../04-components-patterns/08-notifications-toasts-banners.md` §2. Здесь тексты.

### 8.1. Тост

| Правило | Пример |
|---|---|
| Одна строка, результат в прошедшем времени или безлично | «Проект создан», «Отчёт отправлен» |
| Без точки в конце | «Приглашение отправлено» |
| Имя объекта, если объектов много | «Проект «Альфа» удалён» |
| Действие отмены, если обратимо, 1–2 слова | «Отменить» |
| Группировка однотипных событий | «Загружено 10 файлов», а не десять тостов |
| Без «успешно» | «Платёж отправлен», не «Платёж успешно отправлен» |
| Без сообщения, если результат виден на экране | строка исчезла из списка — тост не нужен |

**Тост не годится для ошибок** (D2, [S7]): он исчезает, его не успевают прочитать, при нескольких плавающих тостах
интерфейс становится непроходимым. Формулировка Фридмана: «floating toast error messages are the worst»
[V:AVKz9ZYoxgo 1:30:32]. Тексты ошибок пишутся под инлайн-сообщение или панель.

### 8.2. Баннер

| Элемент | Правило |
|---|---|
| Заголовок | резюмирует причину; без точки; для ошибки — что остановилось |
| Тело | 1–2 коротких предложения; не пересказывает заголовок |
| Действие | максимум два; подпись 1–2 слова, называет назначение |
| Длиннее двух строк | короткая формулировка + ссылка «Подробнее» на полный текст |

Типы по Atlassian (через D2):

- **информация** — сообщить и отпустить;
- **предупреждение** — **до** действия; «информировать, но не пугать»; сказать, что будет при продолжении, и дать
  альтернативу; **не говорить о том, что уже произошло** (это уже ошибка);
- **ошибка** — проблема и следующий шаг, без обвинения: «у нас проблемы с соединением», а не «у вас проблемы с
  соединением»;
- **успех** — подтвердить исход и дать продолжить; при создании объекта — ссылка «Посмотреть».

### 8.3. Сообщение об успехе: когда его нет

`[консенсус]` (D2 §7.2):

- не показывать, если результат виден;
- не показывать на каждое мелкое действие;
- **частые сообщения короче, редкие можно оживлять**: «сообщения, появляющиеся чаще, должны быть более лаконичными;
  сообщения после более крупного или редкого действия могут быть более игривыми».

### 8.4. Подтверждение операции: судьба объекта, а не идентификатор

`[практика]` [V:hDqJzydcHMc 20:30]. Вместо «Платёж № 34 512 создан» — «Платёж отправлен, добавлен в очередь, скоро
исполнится. Его можно отозвать». Срок называют, если он известен; если неизвестен — говорят об этом прямо, а не
молчат.

Экран после завершения отвечает на вопрос «что дальше» [V:vxGrL3YSBvw 14:50]: что придёт, куда, когда, что делать,
если не придёт.

| Правило | Источник |
|---|---|
| 1–2 предложения; больше — не тултип | NN/g, Carbon (через D2) |
| Критичного для задачи в тултипе нет | NN/g: требования к паролю в тултипе — антипример Amtrak |

## 10. Настройки

`[система]` Apple HIG [S2] — самая точная формулировка:

> «Describe what it does when turned on, and people can infer the opposite.»

| Правило | Пример |
|---|---|
| Название настройки — существительное или именная группа | «Таймер мытья рук» |
| Описание объясняет включённое состояние | «Apple Watch определяет, что вы моете руки, и запускает таймер на 20 секунд» |
| Про выключенное состояние не писать | не «Если выключено, таймер не запускается» |
| Не направлять описанием местоположения — давать ссылку или кнопку | «Открыть настройки уведомлений», не «Настройки → Уведомления → Почта» |
| Подпись чекбокса называет, **что** включается, а не «Включено» | «Показывать подсказки при наведении», не «Включена» |
| Подпись чекбокса — утвердительное повествовательное предложение, не вопрос | «Создать ярлык на рабочем столе», не «Создать ярлык на рабочем столе?» |
| Логика галочки не инвертируется | галочка = «включено / нужно / видно» |
| Если у обоих состояний есть последствия — две радиокнопки с явными подписями | «Опубликовано — видно в ленте и рекомендациях» / «Доступно только по прямой ссылке» |

Источник четырёх последних правил — Бирман [V:6Vh49gMvirE 07:20, 12:25, 19:34, 43:13, 45:19].

**«Дополнительно» и «Прочее»** как название раздела настроек — признак того, что параметры плохо классифицированы
[V:6Vh49gMvirE 22:39]. `[спорно]`: в крупных админках «Дополнительно» — осознанный приём прогрессивного раскрытия
редких параметров. Правило базы: раздел «Дополнительно» допустим, если в нём лежат **редкие параметры одной
области**, и запрещён, если в него свалили то, чему не нашлось места.

## 11. Статусы

Механика (сколько индикаторов, три канала кодирования) — `../04-components-patterns/04-lists-cards-and-record-view.md`
§5. Здесь названия.

### 11.1. Формула

Статус — **прилагательное или причастие, отвечающее на вопрос «какой?»**, либо короткая именная группа. 1–2 слова.

| Плохо | Хорошо | Почему |
|---|---|---|
| «Обработка» | «Обрабатывается» | Отвечает на «какой?», а не «что происходит?» |
| «Заявки в обработке» | «В обработке банком» | Снимает вопрос «кем обрабатывается» [V:hDqJzydcHMc 19:29] |
| «Готово» | «Готов к отправке» | Называет, к чему готов |
| «Ошибка» | «Не отправлен» | Называет состояние объекта, а не факт сбоя |

### 11.2. Согласованность набора

`[практика]` [V:hDqJzydcHMc 29:46, 30:47]: все статусы одного объекта отвечают на один и тот же вопрос и лежат в
одной грамматической форме. Набор «Черновик / Отправлен / Обрабатывается / Исполнен / Отклонён» согласован; набор
«Черновик / Отправка / Готово / Ошибка» — нет.

Осознанное отступление Т-Банка: статус описывает объект и заодно говорит, что делать, чтобы не открывать
карточку («Нужна подпись»). Это допустимо, если так сделаны **все** статусы набора, а не один.

### 11.3. Цвет и текст статуса

`[практика]` Бирман [V:0Cf80XFusHg 28:36]: **цвет кодирует требуемое действие, а не этап процесса**. Серый — ничего
делать не надо; зелёный — можно забирать; красный — проблема. Зелёная плашка на этапе доставки прочитана как
«готово» и привела к напрасной поездке.

**Текст статуса называет, что делать сейчас, а не что станет возможно позже**: «Доставляется» вместо «Можно забрать
23 февраля»; когда действительно можно — «Заберите до 28 февраля».

Словарь статусов Carbon и правило «не более 2–3 типов индикаторов на запись» — у D1; здесь они не дублируются.

## 12. Пункты меню, вкладки, разделы

| Правило | Источник | Пример |
|---|---|---|
| Раздел — существительное во множественном числе | B, `../02-ia-navigation/01-information-architecture.md` | «Проекты», «Сотрудники» |
| Все пункты одного меню отвечают на один и тот же вопрос | [V:hDqJzydcHMc 29:46] | «Не добавлены / Обрабатываются банком / Добавлены / Уволены» — все на «какие?» |

## 14. Ожидание и прогресс

| Ситуация | Текст | Запрещено |
|---|---|---|
| Короткая загрузка (< 1 с) | текста нет | «Загрузка…» на 300 мс |
| Загрузка 1–10 с | называть объект: «Загружаем отчёты» | «Пожалуйста, подождите» |
| Длинная операция с этапами | называть текущий этап: «Проверяем документы», «Формируем архив» | безликий процент без этапа |
| Известный точный срок | обратный отсчёт: «Ссылка действует ещё 4:59» | — |
| Неизвестный срок | этап или прошедшее время; «Обычно занимает до 2 минут» | «Осталось примерно 30 секунд» при ненадёжной оценке |
| Фоновая операция | «Отчёт формируется. Пришлём уведомление, когда будет готов» | блокировать экран |
| Долгая операция завершилась ошибкой | что именно не удалось и сохранилось ли сделанное | «Ошибка» |

`[исследование]` (через E2, CHI 2026): **обратный отсчёт «осталось N с» вызывает больше фрустрации, чем «прошло
N с»**. Из этого практическое правило: числовой обратный отсчёт только при точно известном сроке (таймер сессии,
окно отмены, код из SMS); в остальных случаях — этап или прошедшее время.

Текст на экране загрузки оправдан, если информирует («Ищем среди 10 000 ресторанов») или несёт голос; при ожидании
порядка 50 мс слов не нужно [V:vxGrL3YSBvw 21:04].

## 15. Страницы 403, 404, 500 внутри приложения

`[система]` Контур [S6] + E1 (`../05-flows-journeys/04-errors-and-recovery.md` §4.1).

**Общее правило: одна страница на все виды ошибок запрещена.**

| Код | Заголовок | Причина | Действия | Особое |
|---|---|---|---|---|
| **404** | «Страница не найдена» | «Возможно, вы ошиблись, набирая адрес, или страница удалена» | «На главную», поиск по сайту, ближайшее совпадение | **Никакого автоматического редиректа**: проще исправить опечатку в адресной строке. Без извинений |
| **403** | «Нет доступа к этой странице» | «У вашей учётной записи нет прав на этот раздел» | «Войти под другой учётной записью», «Запросить доступ», «На главную» | **Обязательна ссылка на выход и повторную авторизацию**. Без извинений |
| **500** | «Сервис недоступен» | «Извините, у нас неполадки. Мы уже занимаемся ими» | «Обновить страницу», «Написать в поддержку» | Извинение обязательно. Если время возврата неизвестно: «Вернёмся в онлайн совсем скоро» |

Обязательные элементы страницы: логотип сервиса и ссылка на главную или основные разделы; заголовок; блок причины
(необязательный); действия; виджет поддержки, к обращению из которого **автоматически прикладывается информация об
ошибке**. Код ошибки — рядом с заголовком, визуально второстепенно.

**Графика**: без эмоциональной нагрузки; избегать смайликов, персонажей и изображений животных — «даже, казалось бы,
милая и весёлая графика может вызвать негативные эмоции» [S6].

## 16. Письма и push

### 16.1. Письмо

`[практика]` [V:jh8ClG3Tl8M 26:31, 27:31]:

- **Письмо начинается с дела.** Письмо, начинающееся с «Благодарим за выбор нашей компании, желаем счастья вашему
  бизнесу», уходит в спам вместе со счётом к оплате.
- Тема письма — суть в первых двух словах, ≤ 50 знаков: «Счёт на оплату до 5 октября», не «Информация от вашего
  провайдера».
- **Метрика письма — совершённое действие, а не открытие.**
- Проектируются не отдельные письма, а **цепочки по ситуациям**, с учётом того, что диалог разорван по каналам:
  письмо → действие в интерфейсе → подтверждение снова письмом.
- В письме и push **нет ни навигации, ни визуального бренда — остаётся только голос** [V:1Z8gbVnrTfE 25:31].

Разграничение модальностей Контура [S4]: письма и СМС **о событиях в сервисе** пишет «робот» — без персонификации и
форм вежливости, страдательный залог уместен, коротко и по делу. Рассылки **от команды продукта** пишутся от первого
лица, с приветствием и подписью, из которой понятно, кто эти «мы».

### 16.2. Push

- До двух строк; действие и объект в первых словах.
- Не дублировать заголовок в теле.
- Не отправлять push о том, что человек увидит сам при следующем входе.
- Не использовать push для маркетинга без отдельного согласия (запреты E2 §8.1).

### 16.3. Приглашение

`[практика]` [V:1Z8gbVnrTfE 25:57]: предзаполненный текст приглашения пишется **от лица человека, а не от лица
компании**, иначе его не отправят. «Иван приглашает вас в проект «Альфа»» — от системы; «Привет! Присоединяйся к нам
в «Альфе»» — от человека, и его можно править.

## 17. Обрезка текста и «показать ещё»

| Правило | Пример |
|---|---|
| Многоточие ставит система (CSS `text-overflow`), а не автор | — |
| Полное значение доступно: подсказка, раскрытие, страница объекта | — |
| Кнопка раскрытия называет, чего ещё | «Показать все 37 участников», не «Показать ещё» |
| Свёртка называет, что свернётся | «Свернуть список участников» |
| Критичное не прячется за раскрытием | Требования к паролю, итоговая сумма, условия возврата |
| Спрятанное во вкладке или аккордеоне не находится поиском по странице | [V:AVKz9ZYoxgo 1:51:56] |
| Имя объекта не обрезается посередине там, где по нему опознают объект | в первой колонке таблицы обрезать конец, а не начало |

Правило перечисления вместо числа [V:0Cf80XFusHg 07:07]: «Иван Петров, Мария Иванова и ещё 26 человек» — максимум
две строки, «ещё 26 человек» — ссылка на полный список. Это лучше, чем «28 человек», потому что даёт узнавание.

## 18. Тексты для ИИ-функций

`[консенсус]` — свод из запретов E2 (§8.1, п. 21), правил Фридмана [V:AVKz9ZYoxgo 2:00:02, 2:48:08] и каталога C.
Подробный плейбук ИИ-функций — `../13-app-types/03-ai-features-ux-playbook.md` (волна 3, агент H).

| Требование | Формулировка |
|---|---|
| Сгенерированное помечено | «Сгенерировано ИИ», «Черновик от ассистента» — рядом с содержимым, а не в подвале |

| Источник показан и проверяем | «По данным договора № 12 от 3 марта» со ссылкой на фрагмент |
| Человек подтверждает, система не применяет сама | «Применить», «Отклонить», а не автоприменение |

| Уточняющий вопрос можно пропустить | «Пропустить и показать результат» |
| Ограничения названы честно | «Ассистент видит только документы этого проекта» |

**Чего не писать**: «Магия», «Умный», «Интеллектуальный» как самоописание функции; обещание точности; «Я думаю»,
«Я считаю» от лица системы; извинения ассистента за каждый промах.

## Чек-лист

Кнопки и ссылки:

1. Каждая кнопка попадает в одну из трёх категорий (команда / навигация / статус)?
2. Каждая кнопка называет результат нажатия без чтения окружающего текста?
3. Нет ни одного «OK», «Подтвердить», «Да/Нет» в подтверждениях действий?
4. Русские кнопки — инфинитив совершенного вида, все в одной форме?
5. Ни одна кнопка не в две строки и не сокращена?
6. Ни одной ссылки «здесь», «тут», «подробнее», «click here»?
7. В предложении залинкован только фрагмент, называющий назначение?

Поля:

8. У каждого поля видимая подпись из 1–3 слов без двоеточия и без призыва?
9. Плейсхолдер — только пример, не дублирует подпись, не содержит инструкции?
10. Подсказка под полем — одно предложение без точки и без ссылок внутри?
11. Необязательное поле, нужное бизнесу, сопровождается выгодой?
12. Формулировка каждого вопроса допускает ровно один тип ответа?

Состояния и сообщения:

13. Для каждой из четырёх причин пустоты написан свой текст?
14. В каждом пустом состоянии есть заголовок и (кроме «всё сделано») одно действие?
15. «Ничего не найдено» повторяет запрос и перечисляет применённые фильтры?
16. Каждое сообщение об ошибке отвечает на «что случилось», «почему», «что сделать»?
17. Ни в одном сообщении нет «неверно», «недопустимо», «что-то пошло не так», кода как текста, точки в конце,
    восклицательного знака, капса?
18. Извинение стоит только там, где виноват сервис?
19. Ошибки показаны инлайн или панелью, а не тостом?
20. Тост — одна строка без точки, с «Отменить», если обратимо?
21. Нет сообщения об успехе там, где результат виден?

Подтверждения:

22. Заголовок — вопрос с именем объекта?
23. Тело — одна строка с конкретным последствием (число объектов, зависимости, необратимость)?
24. Обе кнопки называют результат; «Отмена» называется «Отмена»?

Согласованность:

25. Имя действия одинаково в кнопке, заголовке диалога, сообщении и статусе?
26. Все статусы одного объекта в одной грамматической форме и отвечают на «какой?»?
27. Все пункты одного меню отвечают на один вопрос?
28. Одно слово на одно действие во всём продукте («изменить» или «редактировать», но не оба)?

Специальные случаи:

29. 403, 404 и 500 имеют разные тексты; при 404 нет автоматического редиректа; при 403 есть смена учётной записи?
30. Настройка описывает включённое состояние; про выключенное не написано?
31. Тексты ожидания называют этап; обратный отсчёт только при точно известном сроке?
32. «Показать ещё» называет, чего ещё, и за ним не спрятано критичное?
33. Сгенерированное ИИ помечено; источник показан; действие обратимо?
34. Доступное имя каждой иконочной кнопки = действие + объект?
35. В текстах нет указаний направления («справа», «ниже»)?

   побочных эффектов. Измерений ни у одной стороны нет.
2. **Код ошибки на экране** `[спорно]`. Кочеткова: код не даёт клиенту ничего. Контур: код рядом с заголовком
   ускоряет поддержку. Разрешено в §6.3 разделением «страница ошибки — код есть, инлайн-ошибка — кода нет», но это
   синтез базы.
3. **Указание направления** `[спорно]`. Polaris запрещает; Carbon в пустых состояниях рекомендует «Нажмите „Создать“
   в правом верхнем углу». Разрешено в §3.5 условием видимости и неизменности расположения; условие не проверено
   тестами.
4. **Заголовок пустого состояния по-русски** (§5.2) — решение базы, а не позиция источника. Ни один найденный
   источник не сравнивал утвердительную и отрицательную форму по-русски экспериментально.
5. **Длина статуса.** Предел «1–2 слова» взят из практики Uber и Carbon; для русского, где статус часто требует
   уточнения («В обработке банком»), предел приходится раздвигать до 3 слов. Данных о влиянии длины статуса на
   скорость сканирования строки не найдено.
6. **Эмоциональный текст в пустом состоянии «всё сделано».** Контур рекомендует «эмоциональный текст» и цветную
   иконку; Carbon и NN/g в тех же ситуациях требуют сдержанности. Разрешено §5.1 через тон «положительный,
   завершающий», но граница между «положительный» и «эмоциональный» не операционализирована.
7. **Тексты ИИ-функций** (§18) собраны из запретов и практик 2025–2026 годов; устойчивых конвенций пока нет, и
   раздел придётся пересматривать.
8. **Не проверено**: полный текст Polaris «Error messages», «Voice and tone», «Grammar and mechanics» — архив
   web.archive.org отдал только «Actionable language», остальные страницы вернули 429 и таймауты. Правила Polaris,
   на которые я ссылаюсь, взяты только из открытой страницы.
