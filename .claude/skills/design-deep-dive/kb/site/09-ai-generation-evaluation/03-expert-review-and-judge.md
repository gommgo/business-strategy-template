# Экспертный проход и судья для сайта: протокол, оси, конгруэнтность, пятисекундный тест, рубрика `site-rubric.json`

Волна 3 · агенты K (каркас протокола в заметках), K3 (файл и рубрика) · 2026-09-24 · файлов базы, соседей и сестёр прочитано
целиком или нужными разделами: 11; дайджесты роликов: 3 · опыты `99-raw/experiments/K/02-ux-profile/`,
`K/03-gates-v1/` · машиночитаемое — `site-rubric.json` v1.0 (8 осей, 28 атомарных вопросов)

Как проверять маркетинговую страницу после автоматики: в каком порядке, по каким осям, как считать конгруэнтность секций,
как заменить пятисекундный тест до живой фазы и как запускать судью-модель, чтобы его баллу можно было верить. Протокол
ux (`../../ux/12-evaluation-checklists/01-expert-review-protocols.md`) переносится с поправками для маршрута
«визит → действие»; слова оценивает рубрика text (`../../text/09-ai-generation-evaluation/copy-rubric.yaml`),
подачу — creative. Судья здесь — фильтр перед людьми и экспериментом, а не их замена.

## Выжимка для агента

1. **Судью запускай последним из автоматики**: после ворот, маркеров и сверки с фактами; иначе рубрика оценит силу
   убеждения выдуманных отзывов (демо K3 — 5,0 из 5). → §1.1 `[проверено]`
2. **Порядок: отдельная сессия → автопроверки → факты → экспертный проход по осям → конгруэнтность → прокси пятисекундного
   теста → рубрика → серьёзность отдельным проходом → отчёт → заказчик → живая фаза.** → §1.1 `[практика]`
3. **Оси прохода — восемь вопросов A**: запах, ясность за 5 с, ценность, мотивация источника, тревога, трение, отвлечение,
   честная срочность; порядок исправления — по CCD Гарднера, с первого проваленного принципа. → §2.1, §2.2 `[практика]`
4. **Рамка Google «внимание — вовлечение — действие — поток»** — проверочный список экранов: главное сообщение, взаимодействие
   с содержимым, лёгкость действия, скорость и исправность. → §2.3 `[практика]`
5. **Конгруэнтность считай по секциям плана**: 0 — не о цели страницы, 1 — частично, 2 — полностью; процент = сумма / (2 ×
   секций); секции с 0 — удалить или переписать. → §2.4, SITE-STR-03 `[практика: V:w87hTii1Dao 36:07]`
6. **Пятисекундный тест — у людей** (20 человек, ≥ 80 % верно называют, что это); у модели «пяти секунд нет»: до живой фазы
   — прокси по одному кадру в отдельной сессии, ответ сверяется с целью плана. → §2.5 `[практика]`
7. **Шесть линз сайта**: холодный из соцсетей, горячий из объявления, телефон во встроенном браузере, клавиатура,
   скринридер, тревожный покупатель дорогой услуги. → §2.6 `[практика]`
8. **Покрытие проверено до вердикта**: призывы, пункты меню, каждое поле формы, аккордеоны, вкладки, окна, баннер cookie —
   каждый элемент осмотрен или помечен «не проверен». → §2.7 `[практика]`
9. **Находка = что, где, правило, доказательство, серьёзность, наименьшая правка**; ≤ 12 находок за проход; ноль находок —
   неудачный прогон. → §3 `[практика]` `[мнение: Нильсен]`
10. **Серьёзность — маршрут «визит → действие»** (B/S/D файла 02 §1.2), отдельным проходом; три оценки — среднее. → §3
    `[практика]`
11. **Рубрика — профиль из 8 осей без общего балла**; ворота SITE-OUT-10 — оси ясности, пути к действию и честности не ниже 3. →
    §4 `[практика]`
12. **Балл оси — формула по атомарным вопросам**: share = «да» / отвечено, score = min(max(1, round(5 × share)), наименьший
    `cap_if_no` среди «нет»); каждый ответ «нет» — с цитатой или координатой, иначе «не уверен». → §4.2 `[практика: формат text]`
13. **Слова не дублируй**: ясность формулировок — COPY-R-01, сюжет заголовков — COPY-R-07, призыв — COPY-R-09; site смотрит
    композицию, место и связь с планом. → §6 `[практика]` (контракт v2 §2)
14. **SEO-гигиену судье не отдавай**: ось 08 считается из отчёта `page_gates.py`. → §4.1 `[практика]`
15. **Прогонов: 3 — черновая сортировка, 11 — решение, 15 — при большом разбросе**; попарно — оба порядка, победа только при
    совпадении. → §5.1 `[исследование: arXiv 2606.13685; MT-Bench]`
16. **Судья — другого семейства, чем генератор, в сессии без контекста создания**: самопредпочтение до +25 %. → §5.1
    `[исследование]`
17. **Не отдавай судье содержание фактов и вкус**: люди и обученные на них судьи слепы к тексту (Design2Code −0,354);
    подача — creative, факты — сверка. → §5.2 `[исследование]`
18. **Судья не предсказывает победителя A/B** (κ = 0,14 на 330 тестах); выбор по конверсии — эксперимент по методике P. →
    §5.2 `[исследование]` (через text I)
19. **Ясность цели закладывай в план**: ревью по отчёту судьи почти не чинит её (Goal −0,02…+0,15 из 5 в UXBench), хорошо
    чинит обратную связь и сканируемость. → §5.3 `[исследование]`
20. **Рубрика не откалибрована**: до разметки людей доверие — «отсев брака» (agreement ≥ 0,7), сортировка вариантов — только
    при согласии с людьми ≥ 0,8 и нижней границе Уилсона ≥ 0,65 на n ≥ 20. → §5.4 `[практика]`

### 1.2. Что поправлено против протокола ux

Поправка к `../../ux/12-evaluation-checklists/01-expert-review-protocols.md` §3.1, §4.2, §7.2–7.3 для сайта:
- **серьёзность** — не шкала Нильсена по частоте работы, а маршрут «визит → действие» (файл 02 §1.2: B — действие не
  выполняется, закон, обман; S — трение, доверие, исход хуже профиля; D — улучшение), потому что визит разовый;
- **когнитивный проход** (4 вопроса) — по одному маршруту «первый экран → доводы → призыв → форма → «спасибо»», а не по
  рабочим задачам ролей;
- **линзы** — посетители сайта (§2.6), а не «новичок и эксперт» инструмента;
- **coverage gate** — элементы маршрута сайта (§2.7);
- **PURE** (оценка шагов 1–3) — только для многошаговых форм и квизов (SITE-FRM-09), у посадочной шагов нет.

### 2.2. CCD Гарднера — порядок исправления

Семь принципов conversion-centered design (attention, context, clarity, congruence, credibility, closing, continuance)
кампания проходит по порядку; провал на раннем шаге обесценивает поздние — **исправление начинай с первого проваленного**
(`../91-videos/digests/w87hTii1Dao.md` [01:07]–[02:07]) `[практика]`. Для агента:
1. **attention** — выходы с пути к цели (attention ratio: у кампании цель одна; число 1:1 — позиция вендора `[мнение вендора]`,
   механизм и счёт — по C `../03-page-structure/02-length-goal-message-match.md` §2.1–2.2);
2. **context** — конкретики источника (предмет, число, срок, картинка, тон) есть в первом экране [16:35];
3. **clarity** — заголовки H1–H3 подряд пересказывают предложение [24:49]; сомнение → пятисекундный тест людей;
4. **congruence** — таблица §2.4 [36:07];
5. **credibility** — только реальные доказательства; нет своих — «support the concept» или честное отсутствие [38:10];
6. **closing** — что написано вокруг кнопки: одна фраза против главной тревоги шага, без общих заверений [41:15]
   (формулировку проверяет text: COPY-R-08 q4);
7. **continuance** — «спасибо»: подтверждение первым, следующий шаг вторым, без отвлечений [44:20].

### 2.3. «Внимание — вовлечение — действие — поток»

Рамка аудита конверсии команды Google Mobile UX (`../91-videos/digests/XPH01OGrinQ.md` [09:15]–[10:16]): **внимание** —
главное сообщение первого экрана (ценностное предложение, призыв, визуал); **вовлечение** — как посетитель взаимодействует с
содержимым (категории с картинками и подписями, поиск там, где ищут); **действие** — насколько легко совершить (призыв —
форма, текст, цвет, место; главный — сплошной, второстепенные иным стилем); **поток** — скорость, производительность,
«гигиена» сайта `[практика]`. Использование: проверочный список к каждому экрану кадра; из рамки в маркеры попали AIL-48
(ghost-кнопка главного призыва) и AIL-51 (иконки без подписей).

### 2.4. Конгруэнтность секций

Метод Гарднера («congruence scorecard», [V:w87hTii1Dao 36:07]–[37:08]): выписать элементы страницы (только текст), каждому
поставить 0, 1 или 2 против цели кампании, сумма в процентах; пример из доклада — 3 из 24 = 12,5 %; всё с нулём — удалить или
переписать `[практика]`. Для сайта единица — **секция плана**, цель — `page.goal` и `page.primary_action`:

| Балл | Значит | Пример (лидогенерация «замер окон в Самаре») |
|---|---|---|
| 2 | секция помогает принять решение по этой цели | «Цена окна с установкой от 3 500 ₽/м² — что входит» |
| 1 | о продукте или компании, но не о решении посетителя | «История компании с 2008 года» без связи с гарантией |
| 0 | не о цели страницы | лента новостей компании, «Наши вакансии», SEO-текст между оффером и формой |

Результат = сумма / (2 × число секций). Порог базы: ни одной секции с 0 (SITE-STR-03, S); процент — сигнал, не ворота (порог
90 % в якоре 5 оси SITE-R-06 — ориентир K3 без замера). Судья ставит балл с цитатой заголовка и одной фразой «зачем эта
секция для цели»; спорные — человеку. SEO-текст и перелинковка законны **после** главного призыва (SITE-STR-14) — там они
получают 1, а не 0.

### 2.5. Пятисекундный тест: люди и прокси

- **Люди** (живая фаза): экран показывают 5 секунд, один вопрос на тест — «Что это за страница?», «Что будет после нажатия
  кнопки?», «Выглядит ли страница надёжной?»; 20 человек; переписывать заголовки до стабильно верных ответов
  ([V:w87hTii1Dao 25:52]–[27:56]) `[практика]`; порог text — ≥ 80 % верно называют, что это, для кого и что сделать
  (COPY-C-40; быстрая версия ≥ 8 из 10). Панели в РФ: Яндекс Взгляд закрыл платные опросы с 20.03.2026, Анкетолог — 90 ₽ за
  ответ (text I, снимок 2026-09-24).
- **Прокси до живой фазы**: отдельная сессия, один кадр первого экрана (1440×900, затем 390×844), ответ ≤ 3 строк на вопросы
  «чей это экран, что можно сделать, что главное» (ux 12/04 §9.1); ответ сверяется с `page.goal` и `first_screen.must_show`;
  расхождение — находка к SITE-R-01. У модели «пяти секунд нет» — это проверка кадра, а не восприятия `[практика]`.
- **Тест заголовков**: прочитать подряд только H1–H3 — пересказывается ли предложение (Гарднер [24:49]; сюжет слов — COPY-R-07).
- **Банановый тест** (ux 12/01 §9.1): текст заменён одним словом — узнаются ли логотип, меню, кнопка, форма (конвенции
  взаимодействия, SITE-STR-16).

### 2.6. Линзы

Поправка к `../../ux/12-evaluation-checklists/01-expert-review-protocols.md` §7.2 для сайта: шесть линз — посетители
маршрута «визит → действие», а не роли инструмента (одна линза находит часть проблем: у одного оценщика 42 % крупных и 32 %
мелких — Nielsen 1992 через ux 12/01 §3; 3–5 проходов).

| Линза | Кто | Что особенно проверить |
|---|---|---|
| `cold` | холодный посетитель из соцсетей: не знает ни компанию, ни проблему | ясность категории, первый довод — ситуация, а не «наши преимущества» |
| `hot` | горячий посетитель из объявления с конкретным обещанием | `message_match`, цена или условие в первом экране, короткий путь к форме |
| `phone` | телефон 390×844 во встроенном браузере соцсети, с баннером cookie | первый экран, липкие слои, меню, скорость |
| `keyboard` | только клавиатура | Tab по шапке, призыву, форме и баннеру; фокус не закрыт |
| `screen-reader` | скринридер | H1, имена ссылок и кнопок, подписи полей, объявление успеха |
| `anxious` | тревожный покупатель дорогой услуги | цена и что входит, гарантия из договора, кто придёт, что будет после заявки |

### 2.7. Покрытие до вердикта

Coverage gate ux (12/01 §7.3) для сайта: до вердикта осмотрены все **призывы** (каждое место и подпись), **пункты меню**
шапки и подвала, **каждое поле** каждой формы и квиза, каждый **аккордеон, вкладка, окно**, **баннер cookie** в первом
визите и после выбора, **«спасибо»**. Не осмотренный элемент помечается «не проверен» и снижает доверие к проходу; ноль
находок при неполном покрытии — неудачный прогон.

## 3. Находка и отчёт

**Находка — шесть полей** (ux 12/01 §6.3): что (наблюдение), где (устройство, экран, секция плана, координата кадра),
правило (`SITE-*`, `AIL-*`, `SG-*`), доказательство (цитата текста, фрагмент HTML, кадр), серьёзность B/S/D, наименьшая
правка (изменение, которое снимает находку без перестройки страницы, ux 12/01 §6.5). Формат VLM-критика kimi (08/02 §6)
совместим: `expected / gap / fix / region`.

Пример:

```yaml
- what: "Баннер cookie на телефоне закрывает кнопку «Вызвать замерщика» в первом экране"
  where: {device: 390x844, screen: 1, section: hero, region: [0, 640, 390, 204]}
  rule: SITE-MOB-04            # DEF-08
  evidence: "cmp_mobile.jpg: баннер 22,8 % экрана, кнопка под ним"
  severity: B                  # действие недоступно на маршруте «визит → действие»
  fix: "баннер — полосой внизу ≤ 20 % высоты, над ним видна кнопка; или кнопка выше сгиба"
```

Правила отчёта:
- **≤ 12 находок за проход** (kimi 08/02 §6), в каждой — одно правило; повтор той же находки на другом экране — одна находка
  со списком мест.
- **≥ 2 сильные стороны** — чтобы правка их не сломала (kimi 08/02 §6).
- **Серьёзность — отдельным проходом**: сначала список наблюдений, потом серьёзность по файлу 02 §1.2 (B/S/D на маршруте),
  три оценки — среднее (ux 12/01 §3.1). Уточнение по контексту: на посадочной под платный трафик пункты CTA, FRM и MOB —
  на ступень выше, но не выше B; на служебной странице — на ступень ниже.
- **Ноль находок — неудачный прогон** (SITE-OUT-09, UX-OUT-12): повторить с другой линзой и другим порядком осей
  `[мнение: Нильсен]`.
- **«Низко висящие плоды» не выдаются за главное**: сначала находки B и находки на осях SITE-R-01, 03, 04.
- **Конфликт правил** решается однозначно и записывается (ux 12/01 §10.3): например, SITE-CTA-02 (повтор призыва) против
  UX-LAY-16 — действует профиль (`ux-marketing-profile.tsv`: UX-LAY-16 → `replaced`).
- **Решения вкуса, фактов, прав на фото и тона** — одним блоком заказчику (SITE-OUT-12); в отчёт проверяющего не входят.

### 4.2. Балл и профиль

- Формула (как `copy-rubric.yaml` text v1.1): share = yes / answered (unsure = «нет»; n/a не в знаменателе); score =
  min(max(1, round_half_up(5 × share)), наименьший `cap_if_no` среди ответов «нет»); ноль — только `cap_if_no: 0`
  (SITE-R-04 q1) или человек; минимум два отвеченных вопроса. Примеры: 4 из 4 → 5; 3 из 4 и «нет» с потолком 4 → 4; 3 из 4 и
  «нет» с потолком 1 → 1; 3 из 4 и «нет» у SITE-R-04 q1 → 0.
- Потолки `cap_if_no` связывают ответ с якорем: без категории в первом экране (SITE-R-01 q1) страница не выше 1, сколько бы
  «да» ни было у остальных вопросов; без повтора призыва (SITE-R-03 q2) — не выше 2.
- **Профиль, а не балл**: таблица «ось × страница» (у многостраничника — «ось × шаблон»); общий балл не считается
  (`aggregation.total_score: false`). Ворота SITE-OUT-10: оси SITE-R-01, 03, 04 не ниже 3 в 3 прогонах при согласии ≥ 2 из
  3.
- Правила решения (`decision_rules`): DR-1 — нет сверки с фактами или есть B ворот и маркеров → судью не запускать; DR-2 —
  SITE-R-01, 03 или 04 ≤ 2 → правка на шаге, где дефект рождается (план, бриф, факты), а не только вёрстка; DR-3 — SITE-R-02
  ≤ 2 при платном трафике → `message_match` и отдельная страница под сегмент; DR-4 — выбор варианта: ворота и маркеры,
  судья сортирует только после калибровки, победителя по конверсии решает A/B; DR-5 — изменён вопрос, якорь или `read` →
  новая версия и пересчёт калибровки; DR-6 — рубрика против людей и эксперимента → верить людям.

### 4.3. Что судье дают и чего не дают

- **Дают** (`inputs`): план v1 (роли, вопросы, политика первого экрана, `message_match`, осведомлённость, трафик, право,
  события), кадры PNG без потерь (1440×900, 390×844 с баннером, контактный лист, кадр баннера), видимый текст по секциям,
  отчёты ворот и маркеров, `facts.yaml` — после сверки.
- **Не дают**: задание «оценить красоту» (подача — creative; при необходимости — обесцвеченный кадр, ux 12/01 §7.6), истину
  фактов без `facts.yaml`, предсказание победителя A/B, естественность и голос текста (у text — только человек: COPY-R-10…12).
- **Две задачи раздельно**: критика и локализация (где на кадре) — разными запросами: с подсказкой области IoU 0,222 против
  0,004 без неё (kimi 08/02 §6) `[данные: kimi]`.
- **Машинный отчёт — первым**: судья видит результаты ворот и маркеров до кадров, чтобы не тратить находки на уже
  найденное (kimi 08/02 §6).

## 5. Когда судье можно верить

### 5.1. Прогоны, порядок, семейство

| Смещение или шум | Число | Что делать | Источник |
|---|---|---|---|
| разброс повторов | переворот попарных решений 13,6 %; для 95 % воспроизводимости — **11 повторов** (15 при большом разбросе); поточечные оценки стабильнее попарных | 3 прогона — черновая сортировка, 11 — решение; ось оценивается поточечно | «Coin Flip Judge?», arXiv 2606.13685, через ux 11/02 §4 `[исследование]` |
| формулировка промта | эквивалентные шаблоны меняют итог в 25 % случаев | версия рубрики и промта фиксирована (`prompt_version`); правка вопроса → новая версия и калибровка (DR-5) | там же |
| согласие судей между собой | κ = 0,51 | не усреднять разных судей без калибровки | там же |
| порядок показа | GPT-4 согласован с собой в 65 % пар; у 36 моделей показанный первым выбран в 64,3 %, медиана переворотов 41,3 % | оба порядка; победа только при совпадении; доля «A» в 0,35–0,65 | MT-Bench 2023 через ux 11/02 §4; lechmazur 2026 через text I `[исследование]` |
| самопредпочтение | GPT-4 +10 %, Claude-v1 +25 % | судья другого семейства, чем генератор | ux 12/01 §7.1 `[исследование]` |
| многословие | длинный ответ кажется лучше | ограничение вывода, ≤ 12 находок | ux 12/01 §7.5 |
| без опоры | ошибки 14 из 20 → 3 из 20 при reference-guided | судья сначала отвечает на вопрос сам по плану (что должно быть в первом экране) | ux 12/01 §7.5 `[исследование]` |
| без рубрики | согласие с людьми на уровне монетки (51,58 %); с рубрикой — Пирсон 0,9892 | только атомарные вопросы рубрики | kimi 08/02 §6 `[данные: kimi]` |

### 5.2. Что судья не видит и чего от него не ждать

- **Содержание**: в регрессии Design2Code предпочтение людей имеет отрицательный коэффициент по текстовому сходству (−0,354)
  при положительном по позиции (0,761) — и люди, и обученные на них модели слепы к содержательным ошибкам (ux 12/01 §7.6)
  `[исследование]`. Поэтому факты — сверкой, а не судьёй.
- **Происхождение**: рубрика мерит силу убеждения: лидеры 3,96–4,07, средний рынок 2,52–2,71, ИИ-тексты посередине; демо K3 с
  выдуманными отзывами — 5,0 из 5 (text I) `[проверено]`.
- **Победитель A/B**: «Judge Knows When It Knows» (2026) — κ = 0,14 на 330 тестах; судья не прогнозирует конверсию (text I,
  COPY-C-24) `[исследование]`.
- **Вкус**: согласие людей между собой по вкусу — Fleiss κ 0,29–0,31 (kimi 08/02 §7); вкус и «узнаётся ли продукт» решает
  заказчик.

### 5.3. Что ревью может починить, а что — нет

UXBench (arXiv 2606.16262, 15.06.2026; 41 страница-фикстура, 10 семейств, включая Landing и Pricing; 7 измерений 1–5): после
ремонта по отчёту судьи обратная связь выросла на +0,24…+0,44, сканируемость и доступность — на +0,26…+0,39, поток — на
+0,03…+0,12, **ясность цели — на −0,02…+0,15** (ux 11/02 §4) `[исследование]`. Для сайта: ясность предложения и путь к
действию закладываются в бриф и план (SITE-PRE-01…20), а не «докручиваются» по находкам судьи; отсюда DR-2 — правка на шаге,
где дефект рождается.

### 5.4. Калибровка

- **Статус 2026-09-24**: разметки людей по `site-rubric.json` нет; доверие всех осей — `pre-filter` (судья отсеивает явный
  брак и отдаёт находки с доказательством человеку), ось 08 — `auto`.
- **Пороги** (как у text и ai-media): сортировка вариантов — согласие с решающими голосами людей ≥ 0,8, нижняя граница
  Уилсона ≥ 0,65, n ≥ 20; отсев брака — согласие ≥ 0,7; ниже — судья не используется; F1 против людей ≥ 0,8 (NN/g через ux
  11/02 §4).
- **Пересчёт**: новая модель судьи, новая версия рубрики или промта, доля «не уверен» > 0,2, расхождение в трёх сессиях
  подряд.
- **Как калибровать** (живая фаза, отчёт K §5): 20–30 страниц (лидеры, средний рынок, сборки K3 по `page-plan`), два
  человека размечают вопросы осей 01–07 вслепую; судья — 3 прогона; считать согласие по вопросам, а не по баллам; вопросы с
  согласием < 0,7 переписать (`read`) и перемерить.

## Частые ошибки

1. **Судья до сверки с фактами** — выдуманные отзывы и метрики получают высший балл (text I/03: 5,0 из 5).
2. **Один прогон судьи как решение** — переворот 13,6 %, шаблон промта меняет итог в 25 %; решение — 11 прогонов.
3. **Сравнение вариантов в одном порядке** — показанный первым выигрывает в 64,3 % пар; нужны оба порядка.
4. **Судья того же семейства, что генератор**, в той же сессии — самопредпочтение и память о задании.
5. **Общий балл вместо профиля** — пятёрка по сюжету прячет единицу по ясности; ворота — по осям 01, 03, 04.
6. **Нормы рабочего экрана в проходе**: «одна primary-кнопка», «шапка страницы с H1», «оверлей запрещён» — 87 % ложных
   срабатываний на маркетинговых страницах (K/02); проходить по профилю `ux-marketing-profile.tsv`.
7. **Конгруэнтность по цели бизнеса, а не страницы**: «О компании» получает 2, хотя посетителю объявления о замере она не
   помогает решить.
8. **«Пятисекундный тест» моделью** выдан за тест с людьми; прокси — только проверка кадра.
9. **Вкус и эффектность в рубрике логики** — у creative своя рубрика; красота кадра не компенсирует провал ясности.
10. **SEO-гигиена «на глаз» судьи** — считается из ворот (ось 08).
11. **Ноль находок принят как «чисто»** (DEF-47).
12. **Находка без доказательства**: «первый экран слабый» без кадра, координаты и правила — не находка.
13. **Правка по находке судьи там, где дефект не рождается**: ясность цели чинят в брифе и плане, а не в CSS (UXBench).
14. **Прогноз победителя A/B судьёй** — κ = 0,14; решает эксперимент.
15. **Правка вопроса рубрики без новой версии** — прошлые баллы несопоставимы.

## Чек-лист

- Проверка идёт в отдельной сессии, судья другого семейства, чем генератор?
- До судьи пройдены ворота (0 B), маркеры B сняты, сверка с фактами без ошибок?
- Экспертный проход прошёл все восемь вопросов A и все шесть линз, покрытие элементов отмечено?
- Конгруэнтность посчитана по секциям плана против `page.goal`, секций с 0 нет?
- Прокси пятисекундного теста совпал с целью плана на 1440×900 и 390×844?
- У каждой находки шесть полей, находок ≤ 12, сильных сторон ≥ 2, ноль находок не принят?
- Серьёзность назначена отдельным проходом по маршруту «визит → действие»?
- Рубрика: 3 прогона (11 для решения), оба порядка при попарном сравнении, версия рубрики и промта записана?
- Оси SITE-R-01, 03, 04 не ниже 3; ось 08 — из отчёта ворот?
- Слова оценены рубрикой text (COPY-R), подача — creative, вкус и факты — заказчиком?
- Судья не использован для прогноза A/B и оценки «естественности»?

## Открытые вопросы и противоречия

1. **Калибровки нет**: ни одна ось не сверена с людьми; доверие — только отсев брака. Разметка 20–30 страниц — живая фаза.
2. **Порог конгруэнтности** (0 секций с нулём, ориентир 90 % для якоря 5) — без замера; у Гарднера — только пример 12,5 %.
3. **Прокси пятисекундного теста** не проверен против людей; модель видит кадр целиком и дольше, чем человек.
4. **Серьёзность находок** — назначена по маршруту «визит → действие» агентом K, не измерена (как у ux: свёртка шкалы Нильсена).
5. **Эффектность против ясности**: у кампаний L2 форма `poster` законно откладывает призыв; SITE-R-01 q3 засчитывает призыв
