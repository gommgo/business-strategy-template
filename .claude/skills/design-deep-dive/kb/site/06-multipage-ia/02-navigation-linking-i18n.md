## Выжимка для агента

1. **Шапка, подвал, крошки и поиск задаются один раз в `site-map.chrome`**; шаблон и `page-plan` только выбирают вариант
   (`site | landing-minimal | none`), пункты меню не повторяют. → §1.5 [стандарт: WCAG 2.2 3.2.3, 3.2.6]
2. **Каждый пункт шапки и подвала ведёт на страницу карты**, пункт с подменю — на страницу-хаб; пунктов «для полноты»
   («Ресурсы», «Решения», «Блог» без страниц) нет. → §1.1 [практика] [мнение вендора: Hallmark «AI nav»]
3. **Логотип слева ведёт на главную на каждой странице**, плюс явная ссылка «Главная» (первая крошка или первая ссылка
   подвала), без дубля в меню и крошках одновременно. → §1.1 [исследование: NN/g 2016, 2018, 2024]
4. **Архетип шапки — по структуре сайта**: один из 7 (`$defs.header-archetype`) по порядку выбора §1.2; правило kimi
   «логотип + 3–5 якорей + кнопка» — только для лендинга. → §1.2 [практика] (поправка PLAN №24)
5. **Пунктов верхнего уровня ≤ 7** (8–9 — при коротких подписях); подпись не переносится на вторую строку; «7 ± 2» тут не
   аргумент — предел задаёт ширина строки. → §1.1 [практика] [исследование: NN/g через ux 02-01 §3.2]
6. **Мега-меню — когда у ≥ 2 пунктов по ≥ 10 страниц** в группах: всё видно без прокрутки, каждый пункт один раз, без
   поиска и форм внутри, панель не накрывает экран. → §1.3 [исследование: NN/g 2017, 2024]; порог — [практика] (вывод базы)
7. **Подменю раскрывается кликом, касанием, Enter и Space**; наведение — только дополнение с задержкой 0,5 с; пункт —
   ссылка на хаб + отдельная кнопка с `aria-expanded`; роль `menu`/`menubar` не используется; Esc закрывает. → §1.3
   [стандарт: W3C APG] + [спорно: NN/g 2017 против 2024]
8. **Каскад глубже одного уровня запрещён** — вместо него мега-меню или страница-маршрутизатор. → §1.3 [исследование:
   NN/g 2024]
9. **Гамбургер на десктопе запрещён**; на телефоне ≤ 4 пунктов — видимыми ссылками, больше — кнопка «Меню» с полноэкранным
   списком, мега-меню — последовательным меню (drill-down), не аккордеоном. → §1.3 [исследование: NN/g 2016, 2024]
10. **На телефоне без меню видны логотип и главное действие**; у услуг РФ — ещё телефон `tel:`; шапка ≤ 64 px, частично
    липкая. → §1.3 [данные: M; C 03 §4.2]
11. **Подвал на каждой странице несёт служебные ссылки**: контакты, политику, согласие, оферту, реквизиты — даже если
    контакты есть в шапке. → §1.4 [исследование: NN/g 2019; стандарт через I]
12. **Подвал-карта законна на многостраничнике**, если группы собраны из страниц карты (≥ 2 групп по ≥ 3 страницы);
    гейт Hallmark 43 бракует выдуманные группы, а не колонки. → §1.4 [исследование: NN/g 2019] [спорно] (с Hallmark)
13. **Подвал на телефоне открыт целиком** (`open-list`); аккордеон — только для групп разделов при > 25 ссылках,
    служебные ссылки видимы всегда, и тогда нужна HTML-карта сайта. → §1.4 [исследование: NN/g 2019] [спорно]
14. **Шапка и подвал — роль `chrome`**: без эффектов уровня L1, строятся в пакете 1 с главной и одинаковы на всех
    страницах, включая страницы L0. → §1.5 [практика] (решение 20 PLAN)
15. **Крошки — на страницах глубины ≥ 2 от главной** у разделов со страницей-хабом; нет на главной, страницах 1-го уровня,
    лендингах, 404 и «спасибо»; текущая страница — последней и без ссылки. → §2.1 [консенсус: NN/g 2018, пересм.
    2026-09-01]
16. **Крошки на телефоне — одна строка**: полный путь, если помещается, иначе только родитель. → §2.1 [исследование:
    NN/g 2018, правила 9, 11]
17. **Трейл один — по `parent`**; первый трейл разметки BreadcrumbList равен видимому. → §2.1 [консенсус] / [спорно:
    Google допускает несколько трейлов]
18. **Локальная навигация — у разделов, где сравнивают соседние страницы** (программы, модели, направления): под шапкой
    или слева, тише глобальной. → §2.2 [исследование: NN/g 2021]
19. **Текущее место видно ≥ 2 признаками** (цвет и форма), подсвечен раздел текущей страницы, ссылка на неё —
    `aria-current="page"`; `<title>` уникален. → §2.3 [исследование: NN/g 2015, 2024; стандарт: APG]
20. **Поиск по сайту — когда ищут по названию**: > ≈ 150 страниц, коллекция > ≈ 30 записей (врачи, программы) или
    > ≈ 100 статей; на десктопе — поле, не значок; результаты — `Disallow` шаблона (новый сайт) или `noindex`
    (уже в индексе), не оба (01 §5.2). → §2.4 [практика] [гипотеза] (порог)
21. **Аудитории («Частным / Бизнесу») — не основа меню**; вход аудитории — только с уникальным содержимым. → §2.5
    [исследование: NN/g 2015]
22. **Ссылки идут в трёх направлениях**: вниз (хаб перечисляет всех детей), вверх (крошки, ссылка на хаб), вбок (соседи
    и связанные по полям). → §3.1 [практика] [исследование: NN/g 2019]
23. **Хаб перечисляет коллекцию полностью** ссылками `<a href>`: постраничная навигация или «Показать ещё» со ссылкой на
    следующую страницу; страницы фильтров — `noindex`. → §3.2 [документация: Google]
24. **Связанные материалы строятся из полей связи** (`related_rules`), 2–8 ссылок, по умолчанию после главного призыва; на
    посадочной под платный трафик их нет. → §3.3 [практика] (E `related-links`)
25. **Текст ссылки называет цель** («Цены на имплантацию»), не «Подробнее», «Читать далее», «здесь». → §3.4
    [документация: Google; исследование: NN/g 2024]
26. **У каждой индексируемой страницы ≥ 1 входящая ссылка** со страниц сайта; sitemap сироту не спасает; сиротой может
    быть только неиндексируемое. → §3.5 [документация: Google, Яндекс]
27. **Меню, крошки, пагинация и «связанные» — настоящие `<a href>` в исходном HTML**: без `onclick`, `routerLink`,
    подгрузки меню скриптом. → §3.6 [документация: Google, Яндекс; V:Vkn3R6DUJ34 12:16] [проверено]
28. **URL строчными, через дефис, транслитом по одной схеме**; путь повторяет трейл крошек, у каждого сегмента-предка
    есть страница; без дат, id и расширений; глубина ≤ 3. → §4.1 [документация: Google, Яндекс; мнение: NN/g 1999]
29. **URL не меняются без причины**; меняются — таблица 301 на равноценные страницы, меню сразу на новые адреса. → §4.3
    [документация: Google, Яндекс]
30. **Второй язык — подкаталог `/en/`**, основной язык в корне; не параметр `?lang=` и не cookie; поддомен или ccTLD — при
    отдельной стране, команде или сервере. → §5.2 [документация: Google 2025-12-10]
31. **Переключатель языка** — в утилитарной зоне шапки, самоназвание языка («English»), без флагов, на ту же страницу, без
    автоперенаправления по IP и `Accept-Language`. → §5.3 [документация: Google; практика: ux 07-05 §11]
32. **На странице один язык** — и содержимое, и навигация; меню проверяется на самом длинном языке. → §5.4
    [документация: Google; исследование: W3C через ux 07-05 §6.2]

## 1. Общие элементы сайта: шапка, мега-меню, подвал

### 1.1. Шапка каждой страницы

| Элемент | Правило | Метка |
|---|---|---|
| Логотип | слева вверху, ссылка на главную на всех страницах, включая посадочные без меню; отличается от текста меню | [исследование: NN/g 2016 — логотип по центру даёт в 6 раз больше провалов возврата на главную, 14 сайтов, 50 участников; ux 02-02 §7]; у 23 % живых страниц логотип — не ссылка [данные: M, предварительно] |
| «Главная» словом | явная ссылка на каждой странице: первая крошка, на страницах без крошек — первая ссылка подвала; в меню и крошках одновременно не дублируется | [исследование: NN/g 2024 принцип 1.1; NN/g 2018 правило 8] + [практика] |
| Основная навигация | пункты = хабы и уникальные страницы карты (`chrome.header.items[].page`); порядок — по частоте задач, «Контакты» последними | [консенсус: NN/g 2024 п.2; ux 02-01 §4] |
| Утилиты | справа, над основной строкой или в её конце: телефон, мессенджер, город или адрес, поле поиска, язык, «Войти» (`utilities`) | [исследование: NN/g 2015 — через ux 02-01 §11] |
| Главное действие | одна кнопка справа: `utilities.cta` (`action` + страница или `#якорь` формы) | [практика] (E `header`) |

- **Пункт — только страница карты.** Проверка J (`site_validate.py`): каждый `chrome.header.items[].page` и каждая страница
  групп есть в `pages[]`; пункт с подменю тоже ведёт на страницу-хаб (01 §3.4). Раздел без страниц — дефект, именно это
  Hallmark называет «AI nav»: «the shape is genre-blind» — одна и та же шапка у свадебного фотографа, пекарни и B2B SaaS
  (`anti-patterns.md`). [мнение вендора] + [практика]
- **Пунктов верхнего уровня ≤ 7**, 8–9 — при коротких подписях (схема: `maxItems: 9`). Предел задаёт ширина строки с
  русскими подписями, утилитами и кнопкой, а не «7 ± 2»: NN/g считает и 13 пунктов нормой, если они различимы (ux 02-01
  §3.2). Подпись не переносится на вторую строку ни на одной ширине, где меню развёрнуто; не помещается — короче подпись
  или раньше кнопка «Меню» (Hallmark, гейт 49). [практика] + [мнение вендора]
- **Подписи** описательные, первое слово несёт запах, без выдуманных терминов и оргструктуры («О компании», а не «Опыт
  компании»; «Услуги», а не «Решения», если продаются услуги). Финальный текст — text (`slot:nav-label`). [исследование:
  NN/g «Category names» 2013/2024 — через ux 02-01 §5.2–5.3]
- **Антипример**: «Главная · Услуги · О нас · Блог · Контакты» и кнопка справа у любого бизнеса — пункты не выведены из
  карты, «Блог» пуст, «Главная» в меню дублирует первую крошку. Живые случаи (G/01, §6): у taradash «Home» — и пункт меню,
  и первая крошка; у cleanon пункт «Информация» ничего не обещает.

### 1.2. Архетипы шапки: выбор по структуре сайта

Архетип — компоновка строк шапки (`chrome.header.archetype`); вид каждого пункта — `items[].presentation` (`link`,
`dropdown`, `mega`); подача (форма, цвет, движение, варианты Hallmark N1b–N13) — creative (`hallmark_ref`).

| Архетип | Компоновка | Когда (структура) | Типичный `site_type` | Телефон | Подача Hallmark (creative) |
|---|---|---|---|---|---|
| `minimal-cta` | логотип · контакт · кнопка, меню нет | страница без разделов: лендинг, посадочная под рекламу, кампания из 1–2 страниц | `landing-site`; вариант `landing-minimal` любого сайта | логотип + кнопка или телефон | N9, N2, N5 |
| `bar-links` | логотип · 3–7 ссылок · кнопка | ≤ 7 разделов, подстраницы видны на хабах | `portfolio-site`, `event-site`, `personal-brand-site`, малый `services-site` | ≤ 4 пунктов — `visible-links`, иначе `full-screen-list` | N1b, N5; N1a — только при 2 направлениях |
| `bar-dropdowns` | как `bar-links`, у 1–3 пунктов список ≤ 8 ссылок одного уровня | у части разделов 2–8 подстраниц, которые ищут из меню | `corporate-site`, средний `services-site`, `school-site` с 2–3 направлениями | `full-screen-list` с вложенными списками | N1b |
| `two-tier` | утилитарная полоса (телефон, город, адрес, мессенджер, язык, вход) над основной строкой | ≥ 3 утилит должны быть видны или телефон — канал главного действия (`call`, `booking`) | `services-site` РФ, `corporate-site` с языками | логотип + телефон `tel:` + кнопка | N1b + полоса; прямого аналога нет (N12 — строка объявления, не вторая навигация) |
| `mega-menu` | одна строка, у ≥ 2 пунктов панели с группами | ≥ 2 пунктов по ≥ 10 страниц, которые делятся на группы | крупный `saas-marketing-site`, холдинг `corporate-site` | `drill-down` | N11 |
| `search-led` | поле поиска на виду + меню | условие §2.4: сотни страниц или коллекция, которую ищут по названию | сеть клиник, школа с каталогом, база знаний | значок поиска → лист поиска; `drill-down` | N13 |
| `editorial-masthead` | название по центру, меню строкой ниже, «Главная» пунктом меню | только редакционный жанр: автор или издание с регулярными публикациями | `personal-brand-site` | `full-screen-list` | N6 |

**Порядок выбора** (первое совпадение): (1) у страницы нет разделов → `minimal-cta`; (2) выполнено условие поиска §2.4 →
`search-led`; (3) ≥ 3 видимых утилит или телефон — канал действия → `two-tier`; (4) ≥ 2 пунктов по ≥ 10 страниц →
`mega-menu`; (5) у пунктов 2–8 подстраниц → `bar-dropdowns`; (6) иначе `bar-links`. `editorial-masthead` — только по жанру
брифа. Совмещения (сеть клиник: поиск + телефон + мега-меню услуг) задаются флагами `utilities` и `presentation` пунктов;
архетип один. Примеры G: завод и стоматология — `two-tier`, школа с каталогом — `search-led` с мега-меню «Программы»
(`examples/`); что стоит в шапках живых сайтов — §6. [практика] + [проверено]

Архетипы Hallmark, которые на сайте нельзя брать как есть:
- **N4** (навигация только за ⌘K) — запрещён: скрытую навигацию на десктопе использовали в 27 % случаев против 48 % у
  видимой, находимость ниже на 20 % (NN/g, Pernice и Budiu 2016, 179 участников, 6 сайтов — через ux 02-02 §12.1).
  [исследование]
- **N6** (название по центру) — только `editorial-masthead` с «Главной» в меню: у центрированного логотипа в 6 раз больше
  провалов возврата на главную (NN/g 2016). [спорно]
- **N9, N2** (без ссылок, одна кнопка) — только страницы без разделов; на многостраничнике это вариант шаблона
  `landing-minimal`. [практика]
- **N3** (боковая рейка) — глобальная навигация сайта сверху; слева — только локальная навигация раздела (NN/g 2024 п.2).
  [исследование]
- **N11**: «грация» закрытия 140 мс — заменяется таймингами NN/g (§1.3); мобильные «колонки → аккордеон-группы» —
  последовательным меню. [исследование] против [мнение вендора]
- **Ротация архетипов** («no two outputs may share the same nav archetype») работает между проектами; внутри сайта шапка
  одна на все страницы (§1.5).

**Поправка к `../../kimi-research/07-brief-handoff/templates/build_package.py` (NAV_RULE, стр. 465) для многостраничника:**
«top bar 64–72 px: logo left, 3–5 anchor links, the primary CTA right» остаётся для лендинга (`minimal-cta`, `bar-links` с
якорями); на многостраничнике архетип и пункты берутся из `site-map.chrome.header` (пункты — URL страниц карты), высота на
телефоне ≤ 64 px (C `../03-page-structure/03-first-screen-and-mobile.md` §4.2) — потому что NAV_RULE совпадает с гейтом
Hallmark 42 «AI nav» (аудит KIMI §4 п.1; поправка PLAN №24) и не знает разделов сайта.

### 1.3. Выпадающие списки, мега-меню, меню на телефоне

- **Вид пункта** (`presentation`): `link` — раздел без подменю; `dropdown` — список ≤ 8 ссылок одного уровня; `mega` —
  панель с группами (в схеме ≤ 5 групп по ≤ 8 страниц). **Каскад глубже одного уровня запрещён**: второй уровень раздражает,
  больше двух — «highly inadvisable»; замена — мега-меню или страница-маршрутизатор. [исследование: NN/g 2024 п.14]
  Антипример — список из 67 ссылок в одном пункте (cleanon, G/01): это хаб или мега-меню с группами.
- **Мега-меню — когда** у ≥ 2 пунктов ≥ 10 страниц, которые делятся на группы: «Mega Menus Work Well for Site Navigation» —
  не прячут варианты и группируют их (NN/g 2017, качественные тесты без чисел). **Поправка к
  `../../ux/02-ia-navigation/02-navigation-patterns.md §12.4` для сайта**: «внутри приложения мега-меню не нужно»
  на сайт не переносится — при многих разделах оно законно, потому что исследования NN/g 2017 и 2024 сделаны на сайтах.
  [исследование] (порог «≥ 2 пунктов по ≥ 10 страниц» NN/g не даёт — вывод базы, [практика])
- **Панель**: группы с короткими различимыми заголовками (первое слово информативно), порядок групп — по важности;
  всё видно без прокрутки; **каждый пункт один раз**; без форм, виджетов и **без поля поиска** (поиск всегда на виду);
  картинки и иконки — только вместе с текстом; на больших экранах панель **не накрывает весь экран**. [исследование:
  NN/g 2017; NN/g 2024 пп. 4, 10] Hallmark N11: ≤ ≈ 4 колонок, высота ≤ ≈ 60vh, у пункта — название и строка описания.
  [мнение вендора]
- **Открытие — клик, касание, Enter, Space**; наведение — необязательное дополнение: показать после 0,5 с неподвижности
  за 0,1 с, держать 0,5 с после ухода указателя, не закрывать при движении по диагонали к панели. NN/g 2017 допускал
  наведение с этими таймингами, NN/g 2024 советует клик: касание, клавиатура, случайные срабатывания. [спорно → позиция:
  клик обязателен, наведение — дополнение]
- **Каретка у пункта с подменю; пункт = ссылка на хаб + отдельная кнопка раскрытия.** Так содержимое панели доступно без
  скрипта через хаб (NN/g 2017: каждый пункт верхнего уровня ведёт на обычную страницу со всеми пунктами панели) и снято
  противоречие с Carbon «заголовок выпадающего меню не ссылка» (ux 02-02 §7). Разметка — W3C APG «Disclosure Navigation
  Menu with Top-Level Links»: `<nav>` с именем, в `<li>` ссылка, кнопка с `aria-expanded` и `aria-controls`, вложенный
  список; **роль `menu`/`menubar` для навигации сайта не используется**: обычной навигации не нужна вся клавиатурная
  механика паттерна menubar, а ассистивные технологии ждут её от этой роли. [стандарт: W3C APG, 2026-09-24]

```html
<nav aria-label="Основное меню">
  <ul>
    <li>
      <a href="/uslugi/">Услуги</a>
      <button type="button" aria-expanded="false" aria-controls="nav-uslugi" aria-label="Услуги: разделы"></button>
      <ul id="nav-uslugi" hidden>   <!-- ссылки панели — в исходном HTML, не подгружаются при наведении (§3.6) -->
        <li><a href="/uslugi/implantaciya/">Имплантация</a></li>
        <li><a href="/uslugi/lechenie/">Лечение</a></li>
      </ul>
    </li>
    <li><a href="/ceny/" aria-current="page">Цены</a></li>
  </ul>
</nav>
```

  Клавиатура (APG): Tab — по ссылкам и кнопкам; Enter или Space на кнопке — раскрыть и свернуть; Esc — закрыть и вернуть
  фокус на кнопку; уход фокуса из `<nav>` закрывает панель; стрелки, Home и End — только дополнение к Tab. Имя кнопки
  (`aria-label`) — практика G; APG оговаривает пробелы поддержки на мобильных — проверять.
- **Телефон** (`chrome.header.mobile.pattern`): `visible-links` — ≤ 4 пунктов видимыми ссылками (NN/g Hamburger 2016:
  больше — часть прятать, дополняя ссылками внутри страницы); `full-screen-list` — кнопка «Меню» (значок с подписью) →
  полноэкранный список тех же пунктов в том же порядке, с кнопкой действия и телефоном; `drill-down` — для мега-меню:
  уровень за уровнем, «Назад», первой строкой — ссылка на хаб раздела. **Аккордеон вместо последовательного меню — нет**
  (NN/g 2024 п.9, пример Toyota). [исследование]
- **Одни порядок и названия разделов** на телефоне и десктопе (NN/g 2019 «About Us»: одинаковая структура навигации —
  среди плюсов; ux 02-02 §10); нижняя панель вкладок — не для сайта (поправка PLAN №3); шторка и нижняя панель с одними
  пунктами — дубль. [исследование] + [практика]
- **Гамбургер на десктопе запрещён**: «not suitable for desktop websites» (NN/g 2024 п.1); два меню с одними пунктами
  (строка + гамбургер) — антипример BDO (ux 02-02 §12.2). [исследование]
- **Видимо без меню** (`keep_visible`): логотип всегда; услуги РФ — телефон `tel:` и кнопка записи (телефон — канал
  целевого действия: M `header_phone`, B §3.1); школа и каталог — поиск; сайт с двумя равноправными языками —
  переключатель. [данные: M, выборка 49 страниц] + [практика]
- **Липкость** (`sticky`): по умолчанию `partial` — шапка появляется при прокрутке вверх (300–400 мс), маленькая и
  непрозрачная; на телефоне ≤ 64 px, на десктопе ≤ 80 px, все липкие слои ≤ 20 % высоты экрана телефона; якоря — с
  `scroll-padding-top` на высоту шапки; фокус не прячется под шапкой (WCAG 2.2 2.4.11). [исследование: NN/g 2021 —
  через ux 02-02 §8.2; C 03 §4.2, §4.4] Вторая липкая полоса (локальная навигация) сдвинута на высоту шапки, шапка —
  выше по `z-index` (Hallmark, гейт 56). [мнение вендора]
- **Строка объявления** (`announcement`, E `announcement-bar`): одна, над шапкой, из факта (`fact:`) со сроком `until`,
  закрывается навсегда; не вторая навигация (Hallmark N12). [практика]

### 1.5. Один источник для всех страниц

- **WCAG 2.2**: 3.2.3 Consistent Navigation (AA) — повторяющиеся механизмы навигации в одном относительном порядке на всех
  страницах набора; 3.2.4 Consistent Identification (AA) — одинаковые функции подписаны одинаково; 3.2.6 Consistent Help
  (A) — контакты и помощь в одном порядке; 2.4.5 Multiple Ways (AA) — больше одного способа найти страницу: меню плюс
  поиск, HTML-карта, подвал-карта или связанные ссылки. [стандарт: W3C, 2024-12-12]
- **Механизм**: шапка, подвал, крошки, поиск — один раз в `site-map.chrome`; шаблон выбирает вариант
  (`templates[].header: site | landing-minimal | none`, `footer: site | minimal`); `page-plan.navigation` — копия варианта
  и `archetype` без пунктов меню; J проверяет равенство копии и карты. `none` — не для страниц сайта, только для
  встраиваемых фрагментов (виджет, iframe). [практика] (решение G по вопросу E)
- **Навигация не меняется от страницы к странице** («transitional volatility», Carbon — через ux 02-02 §11); у подсайта —
  своя локальная навигация под общей шапкой (§2.2). Исключение — посадочные под платный трафик (`landing-minimal`,
  C 02 §2.3). [консенсус] + [спорно] (для посадочных)
- **Сборка**: шапка и подвал строятся в пакете 1 вместе с главной как общие компоненты и не генерируются заново в
  следующих пакетах (01 §6). Приёмка каждого пакета — разметка `<header>` и `<footer>` совпадает на всех собранных
  страницах, кроме `aria-current` и активного пункта. [практика]
- **Уровень подачи**: шапка, подвал, утилиты и юридическая полоса — роль `chrome` у creative («вне ритма: visual_role
  chrome, движение — только отклик», `../../creative/01-creative-direction/ambition-levels.yaml`,
  `section_caps.chrome_roles`). Они стоят и на главной (L1), и на внутренних страницах L0 — услуга, цены, контакты, форма,
  статья (решение заказчика п. 20, `defaults_by_page_type`), поэтому собираются без эффектов уровня L1 (морфинг «полоса →
  пилюля» N10, параллакс). Прозрачная шапка поверх hero — только на страницах с hero, контраст ≥ 4,5 : 1, в липком
  состоянии непрозрачная (C 03 §4.1). Уровень страницы не выше уровня сайта; у страниц одного шаблона уровень один (один
  `page-plan`). В `site-map.schema.json` v0 поля уровня нет: его задают бриф (`ambition.by_page`) и `page-plan`
  (`page.ambition_level`); предложение J — `templates[].level` как копия для пакета. [практика] (решение 20 PLAN)
- **Переходы между страницами** (`@view-transition`) и scroll-driven анимации — только прогрессивное улучшение внутри
  `prefers-reduced-motion: no-preference`; поддержку браузеров не дублируем (скоропортится, владелец — creative):
  `../../creative/05-motion/02-choreography-scroll-transitions.md` §3.1, §8.1 (на 2026-09-24); прелоадер,
  блокирующий прокрутку до загрузки, — антипример (там же §9). [практика] (пакет creative волны 2, пп. 5–6)

## 2. Ориентация: крошки, локальная навигация, «Вы здесь», поиск, аудитории

### 2.1. Хлебные крошки

- **Где**: страницы глубины ≥ 2 от главной (главная → раздел → страница), если у раздела есть своя страница-хаб
  (`chrome.breadcrumbs.rule: depth-2-plus`, `templates[].breadcrumbs: true`) — это «с третьего уровня» поправки PLAN №4.
  **Не нужны**: сайт в 1–2 уровня и линейная структура (главы кампании) — `rule: none`, место показывает активный пункт
  меню (NN/g 2018, правило 7: MIT, NPR). Крошек нет на главной, страницах 1-го уровня, лендингах, 404 (GOV.UK — через E
  `not-found`) и «спасибо». [консенсус: NN/g 2018, пересм. 2026-09-01] G/01: крошки на большинстве глубоких страниц — у
  10 из 17 сайтов, в том числе у всех сайтов услуг и корпоративных; у студий, событий и личного блога их нет (§6).
  [проверено]
- **Как**: под глобальной навигацией, над H1; первый пункт — «Главная»; разделитель «›» или «/»; последний пункт —
  текущая страница, не ссылка, визуально отличается; только реальные страницы (заголовок группы мега-меню без своей
  страницы в трейл не попадает); иерархия, а не история посещений; без выпадающих списков соседей — крошки не заменяют
  локальную навигацию. [исследование: NN/g 2018, правила 1–6]
- **Трейл один — по `parent`**; полииерархия (`also_listed_in` ≤ 2 хабов) — ссылками с дополнительных хабов; трейл не
  персонализируется — «mixed signals to search engines» (правило 3). Google допускает несколько трейлов в разметке
  BreadcrumbList и показывает крошки в выдаче только на десктопе (2026-09-24); **первый трейл разметки = видимому**
  (`structured_data: H`). [консенсус] / [спорно: Google против NN/g — дополнительные трейлы решает H]
- **Телефон**: одна строка без переноса (правило 9: у REI перенос вытеснил название товара ниже сгиба); полный трейл, если
  помещается, иначе только родитель «‹ Имплантация» (`mobile: parent-only` по умолчанию); цели касания ≥ 1 × 1 см
  (правило 10); десктоп — полный трейл (правило 11). [исследование]
- **Поправка к `../04-blocks/blocks.yaml` (блок `breadcrumbs`, поле `mobile`: «перенос строк или вариант parent-only») для
  сайта**: перенос строк убрать — одна строка (`full-no-wrap` или `parent-only`), потому что правило 9 NN/g прямо против
  многострочных крошек на телефоне; внесено J в `blocks.yaml` v1 (журнал v1 п. 5). Крошки и кнопка «Назад» вместе не ставятся (ux 02-02 §4.2).
- **Разметка** (E `breadcrumbs`): `<nav aria-label>` + `<ol>`, текущая — `aria-current="page"`, ссылки — `<a href>` (§3.6).

```html
<nav aria-label="Хлебные крошки"><ol>
  <li><a href="/">Главная</a></li>
  <li><a href="/uslugi/">Услуги</a></li>
  <li><a href="/uslugi/implantaciya/">Имплантация</a></li>
  <li aria-current="page">All-on-4</li>
</ol></nav>
```

### 2.2. Локальная навигация раздела

- **Когда** (`templates[].local_nav`): посетитель изучает несколько соседних страниц раздела за визит — сравнивает
  программы, модели, направления — или входит сразу на внутреннюю страницу. Малому сайту не нужна; в очень глубоких
  разделах — контекстные «связанные» (§3.3). [исследование: NN/g 2021]
- **Виды**: `siblings` — соседи раздела (направления компании, категории услуг); `subpages` — подстраницы одного объекта
  (программа: обзор, преподаватели, цены, отзывы; мероприятие: программа, спикеры, место, билеты); `anchors` — оглавление
  длинной страницы (E `anchor-nav`: ≥ 3 пунктов, страница > ≈ 8 экранов десктопа).
- **Место**: горизонтально под шапкой или слева на десктопе (NN/g 2024 п.2: локальная навигация — вдоль левого края на
  десктопных сайтах); на телефоне — горизонтальная полоса или список «В разделе» над содержимым [практика]; **заметна, но
  тише глобальной** — у Generac яркая локальная заслонила глобальную, и посетители решили, что разделов только столько.
  Липкая локальная навигация — для глубокого изучения одного объекта (программа RISD), с отступом на высоту шапки.
  [исследование: NN/g 2021]
- Меняется по разделам, **не по посетителю и не по сессии**; тянет 2–3 уровня, глубже — крошки (Prudential).
  [исследование]
- **Подсайт** (серия конференций, программа курса, продукт холдинга): на каждой странице — ссылка на главную подсайта и на
  главную всего сайта; общая шапка сверху, локальная навигация подсайта ниже; оторванный «микросайт» дробит присутствие
  компании (NN/g 1996, дополнение 2003). [мнение] (механизм в силе)

### 2.3. «Вы здесь»: активный пункт, заголовок окна, адрес

- Не показать текущее место — по NN/g, «the single most common mistake we see on website menus» (NN/g 2024 п.5); каждая
  страница может оказаться первой — вход из поиска «высаживает в незнакомом городе» (NN/g 2015). [исследование]
- **Активный пункт** — раздел текущей страницы, а не только сама страница: на `/uslugi/implantaciya/all-on-4/` подсвечен
  пункт «Услуги». **≥ 2 признака** — цвет и форма (подчёркивание, насечка, начертание): NN/g 2015 — изменение цвета и
  смещения «for better accessibility»; оттенок серого как единственный признак — ошибка (ux 02-02). Ссылка на текущую
  страницу — `aria-current="page"` (APG). [исследование] + [стандарт]
- **`<title>`** — уникальный и описательный: страница → раздел → бренд («All-on-4 — имплантация — Дентис»); слова — text
  (`../../text/07-seo-geo-copy/`), структура — здесь. **Адрес** читаемый и повторяет иерархию (§4.1).
  [исследование: NN/g 2015]
- Проверка в живой фазе — протокол NN/g из 5 вопросов («Где вы? Как вы это поняли? …»); в аналитике блуждание, возвраты и
  pogo-sticking — признак проблемы ИА (NN/g 2015).

### 2.4. Поиск по сайту — когда нужен

| Условие (`chrome.search.enabled`, причина — в `why`) | Решение | Метка |
|---|---|---|
| > ≈ 150 индексируемых страниц | включить | [гипотеза: порог — живая фаза] |
| коллекция > ≈ 30 записей, которую ищут по названию (врачи, программы, услуги клиники) | включить; фильтры хаба — дополнение | [практика] |
| раздел материалов > ≈ 100 статей или база знаний | включить | [практика] |
| ≤ ≈ 50 страниц, 1–2 уровня | не нужен: меню, хабы и подвал дают ≥ 2 способа найти страницу | [практика] + [стандарт: WCAG 2.4.5] |

- **Интерфейс**: на десктопе — **поле, а не значок**, вверху справа, на каждой странице; запрос в среднем ≈ 2 слова; поле
  не прячется в мега-меню (NN/g 2001 — через ux 02-01 §10; NN/g 2017); на телефоне — значок → полноэкранный лист
  (Hallmark N13). [исследование] + [мнение вендора]
- **Результаты** (`search-results-page` (новый id)): `Disallow` шаблона поиска в robots.txt (новый сайт) или `noindex`
  (страницы уже в индексе; `Disallow` — после выпадения) — вместе не работают, за `Disallow` Google не видит `noindex`
  ([V:cfIQ_ksB61U 13:18]; Google «URL structure»; Яндекс
  «Структура сайта»; техника — H); «ничего не найдено» устроено как 404 — подсказки, популярные разделы, контакт (NN/g
  2015); поиск по части сайта без явной подписи области — ловушка (ux 02-01 §10). [документация]
- Примеры G: завод (≈ 45 страниц) и стоматология (≈ 75) — поиск выключен с причиной в `why`; школа (12 программ и
  ≈ 150 статей через год) — включён (`examples/`). Живые сайты — §6.

### 2.5. Вход по аудиториям

- Навигация «Частным лицам · Бизнесу · Партнёрам» основой шапки — **обычно проблема**: не ясно, какую группу выбрать; «о
  группе или для группы?»; лишний шаг самоидентификации; тревога «другим — лучшие цены»; пересечения содержимого → дубли и
  pogo-sticking (NN/g 2015, качественные тесты). [исследование]
- **Можно**: вход аудитории с **уникальным содержимым** (школа: «Компаниям» — корпоративное обучение, `for-companies` в
  `examples/site-map-school.yaml`) — пунктом меню или в утилитарной полосе; подпись с «для» или обращением («Для врачей»,
  «Компаниям»); переход между аудиториями в один клик; разводка аудиторий **заголовками на главной** («For Job Seekers /
  For Businesses» у Robert Half — NN/g 2024, принцип 4.1). Основа меню — темы и задачи. [исследование]
- G/01: у cleanon первые пункты шапки — «Частным клиентам · Юридическим лицам»; допустимо, только если услуги для квартир
  и для офисов действительно разные (уникальность содержимого опыт не проверял). [проверено] (частично)

## 3. Перелинковка

### 3.1. Три направления ссылок

| Направление | Механизм | Поле карты | Правило |
|---|---|---|---|
| Вниз | хаб перечисляет всех детей; главная — хабы и 2–4 примера из каждого раздела | `linking.hubs[]` | каждый ребёнок — в одном клике от своего хаба [исследование: NN/g 2019 «3-click»; NN/g 2024 принцип 3.2] |
| Вверх | крошки на страницах глубины ≥ 2 (§2.1), ссылка на хаб в тексте или локальной навигации, логотип → главная | `templates[].breadcrumbs`, `pages[].parent` | путь к главной без кнопки «Назад» браузера [консенсус] |
| Вбок | соседи раздела, связанные по полям, следующий шаг | `templates[].local_nav`, `linking.related_rules[]` | 2–8 ссылок, только близкое по смыслу [практика] (ux 02-01 §8) |

- «Правило трёх кликов» — миф: отказ не растёт после третьего клика (Porter, UIE 2003 — через NN/g 2019); значение имеют
  запах подписей и «остановки» на хабах. Для робота глубина важна: Яндекс связывает глубину вложенности со скоростью
  индексации — страницы главного входа (услуга, программа, направление) держатся в ≤ 3 переходах от главной через меню и
  хабы. [исследование] + [документация: Яндекс]
- Типовые связи шаблонов (примеры G): услуга → врачи (`team-grid` в тексте), цены, запись; врач → услуги, клиника; проект ↔
  направление; программа → преподаватели, отзывы; статья → программа или услуга (мост к продаже); хаб → все дети.

### 3.2. Хабы и списки

- Раздел с подстраницами = хаб (01 §3.4): список детей с короткими описаниями, «остановка» на пути и переходы к соседям
  (NN/g 2019: хабы в ключевых точках пути, пример Accenture). Порядок — по важности или частоте; по алфавиту — когда ищут по
  известному имени (врачи). [исследование] + [практика: ux 02-01 §4]
- Хаб перечисляет коллекцию **полностью** (`hubs[].lists`). Длинный список — постранично (`collections[].pagination:
  pages`) или «Показать ещё» со ссылкой на следующую страницу (`load-more-with-links`): у каждой страницы списка свой URL
  (`?page=2`) и свой canonical, номера без `#`, ссылка на следующую — `<a href>`; Google кнопки не нажимает и скрипт по
  действию не запускает — лента без ссылок прячет содержимое. Фильтры и сортировки (`facets`) — `noindex` или запрет в
  robots.txt (H). [документация: Google «Pagination», 2026-09-24]

### 3.3. Связанные материалы

- Строятся из полей (`related_rules.by`: `reference-field` — поле связи коллекции; `same-category`, `same-location`,
  `shared-tag`, `next-step`; `editor-pick` — ручной выбор, редко), а не ручными списками на каждой странице (01 §4.4).
- 2–8 ссылок (`max` ≤ 8; E `related-links`); блок — `related-links`, `article-cards`, `case-cards`, `service-cards`,
  `team-grid`; место — после главного призыва (`after-final-cta`, по умолчанию), в тексте (`in-content`, если связь —
  довод: врачи на странице услуги), сбоку (`sidebar`: статьи на десктопе). [практика] (E)
- **Не ставятся** на посадочной под платный трафик — выходы в момент решения (C 02 §2.2); не повторяют меню; только
  несколько самых близких ссылок: избыточные связи на одном экране мешают (ux 02-01 §8). Разметка —
  `<nav aria-label="Связанные материалы">` (E). [практика]

### 3.4. Контекстные ссылки и тексты ссылок

- Google: текст ссылки описательный, короткий, по делу; «Click here», «Read more», «website», «article» — плохо; пустой
  текст — плохо (у картинки-ссылки — `alt`); ссылки не цепочкой подряд, а в контексте предложения. [документация: Google
  «Link best practices», 2026-09-24] NN/g: первые 1–2 слова несут запах; «Click Here», «Explore», «Learn More» — нет
  (NN/g 2024 принцип 4.1; ux 02-01 §5.3). [исследование]

| Плохо | Хорошо |
|---|---|
| «Подробнее» под каждой из 12 карточек услуг | заголовок карточки — ссылка: «Имплантация all-on-4» |
| «Читайте здесь» | «Политика обработки персональных данных» |
| «Узнать больше» в тексте статьи | «сколько стоит имплантация» — ссылка на прайс |

- Карточка — одна ссылка (заголовок), кликабельная область растягивается на карточку; вложенных ссылок нет. Слова ссылок —
  text (`slot:link`). [практика]

### 3.5. Сироты и проверка связности

- Google: «Every page you care about should have a link» с другой страницы сайта; Яндекс: на документ без входящих ссылок
  робот может так и не выйти. → `linking.min_inbound_links: 1` для каждой индексируемой страницы; `orphans_allowed` —
  только неиндексируемые: «спасибо», посадочные под рекламу, результаты поиска. Sitemap — подсказка, а не замена ссылок:
  страницы находят в основном по ссылкам (Google SEO Starter Guide). [документация]
- Проверка карты (J, `site_validate.py`): граф из меню, подвала, хабов, `related_rules` и крошек → число входящих ссылок
  на каждую страницу. Проверка собранного сайта — `ia_probe.py`: `home_links_not_in_sm` (ссылки с главной на адреса вне
  sitemap), `tpl_from_home_pct` (доля шаблонов пути со ссылкой прямо с главной), сверка sitemap со страницами карты (§6).
- Быстрые ссылки (sitelinks) Google строит сам по структуре ссылок: понятные компактные title и заголовки, важные страницы
  со ссылками с релевантных страниц, краткие точные тексты внутренних ссылок; разметки для них нет. [документация: Google
  «Sitelinks»]

### 3.6. Ссылки — настоящие `<a href>` в исходном HTML

- Сканируемая ссылка — `<a href="…">`; не сканируются `<a routerLink>`, `<span href>`, `<a onclick>` без `href`,
  `javascript:` (Google); Яндекс: на каждый документ — обычная ссылка `<a href>`. [документация]
- Шапка, подвал и боковые ссылки — путь, которым краулер находит страницы, не связанные в тексте
  (`[V:Vkn3R6DUJ34 12:16]`); ИИ-краулеры скрипты не исполняют (PLAN, риск 7) — меню, собранное скриптом, для них не
  существует. Отдельная мобильная версия теряла ссылки, навигацию и `hreflang` — одна адаптивная версия на одном URL
  (`[V:kype1JQbrks 22:36]`). [документация]
- Ссылки панели мега-меню — в исходном HTML, скрытые до раскрытия (`hidden`), а не подгружаемые по наведению; пункт
  верхнего уровня — ссылка, не только кнопка; хаб дублирует панель обычной страницей (§1.3). G/01: у linear пункты
  «Product» и «Resources» — кнопки без ссылок, панели в исходном HTML пусты, и путь к разделам в HTML даёт подвал (42 ссылки
  в 6 группах); у kontur панель «Продукты и решения» — 3 ссылки в HTML при подвале из 80 ссылок в 7 группах. [проверено:
  G/01] + [практика]
- Семантика: один `<header>` — шапка сайта с глобальной навигацией внутри; hero — `<section>`, не `<header>`; меню —
  `<nav aria-label>`. G/01: у lewagon `<header>` занят hero, меню — `<nav>` снаружи; у severstal в `<header>` только
  логотип, поиск и язык, главное меню — в боковой панели (§6). [проверено] + [практика] (E `header`)

## 4. Адреса (URL)

### 4.1. Правила пути

| Правило (`url_policy`) | По умолчанию | Почему | Метка |
|---|---|---|---|
| `case` | только строчные | `/APPLE` и `/apple` — разные URL | [документация: Google] |
| `word_separator` | дефис | подчёркивание не разделяет слова | [документация: Google] |
| `slug_source` | `translit` для RU, `english` для EN-версии | Яндекс: транслитерация помогает роботу; Google: слова языка аудитории | [документация] |
| слова, не id | `ids_in_urls: false` | описательные слова вместо длинных id; id — только у коллекций без устойчивых имён | [документация: Google] |
| иерархия | путь = трейл крошек: `/uslugi/implantaciya/all-on-4/` | URL показывает структуру; части пути Google выводит в выдаче как крошки | [мнение: NN/g 1999] + [документация: Google SEO Starter Guide] |
| «взламываемость» | у каждого сегмента-предка есть страница-хаб | обрезал хвост — поднялся на уровень | [мнение: NN/g 1999] |
| `max_depth` | ≤ 3 сегментов без языкового префикса | глубже — хаб или фильтр; Яндекс: глубина вложенности замедляет индексацию | [документация] + [проверено] |
| `section_prefixes` | коллекция под своим сегментом (`/uslugi/…`, `/blog/…`) | каталоги по типу содержимого помогают сканировать большие сайты | [документация: Google] |
| `dates_in_urls`, `file_extensions` | нет | «вечные» страницы без дат; без `.html` и `.php`; архив события — год сегментом (`/2025/`) | [практика] |
| `trailing_slash` | одна форма, вторая — 301 на первую | одно содержимое — один URL | [документация: Google] |
| параметры | только фильтр, сортировка, номер страницы списка (`key=value`) | содержимое — не в параметрах и не во фрагменте `#/` (History API) | [документация: Google] |
| ссылки | от корня: `/uslugi/…`, не `../../` | относительные пути ломаются | [документация: Google] |

- Ключевые слова в пути «alone have hardly any effect beyond appearing in breadcrumbs» (Google SEO Starter Guide,
  2025-12-10): адрес выбирается ради людей и управляемости, а не ради ключей. [документация]
- Microsoft Research 2007 (айтрекинг выдачи): ≈ 24 % времени взгляда — на URL; понятный адрес повышает клики (через
  NN/g «URL as UI», дополнение 2007). [исследование] (2007)
- **Пример**: `/uslugi/implantaciya/all-on-4/`, `/programmy/analitika-dannyh/`. **Антипример**:
  `/Uslugi/Implantaciya_Zubov.php?id=17&sort=asc`, `/#/services/17`.

### 4.2. Кириллица, транслит, домен

- Кириллица в пути допустима (Google: UTF-8, в `href` — percent-encoding; Яндекс: одна кодировка страниц и кириллических
  адресов), но пересланная в мессенджер ссылка превращается в `/%D0%BA%D0%BE…` — по умолчанию транслит
  (`slug_source: translit`) по одной схеме на сайт (`translit_scheme`); схемы не смешиваются. [документация] + [практика]
- Домен: национальный — для местной аудитории (NN/g 1999 [мнение]); ccTLD — сигнал страны для Google (§5.2); прозвища и
  частые опечатки бренда — купить домен и поставить 301 (NN/g 2024, принцип 1.2: coke.com → coca-cola.com).
  [исследование]

### 4.3. Постоянство и смена адресов

- «Do not move pages around» (NN/g 1999): при редизайне адреса сохраняются (`url_policy.keep_existing` = бриф
  `search.existing_site.keep_urls`). [мнение] (механизм в силе)
- Меняешь — таблица «старый → новый» (`url_policy.redirects`): 301 или 308 на равноценную страницу, удалённое без замены —
  404 или 410; меню и внутренние ссылки сразу на новые адреса; новый sitemap; менять по одному (домен, затем CMS, затем
  макет); малый и средний сайт переносится целиком за раз (Google «How to move a site»). Яндекс: проверить, что в меню уже
  новые адреса; после «Переобхода страниц» изменения появляются в поиске примерно за 2 недели. Расхождение Google и Яндекса
  о редиректах удалённых страниц и цепочках — 01 §3.7. [документация] [спорно] (в деталях)
- Бесконечно растущие адреса (`/vasya/vasya/vasya/` — Яндекс), бесконечные календари, аддитивные фильтры, идентификаторы
  сессий и реферальные метки в пути (Google) закрываются правилами `url_policy` и техникой H.

## 5. Языки и регионы (структура)

### 5.1. Версия — адаптация; язык ≠ регион

- Мультиязычный сайт ≠ мультирегиональный (Google: Канада — EN и FR; США и Канада — регионы). Набор версий — бриф
  `languages[]` (`role: primary | adaptation`, `scope: all-pages | selected-pages`); вторая версия — адаптация под свою
  аудиторию, а не дословный перевод (решение заказчика; ux 07-05 §2: порядок слов в пунктах меню переводом не
  выводится). [документация] + [практика]
- Локаль = язык + регион: валюта, единицы, реквизиты (ИНН и ОГРН против VAT), право согласий (ux 07-05 §9.1; I). Версия для
  другой страны строится из её фактов: контакты, цены в валюте, юридический набор юрисдикции. Нет фактов — нет версии.
- Частичная версия (`selected-pages`) — норма для B2B: английская адаптация 7 страниц завода
  (`examples/site-map-corporate-b2b.yaml`); переключатель со страницы без пары ведёт на главную версии
  (`untranslated_fallback: language-home`) или скрыт (`hide-link`).

### 5.2. Структура адресов

| Вариант (`languages.structure`) | Пример | Плюсы | Минусы | Когда |
|---|---|---|---|---|
| `subdirectory` | `example.ru/en/` | легко, один хост, мало поддержки | геотаргет неочевиден, один сервер, разделять сложнее | **по умолчанию** для второго языка |
| `subdomain` | `en.example.ru` | легко, разные серверы, лёгкое разделение | «en — язык или страна?» | отдельная команда, CMS или сервер версии |
| `cctld` | `example.kz` | ясный геотаргет, место сервера не важно, лёгкое разделение | дорого, больше инфраструктуры, строгие правила зоны, одна страна | отдельная страна с юрлицом и фактами |
| параметр | `example.ru/?loc=en` | — | Google не рекомендует | запрещён |

[документация: Google «Managing multi-regional and multilingual sites», обновлено 2025-12-10]

- Основной язык — в корне без префикса (`primary_prefix: false`), второй — `/en/` (`versions[].base`). **Отдельные URL**
  для каждой версии: не cookie и не подмена по `Accept-Language` на одном URL — Googlebot обычно сканирует из США,
  `Accept-Language` не шлёт и варианты может не найти. Зоны `.io`, `.ai`, `.co`, `.me`, `.tv`, `.su` Google считает
  общими. [документация]
- G/01: подкаталог — heisenbug (`/en/`), lewagon (6 языковых префиксов), thoughtworks (12 префиксов «язык-регион»:
  `en-gb`, `de-de`, `pt-br` …); оба языка с префиксом — severstal (`/rus/`, `/eng/`); отдельный домен — ilyabirman
  (`.net`), medsi и artlebedev (`.com`, у artlebedev ещё `?lang=cn`). [проверено]

### 5.3. Переключатель языка

- **Место**: утилитарная зона шапки справа (`switcher.placement: header-utility`), по желанию — ещё и подвал; на телефоне —
  в меню, а видимым — если второй язык равноправный вход (§1.3). [практика: ux 07-05 §11]
- **Подпись**: самоназвание языка («Русский», «English», «Қазақша»), **не флаг** (флаг — страна) и не «RU/EN»
  (`label: native-name`); `native-code` — допуск для узкой шапки телефона, полное название — в меню. Текст ссылки на другом
  языке — с атрибутом `lang` (WCAG 3.1.2). [практика: ux 07-05 §10.2, §11] + [стандарт]
- **Поведение**: ведёт на **ту же страницу** другой версии (`same_page: true`); без пары — по `untranslated_fallback`;
  **без автоперенаправления** по IP и `Accept-Language` (`auto_redirect: false`): Google — не перенаправлять по догадке о
  языке, давать ссылки на версии; ux — редирект по IP ломает прямые ссылки. Запомненный выбор не уводит с прямой ссылки:
  источник правды — URL. [документация] + [практика]
- G/01: на ту же страницу другой версии переключатель ведёт у 3 из 6 сайтов с переключателем (heisenbug 14 из 14
  внутренних страниц, thoughtworks 13 из 14, ilyabirman 13 из 13); у medsi — на главную `.com` (12 из 12), у severstal —
  чаще на раздел (`/eng/clients/` со страницы изделия, 7 из 11), у artlebedev — на раздел `.com`. **Антипример** — эти три
  случая, флаги вместо названий, `?lang=en` на том же URL. [проверено]

### 5.4. Содержимое версии

- **Один язык на странице** — и содержимое, и навигация; без переводов «бок о бок» и без перевода одной обвязки при
  содержимом на другом языке. Google определяет язык **по видимому содержимому**, не по `lang` и не по URL; атрибут `lang`
  у `<html>` всё равно обязателен — для экранных дикторов (WCAG 3.1.1; ux 07-05 §10.2). [документация] + [стандарт]
- Меню версии — только разделы, которые есть в этой версии (кроме переключателя). Слаги английской версии — английскими
  словами (`slug_source: english`; Google: слова языка аудитории). [практика]
- **Длина подписей**: при переводе строки до 10 знаков вырастают в 2–3 раза, 11–20 знаков — в 1,8–2 раза (таблица IBM у W3C
  — через ux 07-05 §6.2) → шапку, пункты меню и кнопки проверять на самом длинном языке, без переноса (§1.1).
  [исследование]

### 5.5. Граница с H

H — `hreflang` (теги, заголовки или sitemap), `x-default`, canonical на себя у каждой версии, языковые пары в sitemap,
сигналы региона. G — какие версии есть (`languages.versions[]`), где живут (`structure`, `base`), какие страницы в какой
версии (`pages[].lang_versions`), переключатель (`switcher`). G/01: `hreflang` в `<head>` — у 6 из 19 сайтов, в sitemap —
у 1 (heisenbug, все 196 URL) (§6).

## Частые ошибки

1. Шапка «логотип + 5 ссылок + кнопка» одна и та же у пекарни, клиники и завода; пункты не из карты; «Ресурсы» и «Блог» без
   страниц.
2. Пункт верхнего уровня — кнопка без ссылки, раздел-«папка» без хаба (у linear «Product» и «Resources» — кнопки без
   `href`, G/01).
3. Выпадающий список на десятки ссылок одним столбцом (cleanon — 67 в одном пункте, G/01) вместо хаба или мега-меню с
   группами; каскад второго уровня.
4. Гамбургер на десктопе; навигация только за ⌘K или значком; шапка разная на разных страницах, потому что исполнитель
   собирал её для каждой страницы заново.
5. Мега-меню только по наведению, на весь экран, с полем поиска внутри; роль `menu`/`menubar` у навигации сайта; панель
   подгружается скриптом.
6. Крошки на главной и страницах 1-го уровня, в две строки на телефоне, вместе с «Назад»; «Главная» и в меню, и первой
   крошкой (taradash, G/01); трейл по истории посещений.
7. Подвал, свёрнутый на телефоне в аккордеон целиком; колонка «Ресурсы» у сайта без материалов; нет реквизитов и политики
   на посадочной без меню.
8. «Подробнее» под каждой карточкой хаба; «Показать ещё» без ссылки на следующую страницу; меню и «связанные» только в JS.
9. Страницы серии без входящих ссылок — только в sitemap; «связанные» из случайных записей, а не из полей связи.
10. `<header>` для hero, меню вне `<header>` (lewagon, severstal — G/01); два меню с одними пунктами.
11. URL с заглавными буквами, подчёркиваниями, `.php?id=`, датами у «вечных» страниц; смена адресов при редизайне без 301
    и без правки меню.
12. Автоперенаправление по IP на `/en/`; флаги вместо названий языков; переключатель ведёт на главную или раздел другой
    версии (medsi, severstal — G/01); `?lang=` на том же URL; меню на одном языке, текст на другом.

## Чек-лист

- [ ] **SITE-NAV-01** Шапка, подвал, крошки и поиск описаны один раз в `site-map.chrome`; `page-plan.navigation` только
  выбирает вариант?
- [ ] **SITE-NAV-02** Каждый пункт шапки и каждая страница групп подвала есть в `pages[]`; у пункта с подменю есть хаб?
- [ ] **SITE-NAV-03** Архетип шапки выбран по порядку §1.2, причина записана; NAV_RULE к многостраничнику не применён?
- [ ] **SITE-NAV-04** Пунктов верхнего уровня ≤ 7 (8–9 — с короткими подписями); подписи без переноса на самом длинном
  языке?
- [ ] **SITE-NAV-05** Подменю — по клику и Enter; ссылка + кнопка `aria-expanded`; Esc закрывает; роли `menu` нет;
  каскада второго уровня нет?
- [ ] **SITE-NAV-06** На десктопе нет гамбургера; на телефоне ≤ 4 пунктов видимы или «Меню» с тем же порядком; мега-меню
  — последовательным меню?
- [ ] **SITE-NAV-07** На телефоне без меню видны логотип и действие (у услуг — `tel:`); шапка ≤ 64 px, частично липкая,
  фокус не перекрыт?
- [ ] **SITE-NAV-08** В подвале каждой страницы — контакты, юридические ссылки и реквизиты; группы из реальных страниц; на
  телефоне подвал открыт?
- [ ] **SITE-NAV-09** Шапка и подвал собраны в пакете 1 и совпадают на всех страницах (кроме `aria-current`); без эффектов
  L1?
- [ ] **SITE-NAV-10** Крошки только на страницах глубины ≥ 2 у разделов с хабом; одна строка на телефоне; трейл по
  `parent`; BreadcrumbList = видимому?
- [ ] **SITE-NAV-11** Раздел текущей страницы подсвечен ≥ 2 признаками; `aria-current="page"`; `<title>` уникален?
- [ ] **SITE-NAV-12** Решение о поиске записано в `chrome.search.why` по таблице §2.4; результаты — `Disallow`
  шаблона (новый сайт) или `noindex` (уже в индексе), не оба?
- [ ] **SITE-NAV-13** Хабы перечисляют коллекции полностью; пагинация и «Показать ещё» — со ссылками `<a href>`; фильтры
  не индексируются?
- [ ] **SITE-NAV-14** «Связанные» строятся из полей связи, 2–8 ссылок, на посадочной под рекламу их нет?
- [ ] **SITE-NAV-15** У каждой индексируемой страницы ≥ 1 входящая ссылка; сироты — только неиндексируемые?
- [ ] **SITE-NAV-16** Все ссылки навигации — `<a href>` в исходном HTML (проверка `ia_probe.py` или исходного кода)?
- [ ] **SITE-NAV-17** URL строчными, через дефис, одна схема транслита, путь = трейл, у предков есть страницы, глубина
  ≤ 3, одна форма слэша?
- [ ] **SITE-NAV-18** При смене адресов — таблица 301 на равноценные страницы, меню и ссылки обновлены?
- [ ] **SITE-NAV-19** У второго языка отдельные URL (`/en/` по умолчанию); переключатель — самоназвание, та же страница,
  без автоперенаправления; на странице один язык?

## Открытые вопросы и противоречия

1. **Наведение или клик** для подменю: NN/g 2017 (тайминги 0,5/0,1/0,5 с) против NN/g 2024 (клик) [спорно]; позиция —
   клик обязателен; проверить тестом находимости с клавиатурой и касанием.
2. **Подвал-карта**: Hallmark (гейт 43) против NN/g 2019 — решено условием «группы из реальных страниц»; визуальный
   отпечаток — creative.
3. **Подвал на телефоне**: NN/g 2019 против аккордеона E — по умолчанию открыт; порог 25 ссылок перенесён из правила NN/g
   о полной карте в подвале и для аккордеона не измерен (живая фаза, отчёт G).
4. **Несколько трейлов** BreadcrumbList (Google) против одного видимого (NN/g) — дополнительные трейлы решает H.
5. **Порог поиска** (≈ 150 страниц, ≈ 30 записей, ≈ 100 статей) — гипотеза; «Search: Visible and Simple» (NN/g 2001)
   прочитана через ux, не напрямую; проверка — аналитика поиска на живых сайтах.
6. **`native-code` («EN»)** в узкой шапке против ux 07-05 §11 (только самоназвание) — допуск G, проверить на понятность.
7. **Центрированный логотип** (N6) — только редакционный жанр с «Главной» в меню [спорно]; исследований на русских сайтах
   нет.
8. **Меню и телефон, которые вставляет скрипт**, `ia_probe.py` не видит: число пунктов, мега-меню и видимость на телефоне
   — только браузером; сверка с итоговым `pages.csv` M (5 общих доменов, пересчёт X2) это подтверждает (§6): у сайта с серверной шапкой
   (taradash) HTTP и браузер совпадают, у сайтов со скриптовыми панелями (kontur, practicum, stamus) — нет.
9. **Уровень подачи** в `site-map` не задан: предложение J — `templates[].level` (копия из брифа) и проверка «шаблон ≤
   сайт»; умолчания для новых `page_type` G — предложение creative и J (отчёт G, раздел 6).
10. **Паттерн APG**: имя кнопки раскрытия (`aria-label`) — практика G; поддержку на телефонах и экранных дикторах APG сам
    просит проверять.
11. **Google против Яндекса** о редиректах удалённых страниц и цепочках — 01 §3.7 [спорно].
