## Часть 1. Профиль `ux-marketing-profile.tsv`

- **Цель.** Для каждого из 434 пунктов `UX-*` сводного чек-листа ux (`../ux/12-evaluation-checklists/master-checklist.yaml`,
  20 блоков) решить, как он действует на маркетинговой странице: `keep` (как есть), `modify` (с поправкой порога,
  серьёзности, условия или объёма), `off` (объекта на сайте нет или это визуальный слой creative), `replaced` (заменён
  пунктом `SITE-*` или `CRV-*`, `COPY-*` сестёр). Основание — таблица поправок PLAN №1–26 (исполнитель профиля K: №1, 3, 4,
  5, 6, 7, 10, 11, 13, 15), аудит UX §4 п.1–17 и §7 п.3 (`99-raw/notes/audit-2026-09-24/UX-report.md`).
- **Команда.** `python3 ../../scripts/site/build_profile.py` → `09-ai-generation-evaluation/ux-marketing-profile.tsv`
  (434 строки + заголовок, 7 колонок строго `ux_id block ux_text_short site_action site_replacement reason source`),
  `ac-profile.tsv` (наследование для 246 автопроверок `AC-*` ux), `summary.md`. `--check` — TSV совпадает с решениями.
- **Как устроено.** Решение по блоку (`BLOCK_DEFAULT`, 20 блоков) + 294 точечных решения (`DECISIONS`: id | действие |
  замена | причина | источник). Проверки скрипта: ровно 434 строки; действие из четырёх; у `replaced` непустая замена;
  каждый `SITE-*` есть в `site-checklist.yaml`, `COPY-*` — в `copy-checklist.yaml` или `copy-rubric.yaml` text, `CRV-*` — в
  `ambition-levels.yaml` creative; решения только для существующих id; пункты, названные аудитом UX ложными блокерами
  (UX-FBK-14/15, UX-LAY-02/03/09/13/16, UX-NAV-12, UX-AIG-01/06, UX-OVL-02, UX-CNS-23, UX-TXT-13/14, UX-FLW-18,
  UX-ETH-12, UX-FBK-12, UX-PRE-05), не могут остаться `keep`. Результат 20:58 — 0 ошибок; `--check` — «TSV совпадает».
- **Смысл колонки `site_replacement`.** Для `replaced` — замена (обязательна); для `modify` — пункт с поправкой; для `keep` —
  пункт сводного чек-листа, где правило уже учтено (если есть); для `off` — пусто (куда ушла проверка — в `reason`).

## Часть 2. Срабатывания UX-проверок «до» и «после» профиля на 8 страницах

- **Цель.** Посчитать, сколько автоматических проверок ux срабатывают на маркетинговых страницах, если применять норму ux как
  есть, и сколько — после профиля (пункт заменён или изменён пунктом `SITE-*`); каждое оставшееся срабатывание разобрать:
  верное или ложное. Не перепись 434 пунктов: взяты известные ложные блокеры аудита UX §4 и три контрольных пункта `keep`.
- **Страницы** — те же 8, что в K/03 (`../03-gates-v1/README.md`): 5 из выборки M (`02-site-types/pages.csv`, `valid=1` и
  `speed_valid=1` на обоих устройствах) — ru-azbukaokon, en-capsule, ru-matemarketing, en-headspace, mp-taradash-home — и 3
  демо генераторов — evebcn.com (Lovable), makro.framer.website (шаблон Framer), naturepurecleaning.com (Durable).
- **Данные.** Анатомия `page_anatomy.py` (десктоп и телефон; M/03 — 24.09 ≈ 13:00–17:30, демо — 21:01–21:48), сырой HTML и CSS
  (`../03-gates-v1/pages/`, 21:00), движение на 6-й секунде и axe (`../I/02-axe/out/` 15:03–15:13 для трёх страниц,
  `../03-gates-v1/axe/` 21:32–21:46 для пяти).
- **Команда.** `python3 99-raw/experiments/K/02-ux-profile/fp_check.py` → `fp_results.tsv` (страница × устройство ×
  проверка), `fp_summary.md`.
- **Как считается «до»**: AC-NAV-09 — сплошных главных кнопок > 1; AC-NAV-10 — одна подпись призыва ≥ 2 раз; AC-DOM-08 — нет
  `h1` внутри `<header>` внутри `<main>`; AC-SCF-15 — баннер cookie или окно без действия; AC-TXT-02 — словарь («John Doe»,
  «10k+», «Trusted by», «Нам доверяют», «4,9 из 5»…); AC-TXT-13 — капс или Title Case в заголовках и кнопках (с учётом
  `text-transform`), прямые кавычки в русском тексте; AC-LNT-11 — `IntersectionObserver`, `data-aos`, `data-framer-appear-id`,
  `animation … infinite` в HTML и CSS или бесконечная анимация на 6-й секунде; AC-LNT-12 — автовидео или автокарусель;
  AC-LAY-08 — движущихся элементов > 1; AC-NAV-06 (UX-NAV-12) — липких слоёв на телефоне > 1.
- **Как считается «после»** — по пунктам-заменам: SITE-CTA-02 (одна кнопка на странице длиннее 3 экранов; главный призыв в
  ≥ 3 секциях подряд; `cta-band` ≥ 3 с уверенностью ≥ 0,5), SITE-CTA-04 (две сплошные главные кнопки разных действий рядом в
  первом экране), SITE-BLK-03 и SITE-NAV-20 (H1 ≠ 1; логотип не ведёт на главную), SITE-CTA-07 (окно без действия), SITE-A11Y-14
  (модальный баннер), SITE-LEGAL-06 (нет «Отклонить» на первом уровне — только для права РФ и ЕС), SITE-OUT-03 (заглушки),
  SITE-A11Y-01 (движение > 5 с без паузы), SITE-A11Y-02 (видео со звуком), SITE-BLK-07 (автокарусель), SITE-MOB-05 (липкие
  слои > 20 % высоты); AC-TXT-13 уходит к text (COPY-C-14) — в профиле site не проверяется.

человек. **Что добавилось:** site ловит обратную ошибку — один призыв на длинную страницу (6 срабатываний) — и дефекты
законного баннера (10), которых норма «оверлей запрещён» не различает.

## Вывод

1. Норма ux как есть на маркетинговых страницах даёт **87 % ложных срабатываний** в проверенных пунктах (73 из 84);
   после профиля — **3–14 %** (1 ложное и 4 спорных из 37), при этом 10 из 11 верных находок сохраняются.
2. Больше всего ложных дают «одна primary», «ни одно действие дважды», «шапка страницы с H1», «оверлей без действия»,
   капс и Title Case — ровно пункты таблицы поправок PLAN №1, 4, 6 и аудита UX §4 п.2, 3, 8, 10.
3. Словарные проверки доказательств (AC-TXT-02) ошибаются в обе стороны; опора — связка с фактами в плане.
4. Замеры тоже ошибаются: `scrollWidth` без учёта `overflow-x: hidden`, склейка `innerText` на скрытых `<br>`, `href="./"`
   — поэтому B из автопроверки подтверждается кадром или HTML (правка ворот — K/03).

## Ограничения

8 страниц — иллюстрация, не норма; разбор «верное или ложное» — одним агентом по кадрам, HTML и данным замера, без людей;
движение — один снимок на 6-й секунде десктопа (кнопка паузы ищется по имени); «главный призыв» — самый частый текст
призыва по анатомии M; оценка AC-DOM-08 — по сырому HTML, AC-TXT-13 — по видимому тексту с учётом `text-transform`.
