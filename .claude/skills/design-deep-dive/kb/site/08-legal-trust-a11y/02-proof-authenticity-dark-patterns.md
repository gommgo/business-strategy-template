## Выжимка для агента

1. **Нет факта — нет блока**: каждое число, отзыв, логотип, рейтинг, награда, сертификат, кейс, человек и старая цена
   на странице — слот `data` со ссылкой `fact:<id>` на `facts.yaml`; генератор не пишет доказательств от себя. → §1
   `[практика]` + `[стандарт]` (38-ФЗ ст. 5 ч. 3; UCPD прил. I п. 23b–c)
2. **У факта-доказательства — источник, дата, проверка и разрешение**: `verification.status: verified` для чужих слов,
   логотипов и рейтингов; `stated` — только для собственных свойств и цен заказчика. → §1.2 `[практика]`
3. **«Нам доверяют», «10 000+ клиентов», «4,9 из 5» разрешены** при связке с фактом (источник, дата, для рейтинга —
   площадка и число оценок); без связки — запрет. → §1.2 `[практика]` (поправка 7 PLAN)
4. **Логотип клиента — файл от клиента с письменным разрешением**, подпись связи видимым текстом («клиенты по
   договору»); чужие логотипы по памяти и генерация логотипов — запрет. → §1.2 `[стандарт]` (ГК 1484; ai-media 12/04 №15, 18)
5. **Рейтинг площадки — текстом с площадкой, шкалой, числом оценок и датой снимка + ссылка на карточку**; звёзды без
   источника — запрет. → §1.2 `[практика]` (ГОСТ Р ИСО 20488 п. 7.2)
6. **Люди-доказательства — только реальные с согласием**: клиенты, авторы отзывов, команда, эксперты, врачи,
   преподаватели, спикеры, «наши мастера», результаты «до/после». ИИ-люди в этих ролях — никогда. → §2.1 `[стандарт]`
   (ГК 152.1; 152-ФЗ ст. 10.1; решение заказчика 15)
7. **Люди-декор (атмосфера, сценарий) — реальные со стока с лицензией или ИИ по решению заказчика**, без подписи-
   утверждения «наш клиент», для ЕС — с видимой меткой ИИ. → §2.1 `[практика]` + `[стандарт]` (AI Act 50(4))
8. **«Люди в hero» — это п. 6 или 7 по смыслу hero**: если hero говорит «наша команда», «наш клиент», «результат» —
   правило доказательств; если это сцена — правило декора. Фото людей само доверие не поднимает. → §2.2 `[исследование]`
   (CHI 2003)
9. **Медицина: «до/после» и истории излечения на посадочной — нет** (38-ФЗ ст. 24); в портфолио клиники — только с
   письменным согласием пациента (сведения о здоровье). → §2.3 `[стандарт]`
10. **Отзыв — дословно, с датой, согласием автора на показ имени и фото**; правка — только автором; сокращение — с
    его согласия. → §3.2 `[стандарт]` (152-ФЗ ст. 10.1; ГК 1266; ГОСТ Р ИСО 20488 п. 6.8)
11. **Раздел отзывов публикует и отрицательные**, быстро (≤ 72 ч по ГОСТ), с правилами модерации на сайте; витринная
    подборка на лендинге подписана «подборка» со ссылкой на все отзывы. → §3.3 РФ — `[практика]` (ГОСТ Р ИСО 20488-2023
    добровольный); ЕС — `[стандарт]` (UCPD 7(6), прил. I п. 23b–c)
12. **Отзывы с Яндекс Карт, 2ГИС — официальным виджетом площадки или цитатой без имени со ссылкой**, не скриншотом с
    именами. → §3.4 `[стандарт]` (152-ФЗ ст. 10.1 ч. 2)
13. **Отзыв за вознаграждение помечается рядом**; купленные и написанные нанятыми людьми — не публикуются. → §3.2 РФ — `[практика]`
    (ГОСТ Р ИСО 20488 п. 5.6, добровольный); ЕС — `[стандарт]` (UCPD 7(6), прил. I п. 23b–c)
14. **Таймер — только до реальной даты из факта `promo` (`valid.until`), без сброса, с текстовой датой рядом**. → §4
    `[исследование]` (157 из 393 таймеров лживые — Mathur 2019)
15. **«Осталось N мест» — только живые данные с временем обновления**; «мало» без числа при известном числе — нет. → §4
    `[исследование]`
16. **Никаких виджетов «Алексей из Казани только что купил», «12 человек смотрят»** без реальных данных; с реальными —
    не на лендинге по умолчанию. → §4 `[исследование]`
17. **Отказ в окне и форме — нейтральной подписью** («Не сейчас», «Не подписываться»), без стыда. → §4 `[консенсус]`
18. **Подписка с лендинга — только отдельной неотмеченной галочкой**; предотметка рассылки и платных опций — запрет. → §4
    `[стандарт]`
19. **«Бесплатно» с платным продолжением — сумма, период и дата первого списания рядом с кнопкой** до ввода карты. → §4
    `[консенсус]` (ux 06/04 §8.1 п. 14)
20. **Зачёркнутая цена — только реально действовавшая** (факт с периодом); ЕС — минимальная за 30 дней. → §4 `[стандарт]`
21. **Процедура сбора доказательств — до вёрстки**: анкета → документы и разрешения → проверка → `facts.yaml` → план;
    пустой инвентарь — честная страница без выдумок (процесс, договор, гарантии, лицо основателя с согласием). → §5 `[практика]`
22. **Заказчик просит тёмный приём — назвать его, показать норму, дать честную замену и парную метрику** (конверсия ↔
    отмены и жалобы); по закону отказ не отменяется повторной просьбой. → §6 `[мнение]` (ux 06/04 §8.4)

## 1. Правило подлинности по видам доказательств

### 1.1. Принцип

Инвентарь доказательств в брифе — **единственный** источник чисел, отзывов, логотипов, наград и людей (PLAN, риск 4;
контракт §3 п. 10). Цепочка: `site-brief.proof.facts_ref` → `facts.yaml` (формат text B2) → слот `data` плана страницы
(`fact_kinds` блока в `blocks.yaml` E) → текст `copy-deck` (text) → сверка `claims_check.py` (text). Правило подлинности I
добавляет к этой цепочке **условия допуска факта на страницу**: чем подтверждён, чьё разрешение, на какую дату, где
можно показывать. Граница «убеждение ↔ обман» — достоверность содержания: реальные отзывы, настоящая старая цена, живой
остаток — убеждение (NN/g по ux 06/04 §1.2) `[консенсус]`.

### 1.3. Где правило ломает чужие проверки

**Поправка к `../../ux/07-ux-writing/06-banned-words-and-patterns.md` §5.2, UX-AIG-01, AC-TXT-02 для сайта:**
«Нам доверяют», «10 000+», «4,9 из 5» разрешены, если каждый элемент — слот `data` с `fact:<id>`, у факта есть источник и
дата; проверка — по связке (`site_validate.py` J: каждый `fact:` существует и допущен), а не регулярным выражением,
потому что регулярка режет настоящие доказательства (аудит UX §4 п. 7) и не видит выдуманных без ключевых слов.

### 2.3. Медицина и здоровье

38-ФЗ ст. 24 ч. 1 п. 2 запрещает в рекламе «ссылки на конкретные случаи излечения от заболеваний, улучшения состояния
здоровья человека в результате применения объекта рекламирования», п. 3 — благодарности физических лиц; ч. 3
распространяет п. 2–5 на рекламу медицинских услуг, методов профилактики, диагностики, лечения и реабилитации [S1]
`[стандарт]`. Следствия: на посадочной клиники — без «до/после» (стоматология, косметология-медуслуга, коррекция зрения),
без отзывов-благодарностей и «вылечили»; в разделе работ сайта (не реклама по ФАС 821/23) — `[спорно]`, только с
письменным согласием пациента (фото — сведения о здоровье, специальная категория ПД, 152-ФЗ ст. 10) и без обещания
результата. Немедицинские «до/после» (ремонт, клининг, благоустройство) — можно, только реальные (ai-media 12/04 №10).

## 3. Отзывы как процесс

### 3.1. Что регулирует отзывы

| Норма | Что даёт сайту | Метка |
|---|---|---|
| 38-ФЗ ст. 5 ч. 3 п. 10 (ред. от 04.08.2026) | отзывы и рекомендации в рекламе — достоверны | `[стандарт]` |
| ФАС 821/23 разд. 9 | отзывы в специальном разделе — не реклама; на лендинге под трафик — часть рекламы (text H) | `[регулятор]` + `[спорно]` |
| 152-ФЗ ст. 10.1; ГК 152.1 | имя и фото автора — согласие на распространение и изображение | `[стандарт]` |
| ГК 1266 | правка произведения — с согласия автора | `[стандарт]` |
| ГОСТ Р ИСО 20488-2023 (IDT ISO 20488:2018; утв. приказом Росстандарта от 02.10.2023 № 1029-ст) | сбор, модерация, публикация — добровольный стандарт | `[стандарт]` (добровольный) |
| UCPD ст. 7(6), прил. I п. 23b–c (Omnibus 2019/2161) — ЕС | сказать, как проверяются отзывы; фальшивые и искажённые — запрет | `[стандарт]` |
| FTC 16 CFR 465 — США (ai-media 12/03 §1.3) | запрет отзывов несуществующих авторов, ИИ-лиц | `[стандарт]`, профиль `us` не покрыт |

### 3.2. Сбор и публикация (ГОСТ Р ИСО 20488-2023)

- **Запрос отзыва** — после опыта клиента (п. 5.4.3); в запросе — кто просит, о чём, где и как опубликуют, какие ПД
  покажут, ссылка на правила (п. 5.4.2) [S3]. Для сайта: письмо-запрос содержит галочки «можно показать имя», «можно
  фото» (→ `permission.shows`, `pd_consent`, `image_consent`).
- **Купленные отзывы и отзывы нанятых лиц не публикуются** (п. 5.6.1); вознаграждение за отзыв — не зависит от оценки,
  описано в правилах, **помечено рядом с отзывом** (п. 5.6.2) [S3].
- **Администратор не редактирует отзывы**; правка — автором, с пометкой «Отзыв был отредактирован автором» и датой
  (п. 6.8); удаление — по требованию автора обязательно (п. 6.7.1) [S3]. Соответствует ГК 1266 и text H §7 (опечатки —
  допустимо по B2 text; всё прочее — с согласия автора).
- **Отклонение** — только при мошенничестве или нарушении опубликованных правил (п. 6.6) [S3].

### 3.3. Показ

- **Раздел отзывов** (`page-type:reviews-page`, многостраничник): публикует и положительные, и отрицательные «как можно
  быстрее… в течение 72 ч, но не более чем через месяц», публикация не задерживается из-за связи с поставщиком (п. 7.6);
  общий рейтинг — математически объективный, с методом и **рядом с числом отзывов** (п. 7.2); правила публикации — на
  сайте (п. 7.4–7.5) [S3].
- **Витрина на лендинге** (`block:testimonial-cards`): отобранные отзывы — законно, если подпись честная («Отзывы
  клиентов, подборка») и есть ссылка на раздел или площадку (`slot:stat-source` «откуда отзывы и за какой период»).
  ЕС: при показе отзывов — сказать, проверяете ли вы и как (UCPD 7(6)); только положительные, скрывая отрицательные, —
  манипуляция (Omnibus, соображение 49) [S5].
- **Ответ компании** на отзыв — можно, как «право на ответ» (ГОСТ п. 7.8), без удаления неудобного отзыва.

### 3.4. Отзывы с площадок (Яндекс Карты, 2ГИС, отзовики)

- Человек сам опубликовал отзыв на площадке, согласия сайту не давал → **распространяя его имя и фото на своём сайте,
  доказывать законность обязан сайт** (152-ФЗ ст. 10.1 ч. 2) [S2]; тексты — ещё и правила площадки и авторское право
  (не разбиралось, `[не проверено]`).
- Варианты по безопасности: (1) официальный виджет площадки (встраивание по её правилам — `permission.form:
  platform-terms` в `facts.yaml`); (2) рейтинг текстом + ссылка на карточку (`block:review-aggregate`); (3) цитата без
  имени и аватара со ссылкой на источник и датой; (4) запрос автору и отзыв с согласием — лучший.
- Виджет — стороннее содержимое: грузить фасадом по прокрутке (вес — P), у iframe `title` (доступность — `03` §4).

## 5. Процедура сбора доказательств у заказчика (с F и text)

1. **Инвентарь по анкете** text `proof-intake.md` (что есть: цифры, отзывы, клиенты, награды, сертификаты, люди, кейсы,
   цены и акции) → черновой `facts.yaml` со статусами `unverified`.
2. **Документы**: для каждого чужого доказательства — разрешение (письмо, подписанное согласие, пункт договора,
   правила площадки); для людей — согласие на изображение и на распространение ПД (отдельными документами; шаблоны — юрист
   заказчика); для чисел — источник (CRM, отчёт, реестр) и дата.
3. **Проверка** (`verification`): отзыв — найден у автора или на площадке; логотип — файл от клиента; рейтинг — снимок
   карточки с датой; сертификат — номер в реестре; старая цена — история цен.
4. **Допуск**: `permission.status: granted`, `verification.status: verified` (или `stated` для своих свойств) → факт
   разрешён к слотам по `use`; `missing[]` — пробелы с вопросами заказчику; `never_claim[]` — чего утверждать нельзя.
5. **План страницы**: блоки с `requires_facts: true` (E) ставятся только при наличии допущенных фактов нужных
   `fact_kinds`; иначе — честная замена (F: процесс, договор, гарантии, лицо основателя с согласием, демо).
6. **Сверка текста** — `claims_check.py` text; **сверка плана** — `site_validate.py` J (каждый `fact:` существует,
   допущен, не просрочен `valid.until`).
7. **Обновление**: отзыв разрешения (`permission.withdrawn`) → факт снимается со всех страниц в 3 рабочих дня (152-ФЗ
   ст. 10.1 ч. 14 — срок прекращения по требованию) `[стандарт]`.

## 6. Когда заказчик просит тёмный приём

По ux 06/04 §8.4: назвать приём по типу; показать норму (здесь и `01`); предложить честную замену (§4); предложить
парную метрику «конверсия ↔ отмены»; строки, запрещённые законом (фальшивые отзывы, ИИ-люди в роли клиентов, чужие
логотипы, ложная старая цена, «до/после» в медицине), не меняются повторной просьбой — отказ с альтернативой в той же
реплике (так же ai-media 12/04 §1.2) `[мнение]` + `[стандарт]`.

## Частые ошибки

1. **Генератор пишет «10 000+ клиентов» и «4,9 ★»** без фактов — выдуманные доказательства (риск 4 PLAN).
2. **«Нам доверяют» с логотипами известных брендов** «для примера» — товарные знаки и недостоверность.
3. **ИИ-фото у отзывов и «нашей команды»** — запрет (решение 15, ai-media 12/04 №14).
4. **Отзывы переписаны «покрасивее»** — ГК 1266, ГОСТ п. 6.8; подпись «Анна К.» без согласия на имя.
5. **Скриншоты отзывов с Яндекс Карт с именами и аватарами** — ст. 10.1 ч. 2.
6. **Таймер «до конца акции» на каждом визите 23:59** — 38-ФЗ ст. 5 ч. 3 п. 3, ux 06/04 §3.6.
7. **«Осталось 2 места» без данных** в курсах и мероприятиях.
8. **Виджет «только что купил»** со случайными именами.
9. **«До/после» на лендинге стоматологии**.
10. **Удалены отрицательные отзывы из раздела** — манипуляция (ЕС — Omnibus, соображение 49).
11. **Регулярка UX режет настоящие «Нам доверяют»** — проверять связку с фактом, а не слова (поправка §1.3).
12. **Ошибки ИИ-агентов**: «пример отзыва для наполнения», «заглушка до получения реальных» на опубликованной странице,
    «стоковое фото подпишем “наш мастер”», «таймер повышает конверсию — добавим», «ИИ-аватар с согласия клиента на отзыв
    законен» (США — нет: 16 CFR 465.1(f)).

## Чек-лист

- [ ] Каждый слот `data` ссылается на `fact:<id>`; у факта источник, дата, проверка и разрешение?
- [ ] Рейтинг — с площадкой, шкалой, числом оценок, датой и ссылкой?
- [ ] Логотипы клиентов — файлы от клиентов с разрешением; подпись связи видимым текстом?
- [ ] Люди-доказательства — реальные, с согласием на изображение и распространение ПД; ИИ-людей в этих ролях нет?
- [ ] Люди-декор — по решению заказчика, без подписи-утверждения; для ЕС — метка ИИ?
- [ ] Медицина: нет «до/после», историй излечения и благодарностей на посадочной?
- [ ] Отзывы дословны, с датой; правка только автором; вознаграждение помечено; купленных нет?
- [ ] Раздел отзывов публикует и отрицательные; правила модерации опубликованы; витрина подписана «подборка»?
- [ ] Отзывы с площадок — виджетом, ссылкой или без имён?
- [ ] Таймеры — до реальной даты без сброса; остатки — живые; нет виджетов фальшивой активности?
- [ ] Отказ в окнах и формах — нейтральной подписью; нет автопоказа окон и чата при входе?
- [ ] Рассылка и платные опции — отдельные неотмеченные галочки; «бесплатно» с автосписанием — сумма и дата у кнопки?
- [ ] Старая цена — из истории цен (ЕС — минимум за 30 дней)?

## Открытые вопросы и противоречия

1. **Отзывы на лендинге под трафик — реклама?** text H: да (часть рекламы, ст. 5 ч. 3 п. 10); ФАС 821/23 прямо говорит
   только о специальных разделах. Для генератора одна планка — достоверность; маркировка не нужна `[спорно]`.
2. **ГОСТ Р ИСО 20488-2023 добровольный** — нормы «72 часа» и «не редактировать» — хорошая практика, не обязанность; в
   ЕС близкие требования обязательны (UCPD 7(6), 23b–c).
3. **Правила площадок** (Яндекс Карты, 2ГИС) о встраивании и цитировании отзывов — не читались.
4. **ИИ-люди-декор на сайте для РФ без метки** — законом не запрещено (243-ФЗ ст. 9 — право с 01.03.2027, ai-media 12/03
   §7); база рекомендует метку для реалистичных людей — позиция ai-media `[спорно]`.
5. **Количественные данные о вреде фальшивых отзывов для конверсии** в этой волне не искались — правило держится на
   законе и этике, не на A/B.
6. **Что проверить в живой фазе: консультация юриста** — отзывы с площадок на своём сайте (§3.4, `[не проверено]`):
   правила Яндекс Карт и 2ГИС о встраивании и цитировании и авторское право на текст отзыва.
