## Порядок работы агента-генератора

1. Бриф → одно действие страницы (`conversion.action`) и каналы (`conversion.channels`; РФ — форма и телефон) → `01` §1, §6.
2. Набор формы из `lead-forms.yaml` по задаче и температуре трафика; каждое поле — с `why` → `01` §3.
3. Места призыва и формы по сюжету; липкий призыв на длинной странице телефона → `01` §1.2, §2, §4.
4. Доводы — под сомнения у точек решения, только из допущенных фактов; нет фактов — честные замены → `02` §1.
5. Цена, полная стоимость, тарифы, гарантия, честный срок → `02` §2–§4.
6. Шаги после формы: «спасибо», подтверждение, срок ответа, письма, скрытые поля, офлайн-конверсии → `01` §9–§10, `03`.

## Выжимка папки

1. Одно целевое действие, много мест призыва; одна подпись действия на всю страницу и цепочку писем.
2. Поле формы живёт, только если ответ использует следующий шаг продаж; заявка на услугу — 2 поля, максимум 3 видимых.
3. Квиз — когда ответы меняют предложение (3–7 вопросов, честный прогресс, контакт последним); калькулятор — до 3
   параметров (жёсткий максимум 5), итог без телефона.
4. РФ 2026-09: каналы — форма и телефон; мессенджер — MAX, Telegram и WhatsApp только дополнительно и не единственным.
5. Согласие на ПД — отдельная пустая галочка с журналом; антиспам — honeypot, ловушка времени, лимиты; капчи нет.
6. Конверсия — подтверждённый сервером успех; «спасибо» — статус, срок, канал, один следующий шаг.
7. Окна захвата — по нажатию; автопоказ — немодально после вовлечения и только решением заказчика; exit-intent — нет.
8. Доказательство — у точки решения и только из фактов; цена — на странице и полной стоимостью; «популярный» — по данным.
9. Гарантия — пункт договора у цены и формы; срочность — только реальная дата или живой остаток, после срока блок исчезает.
10. Метка → заявка → сделка: скрытые поля, журнал согласия и статусы CRM в Метрике; успех воронки — качество заявок.
