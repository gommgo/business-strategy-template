## Выжимка для агента

1. **Многостраничник — когда задач несколько**: несколько услуг или сегментов, поиск по каждой услуге («услуга + город»), нужда в
   доверии (команда, лицензии, отзывы), постоянное присутствие. → §1 `[практика]` (B 01 §6)
2. **Карта — закрытый список**: у каждой страницы один шаблон и план; серии — коллекции CMS с полями; служебные — «спасибо»
   (`noindex`) после каждой формы, 404 с кодом 404, юридический набор в подвале каждой страницы. → §2.1 `[практика]` (G 01)
3. **Шапка и подвал — один раз на сайт** (`site-map.chrome`); план страницы только выбирает вариант; посадочные под рекламу внутри
   сайта — `landing-minimal` без меню, но с тем же подвалом. → §2.2 `[стандарт: WCAG 3.2.3, 3.2.6]` (G 02 §1.5)
4. **Архетип шапки — по структуре, первое совпадение**: нет разделов → `minimal-cta`; поиск нужен → `search-led`; ≥ 3 утилит или
   телефон — канал действия → `two-tier`; ≥ 2 пунктов по ≥ 10 страниц → `mega-menu`; 2–8 подстраниц → `bar-dropdowns`; иначе
   `bar-links`. → §2.2 `[практика]` + `[проверено]`
5. **Не «Главная · Услуги · О нас · Блог · Контакты» по привычке**: пункты — хабы разделов этого сайта; гамбургер на десктопе,
   подменю только по наведению, `role="menu"` — ошибки. → §2.2 `[практика]` (K DEF-25; G)
6. **Крошки — со второго уровня глубины** (главная → раздел → страница), одной строкой, трейл = BreadcrumbList. → §2.3
   `[исследование: NN/g]` (G 02 §2.1)
7. **Нет сирот**: у каждой индексируемой страницы ≥ 1 входящая ссылка из меню, подвала, хаба, связанных или дочерних страниц;
   исключения — только служебные (`orphans_allowed`). → §2.3 `[документация]` (G 02 §3; SM-19)
8. **Поиск по сайту — от сотен страниц или коллекции, которую ищут по названию**; страница результатов — новый сайт: путь
   `Disallow: /search?` одним правилом (по умолчанию); уже в индексе — сначала `noindex`, `Disallow` — после выпадения;
   не оба. → §2.3 `[практика]` `[V:cfIQ_ksB61U 08:15]` `[V:cfIQ_ksB61U 13:18]` (G 02 §2.4, G 01 §5.2; H)
9. **Главная — маршрутизатор, а не продажа**: что делает компания и для кого (таглайн прямо), пути по задачам, масштаб, кейсы,
   контакты; первый экран `offer-cta-header`. → §2.4 `[практика]` (C 01 §3.2; NN/g Homepage)
10. **Уровни**: главная и хабы — L1, внутренние (услуга, тарифы, контакты, формы, статьи, служебные) — L0; шаблон ≤ сайта;
    подъём — с `level_why`. → §2.5 `[практика]` (решение 20; SM-21)
11. **Цена или «от» — из одного поля коллекции** на странице услуги и в прайсе; одна правда для всех страниц. → §3 `[практика]`
    (G 01 §4.2; F 02 §1.6)
12. **Сайт услуг РФ: телефон в шапке на всех страницах и видим на телефоне без меню** (`two-tier`, `keep_visible: phone`). → §3
    `[данные: M, предв.]` (G 01 §2.2)
13. **Страницы «услуга × город» — только с локальными фактами** (работы, отзывы, цены, сроки в этом городе); клоны — дорвей. → §3
    `[документация]` (H 01; spam policies)
14. **Филиал — отдельная страница только при ≥ 2 адресах** со своими фактами (`location-page`); специалист — `specialist-page` с
    согласием на изображение. → §3, §6 `[практика]` + `[стандарт: 152-ФЗ ст. 10.1]` (G; I)
15. **SaaS-сайт: продукт → функции, решения → сценарии, тарифы, интеграции, безопасность, кейсы, сравнения**; вход в продукт —
    ссылка в шапке, продукт — отдельный пакет с общим DESIGN.md. → §7 `[практика]` (G 01 §2.7)
16. **Корпоративный: «О компании» в 4 уровнях** — таглайн, сводка, подстраницы, подвал; небольшой компании подстраницы не нужны.
    → §4 `[исследование: NN/g 2019]` (G 01 §2.1)
17. **Новости — только при выпуске не реже раза в квартал**; раздел с последней датой двухлетней давности вредит доверию. → §4
    `[практика]` (G 01 §2.1)
18. **Порядок сборки**: пакет 1 — главная с общими шапкой, подвалом и DESIGN.md; дальше — шаблоны по трафику (посадочные услуг,
    форма, контакты), служебные — в конце. → §2.6 `[практика]` (G `build_order`)
19. **Языки — одна структура адресов**, переключатель ведёт на ту же страницу другой версии (при паре), `hreflang` — H; второй язык —
    адаптация, а не перевод. → §2.3 `[практика]` + `[проверено]` (G 02 §5; решение 15)
20. **После запуска — диагностика индексации**: отрисованный HTML в «Проверке URL», ресурсы и API не закрыты в `robots.txt`, код
    404 у несуществующих адресов, `noindex` не плавает за CDN. → §2.7 `[документация]` `[V:0yedoWKPgo4 02:08]`

## 2. Общее для всех многостраничников

### 2.1. Карта и шаблоны

- Карта по умолчанию типа — G 01 §2 (ниже — по типам) минус `pages.exclude` брифа плюс страницы под задачи брифа; в карте:
  `derived_from` (откуда карта), `templates[]` (шаблон: тип, экземпляры `single | collection`, план, уровень, крошки, связанные,
  индексация, пакет), `pages[]` (страницы и образцы коллекций), `collections[]` (модель CMS), `chrome`, `linking`, `utility_pages`,
  `build_order`.
- Адреса (G 02 §4): строчные латиницей, слова через дефис, транслит по одной схеме, ≤ 3 сегментов у услуг и статей, без дат и id в
  пути; существующие адреса — сохранить или 301 (`search.existing_site.keep_urls`). `[практика]` + `[документация]`
- Модель контента (G 01 §4): поле цены, срока, адреса — одно на коллекцию и выводится во все шаблоны; факты — ссылками `fact:`.

### 2.2. Шапка, подвал, крошки

- Шапка — `chrome.header`: архетип по порядку выбора (выжимка 4), пункты — страницы карты, утилиты (телефон, город, язык, вход,
  поиск, призыв), телефон на телефоне — `keep_visible`, липкость частичная (появляется при прокрутке вверх), ≤ 64 px на телефоне.
  План страницы: `navigation.header: site`, `archetype` = карте (PL-N02). Поправка к NAV_RULE kimi — `../06-multipage-ia/02…` §1.2.
- Подвал — `chrome.footer` (`site`: ≤ 6 групп разделов, юридический набор, реквизиты фактом `company`, контакты; на телефоне —
  открытый список, аккордеон только групп при > 25 ссылках — blocks.yaml v1). Четыре колонки «Продукт · Компания · Ресурсы ·
  Правовое» по привычке — ИИ-отпечаток (Hallmark Ft3), если за ними нет настоящей карты.
- Крошки — `chrome.breadcrumbs.rule: depth-2-plus`; у шаблонов глубины ≥ 2 — `breadcrumbs: true`; на телефоне одна строка или
  «← Раздел».

### 2.3. Перелинковка, поиск, языки

- Хабы коллекций (`linking.hubs`: страница-список ↔ коллекция), правила связанных (`related_rules`: направление → проекты, проект →
  направление; блок `case-cards` или `related-links`), контекстные ссылки в тексте; минимум входящих — 1 (SM-19 считает граф).
- Поиск — по правилу G 02 §2.4; результаты — `search-results-page` (v1): новый сайт — `Disallow: /search?` одним правилом;
  уже в индексе — сначала `noindex`, `Disallow` — после выпадения; не оба (G 01 §5.2; `[V:cfIQ_ksB61U 13:18]`);
  `[документация]` `[V:cfIQ_ksB61U 08:15]`; «ничего не найдено» — как 404 с путями.
- Языки — `languages.structure` (префикс пути по умолчанию), переключатель на ту же страницу при паре, иначе на главную версии с
  пометкой; `hreflang` в `<head>` или sitemap — H. У живых сайтов на ту же страницу ведут 3 из 6 (G/01). `[проверено]`

### 2.4. Главная многостраничника

Порядок по умолчанию (C 01 §3.2; у живых — медиана 12 секций): `hero` (что делает компания и для кого) → `audience`/`services`
(пути по задачам ссылками на страницы) → `proof-stats`/`proof-logos` (масштаб, клиенты — факты) → `case-studies` (2–4 кейса со
ссылками) → `how-it-works` (для услуг) → `about`/`team` (коротко, ссылка на «О компании») → `testimonials`/`awards-press` →
`related` (новости, если ведутся) → `final-cta` + `contacts`. Форма — `directory` · `split-studio` · `marquee-hero`; первый экран —
`offer-cta-header`; длина 8–12. Одна главная услуга — главная работает как `service-page`.

### 2.6. Порядок сборки и пакеты

`build_order`: 1 — главная (строит `chrome` и DESIGN.md) → 2–4 — шаблоны с трафиком и формой (услуга или направление, форма
запроса, контакты) → хабы и коллекции → «О компании», документы, команда → новости, вакансии → юридические, 404, «спасибо».
Каждый шаг — пакет kimi на шаблон (`site_brief_to_kimi.py --plan plans/<шаблон>.yaml --sitemap site-map.yaml`), приёмка шаблона —
по образцам коллекции (1–3 экземпляра). `[практика]`

### 2.7. SEO, GEO и проверки уровня сайта

- `sitemap.xml` с абсолютными каноническими адресами без редиректов; `robots.txt` — `text/plain` 200 или 404, только `user-agent`,
  `allow`, `disallow`, `sitemap` (Google исполняет только их) `[документация]` `[V:DchuJS7JWvk 03:20]`; Clean-param для `yclid`,
  `gclid` (Яндекс); 404 — код 404, не редирект на главную (у 2 из 20 сайтов G/01 — мягкая 404).
- Разметка — `head-kit.yaml page_types` по шаблону; Organization (или LocalBusiness у услуг) — на главной или «О компании», не в двух
  местах с разными данными; BreadcrumbList = видимый трейл (у 4 сайтов G/01 крошки без разметки). `[документация]` + `[проверено]`
- Автопроверка собранного сайта: `ia_probe.py` (ссылки навигации в исходном HTML, 404, sitemap, крошки по глубине) + `geo_probe.py`

## 3. Услуги и локальный бизнес (`services-site`) — приоритет 1

**Карта** (G 01 §2.2): главная-маршрутизатор (услуги, цены, специалисты, адрес) → услуги — хаб (`services-index-page`; категории при
> ≈ 12 услуг) → услуга × N (`service-page`, коллекция; внутри категории — 3-й уровень) → цены (`pricing-page` из поля цены
коллекции) → специалисты (`team-page`) → специалист × N (`specialist-page`) → филиал × N (`location-page`, при ≥ 2 адресах) →
отзывы (`reviews-page`, при фактах) → о компании (лицензия — `documents-page` или раздел) → запись (`form-page`) → контакты;
посадочные под рекламу — `landing-lead-services` без меню; `noindex` или `canonical` на страницу услуги — не оба (H 01 §2.3).
**Шапка** `two-tier` (телефон `tel:`, город или адрес, мессенджер, запись); сеть с сотнями услуг и врачей — `search-led` с мега-меню
услуг. **Страница услуги** (C 01 §3.3; 10–14 секций у живых): `hero` (услуга, город, цена «от», призыв) → `offer` → `pricing` →
`how-it-works` → `case-studies` → `testimonials` → `team`/`awards-press` → `faq` → `lead-form` → `related` (смежные услуги);
юридические и медицинские — `team` и лицензии выше.
**Формы** — `consultation-request`, `booking` (при реальных слотах; запись к специалисту — по специалисту и филиалу), `callback`;
`contacts-page` — `contact-message` + телефон и почта обязательно.
**Доказательства** — `company`, `price` или `offer-terms` (обязательные брифа); `credential` (лицензия медицины, СРО строительства),
`person` (специалисты с согласием), `rating` (карты с датой), `case` (работы с датой и ценой).
**SEO и GEO** — LocalBusiness (подтип отрасли) на главной и контактах, Service на страницах услуг, адрес и часы как в Яндекс Бизнесе
и 2ГИС; «услуга × город» — только с локальными фактами; профили карт — `sameAs`. **Право** — LR-RU-01…07, 10, 12…14, 21
(медицина), 22; реквизиты в подвале каждой страницы (у лидогенов РФ реквизиты редки: 3 из 14, M предв.). **События** —
`booking-complete`, `phone-click`, `messenger-click`, `route-click`, `lead-submit`.
**Ошибки** — телефон только в подвале; прайс PDF-картинкой; «наши врачи» стоком; город в заголовке без адреса и фактов;
отдельная «страница отзывов» из трёх отзывов без источников.

## 4. Корпоративный сайт (`corporate-site`) — приоритет 4

**Карта** (G 01 §2.1): главная (`directory`) → направления — хаб → направление × N (`service-page`) → проекты — хаб
(`case-list-page`) → проект × N (`case-page`, с разрешения клиента) → о компании (`about-page`) → документы и допуски
(`documents-page`), руководство, история (по размеру компании) → новости (`blog-index-page` + `article-page`, при выпуске ≥ раза
в квартал) → вакансии (`careers-page`; вакансия — `JobPosting`) → контакты → запрос расчёта (`form-page`) → «спасибо», юридические,
404. Пример — `examples/corporate-b2b-stalkon/` (бриф, демо-факты J, карта G v1, планы 15 шаблонов).
**Шапка** `bar-dropdowns` (направления, о компании), `two-tier` при языках и телефоне; холдинг с ≥ 2 разделами по ≥ 10 страниц —
`mega-menu`. **Страница направления** — `hero` (что делаете, для кого, масштаб) → `services` (состав) → `case-studies` (проекты
направления — `related_rules`) → `how-it-works` (этапы, договор) → `credentials` (допуски) → `faq` → `final-cta` (запрос расчёта).
**Формы** — `b2b-request` (компания, задача, контакт; ≤ 4 видимых поля) или `quote-request`; B2B с длинной сделкой — «обсудить
задачу», форма короткая. **Доказательства** — `company` (реквизиты), `case` с разрешением, `client` (логотипы с письменным
разрешением), `credential` (номер, срок, реестр). **SEO** — Organization + WebSite на главной, AboutPage, Service, Article для
проектов и новостей; языковые версии — `hreflang` (H). **Право** — LR-RU-01…07, 10, 12, 13; B2B-сделка — LR-RU-14 не применяется,
если нет продажи потребителям; ЕС — LR-EU-06 (основание «шаги до договора»). **События** — `quote-submit`, `lead-submit`,
`job-apply-submit`, `phone-click`.
**Ошибки** — «О компании» из миссии и стоковой команды; новости двухлетней давности; «Нам доверяют» без разрешений; мегаменю из
пяти пунктов; документы без номеров и сроков.

## 5. Портфолио и студия (`portfolio-site`)

**Карта** (G 01 §2.3): главная = работы (`portfolio-page`, `portfolio-grid`) или главная с работами первыми → работы — хаб с
фильтром по отрасли и услуге (при > ≈ 12 работ) → проект × N (`case-page`) → услуги → о студии (команда внутри) → контакты и бриф на
проект (`form-page`). Два уровня — крошки обычно не нужны. **Шапка** `bar-links`. **Уровень** — L2 допустим только на сайте L2
(`portfolio-page`), проект — L1, контакты и форма — L0; первый экран — `poster` или `offer-cta-header`.
**Формы** — `b2b-request` или `contact-message` (бриф: задача, сроки, бюджет — поля с назначением). **Доказательства** — только
настоящие работы с разрешением клиента, даты, роль студии; награды — год и организатор (`[награда]`). **SEO** — CollectionPage,
Article для проектов; подписи работ — текстом, работы в WebGL — дубль текстом в HTML. **Право** — LR-RU-01…05, 12, 13.
**События** — `lead-submit`, `cta-click`, `section-view` проектов.
**Ошибки** — работы-концепты без пометки; тяжёлые видео каждого проекта в сетке; бриф-форма из 12 полей.

## 6. Личный бренд (`personal-brand-site`)

**Карта** (G 01 §2.6): главная (кто, чем помогает, главное действие) → о себе → услуги или продукты (1–5 — одной страницей, больше —
хаб) → публикации (блог или список внешних ссылок с датой) → выступления (даты, записи) → контакты → юридический набор при сборе
данных. 1–2 уровня. **Шапка** `bar-links`; автор с регулярными публикациями — `editorial-masthead` с «Главной» в меню.
**Формы** — `consultation-request`, `newsletter-subscribe` (отдельная галочка рассылки), `lead-magnet`. **Доказательства** — `person`
(обязательный вид вместо `company` — A allOf), отзывы с согласием, публикации со ссылками и датами. **SEO** — ProfilePage + Person,
`sameAs` на профили. **Право** — LR-RU-01…05, 11, 12, 13 (владелец сайта — сам автор или ИП). **События** — `lead-submit`,
`newsletter-subscribe`, `lead-magnet-download`.
**Ошибки** — «эксперт №1» без основания (text, 38-ФЗ ст. 5); фото из фотостока; блог без дат.

## 7. Маркетинговый сайт SaaS (`saas-marketing-site`) — приоритет 2

**Карта** (G 01 §2.7): главная → продукт — хаб → функция × N (`feature-page`) → решения — хаб → сценарий × N (`use-case-page`:
отрасль, роль, размер) → тарифы (`pricing-page`) → интеграции (`integrations-page` proposed → интеграция × N при каталоге) →
безопасность (`security-page` proposed: где данные, 152-ФЗ, сертификаты) → кейсы (хаб → кейс) → ресурсы (блог, вебинары;
документация — часто отдельный хост) → сравнения и «альтернативы» (серия) → компания (о нас, вакансии) → запрос демо
(`form-page`); вход в продукт — `log-in` в шапке.
**Шапка** — 4–6 ссылок у малых (`bar-links`), мега-меню «Продукт / Решения / Ресурсы» у больших (linear: 8 пунктов, kontur: 7 с
подменю — G/01). **Страницы функции и сценария** (C 01 §3.3): `hero` → `product-demo` → `benefits` → `how-it-works` → `integrations`
→ `testimonials` → `final-cta` + `related`. **Тарифы** (C): `hero` короткий → `pricing` → `comparison` (таблица функций, ≤ 5
вариантов, на телефоне 2 колонки или вкладки — NN/g 2024) → `faq` (оплата, отмена) → `testimonials` → `final-cta`.
**Формы** — `trial-start`, `b2b-request` (демо). **Доказательства** — `demo` (настоящий продукт — обязателен), `client`, `case`, `metric`
с периодом, сертификаты безопасности (`credential`). **SEO и GEO** — SoftwareApplication на тарифах и главной (без оценок без
площадки), Article для сравнений; ответы о данных и безопасности открытым текстом; сравнения — только проверяемые факты о
конкурентах (38-ФЗ ст. 5, I). **Право** — LR-RU-01…07, 10, 13, 16, 22, 24; ЕС — LR-EU-01…10. **События** — `trial-start`,
`sign-up-complete`, `demo-request-submit`, `pricing-view`, `login-click`.
**Ошибки** — 30 страниц функций из одного абзаца; «альтернативы» с выдуманными минусами конкурента; разные цены на главной и в
тарифах; документация и блог без связи с продуктовыми страницами.

## 8. Школа и курсы (`school-site`)

**Карта** (G 01 §2.5): главная → каталог программ (`program-catalog-page`, фильтры направления, уровня, длительности — `noindex`) →
направление (хаб, при ≥ 3 направлениях) → программа × N (`landing-course` внутри сайта с локальным оглавлением) → преподаватели (хаб)
→ преподаватель × N (`specialist-page`) → цены и оплата (рассрочка, вычет — факты) → отзывы → «Компаниям» (только при уникальном
содержимом) → бесплатные уроки (лид-магнит) → блог → о школе (лицензия) → оферта.
**Шапка** `bar-dropdowns`; каталог с поиском — `search-led` с мега-меню «Программы». **Программа** — порядок `02-playbooks-landings.md` §7.
**Формы** — `consultation-request`, `booking` (пробный урок), `event-registration` (день открытых дверей), `lead-magnet`.
**Доказательства** — `price`, `person` (обязательные брифа), лицензия (`credential`), выпускники с согласием. **SEO** — Course на
программах (Course info Google снят; фид курсов Яндекса), ProfilePage преподавателей. **Право** — LR-RU-01…07, 10…14, 22; дети —
согласие родителя, фото детей не публиковать без согласия (I: пробел базы). **События** — `lead-submit`, `booking-complete`,
`event-register`, `lead-magnet-download`.
**Ошибки** — обещание трудоустройства и дохода; программы-клоны с разными названиями; преподаватели без согласия.

## 9. Мероприятие (`event-site`)

**Карта** (G 01 §2.4): главная события (дата, место, билеты в первом экране) → программа (`event-program-page` proposed: день ×
секция) → спикеры — хаб (`speakers-page` proposed) → спикер × N (`specialist-page`) → доклад × N (при > ≈ 30 докладах) → место и как
добраться → билеты и цены → партнёры → прошлые события (архив с годом в пути `/2025/`) → оферта при продаже. Серия конференций — у
каждой свой подсайт с локальной навигацией и общий раздел бренда (smashingconf: 125 шаблонов пути на 1 347 URL — G/01).
**Шапка** `bar-links` (программа, спикеры, место, билеты) + призыв «Купить билет». **Формы** — `event-registration`; билеты —
внешняя платформа или оплата на сайте (LR-RU-14, 15). **Доказательства** — `date`, `offer-terms` (обязательные), спикеры `person`,
прошлые события с числами. **SEO** — Event на странице события; после даты — архив, не 404. **Срок** — секции регистрации получают
`expires` по дате: после — `swap-state` (записи, материалы). **События** — `event-register`, `purchase`, `video-play`.
**Ошибки** — программа картинкой; время без часового пояса; архив прошлых лет удалён — ссылки и поиск теряются.
