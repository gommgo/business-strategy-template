# Как не зафиксироваться на версии Claude Design и обновляться вслед за ним

Главная сессия, 26.09.2026, Claude Code (десктоп), Opus 5.5. Повод — требование заказчика 26.09: «Claude Design будет обновляться; важно
не зафиксироваться железобетонно — если он обновится, мы тоже сможем обновиться». Основано на ответах инструмента `Artifact` 26.09
(релизы и контракт в каждом ответе), наблюдениях при публикации демо (`01` §6) и журнале изменений этой базы (25.09 → 26.09).

## Выжимка для агента

1. Знай: меняются сразу несколько слоёв — продукт Claude Design, режимы `/design`, каталог типов в `Artifact`, релизы типов Design и
   Design System, контракт артефакта, флаги возможностей, правила формата в SKILL.md и справке. `[проверено: версии в ответах]` → §1
2. Делай: не копируй правила типа в свои скиллы — бери их из ответа инструмента при каждом создании и чтении; в своём скилле держи только
   наше: когда использовать, где лежат исходники, как синхронизировать, как проверять. `[мнение базы]` → §2
3. Делай: источник правды — наши файлы в репозитории; форматы простые (JSON + HTML) → переход на новый формат делается скриптом.
   `[проверено: демо]` → §2
4. Делай: храни снимок версий (`snapshots/<дата>-types.json`) и сверяй его раз в неделю, после обновления Claude Code и при любой
   странности в ответах инструмента. → §3
5. Делай: контракт артефакта поднимай осознанно — сначала на демо «Спица» (`contract: "latest"`), потом в проектах по одному. → §4
6. Не делай: не опирайся на внутренности страницы (`app.js`, `dc-runtime.js`, недокументированные поля) — только на то, что описано в
   справке типа. `[мнение базы]` → §2
7. Делай: при слиянии сохраняй неизвестные ключи — редакторы добавляют свои (`attachments`, `frameless`, фигуры пользователя).
   `[проверено]` → §2
8. Делай: держи запасной путь — `kit` (локальный HTML-холст) и выгрузку в обычные HTML, CSS и токены, чтобы поломка или уход типа не
   остановили работу. → §5
9. Делай: найдено изменение → прочитать изменившуюся справку → смоук на демо «Спица» → обновить `01`, снимок и журнал (§6) → поправить
   наш скилл-адаптер. → §3
10. Знай: сигналы изменений — ответ quickstart, релиз и размеры файлов типа, «newest» контракт в ответе публикации, отказ публикации с
    новой причиной, описание `/design` в меню `/`, release notes Claude Code, help center Claude Design. → §1

## 2. Принцип: тонкий слой над типом

Три слоя, и меняется при обновлении только средний:

1. **Тип Anthropic** — редактор, формат, правила (меняется без нас).
2. **Наш адаптер** — раздел скилла: когда звать тип, как создать и опубликовать, как синхронизировать с репозиторием, как проверять;
   правила формата — ссылкой на ответ инструмента, а не копией.
3. **Наше содержимое** — исходники ДС и холста в репозитории, брифы, решения.

Правила адаптера:

- Правила типа — только из ответа инструмента; в скилле — «прочитай справку типа», а не её пересказ.
- Опираться только на описанные в справке файлы и поля; внутренности страницы — нет.
- При слиянии — сохранять чужие ключи и маркер `createdOnFiles`; писать только свои ключи.
- Всё своё — в наших файлах (git): при смене формата пишется скрипт перевода, а не делается ручная переделка.

## 3. Проверка дрейфа: процедура

Когда: раз в неделю, после обновления Claude Code, при новом отказе публикации или непонятном ответе инструмента.

1. `Artifact action=quickstart intent=design` — есть ли тип Design, адрес тот же, какие ДС в аккаунте.
2. `Artifact action=read type_url=<Design>` и `…=<Design System>` — релизы, список файлов типа.
3. `Artifact action=list url=<демо-холст> scope=files` и `…=<демо-ДС>` — размеры файлов типа; для изменившихся — `read` и sha256.
4. Сравнить со снимком `snapshots/<последний>.json`: релиз, контракт, флаги, размеры и sha256 файлов типа.
5. Совпало — записать дату проверки в §6. Не совпало:
   - прочитать изменившуюся справку (SKILL.md, `format.md`, `design-system-components.md`, `cover.md`) и выписать отличия;
   - смоук на демо «Спица»: маленькая правка холста и ДС по новым правилам → публикация → заказчик смотрит (правило типа о самопроверке);
   - обновить `01-design-system-and-canvas-in-session.md`, новый снимок `snapshots/<дата>-types.json`, строку журнала §6;
   - поправить адаптер в скилле и, если нужно, скрипт перевода исходников проектов.

## 4. Контракт артефакта: закрепление и подъём

- У инструмента `Artifact` параметр `contract`: без него версия артефакта сохраняется, `"latest"` поднимает до новейшей, точная версия
  закрепляет или откатывает. Наши артефакты — 0.2.47, новейший на 26.09 — 0.2.60. `[документация инструмента]` `[проверено]`
- Подъём: демо «Спица» → проверка заказчиком → проекты по одному, с записью в `ARTIFACTS.md` проекта. Без причины не поднимать.

## 5. Запасной путь и выход

- `kit` (`../../../scripts/claude-design/kit/`) — локальный холст на HTML + `tokens.css` с кадрами, метками и `diffshots`: работает без типов.
- Содержимое переводимо: токены ДС → CSS-переменные (ДС отдаёт скомпилированный `tokens.css`); статичные артборды `.dc.html` → HTML
  (инлайн-стили сохраняются; убрать `<x-dc>`, `<helmet>`, блок логики, подставить значения твиков).
- Экспорт со страницы — меню Share › Export. Если тип исчезнет, исходники и экспорт остаются у нас.
