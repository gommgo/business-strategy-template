# План ресёрча: Claude Design под управлением Claude Code

Дата старта: 25 сентября 2026, 15:00 MSK. Оркестратор: Opus 5.5 (основной сеанс Claude Code 2.1.281). Исполнители: 4 Opus-агента
без помощников, одна волна, синтез делает оркестратор. Масштаб по решению заказчика **небольшой** («три агента, четыре агента»), без
аудита и отдельных волн. Соседние базы: `../kimi-research/` (Kimi K3 как исполнитель дизайна: образец конвейера и контраст),
`../ui/`, `../ux/`, `../site/`, `../text/`, `../creative/` (что должно получиться),
`../ai-media/`, `../blender/` (ассеты и 3D).

## Зачем

Заказчик строит систему генеративного дизайна: Claude ведёт исполнителя дизайна по брифу, смотрит результат, требует правки и
принимает работу. База `../kimi-research/` (завершена 24.09.2026) расписала такой конвейер для Kimi K3, но итог неоднозначный: на
23.09 K3 — № 8 Code Arena WebDev (№ 1 была только 16–30.07), управляемость в правках — 1,99 % против 6,8 % у Opus 5, условия
подписки для запусков из скрипта — `[спорно]`, всё поведение K3 — `[не проверено]`. Гипотеза заказчика: **Claude Design на Opus 5.5
даст дизайн лучше K3 и будет управляемее**. Эта база отвечает, как с Claude Design работать из Claude Code.

Вопросы базы:
1. **Что такое Claude Design на 25.09.2026**: статус, тарифы и лимиты, модель (на старте 17.04 — Opus 4.7; ролик 24.09 — «Opus 5.5
   Just 10X'd Claude Design»), что блогеры называют «2.0» и «3.0», возможности (типы проектов, холст, варианты, комментарии,
   «ручки», импорт, web capture, дизайн-системы, экспорт, шаринг, handoff), официальные советы по промтам, ограничения, данные.
2. **Как Claude Code «вызывает» Claude Design**: что есть на самом деле — инструмент `DesignSync` и команды `/design-sync`,
   `/design-login` в Claude Code 2.1.281, handoff bundle из Claude Design в Claude Code, есть ли API или MCP, автоматизация браузером
   (риски); какая схема даёт полноценную работу, а какая — полумеру.
3. **Конвейер**: бриф → вайрфрейм → макет → прототип → код. Кто делает каждый шаг (Claude Code, Claude Design, заказчик), что
   передаётся между шагами, где подключаются наши базы.
4. **Промтинг Claude Design**: что работает у практиков и в роликах заказчика — дословные промты, приёмы, сбои.
5. **Тесты**: что проверить до перехода (Claude Design против Kimi K3 и против Claude Code + `frontend-design` на одном брифе,
   управляемость правок, лимиты, handoff) и как принимать результат.
6. **Сравнение с Kimi — коротко**: что лучше, что хуже, что переносится из `../kimi-research/` (бриф, пакет, цикл арт-директора,
   проверки).

Читатель — Claude-оркестратор и заказчик.

## Главный риск темы

1. **Продукт меняется каждый месяц.** Claude Design — research preview Anthropic Labs с 17.04.2026; в роликах «2.0» (13.08) и «3.0»
   (05.08) — возможно, названия блогеров, а не версии Anthropic. У каждого факта — дата и источник: `(Claude Design, 2026-09-xx)`.
2. **Хайп-ролики.** «Build $50,000 Websites», «10X'd», «95 % за 18 минут» — ценны процесс, промты и сбои, а не выводы о качестве.
3. **Связь с Claude Code может быть односторонней.** Судя по описанию, `DesignSync` работает только с проектами дизайн-систем.
   «Вызвать Claude Design из Claude Code» как исполнителя, возможно, нельзя. Тогда база прямо говорит, что есть вместо этого.
4. **Claude Design не запускаем** (решение оркестратора по умолчанию, см. «Решения заказчика»): это аккаунт и лимиты заказчика.
   Поведение, которое подтверждается только запуском, — `[не проверено]` и строка в «Что проверить в тестах».
