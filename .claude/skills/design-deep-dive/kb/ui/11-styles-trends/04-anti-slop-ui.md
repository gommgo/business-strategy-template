## Выжимка для агента

1. **Слоп — не уродство, а отсутствие автора.** «Slop is design with no author… the statistical average of
   ten thousand interfaces, rendered cleanly and shipped without anyone stopping to ask whether it should
   look and feel like this» [S16]. → §1.1 `[мнение]`
2. **Диагноз ставится по кластеру, а не по одному признаку.** Inter сам по себе нормален; Inter + индиго
   градиент + три карточки + одинаковый радиус — диагноз. Порог: **4 и больше маркеров одновременно**.
   → §1.3 `[консенсус]`
3. **Механизм задокументирован:** `bg-indigo-500` как дефолт Tailwind UI → тысячи туториалов → корпус
   обучения → «modern web design = purple buttons». Извинение автора Tailwind, август 2025, >1 млн
   просмотров. → §1.2 `[консенсус]`
4. **Петля самоусиления реальна:** заметный сгенерированный сайт попадает в следующий срез обучающих
   данных. «A pattern that looked original in early 2025 was a cliche by mid-2026.» → §1.4 `[мнение]`
5. **Качество исполнения и различимость — разные оси.** Модели становятся чище, но не разнообразнее:
   «polished slop is harder to recognize as slop». → §1.4 `[мнение]`
6. **Самая дешёвая правка — шрифт.** «Change the font before you change anything else. It's an hour of
   work and it's the single highest-leverage move against slop.» → §6.1 `[мнение]`
7. **Вторая по отдаче — сложные раскладки и карточки:** «модели плохо собирают сложные раскладки, поэтому
   здесь наибольший эффект за наименьшее время» `[V09 B]`. → §6.1
8. **34 маркера в §2 сгруппированы по девяти темам, у каждого — проверка числом или условием.** Двадцать
   из них проверяются автоматически по computed styles. → §2, §3
9. **Белый текст на `#6366f1` даёт 4.47:1** — дефолтная «фиолетовая кнопка» формально не проходит 4.5.
   Посчитано. → §2.1 маркер 2 `[исследование]`
10. **Тень ровно `rgba(0,0,0,0.1)` на всём** — это `shadow-md` Tailwind без изменений. Практика: медиана
    2.5 разных тени, у 4 продуктов из 24 теней нет вовсе. → §2.4 маркер 13
11. **Один радиус на всех контейнерах** против медианы практики **3.5 разных радиуса на экране**. → §2.4
12. **«Шаблонный хром» — шесть отдельных маркеров:** капс-eyebrow, точки-разделители `A · B · C`, лейблы
    `WORD — fragment`, тонированный почти-чёрный вместо чёрного, моно для мелких подписей, `→` в конце
    кнопок. Все шесть из одного списка [S29]. → §2.9
13. **Нумерация 01/02/03 допустима только если контент действительно последовательность.** → §2.9 маркер 31
14. **Отсутствующие состояния — самый дорогой маркер и самый незаметный на скриншоте.** «AI nails the happy
    path every time… the demo always has data» [S16]. → §2.7
15. **Движение: fade-and-slide-up на каждой секции и hover-переход на каждой карточке — прямо названы
    «generic default, reads as AI-generated»** самой инструкцией для моделей. → §2.8 `[мнение]`
16. **Эпоха имеет значение:** 2023–2024 — фиолетовый градиент; 2025–2026 — кремовый `#F4F1EA` с терракотой
    `#D97757` и серифом, «broadsheet» с волосяными линейками. Список маркеров надо датировать. → §5
17. **Запреты в промте работают, но не исключают паттерн.** «Transformer models can perform negation during
    inference», и тут же: модель «still tends to converge on common choices (Space Grotesk, for example)».
    Поэтому нужна ещё и проверка результата. → §4.3 `[мнение]`
18. **У инструкции Anthropic есть пункт, вредный для веб-сервисов:** «Backgrounds: create atmosphere and
    depth… layer gradients or use geometric patterns. Avoid solid colors» — верно для лендинга, неверно для
    таблицы и формы. → §4.4 `[спорно]`
19. **Порядок правок фиксирован:** раскладка и иерархия → цвет и токены → типографика → форма и глубина →
    иконки → состояния → движение → контент. Начинать с движения бессмысленно. → §6.2
20. **Разрыв не в правилах, а в отсутствии цикла:** генерация одноразовая, поэтому те же дефекты
    возвращаются в следующей сессии. Рабочая схема — «собрать с ограничениями → оценить по явной планке →
    починить весомое → переоценить». → §1.5 `[мнение]`
21. **Отсутствие фокус-состояний и непройденный контраст — системное свойство, а не случайность:**
    вторичные данные говорят о 1.7× дефектов и 2.74× уязвимостей в сгенерированном коде и о систематически
    недоступной разметке. Первоисточники не проверены. → §1.5 `[мнение]`
22. **Финальная проверка — три вопроса:** «Does this feel like it came from somewhere? Does it have a
    voice? Would I notice if it disappeared?» [S16]. → §6.4

## 1. Что это и откуда

### 1.1. Определение

**Слоп в интерфейсе** — визуальный результат, в котором ни одно решение не было принято: каждое поле
заполнено наиболее вероятным значением из обучающих данных. Диагностический признак не «плохо», а
«безлично»: интерфейс компетентен и неотличим.

Слово вошло в общий язык: **«AI slop» — слово года 2025 по версии Macquarie Dictionary** [S16].

### 1.2. Механизм

Документированная цепочка [S17][S18]:

```
один дефолт в популярной библиотеке (Tailwind UI: bg-indigo-500, ~2020)
   → тысячи копий в туториалах и на GitHub (2020–2024)
   → доминирование паттерна в обучающем корпусе
   → «modern web design = purple buttons» как статистическая норма
   → генерация фиолетового при отсутствии инструкций
```

Август 2025: Adam Wathan публикует извинение за то, что «сделал все кнопки в Tailwind UI `bg-indigo-500`
пять лет назад, из-за чего каждый сгенерированный ИИ интерфейс на Земле стал фиолетовым»; пост набирает
**более 1 млн просмотров** [S17].

Общая формулировка оттуда же: «When you ask… to "build a landing page" without specific constraints, you're
not getting design. You're getting the median of every Tailwind CSS tutorial scraped from GitHub between
2019 and 2024. And that median is purple.»

Вторая причина, не связанная со статистикой: **накопление без системы**. «When you don't provide
constraints on the first component, AI invents spacing values and color choices. On the second component,
it invents different values. By component five, your UI is a patchwork of inconsistent decisions»
(цит. по `01-color/06-…` §4.1).

### 1.3. Как ставить диагноз

Ни один маркер по отдельности не является дефектом. Правило:

| Сколько маркеров из §2 одновременно | Вывод |
|---|---|
| 0–1 | нормально |
| 2–3 | проверить, было ли это решением; вероятно, часть достанется по умолчанию |
| **4 и больше** | интерфейс не спроектирован, а усреднён; правки по §6 |
| кластер из §2.9 (три и больше «хрома») | шаблон поверх любого содержания |

### 1.4. Почему становится хуже, а не лучше

Петля обратной связи: заметный сгенерированный сайт попадает в следующий срез обучающих данных и делает
паттерн «ещё нормальнее». Следствие, сформулированное в источнике: «A pattern that looked original in early
2025 was a cliche by mid-2026… Every cycle, the median gets more confident and more homogeneous… The output
is more polished slop, which is arguably worse, because polished slop is harder to recognize as slop» [S18].

Разведение осей оттуда же: **качество исполнения и различимость — разные оси**; улучшение первой ничего не
даёт второй, потому что «taste is not on the roadmap for a system whose entire job is to predict the most
likely next token».

Теоретическая подпорка: **model collapse** — при обучении на собственной генерации модели теряют хвосты
распределения и сходятся к среднему; «distinctive design lives in those tails» [S16].

### 1.5. Измеримая цена: что известно о качестве сгенерированного кода

Два числа, которые попались в обзоре практиков [S32] и которые важны для визуального слоя, потому что
касаются доступности и состояний. **Оба приведены по вторичному источнику: первоисточники я не открывал**,
поэтому уровень `[мнение]`, и это прямой вопрос агенту H (папка `12-ai-generated-ui/`):

- анализ **470 реальных pull request** (CodeRabbit, декабрь 2025): в сгенерированном коде **в 1.7 раза
  больше дефектов** и **в 2.74 раза больше уязвимостей**, чем в человеческом;
- работа, представленная на **CHI 2025** (arXiv 2502.10884): ИИ-ассистенты **систематически порождают
  недоступную разметку**.

Что из этого следует для визуального слоя: отсутствие фокус-состояний, непройденный контраст и
неотрисованные пустые и ошибочные состояния — не случайность конкретной генерации, а системное свойство.
Поэтому маркеры 25–27 (§2.7) и проверки контраста нельзя считать необязательными.

Практический вывод оттуда же, который стоит вынести отдельно: **разрыв не в правилах, а в отсутствии
цикла**. «AI design is one-shot: the agent generates, you eyeball it, you fix the same problems by hand,
and next session it makes them again.» Рабочая схема — замкнутый цикл: собрать с ограничениями → оценить по
явной планке → починить самое весомое → переоценить, и так до прохождения планки. Это согласуется с
формулировкой из [S16]: узкое место — пауза для суждения, а не генерация.

| 28 | **Fade-and-slide-up на каждой секции** | одинаковое появление у всех блоков при прокрутке | **[авто]** число элементов с одинаковой парой `transition`/`animation` > 10 | один оркестрованный момент (загрузка страницы), дальше — только отклик на действие |
| 29 | **Hover-переход на каждой карточке** | `transition: all .3s` повсюду, подъём и тень при наведении | **[авто]** греп `transition: all`; доля элементов с hover-трансформацией > 30 % | hover только у интерактивных; `transition` на конкретные свойства |

### 2.9. Шаблонный хром (маркеры 30–34)

Шесть приёмов из одного списка [S29]; они появляются независимо от предмета продукта, поэтому вынесены
отдельно. Три и больше одновременно — достаточное основание для диагноза.

| # | Маркер | Как выглядит | Проверка | Чем заменить |
|---|---|---|---|---|
| 30 | **Eyebrow-лейбл капсом над каждым заголовком** | `ОБЗОР` мелким разреженным капсом над `h2` | **[авто]** доля заголовков, которым предшествует uppercase-узел < 14 px, > 30 % | убрать; если нужна категория — бейдж со смыслом |
| 31 | **Нумерация 01 / 02 / 03 без последовательности** | крупные номера у трёх независимых блоков | контент действительно последовательность (шаги, таймлайн)? если нет — убрать | маркеры списка или ничего |
| 32 | **Мета-строки через средние точки `A · B · C` и лейблы `WORD — fragment`** | «Дизайн · 12 мин · 2026», «ОТЧЁТ — за квартал» со шпационированным тире | **[авто]** греп `·` и ` — ` в служебных строках; доля > 5 узлов | обычные подписи с ролями; разделять пространством |
| 33 | **Тонированный почти-чёрный вместо чёрного и моно для мелких подписей** | `#0B0B0B`, `#111` как «фирменный чёрный»; `font-mono` у подписей без данных | **[авто]** греп `#0b0b0b`, `#111111` и `font-family: *mono*` на узлах < 14 px без чисел | нейтраль из шкалы; моно только для данных, кода, ID |
| 34 | **Стрелка `→` в конце текста кнопок и ссылок** | «Начать →», «Подробнее →» | **[авто]** греп `→` внутри `button`, `a` | иконка-шеврон как отдельный элемент либо ничего |

## 3. Скрипт проверок

Запускается в консоли на готовой странице. Возвращает объект с флагами; каждый флаг соответствует номеру
маркера. Своих порогов и шкал у скрипта нет: их передаёт параметр `P`, который печатает утилита
`scripts/ui/ui_audit.py` с ключом `--slop-params` (токены ДС проекта — ключом `--tokens`): порог кеглей из
`scripts/ui/data/thresholds.yaml`, шкала `space.*` и цвета из токенов ДС проекта (без ДС — эталон
`../14-recipes/examples/tokens.css`), доля шкалы и цель нажатия из пресета утилиты.

```js
// const P = { … };  — вывод ui_audit.py --slop-params: fontSizesTellAbove, spaceScale, spaceInScaleMin, targetMin, colors
((p) => {
  const all = [...document.querySelectorAll('body *')];
  const cs = el => getComputedStyle(el);
  const vis = all.filter(el => {
    const r = el.getBoundingClientRect();
    return r.width > 0 && r.height > 0 && cs(el).visibility !== 'hidden';
  });
  const uniq = arr => [...new Set(arr)];
  const css = document.documentElement.outerHTML;

  // 9: число уникальных кеглей
  const sizes = uniq(vis.filter(el => el.childElementCount === 0 && el.textContent.trim())
                        .map(el => cs(el).fontSize));
  // 14: число уникальных радиусов у контейнеров
  const radii = uniq(vis.filter(el => el.childElementCount > 0)
                        .map(el => cs(el).borderRadius).filter(v => v !== '0px'));
  // 13: доминирующая тень
  const shadows = vis.map(el => cs(el).boxShadow).filter(v => v && v !== 'none');
  const shadowTop = Object.entries(shadows.reduce((a, s) => (a[s] = (a[s]||0)+1, a), {}))
                          .sort((a,b) => b[1]-a[1])[0] || ['', 0];
  // 10, 11: отступы; 11 — доля значений в шкале space.* ДС
  const pads = vis.flatMap(el => {
    const s = cs(el);
    return [s.paddingTop, s.paddingRight, s.paddingBottom, s.paddingLeft, s.gap, s.rowGap, s.columnGap];
  }).map(parseFloat).filter(v => v > 0 && isFinite(v));
  const inScale = pads.filter(v => p.spaceScale.some(s => Math.abs(v - s) < 0.5)).length / (pads.length || 1);
  // 12: цели
  const inter = vis.filter(el => el.matches('a,button,input,select,textarea,[role="button"],[tabindex]:not([tabindex="-1"])'));
  const small = inter.filter(el => {
    const r = el.getBoundingClientRect();
    return Math.min(r.width, r.height) < p.targetMin;
  });
  // 33: цвет текста и фона литералом вне токенов ДС («фирменный чёрный» и любой другой)
  const hex = c => {
    const m = (c || '').match(/rgba?\(([^)]+)\)/);
    if (!m) return null;
    const v = m[1].split(/[,\s/]+/).filter(Boolean).map(Number);
    if (v.length > 3 && v[3] === 0) return null;
    return '#' + v.slice(0, 3).map(x => Math.round(x).toString(16).padStart(2, '0')).join('');
  };
  const literals = uniq(vis.flatMap(el => [hex(cs(el).color), hex(cs(el).backgroundColor)]))
    .filter(c => c && !p.colors.includes(c));
  // 8: капс
  const textNodes = vis.filter(el => el.childElementCount === 0 && el.textContent.trim());
  const caps = textNodes.filter(el => cs(el).textTransform === 'uppercase');
  // 15: стекло
  const glass = vis.filter(el => (cs(el).backdropFilter || 'none') !== 'none');
  // 16: смешение глубины
  const mixed = vis.filter(el => {
    const s = cs(el);
    return s.boxShadow !== 'none' && parseFloat(s.borderTopWidth) > 0 &&
           s.backgroundColor !== 'rgba(0, 0, 0, 0)';
  });
  // 23: толщины штриха иконок
  const strokes = uniq([...document.querySelectorAll('svg')]
    .map(s => s.getAttribute('stroke-width') || cs(s).strokeWidth).filter(Boolean));
  // 29: transition: all
  const transAll = vis.filter(el => {
    const s = cs(el);
    return s.transitionProperty.split(',')[0].trim() === 'all' &&
           s.transitionDuration.split(',').some(d => parseFloat(d) > 0);
  });

  return {
    m5_lowContrastGray: css.includes('#9ca3af') || css.includes('text-gray-400'),
    m1_purpleAccent: /#6366f1|#8b5cf6|indigo-5|purple-5|from-purple|to-indigo/i.test(css),
    m3_gradients: (css.match(/linear-gradient/g) || []).length,
    m8_capsRatio: +(caps.length / (textNodes.length || 1)).toFixed(3),
    m9_fontSizes: sizes.length,
    m9_tell: sizes.length > p.fontSizesTellAbove,
    m10_spacingValues: uniq(pads).length,
    m11_inScale: +inScale.toFixed(3),
    m11_tell: inScale < p.spaceInScaleMin,
    m12_smallTargets: +(small.length / (inter.length || 1)).toFixed(3),
    m13_dominantShadow: shadowTop[0],
    m13_dominantShadowShare: +(shadowTop[1] / (shadows.length || 1)).toFixed(3),
    m14_radii: radii.length,
    m15_glassElements: glass.length,
    m16_mixedDepth: mixed.length,
    m21_emoji: /[\u{1F300}-\u{1FAFF}\u{2700}-\u{27BF}]/u.test(document.body.innerText),
    m23_iconStrokes: strokes,
    m24_placeholders: /lorem|ipsum|John Doe|example@example/i.test(document.body.innerText),
    m29_transitionAll: transAll.length,
    m32_middots: (document.body.innerText.match(/ · /g) || []).length,
    m33_literalColors: literals,
    m34_arrows: [...document.querySelectorAll('button,a')]
                  .filter(el => /→\s*$/.test(el.textContent.trim())).length,
  };
})(P);
```

**Пороги для интерпретации**

| Поле | Норма | Тревога |
|---|---|---|
| `m8_capsRatio` | ≤ 0.02 | > 0.05 |
| `m9_fontSizes`, `m9_tell` | `font_sizes.norm` в `thresholds.yaml` | `m9_tell`: больше `font_sizes.tell_above` |
| `m10_spacingValues` | 6–10 | ≤ 3 или ≥ 20 |
| `m11_inScale`, `m11_tell` | не ниже `spaceInScaleMin` | `m11_tell`: ниже `spaceInScaleMin` |
| `m12_smallTargets` | < 0.10 | > 0.20 |
| `m13_dominantShadowShare` | ≤ 0.6 | > 0.6 при 5+ тенях |
| `m14_radii` | 3–5 | 1 или ≥ 8 |
| `m15_glassElements` | 0–2 | ≥ 3 |
| `m16_mixedDepth` | 0 | ≥ 1 |
| `m23_iconStrokes` | 1 значение | ≥ 3 |
| `m29_transitionAll` | 0 | ≥ 5 |
| `m32_middots` | ≤ 5 | > 10 |
| `m33_literalColors` | пусто | любое значение: цвет вне токенов ДС |
| `m34_arrows` | 0 | ≥ 2 |

Скрипт **не заменяет** проверок контраста и токенов: для них — `../../scripts/lib/color.py`, грепы из
`09-design-tokens/05-…` §3.2 и скрипт из `05-layout-grid/06-…`.

## 4. «Дефолтный вкус» и как бриф его обходит

Подробный разбор моделей, промтов и бенчмарков — задача агента H (`12-ai-generated-ui/`). Здесь — то, что
нужно для визуальных правил.

### 4.1. Что признаёт сама инструкция для моделей

Anthropic в скилле `frontend-design` перечисляет пять кластеров, вокруг которых «сейчас кучкуется
ИИ-дизайн» [S29]:

| # | Кластер | Опознавательные значения |
|---|---|---|
| 1 | тёплый кремовый + высококонтрастный сериф + терракота | фон около **#F4F1EA**, акцент около **#D97757** (собственный акцент Claude, поэтому в чужом брифе читается как tell) |
| 2 | почти чёрный фон + один кислотный акцент | кислотно-зелёный или вермильон |
| 3 | broadsheet | волосяные линейки, **нулевой радиус**, плотные газетные колонки |
| 4 | SaaS-card kit | одинаковые скруглённые карточки, **один радиус на всём независимо от иерархии**, одинаковая тень `rgba(0,0,0,.1)`, градиентные заливки как декор |
| 5 | template chrome | капс-eyebrow, `A · B · C`, `WORD — fragment`, `#0B0B0B` / `#111` вместо чёрного, моно для мелких подписей, `→` в кнопках |

Там же — оговорка, которую нельзя опускать: **«All traits are legitimate for some briefs… Where the brief
pins down a visual direction, follow it exactly — the brief's own words always win, including when it asks
for one of these looks. Where it leaves an axis free, don't spend that freedom on one of these defaults.»**

### 4.2. Что делает бриф

Формула: **слоп берётся из отсутствия решений; бриф возвращает решения на место**.

| Что задать в брифе | Чем это закрывает |
|---|---|
| гарнитуры (одна или две, с именами) | маркер 6 |
| палитра ролями с hex (8–10 значений) | маркеры 1, 2, 4, 5 |
| шкала радиусов (4 значения) и толщина границы | маркеры 14, 16 |
| модель глубины словами | маркеры 13, 15, 16 |
| четыре размера плотности | маркеры 10, 11, 12 |
| набор иконок и штрих | маркеры 21, 23 |
| реальный контент (самый длинный вариант) | маркер 24 |
| перечень обязательных состояний | маркеры 25, 26, 27 |
| три длительности и две кривые | маркеры 28, 29 |
| список запретов | маркеры 3, 30–34 |

Это ровно карточка стиля из `02-style-tiles-and-character-knobs.md` §5.1 плюс блок запретов.

### 4.3. Что работает и чего ждать

Три задокументированных приёма [S17]:
1. **Направлять по осям, а не просить «красиво»**: отдельные указания для типографики, цвета, движения,
   фона.
2. **Референс через словесное описание**: «палитра горнолыжного домика 1970-х: жжёный оранжевый, авокадо,
   тёплые коричневые» — модель интерполирует между обучающими примерами с общим эстетическим признаком.
3. **Явные запреты**: «Do not use Inter, Roboto, or Arial», «No purple gradients on white backgrounds»,
   «Avoid the three-boxes-with-icons cliché». Обоснование: «transformer models can perform negation during
   inference. You're explicitly reducing the probability weight of the patterns you want to avoid».

Ограничение, названное в тех же источниках: модель **«still tends to converge on common choices (Space
Grotesk, for example) across generations»**. То есть запрет смещает вероятность, но не исключает паттерн,
и у запретов есть собственный дефолт следующего порядка. Отсюда правило: **запрет + токены + проверка
результата**, а не что-то одно.

Дополнительные приёмы, проверенные автором каталога [S17]: назначать роль («senior frontend engineer with a
background in print design»); просить **три разных направления** вместо одного; фиксировать тему тегом
`<theme>` с явными значениями, иначе между итерациями происходит дрейф к дефолту.

### 4.4. Где инструкция для моделей вредит веб-сервису

Два пункта из `<frontend_aesthetics>`, написанные для лендингов и опасные для рабочих интерфейсов:

| Пункт инструкции | Почему вредит | Что вместо |
|---|---|---|
| «Backgrounds: Create atmosphere and depth rather than defaulting to solid colors. Layer CSS gradients, use geometric patterns» | градиент под таблицей ломает читаемость чисел, конфликтует с зеброй, hover и selected; правило площади требует хромы 0.00–0.03 на фоне > 30 % экрана | сплошной фон; градиент — в четырёх разрешённых местах (`01-color/06-…` §2.1) |
| «Use animations for effects and micro-interactions… one well-orchestrated page load with staggered reveals» | в админке, куда заходят 40 раз в день, оркестрованная загрузка мешает; стаггер удлиняет время до данных | движение только как отклик на действие; стаггер 20 ms максимум, и только при первом входе |

Третий пункт — «Avoid generic fonts like Arial and Inter» — для веб-сервиса на кириллице требует поправки:
список безопасных гарнитур с качественной кириллицей короткий (Golos Text, IBM Plex Sans, PT Sans,
Commissioner), и Inter в нём **отсутствует по другой причине** — из-за рисунка «д» и «л»
(`02-typography/01-font-selection.md`). То есть запрет на Inter в русском интерфейсе обоснован лучше, чем в
английском, но заменять его надо не «чем-нибудь необычным», а проверенной гарнитурой.

Общий вывод: инструкция писалась для маркетинговых страниц. Для веб-сервиса её надо читать с поправкой
«рабочий экран ≠ герой лендинга».

## 5. Маркеры зависят от эпохи

| Период | Что было дефолтом | Статус в 2026 |
|---|---|---|
| 2020–2022 | glassmorphism, неоновое свечение, тёмный фон с фиолетовым | опознаётся мгновенно |
| 2023–2024 | Inter + индиго-фиолетовый градиент + три карточки + тень `.1` | канонический слоп |
| 2025–2026 | кремовый **#F4F1EA** + высококонтрастный сериф + терракота **#D97757**; broadsheet с волосяными линейками и нулевым радиусом; «bento из одинаковых плиток» | новый дефолт, ещё не всеми опознан |
| ожидаемое | всё, что сегодня рекомендуется как способ отличиться | попадёт в корпус через 12–18 месяцев |

Практическое следствие: **этот каталог надо датировать и пересматривать**. Признаки 1, 2, 3, 5 (цвет)
устареют быстрее всего; признаки 10–16 (форма, отступы, глубина) и 24–27 (состояния) устойчивы, потому что
опираются на измеримые свойства, а не на моду.

Второе следствие: **не делать список запретов единственным инструментом**. Запрет на фиолетовый в 2026
ничего не даёт, если модель уже перешла на кремовый с терракотой.

## 6. Что делать: порядок правок

### 6.1. Отдача по стоимости

| Правка | Время | Эффект | Источник |
|---|---|---|---|
| сменить гарнитуру | ~1 час | максимальный | «the single highest-leverage move against slop» [S16] |
| исправить сложные раскладки и карточки | часы | высокий | «модели плохо собирают сложные раскладки… наибольший эффект за наименьшее время» `[V09 B]` |
| заменить палитру на токены с ролями | часы | высокий | [S17] |
| развести радиусы по иерархии | минуты | средний | измерения: медиана 3.5 |
| убрать «шаблонный хром» (§2.9) | минуты | средний | [S29] |
| нарисовать состояния | по часу на каждое | высокий и незаметный на скриншоте | «эти экраны занимают меньше часа каждый, и почти никто их не делает» [S16] |
| заменить иконки на один набор | минуты | средний | `07-iconography-imagery/01-…` |
| починить движение | часы | низкий, пока не сделано остальное | `08-motion/` |

### 6.2. Порядок

```
1. Раскладка и иерархия   — что главное на экране; убрать три одинаковые карточки
2. Цвет и токены          — роли вместо hex, один акцент, контраст посчитан
3. Типографика            — гарнитура, 4–7 кеглей, 2 веса, капс убран
4. Форма и глубина        — шкала радиусов, одна модель глубины
5. Иконки и изображения   — один набор, одна толщина, аватары без градиента
6. Состояния              — пустое, загрузка, ошибка, длинный текст, много данных
7. Движение               — 3 длительности, 2 кривые, фокус без анимации
8. Контент                — реальные тексты, включая самый длинный на русском
9. Прогон проверок §3 и контраста
```

Начинать с пункта 7 бессмысленно: полировка движения на неверной иерархии не читается.

### 6.3. Что возвращать вместо каждого кластера

| Кластер | Замена |
|---|---|
| SaaS-card kit | разные радиусы по иерархии; граница вместо тени; главный блок крупнее |
| фиолетовый градиент | акцент из бренда, сплошная заливка, градиент только в четырёх местах |
| template chrome | подписи с ролями; убрать капс, точки, стрелки, моно без данных |
| кремовый с серифом | сериф только в display-роли и только если он выбран под продукт |
| три карточки | список, таблица или асимметричная сетка |
| «всё видно сразу» | прогрессивное раскрытие |

### 6.4. Финальная проверка

Три вопроса, которые задаются перед отправкой [S16]:
1. **Does this feel like it came from somewhere?** — есть ли у решения происхождение (бренд, предметная
   область, ограничение)?
2. **Does it have a voice?** — можно ли по скриншоту без текста отличить продукт от конкурентов (тест
   «выброшенного контента», `02-style-tiles-and-character-knobs.md` §6.3)?
3. **Would I notice if it disappeared?**

Плюс приём из инструкции для моделей: **двухпроходная работа** — сначала план (цвет 4–6 именованных hex,
типографика с ролями, раскладка одним предложением и ASCII-каркасом, принципы), затем **ревью плана против
брифа**: если часть плана — «generic default, который ты выдал бы на любой похожий бриф», переписать и
сказать, что именно изменено и почему. Код пишется только после этого [S29].

## Частые ошибки

1. **Ставить диагноз по одному маркеру.** Inter, белый фон и скруглённые карточки по отдельности нормальны.
2. **Принимать список запретов за стиль.** «Не фиолетовый, не Inter, не три карточки» не описывает ни
   одного положительного решения.
3. **Чинить симптом, не меняя источник.** Перекрасили кнопку, оставили одинаковый радиус, одну тень и
   отсутствующие состояния.
4. **Оценивать только первый экран.** Слоп виден на пустом состоянии и на ошибке, а не в герое.
5. **Доверять «выглядит чисто».** Полированный слоп — самый трудный случай.
6. **Применять каталог к лендингу как к веб-сервису.** Градиентный фон на промо-странице — нормально, под
   таблицей — нет.
7. **Забывать, что маркеры датированы.** Проверять список раз в полгода.
8. **Считать «убрал цвет» решением.** Полное обесцвечивание порождает другую претензию: «bland and
   soulless gray UI» (110 лайков) `[V08 C]`.

### Ошибки, типичные для нейросетей, при попытке самопроверки

- **Пересказ маркеров словами вместо проверки значений.** «Я использовал разнообразные радиусы» при одном
  `rounded-xl` во всём файле.
- **Смена одного дефолта на другой:** запретили Inter — получили Space Grotesk; запретили фиолетовый —
  получили терракоту.
- **Добавление «характера» пятью приёмами сразу.**
- **Исправление скриншота вместо системы:** правка инлайн-стилей на одном экране, токены не тронуты.
- **Игнорирование состояний, потому что их не видно на картинке.**
- **Самоотчёт вместо прогона скрипта.** Проверки §3 выполняются, а не описываются.

## Чек-лист

1. Прогнан скрипт §3, ни одно поле не в «тревоге»?
2. Маркеров из §2 одновременно меньше четырёх?
3. Из §2.9 («шаблонный хром») не выполняется ни один?
4. Акцент имеет происхождение (бренд, предметная область), а не выбран по умолчанию?
5. Контраст текста на акценте посчитан и ≥ 4.5?
6. Вторичный текст ≥ 4.5, третичный ≥ 3?
7. Радиусов на экране 3–5?
8. Тень не одинаковая у более чем 60 % элементов с тенью?
9. Модель глубины одна?
10. Число элементов с `backdrop-filter` ≤ 2?
11. Гарнитура выбрана (и проверена на кириллицу), а не досталась по умолчанию?
12. Доля капса ≤ 2 % текстовых узлов?
13. Кеглей 4–7, весов 2?
14. Кратность отступов 4 ≥ 85 % либо объяснена шкалой продукта?
15. Целей меньше 24 px < 10 %?
16. Иконки одного набора, одна толщина штриха?
17. Эмодзи в интерфейсе отсутствуют?
18. Аватары без градиента?
19. Нарисованы пустое состояние, загрузка, ошибка, длинный текст, много данных?
20. В форме есть обязательность, валидация и сообщения об ошибках?
21. Весь текст реальный (греп по `lorem`, `John Doe`, `example@example` пуст)?
22. `transition: all` отсутствует?
23. Нет `→` в конце текста кнопок, `·` в мета-строках, нумерации без последовательности?
24. Пройден тест «выброшенного контента»?
25. Заданы три вопроса §6.4 и на все три ответ «да»?

## Открытые вопросы и противоречия

1. **Пороги в §3 выведены из медиан практики, а не из эксперимента.** Неизвестно, какие из 22
   автоматических проверок действительно коррелируют с оценкой «это сгенерировано». Эксперимент
   («человек размечает 40 экранов, метрики предсказывают разметку») никто не проводил; агент P предлагал
   аналогичный для «воспринимаемого качества».
2. **Порог «четыре маркера» — мой выбор.** Обоснование: в источниках кластер описывается качественно
   («any one of these is fine alone, all of them together is the fingerprint»), числа нет.
3. **Список маркеров датирован сентябрём 2026 и устареет.** Цветовые признаки (1–5) быстрее остальных.
4. **Model collapse упоминается как объяснение, но ссылка в источнике дана без выходных данных** («a study
   in Nature»); саму работу я не открывал, поэтому механизм помечаю `[мнение]`, а не `[исследование]`.
5. **Противоречие с инструкцией Anthropic не разрешено.** Она требует «атмосферы и глубины» в фонах и
   оркестрованной загрузки; для веб-сервиса это вредно (§4.4). Кто прав, зависит от типа страницы, и
   инструкция этого различия не делает.
6. **Неизвестно, насколько запреты в промте помогают в процентах.** Источники говорят «снижают
   вероятность», измерений нет. Это прямой вопрос агенту H.
7. **Проверка «три одинаковые карточки» не автоматизирована** — нужен анализ структуры DOM-сиблингов;
   в скрипте §3 она отсутствует.
8. **Цифры 1.7× и 2.74× не проверены по первоисточнику.** Взяты из обзора [S32], который
   продвигает собственный инструмент. Отчёт CodeRabbit и статью CHI 2025 нужно открыть отдельно — это
   задача агента H.
9. **Маркеры композиции и состояний (9 из 34) проверяются только руками.** Автоматизация требует открытия
   экранов без данных и с ошибками, то есть управления приложением, а не чтения стилей.
