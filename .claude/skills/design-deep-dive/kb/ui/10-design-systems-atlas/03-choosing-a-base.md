# Какую базу взять генеративному агенту

Волна 2, агент F, 22 сентября 2026. Источников прочитано целиком: 38 (плюс 5 добраны для атласа) и
24 измеренных продукта (агент P).

Выбор базы — это выбор четырёх вещей сразу: словаря токенов, набора компонентов, механики тем и
эстетики по умолчанию. Их можно взять из разных мест, и обычно так и надо делать.

## Выжимка для агента

1. **База по умолчанию: Tailwind v4 (примитивы) + собственный семантический слой + shadcn/ui
   (компоненты) + Radix Primitives (поведение).** Четыре независимых слоя, каждый заменяем. → §3
   `[мнение]`
2. **Не бери готовую систему целиком, если продукт не принадлежит её экосистеме.** Material тянет за
   собой тач-метрики, Carbon — IBM Plex и прямые углы, Ant — свою форму и китайский типографический
   ритм. → §2 `[мнение]`
3. **Семантический слой пиши свой в любом случае.** У shadcn его 37 переменных, этого мало: нет шкалы
   отступов, высот контролов, z-index и движения. Готовый слой на 185 токенов —
   `../09-design-tokens/04-reference-token-schema.md`. → §3.2 `[мнение]`
4. **Пять критериев выбора для конвейера:** есть ли машиночитаемые правила применения, выражается ли
   тема кодом без Figma, сколько решений требует смена характера, насколько эстетика отделима от
   механики, и что с лицензией. → §1 `[мнение]`
5. **Три системы уже документируют себя для моделей:** Primer (`org.primer.llm` в токенах), Carbon
   («Tip for agents» в README), Untitled UI (`CLAUDE.md`), плюс Adobe (MCP-сервер и плагин Claude Code)
   и shadcn (`/llms.txt`). Это прямое преимущество при прочих равных. → §1.1 `[система]`
6. **Для плотной админки бери значения Carbon и Primer, механику — shadcn, палитру — Tailwind.**
   Карбоновские 32/40 контролы и нулевой радиус, примеровская граница 3.45:1. → §4.1 `[мнение]`
7. **Material 3 бери только если продукт android-подобный.** Радиус 28 у крупных поверхностей, цель
   48 dp, тональные контейнеры — это мобильная эстетика; в плотной админке она стоит 30 % плотности.
   Плюс движение Material объявлено устаревшим. → §4.2 `[спорно]`
8. **Fluent 2 и Carbon — базы для корпоративных консолей.** Мелкие радиусы (2–8), плотные отступы,
   готовый высококонтрастный набор у Fluent, модель слоёв у Carbon. → §4.3 `[мнение]`
9. **Radix Themes бери, когда характер должен настраиваться, а не выбираться.** Семь ручек — готовая
   модель параметризации. Цена: дробные px от `--scaling` и отсутствие токенов движения. → §4.4
   `[мнение]`
10. **Ant Design бери, если продукт — форма на форме.** 12 seed-значений как ручки характера,
    полнота компонентов форм. Цена: формулы вместо таблиц и узнаваемая форма. → §4.5 `[мнение]`
11. **Практика отвечает на четыре спорных вопроса волны 1:** высота контрола **32** (не 40), радиус
    **4–8, медиана 6** (10 почти не встречается), карточка **на границе, а не на тени**, база текста
    **14**, второй вариант — **12**, а не 16. → §2.3 `[измерение]`
12. **«Как не выглядеть как все на shadcn» — это пять ручек:** нейтраль не zinc, радиус не 10, тень не
    дефолтная, шрифт не Inter/Geist, акцент не синий. Смена любых двух уже снимает узнаваемость. → §5
    `[мнение]`
13. **Узнаваемость shadcn держится на трёх вещах:** почти чёрный `--primary` `oklch(0.205 0 0)`,
    радиус 10 px и однослойная тень `0 1px 2px rgba(0,0,0,.05)`. → §5.1 `[система]`
14. **Слабое место shadcn чинится одной строкой:** `--input` указать на более тёмную ступень
    (`#949494` даёт 3.03:1, `neutral-500` — 4.76:1) вместо `oklch(0.922 0 0)` с контрастом 1.23:1. →
    §3.3 `[стандарт]`
15. **Проверяй лицензию до, а не после.** В этой работе проверена только у Salesforce (BSD 3-Clause);
    Figma-кит Untitled UI коммерческий. → §1.5 `[мнение]`

## 1. Критерии выбора

### 1.1. Машиночитаемые правила применения

Для агента это главный критерий: система, которая объясняет, **где применять токен**, экономит десятки
неверных решений.

| Система | Что есть | Формат |
|---|---|---|
| GitHub Primer | `$extensions.org.primer.llm` с `usage`, `rules`, `doNotUse`, `alternatives` на 126 функциональных токенах | в токене |
| IBM Carbon | обязательный `$description` формата «что это — сколько px. Когда применять» у каждого токена; разделы «Tip for agents» в README | в токене и в документации |
| Adobe Spectrum | `.claude-plugin/marketplace.json` и `.mcp.json` в репозитории | плагин и MCP-сервер |
| Untitled UI | `CLAUDE.md` в корне с правилами именования и структуры | файл репозитория |
| shadcn/ui | `/docs/skills` и `/llms.txt` на сайте | машиночитаемая документация |
| все остальные | ничего | — |

### 1.2. Тема выражается кодом без Figma

| Система | Тема в коде | Чем задаётся |
|---|---|---|
| Radix Themes | полностью | семь атрибутов `<Theme>` |
| Ant Design 5 | полностью | 12 seed-значений и алгоритм |
| shadcn/ui | полностью | 37 CSS-переменных |
| Tailwind v4 | полностью | `@theme` |
| Carbon, Primer, Fluent | полностью | файлы токенов |
| Spectrum | частично | токены есть, но сборка завязана на инструменты Adobe |
| Material 3 | частично | динамическая схема из seed, но выгрузка токенов генерируется |

### 1.3. Сколько решений требует смена характера

| Система | Ручек | Что меняется одним значением |
|---|---|---|
| Linear (по публикации) | **3** | base color, accent color, contrast |
| Radix Themes | **7** | accent, gray, panelBackground, scaling, radius, appearance |
| Ant Design 5 | **12** | seed целиком |
| Nuxt UI | 7 цветов | семантические цвета |
| shadcn/ui | ~5 | нейтраль, акцент, `--radius`, шрифт, тени |
| Carbon, Material, Fluent | много | характер не параметризован, меняется правкой значений |

### 1.4. Отделима ли эстетика от механики

Механика — это модель токенов, темы, поведение компонентов. Эстетика — конкретные значения.

- **Полностью отделима**: Tailwind (эстетики нет вообще), Radix Primitives (только поведение), Panda,
  Open Props.
- **Отделима с усилием**: shadcn (компоненты копируются в проект и правятся), Radix Themes (семь
  ручек), Ant (seed).
- **Плохо отделима**: Material 3 (форма зашита в компоненты), Carbon (IBM Plex и прямые углы —
  часть идентичности), Polaris, Atlassian.

### 1.5. Лицензия

Проверена в этой работе только у Salesforce: **BSD 3-Clause**, строка в заголовке каждого файла
токенов. Остальные лицензии в `01-atlas-table.md` §1 приведены по типовым значениям пакетов и требуют
проверки в репозитории. Отдельно: **Figma-кит Untitled UI коммерческий**; SF Symbols запрещено
использовать в логотипах.

## 2. Что говорит практика

### 2.1. Что подтверждено измерением

| Норма | Практика |
|---|---|
| Толщина границы 1 px | 24 продукта из 24, 95.0 % вхождений |
| Иконка 16 × 16 | 53.0 % всех `svg`, доминирует у 15 из 22 |
| Доминирующий радиус 4–8 | 19 продуктов из 24 |
| База текста админки 14 px | 14 продуктов из 24 |
| Тёмная тема меняет только цвет | 8 пар из 8: радиусы, отступы, высоты и число теней совпали |
| Карточка на границе, а не на тени | медиана 2.5 тени на продукт, у 4 из 24 теней нет |
| Оверлей на модели «кольцо + key + ambient» | оба пойманных оверлея (GitHub, Radix) |

### 2.2. Что практикой не подтверждено

| Декларация | Практика | Что делать |
|---|---|---|
| Горизонтальный padding кнопки 12 px | 8 px у 9 продуктов из 21, 16 — у 4 | взять 8 для плотного пресета, 12 оставить как допустимое |
| Padding ячейки таблицы 12 px | ни разу в 10 таблицах | взять 8 (встречается у 3 из 10) |
| Высота шапки 56 px | мода 48, медиана 56, диапазон 36–112 | взять 48 |
| Радиус 10 px в клиентском пресете | 2.5 % вхождений, доминанта у одного продукта | заменить на 8 или 12 |
| Граница контрола 3:1 к фону | медиана 1.30, порога достигает 1 продукт из 24 | **норму не смягчать**, см. §2.4 |
| Сетка 8 px | кратность 8 — медиана 45 % | сетка 4 с исключениями 6 и 10 (покрытие 88.1 %) |

### 2.3. Ответы практики на спорные пары

| Вопрос | Ответ практики |
|---|---|
| Высота контрола 32 или 40 | **32**: доминирует у 8 продуктов из 24 против 3 у 40. Клиентский сервис — 36–40, но не 48 |
| Радиус 4, 6, 8 или 10 | **4–8, медиана 6**. 10 px — 2.5 % вхождений |
| Тень у карточек или граница | **граница** 1 px, максимум `0 1px 2px` с альфой 0.05. Тень из двух-трёх слоёв начинается с меню, поповера и модалки |
| База шрифта 13, 14 или 16 | **14**, второй вариант **12** (GitHub, GitLab, tldraw, Redmine), а не 16 |
| Сайдбар 240, 256 или 280 | весь диапазон живой, центр **272–288**; плотная навигация 240–256, документация 280–288 |
| Серый фон или белый | **белый у 16 из 24**; серый — только L 94–99 % и только там, где на странице белые плитки |
| Чистые серые или тонированные | пополам; тонировка слабая, медианная хрома 0.004–0.019, оттенок синий (H 244–286), тёплых нейтралей нет ни одной |

### 2.4. Где практику копировать нельзя

Три нормы, которые нарушаются повсеместно и всё равно остаются нормами:

1. **Контраст границы контрола 3:1** (WCAG 1.4.11): медиана 1.30. Продукты опираются на то, что поле
   опознаётся по лейблу и заливке, а граница декоративна. Трактовка спорная. Компромисс из данных:
   граница в покое слабая, весь контраст перенесён на состояния — кольцо фокуса ровно 2 px
   контрастного цвета у 12 продуктов.
2. **Цель нажатия 24 px** (WCAG 2.2 SC 2.5.8): медиана 14.1 % элементов меньше 24 px; у GitLab 82.2 %.
3. **Шкала `z-index`**: значения ≥ 9999 у половины продуктов, в агрегате 100000 и 999999999.

## 3. Рекомендация по умолчанию

### 3.1. Четыре слоя, каждый заменяем

```
 слой 4  компоненты          shadcn/ui (копируются в проект и правятся)
 слой 3  поведение           Radix Primitives (фокус, клавиатура, порталы, ARIA)
 слой 2  семантика           СВОЙ набор: 185 токенов, ../09-design-tokens/04-reference-token-schema.md
 слой 1  примитивы           Tailwind v4 (22 семейства × 11 ступеней OKLCH, шкала отступов, @theme)
```

Почему так:

- **Слой 1 — Tailwind**, потому что это единственный способ связать токены с utility-классами через
  `@theme`, а палитра уже в OKLCH и содержит восемь нейтралей разной температуры (slate, gray, zinc,
  neutral, stone, mauve, olive, mist, taupe).
- **Слой 2 — свой**, потому что ни одна система не даёт набора ролей нужного размера: у shadcn 37
  переменных (мало), у Atlassian 596 (много). Готовый слой на 185 семантических токенов с правилами
  применения для модели — в `../09-design-tokens/04-reference-token-schema.md`.
- **Слой 3 — Radix Primitives**, потому что поведение (ловушка фокуса, клавиатура, порталы, ARIA) —
  самая дорогая часть и её не надо писать заново. Это **не** Radix Themes: берётся только поведение,
  без эстетики.
- **Слой 4 — shadcn**, потому что компоненты копируются в проект, а не ставятся пакетом: их можно
  править, не воюя с библиотекой. Плюс `/llms.txt` и `/docs/skills`.

### 3.2. Что дописать к shadcn обязательно

У shadcn 37 переменных. Не хватает:

| Чего нет | Что взять |
|---|---|
| шкала отступов | `space.*` 11 шагов + 8 назначений, `../09-design-tokens/04-reference-token-schema.md` §1.3 |
| высоты контролов и строк | `size.control.*`, `size.row.*` оттуда же |
| ширины панелей и оверлеев | `size.panel.*`, `size.modal.*`, `size.overlay.*` |
| статусы кроме `destructive` | `color.{danger,warning,success,info}.{bg,border,solid,on-solid,text}` |
| z-index | `z.*`, 9 значений до 1500 |
| движение | 42 токена из `../08-motion/03-reduced-motion-and-motion-tokens.md` §4–§6, включая `motionScale.*` для сокращённого движения |
| брейкпоинты по смыслу | `breakpoint.tablet` 640, `desktop` 1024, `wide` 1440 |
| типографические роли | 15 композитных ролей из пресета `../02-typography/02-type-scale.md` §7 |

### 3.3. Что починить в shadcn сразу

| Проблема | Дефолт | Контраст | Замена |
|---|---|---|---|
| граница поля ввода | `--input: oklch(0.922 0 0)` ≈ neutral-200 | **1.23:1** | `neutral-500` `#62748e` — 4.76:1 (или минимум `#949494` — 3.03:1) |
| `--border` и `--input` — одно значение | да | — | развести: `--border` — разделитель, `--input` — граница контрола |
| `--radius` 10 px | 10 | — | 6 для админки, 8 или 12 для клиентского сервиса (10 практика почти не использует) |
| `--primary` почти чёрный | `oklch(0.205 0 0)` | — | цвет бренда, если он есть |

### 3.4. Когда этой базы недостаточно

- Нужны **Web Components**, а не React → Material 3 (`material-web`), Fluent, Carbon, Spectrum.
- Нужна **Vue или Nuxt** → Nuxt UI 4.
- Нужен **готовый набор форм с валидацией и таблицами** → Ant Design 5 или MUI.
- Нужен **государственный или формальный сервис** → GOV.UK.
- Продукт живёт **внутри чужой экосистемы** (Salesforce, Atlassian, Microsoft 365) → система этой
  экосистемы, вопрос выбора не стоит.

## 4. Когда брать другую базу

### 4.1. Плотная админка и дашборд

**Возьми значения у Carbon и Primer, механику у shadcn, палитру у Tailwind.**

| Что | Откуда | Значение |
|---|---|---|
| высоты контролов | Carbon `container` | 24, 32, **40**, 48 (практика: основная 32) |
| радиусы | Carbon | 0, 2, 4, 8 (4 — «Default rounding for inputs, cards») |
| отступы | Carbon `spacing` | 2, 4, 8, 12, 16, 24, 32, 40, 48 |
| граница контрола | Primer `borderColor.emphasis` | `#818B98`, 3.45:1 |
| шкала слоёв | Carbon `layer.01–03` | три уровня вместо пяти у Material |
| шрифт | IBM Plex Sans или Inter | база 14 |
| тень | нет на карточках, только на оверлеях | практика: медиана 2.5 |

Готовый пресет с этими значениями — `../03-spacing-sizing/03-control-and-panel-sizes.md` §8 и
`../09-design-tokens/04-reference-token-schema.md`.

### 4.2. Android-подобный или кроссплатформенный продукт

**Material 3.** Что получаешь: 49 ролей цвета с парами `on-`, пять уровней поверхности, динамическая
схема из seed в HCT, Web Components.

Что платишь:

- радиус 28 у крупных поверхностей и 12 по умолчанию — заметно мягче, чем в вебе (практика: медиана 6);
- цель нажатия 48 dp и высота кнопки 40 — теряется около 30 % строк на экране 900 px по сравнению с
  32-пиксельными контролами;
- тональные контейнеры (`primary-container`, `secondary-container`) требуют дисциплины, иначе интерфейс
  становится пёстрым;
- **система длительностей и кривых объявлена неподдерживаемой**: переходить надо на пружины motion
  physics, а их официальная конвертация в CSS даёт перелёт (y₁ до 1.67), который Carbon прямо запрещает
  в рабочих интерфейсах. Для админки бери кривые без перелёта.

### 4.3. Корпоративная консоль

**Fluent 2** или **Carbon**.

Fluent даёт: радиусы 0–8 в мелкой части, отступы с полушагами 6 и 10, 8 длительностей, 9 кривых и
**готовый высококонтрастный набор** отдельным файлом. Carbon даёт: DTCG-формат с описаниями применения,
модель слоёв, четыре темы, прямые углы.

Что учесть: Fluent разводит отступы по осям (22 токена вместо 11) — при переносе в свой набор ось можно
схлопнуть. У Carbon контекстные токены `<Layer>` требуют React; без него бери явные номера.

### 4.4. Продукт, где характер настраивается пользователем

**Radix Themes.** Семь ручек — готовая модель. Цена: `--scaling` даёт дробные px (4 × 0.95 = 3.8),
абсолютный интерлиньяж не переносится в составные токены DTCG, токенов движения нет вообще.

Если нужна только модель, а не компоненты: возьми идею семи ручек и реализуй её таблицей значений на
режим, а не умножением (`../09-design-tokens/03-theming-and-modes.md` §6.2).

### 4.5. Продукт из форм

**Ant Design 5.** 12 seed-значений как готовые ручки характера, самый полный набор компонентов форм,
плотная форма (`controlHeight: 32`, `borderRadius: 6`, `fontSize: 14` — всё совпадает с модой практики).

Цена: значения выводятся формулами и не правятся точечно; шкала кеглей растёт по экспоненте
(12, 14, 16, 20, 24, 30, 38…), что даёт крупные заголовки; узнаваемая форма компонентов.

### 4.6. Государственный или формальный сервис

**GOV.UK.** База 5 px, прямые углы, высокий контраст, адаптивные отступы (шкала переключается на
брейкпоинте 640). Не смешивай его шкалу с сеткой 4: система внутренне согласована на пятёрке.

## 5. Как не выглядеть как все на shadcn

Детали — волна 3, папка 11 (стили и тренды). Здесь механика.

### 5.1. Из чего складывается узнаваемость

Три вещи дают «вид shadcn» сильнее всего:

1. **Почти чёрный акцент** `--primary: oklch(0.205 0 0)` — кнопка без цвета;
2. **радиус 10 px** (`--radius: 0.625rem`) с производными 6 / 8 / 10 / 14 / 18;
3. **однослойная тень** `0 1px 2px rgba(0,0,0,.05)` на карточках.

Плюс два вторичных признака: нейтраль zinc или neutral без тонировки (практика: у shadcn измеренная
хрома **0.0**) и шрифт Geist или Inter.

### 5.2. Пять ручек, снимающих узнаваемость

| # | Ручка | Дефолт shadcn | Чем заменить |
|---|---|---|---|
| 1 | нейтраль | zinc / neutral, хрома 0.0 | slate (0.046), stone (тёплая), mauve / olive / mist / taupe из Tailwind v4; практика допускает хрому до 0.019 |
| 2 | радиус | 10 | 4 или 6 (строгий), 12 (мягкий); 10 практика почти не использует |
| 3 | тень | `0 1px 2px .05` | либо ноль теней и граница 1 px (как Primer, Carbon, Gravity), либо трёхслойная модель с кольцом (как Radix) |
| 4 | шрифт | Geist / Inter | IBM Plex Sans, Atlassian Sans, системный стек, шрифт бренда |
| 5 | акцент | почти чёрный | цвет бренда; если бренда нет — не синий: синий доминирует в выборке |

**Смены любых двух ручек достаточно**, чтобы интерфейс перестал читаться как «стандартный shadcn».
Смена всех пяти даёт собственный характер.

### 5.3. Три приёма, которые меняют вид сильнее токенов

1. **Способ показать слои.** Три варианта в выборке: серый фон и белые карточки (Polaris, MUI,
   Grafana, Matomo), белый фон и границы (GitHub, Primer, Carbon, Consta), светлота поверхностей без
   границ и теней (Linear, по публикации). Выбор меняет вид больше, чем палитра.
2. **Плотность.** Строка таблицы 28, 36 или 48 px — это три разных продукта при одних и тех же цветах.
3. **Тонировка нейтрали.** Хрома 0 против 0.011 (GitHub, Primer) — разница видна, но не читается как
   «цветной интерфейс». Оттенок в практике всегда синий (H 244–286); **тёплая нейтраль сразу выделяет
   продукт**, потому что в выборке её нет ни у кого.

### 5.4. Чего делать не надо

- Менять радиус на 16–24 «для мягкости»: практика держится в 4–12, и крупный радиус в плотной таблице
  читается как ошибка.
- Добавлять градиенты и стекло в рабочий интерфейс: в 24 измеренных продуктах `backdrop-filter` и
  градиенты встречаются только в оверлеях.
- Менять шрифт на декоративный: из измеренных продуктов 24 из 24 используют гротеск, и 11 из них —
  Inter, системный стек или их производные.
- Добавлять третий акцентный цвет: в практике один акцент плюс статусы.

## Частые ошибки

1. **Взять систему целиком «чтобы не думать».** Приходит вместе с эстетикой, которая может не
   подходить продукту.
2. **Взять компоненты одной системы и токены другой.** Компоненты shadcn с токенами Material дают
   радиус 12 на контроле высотой 32 — визуальный конфликт.
3. **Оставить дефолты shadcn.** Граница поля 1.23:1 и почти чёрный акцент — это не решение, а его
   отсутствие.
4. **Путать Radix Primitives и Radix Themes.** Первое — поведение без стилей, второе — полноценная
   визуальная система.
5. **Брать метрики мобильной системы для десктопа.** 48 dp цели нажатия в плотной админке съедают
   треть строк.
6. **Считать практику нормой.** 82 % целей меньше 24 px — дефект, а не ориентир.
7. **Считать декларацию реальностью.** Контраст границ 3:1 объявляют многие, соблюдает один из 24.
8. **Менять характер, не перепроверив контраст.** Смена акцента может увести пару ниже 4.5:1.
9. **Не проверить лицензию.**
10. **Брать шкалу движения Material как актуальную.** Она объявлена неподдерживаемой.

### Ошибки, типичные для нейросетей

- **Смешение значений разных систем в одном экране** — самая частая. Проверка: все радиусы из одной
  шкалы, все высоты из одной, все отступы из одной.
- **Дефолты shadcn как «нейтральный выбор».** Это не нейтральный, а узнаваемый выбор.
- **Выдумывание «принятых» значений.** «Высота кнопки обычно 40» — практика говорит 32.
- **Перенос радиуса 10 из shadcn в админку.** Практика: 2.5 % вхождений.
- **Добавление градиента и стекла «для современности».** В рабочих интерфейсах не встречается.
- **Синий акцент по умолчанию.** Самый частый выбор, и именно поэтому самый безликий.

## Чек-лист

1. Выбраны ли все четыре слоя осознанно (примитивы, семантика, поведение, компоненты)?
2. Семантический слой свой, а не 37 переменных из коробки?
3. В семантическом слое есть шкала отступов, высоты контролов, z-index, движение, статусы?
4. Граница поля ввода даёт ≥ 3:1 к фону?
5. `--border` и `--input` разведены?
6. Радиус выбран из диапазона 4–8 (админка) или 8–12 (клиентский сервис), но не 10?
7. Высота контрола 32 (админка) или 36–40 (клиентский сервис), но не 48?
8. База текста 14 (админка) или 16 (клиентский сервис)?
9. Способ показать слои выбран один: серый фон и белые карточки, либо белый фон и границы, либо
   светлота поверхностей?
10. Карточки без тени или с одной слабой; многослойная тень только на оверлеях?
11. Нейтраль выбрана осознанно (хрома 0, 0.005, 0.011 или 0.019), а не «по умолчанию»?
12. Акцент не синий по инерции?
13. Шрифт не Inter и не Geist по инерции?
14. Лицензии всех использованных систем проверены в репозитории?
15. Не смешаны значения двух систем в одной шкале?
16. Все значения проходят проверки контраста после смены характера?
17. Движение взято не из устаревшей шкалы Material?

## Открытые вопросы и противоречия

1. **Граница контрола 3:1.** Норма WCAG 1.4.11 против практики 23 продуктов из 24. Позиция спорна в
   самом стандарте: поле опознаётся лейблом и заливкой, а граница может считаться декоративной. Если
   нарисовать границу с контрастом 3:1 к белому (`#949494`), интерфейс будет выглядеть тяжелее всех 24
   измеренных продуктов. Компромисс — слабая граница в покое и весь контраст в состояниях — из данных
   виден, но состояния hover и selected не измерялись.
2. **Сколько ручек характера достаточно.** Linear говорит о трёх, Radix о семи, Ant о двенадцати.
   Эксперимента, сравнивающего результат, нет.
3. **Radix Primitives как слой поведения** — рекомендация по опыту, а не по данным; альтернативы (Ark
   UI, React Aria, Base UI) в этой работе не разбирались. Untitled UI React построен на React Aria.
4. **«Не выглядеть как все» не измерено.** Утверждение «смены двух ручек достаточно» — рассуждение, а
   не результат опроса или теста. Это тема волны 3, папка 11.
5. **Практика не покрывает закрытые продукты.** Linear, Stripe Dashboard, Notion, Figma и другие
   измерить без логина нельзя; их эстетика влияет на «вид 2026 года» сильнее, чем измеренные
   продукты.
6. **Витрины систем смещают статистику практики**: 6 из 24 продуктов — демо, где показаны все варианты
   сразу.
7. **Оценка «30 % строк теряется при контроле 40 вместо 32»** — арифметика по высоте строки, а не
   измерение реальных экранов.
8. **Лицензии** проверены только у Salesforce.
