# Глоссарий: дизайн-токены

Волна 2, агент F, 22 сентября 2026. Термины темы «токены и темы». Формат: RU термин (EN термин) —
определение в 1–2 строки; где уместно, пример значения и ссылка на раздел.

## Уровни и виды токенов

**Дизайн-токен (design token)** — именованное решение о визуальном свойстве, хранимое отдельно от кода
компонента. Термин ввёл Salesforce в 2014 (Jina Anne). Пример: `space.md` = 16px.

**Примитив (primitive, reference token, global token, base token, seed)** — точка шкалы без смысла:
`primitive.color.accent.600` = `#155dfc`, `primitive.size.16` = 16px. Имя описывает значение.

**Семантический токен (semantic token, alias token, system token, functional token)** — роль в
интерфейсе: `color.bg.canvas`, `space.inset.card`. Имя описывает назначение, значение — ссылка на
примитив.

**Компонентный токен (component token)** — значение, принадлежащее одному компоненту:
`button.primary.background`. Заводится, когда значение нужно трём и более компонентам, — до этого живёт
в коде компонента. → `01-architecture-and-naming.md` §1.4.

**Контекстный токен (contextual token)** — токен, значение которого подставляется в рантайме по месту в
дереве: `$layer` у Carbon без номера, значение определяется глубиной вложенности `<Layer>`. В DTCG не
выражается. → `03-theming-and-modes.md` §4.2.

**Псевдотокен (pseudo-token)** — переменная уровня компонента, указывающая на токен системы и скрытая от
публикации. Приём Uber: компонент параметризован, словарь системы не растёт. →
`05-anti-patterns-and-pipeline.md` §1.1.

**Алиас (alias, reference)** — значение токена в виде ссылки на другой токен: `"$value":
"{primitive.color.accent.600}"`. Ссылаться можно только на токен целиком, не на группу.

**Мёртвый токен (dead token)** — токен, на который никто не ссылается. Дефект: занимает место в
словаре, который читают человек и модель.

## Формат

**DTCG (Design Tokens Community Group)** — рабочая группа W3C и её формат описания токенов. Стабильная
версия — Design Tokens Format Module **2025.10**, Final Community Group Report от 28.10.2025.

**Design Tokens Format Module** — основной модуль формата: `$value`, `$type`, `$description`,
`$extensions`, `$deprecated`, группы, алиасы, базовые и составные типы.

**Color Module** — модуль формата про цвет: 14 цветовых пространств, `colorSpace`, `components`,
`alpha`, шестизначный `hex`, ключевое слово `none`.

**Resolver Module** — модуль формата про темы: `sets`, `modifiers`, `contexts`, `resolutionOrder`.
Отдельный файл `.resolver.json`. → `03-theming-and-modes.md` §2.

**`$value`** — зарезервированное свойство, делающее объект токеном. Объект без `$value` — группа.

**`$type`** — тип токена; наследуется от ближайшей родительской группы. Если не определён нигде, токен
невалиден; инструменты не имеют права угадывать тип по значению.

**`$extensions`** — объект с произвольными метаданными; ключи в обратной доменной нотации
(`org.primer.llm`). Инструменты обязаны сохранять расширения, которых не понимают.

**`$deprecated`** — пометка «устарел»: `true`, строка-объяснение или `false` (перебивает значение
группы).

**`$root`, `$extends`, `$ref`** — свойства из черновика 2026 года (корневой токен группы, наследование
группы, JSON Pointer). Реализовывать пока нельзя.

**Составной тип (composite type)** — тип, значение которого объект из нескольких подзначений:
`typography`, `shadow`, `border`, `transition`, `gradient`, `strokeStyle`.

**`dimension`** — тип размера; значение — объект `{value, unit}` с единицей `px` или `rem`. Единица
обязательна даже при нуле. Единиц `em` и `%` в типе нет.

**Двойной узел (double node)** — узел, который одновременно токен и группа (`background` плюс
`background.hover`). По спецификации 2025.10 — ошибка; используется Carbon и Panda CSS; в черновике
2026 легализуется через `$root`.

## Темы и режимы

**Тема (theme)** — набор значений, связанный с брендом, продуктом или заказчиком. Ортогональна режиму:
каждому бренду нужны и светлый, и тёмный режим.

**Режим (mode)** — контекст внутри одной оси: `light` / `dark`, `compact` / `comfortable`,
`normal` / `increased` контраст.

**Ось темизации (axis, modifier)** — независимое измерение вариативности: бренд, режим цвета, контраст,
плотность, платформа. Хранить надо оси, а не их произведение.

**Set (набор)** — в резолвере: коллекция токенов без вариантов. Конфликт внутри набора решается
«побеждает последний».

**Modifier (модификатор)** — в резолвере: ось с двумя и более контекстами. Не может ссылаться на другой
модификатор.

**`resolutionOrder`** — порядок наложения наборов и модификаторов; позднее перебивает раннее.

**Ортогональность (orthogonality)** — свойство осей трогать непересекающиеся множества токенов.
Рекомендация резолвера; при пересечении обязателен явный приоритет.

**Комбинаторный взрыв (combinatorial explosion)** — рост числа наборов как произведения контекстов всех
осей. 5 брендов × 2 режима × 2 контраста × 3 плотности = 60 против 12 при хранении по осям.

**Inline theming** — рендер куска страницы в другой теме (`<Theme theme="g100">` у Carbon). Оговорка
документации: только для крупных сдвигов цвета.

**Инверсная роль (inverted, knockout token)** — роль для компонента на противоположном фоне внутри
текущей темы: тёмный тултип на светлой странице. В эталонной схеме — `color.bg.inverse` и
`color.text.on-inverse`.

**Плотность (density)** — ось, меняющая отступы, высоты контролов и высоты строк. Не меняет кегль,
радиусы, цвета и цель нажатия.

**`forced-colors`** — режим принудительных цветов операционной системы. Не тема, а отказ от темы:
цвета задаёт ОС, токены цвета перестают действовать.

**`color-scheme`** — CSS-свойство, сообщающее браузеру, какие темы поддерживает страница. Без него
скроллбары и встроенные элементы формы остаются светлыми на тёмном фоне.

**`light-dark()`** — CSS-функция выбора значения по текущей схеме. Экономит половину объявлений, но
третий режим в неё не помещается.

## Глубина и тени

**`shadow.key` (ключевой слой, key shadow, key light)** — ближний, плотный слой тени: малое смещение,
малое размытие, нулевой или нулевой-отрицательный spread. Отвечает за «отрыв от плоскости».
Пример: `0 1px 2px 0 rgb(2 6 24 / 0.08)`.

**`shadow.ambient` (рассеянный слой, ambient shadow, ambient light)** — дальний, диффузный слой тени:
большое смещение и размытие, отрицательный spread. Отвечает за ощущение высоты.
Пример: `0 4px 8px -2px rgb(2 6 24 / 0.08)`.

> **Предупреждение о терминологии.** Слова «key» и «ambient» означают у разных авторов
> **противоположное**. У Material и Fluent «ambient» — большая рассеянная тень, «key» — короткая
> плотная (это определение принято здесь и в эталонной схеме). У Steve Schoger «ambient» —
> **короткая плотная** тень у самого объекта, а большая называется «direct». Встретив эти слова в
> чужом источнике, проверяй по числам: если смещение и размытие большие, а spread отрицательный,
> это `ambient` в нашем смысле, независимо от того, как это названо.

**`shadow.ring` (кольцо, hairline ring)** — слой `0 0 0 1px` внутри тени, заменяющий границу.
Применяется вместо `border`, чтобы не сдвигать раскладку (приём Primer: «used instead of a border to
prevent layout shift»). В тёмной теме меняет полярность на светлый: чёрное кольцо на тёмном холсте
невидимо. В режиме `forced-colors` исчезает, поэтому требует запасного `border`.

**Слой поверхности (surface layer)** — уровень «высоты» фона: холст → поверхность → всплывающая
поверхность. Material: пять контейнеров, Carbon: `layer.01–03`, эталонная схема: три плюс `subtle`.

## Именование

**Namespace** — префикс системы в имени токена: `md-`, `slds-`, `g-`. Нужен, когда на странице живут
две системы.

**Category / concept / property / variant / state / scale / mode** — части имени по модели Nathan
Curtis. Пример разложения: `color` (category) + `action` (concept) + `background` (property) +
`primary` (variant) + `hover` (state).

**Шкала (scale)** — упорядоченный ряд значений. Пять видов: enumerated (1, 2, 3), ordered (50…900),
bounded (`slate-42`), proportion (`2-x`), t-shirt (s, m, l).

**Полиерархия (polyhierarchy)** — принадлежность одного решения двум наборам («error red» — и статус, и
цвет текста контрола). Решается сохранением обоих имён и алиасом между ними.

**Полнота (completeness)** — свойство набора содержать все нужные роли. Не означает, что каждое имя
должно содержать все части: `shape-tile-corner-radius-default-on-light` — антипример.

**Scoping** — ограничение, в каких свойствах переменная предлагается (Figma, `org.primer.figma.scopes`).
В CSS аналога нет.

**`codeSyntax`** — поле Primer с готовой строкой для вставки в код:
`var(--fgColor-default) /* utility class: .color-fg-default */`.

## Инструменты

**Style Dictionary** — компилятор токенов (Amazon, Danny Banks). С версии 4 понимает DTCG; формат
2025.10 поддержан не полностью («work in progress in v5»).

**Terrazzo** (бывший Cobalt) — компилятор токенов с командами `tz check`, `tz build`, `tz bundle`.
Заявляет полную поддержку формата; резолверы обещаны в 2.0. Умеет раскладывать цвет по гамутам.

**Tokens Studio** — плагин Figma; его формат `$themes.json` + `$metadata.json` стал де-факто стандартом
обмена наборами. Resolver Module вырос из их модели.

**Figma Variables** — модель переменных Figma: четыре типа (Color, Number, String, Boolean), коллекции,
режимы, scoping, лимит 5000 переменных на коллекцию. Составных типов нет.

**Penpot tokens** — реализация DTCG в открытом редакторе; добавляет арифметику в значениях (17 функций)
и модель sets / themes.

**Panda CSS** — CSS-in-JS-движок с разделением `tokens` и `semanticTokens`; режим записан внутрь
значения (`base` / `_dark`).

**Open Props** — набор готовых CSS-переменных-примитивов без семантики и компонентов.

**`@theme`** — директива Tailwind v4, объявляющая переменные, порождающие utility-классы. Модификатор
`inline` подставляет значение ссылки, а не саму ссылку, и без него тема не переключается.

**Пространство имён Tailwind (namespace)** — префикс переменной темы, определяющий, какие утилиты она
порождает: `--color-*`, `--text-*`, `--spacing-*`, `--radius-*`, `--shadow-*`, `--breakpoint-*`,
`--ease-*` и другие.

**Трансформ (transform)** — функция Style Dictionary, меняющая имя или значение токена при выводе:
`name/kebab`, `size/pxToRem`, `color/css`.

**Permutation** — в Terrazzo: одна комбинация контекстов резолвера, выводимая в собственный
CSS-селектор.

**`outputReferences`** — режим компилятора, при котором семантический токен выводится как
`var(--примитив)`, а не как готовое значение. Требует переобъявления всей цепочки в блоках режимов.

## Проверки и качество

**Правило трёх компонентов** — значение становится общим токеном, когда его используют три и более
компонента.

**Закон убывающей отдачи (Nathan Curtis)** — чем больше компонентов в системе, тем выше стоимость
каждого следующего и ниже его ценность.

**Бритва Оккама для систем** — число компонентов, цветов, стилей текста и теней должно быть
необходимым минимумом.

**Магическое значение (magic value)** — размер или цвет, записанный литералом в компоненте вместо
токена.

**Карточка стиля (style card)** — 10–15 строк с hex-значениями, шрифтом, кеглями, радиусом и размерами
плотности, которые передаются генератору изображений вместо JSON токенов. →
`05-anti-patterns-and-pipeline.md` §5.

**`usage` / `rules` / `doNotUse` / `alternatives`** — поля расширения с правилами применения токена для
языковой модели. Формат `org.primer.llm` у GitHub Primer; в эталонной схеме — `org.ui-research.llm`.

**Модальность правила** — три уровня в тексте `rules`: `MUST use for…` (нарушение ломает доступность),
`RECOMMENDED default for…` (выбор по умолчанию), `Use for…` (обычное применение); запрет —
`Do NOT use for…` с причиной.
