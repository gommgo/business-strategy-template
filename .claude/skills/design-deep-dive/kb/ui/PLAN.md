# План ресёрча UI: визуальный слой веб-сервисов

Дата старта: 22 сентября 2026. Оркестратор: Fable 5.1. Исполнители: Opus-агенты, 3–4 на волну, 3 волны и синтез.
Соседний проект: `../ux/` (UX: структура, навигация, сценарии, состояния, доступность). Этот проект
покрывает только визуальный слой: цвет, типографика, отступы, размеры, форма, глубина, сетка и раскладка,
визуальные спецификации компонентов, дизайн-токены, стили, оценка визуального качества.

## Зачем

Строится система генеративного дизайна: нейросети (генерация картинок, Blender, кодогенерация) под управлением
агента Fable проектируют и собирают интерфейсы веб-сервисов. Агенту нужна база, из которой он за несколько минут
возьмёт готовые правила и числа: как построить палитру из одного цвета бренда, какую шкалу шрифтов и отступов взять
для админки или личного кабинета, какие радиусы и тени, какой ширины сайдбар, как всё это записать в токены и как
проверить результат. Читатель базы: ИИ-агент (и человек, который его настраивает).

## Рамки

В фокусе:
- веб-сервисы: админские и бэк-офисные приложения, клиентские приложения (личные кабинеты, SaaS, сервисы с
  авторизацией), их визуальный слой на десктопе и при адаптации к мобильным экранам;
- цвет (палитры, шкалы, семантические роли, тёмная тема, контраст), типографика (шрифты для интерфейсов, включая
  кириллицу, шкалы размеров, интерлиньяж, веса), отступы и размеры (сетка 4/8, плотность, высоты контролов, цели
  нажатия), форма и глубина (радиусы, границы, тени, слои), сетка и раскладка (брейкпоинты, ширины, каркасы
  приложений, анатомия страниц в числах), визуальные спецификации компонентов, дизайн-токены и архитектура тем,
  сравнительный атлас дизайн-систем, визуальные стили и тренды 2024–2026, ошибки нейросетей в визуальном UI и
  способы управления генераторами, чек-листы и автоматические проверки, рецепты для агента;
- терминология UI на русском и английском (глоссарий).

Вне фокуса: лендинги и маркетинговые сайты; UX-логика (структура, навигация, сценарии, состояния, тексты, доступность
как процесс) — она в `../ux/`, сюда попадают только визуальные величины (контраст, размеры целей,
брейкпоинты); брендинг как айдентика (логотипы, фирменный стиль); иллюстрация как искусство; нативная мобильная
разработка. Где темы пересекаются с `ux`, ссылаться на её папки, а не дублировать.

## Структура папки

```
ui-research/
  README.md                       ← точка входа: как пользоваться, выжимка, карта файлов (после синтеза)
  PLAN.md                         ← этот файл: цели, волны, статус
  00-glossary/                    ← сводный глоссарий терминов UI (RU/EN); собирается из глоссариев разделов
  01-color/                       ← цветовые модели, палитры и шкалы, семантические роли, тёмная тема, контраст, инструменты
  02-typography/                  ← шрифты для UI (в т.ч. кириллица), шкалы размеров, интерлиньяж, веса, ритм, OpenType
  03-spacing-sizing/              ← шкала отступов, плотность, высоты контролов, цели нажатия, размеры панелей
  04-shape-elevation/             ← радиусы, границы, разделители, тени, слои и z-index, фокус, слои состояний
  05-layout-grid/                 ← сетки, брейкпоинты, ширины контейнеров, каркасы приложений, анатомия страниц в числах
  06-components-visual/           ← визуальные спецификации компонентов: кнопки, поля, таблицы, карточки, навигация, меню…
  07-iconography-imagery/         ← наборы иконок, толщина штриха, размеры, иллюстрации, аватары, изображения в интерфейсе
  08-motion/                      ← движение как токены: длительности, кривые, пружины, что анимировать, prefers-reduced-motion
  09-design-tokens/               ← архитектура токенов, именование, W3C DTCG, темы и режимы, экспорт в CSS/Tailwind
  10-design-systems-atlas/        ← сравнительная таблица значений реальных дизайн-систем (Material 3, Fluent 2, Polaris, Carbon…)
  11-styles-trends/               ← визуальные стили веб-сервисов, что устарело, тренды 2024–2026, маркеры «нейрослопа» в UI
  12-ai-generated-ui/             ← что нейросети делают плохо и хорошо в визуальном UI, промты для генераторов, инструменты
  13-evaluation-checklists/       ← визуальный QA, рубрики оценки, автоматические проверки (контраст, токены, ритм)
  14-recipes/                     ← пошаговые рецепты для агента: палитра из одного цвета, шкала шрифтов, тёмная тема, пресеты
  90-sources/                     ← сводная библиография с аннотациями
  91-videos/                      ← YouTube: индекс культовых видео, транскрипты, дайджесты правил
  99-raw/                         ← промты агентов, их отчёты, сырые заметки, кэш скачанных статей, утилиты
```

Каждый содержательный файл устроен одинаково: метаданные → «Выжимка для агента» (правила «делай / не делай» с
числами) → детали с уровнем доказательности → частые ошибки (включая ошибки нейросетей) → чек-лист → открытые
вопросы → источники. В каждой папке есть `README.md`: что лежит в файлах и 10-строчная выжимка папки; он пишется
агентом, который папку заполнял.

Уровни доказательности: `[исследование]` (тесты, эксперименты, данные), `[консенсус]` (несколько авторитетных
источников сходятся), `[система]` (так делает конкретная дизайн-система: значение задокументировано, но это выбор
одной команды), `[мнение]` (один автор), `[спорно]` (источники расходятся).

### Синтез (оркестратор + 1 агент-аудитор)

Сводная выжимка в README, сводный глоссарий в `00-glossary/`, карта файлов, сверка противоречий между файлами и

## Трек «видео»

Идея: у культовых видео (доклады Config, WWDC, Laracon, каналы практиков, русскоязычные лекции) собрана концентрированная
практика, которой нет в статьях. Утилита `99-raw/tools/yt_transcript.py` ищет видео по YouTube без API, забирает
метаданные (просмотры, лайки, комментарии, главы), топ-комментарии и субтитры (ручные, иначе автоматические на языке
оригинала) без скачивания видео. Видео без субтитров помечаются `NO_SUBTITLES` и откладываются на локальное
распознавание речи. Дайджесты пишутся в том же формате, что и остальные файлы, с таймкодами вместо номеров страниц.

## Правила для агентов (кратко; полные в промтах)

- Читать источники целиком (`99-raw/tools/fetch.py URL` кладёт полный текст в `99-raw/cache/`).
- Первичные источники в приоритете: документация дизайн-систем со значениями, книги, исследования. Каждое важное
  правило подтверждать двумя независимыми источниками или помечать как единичное.
- Каждое правило с числом и условием: «высота контрола 32 px в плотной админке, 40 px в клиентском приложении».
- Не выдумывать источники и значения: цитировать только то, что реально открыто.
- Писать инкрементально: сырые заметки в `99-raw/notes/waveN/X-notes.md` после каждых 3–5 источников.
- Русский язык, плотный справочник без воды. В каждой папке `README.md` с картой файлов и выжимкой.
- Отчёт оркестратору в `99-raw/reports/waveN-X-report.md`.
