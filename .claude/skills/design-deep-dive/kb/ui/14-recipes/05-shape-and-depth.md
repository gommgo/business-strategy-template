# Рецепт 05. Радиусы, границы, тени и токены движения по характеру продукта

Волна 3 · агент I · 22 сентября 2026 · собрано из `04-shape-elevation/`, `08-motion/`

Вход: тип продукта и одно слово о характере («строгий», «дружелюбный», «нейтральный»). Выход: 5–6 радиусов,
одна толщина границы, 3–4 уровня глубины, шкала z-index, набор из 20–41 токена движения. Время: 10 минут.

---

## Шаги

### Шаг 1. Радиусы: одно число задаёт всю шкалу

Держи **4–6 радиусов**, выведенных из одного базового. Больше шести никто не различает.

| Характер | База | Шкала | Кто так |
|---|---|---|---|
| Инструмент, строгий | 0–4 | 0 / 2 / 4 / 6 / full | Carbon (0), GOV.UK (0), Gravity UI (2) |
| Нейтральный, рабочий | **6** | 0 / 2 / 4 / **6** / 8 / full | Primer, Ant seed, Geist, Grafana |
| Клиентский, дружелюбный | 8–10 | 6 / 8 / **10** / 14 / 20 / full | Polaris (8), shadcn (10), cal.com (10) |
| Игривый | 12+ или пилюля | 12 / 16 / 20 / 28 / full | Material 3 |

Практика: доминирующий радиус **4–8 px у 19 продуктов из 24**; по вхождениям 6 px — 25.4 %, 4 px — 22.5 %,
8 px — 17.4 %. Значение 10 доминирует ровно у одного продукта (Cal.com) — то есть дефолт shadcn узнаваем
именно потому, что практикой не подтверждается. Медиана различных радиусов на экране — **3.5**.

Четыре правила формы:

1. **Вложенный радиус = внешний − padding.** Карточка 12 с padding 8 даёт внутреннему элементу 4.
2. **Радиус ≤ 25 % меньшей стороны элемента.** 16 px у контрола высотой 32 — это уже пилюля.
3. **Чем меньше элемент, тем меньше радиус**: бейдж 3–4, кнопка 32 px → 6, карточка → 8–12, модалка → 12–16.
4. **Радиус не меняется вместе с плотностью и темой.** Смена формы читается как смена продукта.

Полностью круглые элементы (аватар, пилюля, переключатель) — отдельный класс, правило вложенности к ним не
применяется. `radius.full` присутствует в любом наборе: 14.8 % элементов практики скруглены полностью.

### Шаг 2. Границы

- **1 px по умолчанию.** У 24 продуктов из 24 и 95.0 % всех вхождений `border-width`.
- **2 px только для фокуса и выбранного состояния** (4.6 % вхождений).
- **Толщина одна на весь интерфейс.** Если поднял границу с 1 до 2 px — осветли цвет, иначе интерфейс
  выглядит «обведённым».
- **Цвет границы контрастирует с обоими фонами**, а не является средним между ними.
- **Граница не меняет габарит в состояниях**: либо `inset box-shadow`, либо `outline` с offset, либо
  прозрачная граница в покое.
- Две силы границ: слабая (разделитель, ≈ 1.1–1.5:1) и сильная (граница контрола).

**Контраст границы контрола — главное расхождение декларации и практики.** WCAG 1.4.11 требует 3:1 (на
белом это `#959595`). Медиана практики — **1.30**, порога достигает 1 продукт из 24 (phpMyAdmin, 5.74);
декларативно держат только Primer (3.45:1) и Polaris (3.06:1). Выбирай режим осознанно и фиксируй в
токенах; `ui_audit.py` поддерживает оба (`--strict-border` включает 3:1).

### Шаг 3. Глубина

**Тень — это заявление «объект над другим».** Если объект ни над чем не находится, тени не нужно.
Медиана практики — **2.5 различных тени на продукт**, у 4 продуктов из 24 теней нет вообще.

| Уровень | Где | Значение (пресет админки) |
|---|---|---|
| 0 | карточка, панель, таблица | тени нет, граница 1 px |
| ring | тонкое кольцо вместо границы | `0 0 0 1px rgb(0 0 0 / .06)` |
| raised | меню, поповер, дропдаун | `0 0 0 1px rgb(0 0 0 / .06), 0 1px 2px rgb(0 0 0 / .08), 0 4px 8px -2px rgb(0 0 0 / .08)` |
| overlay | модалка, дровер, тост | `0 0 0 1px rgb(0 0 0 / .06), 0 8px 16px -4px rgb(0 0 0 / .12), 0 16px 32px -8px rgb(0 0 0 / .12)` |

Правила:

1. **Один источник света на страницу**: у всех теней одинаковое отношение X к Y (обычно X = 0).
2. **При росте высоты растут offset и blur, падает прозрачность.** Blur ≈ **2 × вертикального смещения**.
3. **Минимум два слоя на уровень**: key (короткая, резкая) и ambient (дальняя, мягкая); плюс кольцо 1 px.
   Так у Material 3 (0.3 и 0.15), Fluent, Tailwind, Radix (кольцо во всех шести уровнях).
4. **Цвет тени берётся из оттенка фона**, а не чистый чёрный.
5. **5–6 уровней максимум.** Material 2 с 25 уровнями — исторический избыток.
6. **Скрим модалки** 32–50 % чёрного в светлой теме, 60–75 % в тёмной. Radix — исключение: 5.9 %, но у него
   многослойная тень и кольцо.
7. **`backdrop-filter`** — не больше двух элементов на экран, всегда с непрозрачной подложкой под текстом
   (на бете iOS 26 замеряли 1.5:1 при требуемых 4.5:1) и с веткой `prefers-reduced-transparency`.

### Шаг 4. z-index

Шкала из 9 значений, числа в компонентах не пишутся:

```
0 base · 10 raised · 100 sticky · 1000 dropdown · 1100 app-bar
1200 drawer · 1300 modal · 1400 toast · 1500 tooltip
```

Выше 1500 не поднимаются: если что-то должно лежать выше тултипа, это ошибка раскладки. В измерениях живых
продуктов встречаются `z-index` 100000 и 999999999; у половины выборки есть значения ≥ 9999.

Всплывающие слои рендерятся в портал, а не борются с контекстами наложения (`transform`, `filter`,
`opacity < 1` создают новый контекст).

### Шаг 5. Фокус

- `:focus-visible`, а не `:focus`.
- **`outline` 2 px + `outline-offset` 2 px**, контраст изменения ≥ 3:1.
- Вдавленное внутрь кольцо 2 px не проходит SC 2.4.13 — нужно 3 px. Кольцо внутрь применяется там, где
  элементы примыкают вплотную (таблица, сегментированная группа, плотный тулбар).
- **Не заменяй `outline` на `box-shadow` без запасного варианта**: в `forced-colors` `box-shadow`
  принудительно `none`. При этом у **7 продуктов из 24 кольцо сделано именно `box-shadow`**, поэтому
  проверка должна смотреть на оба свойства.
- Двухцветное кольцо (тёмное + светлое) решает проблему любого фона. GOV.UK делает это жёлтым фоном с
  чёрной подчёркивающей полосой 4 px.
- Кольцо не должно обрезаться предком с `overflow`.

### Шаг 6. Движение по характеру

Шести длительностей хватает на продукт: **0, 100, 150, 200, 300, 400 ms**. Дефолт 150 ms. Измерения:
150 + 200 + 300 ms покрывают **70 %** всех переходов в вебе (1576 объявлений на 24 продуктах); всё, что
длиннее 300 ms, — 1.4 %.

Четыре кривые: standard `cubic-bezier(0.4, 0, 0.2, 1)`, entrance `(0, 0, 0.2, 1)`, exit `(0.4, 0, 1, 1)`,
linear. Роли: **вход тормозит, выход ускоряется, перемещение внутри экрана симметрично, цикл линеен.**
Выход оверлея короче входа на 50–100 ms; у hover правило обратное (приход 125 ms, уход 450 ms).

| Параметр | Пресет А: админка | Пресет Б: клиентский сервис |
|---|---|---|
| Дефолт | **100 ms** | **150 ms** |
| Потолок | 200 ms (скрим 250) | 400 ms (онбординг 600) |
| Кривых | 2 | 4 |
| Пружин | 0 | 1 (переключатель) |
| Масштаб появления | нет (1) | 0.95 |
| Смещение появления | 4 px поповер, 0 остальное | 4 px мелкое, 8 px блоки |
| Стаггер | нет | 20 ms, до 15 элементов |
| Переходы страниц | нет | fade 150 ms |
| Перелёт | нет | до 5 %, точечно |
| Токенов движения | 20 | 41 |

Каталог по элементам (пресет А): hover строки таблицы **70 ms**, hover кнопки 100, pressed 100,
**фокус 0 ms**, поповер вход 150 / выход 100, модалка 150/150, дровер 200/150, аккордеон 200 через
`grid-template-rows: 0fr → 1fr`, вкладки без анимации, тост 200/150, спиннер 1 s linear, скелетон 1.8 s,
подсветка изменившегося 1500 ms, сортировка и обновление данных — **без анимации**.

Что анимировать: **только `transform` и `opacity`** (плюс цвет на малых площадях). Бюджет кадра 16.6 ms при
60 fps. Одно-два свойства на переход. Поповер растёт из триггера (`transform-origin`), масштаб появления
95 → 100 %, а не 80 → 100 %.

### Шаг 7. Сокращённое движение

`prefers-reduced-motion` — Baseline с января 2020; отсутствие поддержки в 2026 году — дефект, а не
недоработка. Принцип **«reduce, not remove»**: MDN в собственном примере заменяет `pulse` (scale 0.9…1.1)
на `dissolve` и при этом **увеличивает** длительность с 1 s до 4 s.

```css
@media (prefers-reduced-motion: reduce) {
  :root {
    --motion-duration-slow: 150ms; --motion-duration-slower: 150ms; --motion-duration-slowest: 150ms;
    --motion-translate-sm: 0px; --motion-translate-md: 0px;
    --motion-scale-in: 1; --motion-stagger-step: 0ms;
    /* плюс все составные токены переходов */
  }
}
```

Оставлять: `opacity`, цвет, размытие. Убирать: перемещение, масштаб, вращение, параллакс, автозапуск,
стаггер, пружины (перелёт — пространственное движение). **Не писать `* { transition: none !important }`**:
ломает `transition-delay`, нужные затухания и компоненты, снимающие состояние по `transitionend`.
Реализовывать переопределением токенов, а не правками в компонентах.

Ни один продукт из 24 измеренных не объявляет отдельных длительностей при reduced motion — это дыра
практики, а не решённая задача.

## Типичные ошибки

1. **«Радиус на всё»**: `border-radius: 8px` и у карточки, и у строки таблицы, и у разделителя, и у иконки.
2. **Радиусы из разных систем в одном макете**: 6 (Ant) у кнопок, 12 (Material) у карточек, 2 (Carbon) у
   бейджей.
3. **Огромные радиусы в админке**: 16–24 px у контролов 32 px.
4. **Вложенные радиусы «на глаз»**: 12 снаружи, 10 внутри при padding 8 (должно быть 4).
5. **Граница + тень + смена фона одновременно** у каждой карточки.
6. **Тень уровня «модалка» у обычной карточки** (`0 25px 50px -12px` внутри плотной таблицы).
7. **Неоновое свечение** (`box-shadow: 0 0 20px акцент`) вместо тени — маркер генерации без задачи.
8. **Blur без offset** даёт свечение; **blur меньше offset** даёт второй прямоугольник под элементом.
9. **`z-index` произвольными числами** (45, 1001, 9999, 99999).
10. **`outline: none` без замены** — провал SC 2.4.7.
11. **Фокус-кольцо цвета акцента на фоне того же акцента.** Проверяется к фону вокруг элемента при
    положительном offset, к самому элементу — при отрицательном.
12. **Кольцо фокуса, обрезанное `overflow: hidden`.**
13. **`transition: all`** — анимируются `height` и `width`, которых не планировали.
14. **`transition-duration: 0.3s` везде** — самое частое значение из обучающих данных (Bootstrap, старый
    Material), но не современных систем.
15. **`animate-bounce` / `animate-pulse` / `animate-ping` из Tailwind на боевых элементах.**
16. **`scale(1.05)` на hover карточки** — ломает выравнивание соседей; не встречается ни в одной системе.
17. **Анимация появления при прокрутке (scroll reveal)** — паттерн лендинга, в приложении за авторизацией
    не встречается; плюс нарушает SC 2.2.2 и 2.3.3.
18. **Отсутствие блока `prefers-reduced-motion`** при двадцати анимациях.
19. **Глобальный `!important`-выключатель движения** вместо замены пространственного на непространственное.
20. **Анимация фокуса** — кольцо «выезжает», это мешает при навигации с клавиатуры.
