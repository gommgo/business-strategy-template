# Рецепт 03. Типографическая шкала и выбор шрифта

Волна 3 · агент I · 22 сентября 2026 · собрано из `02-typography/`

Вход: тип продукта и язык интерфейса. Выход: гарнитура, 6–7 размеров, 12–15 ролей, набор весов и трекингов,
CSS-скелет. Время: 15 минут, если брать готовый пресет; 40 минут, если нужна другая гарнитура.

**Не изобретай шкалу.** Готовые пресеты лежат в `../02-typography/02-type-scale.md` §7 (плотная админка,
база 14) и §8 (клиентский сервис, база 16), продублированы в рецепте 11. Этот рецепт нужен, когда пресет
приходится менять: другая гарнитура, другая база, другой язык.

---

## Шаги

### Шаг 1. Выбрать базу: 14 или 16

| База | Когда | Кто так делает |
|---|---|---|
| **14 px** | админка, бэк-офис, таблицы на 8+ колонок, дашборд, инструмент оператора | Carbon productive, Fluent 2 web Body 1, Ant seed, Atlassian body |
| **16 px** | личный кабинет, SaaS для конечного пользователя, всё, что открывают с телефона | Material 3 body-large, Radix Themes, Mantine md, Carbon expressive |
| 13 px | только сверхплотные таблицы; Polaris опускается до 13 | Polaris |
| 12 px | не база, но второй по частоте кегль в практике (4 продукта из 24) | GitHub, GitLab, tldraw, Redmine |

Практика: база 14 px у **14 продуктов из 24 (58 %)**; три кегля 14 / 12 / 16 покрывают **77 %** всего
текста на экране.

### Шаг 2. Выбрать гарнитуру

Порядок проверок, по убыванию важности:

1. **Кириллица.** Если 80 % текста русский, шрифт выбирается по качеству кириллицы, а не по популярности.
   Безопасны: **Golos Text, IBM Plex Sans, PT Sans, Commissioner**. Эксперты type.today не рекомендуют
   кириллицу Inter, Roboto, Manrope, Fira Sans, Source Sans 3, Open Sans (жирные веса), Overpass, Oswald.
   **Совсем без кириллицы**: Poppins, Public Sans, Lato, DM Sans, Space Grotesk, Outfit, Sora, Figtree,
   Instrument Sans, Albert Sans, Schibsted Grotesk, Gabarito, Bricolage Grotesque. Plus Jakarta Sans и
   Hanken Grotesk имеют только `cyrillic-ext` — для русского не годятся.
2. **x-height ≥ 0.52 em** при базе 14 (≥ 0.50 при базе 16).
3. **Веса 400, 500 (или 550), 600 (или 650).** Веса 100–300 в интерфейсе не используются.
4. **Табличные цифры.** У Roboto, IBM Plex Sans, PT Sans, Noto Sans, Open Sans, Nunito Sans, Source Sans 3,
   Ubuntu Sans цифры уже равной ширины; у **Inter, Golos Text, Onest, Geist, Manrope, Montserrat, Rubik**
   нужен `font-variant-numeric: tabular-nums`. **Commissioner и Wix Madefor Text нельзя ставить в числовые
   таблицы вообще**: цифры пропорциональные и фичи `tnum` в шрифте нет.
5. **Различимость `Il1` и `0O`** на 12 px. У Inter лечится `ss02`/`cv05`/`cv08`, но в субсетах Google Fonts
   этих фич нет.
6. **Лицензия** OFL или эквивалент, самостоятельный хостинг.
7. **Переменный формат** выгоден от трёх весов.

Тестовая строка, вскрывающая всё сразу:
`Шхуна «Ёж» ждёт: 0O Il1 — №5 ₽1 234,56`

Системный стек — бесплатный вариант (Radix Themes, Ant, Mantine, Tailwind v4): цена — разный вид на
Windows, macOS и Android и гуляющие вертикальные метрики.

### Шаг 3. Собрать ряд размеров

Разрешённый ряд для интерфейса: **11, 12, 13, 14, 16, 18, 20, 24, 28, 32, 36, 40**. Размеров должно быть
**5–7**, ролей 8–15. Не ставь 15, 17, 19, 21, 22, 23 px: соседние ступени различаются минимум на 2 px.

Если шкалу нужно вывести с нуля — формула Ant Design (единственная полностью открытая и простая):

```
размер(i) = round_to_even(base * e^(i/5))          # e^(1/5) ≈ 1.2214
интерлиньяж(px) = размер + 8                        # то есть ratio = (размер + 8) / размер
```
Для базы 14: 12/20, 14/22, 16/24, 20/28, 24/32, 30/38, 38/46.

Коэффициент между соседними ступенями: **1.2–1.33 сверху, 1.1–1.17 снизу**. Одинаковый коэффициент по всей
шкале — признак теоретической шкалы.

### Шаг 4. Интерлиньяж

| Что | Ratio | Правило |
|---|---|---|
| тело | **1.4–1.5** | Material, Carbon, Fluent, Atlassian — все 14/20 = 1.43 |
| плотная ячейка таблицы | 1.28–1.33 | 14/18 |
| заголовки | **1.1–1.3**, убывает с ростом кегля | 20/28 = 1.4, 24/32 = 1.33, 32/40 = 1.25 |
| подписи 11–12 px | **1.33–1.6**, растёт при уменьшении кегля | 11/16 = 1.45, 12/16 = 1.33 |
| однострочные лейблы, кнопки, бейджи | 1.0–1.25 | 12/12, 14/20 |

Простейшая формула: `line-height(px) = кегль + 8` (для плотных таблиц `+6`, для длинного чтения `+10`).
**Все значения — целые пиксели, кратные 4** (допустимо 2 для 14/18).

Практическое требование к шкале: `кегль × ratio` должно давать целое. В эталонной схеме отношения подобраны
именно так: 11 × 1.454545 = 16, 14 × 1.428571 = 20, 12 × 1.333333 = 16. В CSS интерлиньяж выведен шестизначным
отношением, округлённым вверх: `1.428572` для 20 / 14. Браузер усекает высоту строки до шага 1/64 px, и
отношение, округлённое к ближайшему (`1.428571` → 19,98 px), как и точная дробь `calc(20 / 15)`, на части пар
теряет шаг. Округление до 1.43 даёт 20.02 px и ломает ритм на длинных списках.

**Задавай `line-height` явно везде, где задал `font-size`.** Проверено прогоном примеров: если у блока с
`font-size: 12px` не переопределить интерлиньяж, он унаследует `1.428572` от `body` и даст 17.14 px.

### Шаг 5. Трекинг

| Диапазон кеглей | Трекинг |
|---|---|
| 11–12 px | +0.01…+0.02 em |
| 14–16 px (тело) | **0** |
| 20–32 px | −0.01…−0.015 em |
| 36–60 px | −0.02…−0.025 em |
| капс-лейблы | +0.05…+0.1 em |

Значения **не переносятся между гарнитурами**: в коде MUI прямо написано, что трекинг рассчитан под Roboto
и при другой гарнитуре ломает кернинг. Предел отрицательного трекинга проверяется словом «ухо»: уменьшай,
пока буквы не соприкоснулись; предыдущее значение — предел.

В DTCG трекинг записывается **в px на каждую роль**, потому что `em` в типе `dimension` не поддерживается:
−0.01em при 20 px = −0.2px, при 32 px = −0.64px.

### Шаг 6. Веса и уровни цвета

Три веса: **400** (тело), **500** (лейблы, кнопки), **600** (заголовки). 700 — редкий акцент. Практика:
400 несёт 69.6 % текста, 500 — 15.5 %, 600 — 8.7 %, 700 — 4.2 %; 300 — 0.3 %.

Заголовки от 28 px не тяжелее 600: крупный размер сам даёт иерархию. Доля текста весом ≥ 600 на экране —
не больше 20 %.

Уровней цвета текста четыре: primary, secondary, tertiary, disabled. Порядок применения при построении
иерархии: **сначала цвет, потом вес, только потом размер.**

### Шаг 7. Роли

Роль = именованная комбинация размера, интерлиньяжа, веса и трекинга. Ролей больше, чем размеров: 14/400
body и 14/600 card-title — один размер и две роли.

Минимальный набор для приложения (15 ролей пресета админки): caption, caption-strong, helper, label, code,
body-compact, body, body-strong, button, card-title, section, page-title, page-title-lg, metric, metric-lg.

### Шаг 8. Перевод шкалы на другую гарнитуру

При одном `font-size` визуальный размер разных шрифтов отличается **до 13 %**: измеренный x-height
Source Sans 3 — 0.486 em, Inter — 0.546 em. Пересчёт:

```
новый_кегль = старый_кегль × (x_height_старой / x_height_новой)
```
округлить до ближайшей ступени ряда, затем пересобрать интерлиньяж по правилу `кегль + 8` и заново подобрать
трекинг под новую гарнитуру.

### Шаг 9. Локализация

- Короткие надписи при переводе EN → RU шире в **1.4–1.5 раза** («Save» 4 знака против «Сохранить» 9);
  абзацы шире на **13–18 %**. Ширины кнопок, вкладок и заголовков колонок проектируй по русскому тексту:
  `min-width`, а не `width`.
- Кириллическая строчная шире латинской на 12–20 % в том же шрифте: PT Sans 1.120, Golos Text 1.128,
  Inter 1.147, IBM Plex Sans 1.173, Roboto 1.196.
- Только **Sentence case**. Title Case в русском — орфографическая ошибка.
- Кавычки «ёлочки», длинное тире U+2014, короткое U+2013 в диапазонах, минус U+2212, буква «ё»,
  неразрывные пробелы, `1 234 567,89 ₽` через `Intl.NumberFormat('ru-RU')`, множественное число через
  `Intl.PluralRules` (4 формы).
- `lang="ru"` на `<html>` обязателен: без него не работают `hyphens: auto`, `locl` и кавычки в `<q>`.

### Шаг 10. Загрузка

`font-display: swap` + метрический фолбэк (`size-adjust`, `ascent-override`, `descent-override`,
`line-gap-override`); латиница и кириллица разведены по `unicode-range`; знаки `№` U+2116 и `₽` U+20BD
входят в собранное подмножество.

## Выход

```css
:root {
  --font-sans: 'Golos Text', system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif;
  --font-mono: 'JetBrains Mono', ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;

  --text-caption:       0.6875rem/1rem;    /* 11/16 */
  --text-helper:        0.75rem/1rem;      /* 12/16 */
  --text-body-compact:  0.875rem/1.125rem; /* 14/18 */
  --text-body:          0.875rem/1.25rem;  /* 14/20 */
  --text-section:       1rem/1.5rem;       /* 16/24 */
  --text-page-title:    1.25rem/1.75rem;   /* 20/28 */
  --text-page-title-lg: 1.5rem/2rem;       /* 24/32 */
  --text-metric:        1.75rem/2rem;      /* 28/32 */
}
```

В DTCG роль — составной токен `typography` с `lineHeight` **числом**, а не размером (требование стандарта).

## Типичные ошибки

1. **Пятнадцать размеров вместо шести.** Признак: в CSS есть 13, 15, 17, 19, 21, 22, 23 px.
2. **Смешение шкал из разных систем** в одном файле: рядом 18 и 22 px без роли для каждого.
3. **`text-3xl` (30 px) для H1 админки.** Системы дают 20–24 px.
4. **`font-size` в `px` вместо `rem`.** Ломает системное укрупнение и зум 200 % (WCAG 1.4.4).
5. **`clamp()` на теле и лейблах приложения.** Fluid type придуман для маркетинга.
6. **Одинаковый интерлиньяж на всех размерах** (`line-height: 1.5` глобально): заголовок 32 px получает
   48 px и распадается на строки.
7. **`leading-relaxed` на заголовке и `leading-tight` на абзаце** — перепутанные утилиты Tailwind.
8. **`tracking-tight` на всём подряд**, включая подпись 11 px.
9. **Отсутствие `max-width` у абзацев**: на 1440 px строка вырастает до 150 знаков.
10. **Перенос шкалы при смене гарнитуры без пересчёта по x-height.**
11. **Забытые табличные цифры.** Самая частая типографическая ошибка сгенерированной таблицы: в статике
    почти незаметна, при обновлении данных видна сразу.
12. **Стек `font-family: Inter, sans-serif` без подключённого `@font-face`**: страница отрисуется системным
    гротеском, и вся настроенная шкала уедет.
13. **Поля ввода 14 px на мобильной ширине.** iOS Safari зумит страницу при фокусе.
14. **Наследованный интерлиньяж у блока с переопределённым кеглем** — даёт 17.14 px (см. шаг 4).
