# 14-recipes — пошаговые рецепты для агента-генератора

Волна 3 · агент I · 22 сентября 2026

Одиннадцать рецептов: от брифа до проверенного экрана. Каждый устроен одинаково — **вход → шаги с числами
и формулами → выход → проверки → типичные ошибки → ссылки на разделы базы**. Значения не изобретаются:
они собраны из папок 01–10 и помечены ссылкой на источник.

## Выжимка папки

1. **Порядок работы: 09 → 01 → 02 → 03 → 04 → 05 → 08 → 06 → 07 → 10.** Сначала бриф и семь ручек, затем
   цвет, затем шкалы, затем выпуск токенов, затем каркас и компоненты, затем цикл проверки.
2. **Решений семь, а не двести.** Акцент, нейтраль, радиус, плотность, шрифт, тени, тема. Остальные 184
   семантических токена выводятся из пресета (рецепт 09, 11).
3. **Пресетов четыре**, каждый внутренне согласован: плотная админка (база 14, контрол 32, строка 36,
   радиус 6), личный кабинет B2C (16 / 40 / 48 / 10), SaaS-дашборд (14 / 36 / 40 / 8), внутренний
   инструмент в тёмной теме (13 / 28 / 28 / 4). Смешивать значения пресетов нельзя (рецепт 11).
4. **Палитра строится в OKLCH из одного hex** по лестнице светлот и кривой хромы, с обязательной
   контрастной коррекцией: на ступени 600 зелёный, янтарный, бирюзовый и жёлтый не проходят 4.5:1
   (рецепт 01).
5. **Тёмная тема — не инверсия**: фон OKLCH L 13–19 %, поверхностей минимум три с шагом 7–9 п.п., текст
   проверяется по APCA, акцент светлее на 0.06–0.12 L, hover идёт вверх, тени остаются, а кольцо меняет
   полярность (рецепт 02).
6. **Правка всегда возвращается в токены, а не в компоненты.** Иначе через три итерации набор и интерфейс
   расходятся (рецепты 08, 09).
7. **Генератору картинок отдают карточку стиля на 10–15 строк с hex**, кодогенератору — сами токены и
   требование использовать только `var(--*)`; тогда нарушение видит линтер, а не глаз (рецепт 09).
8. **Цикл проверки начинается с раскладки, а не с цвета**: каркас → `max-width` → центрирование → сетки →
   правило внутреннего и внешнего → тени → стили → sticky → ширины → и только потом цвет и иконки
   (рецепт 10).
9. **Машинный прогон — фильтр, а не вердикт.** `ui_audit.py` закрывает 81 проверку (55–66 на прогон); иерархия,
   осмысленность метрик, «ложное дно» и вкус остаются глазам (рецепт 10).
10. **Семь собранных экранов лежат в `examples/`** и прогнаны через `ui_audit.py`: 1488 OK, 1 FAIL,
    74 информативных. Единственный FAIL — находка по эталонной схеме токенов, а не дефект примера.
    > Разрешение противоречия [C34] (22.09.2026): после правки схемы прогон даёт 1489 OK, 0 FAIL,
    > 74 информативных. См. `../CONTRADICTIONS.md`.

## Как пользоваться

```
Есть бриф?           → 09-design-brief.md (квиз → семь ручек)
Нужен пресет целиком → 11-presets.md (выбрать один из четырёх, не смешивать)
Нужен цвет           → 01-palette-from-brand-color.md, затем 02-dark-theme.md
Нужны шкалы          → 03-type-scale-and-font.md, 04-spacing-density-sizes.md, 05-shape-and-depth.md
Нужно выпустить      → 08-tokens-export.md
Нужен экран          → 06-app-shell-and-pages.md (каркас), 07-component-specs.md (компоненты)
Нужно проверить      → 10-review-loop.md, затем ../13-evaluation-checklists/
```

Инструменты: `../../scripts/lib/color.py` (контраст, OKLCH, CVD), `build_reference_tokens.py` (генератор схемы
и проверок), `ui_audit.py` (визуальный QA страницы), `measure_ui.py` (снятие распределений с живого сайта).
