# Рецепт 02. Тёмная тема из светлой

Волна 3 · агент I · 22 сентября 2026 · собрано из `01-color/04-dark-theme.md`, `09-design-tokens/03`

Вход: готовая светлая тема (рецепт 01). Выход: блок переопределений семантического слоя, объявленный на том
же элементе, что и светлая тема. Время: 10 минут скриптом, 20 минут на проверку по APCA.

**Главное правило: тёмная тема не инверсия.** Проверено на Radix: ступень 9 в светлой и тёмной одинакова
(`blue9 #0090ff` в обеих), ступени 1–8 уходят вниз, 10–12 вверх, величина сдвига по светлоте меняется от
−80 до +58 п.п. Геометрия при этом не меняется вовсе: во всех 8 измеренных парах «светлая / тёмная»
радиусы, отступы, высоты и число теней совпали до значения.

---

## Шаги

### Шаг 1. Фон

Целевой коридор **OKLCH L 13–19 %** по декларациям, **14.1–18.3 %** по измерениям шести из восьми продуктов
с тёмной темой. Чистый чёрный есть только у Vercel Geist.

| Система | hex | OKLCH L |
|---|---|---|
| Material | `#121212` | 18.2 % |
| Radix slate1 | `#111113` | 17.9 % |
| Primer | `#0D1117` | 17.6 % |
| Ant | `#141414` | 19.1 % |
| shadcn | `#0a0a0a` | 14.5 % |
| Tailwind gray-950 | `#030712` | 13.0 % |

Хрому фона можно взять **вдвое больше**, чем в светлой теме: на тёмном она заметна слабее.

### Шаг 2. Поверхности: минимум три уровня, шаг больше, чем в светлой теме

```
bg.canvas        = L 0.16
bg.subtle        = L 0.16 + 0.018
bg.surface       = L 0.16 + 0.035
bg.surface-raised= L 0.16 + 0.070
```

Material: светлая 90/92/94/96/98/100 (шаг 2 тона), тёмная 4/10/12/17/22 (шаг 2–6 тонов). В эталонной схеме
шаг светлой темы 1.6–3.2 п.п., тёмной — 7–9 п.п.

Два уровня вместо трёх — самая частая ошибка: поповер поверх модалки сливается с ней.

### Шаг 3. Текст: считать по APCA, не по WCAG

WCAG 2 систематически завышает контраст в тёмной теме. Проверено: `#9198A1` на `#0D1117` даёт
WCAG 6.50:1 (отлично) и APCA Lc −45.8 (ниже минимума Lc 60). Обратный пример: `#777777` на чёрном —
WCAG 4.69:1 (проходит AA), APCA Lc −30.6 («еле разобрать»).

```
text.primary   = find_L_for_apca(target = -90, bg = canvas)   # ≈ L 0.93..0.96
text.secondary = find_L_for_apca(target = -62, bg = canvas)   # ≈ L 0.76..0.78
text.tertiary  = find_L_for_apca(target = -45, bg = canvas)   # ≈ L 0.64..0.68
text.disabled  = find_L_for_apca(target = -30, bg = canvas)   # ≈ L 0.52..0.56
```

Чистый белый текст не используется ни у одного измеренного продукта, кроме Gravity UI. Практика:
`#ededed`, `#edeef0`, `#e4e4e7`, `#d4d4d4`, `#ccccdc`.

**Проверяй текст на каждой поверхности, а не только на `bg.canvas`.** Найдено прогоном примеров:
`fg.tertiary` `#90a1b9` даёт 5.56:1 на `bg.surface` `#1d293d` и всего **3.94:1** на `bg.surface-raised`
`#314158` — то есть на модалке третичный текст перестаёт проходить 4.5:1. То же у `danger.text` `#ff6467`
на `#314158` (3.59:1). Пара «текст × приподнятая поверхность» в проверках эталонной схемы отсутствует.

> Разрешение противоречия [C13] (22.09.2026): в эталонной схеме `fg.tertiary` тёмной темы переведён на neutral-350 `#aebccf` (5.37:1 на `surface-raised`), `accent.text` на accent-300 `#8ec5ff` (5.71), `danger.text` на red-300 `#ffa2a2` (5.40); пары «текст × raised» добавлены в проверки генератора. См. `../CONTRADICTIONS.md`.

### Шаг 4. Границы

```
border.subtle  = rgba(255,255,255, 0.08)
border.default = rgba(255,255,255, 0.12)
border.strong  = find_L_for_wcag(target = 3.0, bg = bg.surface)   # сплошной цвет, не альфа
```

Альфа белого удобна тем, что одно значение работает на любой поверхности. Цена: контраст границы
1.26–1.48:1, чего недостаточно для поля ввода. Поэтому `border.strong` — сплошной цвет с проверкой 3:1.

### Шаг 5. Акцент и сплошные заливки

**Акцент в тёмной теме светлее на 0.06–0.12 L, хрома −10…−20 %.** Material: primary = тон 40 в светлой,
тон 80 в тёмной. Hover идёт **вверх** по светлоте, а не вниз.

```
accent.solid       = oklch(clamp(L + 0.09, 0, 0.85), C * 0.9, H)
accent.solid-hover = shift_L(accent.solid, +0.05)          # СВЕТЛЕЕ
accent.text        = oklch(0.76, min(C * 0.75, max_chroma(0.76, H)), H)
accent.bg          = oklch(0.27, min(C * 0.55, max_chroma(0.27, H)), H)
fg.on-accent       = (L(accent.solid) > 0.70) ? bg.canvas : "#ffffff"
```

Последняя строка критична: `#ffffff` на кнопке, прописанный литералом, ломается в тёмной теме. В эталонной
схеме `accent.solid` = accent-600 `#155dfc` + белый (5.25:1) в светлой и accent-400 `#51a2ff` +
neutral-950 (7.64:1) в тёмной.

### Шаг 6. Статусы

Десатурировать и поднять по светлоте. Radix dark red11 = `#ff9592` (пастельный) против light red11 =
`#ce2c31`.

```
FOR status IN [success, warning, danger, info]:
    status.text   = oklch(0.76, min(C * 0.75, max_chroma(0.76, H)), H)
    status.bg     = oklch(0.26, min(C * 0.50, max_chroma(0.26, H)), H)
    status.border = oklch(0.42, min(C * 0.65, max_chroma(0.42, H)), H)
    status.solid  = oklch(min(L + 0.08, 0.85), C * 0.9, H)
```

Единственная запрещённая пара: **насыщенный красный на тёмном фоне** — для протанопии контраст «greatly
diminished».

### Шаг 7. Глубина, скрим, состояния

- **Тени не выключать.** Ни один из восьми измеренных продуктов с тёмной темой не убирает тени: число
  теней совпадает со светлой темой до значения. Меняется другое: кольцо становится **белым с альфой 0.10**
  (чёрное кольцо на тёмном холсте невидимо), альфа ключевой и рассеянной тени растёт с 0.08 до 0.40–0.50.
- **Скрим сильнее**: 0.60–0.75 против 0.32–0.50 в светлой.
- **Альфа состояний выше примерно в полтора раза**: hover 0.04 → 0.06, active 0.08 → 0.12 (Carbon: 0.12 в
  светлых темах, 0.16 в тёмных).
- **Графики — отдельный набор.** Один набор не может держать 3:1 и к белому, и к `#0f172b`.

### Шаг 8. Переключение

```css
:root { color-scheme: light dark; /* светлая тема */ }

@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { color-scheme: dark; /* тёмная тема */ }
}
:root[data-theme="dark"] { color-scheme: dark; /* та же тёмная тема */ }
```

Три обязательных условия:

1. **`color-scheme: light dark`**, иначе скроллбары, чекбоксы по умолчанию и календарь останутся светлыми.
2. **Блок режима объявляется на том же элементе, что и светлая тема** (`:root`). Пользовательское свойство
   наследуется уже вычисленным: тема на `<body>` при семантике на `:root` не сработает. Подтверждено
   документацией Tailwind и Terrazzo независимо.
3. **Блок режима содержит весь транзитивный список изменившихся токенов**, а не только явные
   переопределения. Список надо вычислять, а не писать руками.

Переключатель — три состояния (светлая, тёмная, системная), по умолчанию системная. Инлайн-скрипт до
первого рендера, иначе вспышка светлой темы.

`light-dark()` экономит половину объявлений, но ломается, как только появляется третий режим (высокий
контраст, второй бренд).

## Выход

Блок `@media (prefers-color-scheme: dark) :root:not([data-theme="light"])` плюс близнец
`:root[data-theme="dark"]` — 60 переопределённых токенов в эталонной схеме. В DTCG это
`$extensions.<ns>.modes.dark` внутри токена (так делают Primer через `org.primer.overrides` и Carbon через
`carbon.themes`) либо отдельный набор в Resolver Module.

## Проверки

| Порог | Чем |
|---|---|
| `L(bg.canvas)` ∈ [0.13, 0.22] | `color.py oklch` |
| `L(bg.surface) − L(bg.canvas)` ≥ 0.025, уровней ≥ 3 | то же |
| `|apca(text.secondary, bg.canvas)|` ≥ 60 | `color.py contrast` |
| `|apca(text.disabled, bg.surface)|` ∈ [30, 60] | `ui_audit.py` I1c |
| Каждый текстовый токен ≥ 4.5:1 **на каждой поверхности**, включая `surface-raised` | `ui_audit.py --scheme dark` |
| `wcag(border.strong, bg.surface)` ≥ 3.0 | `color.py contrast` |
| `L(accent.solid_dark) − L(accent.solid_light)` ∈ [0.06, 0.12] | `color.py oklch` |
| `fg.on-accent` переключён (тёмный, если `L(accent.solid) > 0.70`) | сравнение |
| Hover идёт вверх по светлоте | `ui_audit.py --hover --scheme dark`, проверка S2 |
| Нет пары «насыщенный красный на фоне темнее L 0.25» | `color.py cvd protan` |
| Кольцо тени белое с альфой, тени не выключены | `ui_audit.py` D1, D2 |
| Геометрия совпадает со светлой темой до значения | сравнить JSON двух прогонов |
| `color-scheme` объявлен | `ui_audit.py` (в отчёте блока нет, проверяется грепом) |

Прогон одной командой:

```bash
python3 ../../scripts/ui/ui_audit.py URL --scheme both --tokens tokens.json --out ./audit
```

## Типичные ошибки

1. **`filter: invert(1)` или свап ступеней 50 ↔ 950.** Чистый чёрный фон, чистый белый текст, оба за
   коридорами; фотографии и бренд ломаются.
2. **Проверка контраста только по WCAG.** Даёт формально проходящие, но нечитаемые серые.
3. **Два уровня поверхностей.** Поповер поверх модалки сливается.
4. **Тени оставлены как в светлой теме.** Невидимы и продолжают раздувать CSS; нужно менять полярность
   кольца и альфу.
5. **Тени выключены совсем.** Практика их не выключает; глубина добавляется светлотой, тени остаются.
6. **`dark:bg-gray-900 dark:text-white` на всё подряд.** Один уровень поверхности, чистый белый текст,
   границы не переопределены.
7. **`dark:border-gray-800` при `dark:bg-gray-900`.** Разница светлот 6 п.п., граница почти не видна и при
   этом выглядит сплошной.
8. **Тёмный набор неполный:** часть компонентов наследует светлые значения и вспыхивает белым при
   переключении. Лечится транзитивным замыканием списка.
9. **Статусные цвета скопированы из светлой темы.** Тёмно-зелёный `success` на тёмном фоне нечитаем.
10. **Переключатель без состояния «системная».** Пользователь теряет синхронизацию с ОС.
11. **Тёмная тема по умолчанию для массового продукта.** Исследования: «in users with normal vision, light
    mode leads to better performance most of the time»; исключение — помутнение хрусталика.
12. **Третичный текст на приподнятой поверхности.** Проверено: падает до 3.94:1 (см. шаг 3). Исправлено в
    схеме 22.09.2026 ([C13]).
