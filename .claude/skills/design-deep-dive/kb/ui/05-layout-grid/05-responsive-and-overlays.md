## Выжимка для агента

1. **Пять приёмов адаптации, а не один** (Fluent 2): reposition, resize, reflow, show/hide, re-architect
   `[S5]`. «Просто сжать» — это только resize, и его почти никогда не хватает. → §1.1 `[система]`
2. **Порог 1024: сайдбар сворачивается.** Порог 768: сайдбар только оверлеем, панель складывается над или
   под контентом. Порог 640: одна колонка, модалки становятся листами. → §2.5 `[консенсус]`
3. **Ширина сайдбара-оверлея на узком экране `min(320px, 90 %)`** (Atlassian) `[S1]`. Измеренная практика:
   GitLab 312 (80 %), Matomo 300, остальные — 100 % ширины экрана `[S13]`. → §2.1 `[спорно]`
4. **Правая панель уходит в оверлей раньше сайдбара** — при 1280, а не при 1024: она ближе к контенту по
   приоритету и её отсутствие менее болезненно. → §2.2 `[мнение]`
5. **Шапка приложения почти не меняет высоту при сужении.** Измерено: уменьшается только у GitHub
   (72 → 64), Stripe Docs (112 → 64) и Plausible (80 → 65); у остальных остаётся той же `[S13]`. На 390 px
   это 48 (Ant Pro, shadcn, GitLab), 52 (Discourse), 64–65 (GitHub, Stripe Docs, Redmine). → §2.3
   `[измерение]`
6. **Нижняя панель вкладок 48–56 — только при 3–5 разделах и ширине < 640.** Material: navigation bar на
   compact `[S4]`. Выше 640 нижняя панель мешает. → §2.4 `[система]`
7. **Проектируй до 320 CSS px.** WCAG 1.4.10: без двумерной прокрутки при 320 px ширины и 256 px высоты;
   320 CSS px = вьюпорт 1280 при зуме 400 % `[S6]`. → §4.5 `[стандарт]`
8. **Таблица на узком экране: приоритетные колонки, карточки или горизонтальная прокрутка с закреплённой
   первой колонкой.** «Хорошего метода нет» `[S8]`; WCAG прямо разрешает двумерную прокрутку таблицам
   данных `[S6]`. → §3.2 `[спорно]`
9. **Две колонки → одна при < 768**, три → две при < 1024, и это делается через `minmax`, а не через
   медиазапросы. → §3.1 `[консенсус]`
10. **Форма на мобильном: одна колонка, поля во всю ширину, кегль поля 16 px** (иначе iOS зумит страницу
    при фокусе). → §3.3, `../02-typography/02-type-scale.md` §8 `[консенсус]`
11. **Поля страницы на мобильном 16**, цели нажатия 44–48, шаг между целями ≥ 8
    (`../03-spacing-sizing/02-density.md` §4). → §4.1 `[стандарт]`
12. **`100vh` равен `100lvh`**: при развёрнутых панелях браузера контент частично скрыт. Для полноэкранных
    слоёв бери `100svh` или `100dvh` `[S7]`. → §4.3 `[стандарт]`
13. **`env(safe-area-inset-*)` работает только при `viewport-fit=cover`** в метатеге viewport `[S7]`.
    Прилипшие полосы добавляют инсет к своему padding, а не к margin. → §4.2 `[стандарт]`
14. **Нет hover — нет информации.** Всё, что показывалось при наведении (действия строки, тултипы,
    флайауты), на тач должно иметь постоянный или тапабельный эквивалент. → §4.4 `[консенсус]`
15. **Модалки: 400 (подтверждение) / 560–640 (форма) / 800–960 (большая)** — значения волны 1 §5.5.
    Потолок `90vw × 85vh`. → §5.1 `[система]`
16. **Модалка по вертикали: 100 px от верха или по центру.** Ant по умолчанию `top: 100px`, вариант
    `centered` — через `vertical-align: middle` `[S9]`. → §5.1 `[система]`
17. **Ant ограничивает модалку `calc(100vw − 32px)`, а ниже 576 px — `calc(100vw − 16px)` с полями 8** —
    единственное найденное точное правило для узкого экрана `[S9]`. → §5.1 `[система]`
18. **Дроверы 400–560 или `min(560px, 40vw)`; на мобильном 100 %.** Ant задаёт дроверу `max-width: 100vw`
    `[S9]`. → §5.2 `[система]`
19. **Поповер 240–320, отступ от триггера 4–8.** Primer `control.overlay.offset` = 4; в примерах Radix
    `sideOffset={5}` `[S10]`, `[S11]`. → §5.3 `[система]`
20. **Выпадающее меню: `min-width` = ширине триггера.** Radix отдаёт для этого CSS-переменную
    `--radix-popover-trigger-width` `[S11]`. → §5.3 `[система]`
21. **Максимальная высота выпадающего списка — оставшееся место**, а не фиксированное число: Radix даёт
    `--radix-popover-content-available-height` `[S11]`. Практический потолок 240–320. → §5.3 `[система]`
22. **Порядок стратегий позиционирования: `offset` → `flip` → `shift`** `[S10]`. Менять порядок нельзя:
    `shift` должен работать после `flip`. → §6.1 `[система]`
23. **Значения по умолчанию Floating UI: `offset` mainAxis 0, `flip` по обеим осям, `shift` только по
    главной оси, лимитер не подключён** `[S10]`. → §6.1 `[система]`
24. **Значения по умолчанию Radix Popover: side "bottom", sideOffset 0, align "center", avoidCollisions
    true, collisionPadding 0, sticky "partial"** `[S11]`. `collisionPadding: 0` означает, что слой прилипнет
    вплотную к краю окна: задайте 8–16. → §6.2 `[система]`
25. **Тултип max-width 240–320, отступ 4–8, задержка 300–500 мс**; на тач тултипов нет. → §5.4 `[система]`
26. **Тосты 320–400 фиксированной ширины, отступ от края 16–24, зазор 8–12; на мобильном
    `calc(100vw − 32px)`** — значения волны 1 §5.7. → §5.5 `[система]`
27. **Командная палитра 560–640, сверху 10–20 % высоты окна** — это `[практика]`: cmdk не задаёт размеров
    вообще, они полностью на стороне потребителя `[S12]`. → §5.6 `[практика]`
28. **Модалка на узком экране становится листом** (полноэкранным или с верхним отступом): shadcn ниже `md`
    (768) заменяет сайдбар на Sheet `[S3]`, Primer превращает сайдбар в `position: fixed; 100vw × 100vh`
    `[S2]`. → §7 `[система]`

## 1. Как адаптируется приложение

### 1.1. Пять приёмов

Классификация Fluent 2 `[S5]`, единственная найденная полная:

| Приём | Что делает | Пример в приложении |
|---|---|---|
| **Reposition** | переставить элементы | действия шапки уезжают в меню «ещё»; сайдбар становится нижней панелью |
| **Resize** | изменить размеры и поля | поля 32 → 24 → 16; сайдбар 280 → 56 |
| **Reflow** | перетечь: N колонок → M | дашборд 4 колонки → 2 → 1; форма 2 колонки → 1 |
| **Show/hide** | показать или скрыть | скрыть неприоритетные колонки таблицы; скрыть описание страницы |
| **Re-architect** | перестроить структуру | список + детали превращаются в список, детали открываются отдельной страницей |

Типичная ошибка — использовать только **resize**: всё сжимается пропорционально, сайдбар превращается в
180 px, таблица в нечитаемую сетку. Правильная последовательность при сужении: сначала **resize** полей,
потом **show/hide** второстепенного, потом **reflow** колонок, и только потом **re-architect**.

Apple HIG формулирует ограничение на re-architect `[S14]`: «**не меняй функциональность** в зависимости от
занимаемого места; меняй **объём видимой** функциональности. Используй большее пространство, чтобы
переключиться с tab bar на сайдбар или вынести наружу то, что иначе было бы в overflow-меню».

### 1.2. Что решается медиазапросами, а что нет

| Уровень | Инструмент |
|---|---|
| Каркас: число панелей, сайдбар, нижняя навигация | **медиазапросы** (`@media`), порог по вьюпорту |
| Поля страницы и гаттеры | **медиазапросы** |
| Компонент, живущий и в контенте, и в панели | **container queries** (`@container`) |
| Сетка карточек | `repeat(auto-fill, minmax(280px, 1fr))` — без запросов |
| Каркас «сайдбар + контент» в простом случае | flex-рецепт с `min-inline-size: 50%` |
| Плотность | `@media (pointer: coarse)`, **не** ширина окна |

Последнее — правило волны 1 (`../03-spacing-sizing/02-density.md` §8.2): тач-ноутбук с шириной 1440 это не
десктоп, и цели нажатия у него должны быть 44, а не 24.

## 2. Каркас при сужении

### 2.1. Сайдбар

| Ширина окна | Состояние сайдбара | Подтверждение |
|---|---|---|
| ≥ 1280 | развёрнут, 240–288 | измеренная практика `[S13]` |
| 1024–1279 | развёрнут; можно свернуть вручную | Atlassian: встроен в поток при ≥ 1024 `[S1]` |
| 768–1023 | **автоматически сворачивается** в рейку 48–72 или в оверлей | Atlassian: «при вьюпорте меньше 1024 сайдбар автоматически сворачивается и открывается оверлеем» `[S1]` |
| < 768 | **только оверлей**, ширина `min(320px, 90 %)` | Atlassian `[S1]`; shadcn: сайдбар `md:flex`, ниже — Sheet `[S3]` |

Как именно уезжает сайдбар, по системам:

| Система | Механика |
|---|---|
| Polaris | `transform: translateX(-100%)` у `position: fixed` навигации; открывается как оверлей `[S16]` |
| shadcn/ui | режим `offcanvas`: `margin-left: calc(var(--sidebar-width) * -1)`; на мобильном — компонент `Sheet` шириной 288 `[S3]` |
| Primer | `responsiveVariant="fullscreen"`: `position: fixed; width: 100vw; height: 100vh; z-index: 999` `[S2]` |
| Atlassian | оверлей поверх контента со скримом, ширина `min(320px, 90 %)` `[S1]` |
| Material 3 | modal navigation drawer (поверх) вместо standard rail `[S4]` |

Измеренная практика на 390 × 844 `[S13]`: **сайдбар превращается в полноэкранный оверлей 390 px у 7
продуктов из 11** (Ant Pro, GitHub, shadcn, Redmine, Stripe Docs, cal.com и другие), **у трёх просто
исчезает**; у GitLab оверлей **312** (80 %), у Matomo — **300**. То есть правило Atlassian
`min(320, 90 %)` соблюдают меньше трети измеренных продуктов; большинство делает оверлей полноэкранным.
Отдельное наблюдение того же измерения: **высота кнопки на мобильном не меняется у 7 продуктов из 11**,
то есть «на мобильном всё крупнее» в живых продуктах чаще не выполняется.

Разрешение противоречия: **полноэкранный оверлей проще** (не нужен скрим и обработка тапа мимо), **оверлей
на 90 % лучше** (видна полоска контента, понятно, что панель временная, и её можно закрыть тапом мимо).
Для нового продукта — второй вариант.

### 2.2. Правая панель

| Ширина окна | Состояние | Подтверждение |
|---|---|---|
| ≥ 1280 | встроена в поток, 320–400 | §7.1 файла 02: при 1280 и сайдбаре 280 панель 400 оставляет контенту 552 |
| 1024–1279 | оверлей поверх контента | Atlassian: при < 1024 панель начинает накладываться на main `[S1]` |
| 768–1023 | оверлей на всю высоту | — |
| < 768 | **складывается над или под контентом** | Primer: порядок регионов через CSS-переменные — header 0, pane-start 1, content 2, pane-end 3, footer 4 `[S2]` |

Правило приоритета: **правая панель уходит раньше сайдбара**. Сайдбар — навигация, без неё нельзя
переключиться; панель — дополнение к текущему объекту, её отсутствие переживается легче.

Значения ширины панели по брейкпоинтам у Primer `[S2]`:

| Ширина окна | `small` | `medium` | `large` |
|---|---|---|---|
| < 768 | 100 % (над/под контентом) | 100 % | 100 % |
| ≥ 768 | 240 | 256 | 256 |
| ≥ 1012 | **256** | **296** | **320** |

### 2.3. Шапка

Шапка приложения — единственная зона каркаса, которая **не меняет высоту** при сужении. Измеренные высоты
на 390 px `[S13]`: 48 (Ant Pro, shadcn, GitLab, Matomo), 52 (Discourse), 56, 64 (GitHub, Redmine, Stripe
Docs), 65 (Plausible). То есть тот же диапазон 48–64, что и на десктопе.

Что меняется внутри шапки:

| Элемент | ≥ 1024 | 640–1023 | < 640 |
|---|---|---|---|
| Логотип | полный | полный | знак без текста |
| Поиск | поле 240–400 | поле 200 или иконка | **иконка**, раскрывается на весь ряд |
| Пункты навигации (каркас C) | все | часть + «Ещё» | **бургер** |
| Действия | 2–3 кнопки | 1 кнопка + меню | иконка меню |
| Аватар | 24–32 + имя | 24–32 | 24–32 |

Carbon формулирует это одним правилом `[S15]`: «ссылки шапки на узких экранах переезжают в боковое меню».

### 2.4. Нижняя панель вкладок

| Параметр | Значение | Источник |
|---|---|---|
| Высота | **48–56** плюс safe-area-inset-bottom | Material navigation bar; `../03-spacing-sizing/03-control-and-panel-sizes.md` §5 |
| Число разделов | **3–5** | Material: navigation bar для compact `[S4]` |
| Когда применять | ширина < 640, разделов 3–5, приложение открывают с телефона регулярно | `[S4]` |
| Когда не применять | разделов больше 5; ширина ≥ 640; редкие мобильные сессии | — |

Material 3 задаёт соответствие «брейкпоинт → компонент навигации» `[S4]`:

| Брейкпоинт | Навигация |
|---|---|
| Compact (< 600) | navigation bar снизу или модальная развёрнутая рейка |
| Medium (600–839) | свёрнутая navigation rail (однопанельная) или navigation bar (двухпанельная) |
| Expanded / Large / Extra-large (≥ 840) | свёрнутая или развёрнутая navigation rail (standard или modal) |

Стоимость нижней панели: 56 px плюс инсет (на iPhone 34 px) = **90 px** из 844, то есть 10 % высоты
экрана постоянно занято. Вместе с шапкой 56 это 17 %.

## 3. Контент при сужении

### 3.1. Колонки

Правило: **число колонок выводится из минимальной ширины карточки, а не из брейкпоинта**.

```css
.grid { display: grid; gap: 16px; grid-template-columns: repeat(auto-fill, minmax(280px, 1fr)); }
```

При gap 16 и минимуме 280 получается: 4 колонки от 1204 px, 3 от 904, 2 от 576, 1 ниже 576. Проверять
арифметикой: `n × 280 + (n − 1) × 16 ≤ ширина`.

Раскладки 2/3 + 1/3 и 1/2 + 1/2 схлопываются в одну колонку **при < 768**. Порядок при схлопывании:

| Раскладка | Что идёт первым на мобильном |
|---|---|
| Контент 2/3 + свойства 1/3 | **контент**, свойства под ним (или в аккордеоне) |
| Список + детали | **список**, детали отдельной страницей |
| Форма + предпросмотр | **форма**, предпросмотр под ней или по кнопке |
| Дашборд 4 KPI + графики | **KPI**, графики под ними |

Primer делает это переопределяемым: порядок регионов задан CSS-переменными (header 0, pane-start 1,
content 2, pane-end 3, footer 4), и панель можно поставить и над контентом, и под ним `[S2]`.

### 3.2. Таблицы

Честная оценка `[S8]`: «на смартфоне большая таблица не работает, хорошего метода нет». Варианты и их цена:

| Приём | Как | Когда | Цена |
|---|---|---|---|
| **Горизонтальная прокрутка** с закреплённой первой колонкой | `overflow-x: auto`, первая колонка `position: sticky; left: 0` | много колонок, все важны | WCAG разрешает таблицам двумерную прокрутку `[S6]`, но сравнивать неудобно |
| **Приоритетные колонки** (show/hide) | скрывать по списку приоритета при каждом пороге | есть явный приоритет колонок | часть данных не видна |
| **Строка → карточка** | `display: block` у `tr`, лейбл через `::before` с `data-*` | мало колонок (3–5), строк много | вертикаль растёт в 3–5 раз |
| **Перевёрнутые шапки** | `display: flex` у таблицы, `thead` слева, `tbody` прокручивается | 2–6 записей, много полей | расходится визуальный и DOM-порядок `[S17]` |
| **Сводка + детали** | в списке 2–3 поля, остальное по тапу | много колонок, приоритет один | лишний переход |

Для варианта «строка → карточка» есть техника без магических ширин `[S17]`: `tr` делается
`display: grid`, `td` — `display: contents`, колонка лейблов получает `max-content`, и ширина колонки
лейблов сама равна самому длинному лейблу. Оговорка автора: `display: contents` имеет проблемы с
доступностью, проверять в целевых браузерах.

### 3.3. Формы

| Параметр | Десктоп | Мобильный |
|---|---|---|
| Число колонок | 1 (2 для коротких связанных полей) | **всегда 1** |
| Ширина формы | 480–640 | `100 % − 2 × 16` |
| Ширина поля | по ожидаемой длине значения | **100 %**, кроме совсем коротких (год, код) |
| Кегль поля | 14–16 | **16** (иначе iOS зумит при фокусе) |
| Высота контрола | 32–40 | **44–48** |
| Между полями | 12–20 | 16 |
| Кнопки | в потоке или sticky-футер | **sticky-футер во всю ширину**, кнопка 44–48 |

Правило «кегль поля 16 px на мобильном» — из пресета волны 1 (`../02-typography/02-type-scale.md` §8:
«поля ввода наследуют 16 px — автозум iOS не срабатывает»).

### 3.4. Дашборд

| Ширина | Раскладка |
|---|---|
| ≥ 1280 | KPI 4 в ряд, графики 2 в ряд, таблица во всю ширину |
| 1024–1279 | KPI 4 в ряд (карточка 240–260), графики 2 в ряд |
| 768–1023 | KPI **2 × 2**, графики по одному |
| < 768 | всё в одну колонку; KPI 2 в ряд при ширине карточки ≥ 160 |
| < 400 | KPI по одному |

Дашборд — единственный тип страницы, где **вертикальная прокрутка на мобильном неизбежна и нормальна**:
требование «один экран» `[S18]` выполнимо только на десктопе.

### 3.5. Карточки

| Ширина окна | Карточка |
|---|---|
| ≥ 1280 | 280–400, padding 16–24 |
| 768–1279 | 280–360, padding 16–24 |

## 4. Мобильные величины

### 4.1. Базовые числа

| Параметр | Значение | Источник |
|---|---|---|
| Поля страницы | **16** | `../03-spacing-sizing/01-spacing-scale.md` §6.1; Material compact 16 dp `[S4]`; Carbon margin 16 `[S15]` |
| Минимальная цель нажатия (WCAG 2.2 AA) | **24 × 24** CSS px | `../03-spacing-sizing/02-density.md` §4.1 |
| Рекомендуемая цель на тач | **44–48** | там же §4.2 |
| Зазор между целями | ≥ 8 | там же |
| Кегль полей ввода | **16** | `../02-typography/02-type-scale.md` §8 |
| Высота шапки | 48–64 | измерено `[S13]` |
| Высота нижней панели | 48–56 + инсет | §2.4 |
| Ширина оверлея-сайдбара | `min(320px, 90 %)` или 100 % | §2.1 |

### 4.2. Безопасные зоны

`env(safe-area-inset-top | right | bottom | left)` — отступы под вырез камеры, скруглённые углы и системные
полосы. **Работает только при `viewport-fit=cover`** в метатеге `[S7]`:

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

Правило применения: инсет **добавляется к собственному padding элемента**, а не задаётся как margin:

```css
.app-header  { padding-top:    calc(12px + env(safe-area-inset-top, 0px)); }
.bottom-nav  { padding-bottom: calc(8px  + env(safe-area-inset-bottom, 0px)); }
.sheet       { padding-bottom: calc(16px + env(safe-area-inset-bottom, 0px)); }
.page        { padding-inline: calc(16px + env(safe-area-inset-left, 0px)); }
```

Типичные значения на iPhone с вырезом: top 44–59, bottom 34, left/right 0 в портрете и 44–59 в ландшафте.
Полагаться на конкретные числа нельзя, только на `env()` с фолбэком `0px`.

### 4.3. Единицы высоты вьюпорта

Правила из MDN `[S7]`:

| Единица | Что значит | Когда |
|---|---|---|
| `vh` = **`lvh`** | большой вьюпорт (панели браузера скрыты) | десктоп; **на мобильном контент частично скрыт** под панелями |
| `svh` | малый вьюпорт (панели развёрнуты) | полноэкранные слои: гарантированно влезает, но при скрытии панелей остаётся полоса |
| `dvh` | динамический | подстраивается, но «может вызывать изменение размеров во время прокрутки, что ухудшает интерфейс и бьёт по производительности» |

Рабочее правило:

```css
.shell   { height: 100dvh; }            /* каркас: пересчёт незаметен, прокрутки нет */
.sheet   { max-height: 85svh; }         /* лист снизу: гарантированно влезает */
.modal   { max-height: min(85vh, 85dvh); }
.overlay-full { min-height: 100svh; }
```

### 4.4. Отсутствие hover

Всё, что на десктопе появляется по наведению, на тач-устройстве недоступно. Перечень и замены:

| Десктоп | Тач |
|---|---|
| Действия строки таблицы по hover | **всегда видимая** иконка меню в строке или свайп |
| Тултип | подпись рядом, иконка «i» с тапом или ничего |
| Флайаут свёрнутого сайдбара (Atlassian: раскрывается по наведению `[S1]`) | тап раскрывает оверлей |
| Подсветка строки | подсветка при тапе (`:active`) плюс граница выбранной строки |
| Превью по наведению | тап открывает предпросмотр |

Определять надо по `@media (hover: hover)`, а не по ширине: «hover-интерфейс» на тач-ноутбуке работает,
но неудобен, а на планшете — не работает совсем.

### 4.5. Нижняя граница: 320 CSS px

WCAG 2.2, SC 1.4.10 Reflow (AA) `[S6]`: контент отображается **без двумерной прокрутки** при ширине,
эквивалентной **320 CSS px**, и при высоте **256 CSS px**.

Ключевое: **320 CSS px = вьюпорт 1280 CSS px при зуме 400 %**. То есть это требование не про телефоны, а
про увеличение на десктопе, и оно закрывает оба случая сразу.

Исключения, где двумерная прокрутка допустима: изображения, нужные для понимания (карты, схемы), видео,
игры, презентации, **таблицы данных** (но не отдельные ячейки), интерфейсы, где тулбар обязан оставаться
видимым при манипуляции контентом.

Не требуется схлопывать всё в одну колонку: пример-«pass» из документа W3C — двухколоночное сравнение
версий кода, где каждая колонка влезает в 320 px, а между колонками работает горизонтальная прокрутка.

## 5. Размеры всплывающих поверхностей

Все числа — из волны 1 (`../03-spacing-sizing/03-control-and-panel-sizes.md` §5.5–5.7), здесь добавлены
только позиционирование и поведение при сужении.

### 5.1. Модалки

| Назначение | Ширина | Высота |
|---|---|---|
| Подтверждение, короткий вопрос | **400** | по контенту |
| Стандартная форма | **560–640** | `min(600px, 85vh)`, тело со скроллом |
| Крупная форма, таблица внутри | **800–960** | то же |
| Полноэкранная | 100 % при узком окне | 100 % |

Ограничения по вьюпорту:

| Правило | Значение | Источник |
|---|---|---|
| Максимальная ширина | `calc(100vw − 32px)` (при базовом margin 16) | исходник Ant `[S9]` |
| Максимальная ширина ниже 576 px | `calc(100vw − 16px)`, поля `8px auto` | исходник Ant `[S9]` |
| Максимальная высота | `min(600px, 85vh)` | волна 1 §5.5 |
| Практический потолок | 90vw × 85vh | практика |

**Вертикальное положение** — единственное найденное точное значение системы: Ant Design по умолчанию
ставит модалку `position: relative; top: 100px; margin: 0 auto`, то есть **100 px от верхнего края окна**;
вариант `centered` реализован через псевдоэлемент высотой 100 % и `vertical-align: middle`, при этом у
самой модалки `top: 0` `[S9]`.

Практическое правило: **короткая модалка (подтверждение) — по центру, высокая (форма) — с фиксированным
отступом сверху 80–120**. Центрированная высокая модалка «прыгает» при изменении высоты содержимого,
модалка с фиксированным верхом — нет.

Маска (скрим): `position: fixed; height: 100%`, цвет `rgb(0 0 0 / .32)` в плотном пресете и `.48` в
клиентском (волна 1 §8.4, §9.4). У Ant есть вариант `mask-blur` с `backdrop-filter: blur(4px)` `[S9]`.

### 5.2. Дроверы

| Вид | Ширина | Позиция |
|---|---|---|
| Узкий (детали записи) | **400** | справа, на всю высоту |
| Стандартный (форма) | **480–560** | справа |
| Широкий (редактор) | **640–720** | справа |
| Адаптивный | `min(560px, 40vw)` | справа |
| Нижний лист (мобильный) | 100 % ширины, высота по контенту до `85svh` | снизу |
| На мобильном | **100 %** | справа или снизу |

Ant задаёт обёртке дровера `position: absolute; max-width: 100vw` и отдельную тень для каждой стороны
(`boxShadowDrawerLeft/Right/Up/Down`); секция дровера — `display: flex; flex-direction: column; width: 100%;
height: 100%; overflow: auto` `[S9]`. Последнее важно: **прокручивается тело дровера, а не страница под
ним**.

Когда дровер, а когда модалка `[V09 B 02:03]`: «если форма занимает мало полей при большом пространстве,
бери модалку вместо выезжающей панели». Дровер оправдан, когда содержимое высокое (список, длинная форма,
история) или когда нужно видеть контекст страницы.

### 5.3. Поповеры и меню

| Элемент | Ширина | Прочее |
|---|---|---|
| Выпадающее меню | 160–280, **`min-width` = ширине триггера** | высота пункта 32/40, padding контейнера 4 сверху и снизу |
| Поповер | **240–320** (Primer small 320, xsmall 192) | padding 16 (condensed 8) |
| Комбобокс со списком | **= ширине поля**, `max-height` 240–320 | пункт 32 |
| Отступ от триггера | **4** (Primer `control.overlay.offset`), в примерах Radix 5 | `[S10]`, `[S11]` |

Radix отдаёт CSS-переменные, из которых собираются размеры `[S11]`:

```css
.popover-content {
  width: var(--radix-popover-trigger-width);              /* ширина = ширине триггера */
  max-height: var(--radix-popover-content-available-height); /* остаток до края окна */
  transform-origin: var(--radix-popover-content-transform-origin);
}
```

Это точнее, чем фиксированный `max-height: 320px`: список подстраивается под реальное оставшееся место, а
дальше прокручивается.

## 6. Позиционирование слоёв

### 6.1. Порядок стратегий

Floating UI `[S10]` задаёт порядок middleware, который стал стандартом де-факто (на нём работают Radix,
shadcn, MUI, Mantine):

```
offset → flip → shift
```

«`offset()` обычно ставится первым в массиве». Смысл порядка: сначала отодвинуть слой от триггера, потом
перевернуть на противоположную сторону, если не влезает, и только потом сдвинуть вдоль края.

Значения по умолчанию `[S10]`:

| Middleware | Параметр | По умолчанию |
|---|---|---|
| `offset` | `mainAxis` (расстояние до триггера) | **0** |
| `offset` | `crossAxis` | 0 |
| `offset` | `alignmentAxis` | `null` |
| `flip` | `mainAxis` | `true` |
| `flip` | `crossAxis` | `true` |
| `flip` | `fallbackAxisSideDirection` | `'none'` |
| `flip` | `fallbackStrategy` | `'bestFit'` |
| `shift` | `mainAxis` | `true` |
| `shift` | `crossAxis` | **`false`** |
| `shift` | `limiter` | **отсутствует** (`limitShift()` подключается вручную) |

Два значения по умолчанию требуют изменения почти всегда: **`offset.mainAxis: 0`** (слой прилипает к
триггеру, нужно 4–8) и **отсутствие лимитера у `shift`** (слой может «съехать» так, что стрелка окажется
за пределами триггера).

### 6.2. Значения Radix и что менять

Radix `Popover.Content` по умолчанию `[S11]`:

| Проп | По умолчанию | Что ставить |
|---|---|---|
| `side` | `"bottom"` | оставить |
| `sideOffset` | **0** | **4–8** (в примерах документации 5) |
| `align` | `"center"` | `"start"` для меню, `"center"` для тултипа |
| `alignOffset` | 0 | оставить |
| `avoidCollisions` | `true` | оставить |
| `collisionPadding` | **0** | **8–16**, иначе слой прилипнет вплотную к краю окна |
| `arrowPadding` | 0 | 8–12, чтобы стрелка не наезжала на скруглённый угол |
| `sticky` | `"partial"` | оставить |
| `hideWhenDetached` | `false` | `true`, если триггер может уехать при прокрутке |

### 6.3. Слои и порядок

`z-index` и порядок слоёв — в `../04-shape-elevation/02-shadows-layers-depth.md`. Здесь только напоминание
порядка от нижнего к верхнему: контент → прилипшие полосы каркаса → выпадающие меню и поповеры → дроверы →
модалки → тосты → тултипы.

Отдельное правило Carbon `[S15]`: плавающие панели (floating) **не влияют на сетку** и обязаны закрываться
пользователем. То есть слой никогда не сдвигает контент; если содержимое должно сдвинуть контент, это не
слой, а панель каркаса.

## 7. Оверлеи на узком экране

| Слой | Порог | Во что превращается |
|---|---|---|
| Модалка | **< 640** | полноэкранный лист или лист снизу на `85svh` |
| Модалка (Ant) | **< 576** | `calc(100vw − 16px)`, поля `8px auto` `[S9]` |
| Дровер справа | < 640 | 100 % ширины или нижний лист |
| Поповер | < 640 | лист снизу, если содержимое выше 200 px |
| Меню с 5+ пунктами | < 640 | лист снизу (высота пункта 44–48) |
| Тултип | любой тач | не существует |
| Тост | < 640 | низ по центру, `calc(100vw − 32px)` |
| Сайдбар | < 768 | оверлей `min(320px, 90 %)` или 100 % |
| Правая панель | < 768 | складывается над или под контентом |

Правила листа снизу (bottom sheet):

| Параметр | Значение |
|---|---|
| Максимальная высота | `85svh` (не `vh`) |
| Скругление верхних углов | 12–16 |
| Ручка (drag handle) | 32–40 × 4, отступ сверху 8 |
| Нижний padding | `calc(16px + env(safe-area-inset-bottom, 0px))` |
| Прокрутка | внутри листа, страница под ним заблокирована |

## Частые ошибки

1. **Только resize при адаптации**: всё пропорционально сжимается, сайдбар становится 180, таблица
   нечитаемой. Нужны reflow и show/hide.
2. **Сайдбар не сворачивается вообще**: на 1024 контента остаётся 736, при открытой панели 416.
3. **Панель уходит в оверлей позже сайдбара**: пользователь теряет навигацию раньше, чем дополнение.
4. **Шапка «адаптируется» уменьшением высоты** до 36–40 на мобильном: цели нажатия падают ниже 44.
5. **Нижняя панель вкладок при 7 разделах**: пункты по 55 px, подписи не влезают.
6. **Нижняя панель без `safe-area-inset-bottom`**: на iPhone последние 34 px перекрыты системным
   индикатором.
7. **`100vh` у полноэкранного слоя**: на мобильном низ уезжает под панель браузера.
8. **`env()` без `viewport-fit=cover`**: инсеты всегда 0, и это не видно в десктопном браузере.
9. **Таблица просто прокручивается горизонтально без закреплённой первой колонки**: непонятно, к какой
   строке относится ячейка.
10. **Форма с кеглем поля 14 на мобильном**: iOS зумит страницу при фокусе и не возвращает масштаб.
11. **Действия строки только по hover**: на тач-устройстве они недоступны.
12. **`sideOffset: 0`** (значение Radix по умолчанию): поповер прилипает к триггеру без зазора.
13. **`collisionPadding: 0`**: слой прижимается вплотную к краю окна, тень обрезается.
14. **Модалка 960 на экране 1024**: остаётся по 32 px с каждой стороны, скрим не читается.
15. **Высокая модалка по центру**: при изменении высоты содержимого прыгает.
16. **Тост в правом верхнем углу перекрывает первичное действие**, которое только что нажали.
17. **Дровер, прокручивающий страницу под собой** вместо собственного скролла.
18. **Нет проверки на 320 px**: при зуме 400 % на десктопе появляется горизонтальная прокрутка — провал
    WCAG 1.4.10.
19. **Плотность переключается по ширине окна**, а не по `pointer: coarse`: на тач-ноутбуке цели 24 px.
20. **Модалка на мобильном осталась модалкой** шириной 560 при экране 390.

## Чек-лист

1. Применены все нужные приёмы адаптации, а не только resize? Да / нет.
2. Есть порог **1024** (сайдбар сворачивается) и **768** (сайдбар только оверлеем)? Да / нет.
3. Правая панель уходит в оверлей **раньше** сайдбара (при 1280)? Да / нет.
4. Оверлейный сайдбар на узком экране `min(320px, 90 %)` или 100 % — и это решение принято осознанно?
   Да / нет.
5. Шапка приложения сохраняет высоту **48–64** на всех ширинах? Да / нет.
6. Нижняя панель вкладок используется только при 3–5 разделах и ширине < 640? Да / нет.
7. Все прилипшие к краям полосы учитывают `env(safe-area-inset-*)` в своём padding? Да / нет.
8. В метатеге viewport стоит `viewport-fit=cover`? Да / нет.
9. Полноэкранные слои используют `svh` или `dvh`, а не `vh`? Да / нет.
10. Раскладка проверена на **320 CSS px** (или 1280 px при зуме 400 %)? Да / нет.
11. У таблицы на узком экране закреплена первая колонка или выбран другой осознанный приём? Да / нет.
12. Кегль полей ввода на мобильном **16 px**? Да / нет.
13. Цели нажатия на тач **≥ 44**, зазор между ними ≥ 8? Да / нет.
14. Всё, что показывалось по hover, имеет тач-эквивалент? Да / нет.
15. Плотность переключается по `pointer: coarse`, а не по ширине? Да / нет.
16. `sideOffset` у поповеров **4–8**, а не 0? Да / нет.
17. `collisionPadding` **8–16**, а не 0? Да / нет.
18. Порядок стратегий `offset` → `flip` → `shift` соблюдён? Да / нет.
19. Ширина выпадающего меню привязана к ширине триггера? Да / нет.
20. `max-height` списка берётся из оставшегося места, а не задан фиксированно? Да / нет.
21. Модалка не шире `calc(100vw − 32px)` и не выше `85vh`? Да / нет.
22. Высокая модалка имеет фиксированный отступ сверху (80–120), а не центрируется? Да / нет.
23. Модалки на ширине < 640 превращаются в листы? Да / нет.
24. Дровер прокручивает собственное тело, а не страницу под собой? Да / нет.
25. Тост не перекрывает первичное действие страницы? Да / нет.

## Открытые вопросы и противоречия

1. **Ширина оверлейного сайдбара: `min(320, 90 %)` против 100 %.** Atlassian задаёт первое, но 6 из 9
   измеренных мобильных страниц делают оверлей во всю ширину экрана. Исследований, сравнивающих варианты,
   нет.
2. **Порог сворачивания сайдбара: 768 против 1024.** shadcn и Polaris сворачивают на 768, Atlassian на
   1024. Разница объясняется шириной самого сайдбара (256 против 320), но единого правила нет; в этой
   папке принято 1024 как порог автоматического сворачивания и 768 как порог оверлея.
3. **Таблицы на мобильном.** Прямая цитата источника: «хорошего метода нет» `[S8]`. Пять перечисленных
   приёмов — компромиссы, ни один не протестирован количественно.
4. **Командная палитра.** Ни один источник не даёт размеров: cmdk оставляет их потребителю `[S12]`.
   Значения 560–640 и «10–20 % сверху» помечены `[практика]` и требуют проверки.
5. **Вертикальное положение модалки.** Единственное найденное точное значение — Ant `top: 100px` `[S9]`.
   Ни Radix, ни Primer, ни Polaris числа не публикуют; правило «высокая модалка с фиксированным верхом»
   выведено мной.
6. **`dvh` против `svh`.** MDN предупреждает, что `dvh` «может вызывать изменение размеров во время
   прокрутки, что ухудшает интерфейс и бьёт по производительности» `[S7]`, но не даёт порога, за которым
   это становится проблемой.
7. **Позиция тостов.** Правый верх, правый низ и низ по центру встречаются одинаково часто; исследования
   заметности тостов в зависимости от позиции не найдено.
8. **Нижняя панель вкладок в веб-приложении.** Material описывает её для Android; насколько она уместна в
   мобильном вебе (где есть панель браузера снизу), источниками не подтверждено.
9. **Radix Popover: `sticky: "partial"`** — поведение документировано, но без объяснения, чем отличается от
   `"always"` в числах.
