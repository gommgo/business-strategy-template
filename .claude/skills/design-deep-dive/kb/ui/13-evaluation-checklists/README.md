# 13-evaluation-checklists — оценка визуального качества

Волна 3 · агент I · 22 сентября 2026 · внешних источников прочитано целиком: 52

Как проверить готовый интерфейс: единый чек-лист, рубрика с якорями, промт для модели-критика и разбор
инструментов с их порогами и слепыми зонами. Рецепты, по которым интерфейс собирается, — в `../14-recipes/`.

## Выжимка папки

1. **Один чек-лист на всю базу: 117 проверок в 13 группах** плюс 12 проверок, которые делает только
   человек. В папках 01–11 суммарно около 800 пунктов; здесь они сведены, приоритизированы и снабжены
   порогом, способом проверки и серьёзностью.
2. **Серьёзность задаёт порядок починки**: блокер (нарушен норматив A/AA или интерфейс не работает для
   части пользователей) → серьёзно (виден пользователю) → полировка.
3. **Балл не ставится.** «4 из 7» превращает ревью в оценку. Результат — профиль по десяти измерениям плюс
   список нарушенных порогов.
4. **Рубрика: десять измерений, шкала 0–5 с якорями.** Проходной уровень 3 по каждому измерению и 4 по
   контрасту. Веса нужны только при сравнении вариантов.
5. **Потолок вычислимой эстетики — около 50 % дисперсии** (R² .43–.51 у веба, .13–.32 у мобильного), и он
   держится с 2013 года. В работе 2026 года на 12 интерфейсах и 62 участниках ни одна корреляция метрики с
   восприятием не достигла значимости. Метрики — скрининг, не вердикт.
6. **Самый сильный сигнал первого впечатления — низкая визуальная сложность плюс высокая
   прототипичность**, и он работает уже при 17 мс экспозиции.
7. **Универсальная модель без примеров даёт 13 % валидных критик.** Few-shot по визуальному и задачному
   сходству поднимает качество на 55 %. Локализовать дефект модели не умеют: IoU < 0.20 у всех.
8. **axe-core не проверяет 1.4.11, 1.4.10, 2.4.11 и 2.4.13**; `target-size` и `color-contrast-enhanced`
   выключены по умолчанию; градиент под текстом даёт `incomplete`, а не `fail`.
9. **Собственный прогон `../../scripts/ui/ui_audit.py`** закрывает 81 проверка в каталоге, 55–66 на прогон за один запуск: светлая и
   тёмная тема, сокращённое движение, hover, обход табом, эмуляция тача, сверка с набором токенов.
10. **Результат прогона на семи собранных экранах: 1488 OK, 1 FAIL, 74 информативных.** Единственный FAIL —
    находка по эталонной схеме токенов (отключённый элемент даёт APCA Lc 25 в тёмной теме), а не дефект
    примеров.
    > Разрешение противоречия [C34] (22.09.2026): схема исправлена, повторный прогон семи экранов — 1489 OK,
    > 0 FAIL, 74 информативных. См. `../CONTRADICTIONS.md`.

## Инструмент

```bash
python3 ../../scripts/ui/ui_audit.py ПУТЬ_ИЛИ_URL \
  --preset admin --tokens dist/tokens.json \
  --scheme both --reduced-motion --hover --tab 24 --touch \
  --out ./audit --fail-on serious
```

Отчёт пишется в `<out>/<имя>.md` и `<out>/<имя>.json`. `--selftest` проверяет парсеры без браузера.

## Порядок работы

```
1. ui_audit.py (машинная часть)        → 03-automated-checks.md
2. Пять приёмов глазами                → 01-visual-qa-checklist.md, группа В
3. Рубрика 0–5 или модель-критик       → 02-rubrics-and-vlm-critic.md
4. Правки в порядке «каркас → ширины → композиция → стили → цвет» → ../14-recipes/10-review-loop.md
5. Повторить, пока нарушений уровня «блокер» и «серьёзно» нет
```
