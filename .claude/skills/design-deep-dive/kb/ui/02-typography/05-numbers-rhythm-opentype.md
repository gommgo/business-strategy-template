4. **Числа в таблице — по правому краю**, текст — по левому, заголовок колонки — как содержимое.
   → §1.4 `[консенсус]`
5. **Русский формат чисел: пробел разряда (неразрывный узкий), запятая как десятичный разделитель**:
   `1 234 567,89 ₽`. Не `1,234,567.89`. → §1.5 `[консенсус]`
6. **`slashed-zero` (`zero`) для кодов и идентификаторов**, чтобы отличить 0 от O. → §1.6 `[консенсус]`
7. **KPI-числа: 28–40 px, вес 600, трекинг −0.02 em, табличные цифры**; единицы и знак валюты меньше самого
   числа на 1–2 ступени. Atlassian даёт готовые роли `metric.large` 28/32/Bold, `metric.medium` 24/28,
   `metric.small` 16/20 `[S10]`. → §2 `[система]`
8. **Все `line-height` кратны 4 px** — так вертикальный ритм совпадает со шкалой отступов. Material 3 держит
   кратность 4 без исключений `[S5]`; GOV.UK держит кратность 5 под свою сетку `[S8]`. → §3.1 `[система]`
9. **`text-box-trim: trim-both` + `text-box-edge: cap alphabetic` для заголовков** убирает полулидинг и делает
   отступы предсказуемыми. **Baseline с августа 2026** `[S22]` — можно использовать со страховкой для старых
   браузеров. → §3.3 `[система]`
10. **`text-wrap: balance` на заголовках, подписях и коротких блоках** (Chromium применяет к блокам до 6
    строк, Firefox до 10) `[S28]`. → §4.1 `[система]`
11. **`text-wrap: pretty` — только для абзацев, где качество важнее скорости**: «has a negative effect on
    performance» `[S28]`. Не вешай его на всю страницу и не применяй в таблицах и виртуальных списках.
    → §4.2 `[система]`
12. **`text-wrap: stable` для `contenteditable`**: при редактировании строки выше точки правки не
    переливаются `[S28]`. → §4.3 `[система]`
13. **`hanging-punctuation` не Baseline** («does not work in some of the most widely-used browsers») `[S29]` —
    только как прогрессивное улучшение для блоков цитат. → §4.4 `[система]`
14. **`font-optical-sizing: auto` включено по умолчанию** и работает у шрифтов с осью `opsz` (Inter 14–32,
    Roboto Flex 8–144, Nunito Sans 6–12, Literata 7–72). Не отключай без причины. Baseline с марта 2020
    `[S30]`. → §5 `[система]`
15. **`font-variant-*` предпочтительнее `font-feature-settings`**: первое наследуется и комбинируется,
    второе перезаписывает весь набор фич целиком. → §6.1 `[консенсус]`
16. **Лигатуры выключай в коде, идентификаторах и масках ввода**: `font-variant-ligatures: none`.
    Geist Mono 1.7.0 специально убрал программистские лигатуры из `calt` в `ss11` `[S19]`. → §6.3 `[система]`
17. **`-webkit-font-smoothing: antialiased` глобально не включай** (см. `04-weight-hierarchy-color.md` §1.5);
    `text-rendering: optimizeLegibility` в интерфейсе не нужен. → §6.5 `[мнение]`
18. **Кратность 4 px обязательна для интерлиньяжа и отступов, но не для итоговой высоты блока и не для ширин
    контейнеров** (Tim Gabe `[V07]`). → §3.1 `[спорно]`
19. **Знаковый состав для кодов**: перечёркнутый ноль, тройка с плоским верхом, L с крючком, засечки у
    прописной I (Королькова `[V15]`). → §1.6 `[консенсус]`

## 1. Числа

### 1.1. Табличные цифры

`font-variant-numeric: tabular-nums` (фича OpenType `tnum`) делает все цифры одинаковой ширины, чтобы разряды
выстраивались друг под другом в соседних строках.

Официальное описание Inter `[S16]`: «Fixed-width numbers are useful for tabular data, where comparing columns
across rows is desired. `tnum` enables an entire set of dedicated glyphs that have the same width across all
weights.»

Поддержка: `font-variant-numeric` — Baseline «Widely available», во всех браузерах **с января 2020** `[S21]`.

Где применять обязательно:

| контекст | почему |
|---|---|
| числовые колонки таблиц | разряды выравниваются, глаз сравнивает столбиком |
| суммы и цены в списках | то же |
| таймеры, счётчики обратного отсчёта | иначе цифры «прыгают» при каждом тике |
| прогресс в процентах (`42 %` → `43 %`) | не дёргается ширина |
| даты в формате `ДД.ММ.ГГГГ` | колонка не «дышит» |
| номера версий, идентификаторы | предсказуемая ширина |
| значения на осях графиков | подписи не сдвигаются |

Где **не** нужны: одиночное число в заголовке, число внутри предложения («найдено 12 заказов»). Там
пропорциональные цифры выглядят лучше, потому что они отспейсены под соседний текст.

```css
.table-numeric, .timer, .metric { font-variant-numeric: tabular-nums; }
```

### 1.2. У каких шрифтов цифры уже табличные

Измерено по файлам шрифтов с учётом GSUB и GPOS `[S24]`:

| шрифт | цифры равной ширины по умолчанию | есть `tnum` | что делать |
|---|---|---|---|
| Roboto, Noto Sans, Open Sans, Ubuntu Sans | да | да | ничего, но `tnum` не повредит |
| IBM Plex Sans, PT Sans, Nunito Sans, Source Sans 3 | **да** | нет | ничего, `tnum` не нужен |
| Inter, Inter Tight, Golos Text, Onest, Geist, Manrope, Montserrat, Rubik, Fira Sans | нет | да | **обязательно `tabular-nums`** |
| **Commissioner, Wix Madefor Text** | нет | **нет** | **в числовых таблицах не использовать** |
| JetBrains Mono, Geist Mono, IBM Plex Mono, Roboto Mono | да (моноширинные) | нет | ничего |

Способ проверить шрифт самостоятельно: набрать `111111` и `000000` одним кеглем; если строки разной длины,
цифры пропорциональные.

Steve Schoger `[V01 24:20]` подаёт приём как малоизвестный «CSS-трюк»: `font-feature-settings: "tnum"`
заставляет пропорциональный шрифт вести себя как моноширинный на цифрах, и колонка сравнивается взглядом без
перехода на моноширинную гарнитуру. Он же соединяет это с выравниванием: числа и даты — по правому краю
плюс табличные цифры.

### 1.3. Lining против oldstyle

| форма | что это | где |
|---|---|---|
| **lining** (`lining-nums`, `lnum`) | все цифры высотой с прописные, на одной линии | интерфейс, таблицы, данные — всегда |
| **oldstyle** (`oldstyle-nums`, `onum`) | минускульные, с выносными элементами (3, 4, 5, 7, 9 уходят вниз) | длинный текст, книги; в интерфейсе не нужны |

У Golos Text есть и lining, и oldstyle, пропорциональные и табличные `[S13]`. У Nunito — два набора
табличных, обычные и старостильные `[S13]`. Для интерфейса всегда бери lining, они почти всегда по умолчанию.

### 1.4. Выравнивание

| тип данных | выравнивание | пример |
|---|---|---|
| целые числа, суммы, проценты | **вправо** | `1 234 567,89 ₽` |
| числа с единицами разной длины | вправо по числу, единица отдельной колонкой или фиксированной ширины | `12 ГБ`, `1 024 МБ` |
| даты `ДД.ММ.ГГГГ` | влево или вправо, единообразно по всей таблице | |
| идентификаторы, артикулы | влево | `ORD-2026-0001` |
| телефоны | влево | |
| заголовок числовой колонки | **вправо**, как содержимое | |

Fluent 2 `[S3]`: «Use right-alignment… to distinguish a short text element in English, like a side note.
Don't right-align long blocks of text in LTR languages.» То есть правое выравнивание — для коротких
элементов, и числа в таблице как раз такой случай.

### 1.5. Формат чисел в русской локали

| элемент | русский формат | английский | примечание |
|---|---|---|---|
| разделитель разрядов | **пробел** | запятая | `1 234 567` против `1,234,567` |
| десятичный разделитель | **запятая** | точка | `12,5` против `12.5` |
| знак валюты | после числа, через пробел | перед числом | `1 200 ₽` против `$1,200` |
| проценты | через пробел | слитно | `25 %` против `25%` |
| диапазон | тире без пробелов | | `10–20`, короткое тире U+2013 |
| время | `14:30` | | |
| дата | `22.09.2026` или `22 сентября 2026` | | |

Технически: разделитель разрядов должен быть **узким неразрывным пробелом** U+202F или обычным неразрывным
U+00A0, иначе число разорвётся при переносе строки.

В JavaScript это делает `Intl.NumberFormat`:

```js
new Intl.NumberFormat('ru-RU').format(1234567.89);                    // "1 234 567,89"
new Intl.NumberFormat('ru-RU', {style:'currency', currency:'RUB'})
  .format(1234567.89);                                                // "1 234 567,89 ₽"
new Intl.NumberFormat('ru-RU', {style:'percent'}).format(0.255);      // "25,5 %"
```

Важно: `Intl` вставляет именно узкий неразрывный пробел U+202F. Если число потом режется регулярками по
пробелу, они не сработают — это частая ошибка.

Знак рубля ₽ — U+20BD, добавлен в Unicode в 2014 году. Его нет в старых шрифтах и он **не входит в
стандартный латинский `unicode-range` подмножеств Google Fonts** — при своём сабсеттинге включай явно
(см. `01-font-selection.md` §5.3).

### 1.6. `slashed-zero` и различимость

```css
.code, .identifier { font-variant-numeric: slashed-zero; }
```

Фича `zero` есть у Inter (полная версия с rsms.me), JetBrains Mono, IBM Plex Mono `[S16]`.
В субсетах Google Fonts она часто вырезана `[S24]`.

Александра Королькова `[V15 33:42]` перечисляет нужный знаковый состав для строк, которые пользователь
разбирает побуквенно (промокод, номер заказа, серийник): **перечёркнутый ноль, тройка с плоским верхом,
буква L с крючком, засечки у прописной I**. Это тот же набор различающих признаков, что у Inter в `ss02`,
`cv05`, `cv08`, `cv09`, `zero` `[S16]`.

Inter даёт более полный набор `[S16]`:
- `ss02` «Disambiguation» — набор глифов, «that increases visual difference between similar-looking
  characters» (включая изменённый ноль); `ss04` — то же без изменения нуля;
- `cv01` альтернативная единица, `cv05` строчная `l` с хвостом, `cv08` прописная `I` с засечками,
  `cv09` плоская тройка, `cv02/cv03/cv04` открытые 4, 6, 9.

```css
.identifier {
  font-feature-settings: 'ss02' 1;   /* Inter: развести 0/O, I/l/1 */
  font-variant-numeric: tabular-nums slashed-zero;
}
```

### 1.7. Единицы, валюты, знаки

| приём | как |
|---|---|
| единица меньше числа | `<span class="unit">` на 1–2 ступени меньше, вес 400, цвет secondary |
| знак валюты | того же размера, что число, или на ступень меньше; в русском после числа |
| неразрывный пробел между числом и единицей | `12&nbsp;ГБ`, `25&nbsp;%`, `1200&nbsp;₽` |
| знак номера | `№` U+2116, с неразрывным пробелом: `№&nbsp;45` |
| плюс-минус, градус, минус | `±` U+00B1, `°` U+00B0, `−` U+2212 (не дефис) `[S33]` |
| дробь | `frac` или готовые символы `½`, `¼` |

Ководство `[S33]` формулирует общий принцип: «Во всех случаях надо использовать специальные знаки, не пытаясь
их эмулировать с помощью других знаков»: `©` а не `(C)`, `®` а не `(R)`, `™`, `°`, `±`, `№`, `§`, `•`.

## 2. Крупные числа на дашбордах

### 2.1. Готовые роли

Atlassian — единственная из изученных систем с отдельными токенами для чисел `[S10]`:

| токен | вес | размер | line-height |
|---|---|---|---|
| `font.metric.large` | Bold | 28 px | 32 px |
| `font.metric.medium` | Bold | 24 px | 28 px |
| `font.metric.small` | Bold | 16 px | 20 px |

### 2.2. Рекомендованные параметры

| параметр | значение | обоснование |
|---|---|---|
| размер | 28–40 px (админка 28–32, кабинет 32–40) | Atlassian metric 24–28 `[S10]`; Fluent Title 2 28/36 `[S3]` |
| вес | 600 (Atlassian ставит Bold 700) | крупный размер уже даёт вес; 700 годится, если число короткое |
| интерлиньяж | 1.1–1.15 (28/32, 32/36, 40/44) | правило обратной зависимости (`03-leading-tracking-measure.md` §1.3) |
| трекинг | −0.02 em | Radix на 35 px даёт −0.01 em, на 60 px −0.025 em `[S18]` |
| цифры | **табличные обязательно** | иначе число «дышит» при обновлении данных |
| подпись метрики | 12 px / 500 / secondary | |
| единица и знак валюты | на 1–2 ступени меньше числа, вес 400 | |
| дельта («+12 %») | 12–14 px / 500 / семантический цвет | |

### 2.3. Пример

```html
<div class="kpi">
  <div class="kpi-label">Выручка за месяц</div>
  <div class="kpi-value">1 284 300<span class="kpi-unit"> ₽</span></div>
  <div class="kpi-delta kpi-delta--up">+12,4 % к прошлому месяцу</div>
</div>
```

```css
.kpi-label { font: 500 0.75rem/1rem var(--font-sans); color: var(--text-secondary); }
.kpi-value {
  font: 600 2rem/2.25rem var(--font-sans);
  letter-spacing: -0.02em;
  font-variant-numeric: tabular-nums;
}
.kpi-unit  { font-size: 1.25rem; font-weight: 400; color: var(--text-secondary); }
.kpi-delta { font: 500 0.875rem/1.25rem var(--font-sans); font-variant-numeric: tabular-nums; }
```

### 2.4. Антипаттерны

- Число без табличных цифр, обновляемое в реальном времени: ширина скачет.
- Число 48 px в плитке 200×120 px: не остаётся места на подпись.
- Число и подпись одного размера: непонятно, что главное.
- Усечение числа (`1 284…`) — читается как другое число.
- Разное число знаков после запятой в соседних плитках (`12,4 %` и `8 %`): колонка не выравнивается.

## 3. Вертикальный ритм и baseline-сетка

### 3.1. Кратность 4 px

| система | кратность `line-height` | кратность шкалы отступов |
|---|---|---|
| Material 3 `[S5]` | 4 px, все значения | 4 px |
| Atlassian `[S10]` | 4 px | 4 px |
| Tailwind `[S9]` | 4 px | 4 px |
| Carbon `[S2]` | 2 px (18, 22, 50 — исключения) | 8 px с половинками |
| Radix `[S18]` | 2 px | 4 px |
| Fluent `[S3]` | 2 px | — |
| GOV.UK `[S8]` | **5 px** | 5 px |
| Ant Design `[S35]` | без кратности (`кегль + 8`) | 8 px |

Зачем кратность: если высота каждой текстовой строки кратна 4 px и все отступы кратны 4 px, любая композиция
автоматически попадает в общую сетку, и высоты блоков складываются без «хвостов».

Практическая проверка: высота строки таблицы = `line-height` + `padding-top` + `padding-bottom`.
При 14/20 и padding 6+6 получается 32 px — кратно 4 и совпадает с типовой высотой компактной строки.

Отдельное уточнение от практика, которое противоречит части рекомендаций: Tim Gabe `[V07 B, ответ автора]`
прямо пишет, что **сетку 4/8 он не тянет на кегли и интерлиньяжи**: «Я никогда не применяю её к line height
или font size; если размеры и оказываются кратны 4, это случайность». `[спорно]` Его аргумент: сетка — про
паддинги, отступы, высоты контролов и размеры иконок, а кегль подбирается по читаемости.
Контраргумент со стороны систем: Material 3 держит кратность 4 у **всех** значений `line-height` без
исключений `[S5]`, и именно это позволяет складывать высоты блоков арифметикой. Рекомендация для генератора:
кегль подбирай по читаемости, **интерлиньяж округляй к 4 px** — это компромисс, который выполняется в 11 из
12 изученных систем.

Ещё два правила Tim Gabe `[V07 B]`, относящихся к ритму:
- **не требуй кратности от итоговой высоты блока**: если паддинги и отступы кратны, суммарная высота
  (в его примере 195 px) кратной не будет, и это нормально; «мастера» — паддинги и отступы `[B 06:09]`;
- **не натягивай сетку на ширины контейнеров и колонок**: контейнер обычно фиксированный (в примере 1140 px),
  а ширины внутри резиновые `[B 04:07]`.

### 3.2. Настоящая baseline-сетка в вебе не применяется

Классическая baseline grid (все базовые линии текста на странице лежат на общей сетке независимо от кегля)
в интерфейсах практически не встречается `[мнение]`:
- текст лежит в боксах разной высоты (кнопки, поля, карточки), и привязать базовые линии к общей сетке
  можно только ручным подбором `padding`;
- при динамическом контенте сетка немедленно ломается;
- до `text-box-trim` в CSS не было механизма позиционировать элемент по базовой линии.

Fluent 2 упоминает baseline alignment `[S3]`: «Fluent uses baseline alignment to distribute vertical space.
This creates a consistent visual rhythm within a layout» — но речь о выравнивании соседних элементов, а не о
глобальной сетке.

Что применяется вместо: **кратность 4 px для всех вертикальных величин** (line-height, padding, margin,
высоты контролов). Это даёт тот же эффект дешевле.

### 3.3. Полулидинг и `text-box-trim`

Интерлиньяж распределяется поровну над и под строкой: у заголовка 32 px с `line-height: 40px` сверху и снизу
добавляется по 4 px пустоты. Из-за этого заданный `margin-top: 32px` выглядит как 36 px, а визуальный отступ
между заголовком и текстом под ним получается больше, чем задумано.

**`text-box-trim`** `[S22]`:
- **Baseline 2026, «Newly available»: с августа 2026** работает в актуальных версиях всех браузеров.
- Значения: `none` (по умолчанию), `trim-start`, `trim-end`, `trim-both`.
- Работает в паре с `text-box-edge`, который задаёт, докуда обрезать: `cap alphabetic` — сверху по высоте
  прописных, снизу по базовой линии; есть шорткат `text-box`.
- Зачем, по формулировке MDN: «Different fonts have different base line-heights, meaning that lines of text
  with the same `font-size` will produce line boxes of differing heights, affecting the appearance of spacing
  between lines.»

```css
h1, h2, h3, .card-title {
  text-box: trim-both cap alphabetic;
}
```

После этого `margin-top` и `margin-bottom` у заголовка означают ровно то, что написано, и одинаково работают
при любой гарнитуре.

**Страховка для старых браузеров**: свойство деградирует молча (старый браузер его игнорирует и оставляет
полулидинг), поэтому специальной проверки не требуется. Если разница критична, заверни в
`@supports (text-box-trim: trim-both) { ... }` и во второй ветке вычитай полулидинг вручную.

**Как делали до этого**: Radix Themes хранит значения обрезки в токенах `[S18]`:
`--default-leading-trim-start: 0.42em`, `--default-leading-trim-end: 0.36em`, и отдельно для заголовков
(`--heading-leading-trim-start: 0.42em`, `--heading-leading-trim-end: 0.38em` в примере документации).
Эти значения применялись как отрицательные margin.

Формула ручного вычитания:

```
полулидинг = (line-height − font-size) / 2
margin-top_фактический = margin-top_желаемый − полулидинг
```

Для заголовка 24/32: полулидинг 4 px, значит при желаемом отступе 32 px ставим `margin-top: 28px`.

## 4. Перенос строк: `text-wrap`

Источник: MDN `text-wrap-style` и `text-wrap` `[S28]`. Свойство `text-wrap` — шорткат для `text-wrap-mode`
(можно ли переносить) и `text-wrap-style` (как переносить).

**Поддержка**: `text-wrap-style` — **Baseline 2024, «Newly available» с октября 2024**, с оговоркой MDN:
«Some parts of this feature may have varying levels of support». То есть `balance` поддержан шире, чем
`pretty`.

### 4.1. `balance`

Что делает: «Text is wrapped in a way that best balances the number of characters on each line, enhancing
layout quality and legibility» `[S28]`.

**Ограничение движков, записанное в документации**: «this value is only supported for blocks of text spanning
a limited number of lines (**six or less for Chromium and ten or less for Firefox**)». Если строк больше,
браузер молча применяет `auto`. Благодаря этому ограничению «this value's impact on performance is
negligible».

Где применять `[система]`:

| контекст | почему |
|---|---|
| заголовки страниц и секций | не остаётся одинокого слова на второй строке |
| заголовки карточек и модалок | |
| подписи под иллюстрациями и графиками | |
| текст пустого состояния (1–3 строки) | |
| заголовок и текст диалога подтверждения | |
| текст тоста и баннера | |
| цитаты и отзывы | прямо названы в документации: «headings, captions, and blockquotes» |

Где **не** применять:
- абзацы длиннее 6 строк (не сработает);
- ячейки таблиц (лишние вычисления на каждой строке, эффекта почти нет);
- виртуализированные списки и бесконечная прокрутка;
- элементы, ширина которых анимируется (пересчёт на каждом кадре);
- `contenteditable` (используй `stable`).

```css
h1, h2, h3, .card-title, .empty-state__title, figcaption, blockquote {
  text-wrap: balance;
}
```

Ограничения, о которых стоит помнить:
- `balance` не гарантирует, что строки будут равны — он минимизирует разброс;
- вместе с `-webkit-line-clamp` работает непредсказуемо: сначала балансировка, потом обрезка;
- на однострочном тексте не делает ничего (и не вредит).

### 4.2. `pretty`

Что делает: «Text is wrapped using a slower algorithm that favors better layout over speed. This is intended
for body copy where good typography is favored over performance (for example, when the number of orphans
should be kept to a minimum)» `[S28]`.

Прямое предупреждение MDN: «Note that `pretty` has a negative effect on performance, so it should be only
used for longer blocks of text when the layout is more important than speed.»

Где применять `[система]`:
- абзацы справки, соглашений, описаний;
- тело статьи в «редакторском» режиме;
- длинные описания товаров и услуг.

Где **не** применять:
- глобально на `body` или `*`;
- в таблицах и списках с сотнями строк;
- в виртуализированных списках;
- в интерфейсе, который часто перерисовывается.

```css
.prose p, .description, .legal { text-wrap: pretty; }
```

### 4.3. `stable` и `auto`

- `stable` — «Text is wrapped such that when the user is editing the content, the lines that come before the
  lines they are editing remain static rather than the whole block of text re-wrapping» `[S28]`.
  Ставь на любой `contenteditable`: комментарии, описания, встроенные редакторы.
- `auto` — значение по умолчанию, «the most performant way for the browser».

В спецификации описано ещё `avoid-short-last-line` / `avoid-orphans`, но **ни один браузер его не
поддерживает** `[S28]`.

Сводная таблица:

| значение | назначение | ограничение | производительность |
|---|---|---|---|
| `auto` | всё остальное | — | максимальная |
| `balance` | заголовки, подписи, короткие блоки | ≤ 6 строк Chromium, ≤ 10 Firefox | незначительное влияние |
| `pretty` | абзацы, где важна типографика | — | **заметно медленнее** |
| `stable` | `contenteditable` | — | обычная |

### 4.4. `hanging-punctuation`

`[S29]`: **«Limited availability», не Baseline** — «does not work in some of the most widely-used browsers».
На сентябрь 2026 поддержка фактически только в Safari.

Значения: `none`, `first` (открывающая кавычка или скобка первой строки выносится в левое поле),
`last` (закрывающая — в правое), `allow-end` (точка или запятая свисает, если иначе не влезает).
Комбинируются: `first allow-end last`.

Для русского интерфейса практический смысл один: вынос открывающей ёлочки «» в левое поле, чтобы левый край
цитаты оставался ровным.

```css
blockquote { hanging-punctuation: first last; }  /* прогрессивное улучшение */
```

В таблицах, формах и навигации не применяется. Использовать только как улучшение: в браузерах без поддержки
ничего не сломается.

### 4.5. Переносы слов

```html
<html lang="ru">
```
```css
.prose { hyphens: auto; hyphenate-limit-chars: 6 3 3; }
```

`hyphens: auto` работает только при корректном `lang`. Для русского особенно полезен в узких колонках, потому
что русские слова длиннее и без переносов в колонке 30–40 знаков появляются большие дыры.

Где включать: колонки уже 45 знаков, карточки, мобильная версия, сайдбар.
Где не включать: заголовки, кнопки, ячейки таблиц, идентификаторы, ссылки.

Для длинных неразрывных значений (ссылки, id, base64) используй `overflow-wrap: anywhere` или
`word-break: break-word`, а не `hyphens`.

## 5. Оптический размер (`opsz`)

`font-optical-sizing` `[S30]`: **Baseline «Widely available», во всех браузерах с марта 2020**.
Значения `auto` (по умолчанию) и `none`. Работает только у переменных шрифтов с осью `opsz`.

Что происходит при `auto`: браузер подставляет в ось `opsz` значение, равное текущему кеглю. Мелкий текст
получает более открытые формы, чуть более толстые тонкие штрихи и более широкие просветы; крупный — более
тонкие детали и плотный набор.

Apple описывает ту же механику для системных шрифтов `[S4]`: «Variable fonts support optical sizing…
On all platforms, the system fonts support dynamic optical sizes, which merge discrete optical sizes (like
Text and Display) and weights into a single, continuous design, letting the system interpolate each glyph or
letterform to produce a structure that's precisely adapted to the point size.»

Inter реализует это явно `[S16]`: «The smaller "text" optical-size designs features a tall x-height to aid in
legibility of lower-case text, with several contrast-enhancing details like ink traps and bridges. The larger
"display" optical-size designs offers clean lines, smooth curves and delicate details.»

Шрифты с осью `opsz` среди проверенных в Google Fonts `[S20]`:

| шрифт | диапазон `opsz` | кириллица |
|---|---|---|
| Inter | 14–32 | есть |
| Roboto Flex | 8–144 | есть |
| Nunito Sans | 6–12 | есть |
| Literata | 7–72 | есть |
| Merriweather | 18–144 | есть |
| Piazzolla | 8–30 | есть |
| DM Sans | 9–40 | **нет** |
| Bricolage Grotesque | 12–96 | **нет** |

Когда отключать (`font-optical-sizing: none`): только если дизайн сознательно фиксирует один оптический
размер, например при подгонке заголовка под конкретный макет.

Ручное управление: `font-variation-settings: 'opsz' 28` — перебивает автоматику, полезно, когда нужно
поставить «дисплейный» рисунок на мелкий кегль или наоборот.

**Важно**: `font-variation-settings` перезаписывает **все** оси разом, включая `wght`. Если задаёшь `opsz`
вручную, укажи и `wght`: `font-variation-settings: 'opsz' 28, 'wght' 600`.

## 6. OpenType в интерфейсе

### 6.1. `font-variant-*` против `font-feature-settings`

| | `font-variant-*` | `font-feature-settings` |
|---|---|---|
| уровень | высокий | низкий |
| наследование | да | да, но **перезаписывает весь набор** |
| комбинирование | значения складываются | последнее объявление отменяет предыдущее |
| читаемость кода | `tabular-nums slashed-zero` | `'tnum' 1, 'zero' 1` |
| покрытие | только стандартизованные фичи | любые, включая `ss01`, `cv01` |

**Правило**: всё, что можно, задавай через `font-variant-numeric`, `font-variant-ligatures`,
`font-variant-caps`; `font-feature-settings` оставь для стилистических наборов (`ss*`, `cv*`), которых в
`font-variant-*` нет.

Опасность: два правила с `font-feature-settings` на одном элементе не складываются. Если в одном месте
`'tnum' 1`, а в другом `'ss02' 1`, победит последнее, и табличные цифры потеряются.

### 6.2. Полезные фичи для интерфейса

| фича | CSS | зачем |
|---|---|---|
| `tnum` | `font-variant-numeric: tabular-nums` | табличные цифры |
| `pnum` | `font-variant-numeric: proportional-nums` | вернуть пропорциональные внутри текста |
| `lnum` | `font-variant-numeric: lining-nums` | цифры в рост прописных |
| `zero` | `font-variant-numeric: slashed-zero` | перечёркнутый ноль |
| `frac` | `font-variant-numeric: diagonal-fractions` | дроби `1/2` |
| `ordn` | `font-variant-numeric: ordinal` | `1st`, для русского не нужно |
| `case` | `font-feature-settings: 'case' 1` | скобки и знаки под высоту прописных при капсе |
| `calt` | `font-variant-ligatures: contextual` (вкл. по умолчанию) | контекстные альтернативы |
| `liga` | `font-variant-ligatures: common-ligatures` (вкл.) | обычные лигатуры `fi`, `fl` |
| `dlig` | `font-variant-ligatures: discretionary-ligatures` | декоративные, в интерфейсе не нужны |
| `kern` | `font-kerning: normal` (вкл. по умолчанию) | кернинг |
| `locl` | автоматически по `lang` | локальные формы букв |
| `ss02` (Inter) | `font-feature-settings: 'ss02' 1` | различимость похожих знаков |
| `cv05`, `cv08`, `cv11` (Inter) | `font-feature-settings: 'cv05' 1` | `l` с хвостом, `I` с засечками, одноэтажная `a` |
| `ss11` (Geist Mono) | `font-feature-settings: 'ss11' 1` | программистские лигатуры, **по умолчанию выключены** `[S19]` |

`locl` заслуживает отдельного упоминания для многоязычных интерфейсов: он подставляет локальные варианты
глифов (например, болгарские формы кириллицы) в зависимости от `lang`. Работает автоматически, но только если
атрибут `lang` выставлен правильно.

### 6.3. Лигатуры: где выключать

```css
code, kbd, samp, .identifier, .input-mask, .table-id {
  font-variant-ligatures: none;
}
```

Почему:
- в идентификаторах `fi`, `fl`, `ff` склеиваются, и строка перестаёт побуквенно совпадать с оригиналом;
- в моноширинном программистские лигатуры (`->`, `=>`, `!=`, `==`) ломают посимвольное выравнивание.

Показательный случай `[S19]`: в Geist Mono 1.7.0 лигатуры кода случайно активировались через `liga`
(включённую по умолчанию во всех рендерерах), из-за чего `--debug-prerender`, `[id...]`,
`NODE_OPTIONS='--debug-prerender'` отрисовывались склеенными и «broke monospace alignment in code».
В 1.7.1 это починили, а сами лигатуры перенесли в `ss11`, где они выключены по умолчанию.

### 6.4. Дефолты Inter

Автор Inter рекомендует явное включение `[S16]`:

```css
:root {
  font-family: Inter, sans-serif;
  font-feature-settings: 'liga' 1, 'calt' 1; /* fix for Chrome */
}
@supports (font-variation-settings: normal) {
  :root { font-family: InterVariable, sans-serif; }
}
```

`calt` у Inter отвечает за контекстные альтернативы пунктуации, стрелок и смайлов.

Напоминание из `01-font-selection.md` §2.2: **в субсетах Google Fonts стилистические наборы `ss*` и `cv*`
вырезаны** `[S24]`. Если они нужны — подключай шрифт с rsms.me или самостоятельно собранный файл.

### 6.5. Сглаживание и рендеринг

| свойство | значение | вывод |
|---|---|---|
| `-webkit-font-smoothing: antialiased` | отключает субпиксельное сглаживание на macOS | **не включать глобально**; допустимо на тёмной теме и для текста ≥ 14 px `[спорно]` |
| `-moz-osx-font-smoothing: grayscale` | то же для Firefox на macOS | пара к предыдущему |
| `text-rendering: optimizeLegibility` | включает кернинг и лигатуры, которые и так включены; может тормозить длинные тексты | **не использовать** `[мнение]` |
| `font-kerning: normal` | кернинг | включён по умолчанию |
| `font-synthesis: none` | запрещает синтетический жирный и курсив | полезно: заставит заметить отсутствующее начертание |

Mantine включает `fontSmoothing: true` по умолчанию `[S37]` — это единственная из изученных систем, которая
принимает такое решение за разработчика.

## Частые ошибки

### Общие

1. **Числа в таблице без `tabular-nums`.** Разряды не выстраиваются, глаз не может сравнить столбиком.
2. **`tabular-nums` на весь `body`.** Числа внутри предложений выглядят разреженными.
3. **Шрифт без `tnum` в финансовой таблице** (Commissioner, Wix Madefor Text) `[S24]`.
4. **Формат `1,234.56` в русском интерфейсе.** Должно быть `1 234,56`.
5. **Обычный пробел как разделитель разрядов.** Число разрывается при переносе строки.
6. **Число и единица разделены обычным пробелом**: `12 ГБ` переносится на две строки.
7. **`line-height` не кратен 4 px**, из-за чего высоты строк таблицы не складываются в сетку.
8. **Заголовок «прилипает» к тексту снизу из-за полулидинга**, отступы подобраны на глаз.
9. **`text-wrap: pretty` на `body`.** Заметная просадка производительности на длинных страницах `[S28]`.
10. **`text-wrap: balance` на абзаце в 20 строк.** Не работает (лимит 6/10 строк) и создаёт ложное ощущение,
    что свойство применено.
11. **`hanging-punctuation` как основа вёрстки.** Не Baseline `[S29]`.
12. **Лигатуры включены в колонке с идентификаторами.**
13. **`font-feature-settings` в двух местах**: второе объявление отменяет первое.
14. **`font-variation-settings: 'opsz' 28` без указания `wght`**: вес сбрасывается в дефолтный.
15. **`text-rendering: optimizeLegibility` «для красоты».**

### Характерные для нейросетей

16. **Забытые табличные цифры.** Самая частая типографическая ошибка сгенерированной таблицы: визуально
    почти незаметна в статике и очень заметна при обновлении данных. Проверка: во всех числовых колонках
    должен стоять `font-variant-numeric: tabular-nums`.
17. **Числа в английском формате в русском интерфейсе** (`$1,234.56`, `1,000 items`) — след англоязычных
    обучающих примеров. Проверка: поиск по `,` между цифрами и `.` перед двумя цифрами.
18. **`%` слитно с числом** по английскому правилу.
19. **Знак рубля заменён на «руб.» или на `P`.** Должен быть `₽` U+20BD, и он должен входить в подмножество
    шрифта.
20. **`text-wrap: balance` навешен на всё подряд**, включая `body` и ячейки таблиц.
21. **`text-box-trim` применён без `text-box-edge`**: свойство есть, эффекта нет (нужно указать, докуда
    обрезать).
22. **Копирование `font-feature-settings: 'ss01' 1, 'cv11' 1` из чужого проекта**, где подключён полный Inter,
    в проект на Google Fonts, где этих фич в файле нет — тихо ничего не происходит.
23. **Моноширинный только для «красоты» на всех числах интерфейса**, включая цены и даты: моно делает текст
    заметно шире и «технически» окрашивает интерфейс.

## Чек-лист

1. Во всех числовых колонках таблиц стоит `font-variant-numeric: tabular-nums`? Да / нет.
2. `tabular-nums` не применён глобально к `body`? Да / нет.
3. Выбранный шрифт имеет табличные цифры по умолчанию или фичу `tnum`? Да / нет.
4. Числа выровнены по правому краю вместе с заголовками своих колонок? Да / нет.
5. Числа отформатированы через `Intl.NumberFormat('ru-RU')`: пробел разряда, запятая, знак валюты после
   числа? Да / нет.
6. Между числом и единицей стоит неразрывный пробел? Да / нет.
7. Знак `₽` (U+20BD) входит в собранное подмножество шрифта? Да / нет.
8. В идентификаторах и кодах включён `slashed-zero` (или `ss02` у Inter) и выключены лигатуры? Да / нет.
9. KPI-числа: 28–40 px, вес 600, трекинг −0.02 em, табличные цифры? Да / нет.
10. Все `line-height` кратны 4 px (допустимо 2)? Да / нет.
11. Заголовки получили `text-box: trim-both cap alphabetic` либо вручную вычтенный полулидинг? Да / нет.
12. `text-wrap: balance` стоит только на заголовках, подписях и блоках до 6 строк? Да / нет.
13. `text-wrap: pretty` не стоит глобально и не применён к таблицам и виртуальным спискам? Да / нет.
14. У `contenteditable` стоит `text-wrap: stable`? Да / нет.
15. `hanging-punctuation` используется только как прогрессивное улучшение? Да / нет.
16. `font-optical-sizing` не отключён без причины? Да / нет.
17. `font-feature-settings` объявлен в одном месте на элемент? Да / нет.
18. `-webkit-font-smoothing: antialiased` не включён глобально, `text-rendering: optimizeLegibility` не
    используется? Да / нет.
19. `hyphens: auto` включён только в узких колонках и только при `lang="ru"`? Да / нет.

## Открытые вопросы и противоречия

1. **Реальная цена `text-wrap: pretty`** в миллисекундах на типичной странице не измерена ни в одном из
   прочитанных источников; MDN говорит только «negative effect on performance» `[S28]`. Нужен замер.
2. **Точная поддержка `text-wrap: pretty` по браузерам на сентябрь 2026** из MDN не извлекается однозначно:
   страница помечена Baseline 2024 с оговоркой «Some parts of this feature may have varying levels of
   support» `[S28]`. Проверять по caniuse перед использованием.
3. **`text-box-trim` в связке с `line-clamp` и с флексами** — поведение не описано в прочитанных источниках.
4. **Нужно ли `tnum` в датах** `[спорно]`: формально дата — число, но при формате `22.09.2026` все цифры
   одинаковой ширины дают ровную колонку, а при формате «22 сентября» — нет. Общего правила не нашёл.
5. **Влияние табличных цифр на скорость считывания таблицы** никем не измерено количественно; все источники
   говорят «так удобнее сравнивать».
6. **Baseline grid в вебе**: я утверждаю, что она не применяется, на основании того, что ни одна из 12
   изученных систем её не использует. Прямого отрицания в источниках нет. `[мнение]`
7. **Узкий неразрывный пробел U+202F против обычного U+00A0** в разделителе разрядов: `Intl` ставит U+202F,
   но часть старых шрифтов его не содержит, и тогда получается «тофу». Проверить в выбранном шрифте.
8. **`-webkit-font-smoothing`** `[спорно]`: Mantine включает `[S37]`, остальные молчат, измерений нет.
