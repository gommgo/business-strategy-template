## Выжимка для агента

1. **Короткие надписи интерфейса при переводе EN → RU становятся шире в 1.4–1.5 раза** (измерено на 20 парах
   типовых надписей, 5 шрифтов) `[S24]`. Ширины кнопок, вкладок и заголовков колонок проектируй по русскому
   тексту. → §1.1 `[исследование]`
2. **Абзацы при переводе EN → RU растут по ширине всего на 13–18 %**, потому что число знаков почти не
   меняется (+2.6 %), а кириллические глифы шире `[S24]`. → §1.2 `[исследование]`
3. **Кириллическая строчная в среднем на 12–20 % шире латинской в том же шрифте**: PT Sans 1.120,
   Golos Text 1.128, Inter 1.147, IBM Plex Sans 1.173, Roboto 1.196 `[S24]`. → §1.3 `[исследование]`
4. **Не фиксируй ширину кнопок в пикселях.** Ставь `min-width` и `padding`, разрешай перенос или
   `text-wrap: balance`. → §1.4 `[консенсус]`
5. **В русском интерфейсе только Sentence case.** Title Case противоречит орфографии. → §3.1 `[консенсус]`
6. **Кавычки: «ёлочки» для русского, “curly” для английского. Программистские `"` — только в коде.**
   Ководство: «Ни в коем случае не знаки дюйма и не „программистские“ кавычки» `[S33]`. → §3.2 `[консенсус]`
7. **Длинное тире — U+2014, не дефис.** Короткое тире U+2013 для диапазонов, минус U+2212 для минуса `[S33]`.
   → §3.3 `[консенсус]`
8. **Букву «ё» в интерфейсе пиши.** В коротких интерфейсных надписях она снимает двусмысленность и не
   утомляет, в отличие от длинных текстов. → §3.4 `[мнение]`
9. **Неразрывные пробелы обязательны**: между инициалами и фамилией, после однобуквенных предлогов и союзов,
   между числом и единицей, перед `₽` и `%`, в `№ 45`. Длинное тире остаётся на предыдущей строке `[S33]`.
   → §3.5 `[консенсус]`
10. **Числа: `1 234 567,89 ₽`**, пробел разряда неразрывный. Подробности — в
    `05-numbers-rhythm-opentype.md` §1.5. → §3.6 `[консенсус]`
11. **`lang="ru"` на `<html>` обязателен**: без него не работают `hyphens: auto`, `locl` и правильные
    кавычки в `<q>`. → §2.1 `[консенсус]`
12. **`hyphens: auto` включай в колонках уже 45 знаков**, не включай в заголовках, кнопках и таблицах.
    → §2.2 `[консенсус]`
13. **Десять типичных типографических ошибок нейросетей**: слишком много размеров, всё жирное, Title Case в
    русском, серый без контраста, `line-height: 1`, геометрический шрифт в таблице, «Inter везде» и обратная
    крайность, несовпадение размеров у одинаковых ролей, забытые табличные цифры, английский формат чисел.
    Для каждой — правило проверки. → §4
14. **Перед отдачей интерфейса прогони автоматические проверки** из §5: число размеров, число весов, формат
    чисел, регистр заголовков, наличие `lang`, `tabular-nums`. → §5

## 1. Расширение текста при переводе

### 1.1. Короткие надписи: рост в 1.4–1.5 раза

Метод `[S24]`: 20 пар типовых интерфейсных надписей (Save / Сохранить, Cancel / Отмена, Settings / Настройки,
Add user / Добавить пользователя, Payment method / Способ оплаты, Notifications / Уведомления,
Dashboard / Панель управления и т. д.), ширина посчитана по таблице `hmtx` реальных файлов шрифтов.
Выборка составлена автором, это оценка порядка величины, а не корпусная статистика.

| измерение | значение |
|---|---|
| число знаков EN → RU | 159 → 207, **+30 %** |
| ширина, Golos Text | **+42 %** |
| ширина, Onest | +42 % |
| ширина, Inter | +44 % |
| ширина, Commissioner, Manrope, Montserrat, Rubik | +43 % |
| ширина, Fira Sans, Noto Sans | +44 % |
| ширина, IBM Plex Sans | +46 % |
| ширина, Open Sans | +47 % |
| ширина, **Roboto** | **+49 %** |
| ширина, моноширинные (JetBrains Mono, Geist Mono, IBM Plex Mono, Roboto Mono) | +30 % (ровно прирост знаков) |

Практические следствия:

| элемент | правило |
|---|---|
| кнопка | `min-width`, а не `width`; запас 40–50 % к английскому макету |
| вкладка, пункт меню | то же; при нехватке места — перенос в «ещё» |
| заголовок колонки таблицы | ширину колонки считать по русскому заголовку |
| бейдж, чип | «В обработке» вместо «Pending» — в 2.2 раза шире |
| кнопка в тулбаре | предусмотреть вариант только с иконкой + тултип |
| подпись поля | размещать над полем, а не слева (слева русская подпись съедает колонку) |

### 1.2. Абзацы: рост на 13–18 %

Метод `[S24]`: 4 пары типовых интерфейсных фраз («Your changes have been saved successfully.» / «Изменения
успешно сохранены.», «This action cannot be undone…» / «Это действие нельзя отменить…» и т. п.).

| измерение | значение |
|---|---|
| число знаков EN → RU | 233 → 239, **+2.6 %** |
| ширина, Golos Text | +12.6 % |
| ширина, Inter | +14.0 % |
| ширина, Geist | +15.1 % |
| ширина, IBM Plex Sans | +15.5 % |
| ширина, Roboto | +17.7 % |

Почему разница со §1.1 такая большая: в коротких надписях русский использует заметно больше слов и букв
(«Add user» = 8 знаков, «Добавить пользователя» = 21 знак), а в связном тексте это компенсируется — русский
обходится без артиклей и вспомогательных глаголов.

Практическое следствие: **`max-width: 65ch` для русского абзаца остаётся правильным** (число знаков в строке
не меняется), но пиксельная ширина блока вырастет на 13–18 %. Это надо заложить в раскладку.

### 1.4. Как проектировать под расширение

| приём | как |
|---|---|
| `min-width` вместо `width` | кнопки, вкладки, чипы |
| `flex-shrink: 0` на кнопке | чтобы не сжималась в тулбаре |
| разрешить перенос в 2 строки | карточки, пункты меню, заголовки колонок |
| `text-wrap: balance` | заголовки и подписи, чтобы перенос был аккуратным (см. `05-numbers-rhythm-opentype.md` §4.1) |
| `hyphens: auto` | узкие колонки (§2.2) |
| «псевдолокализация» | продублировать английский макет с текстом в 1.5 раза длиннее и проверить, что ничего не ломается |
| подпись над полем, а не слева | русская подпись «Способ получения уведомлений» съест колонку 200 px |
| иконка + тултип вместо текста | плотные тулбары |

Английский и немецкий: немецкий растёт сильнее русского из-за составных слов («Benachrichtigungseinstellungen»).
Численных данных по немецкому я не измерял; проектируй по худшему из целевых языков.

## 2. Технические настройки локали

### 2.1. `lang`

```html
<html lang="ru">
```

Что от этого зависит:
- **`hyphens: auto`** — без `lang` браузер не знает правил переноса и не переносит вовсе;
- **фича `locl`** — подстановка локальных форм глифов (болгарские формы кириллицы, сербские формы);
- **`<q>`** — браузер подставляет кавычки, принятые в языке;
- проверка орфографии в `contenteditable`;
- синтез речи и скринридеры.

В многоязычном интерфейсе `lang` ставится и на отдельные блоки:

```html
<p lang="ru">Изменения сохранены</p>
<code lang="en">git commit --amend</code>
```

### 2.2. Переносы

```css
.prose, .card__description, .sidebar__text {
  hyphens: auto;
  hyphenate-limit-chars: 6 3 3;  /* минимум 6 букв в слове, 3 до и 3 после переноса */
}
```

Где включать: колонки уже 45 знаков, карточки, мобильная версия, сайдбар, описания в узких панелях.
Где не включать: заголовки, кнопки, ячейки таблиц, идентификаторы, ссылки, значения полей.

Для очень длинных неразрывных строк (ссылки, base64, идентификаторы) переносы не помогут, нужен
`overflow-wrap: anywhere` или усечение.

Значения `hyphenate-limit-chars: 6 3 3` — распространённая практика, но подтверждения в открытых мной
источниках нет `[мнение]`.

### 2.3. Форматирование через `Intl`

```js
// числа и валюта
new Intl.NumberFormat('ru-RU').format(1234567.89);                       // "1 234 567,89"
new Intl.NumberFormat('ru-RU', {style:'currency', currency:'RUB'}).format(1200); // "1 200,00 ₽"
new Intl.NumberFormat('ru-RU', {style:'percent', maximumFractionDigits:1}).format(0.255); // "25,5 %"

// даты
new Intl.DateTimeFormat('ru-RU').format(new Date());                     // "22.09.2026"
new Intl.DateTimeFormat('ru-RU', {day:'numeric', month:'long', year:'numeric'})
  .format(new Date());                                                   // "22 сентября 2026 г."

// относительное время
new Intl.RelativeTimeFormat('ru', {numeric:'auto'}).format(-3, 'day');    // "3 дня назад"

// склонение по числу
new Intl.PluralRules('ru-RU').select(1);   // "one"   → "заказ"
new Intl.PluralRules('ru-RU').select(2);   // "few"   → "заказа"
new Intl.PluralRules('ru-RU').select(5);   // "many"  → "заказов"
```

**У русского языка четыре категории множественного числа** (`one`, `few`, `many`, `other`) против двух у
английского. Строки вроде «Найдено {n} заказ(ов)» — костыль; правильное решение — `Intl.PluralRules` или
ICU MessageFormat.

Важно: `Intl.NumberFormat` вставляет **узкий неразрывный пробел U+202F** как разделитель разрядов. Если
потом число парсится регуляркой по обычному пробелу, она не сработает. Это частый источник багов.

## 3. Русские типографские нормы в интерфейсе

Основной источник — «Ководство» Артемия Лебедева, § 62 «Экранная типографика» и § 104 «Кавычки» `[S33]`.

### 3.1. Регистр

**Только Sentence case.** В русском языке прописная буква ставится в начале предложения и в именах
собственных. «Создать Новый Заказ» — орфографическая ошибка.

| элемент | правильно | неправильно |
|---|---|---|
| кнопка | Сохранить изменения | Сохранить Изменения |
| заголовок страницы | Настройки уведомлений | Настройки Уведомлений |
| заголовок колонки | Номер заказа | Номер Заказа |
| пункт меню | Мои платежи | Мои Платежи |
| бейдж | В обработке | В Обработке |
| название продукта (имя собственное) | Яндекс Диск | яндекс диск |

Не используй `text-transform: capitalize` в мультиязычном интерфейсе: для английского он даёт неправильный
Title Case (артикли и предлоги должны оставаться строчными), для русского ломает текст.

Верхний регистр (`uppercase`) — см. `04-weight-hierarchy-color.md` §5: для кириллицы он хуже, чем для
латиницы, и Fluent 2 его прямо не советует `[S3]`.

### 3.2. Кавычки

`[S33]`, § 104: «Кавычки являются парными знаками препинания… Уважающий себя дизайнер книги, газеты или сайта
всегда будет использовать принятые для конкретного языка кавычки.»

| язык | внешние | вложенные |
|---|---|---|
| русский | **«ёлочки»** U+00AB, U+00BB | „лапки“ U+201E, U+201C |
| английский | “curly” U+201C, U+201D | ‘single’ U+2018, U+2019 |
| код, разметка | `"` U+0022, `'` U+0027 | — |

`[S33]`, § 62: «Ни в коем случае не знаки дюйма и не „программистские“ кавычки (которые используются только
для набора исходных кодов программ или в электронной переписке).»

Апостроф в русском тексте — `’` U+2019, не `'`.

В интерфейсе кавычки встречаются в сообщениях вида «Удалить заказ „№ 1024“?». Практичнее избегать кавычек
вообще, выделяя имя объекта весом: `Удалить заказ <b>№ 1024</b>?`.

### 3.3. Тире и дефис

`[S33]`, § 62: «Тире не надо путать с дефисом — оно обычно в два-три раза длиннее.»
Пример из источника: неправильно «Коляныча - за пивом послать!», правильно «Коляныча — за пивом послать!».

| знак | Unicode | где |
|---|---|---|
| дефис `-` | U+002D | внутри слов: «кто-то», «из-за», «интернет-магазин» |
| короткое тире `–` | U+2013 | диапазоны без пробелов: «10–20», «2024–2026», «пн–пт» |
| длинное тире `—` | U+2014 | между словами, с пробелами: «Заказ — это…» |
| минус `−` | U+2212 | отрицательные числа: «−12 °C» |

В интерфейсе длинное тире встречается в прочерках («Не указано» лучше, чем «—»), в подписях и в описаниях.
Прочерк в пустой ячейке таблицы правильнее делать длинным тире с неразрывным пробелом или вообще заменять
на серое «не указано».

### 3.4. Буква «ё»

`[спорно]` в общей типографике, но для интерфейса `[мнение]`: **пиши «ё»**.

Аргументы за:
- интерфейсные надписи короткие, «ёканье» не утомляет;
- снимает двусмысленность: «все / всё», «узнаем / узнаём», «небо / нёбо»;
- поиск по интерфейсу работает предсказуемее, если написание одно;
- в именах собственных (Фёдоров, Алёна) обязательна по правилам.

Технически: проверь, что «ё» и «Ё» (U+0451, U+0401) есть в собранном подмножестве шрифта, и что в поиске
«е» и «ё» считаются эквивалентными (нормализация на стороне бэкенда).

### 3.5. Неразрывные пробелы и правила переноса

`[S33]`, § 62: «На строчке не могут остаться: инициалы, одно-, двух- и некоторая часть трёхбуквенных слов,
цифры года. На строчке должно остаться длинное тире.» И дальше: «предлоги и союзы привязывать к следующему
за ними слову, а частицы — к предыдущему».

| случай | пример | как |
|---|---|---|
| инициалы и фамилия | `В.&nbsp;И.&nbsp;Пупкин` | U+00A0 |
| однобуквенный предлог/союз | `в&nbsp;корзину`, `и&nbsp;ещё` | |
| число и единица | `12&nbsp;ГБ`, `25&nbsp;%`, `1 200&nbsp;₽` | |
| знак номера | `№&nbsp;45` | |
| сокращения | `2026&nbsp;г.`, `стр.&nbsp;12`, `т.&nbsp;е.` | |
| длинное тире | остаётся на предыдущей строке: `слово&nbsp;— слово` | пробел перед тире неразрывный |
| телефон и слова через дефис | `<span class="nobr">+7 999 123-45-67</span>` | `white-space: nowrap`, потому что часть браузеров переносит по дефису `[S33]` |

`[S33]`: «Нельзя писать номера телефонов на западный манер, то есть с одним дефисом (212-8506), нужно всегда
писать с двумя.»

В интерфейсе значительная часть текста приходит из бэкенда, поэтому неразрывные пробелы ставятся либо в
исходных строках локализации, либо типографом на стороне сервера. Для строк, которые пишет дизайнер
(заголовки, кнопки, пустые состояния), это делается вручную.

### 3.6. Числа, валюта, спецзнаки

См. подробно `05-numbers-rhythm-opentype.md` §1.5. Кратко:
`1 234 567,89 ₽` — пробел разряда (неразрывный узкий U+202F), запятая десятичная, знак валюты после числа
через неразрывный пробел; `25 %` через пробел.

`[S33]`, § 62: «Во всех случаях надо использовать специальные знаки, не пытаясь их эмулировать с помощью
других знаков»: `©` вместо `(C)`, `®` вместо `(R)`, а также `™`, `°`, `±`, `№`, `§`, `•`.

Эталонный пример набора из § 62 `[S33]`:
«…Когда В. И. Пупкин увидел в газете («Сермяжная правда» № 45) рубрику Weather Forecast®, он не поверил
своим глазам — температуру обещали ±451 °F.»

### 3.7. Готовый список подстановок для типографа

| было | стало | комментарий |
|---|---|---|
| `"текст"` | `«текст»` | русский |
| `'слово'` | `„слово“` | вложенные |
| ` - ` | ` — ` | тире с неразрывным пробелом перед ним |
| `10-20` | `10–20` | короткое тире |
| `-5` | `−5` | минус |

## 4. Ошибки нейросетей с типографикой

Ниже — типичные дефекты сгенерированных интерфейсов с правилом проверки для каждого. Часть выведена из
правил предыдущих файлов, часть наблюдается непосредственно в дефолтах инструментов (Tailwind, MUI, shadcn).

### 4.1. Слишком много размеров и весов

**Что происходит.** Модель «помнит» несколько шкал сразу (Tailwind 12/14/16/18/20/24/30/36, Material
11/12/14/16/22/24/28/32, Bootstrap) и выдаёт гибрид, где рядом стоят 18 и 22 px без роли для каждого.
Похоже и с весами: `font-medium`, `font-semibold`, `font-bold` появляются вперемешку.

**Проверка.**
```bash
grep -ohE "text-(xs|sm|base|lg|xl|[2-9]xl)" src -r | sort | uniq -c | sort -rn
grep -ohE "font-(thin|light|normal|medium|semibold|bold|extrabold)" src -r | sort | uniq -c
```
Уникальных размеров ≤ 8, весов ≤ 3 (плюс `font-bold` для редких акцентов). Каждому размеру должна
соответствовать названная роль.

### 4.2. Title Case в русском интерфейсе

**Что происходит.** Промпт и обучающие примеры англоязычные, модель переносит английскую конвенцию
заголовков на русский: «Создать Новый Заказ», «Настройки Уведомлений».

**Проверка.** Регулярка по строкам локализации: два и более слова подряд с прописной буквы, не являющихся
именами собственными.
```
\b[А-ЯЁ][а-яё]+\s+[А-ЯЁ][а-яё]+
```
Исключения: имена собственные, названия продуктов.

### 4.3. Всё жирное

**Что происходит.** Дефолт Tailwind `font-bold` = 700 применяется ко всем заголовкам всех уровней, к лейблам
и к значениям; иерархия исчезает.

**Проверка.** Доля текста весом ≥ 600 на экране не больше 20 %. Заголовки ≥ 28 px не тяжелее 600. Тело
всегда 400.

### 4.4. Серый текст без контраста

**Что происходит.** `text-gray-400` (`#9CA3AF`) на белом даёт 2.54:1 — не проходит 4.5:1. Модель берёт этот
класс, потому что он выглядит «вторичным» в примерах.

**Проверка.** Автоматический прогон контраста всех пар «цвет текста / цвет фона» (см. `01-color/` и
`13-evaluation-checklists/`). Для текста мельче 24 px обычного веса порог 4.5:1 `[S3]`.

### 4.5. `line-height: 1` или перепутанные интерлиньяжи

**Что происходит.** `leading-tight` (1.25) на абзаце и `leading-relaxed` (1.625) на заголовке — утилиты
перепутаны местами.

**Проверка.** Любой блок, который может занять больше двух строк, имеет ratio ≥ 1.4. Любой заголовок имеет
ratio ≤ 1.3. `line-height: 1` допустим только для однострочных бейджей.

### 4.5a. Шрифт из агрегатора «бесплатных шрифтов»

**Что происходит.** Модель или человек берёт файл с сайта-агрегатора. Александра Королькова `[V15 01:00]`:
причина отказаться не в правообладателе, а в качестве — у большинства таких файлов **сломан контур и
разъехались межбуквенные расстояния**. В мелком кегле этого не видно, в крупном заголовке видно сразу.

**Проверка.** Источник шрифта — Google Fonts, репозиторий автора на GitHub или сайт словолитни. Увеличить
образец до 200–300 px и посмотреть на контур: тонкие линии не должны «гулять» по толщине, контур не должен
ломаться у петли `[V15 10:13]`.

### 4.5b. Экспериментальная или болгарская кириллица в тексте

**Что происходит.** Шрифт выбран по внешнему виду заголовка, а в наборе у него нестандартные конструкции
знаков: круглая «в» с верхним выносным элементом, курсивные формы «й», «п», «т» в прямом начертании. Это
болгарская норма кириллицы; для русского текста она читается как «шрифт с акцентом», и читатель устаёт
`[V15 36:47]`.

**Проверка.** Набрать абзац и сравнить формы «б», «в», «д», «и», «й», «п», «т» с любым каноническим текстовым
шрифтом (PT Sans, Golos Text). В заголовке и логотипе нестандартные формы допустимы, в тексте — нет.

### 4.6. Геометрический шрифт в таблице с числами

**Что происходит.** Montserrat или Poppins в заголовках и в таблице: широкие, с низкими счётчиками, часто
без настроенных цифр. Poppins вдобавок вообще не имеет кириллицы `[S20]`.

**Проверка.** Если в интерфейсе есть таблица с числами, гарнитура должна иметь x-height ≥ 0.52 em и табличные
цифры (или фичу `tnum`) — см. `01-font-selection.md` §2.

### 4.7. «Inter везде» и обратная крайность

**Что происходит.** Либо Inter во всех проектах без учёта кириллицы (у Inter она признанно слабая `[S13]`,
`[S15]`), либо экзотический шрифт «ради уникальности», который оказывается низкокачественным (Untitled UI:
«99 % of modern fonts are low-quality» `[S32]`).

**Проверка.** Если ≥ 50 % текста интерфейса русский — прогнать выбранный шрифт по тестовой строке из
`01-font-selection.md` §3.5 и сравнить с Golos Text или IBM Plex Sans.

### 4.7a. Много текстовых стилей на одном экране

**Что происходит.** Илья Бирман `[V14 13:19]` разбирает работу, где в верхней части экрана насчитано
**16 текстовых стилей**, при том что до меню разбор ещё не дошёл. Он же отмечает соседний симптом: у двух
одинаковых кнопок разный кегль текста — «почему не взял эту же и не исправил текст?» `[V14 16:21]`.
У генератора та же болезнь по другой причине: нет памяти о том, какие роли уже заведены.

**Проверка.** Выписать все пары «кегль + вес + цвет», встречающиеся на одном экране. Норма, которую ставит
Бирман: **три размера шрифта**, один способ выделить плашку, один стиль иконок, одна толщина линии на весь
макет. Для реального приложения это скорее 6–7 размеров и 12–15 ролей (см. `02-type-scale.md` §3), но
16 стилей на четверть экрана — заведомо ошибка.

### 4.8. Несовпадение размеров у одинаковых ролей

**Что происходит.** Заголовок карточки на одной странице 16 px, на другой 18 px; подпись поля в одной форме
12 px, в другой 14 px. У модели нет памяти о том, что роль уже определена.

**Проверка.** Для каждой роли (заголовок карточки, подпись поля, заголовок колонки, текст кнопки) собрать все
встречающиеся значения. Должно быть по одному.

### 4.9. Отсутствие табличных цифр

**Что происходит.** Самая частая и самая незаметная в статике ошибка: в таблице нет
`font-variant-numeric: tabular-nums`, и при обновлении данных колонка «дышит».

**Проверка.** Все числовые колонки, таймеры и счётчики имеют `tabular-nums` (если шрифт не даёт табличные
цифры по умолчанию, см. `05-numbers-rhythm-opentype.md` §1.2).

### 4.10. Английский формат чисел и дат в русском интерфейсе

**Что происходит.** `$1,234.56`, `1,000 items`, `09/22/2026`, `25%` слитно — след англоязычных примеров.

**Проверка.** Поиск запятой между цифрами и точки перед двумя цифрами в отрендеренном тексте; формат даты
`ДД.ММ.ГГГГ`; пробел перед `%` и `₽`.

### 4.11. Декоративные шрифты в заголовках приложения

**Что происходит.** Playfair Display, Cormorant, Space Grotesk, Unbounded в заголовках админки — «чтобы было
красиво». В приложении это читается как маркетинговая страница внутри рабочего инструмента.

**Проверка.** В приложении одна текстовая гарнитура плюс моноширинная (`01-font-selection.md` §6).

### 4.12. Стек с неподключённым шрифтом

**Что происходит.** `font-family: Inter, sans-serif` без `@font-face` и без ссылки на CDN. Страница
отрисуется системным гротеском, и вся настроенная шкала уедет: разница x-height до 13 % `[S24]`.

**Проверка.** Каждое имя семейства в `font-family` либо объявлено в `@font-face`, либо заведомо системное.

### 4.13. Скопированные значения трекинга

**Что происходит.** `tracking-tight` (−0.025em) на всём подряд, включая подписи 11 px; или значения трекинга,
подобранные под Roboto, применённые к другой гарнитуре. MUI прямо предупреждает: «Using the same
letter-spacing across font-families can cause issues with the kerning» `[S36]`.

**Проверка.** Трекинг = 0 на теле, отрицательный только с 18–20 px, положительный только на 11–12 px и на
капсе.

### 4.14. Отсутствие `max-width` у абзацев

**Что происходит.** Текст растягивается на всю ширину контейнера 1440 px — это ~180 знаков при 16 px,
нарушение WCAG 1.4.8 `[S23]`.

**Проверка.** У всех абзацев есть `max-width` в диапазоне 45–75 знаков (`60ch`–`70ch`).

### 4.15. Забытый `lang="ru"`

**Что происходит.** Шаблон сгенерирован с `lang="en"`. Переносы не работают, `locl` не применяется, скринридер
читает русский текст английской фонетикой.

**Проверка.** `grep -o 'lang="[a-z-]*"' index.html`.

## Частые ошибки

Сведено из §3 и §4, без повторов:

1. Title Case в русских заголовках и кнопках.
2. Программистские кавычки `"` вместо «ёлочек».
3. Дефис вместо длинного тире.
4. Дефис вместо короткого тире в диапазонах и вместо минуса в отрицательных числах.
5. Отсутствие «ё».
6. Отсутствие неразрывных пробелов: инициалы, предлоги, числа с единицами, `№ 45`.
7. Обычный пробел как разделитель разрядов — число рвётся при переносе.
8. Английский формат чисел и дат.
9. `%` и `₽` слитно с числом.
10. `text-transform: capitalize` в мультиязычном интерфейсе.
11. Ширина кнопки задана в пикселях по английскому макету.
12. Подпись поля слева от поля в русском интерфейсе (съедает колонку).
13. Забытый `lang="ru"`.
14. `hyphens: auto` в заголовках и кнопках.
15. «ов» и скобки для множественного числа («3 заказ(ов)») вместо `Intl.PluralRules`.
16. Замена `₽` на «руб.» или на латинскую `P`.

## Чек-лист

1. Ширины кнопок, вкладок и заголовков колонок проверены на русском тексте, а не на английском? Да / нет.
2. Кнопки имеют `min-width`, а не фиксированный `width`? Да / нет.
3. `lang="ru"` стоит на `<html>`, и на иноязычных вставках свой `lang`? Да / нет.
4. Все заголовки, кнопки и пункты меню в Sentence case? Да / нет.
5. Кавычки «ёлочки», апостроф `’`? Да / нет.
6. Длинное тире `—` в тексте, короткое `–` в диапазонах, минус `−` в числах? Да / нет.
7. Буква «ё» пишется и входит в подмножество шрифта? Да / нет.
8. Неразрывные пробелы расставлены: инициалы, однобуквенные предлоги, число + единица, `№ 45`,
   перед длинным тире? Да / нет.
9. Числа форматируются через `Intl.NumberFormat('ru-RU')`? Да / нет.
10. Множественное число реализовано через `Intl.PluralRules` (4 формы), а не через «(ов)»? Да / нет.
11. Даты в формате `ДД.ММ.ГГГГ` или «22 сентября 2026»? Да / нет.
12. Знак `₽` (U+20BD) и `№` (U+2116) есть в собранном подмножестве шрифта? Да / нет.
13. `hyphens: auto` включён только в узких колонках? Да / нет.
14. Псевдолокализация (текст ×1.5) не ломает раскладку? Да / нет.
15. Автоматические проверки из §5 пройдены? Да / нет.

## Открытые вопросы и противоречия

1. **Мои измерения расширения текста** `[S24]` сделаны на выборке из 20 надписей и 4 предложений, которые я
   составил сам. Это оценка порядка величины. Нужна проверка на реальном корпусе строк локализации крупного
   продукта.
2. **Немецкий и другие языки** я не измерял. Общепринятые таблицы расширения (IBM Globalization, Microsoft)
   недоступны: страницы отдают 403 и 404. Кандидат для отдельной проверки.
3. **«Ё» в интерфейсе** `[спорно]`: в книгоиздании принято писать выборочно, в интерфейсе аргументы за
   сплошное написание сильнее, но нормативного источника, прямо регулирующего интерфейсы, нет.
4. **Правило «на строчке не могут остаться цифры года»** `[S33]` в интерфейсах почти не применяется:
   типограф на стороне сервера обычно ограничивается предлогами и числами с единицами. Насколько это заметно,
   не измерено.
5. **`hyphenate-limit-chars` для русского** — значения 6 3 3 из практики, источника нет. `[мнение]`
6. **Скорость чтения русского текста при разной длине строки** — все известные исследования (Ruder, Baymard)
   сделаны на латинице. Переносимость диапазона 50–75 знаков на кириллицу не проверена.
7. **Ошибки нейросетей** в §4 частично выведены из правил, а не наблюдались в контролируемом эксперименте.
   Волна 3 (агент H, папка `12-ai-generated-ui/`) должна проверить их на реальных генерациях и дополнить
   количественными данными.
8. **Узкий неразрывный пробел U+202F** есть не во всех шрифтах; в каких именно из рекомендованных он
   присутствует, я не проверял.
