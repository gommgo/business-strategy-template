# Матрица состояний компонентов

Волна 2 · агент E · 22.09.2026 · источников прочитано целиком: 28

Сводная таблица «компонент × состояние → визуальная дельта» с числами: насколько темнеет фон, что делает
граница, где появляется кольцо, как выглядит отключённое и загружающееся. Способы получения состояний из
базового цвета (шаг шкалы, альфа-слой, сдвиг светлоты) разобраны в
`../01-color/05-states-and-interaction.md`; здесь они приложены к конкретным компонентам.

---

## Выжимка для агента

1. **Обязательный минимум состояний интерактивного элемента: rest, hover, active, focus-visible, disabled.**
   Для списков и таблиц добавляется selected, для форм — invalid и readonly. → §1 `[консенсус]`
2. **ΔL между rest и hover — 2–6 п.п. светлоты**, между rest и active — 5–9 п.п. Меньше 2 не видно,
   больше 8 читается как другой элемент. → §4.1 `[консенсус]`
3. **Альфа-слои нейтрали для прозрачных элементов: hover 4–5 %, active 8 %, selected 8 %.** Проверено:
   4 % над белым даёт `#f5f5f5` (ΔL 3.0), 8 % — `#ebebeb` (ΔL 6.0). → §4.2 `[исследование: расчёт]`
4. **Material state layers из исходника v0.192: hover 0.08, focus 0.12, pressed 0.12, dragged 0.16.**
   Документация часто называет 0.10 — это Material 2. → §3.1 `[система]`
5. **Radix двигает состояние шагом шкалы**: 3 → 4 → 5 для приглушённых фонов, 9 → 10 для сплошных
   (ΔL 2.2–3.3 п.п.). → §3.2 `[система]`
6. **Polaris задаёт четвёрку переменных на каждое свойство** (`--pc-button-bg`, `_hover`, `_active`,
   `_pressed`, `_disabled`) — готовая модель для кодогенерации. → §3.3 `[система]`
7. **Направление зависит от полярности темы, а не от цвета**: в светлой теме hover темнее, в тёмной светлее.
   → §4.3 `[система]`
8. **Selected ≠ active.** Active — момент нажатия, selected — устойчивый выбор; selected заметнее hover и
   всегда дублируется вторым признаком. → §6 `[консенсус]`
9. **Открытый дропдаун подсвечивает триггер как `:active`** (`[aria-expanded='true']` у Primer) либо через
   отдельный токен `pressed` (Polaris). → §6.3 `[система]`
10. **Фокус: `outline` 2 px + `outline-offset` 2 px, контраст ≥ 3:1 и к фону, и к элементу.**
    `box-shadow` — только усиление: в `forced-colors` он принудительно `none`. → §5 `[консенсус]`
11. **Кольцо внутрь (`outline-offset: -1…-2`) применяется, когда элемент примыкает к соседям вплотную**
    (таблица, сегментированная группа, плотный тулбар); тогда толщина 2–3 px. → §5.3 `[спорно]`
12. **Disabled — отдельные токены, не `opacity` на контейнере.** Целевой контраст APCA Lc 30–45. → §7 `[консенсус]`
13. **`opacity: 0.5` поверх вторичного текста даёт ≈ 2.4:1 и Lc < 30** — элемент перестаёт читаться.
    → §7.2 `[исследование: расчёт]`
14. **Loading: содержимое скрывается, размер сохраняется**, добавляется `aria-busy` и `pointer-events: none`.
    → §8 `[консенсус]`
15. **Hover отключается на устройствах без указателя** (`@media (any-hover: hover)` у Carbon), а
    появляющиеся по hover действия остаются видимыми при `pointer: coarse`. → §4.5 `[система]`
16. **Переход 70–150 мс на фон, границу и цвет; `:active` без перехода** (Primer: `transition: none` при
    нажатии — нажатие мгновенно, отпускание плавно). → §9 `[система]`
17. **Комбинированные состояния имеют собственные токены**: selected + hover (третий, более тёмный шаг),
    invalid + focus (фокус важнее: Fluent гасит красную границу в фокусе). → §10 `[система]`
18. **В тёмной теме направление разворачивается**, а кольцо усиливается (Radix увеличивает вклад кольца в
    тенях). → §4.3 `[система]`
19. **Каждое состояние проверяется на контраст отдельно**, включая невидимые с первого взгляда (readonly,
    invalid, selected + hover). → §12 `[консенсус]`
20. **Не больше трёх одновременно меняющихся свойств**: фон + граница + текст. Тень и размер в состояниях
    меняют только там, где это стилевая черта (Radix classic, GOV.UK). → §9 `[мнение]`

## 1. Словарь состояний

| Состояние | CSS | Что означает | Обязательно для |
|---|---|---|---|
| rest | — | покой | всех |
| hover | `:hover` | указатель над элементом | всех интерактивных с указателем |
| active / pressed | `:active` | момент нажатия | кнопок, пунктов, строк |
| focus | `:focus` | элемент получил фокус | всех фокусируемых |
| focus-visible | `:focus-visible` | фокус, который нужно показать (клавиатура) | всех фокусируемых |
| selected | `[aria-selected]`, `[data-state=selected]` | устойчивый выбор | строк, вкладок, пунктов, чипов |
| checked | `:checked`, `[data-state=checked]` | отмечен | чекбокс, радио, переключатель |
| expanded | `[aria-expanded=true]` | раскрыт (меню, аккордеон) | триггеров |
| disabled | `:disabled`, `[aria-disabled]` | недоступен | контролов |
| readonly | `[readonly]` | только чтение, значение копируется | полей |
| invalid | `[aria-invalid=true]` | ошибка валидации | полей |
| loading | `[aria-busy=true]` | операция идёт | кнопок, панелей, таблиц |
| dragged | — | перетаскивается | элементов drag-and-drop |
| visited | `:visited` | посещённая ссылка | контентных ссылок |

## 2. Сводная матрица

Значения даны как «что меняется» + рекомендуемая дельта для светлой темы. `α` — альфа нейтрали над фоном,
`шаг` — шаг цветовой шкалы, `A` — акцент.

| Компонент | hover | active / pressed | focus-visible | selected / checked | disabled |
|---|---|---|---|---|---|
| Кнопка primary (сплошная) | фон −4 п.п. L (или `A-10`) | фон −7 п.п. L | кольцо 2 px + offset 2 | — | фон `surface-disabled`, текст `text-disabled` |
| Кнопка secondary (белая с границей) | фон α 4 %, граница на шаг темнее | фон α 8 % | кольцо 2 px | фон α 8 % + вес 500 | фон `surface-disabled`, граница `border-disabled` |
| Кнопка ghost | фон α 4–5 % | фон α 8 % | кольцо 2 px (offset −1 в плотном ряду) | фон α 8 % | только текст `text-disabled` |
| Кнопка danger | текст красный → фон `danger-9`, текст белый (Primer) | фон `danger-10` | кольцо `danger` 2 px | — | как у secondary |
| Иконочная кнопка | фон α 5 % | фон α 8 % | кольцо 2 px | фон α 8 % | иконка `icon-disabled` |
| Поле ввода | граница на шаг темнее, фон `surface-hover` | — | граница `A`, кольцо 2 px | — | фон `surface-disabled`, граница прозрачная |
| Поле invalid | граница `danger` темнее | — | **кольцо `A`, красная граница гасится** (Fluent) | — | — |
| Чекбокс / радио | граница `A`, фон α 4 % | граница 2 px `A` | кольцо 2 px + offset 1–2 | заливка `A`, галочка белая | заливка `surface-disabled`, галочка `icon-disabled` |
| Переключатель | трек на шаг темнее | бегунок шире на 2–4 (Material: 16 → 28 при нажатии) | кольцо вокруг трека | трек `A`, бегунок к правому краю | трек `surface-disabled` |
| Строка таблицы | фон α 4 % | — | кольцо внутрь 2 px | фон `A-a8` (ΔL 3–4 п.п.) + чекбокс | текст `text-disabled` |
| Строка + selected | фон `A-a12` (третий токен) | — | — | — | — |
| Пункт меню | фон α 4–6 % / `accent` | фон α 8 % | тот же фон, что hover (клавиатура) | галочка + вес 600 (Primer) | `text-disabled`, `pointer-events: none` |
| Пункт сайдбара | фон α 4 % | фон α 8 % | кольцо 2 px | фон `A-a8` + текст `A-11` + вес 500 (+ полоса 2–3 px) | `text-disabled` |
| Вкладка | текст темнее, фон α 4 % (pill) | — | кольцо 2 px | текст `text`, вес 500–600, индикатор 2–3 px | `text-disabled`, индикатор скрыт |
| Карточка-ссылка | тень на уровень выше или фон α 2–4 % | тень обратно | кольцо 2 px по контуру | граница `A` + фон `A/5 %` | — |
| Чип-фильтр | фон α 4 % | фон α 8 % | кольцо 2 px | заливка `A-a3` + галочка 16 | `text-disabled`, граница `border-disabled` |
| Ссылка в тексте | подчёркивание + цвет на 1–2 шага темнее | цвет ещё темнее | кольцо 2 px | — | `text-disabled`, без подчёркивания |
| Слайдер | ручка +2 px, ореол `A/20 %` | ручка +2 px | кольцо `0 0 0 3px A-3, 0 0 0 5px focus` (Radix) | — | трек и ручка `disabled` |
| Аккордеон-заголовок | фон α 4 %, границы соседей перекрашиваются | — | кольцо внутрь | шеврон повёрнут, фон остаётся | `text-disabled` |
| Строка списка | фон α 4 % | фон α 8 % | кольцо внутрь | фон `A-a8` + полоса слева | — |

## 3. Как это устроено в системах

### 3.1. Material 3: слои состояний [S5]

```scss
'hover-state-layer-opacity':   0.08,
'focus-state-layer-opacity':   0.12,
'pressed-state-layer-opacity': 0.12,
'dragged-state-layer-opacity': 0.16
```

Слой рисуется цветом `on-<container>` поверх контейнера, поэтому направление меняется автоматически:
на светлой поверхности слой тёмный, на сплошной кнопке — светлый. Посчитанные дельты:
поверх светлой поверхности hover 5.4 п.п., focus и pressed 8.0, dragged 10.7; поверх сплошной кнопки
4.1 / 6.2 / 8.3 п.п. (`../01-color/05-states-and-interaction.md` §1.2).

**focus и pressed имеют одинаковую альфу**, поэтому Material различает их индикатором фокуса, а не цветом.

### 3.2. Radix: шаг шкалы [S6]

| Роль | Шаг |
|---|---|
| Фон компонента в покое | 3 |
| hover | 4 |
| pressed / selected | 5 |
| Граница компонента | 7 |
| Граница при hover и кольцо фокуса | 8 |
| Сплошной фон | 9 |
| hover сплошного | 10 |

Для прозрачного в покое элемента цепочка сдвигается: 0 → 3 → 4. ΔL шага 3 → 4 составляет 2.2–2.4 п.п.,
9 → 10 — 2.7–3.1 п.п. Дополнительно `solid`-кнопка при нажатии получает
`filter: brightness(0.92) saturate(1.1)` (в тёмной теме `brightness(1.08)`).

### 3.3. Polaris: четвёрка переменных [S2]

Каждое свойство кнопки существует в пяти вариантах: `--pc-button-bg`, `_hover`, `_active`, `_pressed`,
`_disabled`; то же для `color`, `box-shadow`, `icon-fill`. Прозрачные заливки: `bg-fill-transparent` 2 %,
`hover` 5 %, `active` 8 %, `selected` 8 %, `secondary` 6 / 8 / 11 %.

### 3.4. Fluent 2 [S3]

У каждого appearance свои токены `*Hover` и `*Pressed`; **в subtle и transparent при hover иконка
перекрашивается в брендовый цвет и меняет начертание с regular на filled**. Фокус — двойное кольцо внутри:
`border-color: colorStrokeFocus2` + `outline: 2px solid transparent` + `box-shadow: inset 0 0 0 1px`.
В `forced-colors` каждое состояние описано явно через `Highlight`, `HighlightText`, `ButtonText`, `GrayText`.

### 3.5. Carbon [S4]

Фокус — двойное кольцо внутрь: `box-shadow: inset 0 0 0 1px $focus, inset 0 0 0 2px $background`.
Hover только там, где есть указатель: `@media (any-hover: hover)`. Переход 70 мс
(`$duration-fast-01`), кривая `motion(entrance, productive)`.

### 3.6. Primer [S8]

`[aria-expanded='true']` красится как `:active`; selected в списках действий = фон `bgColor-selected` +
`font-weight: semibold`; переход 80 мс `cubic-bezier(.65,0,.35,1)`, но `:active { transition: none }`.

### 3.7. GOV.UK [S9]

Фокус: жёлтая заливка `#ffdd00`, чёрный текст, чёрная подложка-тень 4 px, кольцо 3 px. Нажатие: кнопка
опускается на 2 px (`top: 2px`), тень `0 2px 0` схлопывается. Disabled: `opacity: 0.5` и отключённое
смещение.

### 3.8. shadcn [S1]

Состояния делаются альфой на самом цвете: `hover:bg-primary/90`, `secondary/80`, `accent/50`;
фокус — `focus-visible:border-ring focus-visible:ring-[3px] focus-visible:ring-ring/50`;
ошибка — `aria-invalid:border-destructive aria-invalid:ring-destructive/20` (в тёмной теме 40 %).

## 4. Числа

### 4.1. Дельты светлоты (OKLCH)

| Переход | Рекомендуемая ΔL | Диапазон по системам |
|---|---|---|
| rest → hover | **4 п.п.** | Radix 2.2–3.1, Polaris 2.4, Material 4.1–5.4 |
| rest → active | **7 п.п.** | Radix 4.4–6.4 (два шага), Material 6.2–8.0 |
| rest → selected | **7 п.п.** | Polaris 3.0, Radix 4.4 |
| rest → dragged | 10 п.п. | Material 8.3–10.7 |

Для очень тёмной (L < 0.35) или очень светлой (L > 0.90) базы дельту умножай на 1.5–2: Polaris на тёмной
бренд-кнопке берёт 9.1 п.п.

### 4.2. Альфа-слои над белым (посчитано [S25])

| Альфа чёрного | Результат | ΔL |
|---|---|---|
| 2 % | `#fafafa` | 1.5 п.п. |
| 4 % | `#f5f5f5` | 3.0 п.п. |
| 5 % | `#f2f2f2` | 3.9 п.п. |
| 6 % | `#f0f0f0` | 4.5 п.п. |
| 8 % | `#ebebeb` | 6.0 п.п. |
| 10 % | `#e6e6e6` | 7.5 п.п. |
| 12 % | `#e0e0e0` | 9.3 п.п. |

Акцент (blue-600) с альфой над белым: 4 % → `#f6f9ff` (ΔL 1.8), 8 % → `#ecf2ff` (4.0), 12 % → `#e3ecff` (5.8).
Отсюда рекомендация для выбранной строки таблицы: **8 % акцента** (ΔL 4.0) и 12 % для selected + hover.

### 4.3. Направление и тёмная тема

| Тема | hover | active |
|---|---|---|
| Светлая | темнее | ещё темнее |
| Тёмная | **светлее** | ещё светлее |
| Windows-приложения (Fluent) | светлее | — |

Практический приём (`../01-color/05-states-and-interaction.md` §1.6):

```css
:root { --state-dir: -1; }
.dark { --state-dir: 1; }
.btn:hover  { background: oklch(from var(--btn-color) calc(l + 0.04 * var(--state-dir)) c h); }
.btn:active { background: oklch(from var(--btn-color) calc(l + 0.07 * var(--state-dir)) c h); }
```

### 4.4. Что меняется помимо фона

| Свойство | Когда допустимо менять |
|---|---|
| Граница | всегда вместе с фоном у outlined-элементов |
| Цвет текста | у ссылок, текстовых кнопок, Ant `default`-кнопки |
| Цвет иконки | у subtle-кнопок (Fluent красит в бренд), иконка ≠ текст по цвету |
| Тень | только у карточек и у систем со скевоморфным характером (Radix classic) |
| Положение | нажатие со смещением 1–2 px (Polaris, GOV.UK) — стилевой приём для всей системы |
| Размер | нет (кроме ручки слайдера и бегунка переключателя) |

### 4.5. Указатель

```css
@media (any-hover: hover) { .row:hover { background: rgb(0 0 0 / .04); } }
@media (pointer: coarse)  { .row-actions { opacity: 1; } }  /* действия видны всегда */
```
Radix добавляет тач-ripple без JS: `@media (pointer: coarse) { &:active { outline: 0.5em solid var(--accent-a4);
outline-offset: 0 } }` [S6].

## 5. Фокус

### 5.1. Геометрия

| Параметр | Значение |
|---|---|
| Толщина | **2 px** (GOV.UK 3, Carbon двойное 1 + 2 внутрь) |
| Offset | **2 px** снаружи; −1…−2 внутрь |
| Радиус | радиус элемента + offset |
| Контраст | ≥ 3:1 к фону **и** к самому элементу |
| Реализация | `outline` + `outline-offset`; `box-shadow` только как усиление |

### 5.2. Контрасты (посчитано [S25])

| Кольцо | Фон | WCAG |
|---|---|---|
| blue-600 `#155dfc` | белый | 5.25 |
| blue-600 | панель `#f6f8fa` | 4.93 |
| blue-600 | на самой кнопке blue-600 | **1.00** — поэтому нужен offset с фоном страницы между кольцом и кнопкой |
| `#0a0a0a` | белый | 19.80 |

Двойное кольцо (тёмное + светлое), как в современных Chrome и Edge, решает проблему любого фона:
`outline: 2px solid var(--focus); box-shadow: 0 0 0 4px var(--focus-contrast)`.

### 5.3. Снаружи или внутрь `[спорно]`

| Ситуация | Решение |
|---|---|
| Отдельно стоящая кнопка, поле в форме | снаружи, offset 2 |
| Сегментированная группа, тулбар без зазоров | внутрь, offset −1, толщина 2–3 |
| Строка таблицы, пункт меню | внутрь, offset −2 |
| Элемент у края контейнера с `overflow: hidden` | внутрь (иначе кольцо обрежется) |
| Плотная сетка карточек с зазором 8 | снаружи, offset 1 |

### 5.3a. Чем фокус нарисован в живых продуктах `[исследование: измерения]`

Измерения 24 продуктов после восьми нажатий Tab [S24]:

| Способ | Продукты |
|---|---|
| `outline` 2 px | Carbon (offset −2), Gitea (−2), GitHub ×2 (−2), Mantine (+2), Matomo (−2), MUI (+1), tldraw (−5) |
| `outline` 3 px | Ant Design Pro (+1) |
| Кольцо через `box-shadow` | Cal.com (2 px белое + 4 px тёмное), GitLab, Grafana, Plausible (2 px белое + 4 px акцент), Radix, shadcn, Stripe |
| Остался браузерный `1px auto` | Discourse, Gravity UI, phpMyAdmin, Primer, Redmine, Vercel Geist |
| Не поймано | Consta, Excalidraw |

Два следствия. **Для кода**: основной индикатор — `outline`, потому что в `forced-colors` `box-shadow`
обнуляется; кольцо через тень оставляй как усиление. **Для проверки**: скрипт обязан смотреть и `outline`,
и `box-shadow`, иначе он даст ложный отрицательный результат на всех Tailwind-продуктах (у Grafana
`outline` формально есть, но он прозрачный `rgba(255,255,255,0.01)`). Приём «двойное кольцо» (белая
прослойка + цветное кольцо) встречен у Cal.com и Plausible.

Четверть измеренных продуктов вообще не задаёт фокус и живёт на браузерном дефолте: это не образец,
а напоминание, насколько часто состояние забывают.

### 5.4. `forced-colors`

`box-shadow` в режиме принудительных цветов игнорируется, поэтому основной индикатор — `outline`:

```css
@media (forced-colors: active) {
  :focus-visible { outline-color: Highlight; }
  [aria-selected='true'] { forced-color-adjust: none; background: Highlight; color: HighlightText; }
}
```

## 6. Selected, checked, expanded

### 6.1. Разница

| Понятие | Пример | Признак |
|---|---|---|
| active | момент нажатия кнопки | держится доли секунды |
| selected | выбранная строка, активная вкладка | держится до смены выбора |
| checked | чекбокс, переключатель | состояние данных |
| expanded | открытый дропдаун, раскрытый аккордеон | состояние раскрытия |

### 6.2. Требования

- **selected заметнее hover** (иначе при наведении на соседнюю строку выбранная теряется);
- **selected + hover** имеет собственный токен (Carbon `$layer-selected-hover`, Ant `rowSelectedHoverBg`);
- **selected дублируется вторым признаком**: чекбокс, галочка, вес текста, полоса-индикатор. Это требование
  1.4.1 и условие работы в `forced-colors`.

### 6.3. Expanded

Primer: `[aria-expanded='true']` красится как `:active` [S8]. Polaris держит отдельное состояние `pressed`
с токеном `bg-fill-selected` [S2]. Если триггер и меню видны одновременно, подсветка триггера обязательна:
иначе непонятно, чьё это меню.

---

## 7. Disabled

### 7.1. Токены против `opacity`

| Подход | Плюсы | Минусы |
|---|---|---|
| Отдельные токены (`bg-disabled`, `text-disabled`, `border-disabled`, `icon-disabled`) | точный контроль, граница остаётся видимой | больше токенов |
| `opacity: 0.38–0.5` на контейнер | одна строка | гасит всё сразу, полупрозрачность просвечивает фон, контраст непредсказуем |

### 7.2. Целевые числа

| Значение | Контраст |
|---|---|
| Polaris `#b5b5b5` на белом | 2.05:1, APCA Lc 40.0 |
| Primer `#818B98` на `#EFF2F5` | 3.07:1, Lc 54.1 |
| `opacity: 0.5` поверх вторичного текста | ≈ 2.4:1, Lc < 30 — **не читается** |
| Рекомендация | APCA **Lc 30–45** (≈ WCAG 2–3.5:1) |

WCAG не нормирует отключённые элементы (1.4.3 «Incidental: Inactive»), но невидимая кнопка — тоже ошибка.

### 7.3. Прочее

`cursor: not-allowed`, `box-shadow: none`, hover не срабатывает (Fluent явно сбрасывает все hover-правила),
`pointer-events: none` только если рядом есть объяснение, почему элемент недоступен (иначе тултип не
покажется).

## 8. Loading

| Компонент | Приём |
|---|---|
| Кнопка | текст `visibility: hidden` (Primer) или `color: transparent` (Polaris), спиннер 16 по центру, ширина сохранена |
| Поле | спиннер 16 в правом слоте, поле остаётся редактируемым или `readonly` |
| Таблица | скелетон-строки при первой загрузке; полоса прогресса 2–4 px сверху при обновлении |
| Карточка, панель | скелетон по геометрии контента |
| Страница | не полноэкранный спиннер, а скелетон каркаса |
| Кнопка с прогрессом | линейный индикатор 2 px по нижней кромке кнопки |

Атрибуты: `aria-busy="true"`, `disabled` только если повторное нажатие вредно; текст «Сохранение…» вместо
спиннера, когда операция дольше 2 с.

---

## 9. Переходы

| Свойство | Длительность | Кривая |
|---|---|---|
| background, border-color, color | **70–150 мс** (Carbon 70, Primer 80, Fluent `durationFaster`) | `ease-out` / `cubic-bezier(.65,0,.35,1)` |
| Кольцо фокуса | 0 (мгновенно) | — |
| Тень при hover карточки | 120 мс (Radix) | `ease` |
| Раскрытие меню | 150–200 мс | `ease-out` |
| `:active` | **без перехода** (Primer) | — |
| При `prefers-reduced-motion` | 0.01 мс (Fluent) | — |

Подробности кривых — `../08-motion/` (агент M).

## 10. Комбинации состояний

| Комбинация | Решение |
|---|---|
| selected + hover | третий токен, темнее selected на 3–4 п.п. |
| selected + focus | кольцо поверх фона selected; фон не меняется |
| invalid + focus | **фокус важнее**: Fluent гасит красную границу, пока поле в фокусе; кольцо остаётся акцентным, текст ошибки виден |
| invalid + disabled | красная граница снимается, остаётся disabled |
| checked + disabled | заливка `surface-disabled`, галочка `icon-disabled`, форма сохраняется |
| loading + disabled | визуально disabled, но `aria-busy`, а не `aria-disabled` |
| hover + drag | при перетаскивании hover соседей выключается, подсвечивается только зона вставки |
| readonly + focus | кольцо есть (поле фокусируемо), граница не меняется |

## 11. Рецепты

### 11.1. Через data-атрибуты (один компонент, все состояния)

```css
.item {
  --item-bg: transparent;
  --item-fg: var(--text);
  background: var(--item-bg);
  color: var(--item-fg);
  transition: background-color 80ms, color 80ms, border-color 80ms;
}
.item:hover                      { --item-bg: rgb(0 0 0 / .04); }
.item:active                     { --item-bg: rgb(0 0 0 / .08); transition: none; }
.item[data-state='selected']     { --item-bg: var(--accent-a8); --item-fg: var(--accent-11); font-weight: 500; }
.item[data-state='selected']:hover { --item-bg: var(--accent-a12); }
.item[aria-expanded='true']      { --item-bg: rgb(0 0 0 / .08); }
.item:focus-visible              { outline: 2px solid var(--focus); outline-offset: -2px; }
.item[aria-disabled='true']      { --item-fg: var(--text-disabled); pointer-events: none; }
```

### 11.2. Через относительные цвета

```css
.btn { background: var(--btn-color); }
.btn:hover  { background: oklch(from var(--btn-color) calc(l - 0.04) c h); }
.btn:active { background: oklch(from var(--btn-color) calc(l - 0.07) c h); }
```
Оговорки: `%` в `L` внутри `calc()` не работает (писать дробью); при насыщенных акцентах вычисляй значения
заранее, иначе браузер клиппингует гамут со сдвигом оттенка.

### 11.3. Набор токенов на компонент

```
component.<name>.<part>.<property>.<state>
button.primary.bg.rest / .hover / .active / .disabled
input.border.rest / .hover / .focus / .invalid / .disabled
row.bg.rest / .hover / .selected / .selected-hover
```
Так делают Carbon (component tokens), Polaris (component tokens) и Material (`_md-comp-*`). Подробнее об
именовании — `../09-design-tokens/` (агент F).

## 12. Проверки

```
FOR каждый интерактивный компонент:
    FOR состояние IN [rest, hover, active, focus, selected, disabled, invalid, readonly]:
        ASSERT wcag(текст[состояние], фон[состояние]) >= 4.5          # кроме disabled
        ASSERT wcag(граница[состояние], соседний_фон) >= 3.0          # кроме disabled
        ASSERT |L(состояние) - L(rest)| >= 0.02                        # ≥ 2 п.п. светлоты
    ASSERT L(rest) > L(hover) > L(active)    в светлой теме
    ASSERT L(rest) < L(hover) < L(active)    в тёмной теме
    ASSERT L(selected) отличается от L(hover) >= 0.02
    ASSERT focus реализован через outline (не только box-shadow)
    ASSERT wcag(кольцо, фон) >= 3.0 AND wcag(кольцо, элемент) >= 3.0
    ASSERT selected имеет второй признак (иконка, вес, полоса)
    ASSERT 30 <= |apca(текст_disabled, фон_disabled)| <= 60
    ASSERT ширина элемента в loading == ширине в rest
    ASSERT hover обёрнут в @media (any-hover: hover) ИЛИ действия видимы при pointer: coarse
```

Автоматизация: скрипт Playwright по computed styles из
`../04-shape-elevation/03-tools-checks-and-ai-errors.md` §1 плюс `../../scripts/lib/color.py` для контрастов.

## Частые ошибки

1. **Нет `:active`** — нажатие никак не отражается, интерфейс кажется «залипшим».
2. **hover-дельта 1 п.п.** — состояние не читается.
3. **hover-дельта 12 п.п.** — интерфейс «мигает» при движении мыши.
4. **selected бледнее hover.**
5. **selected только цветом** — теряется при CVD и в `forced-colors`.
6. **Одинаковый фон у hover и selected.**
7. **Нет состояния selected + hover** — выбранная строка «подпрыгивает» к цвету hover.
8. **Кольцо фокуса того же цвета, что кнопка** — контраст 1.0:1.
9. **`outline: none` без замены.**
10. **Фокус только через `box-shadow`** — в `forced-colors` исчезает.
11. **`opacity` для disabled** поверх вторичного текста.
12. **Состояния сделаны только для светлой темы** — в тёмной hover темнее фона и сливается.
13. **Hover у неинтерактивных элементов** (карточка подсвечивается, но никуда не ведёт).
14. **Действия по hover на тач-устройстве** — недоступны.
15. **Переход 300 мс на фон** — кнопка «догоняет» курсор.
16. **Меняется размер при hover** (`scale(1.05)`) в плотном списке — соседи дёргаются.

### Ошибки, характерные для генерации нейросетями

17. **`hover:bg-gray-100` на элементе, лежащем на сером фоне** — hover светлее фона.
18. **`hover:opacity-80`** вместо смены цвета — элемент просвечивает.
19. **`dark:` классы скопированы со светлых** — направление не развёрнуто.
20. **`focus:` вместо `focus-visible:`** — кольцо при клике мышью.
21. **`disabled:opacity-50 disabled:cursor-not-allowed`** без проверки контраста.
22. **`active:` и `focus:` перепутаны** (в разных библиотеках разная семантика).
23. **Состояния заданы только у кнопки**, а у строк, пунктов меню и чипов — нет.
24. **`transition: all`** — анимируются вообще все свойства, включая размеры и тени.
25. **Три уровня подсветки одного оттенка** (`gray-50`, `gray-100`, `gray-200` для hover, active, selected)
    без проверки, различимы ли они: ΔL между `gray-50` и `gray-100` может быть 1 п.п.

## Открытые вопросы и противоречия

1. **Material: 0.10 или 0.12** для focus и pressed. Исходники v0.192 дают 0.12, документация и пересказы —
   0.10. Принято значение исходников. `[спорно]`
2. **Меняется ли хрома при hover**: Erik Kennedy говорит «темнее = насыщеннее», Radix меняет только
   светлоту (ΔC ≈ 0), Material меняет обе величины из-за альфа-слоя. `[спорно]`
3. **Величина hover-дельты** различается втрое между системами (Polaris 2.4 п.п. против Material 5.4 п.п.) —
   это вопрос характера системы, а не правильности. `[спорно]`
4. **Фокус снаружи против внутрь**: правило выбора выведено мной из практики систем, в источниках прямо не
   сформулировано. `[мнение]`
5. **WCAG 2.2 SC 2.4.13 Focus Appearance**: первоисточник w3.org недоступен из этой среды, значения
   «2 px + offset 2» взяты из практики систем. `[не проверено]`
6. **Fluent 2 не даёт числовых значений состояний** вообще — только словесные описания направления.
   `[не проверено]`
7. **Нет исследований**, измеряющих заметность hover в зависимости от ΔL: пороги 2 и 6 п.п. выведены из
   значений систем, а не из экспериментов.
