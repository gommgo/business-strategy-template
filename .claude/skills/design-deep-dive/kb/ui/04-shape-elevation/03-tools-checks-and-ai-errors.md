## Выжимка для агента

1. **Проверяй не макет, а computed styles.** Единственный надёжный способ узнать реальные отступы и размеры это собрать `getComputedStyle` со всех узлов. → §2 [консенсус]
2. **Порог приёмки по кратности: ≥ 95 % значений `padding`, `margin`, `gap` из шкалы.** Исключения перечисляются поимённо. → §6.1
3. **Уникальных высот интерактивных элементов на странице не больше 3.** → §6.2
4. **Уникальных значений `border-radius` не больше 6, `box-shadow` не больше 7.** → §6.3
5. **Ноль значений `z-index`, не принадлежащих шкале токенов.** → §6.4
6. **Ноль интерактивных зон меньше 24 × 24 CSS px без зазора 4 px.** → §6.5 [стандарт]
7. **Ноль элементов с `outline: none` без замены на видимый индикатор фокуса.** → §6.6 [стандарт]
8. **Stylelint запрещает литералы там, где должны быть токены.** `declaration-property-value-allowed-list` плюс `scale-unlimited/declaration-strict-value`. → §3
9. **Визуальная регрессия ловит то, что не ловят числа:** «карточка в карточке», двойные границы, слипшиеся группы. → §5
10. **Собери отчёт в одну таблицу «правило → найдено → порог → вердикт»** и прогоняй его на каждой генерации. → §6.7
11. **Ограничивай генератор списком разрешённых значений прямо в промте**, а не надеждой на «сделай красиво». → §9
12. **Восемнадцать типовых ошибок нейросетей в этой теме** с числовыми проверками собраны в §8.

## 2. Проверка по computed styles

### 2.1 Базовый скрипт

```js
// node check-visual.mjs http://localhost:3000/orders
import { chromium } from 'playwright';

const SPACING = new Set([0, 2, 4, 8, 12, 16, 24, 32, 40, 48, 64, 96]);
const RADII   = new Set([0, 2, 4, 6, 8, 12, 16, 9999]);
const HEIGHTS = new Set([24, 28, 32, 36, 40, 48]);
const ZINDEX  = new Set([0, 10, 100, 200, 1000, 1100, 1200, 1300, 1400, 1500]);

const url = process.argv[2];
const browser = await chromium.launch();
const page = await browser.newPage({ viewport: { width: 1440, height: 900 } });
await page.goto(url, { waitUntil: 'networkidle' });

const report = await page.evaluate(() => {
  const px = v => (v && v.endsWith('px') ? Math.round(parseFloat(v) * 100) / 100 : null);
  const out = {
    spacing: [], radius: [], shadow: [], zindex: [],
    heights: [], targets: [], focusless: [], glass: 0,
  };

  for (const el of document.querySelectorAll('*')) {
    const cs = getComputedStyle(el);
    const rect = el.getBoundingClientRect();
    if (rect.width === 0 || rect.height === 0) continue;

    for (const p of ['paddingTop','paddingRight','paddingBottom','paddingLeft',
                     'marginTop','marginRight','marginBottom','marginLeft',
                     'rowGap','columnGap']) {
      const v = px(cs[p]);
      if (v !== null && v !== 0) out.spacing.push(v);
    }

    for (const p of ['borderTopLeftRadius','borderTopRightRadius',
                     'borderBottomRightRadius','borderBottomLeftRadius']) {
      const v = px(cs[p]);
      if (v !== null && v !== 0) out.radius.push(v);
    }

    if (cs.boxShadow && cs.boxShadow !== 'none') out.shadow.push(cs.boxShadow);
    if (cs.zIndex !== 'auto') out.zindex.push(Number(cs.zIndex));
    if (cs.backdropFilter && cs.backdropFilter !== 'none') out.glass++;

    const tag = el.tagName.toLowerCase();
    const interactive = ['button','a','input','select','textarea'].includes(tag)
      || el.hasAttribute('tabindex') || el.getAttribute('role') === 'button';

    if (interactive) {
      out.heights.push(Math.round(rect.height));
      out.targets.push({
        tag, w: Math.round(rect.width), h: Math.round(rect.height),
        x: Math.round(rect.left), y: Math.round(rect.top),
        label: (el.innerText || el.getAttribute('aria-label') || '').slice(0, 30),
      });
      if (cs.outlineStyle === 'none' && !/inset/.test(cs.boxShadow)) {
        out.focusless.push(tag + ':' + (el.className || ''));
      }
    }
  }
  return out;
});

const share = (arr, set) => arr.filter(v => set.has(v)).length / (arr.length || 1);
const uniq = arr => [...new Set(arr)];

console.log('отступы в шкале:      ', (share(report.spacing, SPACING) * 100).toFixed(1) + '%');
console.log('радиусы в шкале:      ', (share(report.radius, RADII) * 100).toFixed(1) + '%');
console.log('уникальных радиусов:  ', uniq(report.radius).sort((a,b)=>a-b).join(', '));
console.log('уникальных теней:     ', uniq(report.shadow).length);
console.log('z-index вне шкалы:    ', uniq(report.zindex).filter(z => !ZINDEX.has(z)).join(', ') || 'нет');
console.log('высоты контролов:     ', uniq(report.heights).sort((a,b)=>a-b).join(', '));
console.log('высот вне ряда:       ', uniq(report.heights).filter(h => !HEIGHTS.has(h)).join(', ') || 'нет');
console.log('элементов со стеклом: ', report.glass);
console.log('без индикатора фокуса:', report.focusless.length);

// цели меньше 24x24 без достаточного зазора (упрощённая проверка правила кругов)
const small = report.targets.filter(t => t.w < 24 || t.h < 24);
const bad = small.filter(t => report.targets.some(o => {
  if (o === t) return false;
  const dx = Math.max(0, Math.max(t.x - (o.x + o.w), o.x - (t.x + t.w)));
  const dy = Math.max(0, Math.max(t.y - (o.y + o.h), o.y - (t.y + t.h)));
  return Math.hypot(dx, dy) < 4;
}));
console.log('мелких целей:', small.length, 'из них без зазора:', bad.length);
bad.slice(0, 10).forEach(t => console.log('  ', t.tag, t.w + 'x' + t.h, t.label));

await browser.close();
```

Скрипт даёт восемь чисел, по которым сразу видно, собран интерфейс по системе или на глаз.

### 2.2 Уточнения

- **`:focus-visible` проверяется отдельно**: пройти табом по всем фокусируемым элементам (`page.keyboard.press('Tab')`), снять `outline*` и `box-shadow` в состоянии фокуса и сравнить с обычным. Площадь индикатора считается по формулам из `02-shadows-layers-depth.md` §10.1.
- **Строки списков и таблиц**: собрать высоты `tr` и элементов списка, проверить, что внутри одного контейнера значение одно.
- **Ряды контролов**: сгруппировать интерактивные элементы по координате `y` (с допуском 2 px) и сравнить высоты внутри группы.
- **Вложенные радиусы**: для каждого элемента с радиусом найти ближайшего предка с радиусом и проверить `внутренний ≤ внешний`.
- **Направление света**: распарсить `box-shadow`, проверить, что знак и отношение X к Y одинаковы во всех значениях.
- **Эмуляция тача**: повторить прогон с `hasTouch: true` и медиа-эмуляцией `pointer: coarse`, порог целей поднять до 44.

### 2.3 Расширенные проверки

| Проверка | Как |
|---|---|
| Контраст текста на стекле | снять скриншот области, взять худший пиксель подложки, посчитать контраст |
| Отношение «между группами / внутри» | для контейнера с `display: flex/grid` сравнить `gap` с `gap` вложенных контейнеров |
| Тень при скролле | прокрутить, снять `box-shadow` липкой шапки до и после |
| Скрим | открыть модалку, снять `background-color` подложки, проверить альфу 0.32–0.60 |
| `prefers-reduced-motion` | прогон с `reducedMotion: 'reduce'`, проверить отсутствие `transform` на hover |
| `prefers-reduced-transparency` | прогон с эмуляцией, проверить `backdrop-filter: none` |
| `forced-colors` | прогон с `forcedColors: 'active'`, проверить видимость фокуса |

## 3. Линтеры

### 3.1 Stylelint: запрет литералов

```json
{
  "plugins": ["stylelint-declaration-strict-value"],
  "rules": {
    "scale-unlimited/declaration-strict-value": [
      ["/^padding/", "/^margin/", "gap", "row-gap", "column-gap",
       "/^border-radius/", "box-shadow", "z-index", "border-width"],
      { "ignoreValues": ["0", "auto", "inherit", "none", "initial", "1px"] }
    ],
    "declaration-property-value-allowed-list": {
      "border-width": ["0", "1px", "2px"],
      "outline-width": ["2px", "3px"]
    }
  }
}
```

Правило `declaration-strict-value` требует, чтобы значение было переменной или функцией, а не числом. Это единственный способ удержать шкалу в проекте, где часть кода пишет генератор.

### 3.2 Tailwind

В v4 шкала стала непрерывной (`--spacing`), поэтому линтер должен работать по классам:

```js
// eslint-plugin-tailwindcss или собственное правило:
// разрешены p-0 p-0.5 p-1 p-2 p-3 p-4 p-6 p-8 p-10 p-12 p-16 p-24
// запрещены произвольные значения p-[13px], gap-[18px], rounded-[7px]
```

Отдельно запретить произвольные значения в квадратных скобках для `p-`, `m-`, `gap-`, `rounded-`, `shadow-`, `z-`: именно туда генератор сливает числа вне шкалы.

### 3.3 Проверка токенов

- **Соответствие CSS-переменных и файла токенов:** собрать все `var(--*)` из CSS и сверить с ключами токенов; неизвестные переменные это ошибка.
- **Неиспользуемые токены:** обратная проверка, помогает держать шкалу короткой.
- **Формат значений:** все размеры в px или rem, без `em` в отступах компонентов (иначе отступ зависит от шрифта предка).

## 4. Дизайн-файлы

- **Design Lint (Figma-плагин):** ищет значения, не привязанные к стилям и переменным, включая радиусы, отступы автолэйаута и эффекты.
- **Переменные Figma:** отступы и радиусы задаются переменными, а не числами; тогда несоответствие видно в панели, а не глазами.
- **Auto layout:** `gap` и `padding` только из набора переменных; ручной ввод числа это нарушение.
- **Сверка макета и реализации:** прогнать §2 на собранной странице и сравнить полученные множества значений с множеством переменных в Figma.

Подробнее про инструменты и рубрики в `13-evaluation-checklists/` (волна 3).

## 5. Визуальная регрессия

Числа не ловят композиционные дефекты. Скриншотное сравнение ловит:

- «карточка в карточке» с двойной границей и двойной тенью;
- слипшиеся группы, где отступы формально из шкалы, но одинаковые;
- разные радиусы у соседних элементов (видно, числами ловится только через сравнение значений);
- смещение из-за утолщения границы в фокусе или при наведении;
- обрезанное кольцо фокуса;
- «прыжок» соседей при подъёме карточки.

Практика: снимать эталоны в трёх режимах (светлая, тёмная, `forced-colors: active`) и двух ширинах (1440 и 390), порог различия 0.1 %.

## 6. Пороги приёмки

### 6.1 Отступы

| Метрика | Порог |
|---|---|
| Доля значений из шкалы | ≥ 95 % |
| Значения, кратные 5, но не 4 (10, 15, 25, 30) | 0 (кроме систем на 5 px) |
| Уникальных значений `gap` | ≤ 6 |
| Отношение «между группами / внутри группы» | ≥ 2 в формах и списках |

| Метрика | Порог |
|---|---|

| Иконочные кнопки с `width ≠ height` | 0 |

|---|---|

Правила выпуска:
- **ни одного литерала** в компонентах для перечисленных свойств;
- **семантические алиасы** отдельным слоем поверх шкал: смена плотности и темы правит только их;
- **округление до целого пикселя** при вычислении производных значений;
- **один источник истины**: JSON (W3C DTCG) → CSS-переменные → Tailwind-тема.

## 8. Каталог ошибок нейросетей с проверками

| # | Ошибка | Как выглядит | Проверка (число) |
|---|---|---|---|
| 1 | Произвольные отступы | `padding: 13px`, `gap: 22px`, `margin: 7px` | доля значений из шкалы ≥ 95 % |
| 2 | Шкала «десятками» | 10, 15, 20, 25, 30 | значений, кратных 5 и не кратных 4: 0 |
| 3 | Разный padding у одинаковых компонентов | две карточки 16 и 20 | сгруппировать по классу, уникальных значений padding на класс: 1 |
| 4 | Нет иерархии близости | gap 16 и внутри группы, и между группами | отношение между/внутри ≥ 2 |
| 5 | Внешний padding меньше внутреннего | контейнер 12, gap внутри 24 | padding контейнера ≥ max(gap детей) |
| 6 | Карточка в карточке | вложенные блоки с границей и тенью на каждом уровне | глубина вложенности элементов с `box-shadow ≠ none`: ≤ 1 |
| 7 | Двойные границы | граница контейнера плюс граница первого ребёнка вплотную | смежных границ на расстоянии 0–1 px: 0 |
| 8 | Тень у всего | тень на карточках, полях, кнопках, иконках | элементов с тенью на экране: ≤ 15 % от числа блоков |
| 9 | Разные радиусы у соседей | кнопка 8 рядом с полем 4 | уникальных радиусов в одном ряду: 1 |
| 10 | Огромные радиусы в админке | 16–24 px у контролов 32 px | радиус ≤ 25 % меньшей стороны |
| 11 | Микроскопические цели | иконка 16, зона 16 | зон < 24 × 24 без зазора 4 px: 0 |
| 12 | Сайдбар 320–360 в админке | четверть ноутбучного экрана | ширина сайдбара ≤ 280 при окне ≤ 1440 |
| 13 | Модалка подтверждения на весь экран | диалог с одним вопросом шириной 900+ | ширина модалки-подтверждения ≤ 480 |
| 14 | Стекло везде | `backdrop-filter` на каждой карточке | элементов со стеклом: ≤ 2 |
| 15 | z-index произвольными числами | 45, 1001, 9999, 99999 | значений вне шкалы: 0 |
| 16 | Смешение шкал систем | высоты Material, отступы Carbon, радиусы Ant | уникальных высот ≤ 3, радиусов ≤ 6, теней ≤ 7 |
| 17 | Неоновое свечение вместо тени | `box-shadow: 0 0 20px акцент` | теней с offset = 0 и blur > 8: 0 |
| 18 | Фокус удалён | `outline: none` без замены | элементов без индикатора: 0 |
| 19 | Одинаковая тень в тёмной теме | те же alpha и те же поверхности | в тёмной теме альфа теней выше светлой в 1.3–2 раза либо поверхность светлее |
| 20 | Классы Tailwind v3 в проекте v4 | `rounded-sm` даёт 4 px вместо 2 | сверять computed, а не классы |
| 21 | Все элементы одной высоты | таблица, кнопки, поля, меню по 40 | уникальных высот ≥ 2 (иначе нет иерархии) |
| 22 | Отступ вместо размера | высота 38 px из padding 11 | высоты вне ряда 24/28/32/36/40/48: 0 |
| 23 | Вложенные радиусы «на глаз» | 12 снаружи, 10 внутри при padding 8 | внутренний = внешний − padding (допуск 1 px) |
| 24 | Пустые элементы для отступов | `<div style="height:24px">` | пустых узлов с фиксированной высотой: 0 |

### 8.1 Маркеры генерации, видимые без измерений

Наблюдения из разбора сгенерированных интерфейсов (дайджест `../91-videos/digests/09-kole-jain-dashboard-and-ai-slop.md`). Числами они не ловятся, но распознаются за секунды.

| Маркер | Что делать |
|---|---|
| **Эмодзи в интерфейсе** вместо иконок | заменить набором интерфейсных иконок (в видео названы Phosphor, Lucide) |
| **Градиентный кружок с буквой** вместо аватара | заменить реальным аватаром или нейтральной плашкой с инициалами без градиента |
| **Яркие несочетающиеся цвета**, выбранные моделью | перевести на системную палитру |
| **Одни и те же четыре KPI на трёх разных экранах** | пересобрать раскладку под задачу каждого экрана |
| **«Карточки, которые ничего не делают»** | удалить или превратить в строку данных |
| **Пять тарифов на экране цен** | сократить минимум до четырёх |
| Форма на три поля, занимающая выезжающую панель | заменить модалкой, расширенные настройки свернуть |

Автор дайджеста отмечает, что **самая дешёвая по усилиям правка сгенерированного интерфейса это сложные раскладки и карточки**: модели собирают их хуже всего, поэтому здесь наибольший эффект за наименьшее время. Подробный разбор темы у агента волны 3 (`12-ai-generated-ui/`).

## 9. Как ограничивать генератор

### 9.1 Что писать в промт

Плохо: «сделай современный дашборд, красиво и аккуратно».

Хорошо: явный список разрешённых значений и запретов.

```
Отступы только из набора: 0, 4, 8, 12, 16, 24, 32, 48. Другие значения запрещены.
Высоты кнопок, полей и select: ровно 32px. Иконочные кнопки 32x32.
Строка таблицы 36px, padding ячейки 6px 12px.
Радиусы: 4px для бейджей, 6px для кнопок, полей и меню, 8px для карточек, 12px для модалки.
Границы 1px цвета #E5E7EB. 2px только для фокуса.
Тени: карточки без тени (только граница), меню и поповеры
  "0 0 0 1px rgb(0 0 0 / .06), 0 1px 3px rgb(0 0 0 / .10), 0 4px 8px 3px rgb(0 0 0 / .06)",
  модалка на уровень выше.
z-index только: 100 sticky, 1000 backdrop, 1200 modal, 1300 popover, 1400 toast, 1500 tooltip.
Фокус: outline 2px solid #2563EB, outline-offset 2px, только :focus-visible.
Запрещено: backdrop-filter, градиенты в границах, свечения, произвольные px-значения,
  радиусы больше 12, тени у карточек, z-index больше 1500.
```

### 9.2 Ещё надёжнее: отдать токены

Передать генератору готовый CSS с переменными и потребовать использовать только `var(--*)`. Тогда нарушение видно линтером (§3.1), а не глазами.

### 9.3 Итерация

1. Сгенерировать.
2. Прогнать §2 и §6.
3. Вернуть модели отчёт вида «правило → найдено → порог» и потребовать правок именно по нарушенным строкам.
4. Повторять, пока все строки OK.

Этот цикл работает лучше, чем переписывание промта: у модели появляется измеримая цель.

## 10. Быстрая диагностика без инструментов

Когда скрипт запустить негде (скриншот, макет, чужой продукт), порядок осмотра такой.

### 10.1 Приложить линейку к четырём местам

1. **Лейбл и поле** в форме: 4–8 px. Если 16, иерархии близости нет.
2. **Поле и следующее поле**: 16–24 px и обязательно больше, чем пункт 1, минимум вдвое.
3. **Padding карточки**: 16 или 24, одинаковый у всех карточек экрана.
4. **Высота кнопки и высота поля** в одном ряду: должны совпасть.

Четыре замера отсеивают большинство машинных макетов.

### 10.2 Прищуриться

Расфокусированный взгляд убирает текст и оставляет пятна. Что видно:

- **группы должны читаться как пятна с промежутками**, а не как равномерная сетка;
- **главный блок должен иметь больше воздуха** вокруг, чем соседи;
- **линии не должны образовывать «клетку»**: если видна решётка границ, границ слишком много;
- **тени не должны быть заметны** на этом уровне: заметная тень у карточки почти всегда лишняя.

### 10.3 Посчитать разнообразие

Пересчитать по скриншоту:

| Что считать | Норма |
|---|---|
| Разных высот интерактивных элементов | 1–3 |
| Разных радиусов | 1–3 на экран |
| Элементов с тенью | 0–2 (в админке), 0–5 (в клиентском сервисе) |
| Разных толщин линий | 1 (плюс фокус) |
| Разных цветов границ | 1–2 |

### 10.4 Проверить края

- **Выравнивание левого края** всех блоков колонки: одна вертикаль.
- **Правый край** контента и правый край шапки страницы: одна вертикаль.
- **Первая и последняя строка списка**: одинаковый padding сверху и снизу.
- **Углы вложенных блоков**: внутренний радиус визуально меньше внешнего.

### 10.5 Пройти табом

Без всякого скрипта: нажать Tab десять раз и посмотреть, виден ли фокус на каждом шаге и не обрезан ли он. Это самая частая и самая дешёвая в исправлении ошибка.

## Чек-лист

- [ ] Есть скрипт, собирающий computed styles, и он запускается на каждой сборке?
- [ ] Порог «отступы из шкалы ≥ 95 %» выполняется?
- [ ] Уникальных высот контролов ≤ 3, все из ряда 24/28/32/36/40/48?
- [ ] Уникальных радиусов ≤ 6, теней ≤ 7?
- [ ] Все `z-index` из шкалы, максимум 1500?
- [ ] Ноль целей меньше 24 × 24 без зазора 4 px (и меньше 44 при эмуляции тача)?
- [ ] Ноль элементов без видимого индикатора фокуса при обходе табом?
- [ ] Stylelint запрещает литералы для padding, margin, gap, radius, shadow, z-index?
- [ ] Запрещены произвольные значения Tailwind в квадратных скобках для этих свойств?
- [ ] Визуальная регрессия снимается в светлой, тёмной и `forced-colors` темах?
- [ ] Прогон с `prefers-reduced-motion` и `prefers-reduced-transparency` проходит?
- [ ] Отчёт «правило → найдено → порог → вердикт» сохраняется вместе со сборкой?
- [ ] Промт для генератора содержит явные списки разрешённых значений и запретов?

## Открытые вопросы

1. **Порог 95 % для кратности выбран практически**, не из источника. Возможно, для сложных продуктов реалистичнее 90 %, а для дизайн-системы 99 %.
2. **Правило кругов из WCAG 2.5.8 реализовано в скрипте упрощённо** (проверяется зазор 4 px между прямоугольниками, а не пересечение кругов диаметром 24 px вокруг центров bounding box). Полная реализация требует геометрии кругов и учёта исключений Inline, Equivalent, Essential.
3. **Нет готового открытого инструмента**, который проверял бы всё перечисленное. Design Lint покрывает Figma, Stylelint покрывает CSS, Playwright покрывает runtime, но связного отчёта нет. Кандидат на разработку в рамках проекта.
4. **Стоимость `backdrop-filter` в кадрах не измерена** (см. `02-shadows-layers-depth.md`, открытый вопрос 4), поэтому порог «не больше двух» это инженерная оценка.
5. **Ошибки нейросетей описаны по наблюдаемым признакам,** а не по исследованию корпуса сгенерированных интерфейсов. Систематический разбор это тема агента волны 3 (`12-ai-generated-ui/`).
