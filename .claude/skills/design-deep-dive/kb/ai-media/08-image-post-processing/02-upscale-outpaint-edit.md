## 1. Апскейл

### 1.1 Когда апскейл вообще нужен

- Модели в polza отдают 1K–4K (`image_resolution`); цена ступени 4K у Seedream 4.0 — 3 ₽, у GPT 2.5 — 11 ₽
  (`../02-providers-platforms/02-polza-models-params-prices.md` §6.1) → **сначала выбрать модель и ступень**, апскейлить —
  только если нужного размера нет (hero 2560–3840 px для DPR 2) [документация, polza 2026-09-23].
- Практики: 2K лучше 4K для фото («4K is too smooth»; GPT Image 2 4K high «plasticky»; NB Pro 4K «strips out the film
  grain») [V:ttgNFJ25xfU 51:58–53:00]; «native beats upscale», Topaz «too AI too smooth» [1:00:05, 1:14:21]; Google — 2K+ для
  текста, 4K — для мелкого текста, для фото разницы «I don't know if I could tell» [V:y-RQ48sfPgM 25:32, 32:36, 35:39].
- Противоположная практика — «всегда прогоняем через upscale» (Maytoni, интерьерный свет) [V:5dnNUB27HBQ 26:35]; ETC «The
  Bends»: 8 бит 720/1080 → Topaz (Nyx денойз → Gaia) → 4K 16-bit EXR [V:y6GCXcLVYd4 14:21–15:23] — это кино-мастер, не веб.
  Позиция базы: для веба генеративный апскейл — исключение с проверкой, не шаг по умолчанию [спорно].

### 1.2 Локальный апскейл: Lanczos против Real-ESRGAN (H/02)

Эталон 1024², вход — уменьшение box ×4 и ×2; SSIMULACRA2 (90 ≈ без потерь, 70 — «высокое»):

| Картинка | ×4: Lanczos / x4plus / animev3 | ×2: Lanczos / x4plus→½ / animev3-x2 |
|---|---|---|
| рендер (банка, гладкий CG) | **79,6** / 47,9 / 59,2 | **86,2** / 65,2 / 70,9 |
| мешковина (регулярная ткань) | **48,9** / −41,2 / 1,7 | **74,7** / 15,1 / 57,1 |
| жаккард (органический узор) | **15,2** / −44,0 / −50,1 | **52,2** / −51,1 / −20,9 |

- «Энергия деталей» x4plus 1,2–2,1 от эталона — выдуманная резкость; глазами: мешковина превращается в сетку чёрных «окон»,
  жаккард — в плоскую «векторную» заливку [проверено: H/02, `sheet_upscale_x4.jpg`].
- Время на Iris Xe (Vulkan): x4plus ≈ 4,6 с на Мп выхода, animev3 0,4–0,8 с; модель задавать явно (`-n`), в README и
  бинарнике умолчание разное [проверено: H/02, P/10].
- Где Real-ESRGAN допустим: рисованная графика, аниме, видеокадры низкого разрешения, где «пластик» терпим (`VID-UPSCALE` —
  I); не для фото, текстур, волос, кожи, товара.

```bash
# Lanczos ×2 (Pillow 11.3) — консервативный путь по умолчанию · [проверено: H/02]
python3 -c "from PIL import Image; im=Image.open('in.png'); im.resize((im.width*2, im.height*2), Image.LANCZOS).save('x2.png')"
# Real-ESRGAN — только для графики; модель явно · realesrgan-ncnn-vulkan 20220424 · [проверено: H/02]
(cd 99-raw/tools/bin/realesrgan-ncnn-vulkan && ./realesrgan-ncnn-vulkan -i /abs/in.png -o /abs/out.png -n realesr-animevideov3 -s 2 -m models -g 0 -j 1:2:1)
```

## 2. Правка: процедура проверки (общая для базы)

### 2.1 Почему проверять всегда

- OpenAI: «The model uses the mask as guidance, but may not follow its exact shape with complete precision» [S6]; слайд
  OpenAI «nothing else was changed» [V:8kM5aDD5gLI 12:16] — маркетинг против документации; докладчик не уверен в полярности
  маски («could be the other way around») [V:8kM5aDD5gLI 50:23].
- Google: «pixel perfect… will not always 100% work» [V:H6ZXujE1qBA 14:13]; каждая правка перерисовывает весь кадр — детали
  деградируют с итерациями [V:SLnGJ9iezYo 02:02].
- PaintBench: точная пиксельная правка — NB2 17,1 ≈ GPT-Image-2 16,3 mIoU; все модели меняют в 50–1400 раз больше пикселей,
  чем нужно [исследование: E-helper J16].

### 2.2 Команда и поля отчёта

```bash
# edit_check.py 0.2 · Python 3.13 + numpy + scipy + Pillow (системные) · [проверено: 99-raw/experiments/H/03-edit-check]
python3 ../../scripts/ai-media/edit_check.py check ORIG.png EDITED.png --mask TARGET.png --mask-mode white \
        --match-color --composite --out out/            # → out/report.json, diff_heat.png, composite.png, sheet.jpg
# --mask-mode: white (белое = цель) | black | alpha (прозрачное = цель, как у OpenAI); без маски — проверка дрейфа всего кадра
# --protect PRODUCT_ALPHA.png — защищённая зона (товар, логотип); --feather PX — растушёвка композита (по умолчанию 4)
```

| Проверка | Поле `report.json` | Порог | Если не прошло |
|---|---|---|---|
| совмещение | `shift_px`, `shift_applied` | сдвиг принимается, только если снижает MSE вне цели ≥ 10 % (ложный сдвиг 2,9 px на гладком фоне отклонён) | — |
| утечка вне цели | `outside_leak_frac` (ΔE00 > 5 вне цели и полосы 6 px, после открытия 3×3) | ≤ 0,02 (C1-12) | `LEAK` → композит (§2.3), не перегенерация |
| общий дрейф цвета | `global_drift.global_de00` | ≤ 2 | `--match-color` |
| правка выполнена | `target_changed_frac` | ≥ 0,2 | `NO_EDIT` → перегенерация или другая модель |
| геометрия при правке света/цвета | `edges_iou` | ≥ 0,9 (W6-4); фон при перекадровке ≥ 0,8 (W6-6) | правка «съела» формы |
| защищённый объект | `protect.ssim`, `protect.de_median` | ≥ 0,9 и ≤ 5 (A-3) | вставка объекта по альфе (§3) |
| композит | `composite_outside_de_max` | 0 вне полосы | — |

Карта `diff_heat.png`: чёрное — ΔE00 < 2, жёлтое ≈ 5, красное ≥ 10; `sheet.jpg` — оригинал | правка | карта | композит —
его и показывать заказчику [проверено: H/03].

### 2.3 Дрейф цвета и композит

| Случай H/03 (подложка Blender + артефакты модели) | Утечка | Дрейф ΔE00 | Медиана ΔE вне цели | Доля вне цели с ΔE > 2 |
|---|---|---|---|---|
| идеальное удаление (эталонная подложка) | 0,0001 | 1,05 | 0,72 | 0,24 |
| «как модель»: цвет ×(1,03; 1; 0,97), перерисовка, сдвиг 0,6 px, JPEG 90 | 0,0087 PASS | **3,33** | 3,69 | **0,97** |
| то же + `--match-color` | 0,0019 | подогнан | **0,90** | 0,14 |
| + угол фона светлее на 8 % | **0,131 LEAK** | 3,39 | 3,70 | 0,97 |

- `--match-color`: по каждому каналу МНК `E·gain + offset ≈ O` на пикселях вне цели и полосы; применяется ко всему кадру правки
  до ΔE и композита. Редакторы дают лёгкий сдвиг цвета — его подгоняют к исходному кадру [V:WmC1nqz10Qk 06:19].
- **Подгонка цвета может спрятать утечку** [поправка X 24.09.2026 по K]: случай «угол фона светлее на 8 %» — LEAK 0,131 без
  подгонки и PASS 0,0001 с `--match-color` (локальная утечка уходит под порог ΔE 5 вместе с общим сдвигом). Поэтому вердикт
  утечки — по прогону без подгонки **и** по локальному сдвигу `asset_audit` (связные области ΔE00 > 3 площадью ≥ 1 % вне цели
  → `QA-EDIT-LOCAL-SHIFT`; отличить утечку от «призрака» §2.4 кодом нельзя — смотреть `composite.png` и `sheet.jpg`) —
  `../11-evaluation-qa/01-metrics-and-asset-audit.md` §3.3 [проверено: K/02].
- Композит = правка внутри цели (маска, расширенная на `feather` и размытая) + оригинал снаружи, вне полосы — ровно
  оригинал. Без подгонки цвета на границе маски виден шов (`cases/modellike/sheet.jpg`), с подгонкой — слабый
  (`cases/modellike_mc/sheet.jpg`) [проверено: H/03].

### 2.4 Удаление объекта: «призрак» и ширина маски

Удалённый объект освещал и затенял окружение далеко за своим контуром (полутень, отражённый свет). ΔE00(оригинал, эталонная
подложка) по кольцам от маски «объект + тень + 6 px» на кадре 1024² [проверено: H/03 `ghost_zone.py`]:

| Расстояние от маски | 0–6 px | 6–16 | 16–32 | 32–64 | 64–128 | 128–256 |
|---|---|---|---|---|---|---|
| доля пикселей с ΔE00 > 2 | 0,54 | 0,52 | 0,43 | 0,42 | 0,32 | 0,10 |

- Композит «правка в маске + оригинал снаружи» оставляет контур маски **даже при идеальной подложке**: растушёвка 4 → 16 →
  32 px только смягчает (ΔE00 p95 к подложке 3,68 → 3,42 → 3,19); маска, расширенная на 96 px (≈ 9 % стороны), с растушёвкой
  32 px — контур не виден, p95 2,07 (`ghost_sheet.jpg`).
- Правило: маска удаления = объект + тень + дилатация ≈ 8–10 % стороны кадра, `--feather` ≈ 3 % стороны; модель получает ту же
  широкую маску (фаза 5 H-06 v3 против тугой v1). Практики делают так же: выделить объект, «expand the selection by a few
  pixels», Generative Fill [V:BVMuRw8BgJg 02:02] — «несколько пикселей» мало для мягкой тени.
- Маска без тени даёт ложную утечку (тень исчезла законно; в первом прогоне H — 11 %), а модель с такой маской оставит
  «призрак» тени.

## 4. Аутпейнт и семейство форматов

### 4.1 Кадрировать или дорисовывать

- Мастер генерировать с полем 10–15 % по краям, главный объект — в центральных 60 % кадра (A `01/01` §6); точка фокуса и
  `object-position` — у F (`../06-art-direction-consistency/03-composition-for-web.md`).
- Решение по мастеру W×H и формату w:h: доля ширины, которая остаётся при кропе по высоте, = (w/h) / (W/H); из 16:9 в 9:16 —
  0,316, в 4:5 — 0,45, в 1:1 — 0,56. Если рамка субъекта + 5 % поля шире этой доли — **аутпейнт или отдельная генерация**, иначе
  кроп [практика; гипотеза D: аутпейнт надёжнее кропа, когда субъект у края].
- Лидеры на телефоне у 8 из 10 показывают отдельный кадр 4:5–9:16 (A) — отдельная генерация под телефон — норма, не расход.
- Кроп — детерминированный кодом (нода, `sharp`, Pillow), не «перегенерировать похожее» [V:I9xdmNZxIfA 14:34]; подложку 4:5 не
  растягивать дублированием [V:BVMuRw8BgJg 07:28]; сетка 2×2 из одной генерации → нарезка + апскейл [V:ttgNFJ25xfU 27:30].
- Семейство форматов «1:1 → 10 ассетов»: «lock this in the center… paint around the outsides», system prompt «adapt the
  target aspect ratios while preserving the product fidelity» [V:AxV8TR3BdqI 27:43–29:46]; смена формата правкой «make it my
  9 by 16» [V:y-RQ48sfPgM 06:15].

## Частые ошибки

- Real-ESRGAN как «безопасный» апскейл товара или ткани — выдумывает структуру; Lanczos честнее.
- Апскейл после кодирования или зерно до апскейла — артефакты сжатия и шум раздуваются.
- Правка принята по одной картинке «выглядит так же» — без карты ΔE утечка и дрейф не видны.
- Порог утечки есть, дрейфа нет: весь кадр потеплел на ΔE 3, серия рассыпалась по цвету.
- Композит без `--match-color` — светлое «окно» по форме маски.
- Удаление объекта тугой маской (6 px) с композитом — «призрак» тени и отражённого света.
- Цепочка правок «ещё чуть-чуть» от последнего результата — копится мыло и сдвиг цвета.
- Критерий аутпейнта «SSIM центра ≥ 0,9» — пропускает перерисованный исходник (0,993).
- Зеркалить товар с надписью — зеркальный текст.
- **Ошибки нейросетей-агентов**: полярность маски «белое = менять у всех» (у OpenAI — прозрачное, у `gpt-5-image@mie` —
  чёрное); маска в GPT Image 2.5 polza (её нет); `openai/gpt-5-image` после 23.10.2026; вера слайду «nothing else was
  changed»; `quality`/`background` у GPT 2.5 в polza; апскейл 4K «для качества» у фото (2K лучше); «SSIM ≥ 0,9 — значит не
  перерисовано».

## Чек-лист

- [ ] Ступень разрешения модели выбрана под слот, апскейл нужен реально (нет нужного размера)?
- [ ] Апскейл фото/текстуры/товара — Lanczos или генеративный после слепого сравнения, не Real-ESRGAN?
- [ ] После правки прогнан `edit_check.py check` с маской цели: утечка ≤ 0,02, дрейф ≤ 2, `target_changed_frac` ≥ 0,2?

- [ ] Правка одна на вызов, ≤ 5 изменений, от утверждённого мастера?
- [ ] Товар защищён (`--protect`: SSIM ≥ 0,9, ΔE00 ≤ 5) или вставлен обратно по альфе с контактной тенью?
