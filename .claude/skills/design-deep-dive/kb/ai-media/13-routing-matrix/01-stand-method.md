## 3. Как собираются задания

1. **Сборка**: `99-raw/tools/venv-D/bin/python ../../scripts/ai-media/stand_run.py build` → `99-raw/phase5/jobs/E-*.jsonl`. Бриф →
   `prompt_compile.compile_prompt(spec, model)` в диалект семейства по умолчанию (`gpt-image`, `nano-banana` — sections;
   `flux2`, `seedream`, `qwen-image`, `z-image` — prose); параметры — только те, что есть в каталоге модели; лишние
   снимаются с записью в отчёт сборки. **Перед фазой 5 — пересобрать компилятором D2** (`meta.recompile_before_phase5`).
2. **Буквальные строки** (`tasks.yaml → literals`): тексты кириллицы и латиницы, правки, референс-оговорка товара («Image
   1 is the product reference… label text "ЛЕСНАЯ ОБЖАРКА"…»), префикс серии и черновика — одинаковы для всех моделей.
3. **Входы** — `99-raw/phase5/inputs/E/` (свои рендеры Blender 5.2.2, CC0): пакшот 1024², альфа, сцена 1024×576 с
   масками стены (48,9 %), стола, банки, этикетки, чашки (+6 px), английский баннер, заглушки 16:9 и 1:1. Выход другого
   теста как вход (эталон серии, черновик) — заглушка + `meta.inputs_from: "E-11#winner/0"`.
4. **Цена и провайдер — явно**: `provider: {only: [mie], allow_fallbacks: false}`, разрешение/качество в каждом задании,
   `seed` — только у Qwen 2.1 и Seedream 4 (101, 202), `max_rub` = оценка × 1,25; `stand_run.py estimate` → 86 заданий,
   0 ошибок, 435,10 ₽ [проверено: `polza.py estimate`, без сети].
5. **Метаданные для судейства** (`meta`): тест, задача, плечо, пресет, диалект, критерий, эталонные строки (`expect`),
   исходник и маска правки (`source`, `target`, `target_hex`), группы голосования (`vote_groups`: например, Sunburst 1K
   из E-08, 2K из E-09 и 4K из E-01 встречаются в одной группе «E-09/…»).

### 4.2 VLM-рубрика (фаза 5, модель выбирает K)

- **Допустимо**: чек-лист брифа — атомарные позитивные вопросы да/нет с зависимостями (готовые — `D/03…/ab/questions.json`
  для B1–B5: 10–12 вопросов), доля «да» с обнулением дочерних; «правка выполнена?» и отдельно «остальное не испорчено?»
  в обе перестановки A/B; предфильтр грубого брака перед показом человеку.
- **Недопустимо**: «что естественнее», «почерк слопа», анатомия, мелкие артефакты, текст, счёт предметов, абсолютные
  баллы, вопрос с полным промтом внутри («насколько соответствует» — судья додумывает соответствие, TIIF).
- **Доверие**: VLM принимается как судья задачи, если совпадает с решающими голосами заказчика на тех же парах ≥ 75–80 %
  (уровень GPT-4 ↔ эксперты в Chatbot Arena 76–81 %) — калибровка у K; судья не должен быть той же фирмы, что модель
  (T2I-CoReBench, ViStoryBench, OmniRef-Bench, LingT2I судят моделями Google, а наверху — Google) `[мнение]`.
  **Порог K (действует)**: согласие ≥ 0,8 при нижней границе Уилсона ≥ 0,65 и n ≥ 20 — «сортировать best-of-N»; 0,7–0,8 —
  «только отсеивать брак»; < 0,7 — не использовать (`../11-evaluation-qa/02-vlm-critic-and-rubrics.md` §6, `asset_audit.py
  agree`) [поправка X 24.09.2026 по K: «75–80 %» — ориентир без нижней границы интервала].

### 4.3 Слепые попарные голоса заказчика

`stand_run.py page results.jsonl --out stand-vote --tests …` → `stand-vote/index.html` + `img/` (самодостаточно: без
внешних библиотек, JPEG ≤ 1600 px или PNG при альфе); ключ `stand-vote.key.json` — рядом, в папку страницы не входит.

- **Пары**: внутри группы (тест/задача/плечо или `vote_groups`) — все пары разных моделей; порядок случайный, сторона
  случайная; 10 % пар повторяются во второй половине с переставленными сторонами; 1 контрольная пара на 20 (размытая копия
  должна проиграть); 1 пара «та же картинка с обеих сторон» (ожидается «равно» или «оба не годятся»).
- **Экран**: бриф задачи, эталон (для товара, серии, правки), две картинки одного размера, лупа (пробел, Tab — A/B на
  месте для мерцающего сравнения), фон тёмный / серый / светлый, **«Макет с текстом» (M)** — HTML-заголовок из брифа поверх
  зоны текста: пригодность для слота видна сразу. Клавиши ←/→/↓/X; комментарий «почему» по желанию.
- **Хранение**: `localStorage` + «Скачать голоса (JSON)» / «Скопировать»; «Загрузить» объединяет файл с текущими голосами.
- **Проверено** на 12 тестовых картинках (рендеры E/01 + синтетика): 28 пар, сценарный голосующий в Chromium за 12 с,
  Брэдли–Терри восстановил заданный порядок (1397,9 > 1000 > 602,1), повторы 2/2, контрольная 1/1, «одинаковые» 1/1;
  найдена и исправлена ошибка — после ввода имени клавиши уходили в поле [проверено].
- **Объём фазы 5**: тесты E-08–E-16 дают ≈ 85–95 пар → 10–15 минут на человека; вторая голосующая (оркестратор или
  коллега заказчика) удваивает мощность дешевле, чем новые генерации.

### 4.4 Агрегирование

- По паре моделей в задаче: доля побед по решающим голосам с 95 % интервалом Уилсона; ничья = 0,5; «оба не годятся» —
  отдельный счётчик (не в рейтинг). По категории и сквозь задачи — Брэдли–Терри (MM Hunter, шкала Эло, среднее = 1000);
  отчёт — диапазон мест, а не одно место (`stand_run.py tally`).
- Сколько голосов (расчёт по биномиальному тесту и симуляции BT, `99-raw/notes/wave2/E-helper-judging.md` §12): наблюдённая
  доля 0,70 значима при n ≥ 30, 0,80 — при n ≥ 15; мощность 80 % для истинных 0,70 / 0,80 — 54 / 23 решающих голоса; 4
  модели × 5–8 задач одной категории → полуширина разницы ±170…215 Эло (различимо ≳ 73/27).
- **Контроль стиля**: если голоса лучше объясняются насыщенностью и контрастом (`slop_color`), чем моделью, — это
  «эффект Instagram-фильтра» [V:KLDdXOw6jIc 34:38]: добавить признаки в BT и спросить заказчика вопросом 2.
- Позиционный сдвиг: доля левых выборов вне 0,4–0,6 при ≥ 30 решающих голосах — пересмотреть сессию.

1. Фильтры §4.1 (текст, альфа, размер, ΔE, «не тронуто») — модель, не прошедшая фильтр задачи, выбывает из неё.
2. Среди прошедших — голоса вопроса 1: лидер, если ≥ 70 % выигранных пар в задаче; модели в интервале лидера — равные.
3. Из равных — дешевле (₽ по каталогу на дату), затем быстрее (`wall_s` паспорта), затем с запасным провайдером.
4. Вопрос 2 — вето: победитель по слоту, проигравший ≥ 70 % пар по «естественности», помечается «почерк» и уходит в
   рубрику K; решение переходит ко второму месту, если оно в интервале лидера.
5. Запись: `routing.v0.yaml` → v1 (агент N) с меткой `[стенд]`, числом задач × моделей × повторов, типом судьи и датой:
   «`[стенд: 2 задачи × 6 моделей × 1, голоса 1 чел. + A/04, 2026-10-xx]`».
6. Порядок фазы 5 и экономия: E-01 первым (видимый знак Seedream через `mie` исключает Seedream из E-02, E-03, E-08,

### 6.2 Метрика дословности

`stand_run.text_check(expect, transcript)` [проверено: selftest 5 случаев]: NFC; тире и минус (−, –, —) → «-»; кавычки
«» → "; неразрывные пробелы → пробел; **внутри слов с кириллицей латинские двойники (A B E K M H O P C T X Y, a e o p c x y)
→ кириллица** (пикселями не различимы, OCR их путает — MDPBench, ScriptMoE у C1); дословность — строго и без учёта
регистра (модель вправе набрать заголовок капсом); CER лучшего окна; отдельно — латинские недвойники внутри русского
слова («ВЕСЕNNЯЯ» — фальшивая кириллица), потерянная «ё», лишние слова (precision, как в WeGenBench). Строгий минус U+2212
против дефиса OCR не отличает — проверять глазом на листе.

## Частые ошибки

1. **Место арены как ответ для polza**: арена мерила GPT Image 2.5 с `quality: max`, polza его не выставляет.
2. **Разные промты разным моделям** («подогнать под сильные стороны», как в GenAI Showdown) — сравниваются промты, а не
   модели; у стенда один бриф → один компилятор → диалект семейства.
3. **Лучшая из 20 против первой из 1**: отбор выхода сдвигает оценку до 31 п. п.; сравнивать равные N.
4. **Баллы 1–10 и VLM-эстетика**: у людей и VLM баллы расходятся, VLM ставит «камере» 9,2 стоящему кадру.
5. **Текст через VLM или «на глаз»**: латинская «Р» в русском слове проходит глазом; нужна сверка кодовых точек, но
   двойники — нормализовать, иначе ошибку OCR запишут модели.
6. **Имена моделей на странице** или в имени файла картинки — голос перестаёт быть слепым (у `stand_run.py page` имена
   файлов случайны, ключ вне папки).
7. **Одна сторона всегда слева**: перевес левой картинки реален (LMArena вводит поправку).
8. **«Доказать» 60/40 одним заказчиком**: нужно > 200 решающих голосов; равные по интервалу модели — выбирать по цене.
9. **Повторы одной задачи вместо новых задач**: голоса коррелированы — мощность не растёт.
10. **Seedream без E-01**: видимый «AI-generated» в прямом API — сначала 3 ₽ на проверку, потом серии.
11. **Ошибки агентов**: id «по памяти» (`openai/gpt-5-image` выключается 23.10.2026, `flux.2-flex` — дубль за 2,8×), NB Pro
    в 1K (2K стоит так же), `aspect_ratio: auto` у GPT 2.5 (только 1K), Seedance 2 без `duration` (415 ₽).

## Чек-лист

- Спорна ли развилка (арены и документация расходятся или молчат) — иначе тест не нужен?
- Кандидаты — в конфигурации polza, с явными ценовыми параметрами и `provider`?
- Промт собран компилятором в диалект по умолчанию или одной буквальной строкой для всех, диалект в `meta`?
- Задач больше, чем повторов на задачу?
- Жёсткие требования проверяются кодом до голосования?
- На странице нет имён, стороны случайны, есть повторы, контрольная и «одинаковая» пара?
- Голосующий видит бриф, эталон и «макет с текстом»?
- Итог записан с `[стенд]`, N задач × моделей × повторов, типом судьи и датой?
- Равные по интервалу модели решены ценой и скоростью, а не точечной оценкой?
- Для новой модели прогнан мини-стенд, для смены версии — регрессионные ворота?
