## 1. Что решает код, что VLM, что человек

| Слой | Что решает | Чем | Когда доверять |
|---|---|---|---|
| 1. Метрики (`asset_audit.py`) | измеримое: размер, пропорция, альфа, утечка, шов, живость, склейка, камера, звук, палитра, зона текста, контраст, дословность текста, серия, вес, качество сжатия | утилиты волн 1–2 + OCR | всегда; пороги со `status: calibrated` — жёстко, `position`/`uncalibrated` — как сигнал |
| 2. VLM-критик (`02`) | смысл: пункты брифа да/нет, крупные маркеры «сгенерированности» с «где», узнаваемость иконки | `judge-jobs` → `mp_client.py` | после калибровки фазы 5 (K-01, K-02, K-06): согласие с заказчиком ≥ 0,8 |
| 3. Человек за 2 минуты (`03`) | анатомия, функциональные ошибки предметов, физика теней, сходство с оригиналом, латиница-«близнец» в тексте, пульс петли | чек-лист по типу ассета | всегда для hero, товара, OG |
| 4. Заказчик вслепую | эстетика и выбор из годных | `stand_run.py page` + `tally` | единственный арбитр вкуса [V:H6ZXujE1qBA 25:29] |

Почему так (подробно — `02` §1): судья поставил 9,2 за камеру стоящему кадру [V:b_PmGocP4rc 10:16]; o3 назвал уродливую руку
«mostly natural» [V:h5ItAJuB3Fc 00:01]; Gemini 3.1 Pro — 48,6 % в попарной реалистичности видео и 9,8 % в назывании артефакта
против 86,4 / 80,3 % у экспертов [S16]; VQA по тексту — 13,7 % [S12]; CLIPScore, LAION Aesthetics и FID — r 0,39–0,59 с людьми
[S20], FID «horrible» от одних JPEG-артефактов [V:h5ItAJuB3Fc 06:07].

**Семантика вердикта** (поле `verdict` отчёта): максимум уровней дефектов. `fail` — жёсткий брак (не та пропорция, нет
альфы, шахматка, правка не выполнена, аутпейнт перерисовал исходник, шов петли на мезонине, склейка, угасание, слабое
движение к контролю, текст не совпал уверенно, шапка иконки, растр в SVG, распад серии, SSIMULACRA2 ниже порога);
`needs_human` — нужен глаз на конкретный фрагмент (текст с похожими буквами или ё, шов сжатого файла, кластер маркеров,
безмасочная правка, метка в углу, ошибка инструмента); `warn` — отклонение от нормы, не брак само по себе; `info` — факт для отчёта.

### 2.3 Вход: паспорта

Папка → все `*.passport.json` (`polza-passport/1` от `polza.py`, `mp-passport/1` от `mp_client.py`) и их `files[]`, плюс медиа
без паспорта. Из паспорта берутся: модель, провайдер, канал, цена, заказанные `aspect_ratio`/`resolution`/`duration`
(проверка пропорции), `meta.code` (режим и слот), `meta.expect` (строки текста), `meta.source` (исходник правки), sha256
(`QA-FILE-CHANGED`, если файл изменён после скачивания). Режим и слот можно задать явно (`--mode`, `--task`, `--slot`).

### 2.4 Выход (`asset-audit/1`)

`OUT/audit.json` — сводка и массив ассетов; `OUT/audit.md` — таблица; `OUT/<файл>_panel.jpg` — панель для человека (полоса

шахматке); `OUT/index_sheet.jpg` — все панели; для правок — `OUT/<файл>_edit/{sheet.jpg, composite.png, diff_heat.png,

## 3. Проверки по режимам: пороги и источники

Статус: **c** — calibrated (опыт базы), **p** — position (позиция на синтетике или по аналогии), **u** — uncalibrated
(эвристика K, пересмотреть в фазе 5).

### 3.3 Правка и аутпейнт (`edit`)

Пропорция исходника и результата отличается > 1 % → аутпейнт (`edit_check.py outpaint --composite`): PASS = SSIM центра
≥ 0,9 **и** ΔE00 медиана ≤ 3 **и** резкость краёв ≥ 0,85, иначе `QA-OUTPAINT-REGEN` fail + `composite.png` (исходник
вставлен с субпиксельным сдвигом) [проверено: H/03 — перерисовка с SSIM 0,993 ловится резкостью 0,744].

С маской → `edit_check.py check --match-color --composite` (утечка ΔE00 > 5 вне цели ≤ 0,02, дрейф ≤ 2, в цели изменено
≥ 20 %, `edges_iou` ≥ 0,9 для правок света и цвета, `--protect`: SSIM ≥ 0,9 и ΔE00 медиана ≤ 5) **плюс** своя проверка
K `local_shift`:

| Кейс H/03 | edit_check без подгонки | с `--match-color` | `local_shift` (ΔE00 > 3, ≥ 1 % «вне цели») |
|---|---|---|---|
| идеальное удаление | PASS 0,0001 | PASS 0,0 | 0 областей |
| «как модель» (сдвиг цвета, перерисовка) | PASS 0,0087 | PASS 0,0019 | 2 (3,0 %, ΔE 3,9 — у маски: «призрак») |
| + угол светлее на 8 % | **LEAK 0,131** | **PASS 0,0001** | 2 (**13 %, ΔE 4,4**) |

Подгонка цвета снимает общий сдвиг модели (3,3 ΔE), и локальная утечка остаётся ниже порога 5 — робастная подгонка
внутри `edit_check` (пробовал, откатил) даёт 0,0104, всё равно PASS [проверено]. Поэтому `asset_audit` делает
подгонку по «устойчивым» пикселям (второй проход без остатка > 3) и ищет связные области ΔE00 > 3 площадью ≥ 1 % «вне цели»
→ `QA-EDIT-LOCAL-SHIFT` (warn: утечка слабее порога или «призрак» света вокруг изменённого объекта — маска шире,
H 08/02 §2.4). Уровни: LEAK → warn (лечится композитом, не перегенерацией — H), NO_EDIT → fail, защита товара → fail.

Без маски (безмасочная правка, D2 просил): маска из разницы — ΔE00 до и после подгонки цвета по 60 % самых спокойных
пикселей, порог 5, открытие 3×3, закрытие 5×5, области ≥ 0,05 % кадра; изменено < 0,2 % → `QA-EDIT-NOEDIT` fail;
> 50 % → `QA-EDIT-REDRAW` warn (перерисовка); областей больше `--changes` + 2 → `QA-EDIT-EXTRA-REGIONS` warn; маска
расширяется на 2 % стороны (`--removal` — растушёвка 3 %) → композит через `edit_check`; «что изменено по заказу» — глаз
(`needs_human`). Удаление объекта: маска модели и композита — объект + тень + 8–10 % стороны (H 08/02 §2.4).

## 4. Текст в картинке: OCR кириллицы (K/01)

### 4.1 Движок

RapidOCR 3.9.2 (Apache-2.0, ONNX Runtime 1.30, CPU): детектор `PP-OCRv6_det_small` (из колеса), распознаватель
`eslav_PP-OCRv5_rec_mobile` (русский, белорусский, украинский, английский; 81,6 % на 7 031 строке по данным PaddleOCR [S24]),
второй распознаватель `en_PP-OCRv5_rec_mobile` — «латинский нюх». PP-OCRv6 кириллицу не распознаёт (китайский, английский,
японский и 46 латинских языков [S25]) — годится только детектор. Масштаб входа детектора `max 1600` (умолчание RapidOCR
«min-сторона → 736» раздувает узкий баннер ×3,6: 1,0 с вместо 0,06 и хуже точность). Строки: слова детектора
группируются по вертикали и распознаются заново одной рамкой — иначе буква на стыке читается дважды («Весенняяр»).
Медиана 0,07 с на картинку (p90 0,25 с), пик 0,55 ГБ; запуск — под `heavy.lock`, при < 1 ГБ available OCR не стартует.

Почему не VLM: на сквозном многоязычном OCR (CC-OCR) русский F1 у Qwen3.5-9B 78,97, Gemini-3.5-Flash 67,21, GPT-5.6-Terra
63,49 — не выше специализированного конвейера (PP-OCRv5 Det + ScriptMoE 79,22); «русский разрыв — путаница кириллицы и
латиницы» [S23]. VLM-расшифровка против OCR на нашей истине — задание K-05 (≈ 1 ₽).

### 4.2 Сверка и политика (`text_verdict`)

Нормализация E (`stand_run.norm_line`: NFC, тире и кавычки, двойники внутри русских слов → кириллица) + K: если в строке
брифа нет латиницы, двойники заменяются и в словах без кириллицы (однобуквенное «K»). Выравнивание строки брифа по
транскрипту (нечёткий поиск) → классы ошибок: `omission`, `doubling`, `insertion`, `latin_substitute`, `yo_lost`,
`similar_cyr` (и↔й, ш↔щ, б↔в, п↔н…), `digit_confusion` (О/0, З/3, б/6), `case`, `punct`, `spacing`; лишний текст — слова
транскрипта вне найденных окон (только буквы и цифры, висящая точка не в счёт; разрешённый текст — `--allow-text`, например
этикетка); GNED (TIIF-Bench [S13]: согласие с людьми 99 % против 83 % у OCR Recall).

| Решение | Условие | Доля на 570 синтетических баннерах (K/01, без развёртки кегля) |
|---|---|---|
| `pass` | все строки дословно, ни латиницы, ни лишнего, «латинский нюх» молчит | верные строки: 65/72; двойники: 66/72 |
| `fail` | классы только из надёжных (пропуск, удвоение, лишнее слово, явная латиница, потеря строки), уверенность OCR ≥ 0,9, строка ≥ 16 px | ложный брак: **0/72** верных, 1/72 двойников; пропуск 60/72, удвоение 55/72, лишнее слово 64/72, Я→R 6/7 |
| `needs_human` | остальные расхождения, ё → е, «латинский нюх», мелкая или неуверенная строка | похожие буквы 68/72; Д→D 5/5 (нюх); л→n 10/10 |

Ошибка не проходит как `pass`: пропуск 72/72, удвоение 72/72, лишнее слово 72/72, похожая буква 69/72, ё 12/12.

### 4.3 Что OCR не ловит

«Самоисправление»: распознаватель с языковой «догадкой» читает видимую латиницу как кириллицу — «DОСТАВКА» → «ДОСТАВКА» 5/5
(в т. ч. 64 px на белом), «nодробнее» → «подробнее» 4/4, «u» → «и» 15/15, уверенность 0,82–0,997 его не выдаёт.
Английский распознаватель по той же рамке видит D 5/5 (ложных 1/144), R 5/7 (0/144), g 9/16 (2/144) → класс
`latin_suspect` → человек; n, u, r этим способом шумят (34, 8, 6 ложных из 144) и не используются. Цифры вместо букв (0/О,
3/З, 6/б) OCR тоже «исправляет» (пойман 3/60). Итог: **в hero, OG и на упаковке текст читает человек по буквам на 200 %**
даже после `pass`; VLM здесь хуже (сильнее языковая догадка; VQA по тексту 13,7 % [S12]).

### 4.4 Незаказанный текст и реальные рендеры

- На 23 картинках без текста (CC0-фото, мудборд F, hero H, кадры I) — 0 строк из ≥ 2 букв с уверенностью ≥ 0,6 (были «2»
  0,39 и «____» маски) → правило `QA-TEXT-UNREQUESTED` (псевдотекст, «сайт с псевдотекстом» W2, мелкий текст — индикатор
  брака W6).
- Этикетка банки E (рендер Blender, кириллица на изогнутой поверхности): «ЛЕСНАЯ ОБЖАРКА», «кофе в зёрнах · 250 г»,
  «ARABICA 100%» — дословно на плоской этикетке, на банке 1024² и в сцене 1024×576 (строки 27–131 px, уверенность 0,93–1,0).
- Для стенда E: `asset_audit.py ocr <папка> --transcripts-out t.json` → `stand_run.py metrics results.jsonl --transcripts t.json`.

## 6. Калибровка порогов

- В `thresholds.yaml` у каждого из 94 порогов `status`: 45 calibrated, 41 position, 8 uncalibrated (эвристики K: событие в петле,
  мерцание, безмасочная правка — 3 порога, битрейт мезонина, локальный сдвиг ≥ 1 %). Правка порога — только с новым `source`.
- Фаза 5, 0 ₽ (K-07): `asset_audit.py audit` на первых 10 картинках + метки заказчика «годится / нет» (`labels.jsonl`:
  `{"file": …, "label": "ok"|"bad"}`) → `asset_audit.py calibrate --audit audit.json --labels labels.jsonl --metric
  checks.text_zone.edge_density` → порог Юдена, AUC; при n < 20 — ориентир, не замена; расхождение > 30 % с YAML → правка.
- Видимость пульса петли (K-08, 0 ₽): мезонин и H.264 CRF 23 одной петли (K/03 c00, c10) — 3 повтора подряд вслепую.

## Частые ошибки

- Проверять утечку правки только после `--match-color`: локальная утечка слабее ΔE 5 исчезает (H/03: LEAK → PASS) → §3.3.
- Мерить шов на финальном H.264: пульс ключевого кадра даёт 3,4–5,5 на идеальной петле; CRF 10 — тоже не мезонин → §3.6.
- Судить «живость» без i2v-контроля: равномерно слабое движение метрикам без контроля не видно → §3.6.
- Считать «pass» OCR гарантией кириллицы: «близнецы» латиницы и цифры OCR исправляет молча → §4.3.
- RapidOCR «как есть»: в PP-OCRv6 кириллицы нет (бракуется всё), умолчание 736/min раздувает баннеры (×16 медленнее) → §4.1.
- Брать абсолютные пороги цвета как брак: у 9 из 51 фото лидеров тёплый белый — стиль; фильтр — к эталону бренда → §3.1.
- Судить ореол выреза по эвристике на стекле и дыме: кайма законно отличается от «ядра» → info, смотреть на контрасте → §3.2.
- Импортировать скрипты опытов (`f83_check.py`, `banding.py`, `seam_lab.py`, `validate.py`): при импорте пишут файлы в чужие папки — брать модули (`text_zone`, `composition_metrics`).
- Ошибки нейросетей-агентов: FID/CLIPScore как «качество»; «VLM проверит текст»; «пороги из памяти» вместо YAML; `--mode`
  по расширению без паспорта (правка без `--orig` — это просто картинка); «Gemini судит Nano Banana» без второго судьи (`02`).

## Открытые вопросы и противоречия

1. Все пороги OCR — на синтетике шрифтами системы; ИИ-кириллица ломается иначе (полубуквы, «плывущие» глифы) — доля
   `needs_human` на выходах E-02…E-04 неизвестна (K-05, E).
2. Цвет-метрики A/04 не различают ИИ и фото (A/04) — «слоп» живёт в содержании; вклад метрик в кластер маркеров —
   позиция K, не калибровка.
3. `local_shift` ловит и утечку, и «призрак» удаления — различать их кодом не удалось (угол-утечка H/03 тоже касается маски);
   порог 1 % и ΔE 3 — uncalibrated.
4. Спор «шов на сжатом файле»: I и K — мерить мезонин; но на сайт идёт сжатый файл — виден ли пульс глазу (K-08)?
5. `static_frac` 0,3 едва не пропускает стоп-кадр 1,5 с (0,294) — поломку ловит `cut_ratio`; для стоп-кадра без рывка
   (заморозка в конце) порог может быть мягким.
6. Оптического потока нет (OpenCV в venv-K есть с 23.09 — `opencv-python` 5.0): направление движения, пинг-понг и
   «кипение» фактур мерить потоком — кандидат в v0.2.
7. `check_icons` откалиброван на линейных иконках Lucide; для заливочных наборов порогов нет.
8. Бюджеты веса (A 01/01) — для лендинга; у e-commerce и медиа другие.
