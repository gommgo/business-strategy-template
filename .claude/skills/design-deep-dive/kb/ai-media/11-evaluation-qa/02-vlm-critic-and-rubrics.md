## 2. Режимы судьи

### 2.1 `checklist` — пункты брифа (DSG)

- Вопросы из спецификации ассета: сущности (1-кортежи) → атрибуты (2) → отношения (3); у дочернего `depends` на родителя;
  без дублей; стиль, свет и камера — отдельными вопросами; готовые наборы — `99-raw/phase5/inputs/D2/questions_v2.json`
  (8 брифов, 10–12 вопросов, типы entity / attribute / relation / composition / light / camera / style / count / palette /
  text / probe / keep). Общие вопросы рубрики (`checklist_generic`) — только если брифа нет.
- Форма: позитивная, одна мысль, без «no / without / not» (NegBench [S8]: у CLIP-подобных отрицание — случай, у
  инструктивных VLM лучше, но риск остаётся): не «Is there no person?», а «Is the room unoccupied?» (D2 B1 q11).
- Ответ `yes | no | unsure`; балл — доля «да» с обнулением дочерних (`ab_analyze.score`); `unsure` = «нет» в балле, но
  считается отдельно (доля неуверенности — сигнал плохого вопроса). Зонды (`type: probe`, D2 p1 «есть ли человек») — в балл
  не входят. Счёт и текст в вопросах — только грубо («is there a headline?»), дословность — OCR.

```text
// google/gemini-3.1-flash-lite · polza 2026-09-23 · system (все рубрики) · [не проверено]
You are a strict visual inspector of images made for websites. Judge only what is clearly visible in the image. Do not
assume the image matches any description. Reply only with JSON in the requested format. If you cannot see something
clearly, answer "unsure".
```

```text
// checklist · user · вопросы из questions_v2.json (D2, бриф ab-b1-hero) · [не проверено]
Answer every question about the image with yes, no or unsure. Questions:
q1: Is there an armchair?
q2: Is the armchair mustard yellow?
q3: Is the armchair located in the right third of the image?
q7: Is the left 40 percent of the image a plain, evenly lit wall?
q11: Is the room unoccupied?
```

### 2.2 `defects` — маркеры с «где»

Вопросы рубрики — маркеры A 01/03 §5.2 (IMG-M01…M25) и §5.3 (VID-M…), коды дайджестов (RUB-*), по одному признаку,
«да = дефект». Метка допуска у каждого вопроса: `yes` — VLM можно, `partial` — только предфильтр, `metric` — решает
метрика, `no` / `reference` — только человек или сравнение с референсом. В задание идут только `yes` (hero: 20 вопросов — 18 маркеров и 2 ворот L 04 §5: `RUB-LEGAL-FACE`, `RUB-LEGAL-MARK`).

```text
// defects · user · рубрика hero-photo (фрагмент) · [не проверено]
Inspect the image for each listed defect. For every code set present to yes, no or unsure. If yes, you must fill `where`
with a short location in the image (for example "left hand of the man", "top-right corner") and set severity to minor or
major. Report a defect only if you can point to it. Defects:
IMG-M05: Is the image dominated by purple-blue neon tones with glow?
IMG-M07: Does the image show a glowing brain, a robot, a hologram or an abstract 'neural network' as a symbol of technology?
RUB-MOCKUP-INSTEAD: Does the image show a device, poster, website or frame containing the asset instead of the asset itself?
RUB-UNASKED-ACCESSORY: Are there accessories or marks nobody asked for (rings, jewelry, watches, tattoos, logos)?
```

Найденный маркер — не брак, а `needs_human` с фрагментом; кластер (≥ 3, в ключевом слоте ≥ 2) подтверждённых маркеров —
не публиковать (A 01/03 §5.1). Коды RUB-*: дубль субъекта [V:H6ZXujE1qBA 12:11], «ассет в окружении вместо самого ассета»
и «сайт с псевдотекстом» (W2), «иллюстрация ключевых слов» (W6), незаказанные аксессуары [V:KLDdXOw6jIc 40:44], глянцевая
идеализация [V:bH2nP-aCFjk 11:19], переобработка и естественность встройки товара (W5), перегруженность (W2, F/04).

### 2.3 `pairwise` — A/B/tie/both_bad

- Те же вопросы, что у заказчика на странице `stand_run.py page`: `slot` («что лучше для слота на странице») и `natural`
  («что естественнее и ближе к брифу»); для правок — `edit_done`, `rest_intact`, `slot` раздельно (GEditBench v2 [S4]).
- Ответ: `A | B | tie | both_bad` + коды, решившие выбор. «Оба не годятся» — отдельный сигнал «менять подход, а не модель».
- Слепота: имена файлов нейтральные, модель, плечо, цена — только в ключе; стороны — случайно; 10 % повторов (в K-04 —
  100 %) всегда с переставленными сторонами (`judge-jobs` это гарантирует — тест).
- Кодирование: варианты одной пары — один формат и качество (иначе судья выбирает сжатие — проверка K-04). С
  `--from-stand-page` судья получает те же файлы, что заказчик (`<страница>/img/*`, JPEG q90 ≤ 1600 px), а `agree` сверяет
  выбор по исходникам сторон (`A_orig`/`B_orig` в ключе); пары вне страницы — `--same-encoding DIR` (так же, JPEG q90 ≤ 1600 px).

```text
// pairwise · user · рубрика hero-photo · {brief} — текст брифа пары · [не проверено]
Images A and B are two candidates for the same website slot. Brief: {brief}. For each question choose A, B, tie
(equally good) or both_bad (neither is usable). Judge only visible content; ignore differences in file size and
compression artifacts. Questions:
slot: Which image works better in its slot on a website page, as it would actually be placed?
natural: Which image looks more natural and closer to the brief (less 'made by AI')?
```

### 2.4 `transcribe` — дословная расшифровка (только для сверки с OCR, K-05)

«Transcribe all text visible in the image exactly as written, letter by letter, preserving case, punctuation and line breaks.
Do not correct spelling and do not translate.» Ответ `{"lines": […]}` → `text_verdict` против истины, как у OCR.

## 3. Схема ответа и разбор

`rubrics/judge-response.schema.json` (JSON Schema 2020-12, подмножество structured output Gemini/OpenAI: object, required,
enum, `additionalProperties: false`): `checklist_answer` (`answers[{id, answer: yes|no|unsure}]`), `defects_answer`
(`defects[{code, present: yes|no|unsure, where, severity: none|minor|major}]`), `pairwise_answer` (`answers[{id, winner:
A|B|tie|both_bad}], defect_codes[]`), `transcribe_answer` (`lines[]`). У моделей со structured output (`response_format`
в `supported_parameters` каталога) схема уходит в запрос (`json_schema`, `strict: true`); у остальных (qwen3.5-9b —
только `max_tokens`) — формат словами + образец. `judge-parse`: извлечь JSON (в т. ч. из ```json), проверить схемой
(встроенный валидатор), нормализовать; «да» без «где» (< 3 символов) → `unsure` с пометкой в `problems`.

```json
// defects_answer · пример разбора · [не проверено: живой ответ — фаза 5]
{"defects": [{"code": "IMG-M05", "present": "no", "where": "", "severity": "none"},
             {"code": "RUB-UNASKED-ACCESSORY", "present": "yes", "where": "ring on the left hand of the woman", "severity": "minor"}]}
```

## 4. Рубрики по типам ассетов

Формат `*.rubric.json`: `rubric`, `version`, `applies_to` (коды задач), `slot`; `automated` (режим `asset_audit`, проверки,
`fail_codes`, `warn_codes`); `vlm` (`role`, `modes`, `checklist_generic`, `defect_questions` [допуск yes],

### 6.2 Как собрать и посчитать

```bash
# asset_audit.py 0.1 · [проверено: тесты — повторы со сменой сторон, agree 20/25 → 0,8; страница → файлы страницы, agree 3/3]
python3 ../../scripts/ai-media/asset_audit.py judge-jobs --rubric hero-photo --from-stand-page out/stand-vote --mode pairwise \
        --repeat 0.1 --test K-01 --out 99-raw/phase5/jobs/K-01-pairwise-vs-votes-gemini.polza-chat.json
python3 ../../scripts/ai-media/mp_client.py estimate 99-raw/phase5/jobs/K-01-pairwise-vs-votes-gemini.polza-chat.json --summary
python3 ../../scripts/ai-media/mp_client.py batch 99-raw/phase5/jobs/K-01-pairwise-vs-votes-gemini.polza-chat.json --live   # фаза 5, оркестратор
python3 ../../scripts/ai-media/asset_audit.py judge-parse --passports 99-raw/experiments/_mp/K/<дата> \
        --keys 99-raw/phase5/jobs/K-01-pairwise-vs-votes-gemini.keys.json --out k01_answers.jsonl
python3 ../../scripts/ai-media/asset_audit.py agree --answers k01_answers.jsonl --votes votes-<заказчик>.json --key out/stand-vote.key.json
python3 ../../scripts/ai-media/asset_audit.py agree --answers k02_answers.jsonl --labels k02_labels.jsonl      # {"key", "answers", "types"}
```

`agree` отдаёт по каждому вопросу: согласие, 95 % интервал Уилсона, n, решение («доверять» / «только предфильтр» / «не
использовать» / «мало данных»); согласованность повторов; долю выборов «A»; для чек-листа — κ Коэна, долю «да» судьи и
человека, согласие по типам вопросов. Разметка заказчика для K-02 и K-06 — те же вопросы и маркеры, 1–2 оси на пример,
сессии 10–15 минут [V:b_PmGocP4rc 18:28]; второй голосующий (оркестратор) удваивает мощность дешевле генераций (E).

### 6.3 Сколько нужно данных (E-helper §12)

| Наблюдённое согласие | n, при котором нижняя граница Уилсона > 0,5 | Для 95 % ДИ ± 10 п. п. |
|---|---|---|
| 0,70 | 30 | ≈ 80 |
| 0,80 | 15 | ≈ 60 |
| 0,90 | 10 | ≈ 35 |

Попарные предпочтения между моделями: 60/40 не доказать (> 200 решающих голосов на пару), 70/30 — 50–70, лидера выбрать —
20–30; единица выборки — задача, а не голос (лучше 40 задач по 1 голосу, чем 10 по 4). Поэтому K-01 даёт оценку судьи с
ДИ ≈ ± 10–12 п. п. — достаточно для решения «пускать / не пускать», не для тонкого сравнения судей.

### 6.4 Когда пересчитывать

Новая версия модели судьи в каталоге, правка рубрики (версия), новый класс ассетов, доля «unsure» > 20 %, расхождение
судьи и заказчика в 3 сессиях подряд. Порог — те же 20 решающих голосов на новой паре «судья × рубрика».

## 7. Видео: только кадры и только смысл

- Вход — контактный лист (`99-raw/experiments/K/03-video-negatives/sheets.py`: 16 кадров с номерами + «последний →
  первый»; без полосы |Δ|); вопросы — смысл (есть ли продукт, та ли сцена, нет ли клише) и, для проверки, временные оси
  (K-03: стоп-кадр, слабое движение, склейка, стык, дрейф камеры, яркость, событие, разворот).
- Истина K-03 — `vlm_truth.json`: 14 заложенных признаков на 13 листах (12 поломок + чистый); метрика ловит 12/12 поломок (01 §3.6). Ожидание:
  VLM видит склейку и вспышку на кадре (попадает в лист), не видит стоп-кадр, слабое движение, пинг-понг, дрейф камеры.
- Реалистичность и «естественность» видео — только голоса на одинаково перекодированных роликах (b_PmGocP4rc 11:17).

## Частые ошибки

- Спрашивать «хорошо ли?» или «насколько соответствует промту?» — вайб и додумывание вместо осей → §1–§2.
- Считать ответ «да» VLM фактом: смещение к «да» (LLaVA 80 % на «нет»-вопросах) → «unsure», контроль доли «да» → §5.
- Показывать судье имена моделей или один и тот же порядок A/B → позиционный сдвиг → §2.3.
- Сравнивать варианты с разным сжатием → судья выбирает кодек → §2.3, K-04.
- Судить Nano Banana судьёй Gemini без второго судьи → §5, K-01b.
- Давать видео через `video_url` с локальным файлом: работает только YouTube и только Gemini → §5, §7.
- Верить уверенному тону: судья «in a very confident way» ошибался [V:b_PmGocP4rc 10:16] → калибровка до доверия → §6.
- Ошибки нейросетей-агентов: «VLM проверит текст и цвет» (нет: OCR и OKLab), «VLM оценит эстетику» (нет: голоса),
  «баллы 1–10 надёжнее», «рассуждение перед ответом улучшает судью» (у малых — хуже, GEditBench v2), «Gemini 3 Pro —
  лучший судья видео» (48,6 % попарно — монетка).

## Чек-лист

- [ ] Вопрос судье — атомарный, позитивный, про видимое, без полного промта?
- [ ] Маркер «да» пришёл с «где», иначе засчитан как unsure?
- [ ] Стороны перемешаны, 10 % повторов со сменой сторон, имена скрыты?
- [ ] Варианты пары закодированы одинаково?
- [ ] Есть судья другого вендора, если среди моделей — модель вендора судьи?
- [ ] Калибровка по тем же парам, что видел заказчик, n ≥ 20, решение по `agree`?
- [ ] Эстетика, анатомия, текст, цвет, движение — не у VLM?
- [ ] Рубрика и промт — зафиксированная версия, изменение — пересчёт калибровки?

## Открытые вопросы и противоречия

1. Согласие VLM с заказчиком на наших ассетах не измерено ни разу — всё выше `[не проверено]` до K-01/K-02/K-06; ожидание
   для `slot` — «предфильтр», для `natural` — «не использовать».
2. GenAI-Bench (2024) даёт 45,6 % на 4 классах предпочтения, а TIIF — 90 % на бинарных вопросах: разница в формулировке
   задачи, а не в моделях — бинарное дробление брифа сильнее попарного «что лучше».
3. Structured output у Gemini через polza (`json_schema`, `strict`) — по документации polza [S11], но какое подмножество
   схемы принимает провайдер — `[не проверено]`; при отказе — формат словами (как у qwen3.5-9b).
4. Входят ли рассуждения Gemini в `max_tokens` (верх цены) — зонд B2-03.
5. logprobs есть у `qwen3-vl-8b-instruct` и `gpt-4o-mini` — мягкий P(yes) (VQAScore) мог бы заменить дискретные ответы;
   не реализовано (v0.2).
6. Судья того же вендора: E и C1 предостерегают, данных о величине смещения для картинок нет — K-01b.
7. Коды маркеров A — «мнение A» по таксономиям Northwestern и Artifact-Bench; порог кластера ≥ 3 / ≥ 2 — аналогия с UI.
