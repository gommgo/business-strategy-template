## Выжимка на 10 строк

1. Лидеры 2025–2026: первый экран 4,2 МБ (медиана), hero-картинка 55 КБ AVIF/WebP ровно под ширину экрана; ориентир для генерации — Q1: ≤ 2,5 МБ первого экрана, hero ≤ 150/80 КБ.
2. На телефоне 8 из 10 сайтов показывают **другой hero-кадр** (4:5–9:16), но вес почти тот же: телефонный бюджет и кадр надо планировать явно.
3. LCP ≤ 2,5 с — у 16 из 43; canvas LCP не бывает; hero, видимая часть которого равна вьюпорту, LCP не бывает никогда (LCP = H1, 12 из 12 — J/01): быстрыми должны быть и шрифт H1, и hero меньше вьюпорта (`fetchpriority="high"`, не `lazy`, ≤ 150/80 КБ).
4. PNG — 54 % байт картинок из-за ИИ- и дизайн-продуктов, выкладывающих генерации как есть: выход моделей всегда перекодировать (AVIF + WebP); JPEG XL — только с 06.10.2026 (Chrome 155) и первым необязательным `<source>`.
5. Hero-видео у лидеров — H.264, 200 КБ/с, однокадровые петли бесшовны (`seam_ratio` ≈ 1,1); постер у 20 % видео, пауза — у 1 из 33 петель длиннее 5 с (а по WCAG 2.2.2 пауза нужна любой бесконечной петле), reduce уважают 4 из 16.
6. ИИ рисует материальное и атмосферу (фон, сцена без людей, текстура, иллюстрация, фон вокруг реального товара); лица, отзывы, команда, логотипы, товар «как есть», интерфейс и кириллица в пикселях — нет.
7. Раскрытие «сделано ИИ» в экспериментах снижает доверие; синтетические лица кажутся реальнее настоящих; отобранный ИИ всё равно узнают в 72–82 % — ставь ИИ туда, где раскрытие не нужно или не вредит.
8. Слоп — кластер маркеров, увиденных человеком по каталогу 25 + 18 (≥ 3, или 2 в hero/товаре — не публиковать; порог не калиброван); метрики цвета ИИ от фото не отличают — в `asset_audit` они только подозрение `needs_human` (X24).
9. «Дорого» = отказ (меньше картинок, один приём), реальный материал, серия с единым светом, фактура, согласованность с UI; клише «про ИИ» у лидеров ИИ-рынка нет, у второго эшелона — есть.
10. План ассетов (YAML) — единый вход для D, E, N, K, J: слоты, варианты кадров, зоны текста, бюджеты, движение, доставка, приёмка, политика ИИ.
