## 1. Маршрут: откуда брать линейную иконку

| Ситуация | Маршрут | Почему |
|---|---|---|
| Метафора есть в наборе продукта (Lucide, Tabler, Heroicons…) | взять иконку набора | LLM всё равно воспроизведёт её из памяти (IoU ≥ 0,92 у 9/20) |
| Нет в наборе, простая (предмет с ясным силуэтом) | LLM по спецификации → проверка → правка → узнаваемость | 2 из 5 новых метафор узнаются с первого раза |
| Нет в наборе, сложная (самовар, народный костюм, механизм) | модификатор существующей иконки (бейдж, плюс, стрелка) или иллюстрация-пиктограмма ≥ 48 px | при 24 px и штрихе 2 не хватает деталей; ui 07/02 §4.2 |
| Нужна цветная/заливочная иконка | `VEC-ICON-FILLED` → `03-icon-sets-and-patterns.md` §2 | другой класс, нормы штриха не действуют |
| Вариант «активное состояние» | цвет и фон, а не заливка (у Lucide заливки нет) | ui 07/01 §6.1 |

Лицензии наборов, выбор набора и размеры применения — ui 07/01 §1, §4; здесь не повторяются.

## 2. Спецификация в промте

Шаблон целиком — `99-raw/phase5/inputs/G/llm-svg-icons.system.txt` (325 слов) и `….user.txt`; то же уходит в модели
в заданиях фазы 5. Ядро:

```text
// любая LLM · 2026-09-23 · [проверено на Claude Opus 5.5 в сессии: G/01; другие модели — фаза 5, G-01…G-04]
CANVAS AND HEADER (must, copy exactly):
<svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" viewBox="0 0 24 24" fill="none" stroke="currentColor"
 stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
HARD RULES (must):
1. 24x24 grid. Keep 1 px safe zone: all geometry stays within x,y in [2, 22].
2. One stroke width for everything: 2, centered, round caps and joins. Do not override stroke-width, fill or colors.
3. Color only via currentColor. No hex/rgb/named colors, gradients, filters, opacity.
4. Allowed children: path, circle, rect, line, polyline, ellipse. No <g>, transform, text, id/class/style, comments.
5. Distinct elements keep >= 2 px of empty space (parallel strokes: centerlines >= 4 px apart). Inner holes >= 2 px.
STYLE RULES (should):
6. Whole-pixel coordinates and arc centers; 45-degree diagonals between whole-pixel points.
7. Radius 2 for 90-degree corners of shapes >= 8 px, radius 1 for smaller; no rounding where >2 lines meet.
8. Prefer primitives and simple arcs; avoid needless cubic curves.
9. Visual weight like Lucide "circle" (r=10) and "square" (18x18, rx=2); visually centered.
10. At most 8 elements, ~30 segments; keep the 2-3 defining features recognizable at 16 px.
PROCESS: name 2-3 defining features, plan coordinates, then write the SVG.
OUTPUT: {"icons":[{"name":"...","features":"...","svg":"<svg ...>...</svg>"}]}
```

Почему так:
- **Числа вместо слов.** «По сетке 24» модель понимает как «viewBox 24»; поле и зазор она соблюдает, только если
  они заданы координатами ([2, 22], осевые ≥ 4) [практика G/01; на других моделях — фаза 5]. Спецификация Lucide разделяет must (холст, поле, штрих, соединения,
  зазор) и should (радиусы, сетка, кривые, вес) [S1][S2] — это разделение перенесено в промт.
- **Запрет `<g>` и `transform`.** Упрощает проверку и нормализацию; у Lucide их нет [S4].
- **Точка — только `<circle r="1"/>`.** Штрих 2 заливает её в диск ⌀ 4 px (колёса тележки, глаз).
- **`features` перед `svg`.** Модель сначала называет признаки узнаваемости (силуэт важнее деталей) — это же поле
  потом сверяется с ответом VLM в тесте узнаваемости.
- **Одна иконка — один элемент смысла.** Модификаторы (плюс, бейдж) — в одном углу одного размера по всему набору [S1 §14].

## 3. Геометрия: считать кодом

Координаты касательных, пересечений и флагов дуг агент считает скриптом и подставляет в `d`. Исходник —
`99-raw/experiments/G/01-llm-svg-icons/geom.py` (`heart`, `cloud`, `gear`, `pencil`, `matryoshka`).

```python
# Python 3.13 — [проверено: 99-raw/experiments/G/01-llm-svg-icons/geom.py]
def large_flag(c, p0, p1, sweep=1):
    """large-arc-flag для дуги p0 → p1 вокруг центра c; sweep=1 — по часовой на экране (y вниз)."""
    a0 = math.atan2(p0[1] - c[1], p0[0] - c[0]); a1 = math.atan2(p1[1] - c[1], p1[0] - c[0])
    span = (a1 - a0) % (2 * math.pi) if sweep == 1 else (a0 - a1) % (2 * math.pi)
    return 1 if span > math.pi else 0
# сердце из двух окружностей r = 5 (центры 7,9 и 17,9) и вершины 12,21:
# M12 21L3.48 12.55A5 5 0 1 1 12 9A5 5 0 1 1 20.52 12.55Z   (оба флага = 1: дуги больше 180°)
```

- **Ошибка, которую ловит только расчёт**: у дуги лепестка сердца угол ≈ 225°; с `large-arc-flag=0` рендер рисует
  короткую дугу «вниз» — сердце разваливается. Модель ставит 0 по привычке.
- **Цена расчёта**: узлы касательных уходят с целой сетки (облако — 0 % целых узлов, карандаш — 14 %). У Lucide
  кривые тоже вне сетки (сердце 39 %, карандаш 30 %, шестерня 24 %) — это норма для кривых, но концы прямых
  округлять до 0,5 и перепроверять.
- **Шестерня — самый трудный случай**: при штрихе 2 и зазоре 2 px у 24 px помещается 6 трапециевидных зубьев; у
  своей версии 28 сегментов против 16 у Lucide и «узкий фон» 3,4–14 px² — предпочесть иконку набора.

## 5. Узнаваемость — отдельная проверка

- **Что показал опыт**: новые метафоры проходят геометрию, но не читаются: гиря (узкое тело + ручка) = замок или
  «8»; матрёшка (две окружности + точка) = «8» или снеговик; самовар (корпус + ручки + кран) = голова робота.
  Коляска (капюшон + корзина + ручка + колёса) и чайник (корпус + носик + ручка) узнаются [проверено: G/01].
- **Причина**: при штрихе 2 на 24 px помещаются 2–3 признака; если отличающий признак — деталь меньше 4 px (роспись
  матрёшки, кран самовара), силуэт совпадает с более частой формой.
- **Тест VLM** (фаза 5, G-06): сетка пронумерованных иконок без подписей, в случайном порядке, вопрос «назови предмет
  в 1–3 словах + уверенность», контроль — 5 иконок Lucide (судья годен, если узнал ≥ 4 из 5). Вход и ключ —
  `99-raw/phase5/inputs/G/recognition-sheet-G01.{png,key.json}`, сетку строит `99-raw/experiments/G/grid.py`. Цена ≈ 0,26 ₽.
- **Правило NN/g**: если за 5 секунд не придумывается иконка, иконка не сработает; универсально узнаются только дом,
  печать и лупа — подпись рядом обязательна (ui 07/01 §7).
- **Не давать автору судить себя**: автопилот Cursor с Recraft MCP одобрил слабые иконки, вывод автора — агенту
  оставить вставку, выбор — человеку [V:Y1z1BNcJKTQ 37:41] [мнение].

## 6. Поставка в вёрстку

- **Два размера штриха.** 2 при 20–24 px; для 16 px — копия набора со `stroke-width="1.5"` (1 px на экране) или
  набор с оптическими размерами (ui 07/01 §3.3). `vector-effect="non-scaling-stroke"` держит 2 экранных px при любом
  размере — при 16 px это тяжелее набора, не замена оптическому размеру [мнение].
- **Цвет.** `currentColor` + токен (`icon.subtle` рядом с текстом, `icon.default` для кнопки-иконки); disabled —
  токен, не `opacity` (ui 07/01 §5.3, §6.2).
- **Спрайт.**

```html
<!-- HTML · [практика; вес проверен в G/01: 241–662 байта на иконку] -->
<svg hidden><symbol id="i-bell" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"
  stroke-linecap="round" stroke-linejoin="round"><path d="M18 8a6 6 0 0 0-12 0v5c0 1.5-.67 2.83-2 4h16c-1.33-1.17-2-2.5-2-4z"/>
  <path d="M10 21a3 3 0 0 0 4 0"/></symbol></svg>
<button class="icon-btn" aria-label="Уведомления"><svg width="16" height="16" aria-hidden="true"><use href="#i-bell"/></svg></button>
```

- **svgo.** Для иконок Lucide-стиля выигрыш мал; включать `multipass`, не отключать `viewBox` (в svgo 4.1.0 плагин
  `removeViewBox` вне `preset-default`), оставлять `<title>` только у самостоятельных иконок без подписи.
- **Проверка набора на странице**: у всех `<svg>` одинаковые `viewBox` и `stroke-width`, размеры из ряда
  12/14/16/20/24 (ui 07/01 §8.3).

## 7. Сравнение моделей (фаза 5) и цена

Задания `99-raw/phase5/jobs/G-01…G-06` (канал `polza-chat`, `POST /api/v1/chat/completions`, `response_format:

## Частые ошибки

1. Генерировать иконку, которая уже есть в наборе, — получится копия из памяти модели с худшей геометрией.
2. «Нарисуй в стиле Lucide» без чисел — модель держит `viewBox`, но не поле, зазоры и вес.
3. Верить модели в флаги дуг и касательные — `large-arc-flag` и точки сопряжения считать кодом.
4. Жёсткий цвет (`#333`, `#000`, `red`) вместо `currentColor` — иконка исчезает в тёмной теме.
5. `width`/`height` без `viewBox` — при 16 px видна часть рисунка.
6. Разные `stroke-width` в одном наборе (1,5 у одной, 2 у другой) — «признак новичка» (ui 07/01 §8).
7. Больше деталей «для узнаваемости»: 12 зубьев шестерни при штрихе 1,5 — пятно при 16 px.
8. Судить узнаваемость по метрикам: геометрически чистая «матрёшка» читается как «8».
9. Давать автору (той же сессии модели) финально одобрять свои иконки.
10. Ошибки агентов «по памяти»: `removeViewBox` в конфиге svgo 4 (его там уже нет), Font Awesome по умолчанию
    (CC BY — атрибуция), эмодзи и ✨ как иконки.

## Чек-лист

- [ ] Метафоры нет в наборе продукта (иначе — взять из набора)?
- [ ] Промт содержит дословную шапку, числа поля и зазора, лимит элементов, поле `features`?
- [ ] Кривые и флаги дуг посчитаны кодом?
- [ ] `check_icons.py` без флагов шапки, цвета, поля и зазора; вес 0,70–1,55?
- [ ] Контакт-лист 16/24/48 на светлом и тёмном рядом с 3–5 иконками набора просмотрен?
- [ ] Узнаваемость проверена без подсказки (VLM с контролем или человек за 5 секунд)?
- [ ] Одобрил не автор (метрики + внешний судья или человек)?
- [ ] Для показа в 16 px есть вариант со штрихом 1,5 или набор с оптическими размерами?
- [ ] Иконка в спрайте или компоненте, у всех `<svg>` одинаковые `viewBox` и `stroke-width`?

## Открытые вопросы и противоречия

1. Какая модель polza лучше рисует SVG на 09.2026 — данных нет (у Уиллисона — июнь 2025: Gemini 2.5 Pro впереди);

   `<img>` (крутится), но верно для `prefers-reduced-motion` (внутри `<img>` не срабатывает) → `04-animated-vector.md` §2.
