## Выжимка для агента

1. **Контролируемого теста «JSON против прозы» на выходе одной модели с метрикой не существует** (на 2026-09-23):
   Jarvis — два прогона на плечо без метрики, fofr и Green — практика, Atlabs — описание без результатов. → §3
   `[исследование]` `[мнение]` [поправка фазы 5, 25.09.2026: свой A/B проведён — JSON не выиграл нигде: NB2 Lite JSON против разделов
   +2,8 п. п., ДИ [−2,7; +9,1] (10 пар, судья вслепую); видео Seedance 1.5 Pro — разброс повторов больше разницы форм (D2-11) →
   `99-raw/phase5/runs/3-prompt-form/README.md`]
2. **JSON — контракт системы, а не формат промта по умолчанию.** Спецификация ассета хранится в JSON и компилируется
   в родной диалект модели (`03-asset-spec-and-dialects.md`). → §8 `[консенсус]`
3. **Вендоры моделей с LLM-фронтом прямо говорят: форма не важна** — OpenAI: «Short prompts, descriptive paragraphs,
   JSON-like structures, instructions, and tags can all express the same intent»; TIIF-Bench: NB-Pro 93.1 на коротком
   и 93.3 на длинном промте. → §2, §3 `[документация]` `[исследование]`
4. **Структура обязательна только у моделей, обученных на структуре**: Ideogram 4 (только JSON-подписи; проза без
   Magic Prompt «will not work»), Bria FIBO (JSON ~1 000 слов), MiniMax H3 (IR «ключ: проза», «critical to quality»).
   → §2 `[документация]` [поправка фазы 5, 25.09.2026: Bria FIBO через Gen-API — JSON-плечо 3 из 3 отклонено провайдером (0 ₽), проза
   ≤ 1 000 символов работает, и модель сама разворачивает её в свою схему (4 006–4 761 символ) → писать FIBO JSON незачем (D2-12)]
5. **FLUX.2: JSON официально поддержан** (запуск 2025-11-25, «both formats equally well»), но скилл BFL сплющивает
   JSON в прозу, а API BFL по умолчанию включает апсемплинг промта у [pro] и [max]. Прямой JSON — плечо A/B, не
   умолчание. → §2 `[документация]` `[спорно]` [поправка фазы 5, 25.09.2026: FLUX.2 [dev] без переписчика (D2-02, 20 картинок) —
   глазом JSON развёл цвет и предмет («coral» — цвет, проза дала коралл-организм в 2 из 2), лечится и прозой («coral-colored…»);
   судья не прогнан (отменено) — предварительно, 1 образец на бриф]
6. **Если модель переписывает промт встроенной LLM, форма до генератора не доходит**: Veo (у veo-3.0 переписчик не
   выключался), FLUX.2 [pro] (`disable_pup=false`), GPT Image в Responses (`revised_prompt`), Qwen/Wan
   (`prompt_extend`), Seedream (`optimize_prompt_options`), MiniMax (`prompt_optimizer`). → §6 `[документация]`
7. **Польза JSON — полнота, а не синтаксис**: «you're more easily in direct control… You don't need to remember what to
   define» (fofr). У нас полноту гарантирует схема спецификации, поэтому эффект уже учтён до компиляции. → §4
   `[практика]`
8. **Вред JSON — вне распределения подписей**: «Generative models are known to produce poor results when sampled out of
   their training distribution» (DALL-E 3); скобки и ключи — шум для энкодеров T5/CLIP и лишние символы в лимитах
   polza (Z-Image 1 000, Wan 2.5 800). → §4 `[исследование]`
9. **Проза по разделам с метками — безопасный компромисс для класса A** (OpenAI: «labeled sections», DevRel Google —
   жирные метки, Wan 3.0 и Seedance 2.5 — разделы в примерах); у Qwen-Image разделы — не родная форма (переписчик 2512
   запрещает списки и заголовки). → §2, §8 `[документация]`
10. **Не отправляй сырую спецификацию в модель**: служебные поля (слот, код задачи, выход, версии) — шум; в JSON-плечо
    идут только визуальные поля. → §8, §9 `[мнение]`
11. **Меряй следование брифу атомарными бинарными вопросами** в стиле DSG: один факт на вопрос, граф зависимостей,
    вопросы сформулированы позитивно (VLM не понимают отрицаний, NegBench). → §5, §9.4 `[исследование]`
12. **TIFA / DSG / VQAScore / GenEval — разные вещи**: TIFA и DSG — вопросы из промта, VQAScore — вероятность «Yes» на
    весь промт, GenEval — детектор объектов (счёт, цвет, позиция). Для A/B брифов сайта подходит DSG-подобный набор +
    ΔE палитры + проверка зоны под текст. → §5 `[исследование]`
13. **Короткий промт выигрывает от расширения** (DALL-E 3: 70.4 % → 81.0 % на Drawbench после апсемплинга; OPT2I: до
    +24.9 % DSG), полный — нет данных о выигрыше. → §6 `[исследование]`
14. **Усилители в polza по умолчанию выключены** (`enhance_prompt`, `enable_prompt_expansion`, `isEnhance`); держи их
    выключенными для скомпилированных промтов; включай для коротких промтов и для правок Qwen (вендор: без переписчика
    правка нестабильна). → §6 `[документация]` `[не проверено]`
15. **Переписчик приносит «свой вид»**: Qwen дописывает «Canon EOS R5, f/1.2», у Nano Banana Pro есть «default look»
    (fofr). Для арт-дирекшна это риск слопа — сверяй с правилами F. → §6 `[практика]`
16. **Язык описания — английский; язык надписи — дословно в кавычках с указанием языка.** LingT2I: у моделей с T5/CLIP
    русский промт даёт 0.34–0.44 против 0.77–0.79; у Qwen-Image — 0.78 против 0.82. → §7 `[исследование]`
17. **Культуру задавай явной меткой, а не языком**: 75 % против 32.5 % (LingT2I); модели на многоязычных промтах
    выдают «culturally neutral or English-biased results» (CultureBench). → §7 `[исследование]`
18. **`enableTranslation` у Veo в polza включён по умолчанию** — отправляй английский промт, не полагайся на перевод
    терминов камеры. → §7 `[документация]` `[не проверено]`
19. **Протокол A/B фазы 5**: 5 брифов × 3 диалекта (проза, разделы, JSON) × 2 повтора × 3 модели = 90 картинок,
    327 ₽; плюс необязательный блок Z-Image — 20 заданий, 28 ₽ (итого 355 ₽). → §9 `[не проверено]`
20. **Все три диалекта компилируются из одной спецификации** — содержание одинаково, меряется только форма. → §9.2
    `[мнение]`
21. **Зерно — общее для трёх диалектов**, где есть `seed` (`qwen/image-2.1`), — это парный дизайн; где нет — два
    независимых повтора (`variant`). → §9.2 `[мнение]`
22. **Судья не знает диалекта**: файлы под хэшами, порядок случайный; 10 % картинок — повторная оценка на
    согласованность. → §9.4 `[практика]`
23. **Правило решения**: менять диалект семейства, только если выигрыш ≥ 10 п. п. и 95 % ДИ не пересекает ноль; иначе
    — умолчание `dialects.yaml`. → §9.5 `[мнение]`
24. **Выборка различает только крупные эффекты** (≈ 13 п. п. и больше); мелкие разницы форм меньше разницы моделей
    (10–30 баллов в TIIF-Bench) и для маршрутизации не важны. → §9.5 `[мнение]`
25. **Проверяй лимиты до отправки**: JSON длиннее прозы; у Z-Image JSON-плечо может не влезть в 1 000 символов —
    тогда плечо пропускается, а не обрезается. → §9.2 `[проверено]`

**Смежные исследования с методикой (не JSON против прозы в чистом виде):**

- **Bria FIBO, абляция формата обучения** [S18]: модель 1B, 100K шагов, одни и те же картинки; длинные структурные
  подписи — FID 19.01, короткие — 34.04 (30K COCO-2014 val). Меняются одновременно **длина и структура**, и это формат
  **обучения**, а не промта у модели, обученной на прозе `[исследование]`.
- **TIIF-Bench** [S29]: 5 000 промтов, каждый в короткой и длинной версии с одинаковой семантикой, VLM-оценщик
  бинарными вопросами. «Top-performing models demonstrate strong robustness to variations in prompt length… weaker
  models such as SD-3 and PixArt-Alpha exhibit substantial performance discrepancies»; NB-Pro — 93.1 / 93.3, GPT-Image-1
  — 86.1 / 87.6 `[исследование]`. Это самый близкий к нашему вопросу замер: форма и длина важны слабым моделям, а не
  сильным.
- **UniGenBench++** [S31]: 600 промтов, каждый на английском и китайском в короткой и длинной форме — протокол для
  замера устойчивости к языку и длине; судья Gemini-2.5-Pro и обученный оценщик `[исследование]`.
- **DALL-E 3** [S24]: расширение промта GPT-4 до описательной подписи — 70.4 % → 81.0 % на Drawbench (судья GPT-V):
  выигрывает не синтаксис, а соответствие распределению подписей `[исследование]`.

**Итог на 2026-09-23**: доказательства «JSON лучше прозы» для моделей, обученных на прозе, отсутствуют; для моделей,
обученных на структуре, структура обязательна по документации. Ответ на вопрос «помогает ли» даст только собственный
A/B (§9).

## 4. Механизмы: почему может помогать и почему может вредить

| Помогает | Почему | Когда не работает |
|---|---|---|
| **Полнота** | поля схемы напоминают, что задать (свет, объектив, палитра): «You don't need to remember what to define» [S3] | если полноту уже гарантирует спецификация (наш случай) — эффект переносится в компилятор, а не в промт |
| **Разделение аспектов** | правка одного поля меньше сдвигает остальное: дизентанглмент у FIBO (качественно) [S18], «Two runs from the same JSON prompt stay close to each other in composition» (Ideogram) [S17] | у моделей, обученных на прозе, не измерено; у Green — «may just be luck» [S5] |
| **Привязка атрибутов к объекту** | ключи группируют признаки субъекта (`subjects[].color_palette`); BFL: hex работает, когда «clearly associated with specific objects» [S7] | то же достигается прозой «the LEFT chair in #…» [S8] `[не проверено]` |
| **Формат обучения** | Ideogram 4, FIBO — JSON; H3 — IR; Qwen-Image видел структурные метаданные [S16][S18][S19][S21] | к моделям на прозе не переносится |
| **Машиночитаемость** | валидация, шаблоны, диффы, A/B, журнал: «prioritize a skimmable template over clever prompt syntax» [S11] | это польза для системы, не для картинки |

| Вредит | Почему | Где заметнее |
|---|---|---|
| **Вне распределения подписей** | «Generative models are known to produce poor results when sampled out of their training distribution» [S24] | энкодеры T5/CLIP, модели без переписчика |
| **Синтаксический шум и лимиты** | скобки, кавычки и ключи съедают символы: лимиты polza — Z-Image 1 000, Wan 2.5 800, Kling 2 500; накладные расходы JSON — `[проверено]` | короткие лимиты |
| **Переписчик до генератора** | Veo, FLUX.2 [pro] (`disable_pup=false`), GPT Image в Responses, Qwen/Wan `prompt_extend`, Seedream, MiniMax — форма пересказывается LLM [S9][S12][S15][S44][S46][S55] | эффект формы размывается; переписчик может выбросить поля |
| **Перегруз и противоречия** | больше полей — больше шансов противоречия (Green [S5]); «Over-stuffing can make motion less coherent» (FLUX 3) [S7] | видео, длинные брифы |
| **Чужая форма для переписчика вендора** | переписчик Qwen-Image-2512: «Strictly avoid formal Markdown lists…, numbered items, or headings» [S22] | разделы и JSON у Qwen |
| **Строки текста теряются среди строк-описаний** | в JSON всё — строки в кавычках; модель может нарисовать описание как надпись `[мнение]` | картинки с текстом (у Ideogram решено типом элемента `text`) |

**Аналогия из соседней базы.** Для генерации интерфейсов LLM жёсткие правила выполнялись чаще мягких (92.3 % против
70.4 %) [S49] — у моделей картинок такой замер не найден; переносить как гипотезу, не как факт `[мнение]`.

## 5. Как измерять следование промту

| Метод | Как работает | Надёжность | Годится для A/B брифов сайта |
|---|---|---|---|
| **TIFA** (ICCV 2023) [S25] | LLM делает пары «вопрос — ответ» из промта, VQA-модель отвечает по картинке; балл — доля верных | Spearman с людьми 0.60 против 0.33 у CLIPScore; TIFA v1.0 — 4K промтов, 25K вопросов, 12 категорий; модели слабы в счёте и пространстве | да, как идея |
| **DSG — Davidsonian Scene Graph** (ICLR 2024) [S26] | атомарные уникальные вопросы, полное покрытие, граф зависимостей: дочерний вопрос не задаётся, если родитель «нет» | чинит неатомарные вопросы, дубли и противоречия VQA («нет мотоцикла, но он синий»); DSG-1k — 1 060 промтов | **да — основа метрики §9.3** |

| **GenEval** (NeurIPS 2023) [S28] | детектор объектов + классификатор цвета: объекты, счёт, цвет, позиция, привязка цвета | согласие с людьми 83 % (между людьми 88 %) | для счёта и позиции (бриф B4) |
| **TIIF-Bench** [S29] | VLM-оценщик бинарными вопросами; короткие и длинные версии промтов; GNED для текста (OCR + сопоставление) | GNED согласуется с людьми на 99 % (OCR recall — 83 %) | **да — для текста (бриф B5) и для идеи «коротко / длинно»** |
| **OneIG-Bench** (NeurIPS 2025) [S30] | ~1 120 промтов в 5 категориях, EN и ZH, + 200 многоязычных; выравнивание, текст, рассуждение, стиль, разнообразие | русского нет | нет |
| **UniGenBench++** [S31] | 600 промтов, 10 основных и 27 подкритериев, EN/ZH × коротко/длинно; судья Gemini-2.5-Pro | русского нет | идея протокола |
| **TaBR** (FIBO) [S18] | реальная картинка → подпись → генерация → люди выбирают «ближе к оригиналу» | меряет выразительность промта без чтения длинных текстов | альтернатива для K |
| **OPT2I** [S34] | итеративное переписывание по DSG | «a perfect consistency score does not ensure perfectly aligned images» | предупреждение: метрика ≠ качество |

Правила для нашей метрики: вопросы — **атомарные и позитивные** (VLM класса CLIP понимают отрицание на уровне

через OCR); вопросы с зависимостями (DSG); текст — OCR + нормированное расстояние правки (GNED-подобно); палитра —
ΔE OKLab (`../../scripts/lib/color.py`, функция `dE_oklab`) [S51]. Метрики и калибровка судьи — агент K

### 6.2 Исследования

- **DALL-E 3** [S24]: 95 % синтетических описательных подписей в обучении; GPT-4 «upsample» промты; Drawbench 70.4 %
  → 81.0 %. Ограничение: «"to the left of", "underneath", "behind"… are quite unreliable… because our synthetic
  captioner also has this weakness» — **модель следует тем аспектам, которые описывал её кэпшенер** `[исследование]`.
- **Promptist** (NeurIPS 2023) [S32]: SFT + RL переводят промт пользователя в «model-preferred prompts» для Stable
  Diffusion; «performant prompts are often model-specific and misaligned with user input» `[исследование]`.
- **Prompt Expansion** (Google, 2023) [S33]: расширение запроса в набор промтов ради разнообразия и эстетики; связь
  текста и картинки «still bears the fingerprints of the training data (alt-text)» `[исследование]`.
- **OPT2I** (Meta/Mila, обновл. 2026-08-24) [S34]: LLM итеративно переписывает промт, максимизируя DSG или
  разложенный CLIPScore — до +24.9 % DSG (PartiPrompts) и +12.2 % (MSCOCO) при сохранении FID; лучше случайного
  перефразирования и Promptist `[исследование]`.
- **Z-Image PE** [S23]: усилитель с цепочкой рассуждений; без рассуждения PE «merely renders coordinate text onto the
  image when given geolocation data» `[исследование]`.
- **Qwen-Image-Edit** [S22]: «editing results may become unstable if prompt rewriting is not used» `[документация]`.

   Pro «default look» — «beautiful, warm, detailed, a little bit rustic and candid» [S3]. Для арт-дирекшна (F) это риск
   одинаковых «дорогих» картинок.
4. Включать встроенный усилитель: короткий промт (разведка, `IMG-DRAFT`), правка на Qwen (рекомендация вендора);
   выключать: скомпилированная спецификация, серия (переписчик ломает дословный блок стиля) `[не проверено]`.
5. Цикл «генерация → DSG → переписать» (OPT2I) — кандидат для D2 и K, но только с дешёвыми моделями и лимитом
   итераций.

### 9.1 Вопрос и гипотезы

Вопрос: какой диалект компилятор должен отдавать каждому семейству моделей, чтобы картинка выполняла больше пунктов
брифа. Гипотезы (все `[не проверено]`):

- **H0**: у моделей polza с языковым энкодером форма промта (P — проза, S — проза по разделам, J — JSON) меняет долю
  выполненных пунктов меньше чем на 10 п. п.
- **H1** (FLUX.2 [pro]): J не хуже P (документация BFL — «equally well»; апсемплинг по умолчанию сглаживает разницу).
- **H2** (Qwen Image 2.1): J и S хуже P (родная форма — проза без Markdown; переписчик 2512 запрещает списки).
- **H3** (Nano Banana 2 Lite): S ≥ P на брифах с ≥ 10 пунктами (thinking-модель читает разделы как чек-лист).
- **H4** (палитра): hex, привязанный к объекту, в J и S даёт ΔE не хуже, чем в P.

### 9.4 Метрика и судейство

1. **Следование брифу** (основная): доля «да» по вопросам брифа; дочерний вопрос при «нет» у родителя считается
   «нет». Судья — оркестратор (Claude, зрение) в чистом контексте: картинки под хэш-именами, случайный порядок, без
   промта и диалекта; 10 % картинок оцениваются повторно для согласованности; заказчик выборочно проверяет 10
   картинок. Стоимость на polza — 0 ₽.
2. **Палитра**: k-means (k = 6) в OKLab по уменьшенной до 256 px картинке → для каждого цвета спецификации ближайший
   кластер, ΔE OKLab (`../../scripts/lib/color.py`, `dE_oklab`) и ошибка доли |доля в картинке − доля в спецификации|.
   Отчёт — медиана ΔE по ролям; «совпало» при ΔE ≤ 0.08 для доминирующего и вторичного цвета (порог — `[мнение]`,
   калибрует K; для сравнения: сверка стиль-плиток в ui-research — ΔE OKLab ≤ 0.02 [S50]).
3. **Зона под текст** (B1, B3): в прямоугольнике зоны — доля пикселей с градиентом Собеля выше порога и
   стандартное отклонение яркости; пороги калибруются на 10 размеченных вручную картинках до подсчёта итогов.
4. **Текст** (B5): OCR → нормированное расстояние правки к точной строке (в духе GNED [S29]); «совпало» — точное
   совпадение обеих строк и отсутствие лишнего текста.
5. **Вторичные**: число отказов и ошибок модели по диалектам, длина промта в символах, маркеры «слопа» по списку A/F.

### 9.5 Анализ и правило решения

- Для каждой модели — средняя доля выполненных пунктов по диалектам; парные разности J − P и S − P по 10 парам
  (бриф × повтор); 95 % бутстреп-ДИ (10 000 повторов) и знаковый критерий.
- **Правило**: семейство переходит на диалект X, если X − P ≥ 10 п. п. и ДИ не содержит ноль; иначе остаётся умолчание
  `dialects.yaml`. Результат записывается в `dialects.yaml` (поле `ab_result` с датой и ссылкой на прогон).
- **Мощность**: при стандартном отклонении балла ≈ 0.15 стандартная ошибка средней парной разности на 10 парах ≈
  0.15 × √2 / √10 ≈ 0.067 — надёжно различимы эффекты ≳ 13 п. п. `[мнение]`. Меньшие эффекты для маршрутизации не
  важны: разница между моделями в TIIF-Bench — 10–30 баллов [S29].
- Отдельно по B5 (текст) и по палитре — описательно, без правила решения (n мало).

### 9.7 Угрозы достоверности

- **Апсемплинг FLUX.2 [pro] в polza не управляется** — результат по FLUX.2 относится к паре «модель + переписчик».
- **Исполнитель `mie` ≈ KIE** может сам менять промт или параметры — сверять `usage` и паспорт генерации.
- **Судья — языковая модель**: риск смещения к «красивым» картинкам; вопросы только о фактах брифа, без вкусовых.
- **Брифы — наши**: пять сюжетов не покрывают видео и правки; A/B для видео — после фазы 5 по остатку бюджета
  (Wan 2.6 / Seedance 2 Mini, 480p, 4–5 с, без звука).
- **Зерно** есть только у Qwen: для остальных разность диалектов смешана с шумом выборки — отсюда порог 10 п. п.

## Частые ошибки

1. **Считать JSON «языком модели»** (ошибка агентов): у моделей, обученных на прозе, это просто текст со скобками;
   «родной» JSON только у Ideogram 4 и FIBO.
2. **Отправлять сырую спецификацию** со служебными полями (слот, бюджет, форматы) — модель рисует лишнее или путается.
3. **Ссылаться на тесты-анекдоты как на доказательство**: n = 2 без метрики (Jarvis) не доказывает ни «плацебо», ни
   пользу.
4. **Смешивать форму и содержание в сравнении**: JSON с 15 полями против прозы из 12 слов меряет полноту, а не формат.
5. **Не учитывать переписчик**: сравнивать форму промта у Veo или FLUX.2 [pro] так, будто промт доходит до генератора
   дословно.
6. **Включать усилитель вендора для серии** — переписчик ломает дословный блок стиля.
7. **Задавать VLM-судье вопросы с отрицанием** («Is there no text?») — судья ошибается на уровне случайности.
8. **Обрезать JSON под лимит** (Z-Image 1 000 символов) — теряются поля в конце; правильно — компактная проза или
   пропуск плеча.
9. **Писать русское описание моделям с T5/CLIP** и оценивать «модель плохая».
10. **Надеяться на автоперевод** (`enableTranslation` у Veo) для терминов камеры и имён собственных.
11. **Путать YAML и JSON как разные «диалекты»** — для модели это тот же структурированный текст; fofr: «Any structured
    data will work».
12. **Менять диалект по одному удачному прогону** — только по правилу решения §9.5.

## Открытые вопросы и противоречия

1. **Нет ни одного контролируемого замера «JSON против прозы»** на выходе одной модели — закрывает только наш A/B.
2. **BFL против BFL**: «both formats equally well» (документация) и «Flatten for Execution» (скилл); апсемплинг [pro]
   включён по умолчанию — видит ли генератор JSON вообще.
3. **Veo 3.1**: неизвестно, отключаем ли переписчик (у 3.0 — нет); в polza параметра нет.
4. **Исполнитель `mie` (KIE)**: какой API OpenAI вызывается (Responses с `revised_prompt` или Image API), передаются ли
   умолчания BFL, Seedream, MiniMax.
5. **MiniMax H3 Max в polza**: без IR модель получает «не тот формат»; применяет ли провайдер IR — неизвестно.
6. **Qwen**: старый переписчик запрещает отрицания, новый пишет «No other text appears» — для Qwen Image 2.1 нужна
   проверка.
7. **Русский язык**: LingT2I и MULTITEXTEDIT не включают FLUX.2, Seedream 4.5/5, GPT Image 2.5 — данных по ним нет.
8. **Порог ΔE** для «совпало» в генеративной картинке не откалиброван (0.08 — рабочая догадка).
9. **PMT2I** (двуязычный промт) не проверялся на коммерческих моделях.
