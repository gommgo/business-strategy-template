## Выжимка для агента

1. **Ст. 50 AI Act действует с 02.08.2026**; отсрочка до **02.12.2026** — только машиночитаемой маркировке 50(2) для систем,
   выпущенных до 02.08.2026 (Omnibus, Регламент 2026/1744); видимая метка дипфейков 50(4) — без отсрочки → §1.1 [документация]
2. **Две разные обязанности**: провайдер ИИ-системы метит выход машиночитаемо и даёт способ обнаружения (50(2));
   деплоер видимо раскрывает дипфейки и ИИ-тексты на общественные темы (50(4)); наша in-house система — и то и другое →
   §1.2 [документация: Руководство п. 11–15]
3. **Провайдер может опереться на метку вендора модели** (п. 74), но только пока она есть в выходе: C2PA снимает любое
   перекодирование, SynthID (пиксельный) — заявлен устойчивым → §4 [документация; проверено: L/01, L/02]
4. **Вне 50(2)**: иконки масштаба UI, подписи и alt-текст, исходный код (в т. ч. SVG как разметка — `[спорно]`), черновики
   внутри производства — **маркируется только финальный выход** → §1.3 [документация: Руководство п. 68]
5. **Стандартная правка не маркируется**: сжатие и смена формата, небольшой кроп и цветокор, ресайз, вырез фона,
   «pixel filling for aspect ratio adaptation»; удаление/вставка объектов и людей, композиты, меняющие смысл, — маркируются
   → §1.3 [документация: Руководство п. 90–92]
6. **Дипфейк = 4 признака**: сходство, «существует или может правдоподобно существовать», люди/объекты/места/сущности/
   события, способность сойти за подлинное с учётом контекста и аудитории; фотореализм повышает вероятность, но не решает
   → §2 [документация: Руководство п. 113–116]
7. **Для сайтов**: реалистичная персона, «наш офис», ИИ-картинка товара «лучше, чем в жизни», синтетический CEO —
   дипфейки; фон за реальным товаром, иллюстрация, фантазия (сфинкс над Эйфелевой башней) — нет → §2.2 [документация]
8. **Видимая метка — аббревиатура «AI» заглавными** (иконка ЕС или равноценная), правый верхний угол, с первого показа,
   без действий пользователя, доступно (alt/ARIA, контраст) → §3.2 [документация: Кодекс, разд. 2, Measure 1.1–1.2]
9. **Иконки ЕС свободны**: «AI GENERATED», «AI MODIFIED», базовая «AI»; 4 варианта; без атрибуции; не-подписант не должен
   выдавать иконку за знак присоединения к Кодексу → §3.3, §7 [документация]
10. **Иконка ЕС на кадре занимает 0,35 % площади (десктоп) и 2,1 % (телефон), контраст 10–18 : 1** — в 4 раза меньше и
    читаемее текстовой плашки → §7.1 [проверено]
11. **Кодекс для провайдеров: ≥ 2 слоя** — подписанные метаданные с меткой времени + невидимый водяной знак; отпечаток —
    дополнительно; запрет удаления меток — в условиях провайдера → §3.1 [документация: Кодекс, разд. 1]
12. **Кто что ставит (документация, 23.09.2026)**: Google — C2PA + SynthID всегда; OpenAI — C2PA (Conforming Generator) +
    SynthID с 19.05.2026; BFL — C2PA «may embed» + запрет удаления; Recraft SVG — `<recraft-signature>` + запрет удаления;
    Seedream (прямой API) — видимая «AI-generated»; Kling, Seedance, MiniMax — `AIGC` в MP4 → §4.1; через polza — проверка
    L-01 фазы 5 [поправка фазы 5, 25.09.2026: факт по 254 выходам: OpenAI через polza — C2PA Trusted 71 из 73; Google через `mie` — через раз (NB2 8 из 19,
    NB Pro 1 из 5, NB2 Lite 19 из 21; SynthID-строка — только вместе с C2PA); Seedream, FLUX.2, Grok, Seedance 2 Fast — C2PA Valid (подписант не в
    списке доверия); Kling 3 — `AIGC` в тегах MP4 (4 из 4); Qwen Image 3 (RouterAI) — строка TC260; **Seedance 1.5 Pro (0 из 32),
    Z-Image, Qwen 2.1, Krea 2 — ничего**; видимой «AI-generated» у Seedream через `mie` нет; SVG Recraft через RouterAI —
    `<recraft-signature>` нет, C2PA-манифест в `<metadata>` → метка вендора не гарантия: на каждую производную — свой XMP и паспорт →
    `../99-raw/experiments/L/05-phase5-provenance/2026-09-25-all/README.md`]
13. **Что снимает наш конвейер**: C2PA — любое перекодирование и ресайз (картинки и видео), правка XMP ломает подпись;
    XMP в MP4 — любой ffmpeg; `AIGC` — любой ffmpeg без `-map_metadata 0 -movflags use_metadata_tags`; подпись Recraft —
    svgo по умолчанию → §4.2 [проверено] [поправка фазы 5, 25.09.2026: C2PA-манифест SVG Recraft (17,7 КБ в
    `<metadata>`, 30–79 % веса) валиден только в исходнике: после любой чистки путей — `Invalid` (`assertion.dataHash.mismatch`),
    svgo `preset-default` удаляет `<metadata>` целиком; `provenance_check.py` 0.1.1 читает C2PA в SVG]
14. **Правило производных**: мастер вендора — побайтно; веб-производная — XMP `DigitalSourceType` после финального
    кодирования (+1–3 КБ); для ЕС-дипфейков — sidecar `.c2pa` или CDN с сохранением; видео можно переподписать (+4 %) → §5
    [проверено] [поправка фазы 5, 25.09.2026: для SVG Recraft: мастер побайтно (носитель манифеста), на страницу — чистая производная **без**
    `<metadata>` (сломанный манифест хуже отсутствующего), провенанс — паспорт генерации; без манифеста иконки, споты и фоны —
    2,3–10,1 КБ; эвристика углов `QA-PROV-VISIBLE-MARK` на фактурных углах витрины VAR — 4 ложных из 4 (глазом меток нет)]
15. **Встроенный C2PA на веб-картинке тяжелее самой картинки** (JPEG +57 КБ = 74 %, WebP +141 КБ = 93 %, AVIF-производная с
    родителем +116 КБ = 95 %); на видео — терпимо (+28,7 КБ = 4 % пятисекундного ролика) → §4.3 [проверено]
16. **«Valid» ≠ «Trusted»**: подпись цела против подписанта из списка доверия C2PA (30 корней на 23.09.2026: Google, DigiCert,
    SSL.com, Adobe, TrustAsia…); свой тестовый ключ даёт `signingCredential.untrusted` → §4.4 [проверено]
17. **Для видео `-movflags` пишутся одной строкой** (`use_metadata_tags+faststart`) — второй флаг перетирает первый, `moov`
    уходит в конец → §5.3 [проверено]
18. **Китайская метка (GB 45438-2025, меры CAC с 01.09.2025)** обязывает китайских провайдеров; злонамеренное удаление меток
    запрещено (ст. 10 мер); вне КНР нас прямо не связывает, но `AIGC` в видео сохраняем — это 0 ₽ → §6 [документация]
19. **SynthID локально не проверить**: только Gemini app / Google Lens («Is this AI-generated?») и openai.com/verify (OpenAI)
    — проверка L-03 фазы 5 на паре «оригинал → производная» → §4.1 [документация]
20. **Тексты раскрытия** — короткие, без канцелярита, «ИИ» в тексте и «AI» на иконке; alt не называет ИИ-кадр фотографией →
    §7.2 [документация: Кодекс Measure 1.1; практика]

### 1.2 Кто провайдер, кто деплоер

- **Провайдер** (ст. 3(3)): разрабатывает ИИ-систему (или заказывает) и выпускает на рынок **или вводит в эксплуатацию под
  своим именем, в т. ч. для собственного использования** (п. 11: «developed an interactive AI system… in-house and puts it
  into service… for its own use»). Компания, сделавшая свою генеративную систему и использующая её, — **и провайдер, и
  деплоер** (п. 15). → Система генеративного дизайна заказчика = провайдер ИИ-системы (агентные системы — в сфере 50(2),
  п. 58).
- **Деплоер** (ст. 3(4)): использует систему под своей властью в профессиональной деятельности; сотрудники (веб-дизайнеры)
  — не отдельные деплоеры (п. 14); **клиент, который лишь заказал сайт/рекламу и не решает, как применять ИИ, — не
  деплоер** (п. 14, пример с агентством). Хостинг и платформы — не деплоеры, им «strongly encouraged» сохранять метки (п. 16).
- **Вне ЕС**: провайдер подпадает, если выход используется в ЕС (п. 10); деплоер — если предвидит распространение в ЕС,
  «including by posting deep fakes on the globally accessible internet» (п. 13) → для РФ-сайта с реалистичными людьми и
  местами позиция базы — метить `[спорно]`.
- **Опора на вышестоящего вендора**: провайдер может использовать маркировку поставщика модели или третьей стороны,
  если она соответствует 50(2); ответственность остаётся на провайдере (п. 74; Кодекс, разд. 1, Measure 1.1).

### 1.3 Что маркировать не нужно (провайдер, 50(2))

| Вне сферы или исключение | Пример для сайтов | Основание |
|---|---|---|
| короткие последовательности, подписи, alt-текст, UI-метки, **«icon-scale graphics»** | иконки 24–64 px, фавиконы, бейджи | п. 68 |
| исходный код, разметка, конфиги | CSS, SVG-разметка, JSON-анимации (как код) | п. 68 `[спорно для SVG-иллюстраций: это ещё и изображение]` |
| промежуточные выходы производства (реклама, анимация) | черновики, эскизы, варианты для выбора | п. 68: «only the final output… has to be marked» |
| стандартная правка | сжатие, смена формата, шумодав, небольшой кроп и цветокор, ресайз, вырез фона, «pixel filling for aspect ratio adaptation», «edge image completion» | п. 90–92 |
| несущественное изменение входа деплоера | апскейл, стабилизация, выравнивание горизонта | п. 91–92 |

Маркировать: удаление/замену/вставку объектов и людей, меняющие смысл; замену лица; синтез реалистичной речи; видео
несостоявшихся событий; изменение формы тела и цвета кожи; резкие цвет/контраст, меняющие смысл; **композиты, меняющие
представление о людях, объектах, событиях** (п. 92) [документация]. Аутпейнт под другое соотношение — стандартная правка
по букве п. 92 («pixel filling for aspect ratio adaptation»), если не добавляет новых смысловых объектов `[спорно]`.

## 2. Дипфейк (ст. 3(60), 50(4)): критерии и веб-примеры

### 2.1 Четыре признака (Руководство п. 113–115)

1. **Сходство** — «appreciable», высокая степень сходства с имитируемым (не обязательно тождество).
2. **«Существующий»** — достаточно сходства с тем, что «exists, can plausibly exist or could have plausibly existed»;
   нереалистичное (люди летают без механизмов, драконы, слоны за рулём) — вне сферы.
3. **Люди, объекты, места, сущности, события** — «persons» включает **реалистичных ИИ-аватаров и персон**; «objects» —
   здания, произведения, машины, **потребительские товары**; «events» — сцены, **включая изображение оказания услуг**.
4. **Ложно кажется подлинным** — оценивается объективно (умысел не нужен), с учётом сходства, смысла, контекста показа и
   **реального состава аудитории** (дети, пожилые — п. 115); если аудитория не ждёт подлинности, признак может не
   выполняться; «фотореализм повышает вероятность, но не решает».

### 2.2 Веб-примеры

| Ассет | Дипфейк? | Почему (пункт Руководства) |
|---|---|---|
| Фотореалистичные «довольные клиенты», «наша команда», ИИ-эксперт | да | реалистичная персона; п. 113 iii; пример «synthetic avatar of a company CEO» |
| ИИ-инфлюенсер или знаменитость в рекламе | да (и нарушение прав) | примеры п. 116 и 124 |
| ИИ-картинка товара «лучше, чем в жизни» | да | пример «product… more appealing or with improved quality than in real life» |
| Реальный товар на ИИ-фоне, эстетика | обычно нет | п. 116 и пример «a real product (e.g., a car)… against an AI-generated background» |
| «Наш офис», «наш отель» реалистично, но сгенерировано | да (место) | п. 113 iii «places» |
| Реалистичный интерьер как фон секции без утверждений | зависит от контекста | п. 114: контекст и ожидания аудитории |
| Иллюстрация, 3D-метафора, абстракция | нет | нереалистичное / мультипликационное (примеры п. 116) |
| Видео с синтетическими «покупателями», демонстрирующими товар | да, и не «творческая работа» | пример п. 124 (телемагазин) |
| Фон-петля «облака, свет, ткань» | нет | не имитирует конкретное существующее |

Творческие работы (п. 120–123): «evidently» — толкуется строго; реклама — «в одних ситуациях да, в других нет»; при смеси
информационный характер перевешивает → для коммерческих страниц режим «творческой работы» по умолчанию не применяю.

## 3. Кодекс практики по прозрачности ИИ-контента (10.06.2026)

### 3.1 Раздел 1 — провайдеры (50(2), 50(5))

- **Measure 1.1**: минимум **два слоя** машиночитаемой маркировки: 1.1.1 — **подписанные метаданные** с меткой времени
  («secure and tamper-evident»), 1.1.2 — **невидимый водяной знак**, «difficult to be separated»; 1.1.3 — отпечаток или
  журнал — опционально, одного его мало. Один слой — только для замкнутых встроенных систем и для свободного текста.
- **Measure 1.2 — неудаление**: провайдер (а) сам не удаляет существующие метки во входах, кроме «good faith, legitimate
  processing where the modification, transformation or replacement of existing metadata is necessary to maintain accurate
  and functional information following downstream processing»; (б) **пишет в AUP/условия запрет** умышленного удаления меток
  деплоерами и третьими лицами; не распространяет инструменты обхода меток.
- **Measure 1.3** (рекомендовано): имя системы, компания-провайдер, время; для правок — тип операции.
- **Measure 1.4** (рекомендовано): опция видимой метки в интерфейсе генерации для деплоеров.
- **Commitment 2–3**: детектор, доступный людям с понятным результатом; устойчивость к перекодированию, смене формата,
  кропу, ресайзу, скриншоту, «аналоговой дыре»; интероперабельность детекторов к 02.02.2027.

### 3.2 Раздел 2 — деплоеры (50(4), 50(5))

- **Measure 1.1 — дизайн**: главный элемент — **аббревиатура «AI» заглавными** (на национальном языке — только если
  английский несовместим с законом о языке); рекомендовано уточнение «generated»/«modified» и второй интерактивный слой
  (что изменено); стиль и размер — любые, пока метка ясна, различима и доступна; доступность — EN 301 549, WCAG 2.1,
  alt/ARIA, высокий контраст.
- **Measure 1.2 — размещение**: без действий пользователя; видна достаточное время; **встроена в контент** или
  равноценный оверлей UI; видна при первом показе на любом фоне; **картинка/видео — «например, в правом верхнем углу»**;
  видео — в начале и с интервалами, минимум после перерывов; аудио-дисклеймер только дополнением к визуальному.
- **Commitment 2**: внутренний процесс и документация с примерами; обучение персонала; канал для жалоб на неверные метки.
- **Commitment 3 — творческие работы**: метка может стоять **снаружи, рядом с кадром**, в элементах интерфейса, «клик/hover
  для подробностей» допустим, но сама метка видна без действий.

### 3.3 Иконки ЕС

Три иконки (Приложение 1): «AI + GENERATED» (полностью сгенерировано), «AI + MODIFIED» (частично изменено), базовая
«AI»; варианты — чёрная, белая, 50 % прозрачности; SVG и PNG (`ec.europa.eu/newsroom/dae/redirection/document/129546`,
`…/129547`; кэш `99-raw/cache/eu-ai-act-2026-09-23/eu-icons/`). Пользовательские тесты: вариант с текстом «modified»
заметнее и понятнее. Использование свободно, без атрибуции; иконка «не устанавливает соответствие сама по себе»;

### 4.3 Вес встроенного манифеста (L/01 на корпусе H/04b, L/02)

JPEG 512²: +57 184 Б (74 % файла) · PNG: +56 965 Б (24 %) · WebP: +140 833 Б (93 %) · AVIF: +13 534 Б (67 %) ·
AVIF-производная с родителем: +116 110 Б (95 %) · MP4 5 с 1280×720, новый манифест с родителем: +28 719 Б (4,2 %) ·

### 4.4 «Valid» и «Trusted»

`c2patool` без списка доверия пишет `Valid` + `signingCredential.untrusted` (подпись цела, подписант не проверен);
с официальным списком (`c2patool FILE trust --trust_anchors C2PA-TRUST-LIST.pem`; кэш
`99-raw/cache/c2pa-trust-2026-09-23/`, 30 корней: Google LLC, DigiCert, SSL.com, Adobe, TrustAsia, Huawei, Xiaomi, vivo,
Irdeto, Castlabs, Encypher и др.) — `Trusted` у подписантов из списка. Наш тестовый ключ c2patool — только `Valid`.
Публичная проверка: verify.contentauthenticity.org (временный список доверия), Adobe inspect.cr — официальный список
[документация: c2patool docs usage].

## 5. Что делать с производными

### 5.1 Правило (позиция базы)

1. **Мастер** — файл как скачан, побайтно; `scan` сразу после скачивания; sha256 — в паспорт (`04` §4).
2. **Производные для страницы** (лестница `srcset`, AVIF/WebP, видео H.264/AV1) — без встроенного C2PA (вес, §4.3) и **с
   XMP `DigitalSourceType`** после финального кодирования (`provenance_check.py stamp`).
3. **Сайт с аудиторией ЕС и дипфейками** (видимая метка обязательна) — плюс один из вариантов доказуемого провенанса:
   (а) sidecar `.c2pa` рядом с производной (`c2patool page.avif -p master -s`, файл не меняется, H/04b); (б) CDN с
   сохранением Content Credentials (Cloudflare, Fastly — H §4.4); (в) видео — новый манифест с родителем-мастером
   (+4 % веса, L/02). Подпись — своим сертификатом; «Trusted» — только от CA из списка доверия (покупка — решение заказчика).
4. **Не удалять** SynthID, `AIGC`, подпись Recraft, видимые знаки вендора без решения заказчика; для видео — всегда
   `-map_metadata 0 -movflags use_metadata_tags+faststart` (метка живёт и с `-an`).
5. **Не правка «чистыми» инструментами**: если нужна правка мастера, делать её инструментом, дописывающим C2PA (Deployment
   Guidance C2PA §5.3 п. 4), или считать результат новым мастером со своим паспортом.

Обоснование: Кодекс (разд. 1, Measure 1.2 a) признаёт «legitimate processing» метаданных при последующей обработке;
Руководство п. 74 разрешает опираться на маркировку вендора; пиксельный SynthID у Google и OpenAI не зависит от
метаданных. Слабое место — вендоры без водяного знака (BFL, Recraft-растр, Seedream через `mie`, Qwen, Grok): после
кодирования у производной остаётся только наш неподписанный XMP → для ЕС-дипфейков такие модели не брать или делать (3)
`[спорно]`.

## 6. Китай: меры CAC и GB 45438-2025

- **Меры по маркировке ИИ-контента** (CAC, MIIT, МОБ, NRTA; 国信办通字〔2025〕2号, в силе 01.09.2025): явная метка —
  картинка «в подходящем месте», видео — **начальный кадр и вокруг плеера**; при скачивании файл должен её содержать (ст. 4);
  неявная — в **метаданных** файла: атрибут ИИ, провайдер, номер контента; водяной знак поощряется (ст. 5); платформы
  проверяют метаданные и сами метят «подтверждено / возможно / подозревается» (ст. 6); по запросу пользователя провайдер
  может выдать контент без явной метки, если договор возлагает маркировку на пользователя, логи ≥ 6 мес. (ст. 9);
  **никто не вправе злонамеренно удалять, менять, подделывать, скрывать метки** (ст. 10) [документация].
- **GB 45438-2025** (SAMR + SAC, обязательный с 01.09.2025) — формат меток; текст стандарта платный, не снят. Фактический
  формат из выходов (C2/02): ключ `AIGC` в MP4 — `{"Label":"1","ContentProducer":"…","ProduceID":"…","ReservedCode1":…,
  "ContentPropagator":"…","PropagateID":"…","ReservedCode2":…}`; у MiniMax в `ReservedCode1` — подпись `TC260PG`
  (SM2, OID 1.2.156.10197.1.501; SM3 — …1.401) [проверено: C2/02 `results.json`].
- Для нас: правила адресованы китайским сервисам и платформам; сайт в РФ/ЕС ими прямо не связан `[спорно]`; метку `AIGC`
  сохраняем флагами ffmpeg (0 ₽), удалять намеренно — не нужно и противоречит ст. 10 и условиям MiniMax.

## Частые ошибки

- Считать, что C2PA вендора «доедет» до страницы: снимает любой ресайз и перекодирование, а встроенный манифест на
  веб-картинке весит больше самой картинки (§4).
- Путать обязанности: деплоер не может ограничиться машиночитаемой меткой вендора для дипфейка (Руководство п. 117).
- Прятать метку в правилах пользования, подвале или за кликом: «clear and distinguishable» не выполняется (п. 142); второй
  слой — да, но сама иконка — видна сразу.
- Маркировать иконки UI, фавиконы и код: вне сферы 50(2) (п. 68); лишние метки — шум, а не комплаенс.
- Писать в `-movflags` два раза: второй флаг перетирает первый (L/02).
- Штамповать XMP в подписанный мастер: подпись становится Invalid (H/04b); утилита `stamp` это блокирует.
- Использовать устаревший IPTC `digitalArt` вместо `trainedAlgorithmicMedia` (H §3).
- **Ошибки нейросетей-агентов**: «ст. 50 отложена до 2027 года» (отложен только 50(2) для старых систем и только до
  02.12.2026); «SynthID — часть C2PA» (нет, и его нет в реестре soft-binding C2PA); «у OpenAI нет водяного знака» (с
  19.05.2026 — SynthID); «Кодекс обязателен» (добровольный; обязательна ст. 50); «иконку ЕС нельзя использовать без
  подписания Кодекса» (можно, но не выдавать за знак подписанта).

## Открытые вопросы и противоречия

- Достаточно ли неподписанного XMP на производной для 50(2) у системы, не подписавшей Кодекс, если вендор ставит SynthID?
  Кодекс требует подписанные метаданные + водяной знак; «адекватные иные средства» оценит надзор `[спорно]`.
- SVG-иллюстрация от LLM — «исходный код» (вне 50(2)) или изображение (в сфере)? Для иллюстраций позиция базы — в сфере,
  для иконок — вне (п. 68 «icon-scale graphics») `[спорно]`.
- Подпись `<recraft-signature>`: после svgo тело SVG меняется — проверяется ли подпись и что именно она подписывает, Recraft
  не публикует → хранить исходный SVG как мастер `[не проверено]`.
- Сохраняет ли канал (polza → KIE, RouterAI, Gen-API) C2PA и видимые знаки вендора — L-01/L-02 фазы 5.
- Переживает ли SynthID наш AVIF q≈40–60 и видео CRF 28 — L-03 фазы 5 (вендор заявляет устойчивость к сжатию —
  `[мнение вендора]`).
- Fastly не переносит C2PA в JPEG XL (H) — если выбирать JXL для ЕС-дипфейков, провенанс держать sidecar.
