# Единый state оркестратора

State оркестратора — **не** копия детального знания о сущностях. Это
**срез по всем слоям** (где мы во всём воркфлоу) + **открытые нити**
(маршрутный журнал в forward-only форме). Детальную per-kind память ведут
исполнители; оркестратор лишь ссылается на неё.

## Расположение

```
.claude/skills/entrypoint/state/
├── index.md                 (срез по слоям/проектам + ссылки на per-kind state исполнителей)
└── threads/<slug>.md        (открытая нить = маршрут незавершённого разбора)
```

Создаётся **по требованию**: каталоги и файлы появляются, когда есть что
записать. Forward-only — закрытое удаляется, история живёт в `git log`.

## `index.md` — срез по слоям

Singleton-карта «где мы». По каждому слою (и каждому проекту для проектных
слоёв) — текущая фаза, счётчики draft/stable и ссылка на детальный state
исполнителя. Оркестратор **не дублирует** содержимое per-kind заметок —
только указывает, где смотреть.

```markdown
# Срез по слоям

## business
- фаза: `cohesion` · profile stable · реестр проблем: 5 (4 stable, 1 draft)
- детально: `../../business-deep-dive/state/`

## ajtbd
- сегменты: 3 stable · граф работ собран по 2 из 3
- детально: `../../segment-deep-dive/state/`, `../../job-graph-deep-dive/state/`

## swot
- факторы по 4 проблемам · проблема `slow-launch` без ставок
- детально: `../../swot-deep-dive/state/`

## hypothesis-map
- метрики по 3 проблемам · цель `retain-paid` без метрики
- детально: `../../hypothesis-map-deep-dive/state/`

## projects/clinic
- фаза: `surface` · vision stable · lifecycle: `mvp`
- interface: who/situation заполнены, zone пусто
- screens: —
- детально: `../../project-deep-dive/state/clinic/`, `../../interface-deep-dive/state/clinic/`

## projects/intake-bot
- фаза: `discovery` · vision draft · lifecycle: `draft`
- детально: `../../project-deep-dive/state/intake-bot/`
```

`index.md` — **рабочий срез, не журнал**: устаревшая строка
перезаписывается под актуальное состояние, а не дополняется «было/стало».
Если по слою ничего не начато — строки нет (не писать «пусто» ради
полноты; отсутствие = не трогали).

Источник истины по числам — сами `docs/` и per-kind state исполнителей;
`index.md` — кэш для быстрой сводки. При расхождении верить `docs/` и
перезаписать срез.

## `threads/<slug>.md` — открытая нить

Нить — **незавершённый разбор сырья** или **сквозная задача через
несколько слоёв**. Несёт маршрут: какие чанки куда направлены и какие ещё
**ждут**. Это и есть «маршрутный журнал» — но в forward-only форме:
закрытый чанк **удаляется**, нить без открытых чанков **удаляется**.

```markdown
---
kind: thread
slug: sozvon-2026-06-06
opened-from: транскрипт созвона с клиникой, 2026-06-06
---

## Маршрут (ждут разбора)
- чанк «платные не возвращаются» → business / business-problem — ждёт
- чанк «отток 8% за Q1» → hypothesis-map / metric (baseline ← current-metric) — ждёт
- чанк «приложение с напоминаниями» → projects/? / capability — ждёт уточнения проекта

## Открытые нити (смежные слои не потерять)
- субъект влияния (на кого целим возврат) — после metric завести в hypothesis-map/subject

## Что дальше
- начать с business-problem (корень), затем метрика поверх current-metric
```

Frontmatter: `kind: thread`, `slug`, `opened-from` (краткий дескриптор
источника). Секции (любая опциональна):

- **`## Маршрут (ждут разбора)`** — строки `чанк → слой/kind/исполнитель →
  ждёт`. Делегированный и закрытый исполнителем чанк — **убрать**.
- **`## Открытые нити`** — смежные слои, которые нельзя потерять
  (авторские сквозные рёбра, проспективные сущности).
- **`## Что дальше`** — порядок разбора.

Нить закрывается (файл удаляется), когда все чанки разобраны и открытых
нитей не осталось.

## Что НЕ хранить в state оркестратора

- Детальные открытые вопросы по сущности (это per-kind state исполнителя).
- Доменные формулировки «на всякий случай».
- Историю сессий, даты, «было/стало», «решено такого-то».
- Дубликаты содержимого `docs/` (slug/name/status — в артефактах).

## Перекрёстная видимость

Read-only видимость клиентского оркестратора и исполнителей — правила в
`cross-read.md`. Оркестратор **пишет только в свой** state.
