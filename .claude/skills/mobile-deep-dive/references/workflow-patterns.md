# Режимы ведения сеанса

Режим выбирается по тому, что есть в слоях-источниках **той же поверхности
того же проекта**: `interface/<surface>/` и `services/<svc>/domains/`.

## A. С аналитикой

**Сигнал**: в `interface/<surface>/situation.md` есть ситуации; блоки и
данные заведены; домены — если у приложения есть бэкенд.

1. Освежить канон: `docs/projects/_template/mobile/README.md` и формы
   нужных kind'ов.
2. Прочитать источники: `situation.md`, `block.md`, `zone.md`,
   `data-items.md`, `who.md`; `services/service.md` + домены сервисов,
   обслуживающих поверхность.
3. Синтезировать кандидатов по карте `interface-context.md` в порядке
   inside-out: агрегат / data-item → сущность; блок → экран; переходы →
   сценарий; ситуация → фича; зоны → оболочка; условия старта извне → точки
   входа; шаги с возможностями устройства → разрешения; «не открывая
   приложение» → системные действия; «на лету» → виджеты; шаги системного
   участника → фоновые задачи.
4. Каждый кандидат — через волну `AskUserQuestion` (до 4): подтвердить /
   отбросить / переименовать. Не выдумывать записи, которых нет в
   источнике.
5. Когда базовая карта собрана — предложить пройти линзу платформы
   (`platform-lens.md`) по непройденным разделам.
6. Открытые места — в ветку state (`## Открытые вопросы`, `**blocker**`
   для блокирующих).

## B. С эскизом

**Сигнал**: слои-источники пусты или тонки, но аналитик принёс эскиз
экранов, описание сценария, скриншоты аналога или транскрипт.

1. Прочитать материал, извлечь кандидатов и привязать к kind'ам (место →
   экран, действие → фича, данные → сущность, «придёт уведомление» → точка
   входа, «скажу голосом» → системное действие, «на главном экране» →
   виджет, «само обновится / напомнит» → фоновая задача).
2. Показать план в чат по kind'ам, подтвердить волной `AskUserQuestion`.
3. Завести подтверждённое как `draft`-строки; дыры по обязательным слотам и
   отсутствующие ситуации-источники — `**blocker**` в state.
4. Предложить довести аналитику: ситуации — `/interface-deep-dive`, домены —
   `/domain-deep-dive`. Stable требует источников: колонки `situation` /
   `situation-ref` / `source` должны заполниться до промоушна.

Извлечённое из эскиза — кандидаты до подтверждения, не факты. Скриншот
аналога — референс, не источник: его экраны не становятся нашими без
ситуации.

## C. С нуля

**Сигнал**: ни аналитики, ни эскиза.

1. Рамка приложения (scaffold) + волна базовых вопросов про главные шаги
   пользователя и данные (3–4).
2. Из ответов — минимальный набор `draft`-записей; остальное — «Что копать
   дальше» в state.
3. Пройти линзу платформы — она даёт аналитику карту «что вообще возможно»
   и наполняет kind'ы вне экранов.
4. Предупредить: без interface-слоя карта останется в `draft`; вести
   аналитика в `/interface-deep-dive <project-slug> <surface>`.

## Каскады удаления

Запись удаляется не в одиночку:

- удалить **entity** → снять её из `screens.entities`, `features.entities`,
  `widgets.shows`, `background-tasks.entities`, из покрытия `shared-api.md`,
  из `shell.md#Offline`;
- удалить **screen** → снять из `flows.шаги`, `features.screens`,
  `shell.md` (табы, `start`, auth-gate), `entry-points.target`,
  `system-actions.target`; фича, потерявшая последний носитель, — кандидат
  на удаление, спросить;
- удалить **feature** → снять из `screens.features`,
  `permissions.используется`, `shared-lib` (флаги, события);
  `system-actions.feature` и `background-tasks.runs` без фичи — спросить
  судьбу записи;
- удалить **entry-point** → снять из `widgets.tap`, из каналов
  `notification:<slug>` системных действий, из `result` фоновых задач;
- удалить **permission** → снять из `background-tasks.permissions`; задача
  `continuous` без разрешения теряет stable — спросить;
- удалить **system-action** → пересчитать зеркало `widgets.actions`, снять
  `action:<slug>` из `permissions.используется`;
- удалить **widget** → удалить или перенацелить точку входа `kind: widget`
  с его `pattern`, снять каналы `widget:<slug>`, `result: widget:<slug>`;
- удалить **background-task** → снять `trigger: background:<slug>` у
  push-входов, `refresh: background:<slug>` у виджетов,
  `background:<slug>` из `permissions.используется`;
- удалить ресурс **shared-api** → сущности с этим `source` остаются без
  покрытия — blocker.

После каскада — прогнать чек-лист `draft-stable.md` по затронутым записям.

## Стиль вопросов

- Волна — до 4 вопросов, не 10. Решения — через `AskUserQuestion`.
- Имена — из источника (`situation.name`, имя агрегата, имя блока);
  идентификаторы (`slug`, `key`, push-категорию) выводит скилл.
- Enum'ы канона — опциями по одной на значение; тексты (`rationale`,
  `phrases`, `response`, `freshness`, `fallback`, `when`) — только Other.
- Не предлагать «оптимизации» карты сверх того, что диктует источник, и не
  добавлять виджеты, голос и фон «потому что так принято» — только по
  ответу аналитика на вопрос линзы.
- Не закрывать сессию без чек-листа `draft-stable.md` хотя бы по одной
  правленой записи.
