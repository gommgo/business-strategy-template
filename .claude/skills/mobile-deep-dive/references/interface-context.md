# Карта синтеза: interface → mobile

Источник мобильной карты — UX-слой **той же поверхности того же проекта**
(`docs/projects/<project-slug>/interface/<surface>/`) и домены сервисов.
Скилл предлагает кандидатов **из источника**, аналитик подтверждает,
отбрасывает или переименовывает. Рифма смысловая, не механическая: один
блок не обязан стать ровно одним экраном.

## Что из чего вырастает

| источник (interface / домены) | кандидат в mobile | как читать |
|---|---|---|
| ситуация (situation) | **фича** (`features.situation`) и экран, где она разыгрывается (`screens.situation-ref`) | одна ситуация = одно законченное действие → одна фича; несколько ситуаций одного места — один экран |
| блок (block) — узел навигации | **экран** (`screens.key`) | блок ≈ адресуемое место; мелкие блоки одной зоны могут жить на одном экране — решает аналитик |
| зона (zone) | группа экранов, таб оболочки (`shell.md#Root`) | корневые зоны — кандидаты в табы; вложенная зона — стек внутри таба |
| `block.entrypoint: true` | стартовый экран (`shell.start`), шаг `app-start` | несколько входов по ролям — несколько стартовых веток сценария |
| `block.transition-to-block` / `transition-from-zone` | шаги и переходы `flows` | межзонный переход — кандидат в отдельный сценарий |
| ситуация системного участника (who — планировщик, система) | **фоновая задача** (`background-tasks.situation`) и/или push-вход (`entry-points`, `trigger`) | «система сама вовлекает напоминанием» — напоминание: фон + уведомление |
| `situation.when` вида «пришло уведомление», «перешёл по ссылке», «поделился из другого приложения» | **точка входа** (`entry-points`) | условие старта извне = вход |
| `situation.when` / `using-what` вида «руки заняты», «голосом», «не открывая приложение» | **системное действие** (`system-actions.situation`) | бизнес-средство «голосовая команда», «кнопка в уведомлении» |
| `situation.when` / `using-what` вида «взглянул на телефон», «виджет», «во время доставки/записи» | **виджет** (`widgets.situation-ref`) | предъявление вне экранов приложения |
| субстраты (ux-substrate) ситуации | состав фичи и состояния экрана | `команда` → фича; `ввод`/`выбор` → входные данные фичи; `инфо`/`список` → сущности экрана и состояния `empty`/`populated` |
| данные (data-items) | **сущность** (`entities`), её `ключевые поля` | есть агрегат в домене — `source`/`domain-ref` на него; бэкенда нет — `source: local` |
| агрегат / сущность домена | **сущность** (`entities.domain-ref`), ресурс `shared-api` | поля — в языке источника |
| событие домена, адресованное человеку | push-вход (`trigger: event:<ctx>.<Event>`), обновление виджета (`refresh`), фоновая задача (`remote-event`) | события нет — требование в state, не выдумка |
| шаг, которому нужна возможность устройства | **разрешение** (`permissions.situation`) | ситуация — обоснование; без неё разрешение не заводится |

## Дыры синтеза

После синтеза каждая ситуация мобильной поверхности должна дойти хотя бы до
одного носителя: экрана, фичи, системного действия, виджета или фоновой
задачи. Ситуация без носителя — кандидат в сводку («UX-точка не дошла до
приложения»). Обратное тоже дыра: запись mobile-слоя без ситуации-источника
— сначала вопрос аналитику, вести ли его в `/interface-deep-dive`.

## Чего скилл не делает с interface

- Не заводит и не правит записи `interface/<surface>/` — единая точка входа
  туда — `/interface-deep-dive`.
- Не переносит в mobile-слой дерево компонентов и облик: экран здесь —
  ключ, состояния, сущности и фичи; облик — токены дизайн-системы
  продукта, композиция элементов — код-репо.
- Не тянет ситуации другой поверхности: один и тот же шаг на web и в
  приложении — две записи в двух слоях, общее сводит `/cross-audit`
  (угол `mobile-web` — для общих путей ссылок).
