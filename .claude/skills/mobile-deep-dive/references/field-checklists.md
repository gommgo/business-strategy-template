# Чек-листы полей по kind

Что должно быть заполнено для `stable`, в каком порядке копать и откуда
брать опции. Форма колонок — в `docs/projects/_template/mobile/_template/<kind>.md`
(единственный канон; здесь — порядок работы). Универсально обязательное:
идентификатор (`slug` / `key`), `name`, `description`, `status`.

## Стыки со словарями продукта

Ключи и колонки слоя — контракт с `<org>/mobile`: стыки добавляют смысл,
но ничего не переименовывают. Канон стыков — `docs/projects/_template/mobile/README.md`.

- **Состояния** — ключи `states` приложения сопоставлены словарю
  состояний экрана (S01–S24) таблицей раздела «Состояния экрана и
  словарь»; набор экрана читается через неё (раздел screens ниже).
- **Тексты** — жанр `interface` и голос продукта; реестра текстов у слоя
  нет, роль строки задаёт поле (таблица «поле → роль» раздела «Тексты:
  роли и жанр»). Формулировки — аналитика; голоса продукта нет — долг и
  предложение `/design-deep-dive <project-slug>` (уровень продукта).
- **Облик** — значения темы дают токены дизайн-системы продукта
  (`docs/projects/<project-slug>/design/system.tokens.json`), оболочка
  держит только политику темы (раздел «Стык с дизайном» канона).
- **Паритет с вебом** — по умолчанию; ценность веба, которой в
  приложении сознательно нет, — строка «Урезание» файла возможностей
  мобильной поверхности с основанием и сроком пересмотра. Это продуктовый
  слой: скилл предлагает `/project-deep-dive <project-slug>`, сам туда не
  пишет.

## entities

**Для stable:** `ключевые поля`, `source`, `cache`; `domain-ref` — если
`source ≠ local`.
**Порядок:** источник (агрегат домена / data-item / `local`) → поля в языке
источника → `cache` (что читается без сети).
**Опции:** агрегаты `services/*/domains/`, записи `data-items.md`; enum
`cache`.
**Дыры:** сущность без потребителя (ни экран, ни фича, ни виджет); `source`
на ресурс, которого нет в `shared-api.md`.

## screens

**Для stable:** `entry`, `states`, `platforms`, `situation-ref`; `entities`
и `features` — по факту.
**Порядок:** ситуации-источники → `key` (скилл выводит) → `entry` →
`states` по набору экрана → сущности → фичи → достижимость (оболочка /
сценарий / точка входа / `target` системного действия).
**Набор `states`** — норма канона экранов, прочитанная через таблицу
соответствия: экран с сетью — `loading` и `error`; экран с коллекцией —
`empty` (его ситуации несут субстрат `список` или экран показывает
перечень сущности); экран объекта, который открывают по ключу из ссылки
или пуша, — `not-found`; доступ, ограниченный ролями, —
`permission-denied`; экран с офлайн-политикой (`shell.md`, «Offline») —
`offline`. Тексты состояний — роли по правилу «Тексты состояний» канона
экранов.
**Опции:** ситуации и блоки interface; enum `entry`; словарь `states`
(ключи контракта, их состояния словаря — описанием опции).
**Дыры:** экран-сирота; экран с сетью без `offline`-решения (сверить с
`shell.md#Offline`); `not-found` у объекта в архиве или корзине — объект
существует, это не `not-found`.

## flows

**Для stable:** `триггер`, `шаги`, `выход`, `ветки ошибок`.
**Порядок:** цель сценария → триггер → шаги по существующим `screens.key` →
выход → ветки ошибок (сеть, 401, офлайн).
**Обязательные заготовки:** `app-start`; `login` — если у приложения есть
вход (рамка в `_frame.md`).
**Дыры:** шаг на несуществующий экран; сценарий с сетью без ветки ошибки.

## features

**Для stable:** `situation`, `shared`, `platforms`; `screens` / `entities` /
`api-ops` — по факту; носитель ≥ 1 (экран, точка входа, системное действие
или фоновая задача).
**Порядок:** ситуация-источник → что меняется (description) → экраны →
сущности → операции API (или `—` у локальной фичи) → `shared` (`false` —
только платформенная возможность, с обоснованием в описании).
**Дыры:** ссылка на другую фичу; `api-ops`, которых нет в `shared-api.md`.

## shell

Singleton с секциями; зрелость — по секциям.
**Для stable:** `## Root` (`root`, `tabs` при табах, `start`), `## Auth-gate`
(что без сессии — при наличии входа), `## Overlays`, `## Offline` (при
`full` — строка «Отложенные правки»: где видны статусы отложенных правок и
что видно у правки, которая не прошла, или «не применимо»),
`## Theme & locale`, `## Legal` (при публикации в магазинах).
**Порядок:** корень навигации (вариант — по таблице ux 02/02 §1.6, раздел
«Корневая навигация» канона) → auth-gate → оверлеи (тексты: `banner`;
`title`, `body` и `action`) → офлайн-политика по экранам/сущностям и
отложенные правки → тема и язык (политика темы: режимы токенов
дизайн-системы, умолчание `system` при двух темах; значения темы в
оболочку не пишутся) → правовые документы.
**Дыры:** таб на несуществующий экран; `Offline: full` без фоновой задачи
синхронизации или без строки «Отложенные правки».

## entry-points

**Для stable:** `kind`, `pattern`, `target`, `требует сессии`,
`pending после логина`; `trigger` — у `push`.
**Порядок:** что за вход (enum `kind`) → `target` → `pattern` (категорию
push выводит скилл; у `widget` — slug виджета) → сессия и pending →
`trigger` (`event:` из доменов / `background:<slug>` / расписание). Текст
push-уведомления, если его формулирует аналитик, — роль `push`.
**Обязательная заготовка:** `demo` — если приложение идёт в магазины.
**Дыры:** вход `widget` без записи `widgets.md`; push без `trigger`;
пересечение путей deep link.

## permissions

**Для stable:** `android` / `ios` (по `platforms`), `situation`,
`rationale`, `когда`, `fallback`, `используется` (≥ 1).
**Порядок:** ситуация-обоснование → что даёт пользователю → `rationale`
(слова аналитика; роль текста — `body`) → момент запроса (в момент
ценности) → `fallback` → где используется (фичи, экраны,
`background:<slug>`, `action:<slug>`).
**Дыры:** разрешение без использования; запрос на первом экране.

## system-actions

**Для stable:** `feature`, `channels`, `mode`, `target` (при `opens-app`),
`response`, `требует сессии`, `на заблокированном экране`, `platforms`,
`situation`; `phrases` — при канале `voice`.
**Порядок:** ситуация-источник → фича (существующая или stub) → каналы →
слова пользователя (`phrases`, `parameters` — от аналитика) → `mode` и
`target` → `response` (ответ ассистента — роль `toast`, уведомлением —
`push`) → сессия и блокировка. После правки `channels` — пересчёт
зеркала `widgets.actions`.
**Опции:** фичи; enum `channels` (виджеты и push-входы поверхности), `mode`.
**Дыры:** канал на несуществующий виджет / push-вход; `headless` без
`response`.

## widgets

**Для stable:** `kind`, `shows`, `states` (⊇ `placeholder`, `populated`),
`tap` (кроме `tile` без перехода), `freshness`, `refresh`, `platforms`,
`situation-ref`.
**Порядок:** ситуация-источник → `kind` → что показывает (сущности и поля)
→ состояния → тап (точка входа `kind: widget`, при отсутствии — stub) →
требование свежести (слова аналитика) → чем обновляется → что видно без
разблокировки (в `description` у `lock` / `live`).
**Дыры:** `refresh: background:<slug>` на несуществующую задачу; `live` без
длящегося события; `actions` расходится с каналами системных действий.

## background-tasks

**Для stable:** `trigger`, `when`, `timing`, `runs`, `result`, `fallback`,
`platforms`, `situation`; `permissions` — если нужны.
**Порядок:** ситуация-источник и польза → `trigger` и `when` → `timing`
(`exact` — только обещанный момент и только уведомление; `continuous` —
видимость и разрешение) → что запускает и какие сущности трогает → условия
→ результат → `fallback` → разрешения.
**Дыры:** `exact` без `notification:<slug>` в `result`; `continuous` без
разрешения; `remote-event` без события в доменах (требование в state).

## shared-api

**Для stable:** по ресурсу — `операции`, `владелец`, `идемпотентность`,
`offline-кэш`; по сценарию данных — `состояние`. Контракт покрывает все
сущности с `source ≠ local`.
**Порядок:** сущности с бэкенд-источником → ресурсы и операции (как в
спецификации бэкенда; отсутствующие — требование, не выдумка) → владелец
(`services/<svc>`) → сценарии данных по обязательным состояниям экранов:
`empty` и `populated` — всегда; `error` и `loading-initial` — у
поверхности с сетью; `partial-few` — у экранов с коллекцией;
`overflow-many` — где коллекция бывает кратно больше расчётной;
`no-permission` — когда доступ ограничен ролями. Имена `empty`,
`populated`, `authenticated`, `error` — контракт и не переименовываются,
новые сценарии называются ключами словаря состояний экрана.
**Приложение без бэкенда:** таблица ресурсов пуста, сценарии данных
описывают локальные состояния.

## shared-lib

Секционный файл; зрелость — по строкам секций.
**Для stable:** `## Locales` (⊇ `ru`), `## i18n` (коды ошибок бэкенда —
если он есть; тексты ошибок — роль `error`), `## Logging`,
`## Feature flags` (каждый флаг используется ≥ 1 фичей),
`## Analytics events` (если аналитика включена в stack).
