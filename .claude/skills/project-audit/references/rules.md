# Реестр правил project-audit

У каждого правила — id, тяжесть, где, как обнаружить, что рекомендовать и откуда норма: форма
`docs/projects/_template/project/<kind>.md` или адрес базы знаний скилла дизайна (короткий адрес «ux 13/04 §7» —
`.claude/skills/design-deep-dive/kb/INDEX.md` §1). Проверка — чтением файлов по форме, как у всех структурных аудитов
шаблона; правило, которое требует суждения, так и помечено — «чтением по критериям», и сомнение идёт в отчёт с цитатой.

Категории:

- **R-STRUCT** — структура файлов, перечисления, хребет поверхностей.
- **R-SEM** — семантические подозрения в старых kind слоя.
- **R-COV** — покрытие и стиль.
- **R-VS** — vision: состав, успех, принципы, MVP, допущения, сводки, ссылки.
- **R-RL** — роли и постуры.
- **R-GL** — глоссарий объектов и словарь действий.
- **R-CAP** — возможности: ядро, паспорт, размер, покрытие вниз и вверх.
- **R-MX** — матрица «пользователь × объект × действие» (раздел отчёта).

## Состав слоя

Продуктовый слой проекта `docs/projects/<project-slug>/`:

- **1 singleton** `vision.md`;
- **реестр-хребет** `surface.md` — поверхности; их slug'и — ключи партиционирования;
- **папка возможностей** — по файлу `capability/<surface>.md` на поверхность (имя файла — slug из `surface.md`): реестр,
  `## Паспорта`, `## Урезание`;
- **7 плоских кросс-поверхностных таблиц:** `user.md` (+ таблица «Постура»), `object.md` (+ «Атрибуты»,
  «Представления»), `action.md`, `integration.md` (`## Провайдеры`, `## Функции`), `boundary.md`, `constraint.md`,
  `market.md`.

«Все табличные файлы» ниже — `surface.md`, семь плоских таблиц и каждый файл возможностей; `vision.md` — singleton.

**Что аудит читает кроме слоя** — только для названных правил и только чтением:

- листинг папок слоёв проекта — `interface/`, `screens/`, `fsd/`, `site/`, `telegram-bot-flow/`, `mobile/`, `design/` —
  R-STRUCT-010;
- в `interface/<surface>/` той же папки проекта: колонку `capabilities` и имена `situation.md`, мета `capability` и
  основной путь `scenario.md`, имена `zone.md` и `block.md` — R-CAP-006, R-CAP-008, R-GL-002;
- раздел «Решения» `screens/<surface>/map.md` и заметки поверхностей в ветке state — R-RL-002;
- наличие файлов уровня продукта `<slug>/voice.yaml`, `<slug>/voice.product.yaml` — R-VS-008 (их содержание проверяет
  `/design-audit`);
- листинг `docs/projects/` — R-SEM-011.

**Словарь правил:**

- **Набор vision** — по поверхностям (`docs/projects/_template/project/vision.md § Разделы`): **полный** (двенадцать
  разделов), если хоть одна поверхность идёт маршрутом приложения; иначе **минимум** — `Name`, `Problem`, `Users`,
  `Success`, `Non-goals` и `Assumptions`, если допущения есть.
- **Маршрут приложения** — поверхности `web` рода `app`, `admin`, `desktop`, `embed`.
- **Интерактивная поверхность** — маршрут приложения, `mobile`, `bot`.
- **Пусто** — ячейка пуста, держит `—` или заглушку формы (`<…>`). Исключения — поля, где `—` по форме значение:
  `web-kind` не веб-поверхности, `statuses` объекта без жизненного цикла, `trace` без ребра вверх, опциональные поля
  паспорта.

## Структурные правила (R-STRUCT-*)

### R-STRUCT-001 — Дубликаты slug в одном файле

**Severity:** `error`.

**Где:** все табличные файлы и их подтаблицы.

**Обнаружение:** в одном файле два ряда с одинаковым ключом:

- основная таблица — `slug`; у возможностей область уникальности — **один файл поверхности**: один slug на разных
  поверхностях — разные воплощения одной ценности, дубль — только повтор внутри файла;
- «Атрибуты» — пара `object` · `slug`; «Представления» — пара `object` · `context`; «Постура» — пара `user` · `surface`;
  «Урезание» — `slug`; «Паспорта» — повтор заголовка `### <slug>`.

**Рекомендация:** «два ряда с ключом X в файле Y — переименовать один через
`/project-deep-dive <project-slug> <kind>:<slug>` или объединить».

### R-STRUCT-002 — Обязательный слот пуст при `status: stable`

**Severity:** `error`.

**Где:** все файлы.

**Обнаружение:** запись `stable`, а обязательный слот пуст. Универсально обязательное — `slug`, `name`, `description`,
`status`. По kind:

| kind | обязательно при stable |
|---|---|
| `vision` | оси `audience`, `intent`, `market-maturity`, `lifecycle`; непустой `addresses-problem` (≥ 1 slug); разделы набора — R-STRUCT-004 и R-VS-001 |
| `surface` | `type`, `lives-at`, `user` (≥ 1); род `web-kind` — R-STRUCT-009 |
| `user` | `context`, `jobs`, `pains`, `success`; строка постуры — R-RL-001 |
| `object` | R-GL-001; `creates`, `deletes` — R-MX-001 |
| `action` | R-GL-003 |
| `capability` | R-CAP-001 (реестр, паспорт, урезание) |
| `integration` (провайдер) | `direction`, `owner`, `payload`, `surface` (≥ 1), `target`; `sibling-project` — обязателен **тогда и только тогда**, когда `target: sibling-project`, иначе обязан быть `—` |
| `integration` (функция) | `integration` (slug провайдера), `name`, `description`, `direction` |
| `boundary` | `why` |
| `constraint` | `kind`, `source` |
| `market` | `url`, `sources` (≥ 1) |

`sibling-project`, заполненный при `target: external`, — тоже нарушение слота. Здесь проверяется слот (есть или пуст);
существование поверхности или проекта по ссылке — R-SEM-010, R-SEM-011.

**Норма:** колонки форм; чек-листы полей `.claude/skills/project-deep-dive/references/field-checklists.md`.

**Рекомендация:** «заполнить слот X или понизить запись в draft через
`/project-deep-dive <project-slug> <kind>:<slug>`».

### R-STRUCT-003 — Невалидное значение перечисления

**Severity:** `error`.

**Где:** все файлы с перечислениями.

| поле | допустимо |
|---|---|
| `vision.audience` | `b2b`, `b2c`, `b2b2c`, `internal`, `gov` |
| `vision.intent` | `new-service`, `improve-service`, `internal-problem`, `client-problem` |
| `vision.market-maturity` | `prospective`, `served` |
| `vision.lifecycle` | `draft`, `accepted`, `build`, `mvp`, `beta-testing`, `stable`, `updating` |
| тип приложения в сводке `Name` | `admin`, `client`, `mixed`, `—` |
| `surface.type` | `web`, `mobile`, `api`, `admin`, `bot`, `desktop`, `embed`, `other` |
| `surface.web-kind` | `landing`, `site`, `app`, `—` |
| постура `return` | `daily`, `weekly`, `monthly`, `rare` |
| постура `main-work` | `yes`, `no` |
| постура `posture` | `sovereign`, `transient`, `auxiliary`, `mixed` |
| постура `density` | `high`, `medium`, `low` |
| постура `learning` | `expected`, `minimal`, `excluded` |
| атрибут объекта `type` | `text`, `number`, `money`, `date`, `datetime`, `enum`, `bool`, `file`, `ref:<object>`; суффикс `[]` |
| атрибут объекта `required` | `true`, `false` |
| представление `context` | `row`, `card`, `search`, `option`, `notification`, `breadcrumb`, `inline`, `page` |
| `action.reversibility`, паспорт `reversibility` | `undo`, `soft-delete`, `confirm`, `irreversible` |
| `capability.priority` | `hub`, `critical`, `regular` |
| элемент `capability.trace` | `job:<slug>`, `hypothesis:<slug>` |
| паспорт `frequency` | `hours-daily`, `daily`, `weekly`, `monthly`, `rare`, `once` |
| паспорт `error-cost` | `low`, `medium`, `high` (+ кто платит) |
| паспорт `scope` | `own`, `team`, `all` |
| паспорт `duration` | `instant`, `short`, `long`, `background` |
| паспорт `ai` | `no` или блок с `mode`: `automation`, `augmentation` |
| `integration.direction` (провайдер) | `in`, `out`, `duplex` |
| `integration.owner` | `we`, `partner`, `both` |
| `integration.target` | `external`, `sibling-project` |
| `integration` функция `.direction` | `out`, `in` |
| `constraint.kind` | `regulation`, `sla`, `contract`, `technical`, `other` |
| `<любой>.status` | `draft`, `stable` |

**Обнаружение:** значение не из списка (с учётом обратных кавычек и `—` у опциональных полей).

**Рекомендация:** «значение X не из перечня — выбрать одно из {…} через
`/project-deep-dive <project-slug> <kind>:<slug>`».

### R-STRUCT-004 — Vision без раздела своего набора

**Severity:** `error`.

**Где:** `vision.md` + `surface.md` (набор).

**Обнаружение:** нет H2-раздела своего набора: у полного — любого из двенадцати (`Name`, `Problem`, `Users`,
`Positioning`, `Experience principles`, `Voice`, `Success`, `MVP`, `Devices and accessibility`, `Constraints`,
`Non-goals`, `Assumptions`); у минимума — `Name`, `Problem`, `Users`, `Success`, `Non-goals`, а при пометках
`(допущение)` — ещё `Assumptions`. Имена разделов — английские, ровно как в форме: их читают аудиты и хаб `<org>/infra`.

**Норма:** `vision.md § Разделы`, критерий 7.

**Рекомендация:** «добавить раздел `<H2>` — `/project-deep-dive <project-slug> --phase discovery` (`MVP` и сводки —
`--phase cohesion`)».

### R-STRUCT-005 — Невалидный status

**Severity:** `error`.

**Где:** все файлы.

**Обнаружение:** `status` не `draft` и не `stable`.

**Рекомендация:** «status должен быть `draft` или `stable`; исправить через
`/project-deep-dive <project-slug> <kind>:<slug>`».

### R-STRUCT-006 — Stable с blocker в state

**Severity:** `error`.

**Где:** все файлы + ветка state проекта.

**Обнаружение:** запись `stable`, а в её заметке есть строка с пометкой `**blocker**` или `**жду аналитика**`. Заметка —
`../entrypoint/state/projects/<project-slug>/project/<kind>/<slug>.md` (у vision — `…/project/vision.md`, у возможности
— `…/project/capability/<surface>/<slug>.md`).

**Рекомендация:** «stable несовместим с открытым blocker'ом: закрыть вопрос или понизить запись в draft».

### R-STRUCT-007 — Файл возможностей для поверхности вне реестра

**Severity:** `error`.

**Где:** файлы `capability/<surface>.md` + `surface.md`.

**Обнаружение:** имя файла возможностей без расширения не совпадает ни с одним `slug` реестра: связь возможность →
поверхность структурная.

**Рекомендация:** «файл `capability/<surface>.md` висит без поверхности в реестре — завести поверхность в `surface.md`
или переименовать или удалить файл через `/project-deep-dive <project-slug>`».

### R-STRUCT-008 — Поверхность реестра без файла возможностей

**Severity:** `hint`.

**Где:** `surface.md` + файлы возможностей.

**Обнаружение:** у поверхности реестра нет файла `capability/<surface>.md`. У поверхности маршрута приложения файл нужен
сценариям и экранам; у `web` рода `landing` и `site` он по желанию — подсказка лишь напоминает о выборе.

**Рекомендация:** «поверхность `<surface>` без файла возможностей — завести через
`/project-deep-dive <project-slug> capability:<surface>` или проверить, нужна ли поверхность».

### R-STRUCT-009 — Род веб-поверхности не по типу

**Severity:** `error` / `warning`.

**Где:** `surface.md`.

**Обнаружение:**

- `type: web`, а `web-kind` пуст или `—`: у stable — `error`, у draft — `warning`. Род выбирает маршрут и репозиторий
  кода: без него неизвестно, какой слой проектирует композицию и какой код поднимет поверхность;
- `type` не `web`, а `web-kind` не `—` — `error`: род есть только у веб-поверхности, у остальных маршрут задаёт тип.

**Норма:** `surface.md`, критерий 6 и колонка `web-kind`.

**Рекомендация:** «назвать род поверхности `<surface>` (`landing` · `site` · `app`) через
`/project-deep-dive <project-slug> surface:<surface>`».

### R-STRUCT-010 — Папка слоя не по реестру, типу и роду

**Severity:** `error`.

**Где:** листинг папок слоёв проекта + `surface.md`.

**Обнаружение:** папка поверхности `<слой>/<X>/` не соответствует строке реестра `X` или её типу и роду:

- `interface/<X>/` — у любой поверхности, кроме `web` рода `landing` и `site`;
- `screens/<X>/`, `fsd/<X>/` — у `web` рода `app`, `admin`, `desktop`, `embed`;
- `site/<X>/` — только у `web` рода `landing` и `site`;
- `telegram-bot-flow/<X>/` — только у `bot`; `mobile/<X>/` — только у `mobile`;
- `design/<X>/` (служебные папки с `_` не в счёт) — у `web`, `admin`, `desktop`, `embed`.

Проверяется только листинг: содержимое папок проверяют аудиты их слоёв (`/interface-audit`, `/screen-audit`,
`/fsd-audit`, `/design-audit`, `/telegram-bot-flow-audit`, `/mobile-audit`).

**Норма:** `docs/projects/_template/project/README.md § Связи` («Поверхность — структурная ось»).

**Рекомендация:** «папка `<слой>/<X>/` не по реестру или роду — завести или поправить поверхность через
`/project-deep-dive <project-slug> surface:<X>`; содержимое папки переносит исполнитель её слоя».

## Семантические правила (R-SEM-*)

### R-SEM-001 — Возможность без пользователя

**Severity:** `warning` (draft) / `error` (stable — вместе с R-CAP-001).

**Где:** файлы возможностей.

**Обнаружение:** `user` = `—` или пустой массив.

**Рекомендация:** «возможность без пользователя — мёртвая; связать или удалить через
`/project-deep-dive <project-slug> capability:<surface>:<slug>`».

### R-SEM-002 — Поверхность без пользователя

**Severity:** `warning` (draft) / `error` (stable — вместе с R-STRUCT-002).

**Где:** `surface.md`.

**Обнаружение:** `user` = `—` или пустой массив.

**Рекомендация:** «поверхность без пользователя — кому она нужна? Связать или удалить».

### R-SEM-003 — Отсрочка вместо решения

**Severity:** `warning`.

**Где:** `boundary.md` (`why`); раздел «Урезание» файлов возможностей (`why`).

**Обнаружение:** в `why` — маркеры отсрочки или бюджета: «нет времени», «не хватает ресурсов», «нет бюджета», «потом
сделаем», «когда-нибудь», «отложили», «в бэклоге», «v2», «ждём финансирования», «не успеваем».

**Норма:** `boundary.md`, критерий 1 (граница — устойчивое «нет», а не «потом»); `capability.md § Урезание` (основание
урезания — данные об аудитории).

**Рекомендация:** «`why` похож на бэклог — у границы нужен продуктовый аргумент, у урезания — данные об аудитории;
пересмотреть через `/project-deep-dive <project-slug> <kind>:<slug>`».

### R-SEM-004 — Ограничение без источника

**Severity:** `warning` (draft) / `error` (stable — вместе с R-STRUCT-002).

**Где:** `constraint.md`.

**Обнаружение:** `source` = `—` или пусто.

**Рекомендация:** «ограничение без `source` спекулятивно — назвать документ: закон и статью, контракт и пункт, адрес».

### R-SEM-005 — Аналог без адреса или источников

**Severity:** `warning` (draft) / `error` (stable — вместе с R-STRUCT-002).

**Где:** `market.md`.

**Обнаружение:** `url` = `—` или `sources` пусты.

**Рекомендация:** «запись рынка без адреса или источников — слух; без подтверждённых источников ценности нет».

### R-SEM-006 — Интеграция с направлением, но без инициатора

**Severity:** `warning`.

**Где:** `integration.md`.

**Обнаружение:** `direction` заполнен, а `owner` = `—`.

**Рекомендация:** «направление указано, инициатор — нет: уточнить, кто начинает обмен — мы, партнёр или оба».

### R-SEM-007 — Описание совпадает с именем

**Severity:** `warning`.

**Где:** все табличные файлы.

**Обнаружение:** `description` и `name` совпадают по содержанию.

**Рекомендация:** «`description` дублирует `name` — раскрыть смысл записи в одном предложении».

### R-SEM-008 — Маркетинговая лексика в vision

**Severity:** `warning`.

**Где:** `vision.md` — разделы `Problem`, `Positioning`, `Success`.

**Обнаружение:** маркеры маркетинга и оценочной лексики: «революционн», «уникальн», «лучш в мире», «no.1», «next-gen»,
«цифровизаци», «инновационн».

**Норма:** `vision.md § Что vision НЕ` — маркетинговая копия живёт в текстах страницы; позиционирование — без оценочных
слов.

**Рекомендация:** «vision звучит как продающий текст — это внутренний документ; позиционирование — класс продукта,
альтернатива и наблюдаемое отличие».

### R-SEM-009 — Vision без addresses-problem

**Severity:** `warning` (draft) / `error` (stable — вместе с R-STRUCT-002).

**Где:** `vision.md`.

**Обнаружение:** строка `**addresses-problem:**` отсутствует, пуста (`—`) или держит пустой массив. Проверка структурная
— привязка **есть**; совпадает ли slug со строкой `docs/business/business-problem.md`, сверяет `/cross-audit`.

**Рекомендация:** «vision без `addresses-problem` — продукт не привязан ни к одной проблеме бизнеса; указать строки
реестра через `/project-deep-dive <project-slug> --phase discovery`».

### R-SEM-010 — `integration.surface` на несуществующую поверхность

**Severity:** `error`.

**Где:** `integration.md` + `surface.md`.

**Обнаружение:** в `integration.surface` есть slug, которого нет в реестре. Поверхность — структурная ось, ссылка на неё
проверяется на целостность.

**Рекомендация:** «`integration:<slug>` обслуживает поверхность `<surface>`, которой нет в реестре — завести поверхность
или поправить ссылку через `/project-deep-dive <project-slug> integration:<slug>`».

### R-SEM-011 — `integration.sibling-project` на несуществующий или текущий проект

**Severity:** `error` (проекта нет) / `warning` (ссылка на текущий проект).

**Где:** `integration.md` + листинг `docs/projects/`.

**Обнаружение:** при `target: sibling-project` значение `sibling-project` не совпадает ни с одной папкой
`docs/projects/<slug>/` (кроме `_template` и `infrastructure`) — `error`, стык ведёт в пустоту; совпадает с текущим проектом — `warning`:
это внутренний обмен, а не межпроектный стык.

**Рекомендация:** «поправить slug соседнего проекта или сменить `target` на `external` через
`/project-deep-dive <project-slug> integration:<slug>`; сам стык сводится в `docs/projects/project-map.md`».

### R-SEM-012 — Функция на несуществующего провайдера

**Severity:** `error`.

**Где:** `integration.md` (`## Провайдеры` + `## Функции`).

**Обнаружение:** колонка `integration` строки `## Функции` называет slug, которого нет в `## Провайдеры`: функция без
провайдера — сирота.

**Рекомендация:** «завести провайдера или поправить ссылку через `/project-deep-dive <project-slug> integration`».

Соответствие функции её клиенту в `services/_shared/` и потреблению в use-case — семантическое, это угол
`integration-domain` `/cross-audit`.

**Severity:** `warning` (stable).

**Где:** файлы возможностей + раздел `MVP` vision.

**Обнаружение:** у stable-возможности `trace` = `—`, её нет в `MVP` vision, а в паспорте нет `justification` (или нет
паспорта).

**Норма:** `capability.md`, критерий 8.

**Рекомендация:** «связать возможность с работой сегмента или гипотезой, включить в MVP или записать обоснование».

### R-CAP-008 — Необратимое без защиты

**Severity:** `error`.

**Где:** паспорта возможностей + `interface/<surface>/scenario.md`.

**Обнаружение:**

- `error-cost: high`, а `reversibility` = `—`;
- `reversibility: irreversible`, а в основном пути сценария этой возможности (если сценарий есть) перед необратимым
  действием нет шага, где пользователь видит последствия и подтверждает (чтением).

**Норма:** `capability.md § Паспорта` (`error-cost`); `action.md`, критерий 4; лестница защиты — ux 05/03 §7.2.

**Рекомендация:** «назвать обратимость; у необратимого — шаг защиты в сценарии через
`/interface-deep-dive <project-slug> <surface> scenario:<slug>`».

### R-CAP-009 — ИИ-функция без пути без ИИ

**Severity:** `error` (stable).

**Где:** паспорта возможностей, блок `ai`.

**Обнаружение:** в блоке `ai` нет одного из полей `mode`, `accuracy`, `error-cost`, `fallback`, `data`, `not-doing`,
`owner`, `metrics`, или `fallback` пуст.

**Норма:** `capability.md § Паспорта` (`ai`); ux 13/03 §1.4.

**Рекомендация:** «дописать блок `ai`: путь без ИИ обязателен».

### R-CAP-010 — Возможность не по критериям формы

**Severity:** `warning`.

**Где:** файлы возможностей.

**Обнаружение:** чтением по критериям формы — возможность не самодостаточна (не описывается без отсылки к другой),
описывает «как», а не «что» (шаги интерфейса, бизнес-логику), не называет, кому ценность. В отчёт — с цитатой записи.

**Норма:** `capability.md`, критерии 2–4, тест-критерий.

**Рекомендация:** «переформулировать через `/project-deep-dive <project-slug> capability:<surface>:<slug>`».

## Матрица «пользователь × объект × действие» (R-MX-*)

Матрицу руками не пишут: аудит собирает её в отчёт. Строки — пользователи, колонки — объекты; в ячейке — действия
словаря из возможностей (`user` × `object` × `action`, с `scope` паспорта: `own`, `team`, `all`) и пометки «создаёт» и
«удаляет» из колонок `creates`, `deletes` объекта. Для правил аудит относит каждое действие к виду «создать»,
«смотреть», «изменить» или «удалить» по его `description` и `reversibility`; спорное отнесение пишет в reasoning-trace.
Контейнер, подтверждение и журнал (ux 13/04 §8) — не колонки матрицы: их решают экраны и сценарии.

### R-MX-001 — Объект без создателя или удалителя

**Severity:** `error` (stable).

**Где:** `object.md`.

**Обнаружение:** у stable-объекта пусты `creates` или `deletes`: экземпляры кем-то создаются и кем-то удаляются или
архивируются — пользователем или `system`.

**Норма:** `object.md`, критерий 5; ux 01/03 §6.

**Рекомендация:** «назвать, кто создаёт и удаляет экземпляры: объект без создателя — признак пропущенной роли или
интеграции».

### R-MX-002 — Изменение без просмотра

**Severity:** `error` (изменение) / `warning` (удаление).

**Где:** матрица.

**Обнаружение:** у пользователя есть действие вида «изменить» над объектом, но нет ни действия вида «смотреть», ни
пометки «создаёт» — `error`; «удалить» без просмотра — `warning`.

**Норма:** ux 01/03 §6.

**Рекомендация:** «добавить пользователю возможность видеть объект или пересмотреть его права».

### R-MX-003 — Пользователь без объектов и действий

**Severity:** `warning`.

**Где:** матрица + `surface.md`.

**Обнаружение:** у пользователя поверхности маршрута приложения строка матрицы пуста — ни одного объекта, ни одного
действия.

**Норма:** ux 01/03 §6; ux 13/04 §4.

**Рекомендация:** «назвать возможности пользователя или проверить, нужен ли он продукту».

### R-MX-004 — Формальная матрица

**Severity:** `hint`.

**Где:** матрица.

**Обнаружение:** при двух и больше пользователях и объектах у всех пользователей над всеми объектами один и тот же набор
действий: матрица не выявила ни области видимости, ни доменных глаголов.

**Норма:** ux 13/04 § Частые ошибки (п. 2).

**Рекомендация:** «пройти возможности по ролям: кто что делает на самом деле и над чьими экземплярами».

## Что не делает project-audit

- Не сверяет смысл связей с соседними слоями — пользователей с участниками (who), продукт с `addresses-problem`, трассу
  `trace` с работами и гипотезами, метрики `Success` с Картой гипотез: это `/cross-audit`. Из соседних слоёв аудит
  читает только то, что называют правила R-STRUCT-010, R-CAP-006, R-CAP-008, R-GL-002, R-RL-002, R-VS-008.
- Не проверяет содержимое папок других слоёв — это аудиты этих слоёв; профили голоса и факты — `/design-audit`.
- Не выходит за пределы папки проекта, кроме листинга `docs/projects/` для R-SEM-011 (без чтения артефактов соседа).
  Согласованность сторон межпроектного стыка — угол `integration-crossproject` `/cross-audit`.
- Не предлагает повышение `draft → stable` и не понижает stable — это `/project-deep-dive` и аналитик; аудит лишь
  сообщает, что запись несовместима со stable.
- Не вызывает `/project-deep-dive` сам — даёт текст, что запустить аналитику.
