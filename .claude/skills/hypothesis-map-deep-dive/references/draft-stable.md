# Чек-лист `draft → stable`

После каждой правки скилл прогоняет пункты. Все ✅ → предлагает аналитику
повысить через `AskUserQuestion`. **Не повышает сам.**

## Пункты

1. **Обязательные слоты заполнены** (см. `field-checklists.md`).
   Опциональные могут быть `—`. `hypothesis` — четыре части
   `if/then/because/so`. Для всех 5 kind — **непустой `problem`** (массив
   строк реестра проблем).
2. **`Критерии <kind>` пройдены** — каждый критерий из README слоя
   (`docs/hypothesis-map/README.md`) явно подтверждён аналитиком через
   `AskUserQuestion` (не «скилл уверен», а «аналитик нажал ✅»).
3. **`Anti-patterns` не нарушены** — по каждому скилл спросил «не похоже
   ли?» и получил ❌. Один подтверждённый anti-pattern блокирует stable до
   переформулировки.
4. **Нет `**blocker**`-вопросов** в `state/<kind>/<slug>.md`.

Все ✅ → `AskUserQuestion`: «Запись `<kind>:<slug>` прошла чек-лист.
Повышаем `draft → stable`?» (Да / Нет, ещё подумаю / Да, но сначала закрою:
Other). По «да» — `status: draft → stable`.

## Особое для этого слоя

- Любая запись не становится stable без непустого `problem` (массив
  существующих строк реестра `docs/business/business-problem.md`).
- **Метрика** не становится stable, пока нет `source`, `attribution`,
  `acceptance` и хотя бы одной парной `balancing`-метрики у целевой **в
  пределах её проблемы**; и если она где-то подана как **гарантия**.
- **Субъект** не становится stable без `segments` (≥1 `ajtbd/segment`) и
  `motivation`.
- **Гипотеза** не становится stable, если «тогда» не ссылается на
  существующую метрику **той же проблемы** или «потому что» не опирается
  на мотивацию субъекта.
- **Задача** не становится stable без привязки к гипотезе.
- **Цель** не становится stable без ≥1 метрики.

## Понижение `stable → draft`

Скилл **сам не понижает**. Подсвечивает («запись stable, но критерий X
нарушен / появился `**blocker**` / соседняя запись удалена») и через
`AskUserQuestion` предлагает понизить. Только по «да» — меняет status.

## Когда чек-лист нельзя пройти — это нормально

Сущность может проектно не дойти до stable (нужно интервью, замер, решение
бизнеса). Не «натягивать» stable: закрыть запись `draft`, оставить
`**blocker**` в state, предложить следующий шаг по `phases.md`. Stable-запись,
ссылающаяся на draft, — допустимо (`stable` = «прошла свои критерии», не
«вся цепочка зрелая»).
