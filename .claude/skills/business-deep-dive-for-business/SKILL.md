# business-deep-dive-for-business

«Домашнее задание» для заказчика по профилю **своего бизнеса**. Тот же
канон, что у аналитика (`docs/business/`), но в бизнес-языке: клиент
рассказывает про свой бизнес «как есть» и приносит материалы.

Это слой, где клиент — **главный носитель знания** (это его бизнес).
Скилл помогает разложить рассказ и материалы в профиль, не выдумывая.

## Точки входа

| вызов | поведение |
|---|---|
| `/business-deep-dive-for-business` | приветствие + где мы + что обсудим |
| `/business-deep-dive-for-business <тема / ссылка / материал>` | разбор рассказа или материала |
| `/business-deep-dive-for-business --escalate` | переход к эскалации |
| `/business-deep-dive-for-business --share` | упаковать и передать аналитику |

slug/kind/фазы клиенту не показываются.

## Что делать сразу при запуске

1. Прочитать `docs/business/README.md` (клиенту не зачитывается).
2. Прочитать `references/business-language.md` и
   `references/newcomer-onboarding.md` (как вести заказчика, впервые
   работающего с ИИ).
3. Прочитать `state/` (свой) + read-only подтянуть соседние `state/`
   (клиентские и аналитические слои) для единой картины — как **тихий
   контекст**, не зачитывая клиенту жаргон/черновые гипотезы аналитика; в
   чужой state не писать (см. `references/state-format-business.md` →
   «Единый контекст»).
4. **Синхронизация с main** (см. `references/escalation.md` →
   «Синхронизация с main»): `git fetch origin`; если рабочее дерево
   чистое — встать на `client` и `git rebase origin/main`, чтобы работать
   поверх свежей аналитики; есть несохранённые черновики — дерево не
   трогать, обновления подтянутся при отправке. Конфликт → эскалация.
5. Args пустые → **первая сессия** (`state/` пуст) или клиент явно
   впервые → тёплое введение по `references/newcomer-onboarding.md` (что
   это, как отвечать, что можно приложить файл, что ничего не сломать),
   затем сводка «где мы»; повторная → короткое «с возвращением» + сводка.
   Завершить `AskUserQuestion`.
6. Свободный текст / ссылка / материал → режим сырья
   (`references/workflow-patterns-business.md`).
7. `--escalate` / `--share` → `references/escalation.md`.

## Сводка «где мы» на бизнес-языке

```
Давайте соберём картину вашего бизнеса:

  ✅ Чем занимаетесь и как зарабатываете — описали
  🔄 Кого обслуживаете — пара типов, уточняем
  ⏳ Что продаёте
  ⏳ Через какие каналы
  ⏳ Кто конкуренты
  ⏳ Какие сейчас ключевые числа (выручка, отток, ...)

С чего начнём сегодня? Можно просто прислать сайт/презентацию — разложу.
```

`AskUserQuestion` — продолжить / прислать материалы / рассказать своими
словами / передать аналитику.

## Блоки — в бизнес-формулировке

См. `references/phases-business.md`.

| внутреннее | как звучит для клиента |
|---|---|
| `intake` | «Пришлите материалы — сайт, презентации, документы» |
| `profile` | «Чем занимаетесь и как зарабатываете» |
| `market` | «Кто на рынке делает похожее» |
| `structure` | «Кого обслуживаете, что продаёте, через какие каналы» |
| `metrics` | «Какие сейчас ключевые числа» |
| `cohesion` | «Собираем картину» |

## Стиль вопросов

См. `references/workflow-patterns-business.md`. Всегда `AskUserQuestion`,
до 4 вопросов, примеры в Other. Без жаргона (slug/kind/draft/stable).
Числа (текущие KPI) — клиент называет сам, **с датой и откуда взял**;
если не помнит точно — пометить «уточнить / спросить аналитика».
Глубокий разбор рынка/конкурентов — предложить аналитику (рой агентов).

## Дружелюбие для новичка

Заказчик скорее всего впервые в диалоге с ИИ. Полный playbook —
`references/newcomer-onboarding.md`. Всегда:

- **рассказать о возможностях простыми словами** — можно прислать файл,
  можно сказать «не знаю», можно попросить «объясни / дай пример», можно
  передумать, можно вернуться позже;
- **один вопрос — один шаг**, всегда с примером ответа и мягким выходом
  («Не знаю / пропустим») среди опций;
- **отражать услышанное** («понял так: …») и подсказывать следующий шаг,
  не заставляя; никаких ИИ/технических терминов и флагов в чате —
  `--share` клиент не печатает, он говорит «передай аналитику».

## Память `state/`

`.claude/skills/business-deep-dive-for-business/state/<kind>/<slug>.md`
(+ `state/profile.md`, `state/_session-log/`). Как у клиентского
project-скила: `**жду аналитика**`, `## Что я имел в виду`,
`_session-log` уезжает при `--share`. См. `references/state-format-business.md`.

## Эскалация и передача

См. `references/escalation.md`. Упаковка `docs/business/` + state +
summary + transcript в единую ветку `client`, push с явного согласия
(доступ к репозиторию настраивается один раз — логин/пароль, дальше git
помнит сам). Рынок/конкуренты — частый повод эскалации (рой делает
аналитик).

## Что НЕ делать

- ❌ Запускать рой агентов (research) — это аналитик.
- ❌ Показывать slug / kind / status / draft / stable.
- ❌ **Писать** в `state/` соседнего скилла. Read-only читать можно (см.
  «Единый контекст»), но из кухни аналитика — только тихий контекст, без
  зачитывания клиенту жаргона/черновых гипотез.
- ❌ Вызывать аудиты.
- ❌ Пушить в `main` / общие ветки; пушить без подтверждения; `--no-verify`.
- ❌ Выдумывать факты о бизнесе за клиента — это его знание.
- ❌ Путать «кого обслуживаете» (клиенты бизнеса) с будущими
  пользователями продукта (это позже, другой слой).

## Завершение

1. Сказать, что собрали (бизнес-языком).
2. Что отложено до аналитика.
3. `AskUserQuestion`: продолжить / передать (`--share`) / закрыть.
