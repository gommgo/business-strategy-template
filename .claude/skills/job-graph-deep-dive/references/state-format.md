# Формат заметок `state/`

Память скилла — рабочее состояние знания о графе работ сегмента. Не
журнал. Forward-only.

## Расположение

```
.claude/skills/job-graph-deep-dive/state/
├── job/<slug>.md
├── solution/<slug>.md
├── segment-problem/<slug>.md
├── job-graph/<slug>.md
└── research/<тема>-<UTC-ts>.md   (отчёты волн роя + ## Кандидаты)
```

Заметки лежат **рядом со скиллом**, не в `docs/ajtbd/`. Каталоги
создаются по требованию. Сегментами скилл не владеет — заметок по
сегментам здесь нет (они у `/segment-deep-dive`).

## Шаблон kind-заметки

```markdown
---
kind: job
slug: buy-gear
segment: dacha-owner
ref: docs/ajtbd/job.md#buy-gear
---

## Открытые вопросы
- (**blocker**) Какой результат хочет сегмент на уровне выше — нужен
  навигационный вопрос «зачем? чтобы что?» на интервью.

## Доменные решения
- Целевая = buy-gear (core), а не plan-trip: за неё платят, решение
  завершает целиком.

## Что копать дальше
- В фазе solutions — собрать нанятые решения и их satisfaction.
```

Frontmatter: `kind` (один из 4), `slug`, `segment`, `ref` (на строку
артефакта).

## Секции (все опциональны)

- **`## Открытые вопросы`** — незакрытые смысловые вопросы, одна строка
  каждый. Префикс/суффикс `**blocker**` блокирует `draft → stable`.
  Закрытый вопрос **удаляется** (не зачёркивается). Пусто → удалить
  секцию.
- **`## Доменные решения`** — неочевидные смысловые решения, не лезущие в
  таблицу (выбор целевой работы, почему работа помечена ложной, какой
  метод атрибуции трения). Форма «⟨что выбрано⟩ — ⟨почему⟩». Без
  «было/стало», без дат. Растворилось в записи → удалить.
- **`## Что копать дальше`** — локальные следующие шаги по сущности.
  Выполнен → удалить строку.

## Жизненный цикл

- **Создаётся** только когда есть что записать (≥1 непустая секция).
- **Перезаписывается** свободно.
- **Удаляется**: все секции пусты → файл; запись удалена каскадом → файл.
- **Не аккумулировать** журнал (история — в git).

## Особый случай: `_phase-jump.md`

`state/job/_phase-jump.md` фиксирует решение перепрыгнуть вход (напр.
«начали с решения / трения, минуя явную целевую работу, потому что оно
ярко всплыло») как доменное решение. Не блокер.

## Отчёты роя `research/`

Каждая волна многоволнового research → `state/research/<тема>-<UTC-ts>.md`
с секциями `## <угол>` + `## Кандидаты` (по kind: job / solution /
segment-problem). Отчёты **не удаляются** автоматически — это сырьё для
promotion и засева следующих волн. Кандидаты заводятся в `docs/ajtbd/`
**только через `AskUserQuestion`** (см. `research-waves.md`).

## Единый контекст: read-only видимость соседних state

Для единой картины скилл **read-only** смотрит соседние `state/` и **в
чужой state не пишет**:

- `../segment-deep-dive/state/<kind>/<slug>.md` — что наработал
  сегментный слой (гипотезы работ-stub, отбраковки НЕ-сегментов,
  доменные решения по сегменту);
- `../segment-deep-dive-for-business/state/` — клиентский сегментный
  слой;
- `../job-graph-deep-dive-for-business/state/` — клиентский режим этого
  же слоя (что описал клиент своими словами);
- `../business-deep-dive*/state/` — профиль бизнеса (оферы/каналы/
  конкуренты как контекст для `solution.maps-to`);
- `../business-problem-deep-dive*/state/` — куда трения питают проблему
  бизнеса (`segment-problem.feeds-problem`);
- транскрипты `/jtbd-interview` (его `state/`) — сырьё для intake
  (режим B).

**Anti-leak в обратную сторону здесь не нужен** (аналитический слой), но
писать в чужой state запрещено всегда.
