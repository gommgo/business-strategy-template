# Три режима ведения сеанса

Скилл выбирает режим по виду args (после `<segment-slug>`). Зеркалит
project-deep-dive. Весь сеанс — **внутри одного сегмента**.

## A. Новая сущность

**Сигнал:** args = `<segment> <kind>` или `<segment> <kind>:<новый-slug>`.

1. Прочитать `docs/ajtbd/<kind>.md` целиком (`Критерии`, `Что НЕ`,
   `Тест-критерий`). Освежить `methodology.md` (граф работ).
2. Раунд 1 `AskUserQuestion` — фундамент: `name` (Other), `description`
   (Other); `slug` скилл выводит из `name` и показывает одной строкой для
   контроля (`.claude/rules/naming.md`). Сегмент **наследуется** из
   выбранного на старте
   (`job.segment` / `solution.by-segment` / `segment-problem.segment` /
   `job-graph.segment`) — не переспрашивать, если сегмент один.
3. Записать строку со `status=draft`, `segment` проставлен, прочее `—`.
4. Раунд 2+ — батч по доменным слотам kind (см. `field-checklists.md`).
   До 4 вопросов. Перемежать опции (anti-patterns / enum / выбор соседа /
   навигационная развилка) и Other (тексты работ/решений/трений).
5. Ссылка на несуществующий slug (родительская/предыдущая работа,
   решение, целевая) → **stub** (см. SKILL.md), продолжить.
6. Раунд по `Тест-критерий` (✅/❌ из примеров файла-канона).
7. Чек-лист `draft-stable.md`. Все ✅ → предложить stable.
8. Записать `../entrypoint/state/ajtbd/<kind>/<slug>.md`, если есть что.
9. Предложить следующий шаг по `phases.md`.

### Особое для `job`

- Заполнять **шаблоном целиком**: `when` (контекст+триггер+опыт+
  особенности), `want` + `success-criteria`, `so-that`.
- `level` (enum big/core/low) и `type` (enum) — опциями.
- При `parent-job` — **проверить непрерывность**: `so-that` этой работы =
  `want` родителя. Если родителя нет — stub + вопрос «зачем вам этот
  результат? чтобы что?» в graph-up.
- Проверочный вопрос на **ложную работу**: «двигает ли к ценности?» — при
  подозрении опция `type: ложная`.

### Особое для `solution`

- `hired-for` обязателен (работа без — не решение). Если работа не
  заведена — stub.
- `satisfaction` и `price-value-fit` (X/10) — из research/интервью; нет
  данных → `draft` + `**blocker**`, не на глаз.
- `maps-to` — опцией: существующий `business/competitor`/`offering` или
  `—` (DIY/субститут/бездействие).

### Особое для `segment-problem`

- **`solution` + `job` оба обязательны** — трение без пары запрещено
  (ядро методологии). Если решение/работа не заведены — сначала их.
- `strength` (1–10) с обоснованием; `drivers`/`barriers` — Other.

### Особое для `job-graph`

- Один граф = один сегмент / одна целевая работа. `target-job`
  обязателен.
- `cpr` — **упорядоченный** массив (порядок значим), без разрывов.
- `job-types` — разметка типов работ графа; `value-mechanics` — кандидаты
  из 11 механик (см. `methodology.md`), **не реализация**.

## B. Сырьё

**Сигнал:** args = транскрипт JTBD-интервью / заметки / находки роя.
Транскрипты обычно приходят от `/jtbd-interview` в ветку
`../entrypoint/state/ajtbd/_interview/` — скилл их read-only читает и
разбирает здесь.

1. Прочитать материал внимательно.
2. Подтвердить, что материал **про выбранный сегмент** (если про другой —
   переключить сегмент или предложить завести его через
   `/segment-deep-dive`).
3. Извлечь кандидатов **только то, что прямо названо** действиями (не
   угадывать):
   - job — какая работа звучит (когда/хочу/чтобы), на каком уровне,
     доказана ли затратами;
   - solution — что нанимали, kind, признаки satisfaction/цены;
   - segment-problem — где не получили результат (пара решение+работа),
     сила, драйверы/барьеры.
4. Показать план в чате, `AskUserQuestion` — подтвердить/поправить.
5. Завести **stub'ы** с `segment`, создать state-заметки «извлечено из
   сырья — уточнить ⟨что⟩».
6. `AskUserQuestion` — какую углубить первой (по логике фаз) → режим C.

### Границы режима B

- Извлечённое — кандидаты, а не зафиксированные записи.
- По сырью заполняются только `name` и `description`, близко к языку
  транскрипта; шаблон работы, оценки решений, сила, драйверы и барьеры
  трений добываются в режиме C вопросами.
- Кандидат появляется, только если он есть в материале.
- Гипотетика («хотел бы, чтобы…») — не работа: работа доказывается прошлым
  поведением.
- У каждого кандидата есть `segment`.

## C. Углубление

**Сигнал:** args = `<kind>:<slug>` существующей записи.

1. Прочитать строку + `../entrypoint/state/ajtbd/<kind>/<slug>.md`.
   Отметить её `segment` —
   все проверки соседей идут в пределах этого сегмента.
2. Прочитать соседей семантически: для `job` — `parent-job` (непрерывность
   «чтобы»), `prev-jobs`, какие `solution` на неё наняты; для `solution` —
   `hired-for` и трения на этой паре; для `segment-problem` — её
   `solution`+`job`; для `job-graph` — `target-job` и работы `cpr`.
3. Найти: пустой `segment`; пустые обязательные слоты; подозрения по
   anti-patterns; методологические тупики (разрыв «чтобы», работа без
   решения, трение без пары, неразмеченный тип, ложная работа, CPR с
   разрывом).
4. Раунд `AskUserQuestion` (до 4): дыры → Other; anti-pattern → «да/нет
   почему»; тупик → «связать с ⟨варианты⟩ / оставить, потому что Other».
5. Применить ответы; обновить state.
6. Чек-лист `draft-stable.md`. Все ✅ → предложить stable.
7. Осталась дыра/подозрение → следующий раунд.

## Стиль вопросов

### Когда давать опции

| ситуация | формат |
|---|---|
| anti-pattern из `Что <kind> НЕ` | две опции «соответствует / не соответствует (Other почему)» |
| enum (`job.level`, `job.type`, `solution.kind`) | по опции на значение |
| выбор существующего slug соседа (parent-job / prev-job / целевая / решение / `maps-to`) | по опции на каждого + «нужен новый» (Other) |
| навигационная развилка | «вверх (чтобы что?)» / «последовательность» / «вниз (что делал?)» |
| проверочный вопрос на ложную работу | «двигает к ценности» / «кажется работой → ложная» |
| перепрыгивание входа | «стартуем с решения / трения, потому что …» |
| тест-критерий | опции из примеров ✅/❌ файла-канона |

### Когда только Other (значения)

`name`, `description`, шаблон работы (`when`/`want`/`success-criteria`/
`so-that`), описание решения, описание трения, `drivers`/`barriers`,
оценки (`satisfaction`/`price-value-fit`/`strength`), `price`,
`frequency`/`importance`, разметка `job-types`, `value-mechanics`. Это
экспертиза сегмента (`CLAUDE.md` §3): значения берутся из research,
транскриптов и ответов аналитика. `slug` новой записи не спрашивается —
скилл выводит его из `name`.

### Чего избегать

- Образцов формулировок работ, решений и трений от себя: примеры в md —
  иллюстрация канона, не варианты для текущего сегмента.
- Больше 4 вопросов в одном раунде.
- Закрытия сессии без чек-листа хотя бы по одной правленой сущности.
