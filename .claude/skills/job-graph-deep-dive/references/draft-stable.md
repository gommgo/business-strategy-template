# Чек-лист `draft → stable`

После каждой правки скилл прогоняет пункты. Все ✅ → предлагает аналитику
повысить через `AskUserQuestion`. **Не повышает сам.**

## Пункты

1. **Обязательные слоты заполнены** (см. `field-checklists.md`).
   Опциональные могут быть `—`. У всех записей слоя — **непустой
   `segment`** (`segment` / `by-segment`): граф собирается внутри
   сегмента.
2. **`Критерии <kind>` пройдены** — каждый критерий из секции в
   `docs/ajtbd/<kind>.md` явно подтверждён аналитиком через
   `AskUserQuestion` (не «скилл уверен», а «аналитик нажал ✅»).
3. **`Что <kind> НЕ` не нарушены** — по каждому anti-pattern скилл
   спросил «не похоже ли?» и получил ❌. Один подтверждённый anti-pattern
   блокирует stable до переформулировки.
4. **`Тест-критерий` ✅** — аналитик прошёл бинарный вопрос из секции
   файла-канона.
5. **Факт прослежен** до research или транскрипта интервью — **не
   гипотетика**. Работа/решение/трение доказаны прошлым поведением
   (затраты времени/денег/энергии), не мнением.
6. **Нет `**blocker**`-вопросов** в `../entrypoint/state/ajtbd/<kind>/<slug>.md`.

Все ✅ → `AskUserQuestion`: «Запись `<kind>:<slug>` прошла все пункты.
Повышаем `draft → stable`?» (Да / Нет, ещё подумаю / Да, но сначала
закрою: Other). По «да» — `status: draft → stable`.

## Особое для этого слоя

- **job** не становится stable без полного шаблона (когда/хочу/чтобы +
  success-criteria), осознанного `level`, размеченного `type` и
  **непрерывности «чтобы»** (если есть `parent-job`: `so-that` = `want`
  родителя). Подозрительная работа проверена вопросом на ложную.
- **solution** не становится stable без `hired-for`, `kind`,
  `satisfaction` и `price-value-fit` **из research/интервью** (не на
  глаз).
- **segment-problem** не становится stable без пары `solution` + `job` и
  обоснованного `strength` (ядро методологии — трение следствие решения).
- **job-graph** не становится stable без `target-job`, **CPR без
  разрывов** и разметки `job-types`; `value-mechanics` — кандидаты, не
  реализация.
- У целевой `core`-работы должен быть ≥1 `solution` с оценками — иначе
  Score сегмента не вычислить (поднять при cohesion).

## Понижение `stable → draft`

Скилл **сам не понижает**. Подсвечивает («запись stable, но критерий X
нарушен / появился `**blocker**` / соседняя запись удалена / порвалась
цепочка „чтобы“») и через `AskUserQuestion` предлагает понизить. Только
по «да» — меняет status.

## Когда чек-лист нельзя пройти — это нормально

Сущность может проектно не дойти до stable (нужно интервью, нужны оценки
решения, нужна навигация вверх). Не «натягивать» stable: закрыть запись
`draft`, оставить `**blocker**` в state, предложить следующий шаг по
`phases.md` (часто — `/jtbd-interview` за недостающими работами/оценками).
Stable-запись, ссылающаяся на draft-соседа, — допустимо (`stable` =
«прошла свои критерии», не «весь граф зрелый»).
