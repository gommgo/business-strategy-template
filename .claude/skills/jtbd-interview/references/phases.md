# Карта 5 фаз процесса JTBD-интервью

Процесс **длительный** и **итерационный** (волны интервью), не водопад.
Каждая фаза имеет свой выход в ветке `_interview/`
(`../entrypoint/state/ajtbd/_interview/`). Назад возвращаемся свободно (не
добрали объём → снова `conduct`; новая гипотеза работы → снова `script`).

```
prep ──► channels ──► script ──► conduct ──► interpret
  │                                  ▲            │
  │                                  └── итерация ┘ (волны по 6–8)
  └── сегмент-цель и гипотезы работ из ветки ajtbd дерева (/segment, /job-graph)
```

## Сводка фаз (печатать в сводке состояния)

| фаза | вопрос | готова, когда |
|---|---|---|
| `prep` | под кого и зачем интервью? | есть `_interview/prep.md`: сегмент-цель, гипотезы работ, критерии рекрута, рынок B2B/B2C, объём |
| `channels` | где их найти и как заговорить? | есть `_interview/channels.md`: список «канал → кого → сообщение» |
| `script` | какие вопросы зададим? | собран скрипт под задачу (сегмент / продукт; B2B / B2C) |
| `conduct` | проводим интервью | накоплены транскрипты в `_interview/transcripts/` |
| `interpret` | что вынесли? | конспекты выжаты в `_interview/candidates/` |

---

## Фаза `prep` — подготовка

**Цель:** определить, под какой сегмент и гипотезы работ интервью, кого
рекрутить и сколько.

1. Read-only подтянуть ветку `ajtbd` дерева оркестратора
   (`../entrypoint/state/ajtbd/`: `/segment-deep-dive`,
   `/job-graph-deep-dive`): под какой сегмент целятся, какие гипотезы
   работ-stub и дыры research они оставили. Если сегмент-цель уже есть —
   предложить его опцией.
2. `AskUserQuestion` (до 4):
   - **Задача интервью** (опции): «поиск сегмента» (широкая гипотеза
     работы, навигация) / «поиск продукта» (низкоуровневые работы
     выбранного сегмента, решения, барьеры).
   - **Рынок** (опции): `b2b` / `b2c`. Ветвит скрипт и рекрут.
   - **Сегмент-цель / широкая гипотеза работы** (Other или выбор из
     ветки `../entrypoint/state/ajtbd/`).
   - **Гипотезы работ** (Other) — список «есть / нет» для быстрой
     валидации в каждом интервью (особенно для B2B: список **до** первого
     интервью).
3. **Критерии рекрута** — отдельный раунд. Ключевое правило: рекрутируем
   **только тех, кто уже платит деньги/время/энергию** за выполнение
   работы (затраты доказывают наличие работы). Зафиксировать: роль (для
   B2B — ЛПР напрямую, не через сотрудников), опыт, **подтверждённая
   оплата** работы, квалифицирующие признаки.
4. **Объём** — из «Объём по нормативам» в SKILL.md: навигация 30+ (B2C) /
   20+ (B2B); 10–12 на сегмент (B2C) / 8–10 (B2B); 8+ на продукт;
   итерации по 6–8; стоп — 2 итерации подряд без новых работ. Записать
   план волн.
5. Записать `../entrypoint/state/ajtbd/_interview/prep.md` (см.
   `../entrypoint/references/state-model.md`). Предложить `channels`.

> Размер сегмента интервью **не меряет** — это количественник / кабинетная
> аналитика. Отметить как дыру для `/segment-deep-dive`, не тянуть в
> интервью.

## Фаза `channels` — где искать и как заговорить

**Цель:** единый список каналов рекрута с «кого там найти» и «формат
сообщения», плюс делегирование рекрутинга админу.

См. `recruit-channels.md` (свой рой web-research по каналам) и
`recruit-delegation.md` (передача рутины рекрута администратору).

1. Предложить **свой рой** web-research по каналам (отдельный от
   research-волн соседей): где живёт сегмент из `prep`, как с ним
   заговорить.
2. Свести находки в
   `../entrypoint/state/ajtbd/_interview/channels.md`: таблица «канал →
   кого там найти → формат сообщения», ранжированная по ожидаемой
   конверсии.
3. Принцип **«сообщение важнее канала»**: один хорошо написанный месседж
   бьёт выбор канала. Заготовить тексты сообщений (через Other — это копи
   аналитика/клиента, не выдумка модели целиком).
4. Если рекрут делегируется — собрать бриф админу (`recruit-delegation.md`).
5. Предложить `script`.

## Фаза `script` — сборка скрипта

**Цель:** скрипт под задачу: B2B/B2C **поиск сегмента** или B2C/B2B
**поиск продукта** (низкоуровневые работы). Дать **дословные блоки
вопросов**.

См. `scripts.md` (4 готовых скрипта с дословными блоками) и `conduct.md`
(правила, которые скилл напоминает в ходе интервью).

1. По `prep` выбрать связку: задача (сегмент / продукт) × рынок
   (B2B / B2C) → один из 4 скриптов.
2. Гайд — **маяк, а не скрипт наизусть**: блоки в голове, вопросы цепляются
   за ответ предыдущего («monkey see — monkey do»).
3. Зашить **гипотезы работ из prep** в навигационный блок (для B2B —
   чек «есть / нет» по каждой).
4. Опц. сохранить собранный скрипт в
   `../entrypoint/state/ajtbd/_interview/<тема>-script.md`.
5. Предложить `conduct`.

## Фаза `conduct` — проведение

**Цель:** провести живое интервью. Скилл **держит скрипт, помогает
фиксировать ответы и напоминает правила** — но ответы вписывает только
названные респондентом.

См. `conduct.md` (правила: эмоц. контакт, только про прошлое, открытые
вопросы, один вопрос за раз, паузы, докапывание до эмоций) и
`transcripts.md` (как вести лог).

1. Открыть выбранный скрипт + правила conduct.
2. Вводная часть (контакт, «ты», тема, тайминг, заметки, право не
   отвечать, согласие на запись).
3. Идти по блокам, фиксируя сказанное в транскрипт
   `../entrypoint/state/ajtbd/_interview/transcripts/<YYYY-MM-DD>--<HH-MM>--<тема>.md`
   **в ходе** интервью (не откладывать).
4. После интервью **сразу** (15–30 мин) предложить `interpret` — детали
   не теряются.
5. Итерация: продолжать волнами 6–8 до норматива / сигнала полноты.

## Фаза `interpret` — конспект в кандидаты

**Цель:** превратить конспект в кандидатов под формы `docs/ajtbd/`:
шаблон работы (когда/хочу/чтобы), нанятые решения (satisfaction, цена↔
ценность), трения (сила, драйверы, барьеры). Записать transcript +
кандидатов в ветку `_interview/`.

См. `interpret.md` (шаблоны работы/решения/трения и правила извлечения).

1. По транскрипту выделить **только то, что прямо названо действиями**
   (не угадывать, не достраивать).
2. Заполнить шаблоны кандидатов →
   `../entrypoint/state/ajtbd/_interview/candidates/<тема>-<ts>.md`.
3. Дочистить транскрипт (человекочитаемый, см. `transcripts.md`).
4. Подсказать следующий шаг: разбор сырья идёт через **intake (режим B)**
   `/segment-deep-dive` (кандидаты в сегменты) или `/job-graph-deep-dive`
   (кандидаты в работы / решения / трения). Скилл их **не вызывает** —
   называет пути сырья и предлагает аналитику.
