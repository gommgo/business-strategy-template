# Каналы рекрута + свой рой web-research (фаза channels)

Где искать респондентов и **как с ними заговорить**. Это **отдельный** рой
от research-волн `/segment-deep-dive` и `/job-graph-deep-dive`: те ищут
работы / решения / трения; **этот** — где живёт нужный сегмент и какое
сообщение его зацепит.

## Два железных принципа

1. **Сообщение важнее канала.** Один хорошо написанный месседж бьёт выбор
   площадки. Сначала формулируем «кого зовём и зачем им откликнуться»,
   потом подбираем каналы.
2. **Рекрутим только тех, кто уже платил за выполнение работы** (деньги /
   время / энергия). Затраты — единственное доказательство наличия работы.
   Кто «хотел бы, но ничего не делал» — это гипотетика, не сегмент. Для
   B2B это означает: компания **уже** выполняет работу или ищет подрядчика
   с понятными критериями.

> Рекрутируешь не «респондентов» — **потенциальных клиентов**.
> Исследование = первый этап продаж. Особенно в B2B.

## Каталог каналов (приоритет ~по конверсии)

| канал | кого там найти | как заговорить |
|---|---|---|
| **Реальная рекомендация / интро** | через общего человека, чатик, звонок | «нас познакомил X, хочу 30–40 мин про то, как ты делаешь ⟨работа⟩» — лучшая конверсия |
| **Снежный ком** | контакты в конце каждого интервью | «кого ещё, кто так же активно ⟨делает работу⟩, стоит спросить?» — лучший канал привлечения (особ. ЛПРов) |
| **Текущая база и нетворк** | свои клиенты / ушедшие клиенты / личные контакты | прямое сообщение; ушедшие клиенты — золото для «почему ушёл» |
| **Профильные сообщества и чаты** (телеграм-чаты, Reddit, VC, отраслевые форумы) | те, кто уже обсуждает работу и решения | пост/ЛС в стиле сообщества, без рекламы; «изучаю, как ⟨делают работу⟩, плачу за время / без продажи» |
| **LinkedIn** (особ. западный рынок, B2B) | ЛПРы по роли/индустрии | хорошо написанное холодное сообщение получает ~50% ответ/переадресацию; представляться топом (топы говорят с топами) |
| **Панели рекрута** (Userinterviews.com и аналоги, локальные рекрутёры) | широкая сеть по квалифицирующим признакам | оплата за участие; квалифицирующая анкета по критериям рекрута из prep |
| **Конференции (офлайн)** | ЛПРы, активные практики | запросить список гостей заранее, назначить 15-мин встречи до/в ходе; один из самых результативных дней для сейлзов |
| **Вебинарная воронка / ABM** (B2B) | тёплые ЛПРы из целевых компаний | контент → кто пришёл/задавал вопросы = тёплый контакт; см. `recruit-delegation.md` |
| **Реклама / тест через лендинг** | холодный спрос по гипотезе работы | лендинг под широкую гипотезу работы → кто оставил заявку = есть затраты внимания; быстрый сигнал спроса |

> **Обещание пользы** поднимает согласие на любом канале: «придём с
> исследованием рынка / трендами по вашей отрасли» (B2B), «пришлю сводку
> находок» (B2C).

> **Когда нужных людей в мире мало** (сотни ЛПРов, не тысячи) — это уже не
> рекрутинг, а выстраивание отношений с каждым потенциальным клиентом:
> нужны сейлзы/бизнес-девелоперы, а не массовый рекрут. Отметить в state.

## Свой рой web-research по каналам

Запуск **только** по решению аналитика (или его «да» на предложение
скилла). Параллельные подагенты в **одном** message-блоке (инструмент
**Agent**, `subagent_type: general-purpose`, WebSearch/WebFetch). **Не**
через Workflow.

1. `AskUserQuestion`:
   - **Сколько углов?** «5 — дефолт» / «7 — шире» / «10 — широкая
     разведка».
   - **Фокус** (Other) — под какой сегмент из `prep` и какой рынок.
2. Сгенерить N углов из каталога каналов под сегмент.
3. Спавнить агентов параллельно.
4. Свести в `state/channels.md`: таблица «канал → кого → сообщение» +
   находки (конкретные чаты/сообщества/панели/конференции по сегменту,
   ссылки).
5. Promotion в план рекрута — через `AskUserQuestion`. Авто-залив
   запрещён.

### Промпт для одного агента

```
Сегмент (из prep): <кто это, какую работу выполняет, рынок b2b/b2c>
Критерий рекрута: рекрутируем только тех, кто УЖЕ платит (деньги/время/
энергию) за выполнение этой работы.
Угол (канал): <LinkedIn / телеграм-чаты и сообщества / панели рекрута /
конференции / реклама-лендинг / отраслевые форумы / …>

Найди наблюдаемое из веба:
- где именно живёт этот сегмент по этому каналу (конкретные сообщества /
  чаты / панели / конференции / площадки — с названиями и ссылками);
- по каким квалифицирующим признакам там опознать «уже платит за работу»;
- какой формат сообщения принят на площадке (чтобы не выглядеть рекламой);
- ожидаемая конверсия / подводные камни канала, если есть данные.

Не выдумывай площадки. Пусто по углу → пустой список + фраза почему.
Ответ — markdown с ссылками-источниками.
```

## Тексты сообщений рекрута

Заготовить под топ-каналы. **Структура месседжа:** кто я → почему пишу
именно тебе (квалифицирующий признак) → что прошу (30–40 мин, про прошлый
опыт, не продажа) → что взамен (оплата / польза / сводка). B2C — **не
называть продукт** (не фреймить); B2B — наоборот, прозрачный контракт
(«вот продукт, вот что хочу узнать»).

Сами тексты — копи аналитика/клиента через Other, не выдумка модели
целиком. Скилл предлагает каркас, наполняет человек.

## Что НЕ делать

- ❌ Запускать рой без решения аналитика / через Workflow.
- ❌ Рекрутить тех, кто не платил за работу (нет затрат — нет работы).
- ❌ Выдавать найденные площадки за проверенные без подтверждения.
- ❌ Тащить размер сегмента сюда — это количественник, не рекрут.
- ❌ В B2C называть продукт в приглашении.
