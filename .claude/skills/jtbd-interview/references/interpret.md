# Интерпретация конспекта в кандидатов (фаза interpret)

Превратить транскрипт интервью в **кандидатов** под формы `docs/ajtbd/`.
Кандидаты падают в `state/candidates/<тема>-<ts>.md`, **не** в
`docs/ajtbd/`. Промотируют их `/segment-deep-dive` и `/job-graph-deep-dive`
через intake (режим B).

## Железное правило извлечения

Извлекаем **только то, что прямо названо действиями** (затраты времени /
денег / энергии). Не угадывать, не достраивать, не превращать гипотетику
(«хотел бы, чтобы…») в работу. Если данных нет — кандидат остаётся
неполным с пометкой «уточнить ⟨что⟩», а не выдумывается.

Сразу после интервью (15–30 мин), пока детали свежи.

## Три формы кандидатов

### 1. Работа (job) — шаблон «когда → хочу → чтобы»

Соответствует `docs/ajtbd/job.md`. Заполнять целиком:

| часть | что | из чего достаём |
|---|---|---|
| **когда** (when) | контекст + триггер + прошлый опыт + психологические особенности (B2B: + контекст компании, роль, прошлый опыт компании) | блок контекст/триггер + квалификация |
| **хочу** (want) | понятный результат + критерии успеха («что значит "хорошо"») | «какой результат хотел?» + «что было основным?» |
| **чтобы** (so-that) | работа выше уровнем + как хочу себя чувствовать (B2B верх: KPI/OKR, за ним — личная работа сотрудника) | «зачем тебе это? чтобы что?» + эмоция |
| level | `big` / `core` / `low` (за что платят и решение завершает = core; шаг = low; верхняя мотивация = big) | по месту в дереве |
| type | `разовая`/`последовательная`/`частотная`/`виральная`/`налоговая`/`ложная` | по поведению |
| frequency · importance | раз/период · X/10 | метрики из интервью (с якорем шкалы) |

**Проверка на ложную работу:** говорит, что хочет, но **ничего не делал**?
→ кандидат `type: ложная` + проверочный вопрос «а что уже делал для
этого?». (Классика: «похудеть к лету» — нанимают абонемент не на
похудение, а на снижение тревоги.)

**Непрерывность «чтобы»:** `so-that` нижней работы = `want` верхней (как
«5 почему»), цепочка ведёт вверх до big-работы.

### 2. Нанятое решение (solution) — satisfaction + цена↔ценность

Соответствует `docs/ajtbd/solution.md`:

| поле | что | из чего |
|---|---|---|
| на какую работу нанято | hired-for | «чем ты это делаешь?» |
| kind | `product`/`service`/`diy`(сам)/`substitute`(иначе)/`inaction`(ничего) | по типу решения |
| satisfaction | X/10, насколько решение выполняет работу | «удовлетворённость 1–10?» (10 = идеально) |
| price · price-value-fit | цена · X/10 соответствие цены ценности | «сколько платишь?» + «цена↔ценность 1–10?» (10 = точно стоит) |

Берём **все** нанятые решения, включая DIY, субституты, бездействие,
неожиданных конкурентов — не только прямых. Низкая удовлетворённость —
сигнал ценности.

> Оценки из **одного** интервью — сигнал, не факт. Кандидат несёт
> диапазон/N=1; усреднение и подтверждение — задача `/segment-deep-dive` /
> `/job-graph-deep-dive`.

### 3. Трение (segment-problem) — сила + драйверы + барьеры

Соответствует `docs/ajtbd/segment-problem.md`. **Всегда висит на паре
solution + job** (проблема — следствие конкретного решения на работе):

| поле | что | из чего |
|---|---|---|
| solution + job | пара, на которой трётся | где не получил результат |
| strength | 1–10, сила негатива / недостижимости результата | докопанная эмоция + шкала |
| drivers | что тянет продолжать пользоваться этим решением | «почему всё ещё этим?» |
| barriers | страхи/тревоги, мешающие перейти на лучшее (пожиратели ценности) | «что останавливало сменить?» |

Достаётся вопросом «сталкивался, что не можешь получить результат?» — не
выдумывается. Слово «боль»/«pain» не используем — описываем недостижимый
результат и негативную эмоцию с силой.

## B2B-добавки в кандидаты

- **Роли сделки** (контекст работы): End User / инициатор / ЛПР /
  держатель бюджета / ЛВР (IT, безопасник) / рекомендатель / саботажник /
  чемпион — кто, в каком порядке.
- **Личные работы ЛПРа** (двигатель, не KPI): job security, статус, рост
  позиции, уход от рутины, не остаться без поддержки. KPI — «река»
  (контекст), личная цель — «лодочка».
- **Бизнес-ценность в деньгах** — заземление работы («не найдём — потеряем
  заказ $13k»).
- **Возражения стейкхолдеров** из решенческого блока — барьеры разных
  ролей.

## Процесс фазы

1. Прочитать транскрипт.
2. Выделить кандидатов по трём формам — только названное действиями.
3. Записать `state/candidates/<тема>-<ts>.md` (см. `state-format.md`):
   секции `## Кандидаты-работы`, `## Кандидаты-решения`,
   `## Кандидаты-трения` + ссылка на транскрипт-источник + пометки
   «уточнить ⟨что⟩».
4. Дочистить транскрипт (человекочитаемый, `transcripts.md`).
5. **Не** заводить ничего в `docs/ajtbd/`. Подсказать передачу:
   - кандидаты в **сегменты** (новый бандл работ / критерии успеха) →
     `/segment-deep-dive` (intake);
   - кандидаты в **работы / решения / трения** графа →
     `/job-graph-deep-dive <segment> <путь-к-сырью>` (intake).
   Назвать пути транскрипта и `candidates/`. Скилл их **не вызывает**.

## Что НЕ делать

- ❌ Писать кандидатов прямо в `docs/ajtbd/`.
- ❌ Достраивать шаблон работы / оценки / силу-драйверы-барьеры из головы.
- ❌ Принимать гипотетику за работу.
- ❌ Заводить трение без пары solution + job.
- ❌ Выдавать N=1 оценки за факт сегмента.
- ❌ Терять связь кандидата с транскриптом-источником.
