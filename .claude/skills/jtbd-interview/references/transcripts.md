# Транскрипты интервью

Человекочитаемый лог одного интервью — главный продукт фазы `conduct` и
сырьё для intake соседей. Ведётся **в ходе** интервью, дочищается в
`interpret`.

## Именование файла

```
../entrypoint/state/ajtbd/_interview/transcripts/<YYYY-MM-DD>--<HH-MM>--<тема>.md
```

- `<YYYY-MM-DD>` — дата интервью (напр. `2026-06-05`).
- `<HH-MM>` — время начала, 24ч (напр. `14-30`).
- `<тема>` — короткая человекочитаемая тема в kebab-case, по сегменту/
  работе (напр. `dacha-gear`, `b2b-recruit-lpr`, `qa-bootcamp`).
- Разделитель полей — `--` (двойной дефис), чтобы не путать с дефисами
  внутри темы.

Примеры:
- `2026-06-05--14-30--dacha-gear.md`
- `2026-06-06--10-00--b2b-sed-strahovaya.md`

## Структура транскрипта

```markdown
---
date: 2026-06-05 14:30
тема: dacha-gear
рынок: b2c
задача: поиск сегмента
сегмент-гипотеза: dacha-owner
респондент: <псевдоним/инициалы; роль; квалифицирующий признак — уже платит за работу>
скрипт: A (B2C-сегмент)
---

## Контекст / квалификация
<где живёт, ритм, особенности — дословно близко к словам респондента>

## Целевая работа
- как делает: «…»
- хочу (результат + критерий): «…»
- когда (контекст + триггер): «…»
- чтобы (выше уровнем + эмоция): «…»
- метрики: частота … · важность …/10 · удовлетворённость …/10 · цена↔ценность …/10

## Работа первой покупки
<…>

## Предыдущие работы (воронка / конкуренты)
<…>

## Низкоуровневые работы
| шаг | желаемый результат | проблемы |
|---|---|---|
| <…> | <…> | <…> |

## Решения (что нанимает)
<решение · kind · satisfaction · цена · цена↔ценность>

## Трения
<пара решение+работа · сила …/10 · драйверы · барьеры>

## B2B-блок (если применимо)
- роли сделки: <…>
- личные работы ЛПРа: <…>
- бизнес-ценность в деньгах: <…>
- бюджет / рекомендатели / саботажники: <…>

## Снежный ком
- кого ещё спросить: <контакты для рекрута>

## Заметки интервьюера
- что зацепило, где сбился (будущее/подсказка/закрытый), что уточнить
```

## Правила ведения

- **Фиксировать дословно сказанное респондентом**, близко к его языку. Не
  пересказ модели, не достройка, не интерпретация (интерпретация — отдельно
  в `interpret`).
- Цитаты эмоций — дословно (нужны для докапывания и для силы трения).
- Пропущенные блоки оставлять с пометкой «не дошли» — честнее, чем
  додумывать.
- Один файл = одно интервью.

## Связь с кандидатами

После интервью `interpret` выжимает из транскрипта
`candidates/<тема>-<ts>.md`, который **ссылается** на файл транскрипта
(поле `source`). Транскрипт — первоисточник, кандидаты — выжимка под формы
`docs/ajtbd/`.

## Жизненный цикл

- Транскрипты **не удаляются** авто — это сырьё для intake
  (`/segment-deep-dive`, `/job-graph-deep-dive`) и для повторного разбора.
- Forward-only внутри файла: не вести «было/стало», правки — перезапись
  факта.

## Клиент-режим

Если интервью ведёт клиент — транскрипт всё равно ложится сюда; при push в
единую ветку `client` уезжает как сырьё (по правилам клиент-режима, с
согласия). В чате с клиентом — бизнес-язык, без `slug`/`kind`.
