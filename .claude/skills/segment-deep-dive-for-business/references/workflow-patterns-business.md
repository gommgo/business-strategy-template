# Режимы ведения сеанса (клиент)

Три режима с бизнес-фасадом. В этом слое клиент — носитель знания о своих
клиентах, поэтому режим сырья (рассказ + материалы) — основной.

## A. Новый тип клиента (в бизнес-формулировке)

**Сигнал:** клиент назвал новую группу клиентов («ещё к нам ходят
корпоративы»).

1. Скилл понимает внутри, что это новый тип (сегмент), клиенту не говорит.
2. Прочитать `docs/ajtbd/segment.md` — критерии (на чём держится тип).
3. `AskUserQuestion` — «Как назовём этот тип коротко?» / «Опишите одним
   предложением, кто это» (Other, с примерами); сразу спросить **люди или
   компании** (внутри `kind` b2b/b2c — опции).
4. Записать строку, «в работе» (внутри draft), прочее `—`.
5. Поля — по `phases-business.md`: за что платят и что для них «хорошо» →
   как часто/сколько → насколько довольны.
6. Anti-patterns — из `anti-patterns-real.md`, как опции (особенно
   «демография вместо типа», «продукт вместо цели»).
7. Различимость без термина: «По чему отличите этого клиента от соседнего
   — по делу, а не только по возрасту?»
8. Ок → «Закроем этот тип?» (внутри draft → stable; см. ниже про границу).

**Не делать:** не показывать имена полей; не отказывать в записи
«неправильной» формулировки — записать, пометить в state «обсудить с
аналитиком».

## B. Сырьё (рассказ + материалы) — основной режим

**Сигнал:** клиент описывает клиентов «своими словами», или прислал ссылку
/ файл / презентацию / отзывы.

1. Если материал (ссылка/файл) — прочитать (`WebFetch`/`Read`), зафиксировать
   в state, откуда брали факты.
2. Извлечь кандидатов в типы клиентов — **только прямо названное**. Не
   выдумывать «обычно ещё бывают».
3. **Дружелюбный пересказ** бизнес-категориями:
   > «Я понял так — у вас наметилось несколько типов клиентов:
   > — ⟨тип 1⟩: платят за ⟨…⟩, для них “хорошо” — ⟨…⟩ (**за что платят**);
   > — ⟨тип 2⟩: другая ситуация и другие ожидания (**другой тип**).
   > Верно? Что добавить/поправить?»
4. `AskUserQuestion` — подтвердить/поправить/добавить (Other), для каждого
   типа спросить **люди или компании**.
5. Завести заметки по типам, привязать факты к источнику через state.
6. `AskUserQuestion` — с какого типа клиента начнём углублять.

**Не делать:** не вписывать факт без источника (рассказ клиента или
материал); не путать клиентов бизнеса с будущими пользователями продукта;
не строить «граф работ» (это аналитик) — здесь только первичная картина.

## C. Углубление

**Сигнал:** клиент уже про какой-то тип клиента рассказал.

1. Прочитать заметку по типу + state.
2. Найти дыры (нет «за что платят» / нет «что для них хорошо» / нет «как
   часто» / нет «насколько довольны»), anti-pattern-сигналы
   (`anti-patterns-real.md`), открытые вопросы.
3. `AskUserQuestion` (до 4): дыры → Other с примерами; подозрения → две
   опции; вопросы → уточнить.
4. После ответа — обновить заметку и state.
5. «Закрылось» → «Закроем этот тип?».
6. Застрял (точная оценка размера, глубокий разбор, приоритеты, граф
   работ) → предложить эскалацию (`escalation.md`).

### Когда эскалировать

Точная оценка, насколько клиентов много, поиск неочевидных групп
клиентов, сборка графа работ и расстановка приоритетов — частый случай:
«это лучше доверить аналитику — у него инструменты. Передадим, что уже
есть?»

## Стиль вопросов

- До 4 вопросов, короткий header, без жаргона
  (slug/kind/draft/stable/«сегмент»/«работа»/«Score»).
- Опции из `anti-patterns-real.md` — «как обычно описывают / как обычно по
  делу».
- Опции из enum — в бизнес-словах (люди / компании; прямой вопрос «как
  часто покупают» — часто/иногда/редко).
- Существующие записи — показываем `name`, не slug.
- **Other — всегда с примерами.** Без примеров клиент впадает в ступор.
- Числа (как часто, насколько довольны) — просить **с опорой** (наблюдение
  / отзывы / выгрузка); не уверен → «прикинул» / «уточнить».

**Не делать:** свободные вопросы без `AskUserQuestion`; >4 вопросов;
показывать кухню; запускать рой / собирать граф работ (это аналитик);
упоминать имена скилов/аудитов.

## Про границу «закрыли тип»

Аналитик закрывает тип клиента только когда у него сходится приоритизация
(все четыре опоры: важность, частота, размер, недовольство) — а это часто
требует его инструментов. Поэтому у клиента «закрыто» означает «я
рассказал всё, что знаю про этот тип»; финальную проверку и приоритизацию
доделает аналитик. Не обещать клиенту, что тип «полностью готов» — мягко:
«с вашей стороны собрали, дальше аналитик дополнит и сравнит типы между
собой».
