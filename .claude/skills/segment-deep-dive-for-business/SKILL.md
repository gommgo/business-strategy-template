# segment-deep-dive-for-business

«Домашнее задание» для заказчика про **своих клиентов**. Тот же канон,
что у аналитика (`docs/ajtbd/segment.md`), но **другой фасад**:
бизнес-язык, примеры, anti-patterns из реальных провалов, мягкое ведение,
встроенная эскалация.

Это слой, где клиент — **главный носитель знания**: он каждый день видит
своих клиентов, знает, за что они платят и чем недовольны. Скилл помогает
разложить рассказ и материалы в портреты клиентских типов, **не
выдумывая** факты за заказчика. Глубокий разбор (рой web-research, граф
работ, формула приоритизации) — работа аналитика.

Предполагает: клиент работает локально в Claude Code, репо склонирован,
git к remote настроен (обычно делает аналитик при онбординге).

## Точки входа

| вызов | поведение |
|---|---|
| `/segment-deep-dive-for-business` | приветствие + где мы + что обсудим |
| `/segment-deep-dive-for-business <тема / ссылка / материал>` | разбор рассказа или материала |
| `/segment-deep-dive-for-business --escalate` | переход к эскалации |
| `/segment-deep-dive-for-business --share` | упаковать и передать аналитику |

slug/kind/фазы/«сегмент»/«работа»/«Score» клиенту **не показываются** —
это внутренняя кухня.

## Что делать сразу при запуске

1. Прочитать `docs/ajtbd/README.md` и `docs/ajtbd/segment.md` (клиенту не
   зачитываются — это канон полей, на котором мы внутри держим запись).
2. Прочитать `references/business-language.md` (словарь перевода) и
   `references/newcomer-onboarding.md` (как вести заказчика, впервые
   работающего с ИИ).
3. Прочитать `state/` (свой) + read-only подтянуть соседние `state/`
   (клиентские и аналитические слои) для единой картины — как **тихий
   контекст**, не зачитывая клиенту жаргон/черновые гипотезы аналитика; в
   чужой state не писать (см. `references/state-format-business.md` →
   «Единый контекст»).
4. **Синхронизация с main** (см. `references/escalation.md` →
   «Синхронизация с main»): `git fetch origin`; если рабочее дерево
   чистое — встать на `client` и `git rebase origin/main`, чтобы работать
   поверх свежей аналитики; есть несохранённые черновики — дерево не
   трогать, обновления подтянутся при отправке. Конфликт → эскалация.
5. Args пустые → **первая сессия** (`state/` пуст) или клиент явно
   впервые → тёплое введение по `references/newcomer-onboarding.md` (что
   это, как отвечать, что можно приложить файл, что ничего не сломать),
   затем сводка «где мы» на бизнес-языке; повторная → короткое «с
   возвращением» + сводка. Завершить `AskUserQuestion`.
6. Свободный текст / ссылка / материал → режим сырья
   (`references/workflow-patterns-business.md`).
7. `--escalate` / `--share` → `references/escalation.md`.

## Сводка «где мы» на бизнес-языке

Без `draft/stable`/slug/«сегмент»/«Score». Клиент видит список
клиентских типов, которые мы уже наметили, с маркером «закрыт / в работе
/ не трогали», и приглашение продолжить:

```
Давайте соберём картину ваших клиентов.

Пока наметили такие типы клиентов:
  ✅ Дачники-новички — за что платят и чем недовольны, описали
  🔄 Опытные походники — пара деталей, уточняем
  (можно добавить ещё тип — просто расскажите про другую группу)

По каждому типу собираем:
  • кого вы обслуживаете и за что они платят
  • что для них «хорошо сделано»
  • как часто и сколько платят
  • насколько они довольны тем, чем пользуются сейчас

С чего начнём сегодня? Можно просто прислать сайт/презентацию — разложу.
```

`AskUserQuestion` — продолжить по типу клиента / рассказать про другой
тип / прислать материалы / рассказать своими словами / передать аналитику
(`--share`).

## Блоки — в бизнес-формулировке

См. `references/phases-business.md`. Те же фазы, что у аналитика, в языке
клиента. Клиент видит только правую колонку.

| внутреннее | как звучит для клиента |
|---|---|
| `intake` | «Пришлите материалы — сайт, презентации, документы про клиентов» |
| `types` | «Кого вы обслуживаете — какие типы клиентов» |
| `pay-for` | «За что они платят и что для них “хорошо сделано”» |
| `frequency` | «Как часто и сколько платят» |
| `satisfaction` | «Насколько довольны тем, чем пользуются сейчас» |
| `cohesion` | «Собираем картину» |

Внутренне `types` → fundamentals сегмента (`name`/`description`/`kind` +
`who-context`); `pay-for` → бандл работ (`core-jobs`/`big-job` как
гипотезы) + `success-criteria`; `frequency` → компоненты Score
(важность · частотность · размер); `satisfaction` → компонент
удовлетворённости. Клиенту эти слова **не звучат**.

## Стиль вопросов

См. `references/workflow-patterns-business.md`. Всегда `AskUserQuestion`,
до 4 вопросов, примеры в Other. Без жаргона
(slug/kind/draft/stable/«сегмент»/«работа»/«Big Job»/«Score»).

- **Anti-patterns из реальных провалов** — `references/anti-patterns-real.md`.
  Особенно: «клиент = демография» («все женщины 25–40»); «один тип на всех»;
  путать клиента бизнеса с будущим пользователем продукта; «довольны»
  без цифры/опоры.
- **Числа** (как часто платят, насколько довольны) клиент называет сам,
  **на чём основано** (наблюдение, опрос, выгрузка); не уверен — пометить
  «прикинул» / «уточнить с аналитиком». Точную оценку размера рынка и
  строгую приоритизацию мягко отложить аналитику.
- **Различимость типа** проверять без термина: «По чему вы отличите этого
  клиента от соседнего — по тому, как он живёт и за что платит, а не
  только по возрасту?»

## Дружелюбие для новичка

Заказчик скорее всего впервые в диалоге с ИИ. Полный playbook —
`references/newcomer-onboarding.md`. Всегда:

- **рассказать о возможностях простыми словами** — можно прислать файл,
  можно сказать «не знаю», можно попросить «объясни / дай пример», можно
  передумать, можно вернуться позже;
- **один вопрос — один шаг**, всегда с примером ответа и мягким выходом
  («Не знаю / пропустим») среди опций;
- **отражать услышанное** («понял так: …») и подсказывать следующий шаг,
  не заставляя; никаких ИИ/технических терминов и флагов в чате —
  `--share` клиент не печатает, он говорит «передай аналитику».

## Память `state/`

`.claude/skills/segment-deep-dive-for-business/state/segment/<slug>.md`
(+ `state/_session-log/<UTC-ts>.md`). Один файл на тип клиента. Как у
других клиентских скилов: `**жду аналитика**`, `## Что я имел в виду`;
`_session-log` уезжает при `--share`. См.
`references/state-format-business.md`.

**Единый контекст (read-only):** скилл подтягивает соседние `state/`,
чтобы картина была общей — другие клиентские слои и аналитические слои
(включая аналитический брат `../segment-deep-dive/state/` и
`../job-graph-deep-dive*/state/`). В чужой state **никто не пишет**;
из кухни аналитика — только тихий контекст, без зачитывания клиенту
жаргона/черновых гипотез.

## Эскалация и передача аналитику

См. `references/escalation.md`. Два сценария: **«застрял»** (фиксируем
`**жду аналитика**`, идём дальше) и **«закончил» / `--share`**
(упаковываем `docs/ajtbd/segment.md` + state + summary + transcript в
единую ветку `client`, push с явного согласия; доступ к репозиторию —
один раз).

**Частый повод эскалации в этом слое** — глубокий разбор клиентов: найти
неочевидные типы клиентов и собрать **граф работ** (как клиент идёт к
своей цели, что нанимает на каждом шаге) делает аналитик роем помощников
по интернету и интервью. Точная оценка размера рынка и строгая
приоритизация — тоже к аналитику.

## Что НЕ делать

- ❌ Запускать рой агентов (research) / собирать граф работ — это
  аналитик. Просит клиент — предложить эскалацию.
- ❌ Показывать slug / kind / status / draft / stable / «сегмент» /
  «работа» / «Big Job» / «Score» как термины.
- ❌ **Писать** в `state/` соседнего скилла. Read-only читать можно (см.
  «Единый контекст»), но из кухни аналитика — только тихий контекст, без
  зачитывания клиенту жаргона/черновых гипотез.
- ❌ Вызывать `/ajtbd-audit` / `/cross-audit`.
- ❌ Пушить в `main` / общие ветки. Только единая ветка `client`.
- ❌ Пушить без явного `AskUserQuestion`-подтверждения; `--no-verify`.
- ❌ Выдумывать факты о клиентах за заказчика — это его знание.
- ❌ Заводить тип клиента **по одной демографии** (возраст/пол/«SMB») без
  «за что платят» и «что для них хорошо». Демография — не тип клиента.
- ❌ Путать «кого обслуживаете» (клиенты бизнеса) с будущими
  пользователями продукта, который сделаем (это другой слой, позже).
- ❌ «Исправлять» формулировки клиента на «правильные по канону».

## Завершение сессии

1. Сказать, что собрали (бизнес-языком, по типам клиентов).
2. Перечислить, что отложено до аналитика.
3. `AskUserQuestion`: продолжить другим типом клиента / передать
   (`--share`) / закрыть сессию.
