# Формат заметок `state/`

Память скилла — рабочее состояние знания о сущности. Не журнал.

## Расположение

State **скоупится по проекту** — у каждого `<project-slug>` своя ветка,
чтобы разные продукты не сталкивались:

```
.claude/skills/project-deep-dive/state/<project-slug>/
├── vision.md                          (singleton: vision-заметка)
├── persona/<slug>.md
├── capability/<slug>.md
├── boundary/<slug>.md
├── surface/<slug>.md
├── integration/<slug>.md
├── constraint/<slug>.md
├── market/<slug>.md
└── research/
    ├── <query-slug>-<UTC-timestamp>.md
    └── …
```

Заметки лежат **рядом со скиллом**, не в `docs/projects/<slug>/` и не в
корне проекта. Каталоги создаются по требованию.

## Шаблон для kind-заметки

```markdown
---
kind: persona
slug: nurse-partner
ref: docs/projects/<project-slug>/persona.md#nurse-partner
---

## Открытые вопросы
- В скольких клиниках одновременно она работает — одна или несколько?
- (**blocker**) Какой именно мессенджер используется сейчас — это
  диктует surface.type.

## Доменные решения
- jobs = «передать без переспросов», не «передать быстро» — для неё
  важна точность, а не скорость.

## Что копать дальше
- После следующего интервью — уточнить регуляторный режим (152-ФЗ или
  чужая юрисдикция).
```

## Шаблон для vision-заметки

```markdown
---
kind: vision
ref: docs/projects/<project-slug>/vision.md
---

## Открытые вопросы
- (**blocker**) Бизнес ещё не решил, B2B-only или B2C тоже —
  это меняет persona.

## Доменные решения
- Success измеряется в качественном сдвиге, не в метрике — клиент
  готов к качественным наблюдениям лучше, чем к KPI.

## Что копать дальше
- После разговора с клиникой — пересмотреть Non-goals.
```

## Frontmatter

| ключ | значение | назначение |
|---|---|---|
| `kind` | один из 8 | избыточная подсказка читателю + быстрый фильтр |
| `slug` | равен `slug` записи в таблице (для vision — отсутствует) | связь с артефактом |
| `ref` | `docs/projects/<project-slug>/<kind>.md#<slug>` или `docs/projects/<project-slug>/vision.md` | удобная ссылка в редакторе |

## Секции

Все три опциональны. Любая отсутствует, если содержимого нет.

### `## Открытые вопросы`

Список незакрытых смысловых вопросов. Каждый — одна строка списка.

- Префикс `**blocker:**` или суффикс `(**blocker**)` — вопрос блокирует
  переход `draft → stable`. Без префикса/суффикса — открытый, но не
  блокирующий.
- Закрытый вопрос **удаляется** из секции (не зачёркивается, не
  переносится в «решено»). Если стало пусто — удалить всю секцию.

### `## Доменные решения`

Неочевидные смысловые решения, не лезущие в `description` записи.

- Одна строка списка = одно решение.
- Форма: «<что выбрано> — <почему>». Без «было X, стало Y», без дат,
  без отсылки к прошлым попыткам.
- Если решение уже растворилось в `description` — удалить отсюда (не
  дублировать).

### `## Что копать дальше`

Локальные «следующие шаги» по этой сущности.

- Не путать с открытыми вопросами: «копать дальше» — задача
  аналитика; «открытый вопрос» — конкретный неясный смысл.
- При выполнении шага — удалить строку. Если стало пусто — удалить
  секцию.

## Особый случай: research-отчёт

`state/<project-slug>/research/<query>-<ts>.md` — **не** kind-заметка.
Это сырьё с роя агентов. Структура другая:

```markdown
---
query: <фокус, фразой>
ts: <ISO UTC>
agents: 5
focus-kinds: [market, constraint]
---

## Угол 1: Direct competitors

<отчёт агента 1>

## Угол 2: Indirect/adjacent

<отчёт агента 2>

…

## Кандидаты

### market
- `<slug>` · «<name>» · <one-line description> · `<url>` · sources: `[<urls>]` · relevance: `high`
- …

### constraint
- …
```

Research-отчёт **не удаляется** после promotion кандидатов в артефакты
(в отличие от kind-заметок). Это исходник, к которому может вернуться
аналитик при следующем заходе.

## Read-only видимость state соседнего скилла

Скилл может прочитать
`../project-deep-dive-for-business/state/<project-slug>/<kind>/<slug>.md`,
чтобы увидеть, что клиент уже накопал по этому проекту в режиме
«домашнее задание». **Писать туда запрещено.** Формат тот же — но
владелец другой.

## Правила жизненного цикла

- **Создаётся** только когда есть что записать (хотя бы одна
  непустая секция).
- **Перезаписывается** свободно — это рабочее состояние.
- **Удаляется** (kind-заметки):
  - Все три секции пустые → удалить файл.
  - Запись в артефакте удалена (каскад) → удалить файл.
- **Не аккумулировать** журнал: после правок строк «было/стало», дат,
  «решено такого-то», «обсуждено» — не должно быть.
- Research-отчёты — **не удаляются** автоматически.

## Что НЕ хранить в kind-заметке

- Историю изменений (это git).
- Журнал сессий «над чем работали такого-то числа».
- Дубликаты содержимого таблицы (slug → таблица, name → таблица,
  status → таблица).
- Доменные термины и формулировки от модели «на всякий случай».
- Альтернативы, которые рассматривались, но забыты, — если они
  не «доменное решение» с обоснованием.
- Ссылки на внешние материалы и транскрипты — это сырьё для режима B
  или research-отчёт, не память.
