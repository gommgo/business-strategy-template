# Контракт `draft → stable`

Запись становится `stable`, когда **все 6 пунктов одновременно** ✅.
Скилл проверяет, аналитик подтверждает, скилл применяет. Чек-лист — для
flow, screen, block, shell и `map.md`; у строк реестра `texts.md` свои
статусы (`assumed` → `checked` → `approved`, раздел «Тексты интерфейса»
канона слоя).

## Чек-лист

### 1. Обязательные слоты frontmatter заполнены

Опциональные могут быть `—` или отсутствовать. Остальные —
обязательно с непустым значением (для slug-полей — реф; для
свободного текста — фраза).

См. `field-checklists.md` — там по каждому из 4 kind: какие слоты
обязательны и какие опциональны.

### 2. Все ссылки валидны

Каждый `slug` существует **в пределах текущей поверхности**:

**Внутри screens** (все пути — в папке текущей поверхности текущего
проекта `docs/projects/<project-slug>/screens/<surface>/`):
- `flow.desktop` / `flow.mobile` / `flow.transitions[].{from,to}` →
  существуют как папки `…/screens/<surface>/screens/<slug>/`;
- `screen.shell` → `…/screens/<surface>/shells/<slug>/`;
- `screen.blocks` / `block:<slug>` в `slot-fills`/`states` →
  `…/screens/<surface>/blocks/<slug>/`;
- `screen.transitions-to-screen[].to`, `tiles[].link` →
  `…/screens/<surface>/screens/<slug>/`;
- `screen.mobile-of` → `…/screens/<surface>/flows/<slug>/`;
- `block.used-by-screens` → `…/screens/<surface>/screens/<slug>/`;
- `text:<key>` в деревьях, `form.error`, `tiles.no-data` → строка
  `…/screens/<surface>/texts.md`.

**В interface** (interface-слой **той же поверхности** того же проекта,
`docs/projects/<project-slug>/interface/<surface>/`):
- `screen.situations` → строка `<slug>` в
  `…/interface/<surface>/situation.md`;
- `screen.who` / `flow.who` → строка `<slug>` в
  `…/interface/<surface>/who.md`;
- `block.interface-block` → строка `<slug>` в
  `…/interface/<surface>/block.md`;
- `block.ux-substrates[*]` → строка `<slug>` в
  `…/interface/<surface>/ux-substrate.md`;
- `data:<slug>` внутри `tree`/`slot-fills` → строка `<slug>` в
  `…/interface/<surface>/data-items.md`;
- `screen.zone` → строка `<slug>` в `…/interface/<surface>/zone.md`.

**В продуктовом слое** (`docs/projects/<project-slug>/`):
- `screen.object`, объектный тип в `screen.params` → объект `object.md`;
- `data:<slug>.<атрибут>` → атрибут объекта, на который ссылается
  `data-items.object`;
- `screen.main-task` → возможность `capability/<surface>.md` той же
  поверхности;
- `screen.key-action`, атрибут `action=`, `collection.bulk`,
  `tiles.action` → действие `action.md`.

**Словарь компонентов**: каждый `ui:<Тип>` — тип словаря или расширения
проекта, часть — из `parts` (`tree-notation.md`).

**Assets**: каждый путь в `assets: [...]` ссылается на
существующий файл в
`docs/projects/<project-slug>/screens/<surface>/assets/<kind>/<slug>/`.

`stable` может ссылаться на `draft` — это допустимо. Аудит подсветит
hint, но не блокирует stable.

### 3. Зеркала консистентны

- `block.ux-substrates` (screens, frontmatter) **равен**
  `block.ux-substrates` (interface,
  `docs/projects/<project-slug>/interface/<surface>/block.md`, строка с
  тем же slug). При расхождении — `**blocker**` в state, не stable.
- `block.used-by-screens` **равен** множеству screen-slug'ов, в
  чьих `slot-fills`/`states` встречается `block:<slug>`. Скилл
  пересчитывает автоматически.
- `screen.blocks` **равен** множеству block-slug'ов, на которые
  ссылается `block:<slug>` внутри `slot-fills`/`states` экрана.
  Скилл пересчитывает автоматически.
- Свод `map.md` (`## Карта экранов`, `## Маршруты`, `## Навигация`)
  **совпадает** с полями экранов: экрана без строки и строки без экрана
  нет. Канон — экраны: скилл пересобирает свод после каждой их правки.

### 4. Тест-критерий явно подтверждён

В README соответствующего kind (канон
`docs/projects/_template/screens/_template/<kind>.md`) есть секция
`Тест-критерий` с примерами ✅/❌. Через `AskUserQuestion` скилл
предъявляет аналитику примеры и спрашивает: «какой из этих образцов
ближе всего к вашей записи?».

Запись проходит, когда аналитик соотносит её с ✅-примером и
эксплицитно подтверждает «да, это так».

### 5. State-заметка чиста по `**blocker**`-вопросам

`../entrypoint/state/projects/<project-slug>/screens/<surface>/<kind>/<slug>.md`:

- Не содержит секцию `## Открытые вопросы` ИЛИ
- Содержит, но в ней нет вопросов с префиксом/суффиксом `**blocker**`.

Не-blocker открытые вопросы при stable допустимы (они описывают
«хорошо бы узнать», не «здесь смысл сломан»).

Секции `## Доменные решения` и `## Что копать дальше` к stable не
относятся — они могут быть.

### 6. Дерево в теле полное

Общее для деревьев: дерево парсится как YAML по грамматике
(`tree-notation.md`); `ui:` — тип словаря или расширения; атрибуты — из
закрытого списка; облика нет; текст — ключ `text:<key>` со строкой реестра
`texts.md` в статусе `checked` или `approved`, литерала в дереве нет.

**flow**: тело — markdown-прозa без yaml-дерева. Пункт для flow ✅,
если frontmatter полный; у экрана `type: master-detail` из списка
`desktop` мобильная серия — минимум список и детали.

**screen**:
- `slot-fills` покрывает все слоты, объявленные в shell как
  `required: true`. Опциональные слоты могут быть `—`, но не пусты.
- `states` покрывает **обязательный набор** экрана
  (`field-checklists.md`, раздел screen; канон слоя, «Обязательный
  набор»): каждое обязательное состояние — дельта (хотя бы один слот
  переопределён) или `'не применимо: причина'`. Ключи — только из словаря
  состояний экрана.
- Ровно один заголовок экрана — текстовый узел роли `title` в основном
  содержимом вне оверлеев; у экрана с перетаскиванием — раздел
  `## Доступность` с путём одним указателем и с клавиатуры.

**block**:
- `tree` содержит как минимум `block-body`.
- Каждый объявленный `ux-substrate` представлен узлом в дереве
  (по типу и назначению узла считается покрытым; спорные —
  `AskUserQuestion`).
- Индикаторов и состояний в `tree` нет; у блока `source: own` — раздел
  `states` с `loading-initial` и `error-load` (у коллекции — ещё
  `empty-first-run`, `empty-filtered`, `partial-few`).
- Контракты по составу дерева заполнены: `form` — у блока с субстратом
  `ввод` или `выбор`, `collection` с `volume` — у коллекции, `tiles` — у
  плиток показателей (незаполненное поле плитки — названное решение
  «не выводить»).

**shell**:
- `slots` объявлены и для каждого указаны `required`, `accepts`,
  `landmark`; ровно один слот — `landmark: main`.
- `tree` содержит каркас (`layout:`-узлы и типы словаря) с
  `fills=$<slot>` для каждого объявленного слота; слотовые узлы пустые.
- У основного каркаса — навигация узлом дерева, один узел помощи и
  раздел «Состояния приложения» (строка на каждое состояние или «не
  применимо: причина»).

**map.md**: авторские разделы полны — у строки основание и, где нужно,
проверка («Переход» — как проверить, «Решения» — кто теряет); у каждого
действия экранов — строка «Событий»; «Узкий экран» — строка на каждый тип
экрана поверхности, если vision не записал «только десктоп».

## Алгоритм проверки скиллом

После любой правки сущности:

1. Прочитать
   `docs/projects/<project-slug>/screens/<surface>/<kind>/<slug>/index.md`.
2. Прочитать
   `../entrypoint/state/projects/<project-slug>/screens/<surface>/<kind>/<slug>.md`,
   если есть.
3. Прочитать соседей (см. `field-checklists.md`).
4. Прогнать пункты 1, 2, 3, 5, 6 (проверяемые по форме). Разбор дерева,
   набор состояний и свод `map.md` считают утилиты раздела `project`
   скилла дизайна (`../design-deep-dive/scripts/README.md § project`):
   `tree`, `states` и `screen_map` —
   `check <project-slug> <surface>`, строки находок с правилом
   `/screen-audit`, код 1 — есть `error`; реестр текстов —
   `copy_lint.py texts.md` (0 error — строки могут быть `checked`). Когда
   окружения нет — скилл проверяет то же чтением по форме.
5. Если все 5 ✅ — раунд `AskUserQuestion` по тест-критерию
   (пункт 4).
6. Если и пункт 4 ✅ — раунд `AskUserQuestion`: «Готов к stable,
   повышаем?» с опциями «Да, повысить» / «Нет, ещё не уверен»
   (через Other — что именно смущает).
7. При «Да» — `Edit`'ом поменять `status: draft → stable` в
   frontmatter.

## Что НЕ делать

- **Не повышать сам**, без подтверждения аналитика. Даже если все
  6 пунктов ✅ — спросить.
- **Не понижать `stable → draft` сам** при обнаружении проблемы —
  это смысловое решение аналитика. Можно подсветить и предложить.
- **Не считать пункт 4 пройденным «по умолчанию»**, потому что
  слоты заполнены. Тест-критерий — отдельное смысловое
  подтверждение.
- **Не игнорировать `**blocker**`-вопросы** — они должны быть
  закрыты или удалены (если стали неактуальны) до stable.
- **Не считать пункт 3 пройденным**, если зеркало
  `block.ux-substrates` расходится с interface — даже если аналитик
  сказал «потом разберёмся».
- **Не ставить «не применимо» за аналитика.** Причина, по которой
  обязательному состоянию нечего показать, — его решение; пустая строка
  набора — дыра, а не ответ.
- **Не ждать утверждения текстов для stable экрана.** Экрану достаточно
  строк `checked`; `approved` владельца продукта нужно до чистового
  макета и передачи в код.
