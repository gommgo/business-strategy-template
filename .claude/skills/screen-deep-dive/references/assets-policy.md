# Политика ассетов

Сырьё экранов — снимки действующего интерфейса заказчика, наброски,
кадры из Figma, чужие экраны как референс композиции — живёт в
`docs/projects/<project-slug>/screens/<surface>/assets/<kind>/<slug>/` и
ссылается на сущность через поле `assets: [...]` во frontmatter.
Ассеты скоупятся по проекту **и поверхности**: у каждой поверхности
проекта своя папка `<surface>/assets/`. Это не мудборд и не облик:
мудборд, направления, иллюстрации и иконки живут в слое дизайна
`design/`.

## Структура папок

```
docs/projects/<project-slug>/screens/<surface>/assets/
├── flow/
│   └── <slug>/
│       └── <file>.{png,jpg,svg,webp}
├── screen/
│   └── <slug>/
│       └── ...
├── block/
│   └── <slug>/
│       └── ...
└── shell/
    └── <slug>/
        └── ...
```

Папка `<surface>/assets/<kind>/<slug>/` создаётся, только когда у
сущности появляется первый ассет. Папка живёт под git, ассеты — тоже.

## Имена файлов

- kebab-case;
- расширение по факту (`.png` / `.jpg` / `.svg` / `.webp`);
- осмысленные слова о содержимом: `master-detail-figma.png`,
  `competitor-linear-list.png`, `mobile-list-sketch.jpg`,
  `dashboard-figma-frame-12.png`;
- никаких хешей и uuid'ов в имени, никаких `Screenshot 2024-01-15 at
  14.32.png` — даже если такая картинка пришла. Скилл предлагает
  переименование при сохранении.

## Поле во frontmatter

Любая сущность из 4 kind может иметь поле `assets`:

```yaml
assets:
  - master-detail-figma.png
  - competitor-linear-list.png
```

- Пути — относительные от
  `docs/projects/<project-slug>/screens/<surface>/assets/<kind>/<slug>/`.
  То есть в frontmatter — только имя файла.
- Поле опциональное. Если ассетов нет — поля во frontmatter тоже
  нет (не `assets: []` и не `assets: '—'`).
- Существование каждого файла проверяет `/screen-audit` (R-COV-006).
  Несуществующий путь — audit-error.

## Входящая картинка от аналитика

Сценарий: аналитик в сообщении прикладывает скриншот (или ссылается
на URL картинки) — режим B (сырьё) или режим C (углубление с
референсом).

### Шаги

1. **Прочитать картинку** — скилл описывает содержательно: что за макет,
   какие зоны/слоты/блоки видны, какие паттерны (master/detail,
   list+toolbar, modal, …).
2. **Через `AskUserQuestion`** предложить аналитику что с этим
   делать — батч до 4 вопросов:
   - «Сохранить картинку как референс к сущности?» (опции: «да, к
     <kind>:<slug>» / «да, к новой сущности — какой kind»
     (Other) / «нет, использую только как сырьё»);
   - «Имя файла» (Other, kebab-case; скилл предлагает по умолчанию
     по содержимому);
   - «Поискать в web более качественные референсы по тому же
     паттерну?» (опции: «да, поищи» / «нет, этого достаточно»);
   - «Извлечь кандидатов на flow/screen/block/shell из этой
     картинки сразу?» (для режима B; опции: «да» / «нет, пока
     просто сохрани референсом»).
3. **По «сохранить»** — Edit'ом во frontmatter сущности добавить
   путь в `assets: [...]`. Скилл сохраняет файл через `Bash` —
   копирует из временного пути (где Claude получил картинку) в
   `docs/projects/<project-slug>/screens/<surface>/assets/<kind>/<slug>/<имя>.<ext>`.
4. **По «не сохранять»** — картинка только в контексте сессии,
   используется как сырьё для извлечения кандидатов / углубления.

## Web-поиск референсов

Сценарий: аналитик говорит «найди референсы на X», «как делают такое
в других продуктах», «покажи примеры master-detail для медицинских
систем». **Только по явной просьбе** — скилл не лезет в web сам.

### Шаги

1. **`WebSearch`** с запросом, выведенным из формулировки аналитика.
   Если запрос неясен — `AskUserQuestion` уточнить (паттерн? тип
   продукта? стиль?).
2. **Показать кандидатов** через `AskUserQuestion` — до 4 ссылок с
   короткими описаниями (заголовок + URL + 1 фраза «что это»):
   - «Кандидат 1: <title>» (опция);
   - …
   - «Кандидат 4: <title>» (опция);
   - аналитик выбирает один или несколько; либо «ни один не
     подходит» (Other);
   - либо «поищи ещё с другими словами: <уточнение>» (Other).
3. **По выбранным** — `WebFetch` страницы. Если на странице есть
   подходящая картинка — скачать её в
   `docs/projects/<project-slug>/screens/<surface>/assets/<kind>/<slug>/<имя>.<ext>`.
   Имя — kebab-case по содержимому страницы
   (`linear-issues-list-2024.png`).
4. **Edit** frontmatter сущности — добавить путь в `assets`.
5. Если страница даёт идеи, но картинку извлечь не вышло, — добавить
   в state-заметку `## Что копать дальше` строку с URL и пометкой
   «вдохновение — <что взять>».

### Что НЕ делать

- Не лазить в web без явной просьбы аналитика.
- Не скачивать несколько референсов «на всякий случай» — только
  выбранные аналитиком.
- Не сохранять URL как «ассет» — ассет это файл в репо. URL без
  скачивания → строка `## Что копать дальше` в state.
- Не сохранять картинку, защищённую копирайтом конкурента в
  деликатном контексте — если аналитик явно говорит «нет, это
  чужое, не клади в репо» → только в контексте сессии.

## Каскад при удалении сущности

При удалении сущности (см. SKILL.md `## Удаление сущности (каскад)`)
— папка
`docs/projects/<project-slug>/screens/<surface>/assets/<kind>/<slug>/`
удаляется целиком. Ассеты сущности живут ровно столько, сколько живёт
сущность.

## Связь с кодом

Прямой связи нет. Ассеты — сырьё аналитической работы над композицией;
макет по экранам собирает слой дизайна `design/` по контракту генерации,
который отдаёт слой экранов. Код
`docs/projects/<project-slug>/screens/<surface>/assets/` напрямую не
читает.
