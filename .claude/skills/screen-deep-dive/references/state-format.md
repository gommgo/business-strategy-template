# Формат заметки `state/<project-slug>/<kind>/<slug>.md`

Память скилла — рабочее состояние знания о сущности. Не журнал.

Заметки лежат **рядом со скиллом**, не в
`docs/projects/<project-slug>/screens/` и не в корне проекта, и
скоупятся по проекту:

```
.claude/skills/screen-deep-dive/state/<project-slug>/<kind>/<slug>.md
```

Дальше по тексту — короткое `state/`, это сокращение того же пути
(с учётом текущего `<project-slug>`).

## Шаблон

```markdown
---
kind: screen
slug: studies-workspace
ref: docs/projects/<project-slug>/screens/screens/studies-workspace/index.md
---

## Открытые вопросы
- Какой `route` использовать — `/studies` или `/work/studies`?
- Нужен ли отдельный empty-state для permission-denied? (**blocker**)

## Доменные решения
- detail-слот на mobile уходит в отдельный screen (через flow), а не
  в overlay — потому что master/detail на mobile неприменим из-за
  узкого viewport.

## Что копать дальше
- Раскрыть states.empty для slot=side (фильтры пустые).
- ui-lib gap: нужен ui:SplitView с настраиваемым соотношением — для
  master/detail с резиновой границей.
```

## Frontmatter

| ключ | значение | назначение |
|---|---|---|
| `kind` | один из 4 (`flow`, `screen`, `block`, `shell`) | избыточная подсказка читателю + быстрый фильтр |
| `slug` | равен `slug` сущности в `docs/projects/<project-slug>/screens/<kind>/<slug>/index.md` | связь с артефактом |
| `ref` | `docs/projects/<project-slug>/screens/<kind>/<slug>/index.md` | удобная ссылка в редакторе |

## Секции

Все три опциональны. Любая отсутствует, если содержимого нет.

### `## Открытые вопросы`

Список незакрытых смысловых вопросов. Каждый — одна строка списка.

- Префикс `**blocker:**` ИЛИ суффикс `(**blocker**)` — вопрос
  блокирует переход `draft → stable`. Без префикса/суффикса —
  открытый, но не блокирующий.
- Закрытый вопрос **удаляется** из секции (не зачёркивается, не
  переносится в «решено»). Если стало пусто — удалить всю секцию.

### `## Доменные решения`

Список неочевидных смысловых решений, которые не помещаются в ячейку
`description` сущности, но важны для будущих сессий.

- Одна строка списка = одно решение.
- Форма: «<что выбрано> — <почему>». Без «было X, стало Y», без дат,
  без отсылки к прошлым попыткам.
- Если решение уже растворилось в `description` сущности — удалить
  отсюда (не дублировать).

### `## Что копать дальше`

Список локальных «следующих шагов» по этой сущности. Также сюда
попадают **ui-lib gaps** — обратная связь в библиотеку.

- Не путать с открытыми вопросами: «копать дальше» — задача
  аналитика; «открытый вопрос» — конкретный неясный смысл.
- **ui-lib gap** — отдельная строка списка с префиксом
  `ui-lib gap:` + имя предложенного компонента + для чего нужен.
  Пример: `ui-lib gap: нужен ui:Calendar — для выбора диапазона
  дат в filters-panel`.
- При выполнении шага — удалить строку. Если стало пусто — удалить
  секцию.
- ui-lib gap НЕ удаляется автоматически, даже если компонент
  потом появился в инвентаре. Аналитик решает: либо строка
  устаревает (стереть), либо актуальна (нужно пересмотреть, как
  использовать).

## Правила жизненного цикла

- **Создаётся** только когда есть что записать (хотя бы одна
  непустая секция).
- **Перезаписывается** свободно — это рабочее состояние.
- **Удаляется**:
  - Все три секции пустые → удалить файл целиком.
  - Сущность в `docs/projects/<project-slug>/screens/<kind>/<slug>/`
    удалена (каскад) → удалить файл.
- **Не аккумулировать** журнал: после правок сущности «было/стало»,
  дат, «решено такого-то», «обсуждено» — не должно быть.

## Что НЕ хранить в заметке

- Историю изменений (это git).
- Журнал сессий «над чем работали такого-то числа».
- Дубликаты содержимого frontmatter (slug → frontmatter, name →
  frontmatter, status → frontmatter, ассеты → frontmatter).
- Дизайн-обоснования облика (цвет, шрифт, размер) — это craft
  библиотеки, в state-памяти скилла не место.
- Альтернативы, которые рассматривались, но забыты, — если они не
  «доменное решение» с обоснованием.
- Ссылки на внешние материалы, скриншоты, транскрипты — это сырьё
  для режима B, не память. Сами материалы → `assets/`.
