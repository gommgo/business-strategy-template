# Нотация дерева

Как собирать yaml-дерево `slot-fills` / `states` (screen) и `tree` (block,
shell). Канон нотации — `docs/projects/_template/screens/README.md` (форма
артефакта, layout-язык, узлы раскладки); здесь — как скилл ведёт по нему
аналитика. Читать перед углублением дерева любой сущности.

## Узлы

| префикс | что это | пример |
|---|---|---|
| `ui:` | интерфейсный примитив проекта (кнопка, поле, поиск, таблица) | `ui:Button`, `ui:Search`, `ui:Field.Label` |
| `layout:` | узел раскладки, не компонент | `layout:stack`, `layout:row`, `layout:grid`, `layout:layer` |
| `icon:` | иконка по имени | `icon:plus` |
| `block:` | проектный блок этой поверхности (`blocks/<slug>/`) | `block:filters-panel` |
| `data:` | датум из `interface/<surface>/data-items.md` | `data:study`, `data:study.name` |
| `block-*:` | зона блока (только в `tree` блока) | `block-header:`, `block-body:` |

- `ui:<Name>` — имя примитива в дереве. В коде его реализует проектный
  компонент; у фронтовой поверхности это слайс `shared-ui` FSD-карты. Часть
  составного примитива пишется через точку: `ui:Field.Label`.
- Атрибуты узла (`variant=accent`, `size=lg`, `gap=md`) — смысловые
  пометки автора. Внешнего словаря у них нет, значения ни с чем не
  сверяются.
- Текст и иконка — дети узла (`- 'Новое'`, `- icon:plus`), не атрибуты.
- Раскладка — `layout:`-узлы с атрибутами из канона слоя (`gap`,
  `justify`, `align`, `wrap`, `columns`, `areas`, `span`); размеры —
  токенами намерения (`xs`…`lg`), не пикселями.
- Облик (цвет, типографика, пространство, движение) в дерево не пишется:
  wireframe и hi-fi автор макета собирает вручную по дереву.

## Имена `ui:*` в пределах поверхности

Один примитив — одно имя во всех деревьях поверхности: поиск в шапке
одного блока и в фильтрах другого — один и тот же `ui:Search`. Поэтому при
выборе примитива опции — имена `ui:*`, уже встречающиеся в
`screens/<surface>/`, плюс «новый примитив» (Other). Новый примитив
аналитик называет словами («поле поиска по списку»), имя `ui:<Name>`
(PascalCase, англ.) скилл выводит сам и показывает одной строкой для
контроля — так же, как slug (`.claude/rules/naming.md`).

## Опции по месту в дереве

- слот shell — `block:<slug>` из существующих или inline-дерево (что
  допускает `accepts` слота);
- состояние `loading` в `screen.states` — примитив-индикатор (`ui:Spinner`,
  `ui:Skeleton`) либо композиция;
- прочие состояния (`empty`, `error`, `permission-denied`, `offline`,
  `not-found`) — `layout:`-узлы с текстом-детьми и, если нужно действие
  («повторить», «создать»), примитив действия;
- `tree` блока — зоны `block-*`; внутри `block-body` — `layout:`-узлы и по
  узлу на каждый объявленный субстрат блока (по смыслу субстрата), данные —
  через `data:`;
- `tree` shell — `layout:`-узлы и навигационные примитивы; слотовые узлы с
  `(fills: $<slot>)` пусты;
- overlay — примитив-оверлей (модалка, шторка) либо блок в слоте с
  `accepts: block (modal/drawer)`.

## Значения атрибутов

- структурные enum'ы канона слоя (`viewport`, `accepts`, `behaviour`,
  атрибуты `layout:`-узлов) — опциями, по одной на значение;
- прочие атрибуты — свободная форма (Other): смысл пометки задаёт автор;
- сложные конструкции (`columns: [...]`, `items: data:study`) — отдельным
  раундом; скилл проверяет синтаксис `data:<slug>`;
- текст (подпись кнопки, заголовок, placeholder) — ребёнок узла,
  формулировка аналитика (Other).
