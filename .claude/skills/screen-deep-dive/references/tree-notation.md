# Нотация дерева

Как вести аналитика по дереву экрана (`slot-fills`, `states`), блока
(`tree`; раздел `states` — у блока со своим источником) и каркаса (`tree`).
Канон нотации — `docs/projects/_template/screens/README.md § Нотация дерева`
(узлы, атрибуты, узлы раскладки, внутренние области блока, данные и
тексты). Грамматика ниже повторяет канон дословно: при расхождении прав
канон. Читать перед углублением дерева любой сущности.

## Грамматика

Дерево **парсится как YAML** — компактная форма: узел без детей — строка,
узел с детьми — словарь из одного ключа-головы со списком детей, узел со
структурными атрибутами — словарь атрибутов.

```
узел       := лист | ветвь
лист       := голова                      строка YAML; в draft допустим литерал текста в кавычках
ветвь      := { голова: дети | структура } словарь из одного ключа
дети       := [ узел, … ]
структура  := { атрибут: значение, …, children?: [ узел, … ] }    items, columns, areas, fill, children
голова     := префикс ":" имя { " " атрибут "=" значение }
префикс    := ui | layout | block | data | text | icon
имя        := ui: <Тип>[.<Часть>] · data: <item>[.<атрибут>] · text: ключ реестра · layout: row|stack|grid|layer · block, icon: slug
значение   := токен без пробелов: slug, data:…, text:…, $слот, число
```

- **Корни.** У блока `tree` — словарь внутренних областей (`block-header` ·
  `block-body` · `block-footer` · `block-aside`) → дети; у каркаса `tree` —
  дети; у экрана `slot-fills` — слот → `block:<slug>` \| дети \| `—`;
  `states` — ключ состояния → слот → дети \| `'не применимо: причина'`.
- **Атрибут — в одном месте узла.** Простое значение — в голове
  (`items=nav`, `value=data:study.name`), составное (список колонок,
  области сетки) — ключом структуры.
- Узел с детьми кончается двоеточием; слот каркаса — атрибут
  `fills=$<slot>` в голове узла.

Дерево, которое не парсится как YAML, — ошибка; ключ структуры или атрибут
вне списка — предупреждение (`/screen-audit`). Разбор и проверку дерева
делает утилита `tree` раздела `project` скилла дизайна
(`../design-deep-dive/scripts/README.md § project`); пока её файла нет,
скилл после каждой правки дерева проверяет его разборщиком YAML окружения
и читает по грамматике.

## Компонент — тип закрытого словаря

- `ui:<Тип>` — ключ раздела `types` словаря
  `../design-deep-dive/kb/common/components.yaml` или тип расширения
  проекта (раздел `extensions` карты решений
  `docs/projects/<project-slug>/design/system.yaml`); часть составного —
  `ui:<Тип>.<Часть>` из `parts` типа.
- Имя берут из словаря по потребности (`purpose`) и группе (`group`), а не
  выводят из слов аналитика: одна потребность — один тип во всём продукте,
  иначе два способа выбрать дату со временем расходятся. Аналитик
  описывает, что нужно, словами; скилл называет группу и даёт опциями
  типы, чья потребность ближе к описанию, — с `purpose` одной строкой в
  описании опции.
- Имена из `aka` в дереве не пишутся: `Navbar` — это `TopBar`, `Search` —
  `SearchInput`. Аналитик назвал компонент чужим именем — скилл
  показывает тип словаря, у которого это имя в `aka`.
- Потребность, которую не закрывает ни один тип, — расширение словаря. Его
  заводит слой дизайна рядом с сопоставлением «тип → компонент ДС»
  (`docs/projects/_template/design/README.md § Расширения словаря`), а не
  этот скилл: в заметке узла — `**blocker**` «нужно расширение словаря —
  `/design-deep-dive <project-slug>`», в дереве — ближайший тип словаря до
  решения.
- Композиции — не компоненты: каркас приложения, шапка страницы, список
  объектов, master-detail, панель фильтров собираются каркасами и блоками
  из типов (раздел `outside` словаря); тип экрана — поле `type` экрана.

## Опции по месту в дереве

- **Слот каркаса** — `block:<slug>` из существующих или дерево — что
  допускает `accepts` слота.
- **`states` экрана** — ключи словаря состояний экрана (канон слоя,
  «Состояния экрана») из обязательного набора экрана
  (`field-checklists.md`, раздел screen): загрузка — `ui:Skeleton`,
  `ui:Spinner` или `ui:Progress`; пустое — `ui:EmptyState` с текстом и,
  где нужно, действием; ошибка загрузки — `ui:Alert` с повтором; нечего
  показать — `'не применимо: причина'` (причина — слова аналитика).
- **`tree` блока** — внутренние области `block-*`; в `block-body` — узел на
  каждый объявленный субстрат блока (по смыслу субстрата), данные — через
  `data:`. Индикаторов и состояний в `tree` нет: у блока со своим
  источником они живут в его разделе `states`, у остальных — в `states`
  экрана.
- **`tree` каркаса** — `layout:`-узлы, навигация (`ui:Sidebar items=nav`,
  `ui:TopBar`, `ui:BottomNav`), один узел помощи; слотовые узлы с
  `fills=$<slot>` пусты.
- **Оверлей** — блок в слоте `accepts: block (modal/drawer)`; тип —
  `ui:Modal`, `ui:Drawer` или `ui:ConfirmModal` (подтверждение).

## Атрибуты — закрытый список

| узел | атрибут | как выбирается |
|---|---|---|
| `ui:` | `level` | опции `primary` · `secondary` · `tertiary` — уровень действия по матрице действий (ux 04/10 §1.1–§1.2); «в меню» и «контекстное» — узлом внутри `ui:Menu` |
| `ui:` | `action` | опции — действия словаря `action.md` проекта |
| `ui:` | `illustration` | у `ui:EmptyState` — метафора из списка паспорта визуала продукта (слой дизайна); паспорта нет — атрибут не пишется, вопрос — в заметку |
| `ui:` | `items`, `columns`, `value` | привязка `data:<item>[.<атрибут>]`; у навигации — `items=nav` |
| `ui:`, `layout:` | `fills` | только в дереве каркаса: `fills=$<slot>` |
| `layout:` | `gap` | опции — имена токенов `space.*` дизайн-системы (`xs`, `sm`, `md`, `lg`) |
| `layout:` | `justify`, `align`, `wrap` | перечни канона слоя — опциями |
| `layout:` | `columns`, `areas`, `fill`, `span` | структура сетки — отдельным раундом |

Вид и размер компонента (`variant`, `size`) не пишутся — их решает
дизайн-система; уровень действия — смысл по матрице действий, поэтому он в
дереве. Атрибут вне списка скилл не заводит, даже по просьбе: называет, где
живёт решение (облик — слой дизайна, ось контекста — корень приложения).

## Данные, тексты, иконки

- `data:<item>` — датум `interface/<surface>/data-items.md`;
  `data:<item>.<атрибут>` — атрибут объекта, на который ссылается датум
  (`data-items.object`): опции — атрибуты таблицы «Атрибуты» `object.md`,
  ранги подсказывают, что показать первым.
- Текст — ребёнок узла `- text:<key>`, заголовок колонки —
  `label: text:<key>`. Ключ скилл выводит по месту и роли:
  `{раздел}.{экран}.{элемент}.{роль}` (ux 07/05 §3.1); роль — у текстовой
  части компонента (раздел `text_roles` словаря: под `ui:Button` —
  `action`, под `ui:Field.Error` — `error`). Ключ показывается одной
  строкой для контроля, как slug, а строка реестра `texts.md` заводится
  черновиком (этап «тексты интерфейса», `SKILL.md`).
- В `draft` допустим литерал в кавычках — формулировка аналитика до
  реестра; в `stable` литерал — ошибка, у ключа — строка реестра.
- Иконка — ребёнок узла (`- icon:<имя>`), не атрибут; имя — из набора
  иконок дизайн-системы, сверяет слой дизайна.

## Пример

Иллюстрация формы, не образец ответа: дерево блока формы с полем выбора и
двумя кнопками.

```yaml
tree:
  block-body:
    - layout:stack gap=md:
        - ui:Field:
            - ui:Field.Label:
                - text:referrals.new.patient.label
            - ui:Combobox value=data:referral.patient
            - ui:Field.Error:
                - text:referrals.new.patient.error
  block-footer:
    - layout:row justify=end gap=sm:
        - ui:Button level=secondary:
            - text:referrals.new.cancel.action
        - ui:Button level=primary action=send:
            - text:referrals.new.send.action
```
