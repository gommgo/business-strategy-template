# de-template — движок развёртывания docs-репо

Превращает форк `project-docs-template` в docs-репо проекта, который ничего
не помнит про шаблон. Этот репо — **design-time SoT** (markdown-only,
кода нет), поэтому de-template здесь не разворачивает фундамент по
артефактам, а **снимает показную template-идентичность**:

1. Удаляет показной продукт `docs/projects/example/` целиком (чужая витрина
   screens-слоя — медисследования: flows / screens / blocks / shells +
   interface-stub).
2. Переформулирует template-нарратив в `CLAUDE.md`/`README.md` под
   идентичность проекта клиента.

Движок **skill-only**: committed-скрипта нет — детерминированная механика
идёт как **reviewable edits под этой процедурой**, каждый шаг — отдельный
diff; каждое необратимое действие (удаление `example/`) — через явный
`AskUserQuestion` после показа каскада.

Запускается **один раз** на форке. Финал — репо без `docs/projects/example/`
и без «шаблон»-нарратива в корневых `CLAUDE.md`/`README.md`.

## Что вычищается / что НЕ трогается

**Вычищается (показуха):**

- `docs/projects/example/` — **целиком** (19 файлов: flows / screens / blocks
  / shells + `interface-stub.md` + README). Чужой продукт-витрина.
- Template-нарратив в корневых `CLAUDE.md`/`README.md` («проектный шаблон»,
  «импортируется под бизнес», «Use this template», описание `example/` как
  витрины) — переформулируется под конкретный проект.
- Ссылки на `example/` в `docs/README.md` и `docs/projects/README.md`.

**НЕ трогается (рабочая основа, не показуха):**

- `docs/projects/_canon/` — пустые скелеты-каноны формы (project / interface
  / screens / domains, включая `_templates/` и `_shared/`). Наследуется форком.
- `docs/business/*.md` — kind-шаблоны бизнеса (1 singleton + 6 kind) — пустые
  скелеты, рабочая основа аналитика.
- `docs/business-problem/*.md` — kind-шаблоны слоя проблем (`frame` + 7 kind)
  — пустые скелеты.
- `docs/projects/<slug>/` реальных проектов (если уже заведены аналитиком) —
  это **данные проекта**, не витрина.
- `.claude/` (skills / rules / settings) — система наследуется форком.
- `docs/README.md`-каркас, `docs/getting-started.md` — **getting-started
  удаляется** (META, см. A.3); карта `docs/README.md` остаётся, чистятся
  только ссылки на `example/`.

## Точки входа

| вызов | поведение |
|---|---|
| `/de-template` | полный путь: Gate → Phase A → Verify |
| `/de-template status` | сводка состояния (gate, что уже сделано, что осталось) |

## Интерактив — норма, plain-чат запрещён

**Любое подтверждение / выбор — через `AskUserQuestion`.** Особенно
критично здесь: единственное необратимое действие (удаление `example/`) идёт
через явный `AskUserQuestion` после показа каскада. Никаких «удалю по
умолчанию».

- Gate-провалы → не plain «выход с ошибкой», а `AskUserQuestion` с опциями.
- Каскад в A.1 → `AskUserQuestion` «удалить `example/` (19 файлов)?»
  (Да / Нет / Показать список / Other).
- Идемпотентность (Gate.3) → `AskUserQuestion` «продолжить с фазы X /
  прогнать заново / выход».
- Сводки в чат коротко (≤8 строк) и сразу `AskUserQuestion`.

## Что делать сразу при запуске

1. Прочитать `state/de-template.md`, если есть (что уже сделано).
2. Прогнать **Gate** (см. ниже).
3. Если args = `status` — только сводка + `AskUserQuestion` «что делать?».
4. Иначе — `AskUserQuestion` «полный проход / выход», далее по фазам с
   каскадным `AskUserQuestion` на удалении.

## Gate (проверить ДО любых правок)

1. **Не канонический шаблон.**
   ```bash
   git remote get-url origin
   ```
   Если origin содержит подстроку `stit-template/project-docs-template` И
   каталог не временная тест-копия → СТОП. Запуск на каноне сносит показную
   витрину из самого шаблона. Через `AskUserQuestion` явно подтвердить: «это
   форк `<org>/docs` или throwaway-копия?». При «нет» / каноне — выйти.
   Канонический origin: `git@git.stit.tech:stit-template/project-docs-template.git`.

2. **Аналитика проекта заведена (мягкая проверка).** Под клиента обычно уже
   есть хотя бы `docs/business/` с данными и/или реальный
   `docs/projects/<slug>/` (не `example`, не `_canon`). Если репо ещё пустое
   (только скелеты + `example/`) — через `AskUserQuestion` спросить: «аналитики
   проекта ещё нет — точно де-темплейтить сейчас? (обычно сначала
   `/business-deep-dive` → … → `/cross-audit`)». Это **не** жёсткий блок:
   удаление витрины безопасно и без аналитики, но предупреждаем.

3. **Идемпотентность.** Прочитать состояние:
   - `docs/projects/example/` ещё на месте?
   - `CLAUDE.md`/`README.md` ещё помнят про «шаблон» / `example/`?

   Если что-то уже сделано — показать сводку, через `AskUserQuestion`:
   «продолжить с фазы X» / «прогнать заново» / «выход».

## Phase A — детерминированная механика

Каждый шаг — отдельный reviewable дифф. Перед удалением — **через
`AskUserQuestion` показать каскад** (что исчезнет + где на это ссылаются).

### A.1. Удалить показной продукт `example/`

- Показать каскад: `ls docs/projects/example -R` (19 файлов) + все ссылки на
  `example` в репо:
  ```bash
  grep -rln 'projects/example\|/example/\|example/screens' docs CLAUDE.md README.md
  ```
- Через `AskUserQuestion` подтвердить «удалить `docs/projects/example/`
  целиком?».
- Удалить через `git rm -r docs/projects/example`.
- Снять упоминания `example/` из текста:
  - `README.md § Структура` (строка про `example/`);
  - `docs/README.md` (строка `projects/example/` в таблице слоёв);
  - `docs/projects/README.md § Структура` (строка `example/`) + при
    необходимости § «Как читать»/anti-patterns, если ссылаются на example.
  Это **точечное переписывание**, не каскадное удаление — но прогнать grep
  ещё раз после правок, чтобы не осталось битых ссылок на `example`.

### A.2. Кастомить идентичность

Точечное переписывание (не удаление):

- `README.md` (корневой) — шапку «шаблон проекта дизайна / импортируется
  **под бизнес**» заменить на проектную («docs-репо проекта `<name>`:
  аналитика бизнеса, проблем, продуктов и интерфейса»). Имя/назначение —
  из заполненного `docs/business/profile.md` или vision реального проекта;
  если данных нет — `AskUserQuestion` спросить имя проекта. Убрать «Use this
  template», «форкается первым», блок про показную витрину `example/`.
  **Сохранить:** блок «Где это в экосистеме» (роль docs-репо в экосистеме
  остаётся фактом), воркфлоу, инварианты, карту слоёв.
- `CLAUDE.md` — интро «Этот репозиторий — **проектный шаблон**» →
  «docs-репо проекта `<name>`». Убрать упоминание `/de-template` и
  показного `example/` из блока «Где это в экосистеме» и § 6 (зона правок
  де-темплейтизации — после развёртывания не нужна). **Сохранить** роль
  design-time SoT, handoff-контракт соседям, все слои/правила/скиллы.
- `docs/README.md`, `docs/getting-started.md`, layer-README — общие; правки
  только по ссылкам на `example/` (A.1) и getting-started (A.3).

### A.3. Strip scaffolding

- `docs/getting-started.md` ([META] «путь потребителя форка») — удалить
  (`git rm`). Снять ссылку на него из `docs/README.md § Форку` и `CLAUDE.md`.
- **Оставить**: `docs/README.md` (карта), `docs/contributing`-аналога нет —
  устройство `.claude` описывает корневой `CLAUDE.md`, он остаётся.
- Каноны / kind-шаблоны / скиллы / rules — **оставить** (система и рабочая
  основа наследуются).
- Сам скилл `de-template` остаётся в `.claude/skills/` (как у соседей —
  движок наследуется; повторный запуск отсекает Gate.3 по идемпотентности).

## Verify

```bash
# example вычищен
test ! -d docs/projects/example && echo "OK: example removed"
# нет битых ссылок на example
grep -rln 'projects/example\|/example/' docs CLAUDE.md README.md && echo "STOP: остались ссылки" || echo "OK: ссылок нет"
# нет «шаблон»-нарратива в корне
grep -niE 'проектный шаблон|Use this template|импортируется под бизнес' CLAUDE.md README.md && echo "STOP: остался шаблон-нарратив" || echo "OK"
```

Все три OK + перечитать `CLAUDE.md`/`README.md` глазами на остаточный
template-язык — критерий движка.

## Память `state/de-template.md` — коммитится

Скилл-однократный, но **может прерваться**. State позволяет возобновиться без
полного прохода. Это **коммитбл артефакт** (не приватная память агента), не
попадает в `.gitignore`, ревьюится в PR.

Секции (forward-only, без «было/стало»):

- `## Текущая фаза` (a1 / a2 / a3 / verify);
- `## Открытые вопросы` (`**blocker**` для блокирующих — например имя проекта
  ещё не решено);
- `## Применённые шаги` — короткий список «a1 done, a2 done».

После Verify — `state/de-template.md` удаляется (`git rm`); онбординг закрыт.

## Запреты

- **Не запускать на каноническом шаблоне.** Gate первая защита (origin-подстрока
  `stit-template/project-docs-template`).
- **Не трогать пустые скелеты-каноны** — `docs/projects/_canon/`,
  `docs/business/*`, `docs/business-problem/*` — это рабочая основа аналитика,
  не показуха.
- **Не трогать `docs/projects/<slug>/` реальных проектов** — это данные, не
  витрина (витрина — только `example/`).
- **Не удалять без каскада.** Удаление `example/` идёт после показа каскада +
  явного подтверждения через `AskUserQuestion`.
- **Не оставлять битых ссылок** на `example` после удаления (Verify ловит).
- **Не аккумулировать журнал** в state — forward-only.
- **Коммит / push — гейт человека.** Без явной просьбы агент не коммитит
  (см. `CLAUDE.md § 5`).
