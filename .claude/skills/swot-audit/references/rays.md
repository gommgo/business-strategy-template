# Лучи проверки swot-audit

Каждый луч — отдельный угол семантической проверки инварианта методологии
LinkedSWOT. Один луч = один агент. Запускаются параллельно. Структура:
**Файлы** · **Применим если** · **Что искать** · **Промпт-добавка**.

Слой **многопроблемный**: реестр проблем — `docs/business/business-problem.md`
(одна строка = одна проблема), каждая запись `factor`/`bet` несёт колонку
`problem` (массив строк реестра, M:N). **Все лучи считают инвариант в
пределах одной проблемы**: запись с проблемой P учитывается вместе с
записями той же P, а нарушение помечается полем `problem`. Луч проходит по
каждой строке реестра отдельно (или по одной, если задан scope).

## problem-tag

**Файлы:** `factor.md`, `bet.md`, `docs/business/business-problem.md`.
**Применим если:** есть хотя бы одна запись `factor`/`bet`.

**Что искать:**
- `error`: запись `factor`/`bet` с пустым `problem` (`—`) — вне реестра,
  непонятно, какой проблемы касается.
- `error`: запись, чей `problem` ссылается на slug, которого нет в реестре
  `docs/business/business-problem.md` (несуществующая проблема).

**Промпт-добавка:**
```
У каждой записи factor/bet колонка problem — непустой массив slug-рефов на
существующие строки реестра docs/business/business-problem.md. Найди
записи с пустым problem (error) или ссылкой на отсутствующую в реестре
проблему (error). В finding укажи refs на запись.
```

## factor-usage

**Файлы:** `factor.md`, `bet.md`.
**Применим если:** есть факторы.

**Что искать:**
- `hint`: фактор, не вошедший ни в одну ставку (`bet.factors`) **ни по
  одной из своих проблем**.
- `warning`: фактор в неправильном квадранте — действие в формулировке
  (это `bet`), слабость в `threat`, угроза как внутренний дефект.

**Промпт-добавка:**
```
Стороны (strength/weakness) — про устройство бизнеса; тренды/угрозы — про
мир; любое действие — это уже bet. Проверь квадрант каждого фактора по
смыслу. Фактор может работать на несколько проблем (массив problem):
проверь, использован ли он хотя бы в одной ставке (по любой из своих
проблем); если нет вовсе — hint. В finding укажи problem(ы) фактора.
```

## bet-promotion

**Файлы:** `bet.md`, `factor.md`.
**Применим если:** есть ставки.

**Что искать:**
- `warning`: ставка не доведена до карты (`promoted-to = —`) — мёртвый
  мост.
- `warning`: ставка без баланса факторов (нет ≥1 внутреннего +
  ≥1 внешнего в `factors`).
- `error`: формат ставки не «⟨действие⟩, чтобы ⟨ценность⟩» (нет «чтобы»/
  ценности).

**Промпт-добавка:**
```
Ставка — мост SWOT→Карта гипотез. Проверь: доведена ли до goal/hypothesis
(promoted-to ссылается на сущность docs/hypothesis-map/); балансирует ли
факторы (≥1 внутренний strength/weakness + ≥1 внешний trend/threat); есть
ли «чтобы» (ценность). Перечисли нарушения, в каждом finding укажи
problem(ы) ставки.
```

## Порядок лучей

Полный прогон: `problem-tag` → `factor-usage` → `bet-promotion` (сначала
валидность привязки к проблемам, затем usage факторов и доведённость
ставок — всё per-problem).
