# Приём материалов клиента (фаза `intake`)

Бизнес-слой начинается с **сырья заказчика**: сайт, PDF, презентации,
посты в соцсетях, транскрипты интервью, отчёты. Задача intake — превратить
это в реестр источников (`material.md`) и первичных кандидатов профиля,
не теряя провенанс.

## Что приносит клиент

| тип | `material.kind` | как обрабатываем |
|---|---|---|
| сайт / лендинг | `site` | `WebFetch` страниц; вытащить чем занимаются, оферы, каналы |
| PDF / презентация | `pdf` / `deck` | `Read` файла (положить в репо/хранилище, путь в `uri`) |
| пост / профиль в соцсетях | `social` | `WebFetch`; позиционирование, тон, аудитория |
| транскрипт интервью | `interview` | `Read`; прямые факты о бизнесе, боли, метрики |
| отчёт / выгрузка | `report` | `Read`; текущие KPI → кандидаты `current-metric` |

## Шаги

1. **Завести `material`-запись** на каждый источник: `slug`, `name`,
   `kind`, `uri`, `status=draft`. Это провенанс — к нему привяжутся
   факты.
2. **Прочитать/забрать** содержимое (`Read` для файлов, `WebFetch` для
   ссылок). Не угадывать то, чего в материале нет.
3. **Извлечь кандидатов** по слоям — только **прямо названное**:
   - profile — чем бизнес занимается, как зарабатывает, позиционирование;
   - offering — что продаёт;
   - channel — как привлекает / продаёт / доставляет;
   - competitor — кого называет конкурентом;
   - current-metric — какие числа/KPI названы (с датой и источником!).

   **Сегментные зацепки** («кого обслуживает / кому продаёт») этот слой
   **не заводит** — сегменты по работам живут в `docs/ajtbd/`. Зацепки
   отметить как контекст и предложить разобрать в `/segment-deep-dive`
   (там сегмент собирается по бандлу работ, не по тому, что упомянуто в
   материале).
4. **Показать план** в чате:

   ```
   Из материалов вижу:
     profile: сеть клиник, выручка ОМС + платные
     offering: платный приём, программы чек-апов
     channel: онлайн-запись, регистратура
     current-metric: отток платных 8% (из отчёта Q1)
   Завести как черновики?
   (про клиентов — ОМС-/платные пациенты — лучше отдельно через
    /segment-deep-dive: там сегмент собирается по работам.)
   ```

5. **`AskUserQuestion`** — подтвердить/поправить через Other.
6. По подтверждению — завести **stub'ы** (минимум `slug + name +
   description + status=draft`), привязать факты к `material` через
   state-заметки «извлечено из `material:<slug>` — уточнить ⟨что⟩».
7. Предложить углубить профиль (фаза `profile`), запустить `--research`
   по рынку, или (если в материале были зацепки про клиентов) перейти в
   `/segment-deep-dive` за сегментами по работам.

## Что НЕ делать

- Не вписывать факт без `material`-источника. Каждое утверждение слоя
  прослеживается до источника.
- Не угадывать числа метрик «по рынку» — это делает research, и с
  пометкой источника.
- Не смешивать intake (материалы клиента) и `--research` (веб) в одном
  заходе — путается, что от клиента, что из веба. Сначала intake, потом
  отдельно research.
- Не выдумывать кандидатов, которых в материале нет.

## Чувствительные данные

Если материалы содержат персональные данные / коммерческую тайну — в
артефакты и state идут только **бизнес-факты**, не сами ПДн. Сами файлы
(PDF/выгрузки) — по пути в `uri`, не копировать содержимое целиком в
артефакты.
