# Web-research через рой агентов

Основной механизм наполнения `competitor.md` и подсветки рыночного
контекста для `profile` / отраслевых бенчмарков `current-metric`.
**Никогда** не запускается автоматически — только по решению аналитика.

## Когда

| фаза | повод |
|---|---|
| `market` | основной способ. Аналитик не знает наизусть рынок заказчика. |
| `profile` | проверить позиционирование, размер рынка, тренды отрасли. |
| `metrics` | отраслевые бенчмарки (типичный отток/конверсия в нише) как ориентир — но baseline берём из данных клиента, не из веба. |

## Запуск

1. Аналитик попросил research, или скилл предложил после артефакта.
2. `AskUserQuestion`:
   - **Сколько углов?** «3 — узкий», «5 — дефолт», «10 — широкая
     разведка», «15 — full sweep».
   - **Фокус** (Other) — одной фразой, что копать.
3. Скилл генерит N углов под тему.
4. Спавнит N агентов **параллельно**, все вызовы в **одном**
   message-блоке. `subagent_type: general-purpose` (WebSearch/WebFetch).
5. Ждёт всех. Каждый возвращает структурированный markdown-отчёт.
6. Сводит в `state/research/<тема>-<UTC-ts>.md` с секциями `## <угол>` +
   финальной `## Кандидаты` по kind.
7. `AskUserQuestion` по каждому кандидату: «принять в `<kind>` как
   `<slug>`» / «отбросить» / «доработать (Other)». До 4 в раунде.

## Шаблоны углов (рынок заказчика)

5 углов: (1) прямые конкуренты — тот же сегмент/офер; (2) косвенные —
другой сегмент, та же потребность; (3) субституты — как клиент решает
потребность иначе; (4) лидеры категории; (5) новые игроки за последний
год.

10: + (6) региональные/локальные игроки; (7) агрегаторы/маркетплейсы
ниши; (8) «делают руками»; (9) корпоративные in-house; (10) ушедшие с
рынка за 2-3 года (почему).

15: + отраслевые отчёты, обзоры, форумы/отзывы клиентов, сравнения,
вакансии (кто нанимает).

## Промпт для одного агента

```
Тема: <фокус аналитика>
Угол: <один из шаблонных или custom>
Слой: competitor (рынок заказчика)
Контекст бизнеса (из profile.md): <что за бизнес, сегменты, оферы>

Найди 3-7 игроков по этому углу. Для каждого:
- slug (kebab-case), name;
- one-sentence: кто это и какую позицию занимает;
- position: direct | indirect | substitute | new-entrant;
- url + 2-3 sources;
- чем давит на бизнес заказчика (наблюдаемо).

Не выдумывай. Пусто по углу → пустой список + одна фраза почему.
Наблюдаемые свойства, не маркетинг. Ответ — markdown.
```

## Что НЕ делать

- ❌ Авто-вписывать в `docs/business/`. Promotion только через
  `AskUserQuestion`.
- ❌ Терять отчёты — `state/research/<тема>-<ts>.md` остаётся.
- ❌ Брать baseline-метрики из веба как факт. Бенчмарк ≠ baseline
  клиента; baseline — из `material`/данных клиента, с источником.
- ❌ Смешивать research с intake (материалами клиента) в одном заходе.
