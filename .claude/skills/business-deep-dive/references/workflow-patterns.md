# Три режима ведения сеанса

## A. Новая сущность

**Сигнал:** args = `<kind>` или `<kind>:<новый-slug>`.

1. Прочитать `docs/business/<kind>.md` (`Критерии`, `Что НЕ`,
   `Тест-критерий`).
2. Раунд 1 `AskUserQuestion` — `name` / `description` (Other); `slug`
   скилл выводит из `name` и показывает одной строкой для контроля
   (`.claude/rules/naming.md`).
3. Записать строку, `status=draft`, прочее `—`.
4. Раунд 2+ — батч по слотам kind (`field-checklists.md`). Опции для
   enum/соседей, Other для значений.
5. Тест-критерий → чек-лист `draft-stable.md`.
6. Записать state-заметку, если есть что. Следующий шаг по `phases.md`.

## B / intake. Сырьё

**Сигнал:** args = материал клиента (текст/ссылка/путь) или «расскажу
про бизнес». Подробно — `intake.md`.

1. Завести `material`-запись (провенанс).
2. Прочитать/забрать содержимое (`Read`/`WebFetch`).
3. Извлечь кандидатов **только прямо названное** по слоям.
4. Показать план, `AskUserQuestion` — подтвердить/поправить.
5. Завести stub'ы, привязать факты к `material` через state.
6. `AskUserQuestion` — что углубить первым → режим C.

### Границы режима B

- Факт вписывается только с `material`-источником.
- Числа и значения берутся из материала; чего в нём нет, того нет и в
  кандидате.
- Кандидат появляется, только если он прямо назван; «обычно ещё бывают» —
  не основание.

## C. Углубление

**Сигнал:** args = `<kind>:<slug>`.

1. Прочитать строку + state-заметку.
2. Прочитать соседей (для offering/channel — их сегмент в
   `docs/ajtbd/segment.md`, read-only).
3. Найти дыры, anti-pattern-подозрения, открытые вопросы.
4. Раунд `AskUserQuestion` (до 4): дыры → Other; anti-pattern →
   «да/нет почему»; тупик → «связать / оставить почему».
5. Применить, обновить state, прогнать чек-лист.

## Стиль вопросов

| ситуация | формат |
|---|---|
| anti-pattern | две опции «соответствует / не (Other)» |
| enum (`offering.kind`, `channel.kind`, `competitor.position`, `material.kind`, `business-problem.served`) | по опции на значение |
| тест-критерий | опции ✅/❌ |
| выбор slug соседа | по опции на каждого + «нужен новый» |
| `from-project` (провенанс) | по опции на каждый проект `docs/projects/` + «не из проекта (`—`)» |
| запуск research | «3 / 5 / 10 / 15 агентов» / «не сейчас» |
| promotion кандидата | «принять как `<kind>:<slug>`» / «отбросить» / «доработать» |

**Только Other (значения):** `name`, `description`, `value`,
`position`-текст, числа метрик, текст проблемы и границы
(`business-problem.statement`/`guarantee`/`target`/`out-of-control`/`scope`).
Факты о бизнесе — из материалов или подтверждённого research, не догадкой
скилла. Метрика в `target` — best-effort таргет, не гарантия.

Образцы фактов от себя скилл не предлагает; в раунде — не больше 4
вопросов; сессия закрывается чек-листом хотя бы по одной записи.
