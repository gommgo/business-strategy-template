# Три режима ведения сеанса

Скилл выбирает режим по виду args.

## A. Новая сущность

**Сигнал:** args = `<kind>` или `<kind>:<новый-slug>`.

1. Прочитать `docs/swot/<kind>.md` (`Критерии <kind>`, `Что <kind> НЕ`,
   `Тест-критерий`, колонки) и `docs/swot/README.md` (форма ячеек,
   `Anti-patterns` слоя). Освежить `methodology.md`.
2. Раунд 1 `AskUserQuestion` — фундамент: `name` (Other), `description`
   (Other); `slug` скилл выводит из `name` и показывает одной строкой для
   контроля (`.claude/rules/naming.md`). Здесь же спросить
   `business-problem` (к какой проблеме(ам) относится; опции — существующие
   строки реестра `docs/business/business-problem.md` + «новая проблема»;
   M:N, можно несколько). Реестр пуст — сначала завести проблему через
   `/business-deep-dive business-problem`.
3. Записать строку со `status=draft`, `business-problem` проставлен, прочее `—`.
4. Раунд 2+ — батч по доменным слотам kind (см. `field-checklists.md`).
   До 4 вопросов. Перемежать опции (anti-patterns / enum `factor.area` /
   выбор проблемы / соседи-факторы / promoted-to) и Other (значения).
5. Ссылка на несуществующий slug → **stub** (см. SKILL.md), продолжить.
6. Чек-лист `draft-stable.md`. Все ✅ → предложить stable.
7. Записать `../entrypoint/state/swot/<kind>/<slug>.md`, если есть что.
8. Предложить следующий шаг по `phases.md`.

## B. Сырьё

**Сигнал:** args = транскрипт интервью / заметки бизнеса.

1. Прочитать материал внимательно.
2. Определить, **о какой проблеме(ах)** материал — если в реестре
   `docs/business/business-problem.md` подходящей строки нет, предложить
   завести проблему первой (через `/business-deep-dive business-problem`).
3. Извлечь кандидатов **только то, что прямо названо** (не угадывать),
   проставив каждому `business-problem`:
   - factor — что названо как сила/слабость/тренд/угроза;
   - bet — что предложено как «сделать X ради Y».
4. Показать план в чате, `AskUserQuestion` — подтвердить/поправить (в том
   числе привязку к проблеме).
5. Завести **stub'ы** с `business-problem`, создать state-заметки «извлечено из
   сырья — уточнить ⟨что⟩».
6. `AskUserQuestion` — какую углубить первой → режим C.

### Границы режима B

- Извлечённое — кандидаты, а не зафиксированные записи.
- По сырью заполняются только `name` и `description`, близко к языку
  аналитика или бизнеса; текст фактора и ставки добывается в режиме C.
- Кандидат появляется, только если он есть в материале.
- У каждого кандидата есть `business-problem`; если проблема неясна —
  вопрос аналитику.

## C. Углубление

**Сигнал:** args = `<kind>:<slug>` существующей записи.

1. Прочитать строку + `../entrypoint/state/swot/<kind>/<slug>.md`. Отметить
   её `business-problem` — все проверки соседей идут в пределах этих проблем.
2. Прочитать соседей семантически **в пределах проблем записи** (для
   `bet` — её `factors`; для `factor` — какие ставки её используют).
3. Найти: пустой/невалидный `business-problem`; пустые обязательные слоты;
   подозрения по anti-patterns; методологические тупики (ставка-висяк,
   баланс факторов, фактор без ставки, неправильный квадрант).
4. Раунд `AskUserQuestion` (до 4): дыры → Other; anti-pattern → «да/нет
   почему»; тупик → «связать с ⟨варианты⟩ / оставить, потому что Other».
5. Применить ответы; обновить state.
6. Чек-лист `draft-stable.md`. Все ✅ → предложить stable.

## Стиль вопросов

### Когда давать опции

| ситуация | формат |
|---|---|
| anti-pattern | две опции «соответствует / не соответствует (Other почему)» |
| enum (`factor.area`) | по опции на значение |
| привязка к проблеме (`business-problem`) | по опции на каждую строку реестра (можно несколько) + «новая проблема» (Other) |
| выбор фактора для `bet.factors` | по опции на каждого + «нужен новый» (Other) |
| `bet.promoted-to` | «цель `goal:<slug>`» / «гипотеза `hypothesis:<slug>`» (из `docs/hypothesis-map/`) / «ещё нет — stub» |

### Когда только Other (значения)

`name`, `description`, текст фактора по шаблону квадранта, ставка
«⟨действие⟩, чтобы ⟨ценность⟩». Это экспертиза бизнеса (`CLAUDE.md` §3):
формулировку даёт аналитик. `slug` новой записи не спрашивается — скилл
выводит его из `name`.

### Чего избегать

- Образцов доменных формулировок от себя: примеры в каноне — иллюстрация,
  не варианты для текущего проекта.
- Больше 4 вопросов в одном раунде.
- Закрытия сессии без чек-листа хотя бы по одной правленой сущности.
