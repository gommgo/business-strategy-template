# 3 фазы LinkedSWOT

Скилл ведёт аналитика по фазам как по карте: всегда видно, где мы, что
закрыто. **Порядок — рекомендация, не закон.** Порядок следует методологии:
`factors` → `bets` → `cohesion`. Строим **набегающей волной** — неточно,
потом уточняем.

Слой **многопроблемный**: реестр проблем — `docs/business/business-problem.md`.
Фазы считаются **в пределах одной проблемы**: сначала выбираем, по какой
идём, потом смотрим её факторы и ставки. Каждая заводимая запись тегируется
проблемой(ами) через `business-problem` (массив строк реестра, M:N).

## Карта фаз

### 1. `factors` — факторы LinkedSWOT

**Триггер:** нет факторов с выбранной проблемой в `business-problem`.

**Цель:** собрать факторы из картины бизнеса (`docs/business/`) по 4
квадрантам, тегируя каждый проблемой(ами).

**Что копать:**
- Факторы по 4 областям: сильные/слабые (про устройство бизнеса),
  тренды/угрозы (про мир). Формулировка по шаблону квадранта. К какой
  проблеме(ам) фактор относится (`business-problem`) — один фактор бизнеса часто
  общий для нескольких проблем.

**Подтянуть доказательства из AJTBD (read-only).** Прежде чем спрашивать
факторы, заглянуть в `docs/ajtbd/` (read-only):
- `segment-problem` — трения клиента с нанятыми решениями (`strength`
  1–10). Сильное трение при низкой `satisfaction`/`price-value-fit`
  соответствующего `solution` — это **доказательство** SWOT-фактора
  (часто `weakness`/`threat`).
- Это **не** проблема бизнеса (`business/business-problem`), а трение
  **клиента**. Перенос смысла трения в фактор — через `AskUserQuestion`,
  не автозаливом. Нет данных AJTBD — спросить аналитика, а при углублении
  подсказать `/segment-deep-dive` / `/job-graph-deep-dive`.

**Анти-паттерны:** действие в формулировке фактора (это `bet`); слабость в
графе угроз; фактор без `business-problem`; фактор без опоры на трения клиента,
когда AJTBD-данные есть.

**Переходы после:** `bets` — перебрать пары факторов проблемы в ставки.

### 2. `bets` — стратегические ставки

**Триггер:** есть факторы, нет ставок.

**Цель:** из пар факторов (≥1 внутренний + ≥1 внешний) родить ставки
«⟨действие⟩, чтобы ⟨ценность⟩».

**Что копать:** приём «если сила A, а тренд B — как A раскрыть в условиях
B». Баланс лево/право. Куда ставка доводится (`promoted-to` — `goal` или
`hypothesis` слоя `docs/hypothesis-map/`).

**Анти-паттерны:** ставка без опоры на факторы; только внутренние / только
внешние; ставка-фича без «чтобы».

**Переходы после:** `cohesion`; приоритетную ставку довести до цели в
`/hypothesis-map-deep-dive`.

### 3. `cohesion` — целостность

**Триггер:** факторы и ставки проблемы заполнены, фокус — целостность её
SWOT.

**Цель:** проверить инварианты методологии **в пределах проблемы** (баланс
факторов ставки, доведённость `promoted-to`, фактор без ставки), повысить
проходящие чек-лист записи `draft → stable`, предложить `/swot-audit` и
передать ставки в Карту гипотез (`/hypothesis-map-deep-dive`).

**Анти-паттерны:** принудительный stable у незрелых; ставка-висяк
(`promoted-to = —`) при stable; фактор, не вошедший ни в одну ставку.

## Сводка фаз для UI

Сводка — **по выбранной проблеме**; для остальных проблем даём строку
«закрыта / в работе».

```
Проблема: paid-outflow (1 из 2)
Фазы:
  ✅ factors     — 6 факторов
  🔄 bets        — 2 ставки (1 draft, текущая)
  ⏳ cohesion

Прочие проблемы:
  🔄 slow-onboarding — в работе (фаза factors)
```

✅ — закрыта (≥1 stable, нет blocker); 🔄 — текущая; ⏳ — не начата.

## Перепрыгивание

SWOT — рекомендуемый, не обязательный вход. Если бизнес принёс ясную ставку
без разложенных факторов — `AskUserQuestion`: «Записать ставку, до-насытив
факторы позже — почему сейчас?». Скилл напоминает: без факторов ставка
может оказаться необоснованной — стоит вернуться и до-насытить. Ответ →
`../entrypoint/state/swot/bet/_phase-jump.md` как доменное решение.
