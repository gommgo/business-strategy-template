# Чек-лист `draft → stable`

После каждой правки скилл прогоняет пункты. Все ✅ → предлагает аналитику
повысить через `AskUserQuestion`. **Не повышает сам.**

## Пункты

1. **Обязательные слоты заполнены** (см. `field-checklists.md`).
   Опциональные могут быть `—`. `factor` — `business-problem`/`area`/формулировка;
   `bet` — `business-problem`/`factors`/`promoted-to`/форма «действие, чтобы
   ценность». Для обоих kind — **непустой `business-problem`** (массив строк
   реестра проблем).
2. **`Критерии <kind>` пройдены** — каждый критерий из
   `docs/swot/<kind>.md` явно подтверждён аналитиком через
   `AskUserQuestion` (не «скилл уверен», а «аналитик нажал ✅»).
3. **Anti-patterns не нарушены** (`Что <kind> НЕ` в `docs/swot/<kind>.md`
   и `Anti-patterns` README слоя) — по каждому скилл спросил «не похоже
   ли?» и получил ❌. Один подтверждённый anti-pattern блокирует stable до
   переформулировки.
4. **Нет `**blocker**`-вопросов** в `../entrypoint/state/swot/<kind>/<slug>.md`.

Все ✅ → `AskUserQuestion`: «Запись `<kind>:<slug>` прошла чек-лист.
Повышаем `draft → stable`?» (Да / Нет, ещё подумаю / Да, но сначала закрою:
Other). По «да» — `status: draft → stable`.

## Особое для этого слоя

- Любая запись не становится stable без непустого `business-problem` (массив
  существующих строк реестра `docs/business/business-problem.md`).
- **Ставка** не становится stable, если `factors` не балансирует ≥1
  внутренний (`strength`/`weakness`) + ≥1 внешний (`trend`/`threat`), или
  `promoted-to` не доведена до `goal`/`hypothesis`, или нет «чтобы».
- **Фактор** не становится stable в неправильном квадранте (действие — это
  `bet`, не factor).

## Понижение `stable → draft`

Скилл **сам не понижает**. Подсвечивает («запись stable, но критерий X
нарушен / появился `**blocker**` / соседняя запись удалена») и через
`AskUserQuestion` предлагает понизить. Только по «да» — меняет status.

## Когда чек-лист нельзя пройти — это нормально

Ставка может проектно не дойти до stable (нужно решение бизнеса, не
готова цель в Карте гипотез). Не «натягивать» stable: закрыть запись
`draft`, оставить `**blocker**` в state, предложить следующий шаг по
`phases.md`. Stable-запись, ссылающаяся на draft, — допустимо.
