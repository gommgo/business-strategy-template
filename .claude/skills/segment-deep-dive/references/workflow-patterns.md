# Три режима ведения сеанса

## A. Новая сущность

**Сигнал:** args = `segment` или `segment:<новый-slug>`.

1. Прочитать `docs/ajtbd/segment.md` (`Критерии segment`, «Что segment
   НЕ», `Тест-критерий`).
2. Раунд 1 `AskUserQuestion` — `slug` / `name` / `description` (Other) +
   `kind` (`b2b`/`b2c` — опции). От `kind` ветвится дальнейший разбор
   (`methodology.md`).
3. Записать строку, `status=draft`, прочее `—`.
4. Раунд 2+ — батч по слотам (`field-checklists.md`): `who-context`,
   бандл (`core-jobs` + `big-job` как гипотезы → stub'ы в `job.md`),
   `success-criteria`, компоненты Score, `sizing`. Опции для enum/соседей,
   Other для значений (не выдумывать формулировки).
5. Тест-критерий → чек-лист `draft-stable.md`.
6. Записать state-заметку, если есть что. Следующий шаг по `phases.md`.

## B / intake. Сырьё

**Сигнал:** args = материал клиента (текст/ссылка/путь) или транскрипт
из `jtbd-interview`. Подробно — `intake.md`.

1. Зафиксировать провенанс в `state/`.
2. Прочитать/забрать содержимое (`Read`/`WebFetch`).
3. Извлечь кандидатов в сегменты/работы — **только прямо названное /
   прямо сделанное**.
4. Показать план, `AskUserQuestion` — подтвердить/поправить + спросить
   `kind` каждого кандидата.
5. Завести stub'ы (сегмент в `segment.md`, гипотезы работ в `job.md`),
   привязать факты к источнику через state.
6. `AskUserQuestion` — что углубить первым → режим C, либо `--research`.

### Что НЕ делать в B

- Не вписывать факт без источника.
- Не путать мнение/гипотетику с работой (работа — прошлые действия).
- Не выдумывать кандидатов «обычно ещё бывают».
- Не строить граф работ — только гипотезы-узлы.

## C. Углубление

**Сигнал:** args = `<slug>` или `segment:<slug>`.

1. Прочитать строку сегмента + state-заметку + его stub-работы из
   `job.md`.
2. Прочитать соседей по контексту (research-отчёты с этим сегментом).
3. Найти дыры (пустой бандл, нет одной Big Job, нет компонентов Score),
   anti-pattern-подозрения (демография? несколько Big Job?), открытые
   вопросы.
4. Раунд `AskUserQuestion` (до 4): дыры → Other; anti-pattern → «да/нет
   почему»; недостающий компонент Score → значение из research/Other.
5. Применить, обновить state, прогнать чек-лист `draft → stable`.

## Стиль вопросов

| ситуация | формат |
|---|---|
| anti-pattern («Что segment НЕ») | две опции «соответствует / не (Other)» |
| enum `segment.kind` | опции `b2b` / `b2c` |
| тест-критерий | опции ✅/❌ |
| выбор существующей работы для бандла | по опции на каждую + «новая (stub)» |
| запуск волны роя | «5 / 7 / 10 углов» / «не сейчас» |
| после волны | «ещё волна (дыры: …)» / «полнота, в кластеризацию» |
| promotion кандидата | «принять как `segment:<slug>`» / «отбросить» / «доработать» |
| отбраковка НЕ-сегмента | «отбраковать (почему — Other)» / «оставить как сегмент» |

**Только Other (значения):** `name`, `description`, `who-context`,
`success-criteria`, тексты гипотез работ, оценки компонентов Score,
`sizing`. Формулировки сегментов/работ/критериев — из research/интервью,
**не выдумывать** (`CLAUDE.md` §3).

**Не делать:** не предлагать образцы фактов от себя; не более 4 вопросов
в раунде; не закрывать сессию без чек-листа хотя бы по одной записи.
