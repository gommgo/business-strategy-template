# Многоволновой web-research через рой агентов

**Ключевая особенность слоя.** Поиск сегмента в AJTBD — итерационный
процесс: гипотеза работы → разведка → кластеризация → пересев гипотез →
снова разведка, пока **две итерации подряд не принесли ни одной новой
работы/сегмента** (норматив полноты). Здесь итерация = **волна** роя
web-research. **Никогда** не запускается автоматически — только по
решению аналитика.

Реализация — **внутри-скиловый рой через инструмент Agent**
(параллельные вызовы в одном message-блоке), **не через Workflow**.

## Цикл волн

```
┌──────────────────────────────────────────────────────────────┐
│  ВОЛНА N                                                       │
│  1. Сформировать 5–10 углов под текущие гипотезы и ДЫРЫ        │
│  2. Спавн N агентов ПАРАЛЛЕЛЬНО (один message-блок)            │
│  3. Дождаться всех → свести отчёт в state/research/<тема>-<ts> │
│  4. Кластеризовать находки: новые сегменты? новые работы?      │
│  5. Зафиксировать ДЫРЫ и НОВЫЕ ЗАЦЕПКИ (чем сеять волну N+1)   │
│                                                                │
│  Решение (AskUserQuestion):                                    │
│   • есть новые сегменты/работы или дыры → ВОЛНА N+1            │
│     (засевается дырами + зацепками предыдущей)                 │
│   • ДВЕ волны подряд без новых сегментов/работ → СТОП,        │
│     полнота достигнута → фаза cluster                          │
└──────────────────────────────────────────────────────────────┘
```

**Счётчик полноты.** В `state/research/`-сводке держать строку «волна N:
новых сегментов X, новых работ Y». Две подряд с X=0 и Y=0 → полнота.

## Запуск волны

1. Аналитик попросил research, или скилл предложил после гипотез.
2. `AskUserQuestion`:
   - **Сколько углов в волне?** «5 — дефолт», «7», «10 — широкая
     разведка».
   - **Фокус волны** (Other) — что копать (для первой — гипотезы; для
     следующих скилл предлагает дыры предыдущей как дефолт).
3. Скилл генерит N углов под тему и `kind` (B2B/B2C — разные шаблоны
   ниже).
4. Спавнит N агентов **параллельно**, все вызовы — в **одном**
   message-блоке. Инструмент **Agent**, `subagent_type: general-purpose`
   (WebSearch/WebFetch).
5. Ждёт всех. Каждый возвращает структурированный markdown-отчёт.
6. Сводит в `state/research/<тема>-<UTC-ts>.md`: секции `## <угол>` +
   финальные `## Кандидаты в сегменты`, `## Кандидаты в работы`,
   `## Дыры и зацепки для следующей волны`, строка счётчика полноты.
7. **Кластеризация** находок волны (см. `methodology.md`): группировка по
   бандлу работ + критериям успеха, дифференциация, отбраковка
   НЕ-сегментов с «почему».
8. `AskUserQuestion`: «гнать волну N+1 (дыры: …)» / «полнота, в
   кластеризацию» / promotion отдельных кандидатов в `segment.md`/`job.md`
   как stub'ы.

## Шаблоны углов

Засевается **гипотезами работ** (широкими), а не продуктами. Логика
AJTBD: ищем тех, кто выполняет работу **часто и много платит** — там
сильнейший мотив и ярчайшие проблемы.

**B2C-волна (5 углов):** (1) кто выполняет работу-гипотезу максимально
часто; (2) кто платит за неё больше всего; (3) какие решения нанимают
сейчас и насколько довольны; (4) соседние сегменты с той же работой, но
**другими критериями успеха**; (5) неожиданные/нишевые группы с той же
работой (антипаттерн — тоннелинг на одну гипотезу).

**B2C 7–10:** + (6) спящие работы (есть, но не выполняются из-за высокого
Cost); (7) предыдущие последовательные работы (маркетинговая воронка);
(8) высокоуровневая работа («чтобы что?») и кто ещё на неё целится;
(9) форумы/отзывы — где жалуются на текущие решения; (10) выросшие за
последний год запросы/тренды по работе.

**B2B-волна (5 углов):** (1) компании-контексты, где бизнес-работа острее
всего; (2) **роли сделки** (ЛПР/ЛВР/держатель бюджета/end-user) и их
**личные работы** (job security, статус, рост позиции — 90% мотивации
ЛПРа); (3) какие решения внедряют сейчас и удовлетворённость;
(4) соседние индустрии с той же бизнес-работой; (5) кто блокирует сделки
(саботажники/безопасники) и почему.

**B2B 7–10:** + (6) триггеры покупки (что в компании запускает поиск);
(7) цикл и сложность сделки; (8) in-house-решения («делают сами»);
(9) отраслевые отчёты/кейсы внедрений; (10) вакансии (кто нанимает под
эту работу — сигнал спроса).

## Промпт для одного агента

```
Тема: <фокус волны>
Угол: <один из шаблонных или custom>
kind: b2b | b2c
Слой: сегменты AJTBD (поиск known-unknown по работам, не по демографии)
Контекст бизнеса (из docs/business/ + гипотезы): <профиль, гипотезы работ>

Найди по этому углу группы людей/компаний, объединённые ОБЩЕЙ РАБОТОЙ.
Для каждой:
- предв. slug (kebab-case), name;
- one-sentence: кто это, по какому контексту/работе объединены;
- big-job (гипотеза верхней мотивации) + 1–4 core-jobs (за что платят);
- success-criteria: по чему судят «достаточно хорошо»;
- текущее решение и удовлетворённость им (X/10, если наблюдаемо);
- сигналы важности/частотности/размера (затраты времени/денег, объём);
- [b2b] роли сделки и личные работы сотрудника, если видно;
- url + 2-3 sources.

Не выдумывай. Демография без бандла работ — НЕ сегмент, не давай.
Пусто по углу → пустой список + одна фраза почему. Ответ — markdown.
```

## Что НЕ делать

- ❌ Одна волна и стоп. Полнота — две волны подряд без новых работ.
- ❌ Авто-вписывать в `docs/ajtbd/`. Promotion только через
  `AskUserQuestion`.
- ❌ Терять отчёты — `state/research/<тема>-<ts>.md` остаётся (исходник
  для повторного захода, не удаляется после promotion).
- ❌ Демография как находка («женщины 25–35») — отбраковывать, требовать
  бандл работ.
- ❌ Засевать следующую волну тем же фокусом — сеять **дырами и новыми
  зацепками** предыдущей.
- ❌ Смешивать research с intake (сырьём клиента/интервью) в одном заходе.
- ❌ Реализовывать рой через Workflow — только внутри-скиловый рой через
  Agent.
