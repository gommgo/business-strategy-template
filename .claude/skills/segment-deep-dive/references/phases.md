# Фазы поиска сегмента

Слой строгий (своя методология AJTBD), но разведочный: ищем *known
unknown*. Порядок — итерационный, набегающей волной (широко → уточняем).
Карта помогает не пропустить блок.

### 1. `intake` — приём сырья

**Триггер:** нет материалов и нет гипотез, или клиент/аналитик принёс
материалы либо транскрипты из `jtbd-interview`.
**Цель:** превратить сырьё в первичных кандидатов сегментов/работ, не
теряя провенанс. См. `intake.md`.
**Что копать:** прямо названные группы клиентов, их работы, текущие
решения, затраты времени/денег (единственный внешний сигнал о наличии
работы).
**Анти-паттерны:** вписывать факт без источника; угадывать кандидатов,
которых в материале нет.
**Переход:** `hypotheses`.

### 2. `hypotheses` — широкие гипотезы сегментов

**Триггер:** есть контекст бизнеса (профиль из `business`) и/или сырьё.
**Цель:** **7–10 широких высокоуровневых гипотез сегментов** по бандлам
работ — такого уровня, где наше возможное решение было бы одним из
доминирующих. Гипотеза работы — стартовая точка, не истина.
**Что копать:** для каждой гипотезы — `kind` (`b2b`/`b2c`), грубый бандл
работ (1–4 Core + одна Big), кто в нём по контексту/работам.
**Анти-паттерны:** демография как гипотеза («все, кто хочет похудеть»);
влюблённость в одну гипотезу (тоннелинг — пропустим крупные сегменты
рядом); конкретная узкая гипотеза вместо широкой.
**Переход:** `research` (рой проверяет и расширяет гипотезы).

### 3. `research` — многоволновой рой

**Триггер:** гипотезы есть, нужна внешняя проверка и расширение.
**Цель:** наполнить картину **многоволновым роем web-research** до нормы
полноты. См. `research-waves.md`. Волна 5–10 углов → кластеризация →
следующая волна засевается дырами → стоп, когда **две волны подряд не
дали новых сегментов/работ**.
**Что копать:** кто выполняет работу часто и много платит; какие решения
нанимают; удовлетворённость; неожиданные сегменты рядом.
**Анти-паттерны:** одна волна и стоп; автозалив без подтверждения;
смешивать research с intake в одном заходе.
**Переход:** `cluster`.

### 4. `cluster` — кластеризация в сегменты

**Триггер:** находки роя/интервью накоплены.
**Цель:** сгруппировать находки в **сегменты** (по схожести бандла работ
и критериев успеха), **дифференцировать** сегменты между собой,
**отбраковать НЕ-сегменты** с фиксацией **почему** (критично для
фильтрации следующих волн).
**Что копать:** одна Core Job при разных критериях успеха = разные
сегменты; различимый воспроизводимый признак, не «все подряд».
**Анти-паттерны:** «все клиенты» как один сегмент; сегмент без Big Job
или с несколькими; отбраковка без зафиксированного «почему».
**Переход:** `score`.

### 5. `score` — скоринг и выбор

**Триггер:** сегменты выделены и дифференцированы.
**Цель:** для каждого сегмента — `score` = важность × частотность ×
размер × (10 − удовлетворённость). Применить внутренние фильтры (можем ли
сделать значимо ценнее · стоимость · стратегия), **выбрать 1–2 сегмента**
для углубления. Из 5–10 обычно остаётся 2–4.
**Что копать:** компоненты Score прослеживаются к research/интервью, не
выдуманы; стартап приоритизирует низкую удовлетворённость, корпорация —
размер (`methodology.md`).
**Анти-паттерны:** Score «на глаз»; выбор по размеру без учёта
удовлетворённости (для стартапа).
**Переход:** `cohesion`.

### 6. `cohesion` — целостность и передача

**Триггер:** выбранные сегменты имеют Score.
**Цель:** связность слоя; повышение draft → stable выбранных сегментов;
передача в `job-graph-deep-dive` (граф работ выбранного сегмента) и
вверх/вниз (трения → `business-problem`; механики → `project`).
**Что копать:** каждый компонент Score и бандл прослеживается до
research/транскрипта; у каждого выбранного сегмента есть ровно одна Big
Job и ≥1 Core Job (stub'ы в `job.md`); нет «висящих» сегментов без
бандла.

## Перепрыгивание

Порядок — рекомендация. Если профиль бизнеса уже даёт ясную гипотезу
сегмента — можно стартовать с `hypotheses` или даже завести `segment`
вручную (режим A), но скилл через `AskUserQuestion` спросит «на чём
держится бандл?» и предложит до-насытить research позже.

## Сводка фаз для UI

```
Фазы:
  ✅ intake      — 3 источника + 2 транскрипта
  ✅ hypotheses  — 8 гипотез сегментов
  🔄 research    — волна 2/? (текущая; 1 новый сегмент за волну)
  ⏳ cluster
  ⏳ score
  ⏳ cohesion
```
