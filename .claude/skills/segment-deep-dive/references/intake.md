# Приём сырья (фаза `intake`)

Слой начинается с **сырья**: материалы клиента (сайт, PDF, презентации,
посты) и/или **транскрипты JTBD-интервью** из `/jtbd-interview` (лежат в
`state/` соседнего скилла как готовые конспекты + кандидаты). Задача
intake — превратить это в первичных кандидатов сегментов и гипотез работ,
не теряя провенанс.

JTBD напоминает: работа живёт в психике, напрямую не видна. Единственная
зацепка — **действия** (затраты времени / денег / энергии), не мнения и
не гипотетика. Поэтому из сырья тащим то, **что человек уже делал**, не
«хотел бы».

## Что приносит сырьё

| тип | как обрабатываем | что тащим |
|---|---|---|
| сайт / лендинг | `WebFetch` страниц | кого называют клиентом, какие работы решают, какие решения упоминают |
| PDF / презентация | `Read` (путь в state-провенанс) | сегменты, оферы, текущие решения рынка |
| транскрипт JTBD-интервью | `Read` из `state/` (`jtbd-interview`) | целевая работа · работа выше уровнем · предыдущие работы · решение · удовлетворённость · затраты |
| отчёт / выгрузка | `Read` | размеры аудиторий, частотность, текущие решения |

## Шаги

1. **Зафиксировать провенанс** в `state/` — на каждый источник заметка с
   `ref`/`uri`, чтобы к нему привязались факты. Чувствительные данные
   (ПДн, тайна) — в state идут только бизнес-факты, не сами данные.
2. **Прочитать/забрать** содержимое (`Read` для файлов и транскриптов,
   `WebFetch` для ссылок). Не угадывать то, чего в материале нет.
3. **Извлечь кандидатов** — только **прямо названное / прямо сделанное**:
   - кандидаты в **сегменты** — группы, объединённые общей работой (не
     демографией);
   - кандидаты в **работы** (`when` → `want` → `so-that`), доказанные
     прошлым поведением;
   - текущие **решения** и **удовлетворённость** ими (вход в Score);
   - **затраты** (время/деньги/энергия) — сигнал важности и частотности.
4. **Показать план** в чате:

   ```
   Из сырья вижу:
     сегмент?: дачники-новички   (когда промокли в прошлый раз)
       big-job?: комфортно проводить выходные на природе
       core-job?: купить экипировку
       решение сейчас: no-name дождевик, удовлетворённость ~3/10
     сегмент?: опытные походники   (другие критерии успеха — вес, слои)
   Завести как гипотезы-черновики?
   ```

5. **`AskUserQuestion`** — подтвердить/поправить через Other; для каждого
   кандидата спросить `kind` (`b2b`/`b2c`).
6. По подтверждению — завести **stub'ы**: сегмент в `segment.md`
   (`slug + name + description + kind + status=draft`, прочее `—`),
   гипотезы работ в `job.md` (`slug + name + when/want/so-that как
   гипотеза + segment + level + status=draft`). Привязать факты к
   источнику через state-заметки «извлечено из `<источник>` — уточнить
   ⟨что⟩».
7. Предложить следующий шаг: фаза `hypotheses` (добить до 7–10 широких
   гипотез) или `--research` (рой проверит/расширит).

## Что НЕ делать

- Не вписывать факт без источника. Каждое утверждение прослеживается до
  материала или транскрипта.
- Не угадывать числа Score «по рынку» — это делает research, с пометкой
  источника.
- Не путать **мнение/гипотетику** с работой. Работа доказывается прошлыми
  действиями.
- Не смешивать intake (сырьё клиента/интервью) и `--research` (веб) в
  одном заходе — путается, что откуда. Сначала intake, потом отдельно
  research.
- Не выдумывать кандидатов, которых в сырье нет («обычно ещё бывают»).
- Не строить граф работ — здесь только первичные гипотезы-узлы; рёбра,
  CPR, типы, механики делает `/job-graph-deep-dive`.
