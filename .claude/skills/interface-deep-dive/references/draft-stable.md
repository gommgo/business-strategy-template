# Контракт `draft → stable`

Запись становится `stable`, когда **все пять пунктов одновременно** ✅: скилл проверяет, аналитик подтверждает, скилл
применяет. По stable-записям interface работают экраны, FSD-карта, карта мобильного приложения и диалоги бота, поэтому
повышение — слово аналитика, а не вывод скилла.

## Чек-лист

### 1. Обязательные слоты заполнены

Опциональные могут быть `—`, остальные — непусты: у ссылки — реф, у свободного текста — фраза. Что обязательно у каждого
kind — `field-checklists.md`. Особо:

- **situation** — при `stable` названа `frequency`; у ситуации, которую разыгрывает экран поверхности, — `refusals`
  (ключи отказов или `—` «отказов нет»).
- **scenario** — обязательные поля мета-блока; непусты «Happy path», «Ветвления», «Ошибки», «Конечные состояния» с «что
  дальше» у каждого исхода, «Что меняется», «Приёмка»; при двух и больше участниках — «Чей ход».
- **zone** — `order` и `object` названы (прочерк у них — решение, а не пропуск).
- **data-items** — `object` назван (прочерк — датум вне модели объектов).

### 2. Все ссылки валидны

Каждый slug в ячейке существует как запись соседнего файла **той же поверхности** (`interface/<surface>/`); ссылка в
сущность другой поверхности недопустима.

- `situation.stage` → `stage.md`; `situation.who` → `who.md`; `situation.entry-data`, `exit-data` → `data-items.md`;
  `situation.ux-substrate` → `ux-substrate.md` (зеркало); `situation.block` → `block.md` (зеркало);
- `situation.refusals` → ключи словаря состояний экрана из перечня колонки формы `situation.md`;
- `block.zone` → `zone.md`; `block.who` → `who.md`; `block.ux-substrates` → `ux-substrate.md`;
  `block.transition-to-block` → `block.md`; `block.transition-from-zone` → `zone.md`;
- `zone.parent-zone` → `zone.md`; `ux-substrate.situation` → `situation.md`;
- `scenario.who` → `who.md`; шаги «Happy path» и цели ветвлений → `situation.md` (или шаг этого сценария); ключи
  «Ошибок» → словарь состояний экрана;
- наверх, в продуктовый слой того же проекта: `scenario.capability` → возможность **этой поверхности** в
  `capability/<surface>.md`; `zone.object` → объект `object.md`; `data-items.object` → объект или атрибут `object.md`;
  объекты и статусы «Что меняется» сценария → `object.md`.

Остальные рёбра наружу — `who.users`, `situation.capabilities`, `situation.jobs`, `situation.hypotheses` —
семантические: их сверяет `/cross-audit`, а не этот чек-лист. `stable` может ссылаться на `draft`: аудит подсветит
подсказку, но не блокирует.

### 3. Зеркала консистентны (только у `situation`)

Канонические источники — `ux-substrate.situation` (M:1) и `block.ux-substrates` (M:N). Производные поля ситуации:

- `situation.ux-substrate` — набор всех `ux-substrate.slug`, у которых `ux-substrate.situation` — эта ситуация;
- `situation.block` — набор всех `block.slug`, у которых `block.ux-substrates` пересекается с `situation.ux-substrate`.

Скилл держит зеркала синхронными автоматически после каждой правки канонических источников.

### 4. Тест-критерий явно подтверждён

У формы kind есть секция `Тест-критерий` с примерами ✅/❌. Скилл предъявляет их через `AskUserQuestion` и спрашивает,
какой пример ближе к записи. Запись проходит, когда аналитик соотносит её с ✅-примером и явно подтверждает.

### 5. В заметке нет `**blocker**`-вопросов

Заметка — `../entrypoint/state/projects/<project-slug>/interface/<surface>/<kind>/<slug>.md`. В ней нет секции
`## Открытые вопросы` или в секции нет вопросов с пометкой `**blocker**`. Не-blocker вопросы при stable допустимы — они
о том, что хорошо бы узнать, а не о том, что смысл сломан. `## Доменные решения` к stable не относится;
`## Что копать дальше` к stable обычно пуст.

## Алгоритм проверки

После любой правки записи:

1. Прочитать запись и её заметку, если есть.
2. Прогнать пункты 1–3 и 5 — они проверяются по файлам.
3. Все четыре ✅ — раунд `AskUserQuestion` по тест-критерию (пункт 4).
4. Пункт 4 ✅ — «Готов к stable, повышаем?» — «Да, повысить» / «Нет, ещё не уверен» (что смущает — Other).
5. «Да» — сменить `status: draft → stable` (у сценария — поле `status` мета-блока).

## Чего не делать

- **Не повышать сам**, без подтверждения аналитика, даже если все пять пунктов ✅.
- **Не понижать `stable → draft` сам** при найденной проблеме — это смысловое решение аналитика; скилл подсвечивает и
  предлагает. Stable-запись, которая не проходит форму слоя, при приведении к канону тоже не понижается: пустой
  обязательный слот — находка `/interface-audit` и строка списка работ (`workflow-patterns.md § Привести к канону`).
- **Не считать пункт 4 пройденным по умолчанию**, потому что слоты заполнены: тест-критерий — отдельное смысловое
  подтверждение.
- **Не игнорировать `**blocker**`-вопросы** — до stable они закрываются или удаляются, если стали неактуальны.
