# Формат заметки `state/<project-slug>/<kind>/<slug>.md`

Память скилла — рабочее состояние знания о сущности. Не журнал.

Заметки лежат **рядом со скиллом**, не в
`docs/projects/<project-slug>/interface/` и не в корне проекта, и
скоупятся по проекту:

```
.claude/skills/interface-deep-dive/state/<project-slug>/<kind>/<slug>.md
```

Дальше по тексту — короткое `state/`, это сокращение того же пути
(с учётом текущего `<project-slug>`).

## Шаблон

```markdown
---
kind: situation
slug: submit-referral
ref: docs/projects/<project-slug>/interface/situation.md#submit-referral
---

## Открытые вопросы
- Чем именно отправляется направление — email / API / печать?
- Можно ли сохранять черновики? (**blocker**)

## Доменные решения
- goal = «передать пациента», не «отправить документ» — смысл шага
  в передаче ответственности, не в технике канала.

## Что копать дальше
- Раскрыть using-what в субстраты, когда прояснится канал.
```

## Frontmatter

| ключ | значение | назначение |
|---|---|---|
| `kind` | один из 7 | избыточная подсказка читателю + быстрый фильтр |
| `slug` | равен `slug` записи в таблице | связь с артефактом |
| `ref` | `docs/projects/<project-slug>/interface/<kind>.md#<slug>` | удобная ссылка в редакторе |

## Секции

Все три опциональны. Любая отсутствует, если содержимого нет.

### `## Открытые вопросы`

Список незакрытых смысловых вопросов. Каждый — одна строка списка.

- Префикс `**blocker:**` ИЛИ суффикс `(**blocker**)` — вопрос блокирует
  переход `draft → stable`. Без префикса/суффикса — открытый, но не
  блокирующий.
- Закрытый вопрос **удаляется** из секции (не зачёркивается, не
  переносится в «решено»). Если стало пусто — удалить всю секцию.

### `## Доменные решения`

Список неочевидных смысловых решений, которые не помещаются в ячейку
`description` записи, но важны для будущих сессий.

- Одна строка списка = одно решение.
- Форма: «<что выбрано> — <почему>». Без «было X, стало Y», без дат,
  без отсылки к прошлым попыткам.
- Если решение уже растворилось в `description` записи — удалить отсюда
  (не дублировать).

### `## Что копать дальше`

Список локальных «следующих шагов» по этой сущности.

- Не путать с открытыми вопросами: «копать дальше» — задача аналитика;
  «открытый вопрос» — конкретный неясный смысл.
- При выполнении шага — удалить строку. Если стало пусто — удалить
  секцию.

## Правила жизненного цикла

- **Создаётся** только когда есть что записать (хотя бы одна
  непустая секция).
- **Перезаписывается** свободно — это рабочее состояние.
- **Удаляется**:
  - Все три секции пустые → удалить файл целиком.
  - Запись в артефакте удалена (каскад) → удалить файл.
- **Не аккумулировать** журнал: после правок строк «было/стало», дат,
  «решено такого-то», «обсуждено» — не должно быть.

## Что НЕ хранить в заметке

- Историю изменений (это git).
- Журнал сессий «над чем работали такого-то числа».
- Дубликаты содержимого таблицы (slug → таблица, name → таблица,
  status → таблица).
- Доменные термины и формулировки от модели «на всякий случай».
- Альтернативы, которые рассматривались, но забыты, — если они
  не «доменное решение» с обоснованием.
- Cсылки на внешние материалы и транскрипты — это сырьё для режима B,
  не память.
