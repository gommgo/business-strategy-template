# Вклад в business-strategy-template

Это форкаемый **шаблон бизнес-стратегии** — методология и каркас аналитики:
бизнес → проблемы → AJTBD → SWOT → Карта гипотез (терминал — `task`), а продукт
(`projects/` → интерфейс / домены / экраны) — опциональный исход, когда стратегия
требует его. Вклад полезен, когда он делает методологию, каноны формы или
deep-dive-скиллы чище и понятнее — не когда он зашивает данные конкретного
заказчика.

## С чего начать

- Прочитай `README.md` (карта репозитория и воркфлоу) и `CLAUDE.md` (роль репо,
  роутер слоёв, принципы). Каноны формы — в `docs/projects/_template/` и README
  каждого слоя.
- Сборки здесь нет — артефакты это чистая аналитика: markdown, а у слоёв страницы и
  дизайна — YAML и JSON по схемам базы скилла `design-deep-dive`. «Запуск» репозитория —
  это прохождение слоёв через оркестратор `/entrypoint` или напрямую deep-dive-скиллы
  (`/business-deep-dive`, `/swot-deep-dive`, `/hypothesis-map-deep-dive`,
  `/project-deep-dive <slug>`, и т.д.).

## Принципы

- **Артефакты — source of truth.** Бизнес — верх (профиль + реестр проблем); под ним
  AJTBD, SWOT и Карта гипотез; продукты — опциональный исход (когда проблему не
  закрывает задача `task`); всё растёт сверху вниз. На код напрямую не мапятся.
- **Канон формы — один раз в `docs/projects/_template/`**, данные — в папках проектов;
  канон не дублируется в проект.
- **Экспертиза священна.** Доменные и продуктовые формулировки приходят от
  бизнеса, аналитика и архитектора через `AskUserQuestion`, не из головы агента;
  облик — только в слое дизайна, утверждает владелец продукта. Неоднозначность
  вне покрытия — вопрос человеку, не угадывание.
- **Метрика — best-effort таргет, не гарантия.** Гарантируем доставку проекта по
  scope; на метрику целимся совместно с бизнесом.
- **Связи между слоями семантические**, не slug-валидируемые. Расхождения ловит
  `/cross-audit` (рой агентов), не grep.
- **Forward-only.** Все артефакты — «что есть сейчас и куда идём», без changelog'ов в
  prose, дат, «было/стало». История живёт в `git log`.
- **`.claude/rules/` расширяем.** Каталог правил для агента — открытый: потребитель
  форка добавляет туда собственные `<topic>.md`-правила (path-scoped инварианты своего
  проекта: `paths:` во frontmatter), не ограничиваясь поставляемыми `forward-only.md`
  и `naming.md`.

## Форк, issue, PR

- **Issue** — для багов методологии и предложений: что в каноне/скилле неясно или
  ломается, как воспроизвести, ожидаемое поведение.
- **PR** — форкни репозиторий, заведи ветку, открой pull request с понятным описанием
  «зачем». Держи PR сфокусированным; не подмешивай несвязанные правки. Один sweep =
  одна непересекающаяся зона.
- Правка, способная сломать накопленную продуктовую модель или раскатиться вширь
  (контракт артефактов всех слоёв, таксономия) — опиши обоснование в PR отдельно.

## Перед PR

Сборки нет — gate здесь это **аудиты** соответствующего слоя (у слоёв страницы и
дизайна — вместе с валидаторами и линтерами скилла `design-deep-dive`):

- узкий аудит каждого тронутого слоя — по таблице слоёв в `CLAUDE.md` §2
  (`/project-audit <slug>`, `/interface-audit <slug>`, `/screen-audit <slug>`,
  `/fsd-audit <slug>`, `/design-audit <slug>`, `/telegram-bot-flow-audit <slug>`,
  `/mobile-audit <slug>`, `/service-audit <slug>`, `/infrastructure-audit`; `/swot-audit` ·
  `/hypothesis-map-audit` — по каждой проблеме, `/ajtbd-audit` — по каждому сегменту);
- `/cross-audit` — сквозная семантика между всеми слоями и проектами (прогнать,
  если трогал несколько слоёв).

- **Conventional Commits** (конвенция формата; git-хук не поставляется): `<type>(<scope>)?: <subject>`,
  subject ≤72. Типы: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `meta`.
  Пример: `docs(canon): clarify hypothesis-map metric attribution`.

## Стиль

Спокойно и по делу, без хайпа. По-русски; технические идентификаторы (имена файлов,
slug, kind) — как есть. Английский в backticks — для устоявшегося канона (`a11y`,
FSD-слои, DDD-термины) и структурных идентификаторов handoff-контракта
(`CLAUDE.md` §8), не для полу-калек. Каноны терминов — в README каждого слоя.

Описание скилла (`description` во frontmatter `SKILL.md`) — до 600 знаков: главный
случай первой фразой, дальше — категории намерений и граница с соседним скиллом, без
перечня фраз-триггеров и пересказа устройства скилла. Листинг скиллов Claude Code
держит имена всех скиллов, а описания при переполнении бюджета
(`skillListingBudgetFraction` в `.claude/settings.json`) снимает у реже вызываемых.

## Развитие скилла `design-deep-dive`

База знаний, утилиты и калибровочный набор скилла правятся только в шаблоне: форк получает скилл заменой папки
(`CLAUDE.md` §6). Указатель утилит — `.claude/skills/design-deep-dive/scripts/README.md`, карта базы —
`.claude/skills/design-deep-dive/kb/INDEX.md`; пути ниже — от папки скилла.

**Тексты скилла и базы.**

- Контекст — аудитория, продукт, среда, планка качества и причины ограничений — лишним не бывает.
- Ограничение — спокойно и с причиной: без капса и без «думай пошагово».
- Цель и способ проверки вместо хореографии шагов; точные шаги — только у хрупких операций (публикация холста
  «прочитать → слить → опубликовать», установка окружения).
- Запрет — только настоящий и с причиной; стиль — утверждением. Исключение — бан-лист конкретных примет «дефолтного
  вида» макета: он поимённый.
- Одна норма — одно место: число живёт в машинном файле своего владельца (`kb/common/canon.tsv` — «норма → место»),
  остальные места на него ссылаются. Навигатор `SKILL.md` читается за один присест; путей машины, версий «на сегодня»
  и истории правок в текстах нет (`.claude/rules/forward-only.md`).
- Детерминированное — скриптами, суждение — модели: таблицы, пороги и расчёты — в данных и коде.
- Примеры — несколько разных и помеченных как иллюстрация.
- Текст для человека — по канону ведения `.claude/rules/guiding.md`: что делаем, что сделали, куда идём, что нужно от
  него; слова — рабочие термины без жаргона.

**Правка кода и данных.**

- Утилита описывает своё текущее поведение: докстринг, `--help` и сообщения — без истории и номеров задач. Новое
  поведение покрыто случаем самопроверки (`--selftest`) на вымышленных данных; у новой утилиты — строка в списке
  `scripts/tests/smoke/` и в указателе.
- Коды выхода: 0 — ошибок нет, 1 — есть находки `error`, 2 — ошибка вызова или окружения, особые исходы — от 3.
- Жёстких остановок маршрута — пять гейтов (`references/phases.md § Принципы всех этапов`); новая проверка — доклад
  заказчику (`warning`), пока решение о гейте не принято отдельно.
- Новые поля схем — необязательные: утверждённые файлы проектов проходят схему без правки. Ключ, который читает код,
  меняется вместе с чтением.
- Данные клиентов — имена, тексты, цены, адреса, названия проектов — в код, тесты, фикстуры и базу не попадают.

**Приёмка правки** — перед коммитом, из корня репозитория, Python окружения скилла (`scripts/install.sh`):

- `scripts/maint/accept.py --base <коммит> --mask <glob> [--smoke <папка>]` — изменённые файлы под масками, разбор
  YAML и JSON, ссылки и следы в изменённых строках, смоук своей папки;
- `scripts/tests/smoke.py` — полный смоук, 0 FAIL; самопроверки тронутых утилит;
- `scripts/maint/fixture_gen.py build --all --check` и `scripts/maint/sync_check.py` — фикстуры, производные файлы,
  управляемые копии и описания скиллов совпадают со сборкой;
- `scripts/maint/canon_check.py` и `scripts/maint/mapcheck.py kb/INDEX.md` — таблица «норма → место» и адреса карты;
- `scripts/maint/normcheck.py --base <коммит>` — при правке текста нормы: числа, id, пути, метки и заголовки на месте;
- описание скилла — до 600 знаков, сумма описаний — до 18 тысяч (сверяет `sync_check.py`).

**Работа несколькими агентами.**

- Зоны без общих файлов: у каждого агента — свой список файлов. Общие файлы — списки смоука, фикстуры и их рецепты,
  указатель утилит, карту базы и таблицу канонов — правит только тот, кто принимает работу; агент отдаёт туда готовые
  строки в отчёте.
- Агент не трогает индекс git: без `add`, `commit`, `stash`, `checkout`, `reset` в общем дереве.
- Файл передачи — с первого шага: что сделано, что проверено, что осталось. Оборванного агента возобновляют с места
  остановки; когда возобновить нельзя, продолжатель идёт по файлу передачи и файлам на диске.
- Одновременно — несколько агентов, а не десятки: при массовом запуске растут сбои среды. За контекстом агента следят
  и просят сдать отчёт до того, как он упрётся в предел.
- Модуль, который импортируют соседние утилиты, правится на копии и переносится одним шагом.

**Обслуживание.**

- Скоропортящееся сверяют по расписанию и перед проектом: снимки каталогов моделей генерации
  (`scripts/install.sh --catalogs`, затем `scripts/ai-media/routing_check.py`), версии типов Claude Design и то, что
  холст исполняет (`kb/claude-design/05-design-artifacts/02-staying-current.md` §3, `03-what-canvas-runs.md` §6).
- Правка нормы идёт в шаблон, а не в форк: форк обновляет скилл заменой папки и переустановкой окружения.
- Единая проверка состояния — `scripts/install.sh --check` и полный смоук: с них начинается работа на новой машине.
