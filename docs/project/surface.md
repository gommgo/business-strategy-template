# surface

> Поверхность (surface) — точка, где продукт «торчит наружу» и встречает
> персону (persona): web-приложение, мобильное приложение, публичное API,
> админка, телеграм-бот, embed-виджет. Поверхность принадлежит одному
> типу (`type`) и обслуживает одну+ персону (persona).
>
> Семантически ↔ `interface/zone.md` — зоны интерфейса принадлежат
> поверхности. Жёсткой ссылки нет — `/cross-audit` ловит зоны без
> поверхности и поверхности без зон.

## Критерии surface

1. **Точка встречи с persona.** Поверхность существует, потому что
   через неё persona получает ценность от продукта. Если ни одна
   persona не пользуется — поверхность мёртвая.
2. **Один тип, одно «где».** `type` (web / mobile / api / admin / bot /
   desktop / embed / …) — один. `lives-at` — конкретное «где» (домен,
   store-app, мессенджер, embedding-host). Двух типов на одной surface
   не бывает — это две разные surface.
3. **Самодостаточна.** Persona может закрыть основной job-to-be-done,
   не выходя за пределы поверхности. Если для базовой задачи нужна
   другая поверхность — это или одна поверхность, или зависимость
   нужно явно зафиксировать.
4. **Поверхность ≠ канал нотификации.** Email/SMS/push, через которые
   мы только уведомляем — это **integration**, не surface. Surface — где
   persona **действует**, а не только получает сигнал.

## Что surface НЕ

- ❌ Технологический стек («React-фронт», «Go-API»). Это стек, не
  поверхность. Поверхность — `web`, реализованная на чём угодно.
- ❌ Канал уведомлений без обратного действия (email-рассылка, push без
  deep-link). Это `integration`.
- ❌ Внутренний интерфейс команды (логи, мониторинг, k8s-dashboard).
  Это эксплуатация, не продукт.
- ❌ Поверхность без persona. Surface, на которую никто из persona не
  заходит — либо неправильно очерчена persona, либо surface лишняя.

## Тест-критерий

«Может ли persona, **зайдя только сюда**, закрыть хотя бы один свой
job-to-be-done?»

- `web-clinic` (web для медсестры) → ✅ (заходит, передаёт направление,
  готово).
- `tg-bot-status` (телеграм-бот с уведомлениями о статусе записи) →
  если только показывает — это `integration`; если можно отменить /
  переподтвердить → ✅ как surface.
- `internal-grafana` → ❌ (внутренний tool, не продуктовая
  поверхность).
