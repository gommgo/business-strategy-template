# <worker-slug>

> Одна-две фразы: что воркер делает для сервиса. Воркер — фоновый процесс
> **того же деплой-юнита** (сервис выводится из пути
> `services/<svc>/workers/`): он просыпается по триггеру и **дёргает
> доменные use-case'ы** — бизнес-правил не держит (как и use-case бота:
> оркестрация, не решение). Отдельный деплой-юнит целиком на событиях —
> сервис `type: worker`, не этот файл.

> schedule — смысл словами («ежечасно», «каждую ночь»), cron-выражение —
> runtime (`<org>/infra`).

- **Trigger:** `` `topic:<topic>` `` | schedule: <смысл словами>

> и сбои. Стратегиями и словами, без чисел (количество ретраев, тайминги —
