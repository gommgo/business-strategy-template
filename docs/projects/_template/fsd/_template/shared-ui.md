# shared-ui

> Проектный UI-примитив (shared-ui) — переиспользуемый компонент без
> доменной привязки (кнопка-обёртка, поле формы, карточка-каркас), без
> привязки к внешней UI-библиотеке. Слайс реализует тип закрытого словаря
> компонентов `kb/common/components.yaml` или расширения проекта (колонка
> `ui-type`); в дереве screens этот тип записан узлом `ui:<Тип>`.
> Слайс-локальный UI живёт в своём слайсе и поднимается сюда при реальном
> переиспользовании, поэтому не каждый тип экранов получает слайс: тип без
> слайса реализует компонент дизайн-системы (ДС) проекта напрямую. Облика
> здесь нет: вид, размер и цвет компонента решает ДС, уровень действия —
> дерево screens.

## Критерии shared-ui

1. **Без домена.** Компонент не знает про entities/features — только
   layout-/форм-семантика.
2. **Реализует тип словаря.** `ui-type` — ключ раздела `types` словаря
   `kb/common/components.yaml` или id расширения проекта (раздел
   `extensions` карты решений ДС); имя из `aka` словаря и тип «по месту» не
   принимаются.
3. **Реальное переиспользование.** Используется в ≥2 местах либо является
   явной проектной конвенцией (единый вид полей формы).
4. **Обёртка со смыслом.** `семантика` объясняет, что компонент добавляет
   поверх примитива.

## Что shared-ui НЕ

- ❌ Доменный компонент («карточка заказа») — это entity-презентер или блок.
- ❌ Внешняя UI-библиотека целиком — компоненты проектные; выбор библиотек —
  `docs/stack/` фронт-форка.
- ❌ Значения облика — цвета, шрифты, отступы, радиусы: их дают токены ДС
  проекта (`docs/projects/<project-slug>/design/system.tokens.json`), фронт
  выпускает из них тему; в карте их нет.
- ❌ Обещание покрыть слайсами все типы экранов: покрытие каждого типа
  компонентом проверяет ДС, а слайс заводится только при переиспользовании.

## Колонки

- `slug` — идентификатор компонента · строка-идентификатор · обяз.
- `name` — человекочитаемое имя · строка · обяз.
- `description` — роль в проекте · строка · обяз.
- `ui-type` — тип, который реализует слайс · `<Тип>` — ключ `types` словаря `kb/common/components.yaml` или id расширения проекта · обяз.
- `семантика` — что добавляет поверх примитива · свободный текст · обяз.
- `status` — зрелость записи · `draft | stable` · обяз.

| slug | name | description | ui-type | семантика | status |
|---|---|---|---|---|---|
| `<slug>` | <имя> | <роль> | `<Тип>` | <что добавляет> | `draft` \| `stable` |

> Заполняется под проект. Пример (иллюстрация формы, не образец ответа):
> `form-field` · «Поле формы» · «единая обвязка полей ввода» · `Field` ·
> «связывает подпись, подсказку и текст ошибки с полем ввода» · `draft`.
