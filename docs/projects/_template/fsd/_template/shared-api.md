# shared-api

> Контракт данных поверхности: как фронт разговаривает с бэком на уровне
> смысла — какие сущности покрыты контрактом и какие **сценарии данных**
> нужны для работы без бэка (мок/демо/разработка). Выбор HTTP-клиента,
> либы мока и формат схем — платформа фронт-форка (`docs/stack/`).

## Контракт данных

Форма каждой сущности задаётся её записью в `entities.md` (колонка `поля` +
источник в домене). Контракт покрывает **все** entities поверхности:
сущность без покрытия — blocker для stable этого файла.

## Критерии сценария данных

1. **Продуктовое состояние.** Сценарий описывает осмысленное состояние
   данных поверхности (пусто / наполнено / ошибка / авторизован), а не
   техническую фикстуру.
2. **Покрывает обязательные состояния экранов.** Набор сценариев следует
   обязательным наборам состояний экранов поверхности (канон экранов
   `docs/projects/_template/screens/README.md`, раздел «Обязательный
   набор»): `empty` (пусто с самого начала) и `populated` (идеальное) —
   всегда; `partial-few`, `overflow-many`, `loading-initial`, `error-load`,
   `no-permission` — когда эти состояния есть в наборах экранов поверхности.
   Имена сценариев — `empty`, `populated` и ключи словаря состояний экрана.
3. **Данные — из демо-набора экранов.** `состояние` описывает данные
   смыслом; значения — производный демо-набор слоя экранов (глоссарий
   объектов, объёмы коллекций `collection.volume` блоков, крайние случаи
   ux 06/01 §6.2), своих фикстур карта не держит. `loading-initial`
   задерживает ответ так, как требует колонка «как проверить» строки
   `loading-initial` словаря ux 06/01 §2.

## Что shared-api НЕ

- ❌ Выбор клиента/библиотек, заголовки, эндпоинты — `docs/stack/`
  фронт-форка.
- ❌ Дубль схем сущностей — форма живёт в `entities.md`.
- ❌ Тест-фикстуры конкретных тестов — это исполнительная сторона.

## Сценарии данных

- `slug` — идентификатор сценария · строка-идентификатор · обяз.
- `name` — человекочитаемое имя · строка · обяз.
- `description` — что демонстрирует сценарий · строка · обяз.
- `состояние` — состояние данных по сущностям · свободный текст · обяз.
- `status` — зрелость записи · `draft | stable` · обяз.

| slug | name | description | состояние | status |
|---|---|---|---|---|
| `empty` | Пусто | <что видно без данных> | <все сущности пустые> | `draft` |
| `populated` | Наполнено | <реалистичная картина> | <какие сущности чем наполнены> | `draft` |
| `partial-few` | Мало | <как поверхность выглядит с одной-тремя записями> | <в коллекциях по одной-три записи> | `draft` |
| `overflow-many` | Много | <как поверхность держит объём кратно больше расчётного> | <коллекции — до максимального объёма блоков> | `draft` |
| `loading-initial` | Долгий ответ | <что видно, пока данные в пути> | <ответы источников задержаны> | `draft` |
| `error-load` | Ошибка загрузки | <что видно, когда данные не получены> | <источники отвечают ошибкой> | `draft` |
| `no-permission` | Нет прав | <что видит роль без прав> | <сессия роли без прав на объекты поверхности> | `draft` |
| `<slug>` | <имя> | <что демонстрирует> | <состояние> | `draft` \| `stable` |

Строка `partial-few` … `no-permission` остаётся, когда её состояние есть в
наборах экранов поверхности, иначе удаляется.
