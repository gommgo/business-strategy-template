# shell

> Каркас (shell) — «капсула» экрана: объявляет типизированные слоты каркаса и описывает облицовочный адаптив (сайдбар
> становится выдвижной панелью на узкой ширине). screen заполняет слоты; shell задаёт сами слоты, их обязательность,
> тип принимаемого содержимого, лендмарк и поведение на диапазонах ширины. Основной каркас держит ещё навигацию
> приложения — узлом своего дерева — и раздел «Состояния приложения».
>
> Каркасов у поверхности несколько: основной (рабочие экраны), входа (вход и регистрация), полноэкранный (мастер,
> редактор и полотно).

## Критерии shell

1. **Объявляет слоты.** Поле `slots: {...}` — единственный источник правды о наборе слотов каркаса. screen не вводит
   новых слотов, только заполняет существующие.
2. **Каждый слот типизирован.** Для слота указаны `required` (bool), `accepts` (`block`, `tree`, `block | tree`,
   `block (modal/drawer)`) и `landmark` — какой областью страницы он становится для вспомогательных технологий.
3. **Облицовочный адаптив — здесь.** Поле `responsive` фиксирует, как слот меняет поведение на диапазонах ширины
   (`xs` … `xl` — имена диапазонов, границы — токены `breakpoint.*` дизайн-системы; таблица — канон слоя). Структурный
   адаптив (разные screen) — через `flow`, не здесь.
4. **Не содержимое экранов.** Дерево shell описывает каркас (шапка, сайдбар, main, …) с пустыми слотами; что в слотах
   — задача screen. Своё содержимое у каркаса одно на приложение: навигация, поиск по приложению, узел помощи, меню
   пользователя.
5. **Навигация — в дереве основного каркаса.** Узел `ui:Sidebar items=nav` (или `ui:TopBar`, `ui:BottomNav`) несёт
   пункты из `map.md` (раздел «Навигация»); навигация одна на продукт, вариант — по числу разделов (ux 02/02 §1.6).
6. **Узел помощи — один.** Помощь живёт в одном месте каркаса на всех экранах (WCAG 3.2.6).
7. **Состояния приложения объявлены.** У основного каркаса — раздел «Состояния приложения»: сервис недоступен,
   плановые работы, истечение сессии, нет связи, демо-режим — где и как видны. Экран их не повторяет.
8. **Может быть несколько shell.** `app-shell` (основной), `auth-shell` (вход и регистрация), `fullscreen-shell`
   (мастер, полотно) — разные капсулы под разный смысл.

## Что shell НЕ

- ❌ Не screen: каркас без контента — это shell; route с контентом — screen.
- ❌ Не block: содержимое слота — это блок.
- ❌ Не узел раскладки: `layout:stack` — это узел дерева, не shell.
- ❌ Не карта экранов: пункты навигации приходят из `map.md`, каркас не перечисляет экраны и маршруты.
- ❌ Не боковая панель экрана: фильтры и меню настроек экрана — слот `side` или блок экрана, а не навигация
  приложения.

## Тест-критерий

«Это объявление набора слотов, навигации и поведения на ширинах — а не сам route с контентом, не блок и не узел
раскладки?»

- «**Основной каркас приложения**» (шапка, навигация, side / main / detail / overlay) → `app-shell` ✅
- «**Каркас экрана аутентификации**» (только main по центру, без навигации) → `auth-shell` ✅
- «**Список исследований**» — это block ❌
- «**Рабочее место исследований**» — это screen ❌

## Форма frontmatter

| поле | тип | обязательность | смысл |
|---|---|---|---|
| `slug` | string | yes | kebab-case идентификатор |
| `name` | string | yes | человекочитаемое имя |
| `description` | string | yes | одна фраза о капсуле |
| `slots` | `{ <name>: { required, accepts, landmark } }` | yes | объявление слотов каркаса |
| `responsive` | `{ <xs \| sm \| md \| lg \| xl>: { <slot>: <behaviour> } }` | optional | облицовочный адаптив по диапазонам ширины |
| `assets` | `[имя-файла]` | optional | сырьё каркаса в `assets/shell/<slug>/` (только имена файлов; без ассетов поле отсутствует) |
| `status` | `draft \| stable` | yes | зрелость записи |

Допустимые `accepts`:

- `block` — только ссылка `block:<slug>`.
- `tree` — только дерево.
- `block | tree` — любое из двух.
- `block (modal/drawer)` — блок-оверлей (модальное окно или шторка).

Допустимые `landmark` слота: `main` · `navigation` · `complementary` · `region` · `—`. Ровно один слот — `main`.
Неявные лендмарки типов в дереве: `ui:TopBar` — `banner`, `ui:Sidebar` и `ui:BottomNav` — `navigation`.

Допустимые ключи `responsive`: `xs`, `sm`, `md`, `lg`, `xl` — имена диапазонов ширины; их границы — токены
`breakpoint.*` дизайн-системы проекта (таблица «ключ ↔ диапазон» — канон слоя `../README.md`, раздел «Ключи
`responsive` и брейкпоинты»). Пиксели не пишутся.

Допустимые `behaviour` слота на диапазоне:

- `visible` — слот рендерится как объявлено в `tree`.
- `drawer-via-burger` — слот скрывается, доступен через кнопку меню.
- `overlay` — слот рендерится поверх main.
- `stacked` — слот рендерится после main в потоке.
- `hidden` — слот не рендерится; его функции должны быть доступны иначе — функциональность от ширины не меняется.
- `fullscreen` — оверлей разворачивается на весь экран (модальное окно на узкой ширине).
- `bottom-sheet` — оверлей становится нижней шторкой (боковая панель и поповер на узкой ширине; ux 04/07 §1.4).

## Тело: tree каркаса

```yaml
tree:
  - layout:stack:
      - ui:TopBar:
          - ui:SearchInput
          - ui:Link:
              - text:<раздел>.shell.help.link
      - layout:row:
          - ui:Sidebar items=nav
          - layout:stack fills=$side
          - layout:stack fills=$main
          - layout:stack fills=$detail
      - layout:layer fills=$overlay
```

Атрибут `fills=$<slot>` помечает узел каркаса, в который screen вставит содержимое слота с таким именем; слотовый узел
в дереве пуст. Каркас собирается из `layout:`-узлов и компонентов словаря (`ui:`): шапка — `ui:TopBar`, навигация —
`ui:Sidebar`, `ui:TopBar` или `ui:BottomNav` с `items=nav`. Боковая панель экрана — слот `side`, а не навигационный
узел.

## Состояния приложения

Раздел тела основного каркаса. Строка на состояние: где и как оно видно на всех экранах поверхности; состояния нет у
продукта — строка с «не применимо: причина». Тексты — строки реестра `texts.md` с ролями `banner`, `confirm-title`,
`confirm-body`, `action`.

```markdown
## Состояния приложения

| состояние | где видно | форма | тексты |
|---|---|---|---|
| `service-unavailable` | <узел или слот каркаса> | <баннер под шапкой> | `text:<ключ>` |
| `maintenance` | … | <баннер; во время работ — служебный экран> | … |
| `session-expiry` | … | <модальное окно с продлением — заранее, а не после> | … |
| `connection-lost` | … | <баннер; введённое сохраняется> | … |
| `demo-mode` | … | <полоса режима> \| не применимо: <причина> | … |
```

Форма сообщения для каждого состояния — строки развилки ux 04/08 §2.2 (проблема сервиса целиком — баннер, истечение
сессии — модальное окно с продлением, потеря сети — баннер с сохранением введённого); истечение сессии и потеря связи
— ux 05/04 §4.2–§4.3. Решение, нужен ли сценарий истечения сессии, — раздел `MVP` vision.

## Пример

Иллюстрация формы, не образец ответа.

```markdown
---
slug: app-shell
name: 'Основной каркас приложения'
description: 'Шапка с поиском и помощью, навигация, side + main + detail + overlay'
slots:
  side:    { required: false, accepts: 'block | tree', landmark: complementary }
  main:    { required: true,  accepts: 'block | tree', landmark: main }
  detail:  { required: false, accepts: 'block', landmark: complementary }
  overlay: { required: false, accepts: 'block (modal/drawer)', landmark: — }
responsive:
  xs:
    side:    drawer-via-burger
    detail:  stacked
    overlay: fullscreen
  sm:
    side:    drawer-via-burger
    detail:  overlay
  md:
    side:    visible
    detail:  visible
status: draft
---

# app-shell

Основная капсула рабочих экранов. На `xs` и `sm` боковая панель экрана уходит под кнопку меню; детали на `xs` идут
стеком после main (или становятся отдельным screen в рамках flow), модальное окно разворачивается на весь экран.
Навигация на узкой ширине — нижняя панель вкладок: раздел «Навигация» `map.md`.

​```yaml
tree:
  - layout:stack:
      - ui:TopBar:
          - ui:SearchInput
          - ui:Link:
              - text:app.shell.help.link
      - layout:row:
          - ui:Sidebar items=nav
          - layout:stack fills=$side
          - layout:stack fills=$main
          - layout:stack fills=$detail
      - layout:layer fills=$overlay
​```

## Состояния приложения

| состояние | где видно | форма | тексты |
|---|---|---|---|
| `service-unavailable` | под `ui:TopBar`, над всеми слотами | баннер | `text:app.shell.service-unavailable.banner` |
| `maintenance` | под `ui:TopBar` | баннер заранее; во время работ — служебный экран | `text:app.shell.maintenance.banner` |
| `session-expiry` | слот `overlay` | модальное окно с продлением | `text:app.shell.session-expiry.confirm-title`, `text:app.shell.session-expiry.action` |
| `connection-lost` | под `ui:TopBar` | баннер, введённое сохраняется | `text:app.shell.connection-lost.banner` |
| `demo-mode` | не применимо: демо-режима у продукта нет | — | — |
```

## Anti-patterns

- ❌ Содержимое экранов в shell-tree (конкретный блок, текст экрана); своё у каркаса — только навигация, поиск по
  приложению, узел помощи и меню пользователя.
- ❌ Оси контекста приложения (тема, бренд, плотность, направление письма) как атрибуты узлов shell — их решают бриф на
  вид и дизайн-система, применяет корень приложения в коде.
- ❌ Пиксели/raw-CSS в `tree` или `responsive`.
- ❌ Слот без `accepts`, `required` или `landmark`; ни одного или два слота с `landmark: main`.
- ❌ `responsive`-поведение, не покрытое доступными `behaviour`; `hidden` у слота, чьи функции больше нигде не
  доступны.
- ❌ Структурный адаптив через `responsive` (когда меняется не облик слота, а число экранов) — это `flow`.
- ❌ Навигация как слот, который заполняет экран, или боковая панель экрана как навигация приложения.
- ❌ Два узла помощи или помощь в разных местах на разных экранах.
- ❌ Состояния приложения на экранах вместо раздела основного каркаса.
- ❌ shell без `slots`.
