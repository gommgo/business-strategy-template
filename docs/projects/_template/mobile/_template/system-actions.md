# system-actions

> Системное действие (system-action) — действие приложения, которое **система выполняет по
> просьбе пользователя вне экранов приложения**: голосовой ассистент, автоматизации и команды
> системы, кнопка на виджете, кнопка в уведомлении. Это «витрина» фичи для ОС: логика живёт в
> `features.md`, здесь — какими каналами действие доступно, что пользователь говорит или
> передаёт, открывается ли приложение и что пользователь получает в ответ. Из записи код-репо
> выводит объявление действия для системы (механизм платформы — забота код-репо).

## Критерии system-action

1. **Опирается на фичу.** `feature` → существующая запись `features.md`; своей логики у
   системного действия нет — оно вызывает фичу.
2. **Канал назван.** `channels` непусто: `voice` (голосовой ассистент системы) · `automation`
   (команды и автоматизации системы) · `widget:<slug>` (кнопка виджета из `widgets.md`) ·
   `notification:<slug>` (кнопка уведомления — push-запись `entry-points.md`).
3. **Режим явный.** `mode: headless` — выполняется без открытия приложения; `opens-app` —
   открывает приложение на экране `target`. При `opens-app` `target` обязателен, при `headless`
   — `—`.
4. **Слова пользователя.** `phrases` (обязательны при канале `voice`) и `parameters` — в языке
   пользователя: что он говорит и что передаёт («текст заметки», «срок»); без типов и сигнатур.
5. **Есть ответ.** `response` — что пользователь получает в подтверждение: короткий ответ
   ассистента, уведомление, изменившийся виджет. Действие без обратной связи не заводится.
6. **Сессия и блокировка — решения продукта.** Требует ли действие входа и допустимо ли оно на
   заблокированном устройстве (`headless`-действие с чувствительными данными — осознанный
   выбор).
7. **Есть ситуация-источник.** `situation` → `interface/<surface>/situation.md`: шаг
   деятельности, в котором руки или глаза пользователя заняты либо приложение открывать
   незачем.

## Что system-action НЕ

- ❌ Логика действия — `features.md`; здесь только витрина фичи для системы.
- ❌ Вход на экран по ссылке, пушу, ярлыку или тапу по виджету — `entry-points.md` («куда»);
  системное действие — «что сделать».
- ❌ Собственное постоянное прослушивание (wake word) — это длящаяся фоновая работа
  (`background-tasks.md`, `timing: continuous`) + разрешение на микрофон (`permissions.md`) и
  отдельное решение владельца; здесь — только вызов через ассистента системы.
- ❌ Имена платформенных API, типы параметров, сигнатуры — код-репо.
- ❌ Действие «на всякий случай» — без ситуации, в которой приложение открывать незачем.

## Тест-критерий

«Это действие, которое система выполняет по просьбе пользователя вне экранов приложения, — с
названным каналом, фичей-источником и понятным ответом?»

- «Голосом: „запиши заметку …" → фича `create-note`, без открытия приложения, ответ —
  подтверждение ассистента» → `dictate-note` ✅
- «Ссылка из письма открывает задачу» — entry-point ❌
- «Кнопка „Сохранить" на экране» — feature ❌

## Колонки

- `slug` — идентификатор · `kebab-case` · обяз.
- `name` — человекочитаемое имя действия · текст · обяз.
- `description` — что происходит и что меняется · текст · обяз.
- `feature` — фича-источник · реф → `features` · обяз.
- `channels` — где действие доступно · массив из `voice` \| `automation` \| `widget:<slug>` \| `notification:<slug>` · обяз.
- `phrases` — примеры фраз пользователя (ru) · текст · обяз. при `voice`, иначе `—`
- `parameters` — что пользователь передаёт, в его языке (или `—`) · перечень · опц.
- `mode` — `headless` \| `opens-app` · обяз.
- `target` — экран при `opens-app` · реф → `screens.key` (или `—` при `headless`) · обяз.
- `response` — что пользователь получает в ответ · текст · обяз.
- `требует сессии` — `да` \| `нет` · обяз.
- `на заблокированном экране` — `да` \| `нет` · обяз.
- `platforms` — `all` \| `android` \| `ios` · обяз.
- `situation` — ситуация-источник · реф → `interface/<surface>/situation.md` · обяз.
- `status` — зрелость записи · `draft` \| `stable` · обяз.
