# flows

> Сценарий (flow) — навигационный путь пользователя через экраны: триггер, упорядоченные шаги
> (`screens.key` и действия), выход и ветки ошибок. Это навигационный граф приложения
> (стек, табы, модалки, back-поведение), которого нет в веб-картах. Код-репо разворачивает
> запись в Maestro-флоу `e2e/<platform>/<slug>.yaml` и сценарный тест презентеров.

## Критерии flow

1. **Шаги ссылаются на существующие экраны** (`screens.key`) или на явные действия
   («ввод логина», «подтверждение»).
2. **Есть выход.** Чем заканчивается сценарий (экран, состояние, закрытие).
3. **Есть ветка ошибки** у каждого флоу с сетью: что видит пользователь и куда попадает.
4. **`app-start` и `login` обязательны** для любой поверхности с входом: порядок старта —
   requirements → session → route.

## Что flow НЕ

- ❌ Логика (правила, условия ветвления) — исход фичи/презентера; flow лишь маршрутизирует.
- ❌ Экран — шаг флоу, не сам флоу.
- ❌ Viewport-декомпозиция веба (desktop ↔ mobile) — у мобильного экрана один viewport.

## Тест-критерий

«Это путь пользователя через несколько экранов с триггером, выходом и веткой ошибки?»

- «**Вход**: `Login` → успех → `TodoList`; ошибка → сообщение на `Login`» → `login` ✅
- «**Экран логина**» — screen ❌
- «**Валидация пароля**» — правило фичи ❌

## Колонки

- `slug` — идентификатор · `kebab-case` · обяз.
- `name` — человекочитаемое имя · текст · обяз.
- `description` — цель сценария · текст · обяз.
- `триггер` — что запускает (`app-start`, таб, entry-point, действие) · текст · обяз.
- `шаги` — последовательность `screens.key` / действий · массив · обяз.
- `выход` — чем заканчивается · текст · обяз.
- `ветки ошибок` — что при ошибке (сеть, 401, offline) · текст (или `—` без сети) · обяз.
- `status` — зрелость записи · `draft` \| `stable` · обяз.

| slug | name | description | триггер | шаги | выход | ветки ошибок | status |
|---|---|---|---|---|---|---|---|
| `app-start` | Старт приложения | <requirements → сессия → маршрут> | запуск / возврат из фона | [`Splash`, `Login` \| `<RootTab>`] | корневой экран или pending route | `update_required` → `UpdateRequired`; `maintenance` → `Maintenance`; offline → кэш | `draft` |
| `login` | Вход | <…> | `Login` | [`Login`, `<RootTab>`] | сессия установлена | 401 → сообщение; сеть → retry | `draft` |
| `<slug>` | <имя> | <цель> | <триггер> | [`<Key>`, …] | <выход> | <ветки> \| — | `draft` \| `stable` |
