# placement

> Размещение (placement) — **единственное место**, где записано «кто где
> живёт»: какой юнит (сервис проекта, проектный платформенный ресурс,
> общий ресурс бизнеса) развёрнут в каком рантайме. Сервис «знает свой
> сервер» через эту таблицу: `unit → runtime → servers`. Паспорта сервисов и
> реестры проектов размещение не дублируют — проектный слой
> deployment-agnostic, переезд сервиса на другой сервер = правка одной
> строки здесь.

## Критерии placement

1. **Юнит существует.** `unit` резолвится: `` `service:<project>/<svc>` `` —
   строка реестра `projects/<project>/services/service.md`;
   `` `platform:<project>/<slug>` `` — строка `services/platform.md` проекта
   с `provided-by: own`; `` `shared-platform:<slug>` `` — строка
   `shared-platform.md`; `` `job:<slug>` `` — строка `job.md`.
2. **Рантайм существует.** `runtime` — строка `runtime.md`.
3. **Несколько строк на юнит = несколько окружений.** Prod на k8s + dev на
   compose — две строки; окружение читается из рантайма, здесь не
   дублируется.
4. **Полнота.** Каждый сервис каждого проекта размещён хотя бы в один
   prod-рантайм; каждый `own`-ресурс, каждый используемый общий ресурс и каждая
   джоба периметра — размещены. Дыры ловят `/infrastructure-audit` и `/cross-audit`
   (`service-placement`).

## Что placement НЕ

- ❌ Колонка в паспорте сервиса или `service.md` проекта. «Кто где» — только
  здесь.
- ❌ Раскладка по конкретным нодам кластера, affinity, реплики. Внутри
  рантайма раскладывает `<org>/infra` (и сам k8s).
- ❌ Размещение ресурсов **сервиса** (`Resources` паспорта): его БД и кэши
  едут вместе с сервисом — рантайм сервиса определяет, где их провижинить.
  Отдельная строка нужна только юнитам с собственной жизнью (сервисы,
  платформенные ресурсы).

## Тест-критерий

«Прочитав строку, инфра-репо однозначно понимает: этот юнит материализуется
в этом рантайме (helm-релиз в кластере / блок в compose-файле этого хоста)?»

## Колонки

- `unit` — что размещаем · `` `service:<project>/<svc>` `` \| `` `platform:<project>/<slug>` `` \| `` `shared-platform:<slug>` `` \| `` `job:<slug>` `` · обяз.
- `runtime` — куда · `` `runtime-slug` `` (строка `runtime.md`) · обяз.
- `note` — почему именно здесь, когда неочевидно («изоляция чувствительных данных», «рядом с БД-источником», «дешёвый полигон») · текст · опц. (`—` допустим)
- `status` — зрелость записи · `draft` \| `stable` · обяз.

| unit | runtime | note | status |
|---|---|---|---|

> Заполняется под бизнес. Примеры: `` `service:crm/orders` `` ·
> `` `main-cluster` `` · `—` · `draft`; `` `service:crm/ai-gateway` `` ·
> `` `dev-box` `` · «дешёвый полигон под эксперименты» · `draft`;
> `` `shared-platform:nats` `` · `` `main-cluster` `` · `—` · `draft`.
