# runtime

> Рантайм (runtime) — среда исполнения, развёрнутая на серверах:
> kubernetes-кластер или compose-хост. Это «куда размещаем»: строки
> `placement.md` ссылаются сюда. Один бизнес может держать и кубер, и
> compose одновременно — например, prod на k8s-кластере, dev на дешёвом
> compose-сервере, или весь prod на compose по сплит-серверам.

## Критерии runtime

1. **Одна среда — одна строка.** k8s-кластер (сколько бы нод ни занимал) —
   одна строка с несколькими `servers`; compose-хост — одна строка с одним
   сервером. Сплит на compose = несколько compose-рантаймов. Один
   физический кластер, несущий **несколько окружений**, — по строке-среде
   на окружение (одни и те же `servers`); как материализовать разделение
   (namespaces и т. п.) — решение `<org>/infra`, не этого слоя.
2. **Стоит на учтённых серверах.** Каждый slug в `servers` существует в
   `server.md`. Рантайм без серверов — недоказан.
3. **Несёт окружение.** `environment` (prod / staging / dev) — свойство
   рантайма; один юнит размещается в несколько окружений несколькими
   строками `placement.md`.

## Что runtime НЕ

- ❌ Сервер. Железо — `server.md`; рантайм — то, что на нём развёрнуто.
- ❌ Платформенный ресурс (брокер, traefik). Это `shared-platform.md` /
  проектный `platform.md`; ресурс сам **размещается** в рантайм через
  `placement.md`.
- ❌ Окружение как абстракция без машин («у нас есть staging») — пока нет
  серверов и строки здесь, окружения нет.
- ❌ Runtime-механика: версия k8s, CNI, ingress-контроллер, swap — это
  `<org>/infra`.

## Тест-критерий

«Можно ли сказать юниту „живи здесь“ — и инфра-репо поймёт, как это
материализовать (helm в кластер / сервис в compose-файл этого хоста)?»

## Колонки

- `slug` — устойчивый идентификатор · `kebab-case` · обяз.
- `name` — короткое имя · текст · обяз.
- `type` — вид среды · `kubernetes` \| `compose` · обяз.
- `environment` — окружение · `prod` \| `staging` \| `dev` · обяз.
- `servers` — на каких серверах стоит · `` [`server-slug`, …] `` · обяз.
- `status` — зрелость записи · `draft` \| `stable` · обяз.

| slug | name | type | environment | servers | status |
|---|---|---|---|---|---|

> Заполняется под бизнес. Примеры: `main-cluster` · «Основной кластер» ·
> `kubernetes` · `prod` · `` [`srv-prod-1`, `srv-prod-2`] `` · `draft`;
> `dev-box` · «Dev-полигон» · `compose` · `dev` · `` [`srv-dev-1`] `` ·
> `draft`.
