# server

> Сервер (server) — единица учёта железа/VPS бизнеса: то, на чём стоят
> рантаймы. Учёт смысловой: провайдер, локация, ёмкость, назначение — ровно
> столько, чтобы осмысленно раскладывать сервисы по серверам. Конкретика
> доступа (IP, hostname, ключи, ОС) живёт в инфра-репо `<org>/infra`,
> не здесь.

## Критерии server

1. **Реальная единица аренды/владения.** Строка = один сервер (VPS,
   dedicated, нода облака), за который бизнес платит и который можно
   включить/выключить отдельно.
2. **Назначение словами.** `purpose` отвечает «зачем бизнесу этот сервер»
   («prod-ядро», «дешёвый dev-полигон»), не перечисляет софт — софт виден
   через `runtime.md` и `placement.md`.
3. **Ёмкость — одной колонкой.** `capacity` достаточно для решения «влезет
   ли сюда ещё сервис»; детальные спеки — у провайдера и в `<org>/infra`.

## Что server НЕ

- ❌ Рантайм. k8s-кластер или compose-хост — `runtime.md` (рантайм **стоит
  на** серверах).
- ❌ Managed-сервис без сервера (managed Postgres, S3 облака). Это
  технология ресурса (`Resources` паспорта / `shared-platform.md`), сервер
  под ним — забота провайдера.
- ❌ Инвентарь доступов (IP, hostname, SSH, пароли). Это `<org>/infra`.

## Тест-критерий

«Платит ли бизнес за это как за отдельную машину, и можно ли её выключить,
не выключая другую?»

## Колонки

- `slug` — устойчивый идентификатор · `kebab-case` · обяз.
- `name` — короткое имя · текст · обяз.
- `provider` — у кого арендован/где стоит · текст (`hetzner`, `timeweb`, `on-prem`, …) · обяз.
- `location` — регион/дата-центр словами · текст · обяз.
- `capacity` — ёмкость одной строкой · текст («4 vCPU / 8 GB / 160 GB») · обяз.
- `purpose` — зачем бизнесу этот сервер · текст · обяз.
- `status` — зрелость записи · `draft` \| `stable` · обяз.

| slug | name | provider | location | capacity | purpose | status |
|---|---|---|---|---|---|---|

> Заполняется под бизнес. Пример: `srv-prod-1` · «Prod-ядро» · `hetzner` ·
> «Falkenstein» · «8 vCPU / 16 GB / 320 GB» · «основная prod-нагрузка всех
> проектов» · `draft`.
