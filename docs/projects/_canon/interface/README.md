# Артефакты интерфейса

UX-слой проекта: 7 плоских md-файлов, каждый — таблица сущностей одного
типа. Этот файл — **канон формы** (`docs/projects/_canon/interface/`);
данные каждого проекта живут в его папке
`docs/projects/<project-slug>/interface/`. Все ссылки между сущностями —
через `slug`. **Чистая аналитика**: на код (FSD-слои, компоненты)
артефакты напрямую не мапятся — переход к коду идёт через
`docs/projects/<project-slug>/screens/` и далее вручную, без отдельного
артефакта-моста.

## Файлы

| файл | сущность | поля |
|---|---|---|
| [`who.md`](who.md) | участник системы | slug · name · description · status |
| [`stage.md`](stage.md) | этап бизнес-процесса (порядок строк = порядок этапов) | slug · name · description · status |
| [`situation.md`](situation.md) | ситуация: кто/когда/что/ради чего/с какими данными | slug · name · description · stage · who · when · action · goal · entry-data · exit-data · using-what · ux-substrate · block · status |
| [`zone.md`](zone.md) | зона интерфейса | slug · name · description · parent-zone · status |
| [`block.md`](block.md) | блок (узел навигации + контейнер субстратов) | slug · name · description · zone · who · ux-substrates · entrypoint · transition-to-block · transition-from-zone · status |
| [`ux-substrate.md`](ux-substrate.md) | UX-субстрат: `type` + `name`, принадлежит ситуации | slug · name · description · type · situation · status |
| [`data-items.md`](data-items.md) | элемент данных в языке участника (entry/exit ситуации, опц.) | slug · name · description · status |

## Принципы оформления

Один файл — одна таблица сущностей одного типа. Структура файла:

```markdown
# <имя файла>

> Одна фраза о сущности (что это в проекте, что чем ссылается).

| slug | name | description | <relation columns> |
|---|---|---|---|
| `<slug>` | <имя> | <описание> | `<other_slug>` |
```

H1 = имя файла = kind. Под H1 — одна-две поясняющие фразы, при
необходимости секции `Критерии <kind>` / `Что <kind> НЕ` /
`Тест-критерий` (чем сущность является и чем — нет, с разделяющим
вопросом и примерами ✅/❌), и одна таблица. Frontmatter не нужен — kind
определяется именем файла.

Русское слово, являющееся переводом строгого термина, сопровождается его
`slug` в скобках при каждом вхождении: «участник (who)», «способ действия
(action)», «цель (goal)», «данные (data-items)». Так перевод и канонический
идентификатор остаются однозначно связаны.

### Форма ячеек (единая по проекту)

| тип значения | формат | пример |
|---|---|---|
| одиночный slug-реф | в бэктиках | `` `doctor` `` |
| массив slug-рефов | питон-стиль с бэктиками внутри | `` [`doctor`, `nurse`] `` |
| пустое опциональное поле | em-dash | `—` |
| bool | как в коде | `true` \| `false` |
| `status` (enum) | в бэктиках | `` `draft` `` \| `` `stable` `` |
| свободный текст | без кавычек, одна строка | подпись бумажного направления |

Первые три колонки везде одни и те же: `slug` · `name` · `description`.
Дальше — связи и доменные поля. **Последняя колонка** во всех 7 файлах —
`status` (enum `draft` \| `stable`): зрелость записи относительно своих
критериев.

## Статус записи

- `draft` — заведена, но не прошла полный чек-лист зрелости (часть слотов
  пустая, есть открытые вопросы, тест-критерий не подтверждён, или
  ссылается на ещё не существующие сущности).
- `stable` — прошла все критерии файла-канона (`Критерии <kind>`,
  `Что <kind> НЕ`, `Тест-критерий`), все обязательные слоты заполнены,
  все ссылки валидны, зеркала консистентны, открытых вопросов нет.
- Дефолт у новой записи — `draft`. Повышение в `stable` — через скилл
  `/interface-deep-dive`, по подтверждению аналитика.
- Понижение `stable → draft` — только аналитик руками, когда нашёл
  несостыковку.
- `stable` может ссылаться на `draft`: это «эта запись прошла свои
  критерии», не «вся цепочка зрелая». `/interface-audit` подсветит hint,
  не блокирует.

## Связи и выводимые поля

- **ситуация → этап** (M:1): `situation.stage`.
- **ситуация → участник** (M:1): `situation.who`.
- **ситуация ↔ данные** (M:N, опционально): `situation.entry-data`,
  `situation.exit-data` → `data-items`. Оба поля могут быть `—`
  (например, ситуация открытия экрана без явных входных данных).
  data-items — в **языке участника** (`who`), не в понятиях реализации;
  определение и критерии — в [`data-items.md`](data-items.md).
- **субстрат → ситуация** (M:1): `ux-substrate.situation` —
  канонический источник.
- **ситуация → субстраты** (1:N): `situation.ux-substrate` — **зеркало
  для наглядности**; должно соответствовать фильтру
  `ux-substrate.situation == <ситуация>`.
- **блок ↔ субстраты** (M:N): `block.ux-substrates` — канонический
  источник.
- **блок ↔ ситуация** (M:N): `situation.block` — **зеркало для
  наглядности**; должно соответствовать join'у через субстраты
  (`situation → ux-substrate.situation → block.ux-substrates`).
- **зона → родительская зона** (M:1): `zone.parent-zone`. Цикл запрещён.
- **блок → зона** (M:1): `block.zone`.
- **блок → блоки** (M:N исходящие): `block.transition-to-block`.
- **блок ← зоны** (M:N входящие): `block.transition-from-zone` — из
  этих зон можно попасть в этот блок. Внутри одной зоны блоки достижимы
  взаимно неявно: пишутся только нестандартные/межзонные переходы.
- **глобальный entrypoint**: `block.entrypoint = true` — стартовый блок
  системы (их может быть несколько, например по разным `who`).

## Workflow

```
/interface-deep-dive — единая точка входа.
```

Скилл заводит новые сущности, углубляет частичные, разбирает сырьё
(транскрипт интервью, заметки, скрин UI), ведёт переход `draft → stable`.
В конце сессии предлагает прогнать `/interface-audit` — полный аудит
консистентности (тупики, рассинхрон зеркал, битые ссылки, семантические
подозрения).

## Anti-patterns

- ❌ Несколько таблиц в одном файле (один файл = один kind).
- ❌ Ссылки прозой или на несуществующий slug.
- ❌ Один датум под разными `data-items` slug'ами (реестр сквозной).
- ❌ Расхождение зеркал у ситуации: `situation.ux-substrate` не
  соответствует фильтру по `ux-substrate.situation`, или
  `situation.block` не соответствует join'у через субстраты.
- ❌ Цикл `parent-zone` в `zone.md`.
- ❌ Явный `transition-to-block` внутри одной зоны (внутризонная
  связность — по умолчанию).
- ❌ Блок без `ux-substrates` или без `who`.
- ❌ Код / FSD / компонент / облик в артефактах — это слой кода (ручная
  сборка по `docs/projects/<project-slug>/screens/`) и craft
  `@stit-design/ui`.
