# vision

> Корневой документ продукта. Заполняется один раз и переписывается, когда
> бизнес сдвигает рамки. Один проект (папка `docs/projects/<slug>/`) =
> один продукт = один `vision.md`. Остальные kinds (`user`,
> `capability`, …) растут из этих трёх вопросов. `addresses-problem`
> связывает продукт с проблемами слоя `business-problem` (M:N).

## Критерии vision

1. **Проблема одного предложения.** Чьей боли касается продукт — в
   терминах бизнеса/жизни, не в терминах решения. «Записаться к врачу
   занимает 30 минут на звонки и переключения» — это проблема. «Нужен
   красивый сайт» — нет.
2. **Успех измерим или наблюдаем.** Успех формулируется как «X станет
   так, что Y» с проверяемым исходом. Не обязательно метрика — может
   быть качественный наблюдаемый сдвиг («медсестра не звонит уточнять
   формат снимка»).
3. **Non-goals явные.** Решение, что **не делаем**, ценнее списка фич.
   Каждый non-goal — короткое «не делаем X, потому что Y» (Y — про
   границы продукта, не про техдолг).
4. **Без жаргона.** Сторонний человек прочитал и понял за минуту, чем
   продукт занимается и для кого.
5. **Адресует проблему(ы).** `addresses-problem` — массив slug-рефов на
   строки `frame` слоя `business-problem`, которые продукт закрывает
   (M:N). Без привязки продукт висит в воздухе; `success` целит в метрики
   этих проблем.

## Что vision НЕ

- ❌ Список фич / эпиков / задач. Это `capability`.
- ❌ Описание рынка и конкурентов. Это `market`.
- ❌ Имена платформ / стека / технологий. Это инфра-слой (другой репо).
- ❌ «Мы делаем платформу для X» без указания **чьей** боли касается. Без
   адресата vision пустой.
- ❌ Маркетинговая копия для лендинга. Vision — внутренний документ
   аналитика, не сейлз-материал.

## Тест-критерий

«Если новый член команды прочитает только этот файл — поймёт ли он, к
**какой проблеме** и **для кого** мы прикасаемся, и какие границы мы
себе поставили?»

- «Снизить до 3 минут запись пациента на приём, исключив звонки между
  клиниками» → ✅ (проблема, успех, контекст)
- «Сделать платформу управления медицинскими данными» → ❌ (нет
  адресата, нет проверяемого исхода, нет границ)
