# goal

> Цель (goal) — вершина ветки Карты гипотез: **критерий успеха без
> цифр** («по каким критериям поймём, что достигли»). Числовую
> измеримость несут метрики (`metric`), привязанные к цели. Растёт из
> приоритетной ставки (`bet`).
>
> На `slug` цели ссылаются `metric.goal` и `bet.promoted-to`; принадлежит
> одной+ строке `business-problem` через `problem` (M:N — цель может
> закрывать несколько проблем).

## Критерии goal

1. **Критерий успеха, не цифра.** Описывает состояние, которого хотим
   достичь. Все числа — в `metric`, не в формулировке цели.
2. **Не задача.** Цель — состояние мира, не активность. Если из цели
   выводится ровно одна гипотеза, дублирующая её, — это переодетая
   задача (типовая ошибка методологии).
3. **Самодвижение учтено.** Цель достигается через изменение поведения
   субъектов, не «крутим ручку» напрямую.
4. **Дедлайн опционален.** `deadline` — если у цели есть срок.
5. **Привязана к проблеме(ам).** `problem` — строки `business-problem`
   (массив), ради которых цель ставится. Цель раскрывает проблему в проверяемый
   критерий успеха; одна цель может служить нескольким проблемам.

## Что goal НЕ

- ❌ Цель с цифрой внутри («снизить отток до 5%»). Цифра — в `metric`,
  цель — «удержать платных пациентов».
- ❌ Задача вместо цели («внедрить CRM»). Это решение → `task` / слой
  `project`.
- ❌ Цель без единой метрики (нечем измерить достижение — ловит audit).
- ❌ Зонтичная цель «улучшить всё».

## Тест-критерий

«Это **проверяемый критерий успеха** (цель) — или это **активность**
(тогда задача), или **число** (тогда метрика)?»

- «Удержать платных пациентов в сети» → ✅ (критерий успеха, без цифр)
- «Снизить отток до 5%» → ❌ (цифра — это `metric`)
- «Внедрить программу лояльности» → ❌ (активность — это `task`)

| slug | name | description | problem | from-bet | deadline | status |
|---|---|---|---|---|---|---|
| `<slug>` | <короткое имя> | <критерий успеха, без цифр> | `` [`<problem-slug>`] `` | `` `bet:<slug>` `` \| `—` | `<YYYY-MM-DD>` \| `—` | `draft` |
