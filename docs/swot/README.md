# Артефакты SWOT

Слой **LinkedSWOT**: из сильных/слабых сторон и трендов/угроз бизнеса
рождаются стратегические **ставки** — «за счёт чего возможен следующий
шаг». Стоит между картиной бизнеса (`docs/business/`) и Картой гипотез
(`docs/hypothesis-map/`): факторы вырастают из профиля и конкурентов,
ставки дотягиваются (`promoted-to`) до цели или гипотезы Карты гипотез.

Два kind в порядке потока:

1. **`factor`** — сильная/слабая сторона (внутреннее, про устройство
   бизнеса) либо тренд/угроза (внешнее, про движение мира). Сам по себе
   фактор — не действие.
2. **`bet`** — стратегическая ставка «`<действие>, чтобы <ценность>`»,
   связывающая ≥1 внутренний и ≥1 внешний фактор в идею следующего шага;
   доводится до `goal`/`hypothesis`.

Слой **строгий** (методология LinkedSWOT) и **многопроблемный**: каждая
запись принадлежит одной+ проблеме (M:N) через колонку `business-problem` —
ссылку на строки `business/business-problem.md`.

## Файлы

| файл | сущность | поля |
|---|---|---|
| [`factor.md`](factor.md) | SWOT-фактор бизнеса | slug · name · description · **business-problem** · area · priority · status |
| [`bet.md`](bet.md) | стратегическая ставка | slug · name · description · **business-problem** · factors · promoted-to · priority · status |

`business-problem` — массив slug-рефов на строки `business/business-problem.md`
(M:N). `factor.area` — `strength` \| `weakness` \| `trend` \| `threat`.

## Принципы оформления

Зеркалит канон `docs/projects/_template/project/`. Один файл — одна таблица
сущностей одного типа. H1 = имя файла = kind, без frontmatter. Русское
слово-перевод строгого термина сопровождается `slug` в скобках: «фактор
(factor)», «ставка (bet)».

### Форма ячеек

| тип значения | формат | пример |
|---|---|---|
| одиночный slug-реф | в бэктиках | `` `goal:retain-paid` `` |
| массив slug-рефов | питон-стиль с бэктиками | `` [`strength-ops`, `trend-online`] `` |
| пустое опциональное поле | em-dash | `—` |
| enum (`area`, `status`) | в бэктиках | `` `trend` `` |
| приоритет | целое, 1 = высший | `1` |
| свободный текст | без кавычек, одна строка | «спрос на онлайн-запись» |

Последняя колонка везде — `status` (enum `draft` \| `stable`).

## Статус записи

- `draft` — заведена, не прошла чек-лист зрелости.
- `stable` — прошла критерии файла-канона, обязательные слоты заполнены,
  методологические инварианты соблюдены, открытых вопросов нет.
- Дефолт — `draft`. Повышение — через `/swot-deep-dive` по подтверждению
  аналитика. Понижение — аналитик руками.

## Связи и методологические инварианты (семантические)

Связи **не валидируются slug-целостностью** — они семантические. Все
инварианты считаются **в пределах одной проблемы** (`business-problem`).
Методологические инварианты LinkedSWOT ловит **рой агентов** `/swot-audit`
— смыслом, не grep:

- **Баланс факторов.** `bet.factors` содержит ≥1 внутренний
  (`strength`/`weakness`) **и** ≥1 внешний (`trend`/`threat`). Ставка
  только с одной стороны — без баланса «лево/право».
- **Ставка доведена до карты.** `bet.promoted-to` ссылается на `goal`
  или `hypothesis`. Висящая ставка — недоделанный мост.
- **Фактор использован.** `factor`, не вошедший ни в одну `bet` (ни по
  одной из своих проблем), — повод поднять при cohesion.
- **Приоритет без дублей.** `priority` — целое, 1 = высший; у `factor` —
  внутри пары квадрант × проблема, у `bet` — в пределах проблемы.

Связь с соседними слоями (тоже семантическая, ловит `/cross-audit`):

- `business.profile` / `business.competitor` → `factor` — сильные/слабые
  стороны и тренды/угрозы вырастают из картины бизнеса.
- `bet.promoted-to` → `hypothesis-map.goal` / `hypothesis-map.hypothesis`
  — ставка дотягивается до измеримой цели или проверяемой гипотезы.
- `business-problem` → `business/business-problem.md` — какие строки
  реестра проблем питает запись.

## Workflow

```
/swot-deep-dive   — единая точка входа аналитика.
/swot-audit       — рой агентов: инварианты LinkedSWOT.
/cross-audit      — сквозная проверка с business / hypothesis-map / project.
```

## Anti-patterns

- ❌ Действие в формулировке фактора («создать сайт») — это `bet`.
- ❌ Слабость в графе угроз / угроза как наш дефект (путаница квадрантов).
- ❌ Ставка без опоры на факторы (выдумана, не из SWOT).
- ❌ Ставка только с внутренними или только с внешними факторами.
- ❌ Ставка-фича без «чтобы» (есть действие, нет ценности).
- ❌ Ставка, не доведённая до `goal`/`hypothesis` (мёртвый мост).
- ❌ Запись без `business-problem` (непонятно, какой проблемы касается).
- ❌ Frontmatter / каталоги под kind.
- ❌ Жёсткие slug-валидации. Инварианты ловит рой, не grep.
