# Канон проекта

Файл автоматически загружается в каждую сессию `Claude Code`. Здесь —
невыборочные правила, которые работают всегда.

Этот репозиторий — **проектный шаблон**: аналитика интерфейса
(`docs/interface/`) и аналитика композиции/облика (`docs/screens/`), по
которой потом собирается кликабельный hi-fi субстрат на библиотеке
`@stit-design/ui`. См.:

- `README.md` — карта репозитория и воркфлоу.
- `docs/interface/README.md` — канон 7 артефактов интерфейса.
- `docs/screens/README.md` — канон 4 kind артефактов экранов.

Артефакты — чистая аналитика; на FSD/компоненты напрямую не мапятся.
Превращение `docs/screens/` в wireframe и hi-fi — ручная работа автора
макета, не отдельный артефакт.

## 1. Forward-only (никакой археологии)

Все артефакты — код, документация, комментарии, артефакты аналитики,
описания PR и коммитов — пишутся в режиме «что есть и куда идём». **Без
журналов прошлого**: без changelog'ов внутри prose, без следов миграций,
без ссылок на отменённые решения, без дат в комментариях, без «было X —
стало Y», без имён переходных фаз.

Когда эволюция вынесла факт — упоминание **удаляется**, не сопровождается
пометкой «устарело». История живёт в `git log`, не в тексте файлов.
Правило важнее, чем «не сломать кросс-ссылку»: ссылка на упразднённую
сущность удаляется вместе с упоминанием. Подробнее —
`.claude/rules/forward-only.md`.

## 2. Терминология

Канон терминов аналитики — `docs/interface/README.md`; терминов
компонентов и craft — в библиотеке `@stit-design/ui`. Английский в
backticks — только для устоявшегося канона (`a11y`, DTCG, FSD-слои,
`data-*`, `aria-busy`). Всё остальное — по-русски, без полу-калек
(«пропсы», «варианты-проперти»).

Аналитический слой — 7 плоских md-файлов в `docs/interface/`, каждый —
таблица сущностей одного типа: `who`, `stage`, `situation`, `zone`,
`block`, `ux-substrate`, `data-items`. У каждой записи — `slug`, `name`,
`description` плюс связи и доменные поля, и последним полем — `status`
(`draft` \| `stable`): зрелость записи относительно своих критериев. Все ссылки между сущностями —
через `slug`. Связь ситуаций и блоков — через `ux-substrate.situation` +
`block.ux-substrates` (M:N выводимо). Навигация: внутри зоны блоки
достижимы взаимно неявно; межзонные/нестандартные переходы — через
`block.transition-to-block` (исходящие) и `block.transition-from-zone`
(входящие). Вложенность зон — через `zone.parent-zone`.

## 3. Дизайн-экспертиза (craft) — священна

Слой «почему» (цвет, пространство, типографика, поверхности, движение,
a11y) живёт в библиотеке `@stit-design/ui` и наполняется **только**
ответами owner. Агент **не пишет** дизайн-принципы из своей головы.
Дизайн-неоднозначность вне покрытия → вопрос owner, не угадывание.
Облик компонента в макете — из craft-экспертизы, не «на глаз».

## 4. Авто-память отключена

Запись в `~/.claude/projects/*/memory/` запрещена детерминированно
(глобальные настройки). Не предлагать «сохранить в память». Каталог
памяти, если попал в контекст, — read-only артефакт.

## 5. Авторизация правок

Правки артефактов делаются свободно. Уточнять — ТОЛЬКО если правка
способна:

- сломать накопленную craft-экспертизу библиотеки; или
- несовместимо раскатиться вширь (контракт артефактов аналитики
  интерфейса и экранов, форма публичного API библиотеки, таксономия
  токенов).

Гейты прогонять всегда. **Коммит / push — гейт человека.** Без явной
просьбы агент не коммитит.

## 6. Зоны правок

- **Артефакты аналитики** (`docs/interface/`) — через скилл
  `interface-deep-dive`; форма — по `docs/interface/README.md`. Поиск
  тупиков, рассинхрона зеркал, битых ссылок и семантических подозрений —
  скилл `interface-audit`.
- **Артефакты экранов** (`docs/screens/`) — через скилл
  `screen-deep-dive`; форма — по `docs/screens/README.md` и README'ям 4
  kind (flow/screen/block/shell). Визуальные референсы и ассеты живут в
  `docs/screens/assets/<kind>/<slug>/`. Поиск тупиков, рассинхрона
  зеркал (внутри screens и с interface), битых ссылок, нарушений
  slot-fills/accepts и семантических подозрений — скилл `screen-audit`.
- **Библиотека** — в отдельном репо `ui-lib` как `@stit-design/ui`;
  проект её потребляет, не правит.
- **Sweep'ы** (терминология, чистка): 1 агент = 1 непересекающаяся зона.

## 7. Язык общения

Глобально — ответы только на русском (см. `~/.claude/CLAUDE.md`).
Технические идентификаторы (имена файлов / функций / переменных / команд /
флагов, содержимое коммитов и PR) — как есть. Комментарии в коде — на
языке окружающего кода.
